# 消息呈现手动验收

机制与自动回归见 [消息呈现](../模块/消息呈现.md)。布局/像素测试不能用 jsdom 通过替代。

## 跟随与阅读

1. 让纯文字回复超过一屏，点击索引跳到早期提问，再点回底按钮；继续输出应跟随。
2. 重复上一步，但在翻历史时发送下一条消息；发送必须恢复跟随。
3. 上翻、触摸滚动、拖动滚动条、滚动键离开底部；继续输出及调整窗口尺寸不抢阅读位置。
4. 手动滚到最底后继续追加；重新跟随。短于一屏时不施加底部平移。
5. 在跟随与阅读两态分别调整窗口宽高，展开思考/工具、等待图片及代码高亮回填；阅读态不强制回底，代码内部滚动不应被外层持续抢走。
6. 在普通正文/空白处将对话滚到底，用一次很轻的上滚开始阅读；不能连续滚很多下才离底。
   特别覆盖首帧只动0.5/1px、尚在底部容差的情况，再追加正文或同帧停止收起详情，仍不被拉回。
7. 先上翻，再主动向下滚到底，恢复跟随；底部继续向下滚不能丢失工作行。索引定位到
   近底仍保持阅读，不能仅因旧scroll/窗口缩放/终态布局变化又恢复跟随。此时再给明确
   正wheel、下行键或上滑touch，即使原生clamp没有新位移/scroll，也应立即恢复；仅按下
   滚动条没有方向，不能触发该快捷，须拖出实际下行。
8. 平滑索引定位尚未结束时向上滚，旧程序目标应在当前位置被中断，本次原生滚轮继续生效；
   键盘、触摸和拖滚动条都检查离底/主动回底。区分内层代码/思考滚动与普通正文的外层滚动。

## 单份流内工作行

1. 发送一句「你好」，首片等待与短回复输出时，「工作中」紧跟最后消息；不足一屏、
   恰好一屏与超过一屏时都只有一份工作行；溢出跟随仅给原节点fixed定位，不复制DOM。
2. 长输出跟随时检查 Clock、标题与数字整行；读屏只获得一份「工作中」，码表不逐100ms播报。
3. 上翻/触摸/滚动键/拖动滚动条/索引后，工作行同栈归流、随正文滚动，阅读位置不被抢回；
   主动回底或发送后恢复跟随，往返多次不出现双影。
4. 缩放窗口、展开侧栏、使 Composer 变高，检查工作行与正文对齐；默认/导入主题切换后
   颜色与排版同步，原有小数行高不应导致图标微抖。
5. 完成、停止、失败、工具执行、审批等待和切会话时检查交接；终态由 RunTrace 承接，
   不遗留「工作中」；切回仍运行的会话重新建立工作行。
6. 自动回归命令：npm test -- --project web src/renderer/src/components/ui/message-scroller.render.test.tsx src/renderer/src/features/home/home-chat.render.test.tsx src/renderer/src/features/home/turn-group.render.test.tsx。
   覆盖 StrictMode、父树同批更新、root/viewport/content 重挂与观察者清理；像素需 Electron 验证。

## 亚像素与动效

- 生产构建的纯文字场景，每段小数高度增长时分别采标题、图标、数字；暂停扫光再对比固定裁片，不能以「不到1px」判定无抖动。
- Electron31 下分别测试100%/125%/150%缩放与默认/导入主题；正文行高不为验收临时修改。
- 区分Windows显示缩放和应用缩放；改变窗口尺寸、侧栏与Composer高度，覆盖视口起点差异。
  按30ms自然追加文本记录连续合成帧，不能只在固定top的隔离页等布局稳定后截图。
- 系统 reduced-motion 开启后，运行标题为静态可读文字，正文立即可读；关闭后恢复扫光与正文渐显。
- 临时复现入口 `tmp/chat-audit-20261117/serve.mjs` 构建生产预览，不启动 Electron；完成后停止服务。IAB 数据只能作为同环境对照。
- 像素回归：暂停扫光，固定裁片，连续追加八段61.5px正文，再补不追加的静止控制；
  分别比较图标、标题与数字区域，不用 DOM y 恒定替代像素审查，也不将数字内容变化混算图标抖动。
- 既有工作中文字与 Clock 稳定、阅读/发送/回底行为的用户验收记录见
  [诊断计划 §9](../计划/对话流畅性诊断与改造.md#9-实施进度审批后的追加记录)。
  完整工作行须按本册重验 Electron31 的主题与缩放矩阵；旧 Clock-only 的 IAB
  零像素差对照不能代表当前完整行已通过。
- 单节点定位版本的连续帧验证与用户确认见[归因复核 §10–§11](../计划/底部工作行抖动归因复核.md#10-单节点定位的验证记录)；
  后续回归仍覆盖本册矩阵，不把单一场景的用户确认扩写为全部场景通过。

## 压缩与热路径

- 工具轮间压缩完成、下一段回复尚未到达时，原回合仍保留工作中结构；随后停止也不临时改变压缩归属。
- idle 手动压缩仍直接可见；历史快照没有直播归属字段，继续按相邻工作项推断。
- 侧栏等待审批标记随审批变化；流式正文不应触发审批列表组件更新。usage 随落账/压缩/live用量变化，不随无用量正文逐字聚合。

## renderer入口合批

- 自动可重复命令：`npm test -- --project web src/renderer/src/stores/chat/delta-batcher.test.ts`。
  300片/1ms连续输入 + 末片屏障：301接收，10次定时发布+1次屏障发布，text/thinking全文逐字一致；这是store通知计数，不是FPS。
- 真实Electron：同时开A/B会话流式，切换后文字与思考不串流；工具前后的正文分别保留。输出尾字时停止，半截正文保留，无30ms后复活占位；失败、重载历史、删除后同验。
- App订阅卸载/StrictMode重挂不遗留timer；后台停留后回前台，终态不等timer才收尾。组件直接传入streaming prop立即更新是预期，30ms只在事件入口。
- 本步未测真实模型、Electron FPS或新增视觉矩阵；旧临时audit直接setText不能证明store合批效果。

## 实际停止与最终结果

1. 让回复已经输出正文后点停止；等终态事件到达，停止按钮恢复发送，流内工作行
   撤销，回合显示「已停止」。半截正文、thinking 与已完成工具过程保留，末段只出现一份，
   不应出现运行错误条；不能用直接给 TurnGroup 传 stopped 替代真实事件链。
   过程详情缺省收起，半截终答仍可见；点击「已停止」展开后再点击应收起，手动选择不会
   因同组件重渲染或后续提问被强制反转。无详情的头条没有展开箭头。
   随后再发送「稍等一下」并等新回合完成，旧半截头仍为「已停止」，不能变成「已工作」。
   另在首片前停止后发送「你好」，原来的空输出回合仍保留「已停止」，不能只剩user泡。
2. 分别在纯正文、thinking-only、已有工具轮后继续输出时停止；让尾字仍在30ms批队列内，
   终态不得丢尾或30ms后复活流式占位。核对已封存段的 usage 不丢失、不重复计账。
3. 用可控引擎场景在最后模型回答成功、收口钩子尚未结束时停止；仍应显示「已停止」，
   不要求末条 assistant.stopReason=aborted。输出截断的同类场景不再自动续写。
4. 正常完成先到时仍显示「已工作」；点过停止但引擎明确报告 error 时显示「出错了」与
   错误条。通过其他入口停止、本窗没有 stopping 标记时，也由引擎原因显示「已停止」。
5. 停止后重新发送或继续生成，旧停止/错误状态清除，显示新的「工作中」。A 停止时切 B，
   B 的工作状态不变；切回 A 仍保留停止结果。重启后的历史缺少结果字段，按既有 done 呈现。
6. 注入 abort IPC 拒绝，检查当前停止请求撤销、操作错误可见，实际 run 仍等待自己的终态；
   aborted:false 不制造停止结果。延迟旧响应到下一 run、下一次 abort 或删会话之后，
   旧响应不得更改新请求或重建已删桶。手动压缩报错也不能把成功回合改成「出错了」。
7. 自动回归走真实事件订阅、store 动作与 HomeChat：
   `npm test -- --project web src/renderer/src/stores/chat/store.test.ts src/renderer/src/stores/chat/delta-batcher.test.ts src/renderer/src/features/home/home-chat.render.test.tsx`。
   权威 messages 有值（含中止尾段）、空数组、字段缺席分别验；缺省 reason 按 error。
   启动准备期按下一节走独立生命周期验收；无 user 组替换、工具封段换父容器与历史停止
   标签持久化仍维持既有边界，不把结果标签测试外推到这些路径。

## 启动准备期、续写与输入保留

1. 用可控 Promise 分别卡住 submit 装配、切模型、input/auth、before_agent_start 后停止；
   唯一流内工作行显示「正在停止」，运行锁保留。释放准备 Promise 后，检查唯一
   aborted 终态、没有新增模型 HTTP 请求，后续再发能正常起跑。先已取消才进入
   prepareRequest 检查时不调用 provider；晚于检查的取消仍核对 provider 遵守 signal，
   不把同一个端点的结果当作所有 provider 的结论。
2. 准备期停止后检查原始提问在消息区、live context、JSONL 与重开历史中各恰一份；
   已由 pi 交付的 user 不重复追加。装配彻底失败时显示初始化错误，不伪装已停止，
   也不能把没有落盘的输入说成保存成功。input 返回 handled 时不永久 running。
3. 卡住手动 continue 的首个准备 await，第二次 submit/continue/compact 必须忙拒绝；
   取消后旧截断前缀保留。正常续写与输出新尾段后停止，都保留前缀与新增正文，旧用量
   不重复计入本 run Inspector；压缩条仍在原位置。无效续写显示真实错误并释放预约。
4. 分别在 manual compact 装配中、其内部 await abort 到 compaction_start 之间停止；
   不发摘要模型请求，压缩操作正确收口，不制造一个 run.completed/run.failed 代替它。
   不合作的准备 Promise 释放前仍处于等待收敛状态，不能让下一操作抢进。
5. 删除会话或退出时让装配稍后返回，旧 pi 实例应 dispose，不再 prompt/compact，
   迟到链不能把旧会话挂回来；另在 pi input 准备钩子内删除后再释放，既有/未落盘两类
   会话都不再发请求、无新终态、JSONL 不复活。A/B 同时准备时只停止目标会话。
6. 延迟 submit/continue 的 RPC 拒绝到终态、下一 run、切会话或删桶之后；旧响应不能
   覆盖已停止/完成结果、撤掉别的 user、丢新 delta 或重建桶。延迟旧 submit 成功后再
   编辑输入、切会话或重挂输入区，回包不得清掉新草稿或替旧请求切视图。
   手动压缩准备期间删除会话后再让其 RPC 拒绝，错误不得补造已删除的会话桶。
7. 自动回归分别核对 `session-preparation.test.ts` 的 Host 可控边界、
   `preparation-stop.integration.test.ts` 的真实 pi/本地端点链路、`hook-seat.test.ts` 的
   原钩子前后检查，以及 store/HomeChat 的请求身份隔离。自动回归不能代替真实 Electron
   「正在停止」文案、单份工作行及输入草稿的交互复验；本节是验收步骤，不是通过记录。

## 有界正文渐显

- 短纯文字流式仍按中文逐字、拉丁逐词出现，尾部有细粒度渐隐，不能退化成整段淡入。
- 粘贴或模型单批大段普通正文时，内容首帧完整可选、按连续短语组平滑出现，不整片 settled 直出，也不出现数百/数千个同步淡入字。
- 流式代码围栏保持完整、高亮不闪成纯文本；流式表格列宽与结构稳定，本批不期待逐单元格动画。
- 静态历史与非前缀替换立即完整可读，不播放旧内容动画；第二条同内容的流式消息仍有动画，
  StrictMode 后不重复/停住。运行中消息切走再切回可能按首帧重新渐显，当前 Markdown
  接口没有快照来源信号，不把本批块身份修复算成该边界已解决。

## 相同段落与文本组身份

- 先输出一段「相同」，再输出另一个独立的「相同」段落：第二段从新字开始渐显，
  第一段不重播。一次追加两个同文段落时，两段分别排期，不同时认领同一份计划。
- 继续往第二段追加文字，再追加相同前缀的不同段落、列表项；只有对应块的新增部分渐显，
  不丢文字、空白和标点。中文短批仍逐字，拉丁词跨多片到达时延长既有词节点。
- 601个汉字首批后逐次追加甲、乙：32个旧文本组保留，甲、乙分别获得新节点；
  96个字后继续小步追加也不把旧字重新压成粗组。结合浏览器检查尾部两次淡入都发生，
  不能只凭 data-reveal=new 判定动画启动。
- 同块普通601字加粗体601字、或同批两个601字段落：各连续文本片段独立压组，
  所有新组最晚250ms起跳；32组上限不外推为整个富文本块总数，8ms目标不能突破排期窗口。
- 输出未闭合强调、行内 code、setext 标题、列表与表格前缀，继续补全语法；结构和全文
  与原生 Streamdown 一致，代码/表格仍无逐字 reveal。后补链接定义、脚注引用/定义造成
  合块或解析文字改写时，已经显示的正文不从头重播。
- 自动回归命令：`npm test -- --project web src/renderer/src/components/ui/stream-reveal.test.ts src/renderer/src/components/ui/stream-reveal.render.test.tsx`。
  断言真实节点复用、同文消息隔离、StrictMode、默认清洗与排期；jsdom 不实现透明度过渡，
  实际淡入与 reduced-motion 仍按本册浏览器/真机步骤验收。

## 回复结束时的自然收尾

1. 让大批正文的尾字尚在延迟/淡入阶段就结束回复：终态头、用量和输入区应立即更新，
   「工作中」立即消失；尾字继续平滑变实，不因业务结束突然整批直出。
2. 纯文本与有思考/工具过程的常规回合分别验；检查终态前后的旧正文节点与过渡身份，
   播完后 reveal span 回收，复制得到的全文始终完整。不能只检查 data-reveal 属性。
3. 列表 marker 的 color 过渡也应自然收口；工作行扫光、悬停等无关动画不延长正文收尾。
   动画正常完成与被样式取消两种情况都能进入 static，不出现 Promise 错误。
4. 系统 reduced-motion、已播完或没有正文动画时立即呈现终态；收尾期间切到后台再回来，
   不遗留待清理的视觉树。后台清理不影响业务完成与再次发送。
5. 收尾尚未结束时开新流、替换为非前缀最终正文、切会话或卸载：旧等待不能把新内容切成
   错误模式；权威改写立即显示，失败删除的占位不残留幽灵正文。
6. 用未闭合强调、行内 code、链接、围栏，以及后补 reference/footnote 的正文收尾；最终
   字面与结构应等同原生 static 全文解析，不能永远停在 remend 预览结果。
7. 以实际 Cogent 复验主题与缩放。真实 abort 标签按本册「实际停止与最终结果」走全链路；
   工具封段搬入过程区、无 user 根 key 重挂仍按
   [收尾边界](../计划/正文渐显收尾.md#4-边界与真实的墙) 记录，不把常规相位回归外推成这些路径已验证。
