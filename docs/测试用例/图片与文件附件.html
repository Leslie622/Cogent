图片与文件附件详细测试用例

本册供实际桌面手测。机制见模块页，尺寸与样式以 UI布局为准，技术路线见技术笔记。 下面写的是操作与预期，所有用例初始均为“未测”，不代表已经通过。

怎么测、怎么记录

  • P0：主流程与容易丢数据的场景，优先测。P1：异常、兼容和能力边界，随后测。
  • 先测“导入”和“界面”，无需配置媒体 MCP；发送与内容识别需要可用模型。
  • 涉及图片、视频、文档视觉分析 MCP 的用例另有前置条件；没有对应服务就记“阻塞：未配置服务”，不记通过。
  • 模型未调用指定工具、没有实际触发故障、文件导入太快而没赶上操作，都记“未触发”，不能代替该用例通过。
  • 每条只记录：通过 / 失败 / 阻塞 / 未触发。失败直接反馈“编号 + 实际现象 + 截图或工具错误”即可。
  • 窗口尺寸、45px、180px、10px 都指 CSS 像素；系统 125% DPI 下截图中的物理像素会放大。

第一轮推荐顺序：IN-01 → IN-02 → IN-05 → IN-07 → UI-01～UI-05 → SEND-01～SEND-04 → DRAFT-01、02、05 → FILE-01 → DOC-01、03、05、06。 有图片模型再测 MODEL-01；视频及扫描文档可按 MEDIA 组补测。

样本准备与通用规则

建一个专用测试文件夹，只用可移动、可删除的样本。建议准备以下内容；已有相似文件可替代。

本机已生成样本与答案说明，可直接使用其中的文件； 容量边界文件已单独放置，兼容性原件另列并按成功读取回归。

样本 准备内容与核对点
图片 一张宽图、一张竖图、一张方图；能清楚区分内容。另准备 PNG、JPG、WebP、GIF 各一份；GIF 本轮核对导入与预览，不要求缩略图播放动画
短名 / 长名 a.txt；一个超过 30 个汉字的文件名。两者正文分别写 短名样本 A17、长名样本 B28
中文路径 / 同名 含中文、空格、括号的目录；两个不同目录里都放 说明.txt，正文分别写 目录甲 A17、目录乙 B28
文本 UTF-8 文本、UTF-16LE 带 BOM 文本、JSON/源码/CSV；另备超过 24000 字符的长文本，首尾写不同标记
PDF 两页可选中文字的中文 PDF，每页写不同编号；另备纯扫描页 PDF、带图表 PDF、损坏或需要密码的 PDF
DOCX 两个标题、两段正文、一张两列表格、一张嵌图；事先记下表格的一个具体数值
XLSX 两张工作表“销售”“库存”；销售表 A1:C3 含文字、数字、公式，至少一个公式用 Excel 计算并保存
PPTX 至少两页，各页标题不同；其中一页写演讲者备注；最好调整过页面顺序
视频 10～30 秒短视频，开头和结尾内容不同；带一句自己知道的语音。可另备无声视频
异常 / 其他 零字节 TXT、普通 ZIP、旧版 DOC/XLS、一份把普通文本改名为 .png 的假图片
边界样本（可选） 文件字节数精确可知；按 LIMIT 组准备，不必为第一轮测试先造大文件

通用规则：

  1. 每条默认从空草稿开始。涉及多个聊天时明确叫 A、B，记下各自附件名与正文。
  2. 模型声明保存后下一提交生效，同聊天也要测；MCP 绑定仍按会话快照，新建聊天验证新绑定。 图片开关测试使用此前没出现的新图，并核对 POST 请求内容，旧图的历史文字回答不能证明这次仍传图。
  3. 文档提问默认用：请用 read_attachment 读取本次附件，不运行外部解析脚本；无法读取就说明原因。 再附上各用例的问题。工具记录用于确认实际读了什么，回答用于核对理解结果。
  4. 导入成功只说明文件可用；模型回答正确还要核对是否真正读取了内容，不能只看“收到附件”。
  5. 识图、扫描件和视频答案与已知样本核对；没有分析结果时不应编造内容。

一、粘贴、拖拽和选择文件

IN-01 · P0 · 粘贴系统截图

  • 操作：1）新聊天，输入框聚焦；2）用系统截图工具复制图片；3）按 Ctrl+V；4）再输入一段文字。
  • 预期：只新增一张图片缩略图，不变成路径文字或重复图片；图片位于输入框正文上方；原有文字与后续输入均保留。

IN-02 · P0 · 从资源管理器复制多个文件

  • 操作：1）在真实文件管理器选中两个含中文名称的文件；2）Ctrl+C；3）回 Cogent 输入框 Ctrl+V。
  • 预期：两个文件各出现一张卡片，名称正确，无乱码；没有把文件路径当正文粘贴，没有只导入第一个。

IN-03 · P0 · 普通文字粘贴不退化

  • 操作：1）复制含中文、英文、换行的普通文字；2）在输入框中间粘贴；3）再复制一个普通网页链接粘贴。
  • 预期：文字与链接落在光标位置，换行正常；不新增附件，不弹文件错误，不吞掉原正文。

IN-04 · P1 · Excel 复制单元格

  • 操作：1）在真实 Excel 中选中 A1:C3，Ctrl+C；2）粘贴到 Cogent；3）尝试修改其中的数字。
  • 预期：优先保留可编辑表格文字；不因为 Excel 同时提供位图就变成只有一张截图；修改数字时仍是正文编辑。

IN-05 · P0 · 鼠标拖入图片与文件

  • 操作：1）在真实文件管理器选中一张图片和一个 TXT；2）拖到聊天正文区域后放下；3）清空后再拖到输入区放下。
  • 预期：两个区域均能接收；出现对应两张卡片；不打开外部文件、不导航页面、不替换整个应用内容。

IN-06 · P1 · 拖拽提示正确收起

  • 操作：1）拖着文件进入聊天；2）在消息、输入框、工具按钮之间移动；3）拖出窗口取消；4）再拖回并放下。
  • 预期：局部“添加到当前聊天”提示不因经过子元素闪烁；取消或放下后消失；没有残留白色遮层挡住聊天和按钮。

IN-07 · P0 · 加号多选与取消

  • 操作：1）点击输入区加号，选“添加图片或文件”；2）在系统对话框多选图片、PDF、TXT并确认；3）再次打开选择框后点取消；4）选“引用文件夹”打开目录选择框，取消后核对草稿。
  • 预期：确认后按所选内容生成卡片；取消不新增空卡、不清空已有附件与正文。

IN-08 · P0 · 目录引用的三种入口

  • 操作：分别用资源管理器拖入、复制目录后在输入区粘贴、加号→引用文件夹三种方式加入“09 目录拖拽样本”；同一草稿再次加入相同路径；另测空目录及名称带.png后缀的目录。
  • 预期：显示文件夹图标、目录名和绝对路径，无0 B/另存/上传说明；同一路径只有一张卡；高度45px、最大宽180px、10px圆角，hover关闭、点击打开目录；不递归复制目录，不占图片/文件容量；添加本身不建会话。

DIR-01 · P0 · 纯目录和混合发送、工具读取

  • 操作：1）只添加目录，正文留空并发送；2）让模型先ls再read读取“目录里的文件.txt”标记；3）另发目录+图片+普通文件并加正文；4）切聊天、重启回看。
  • 预期：纯目录可发、无空正文气泡；目录卡随原用户消息保存，原正文不混入内部路径说明；工具实际读到DIRECTORY-7319后才算内容识别成功。首次请求只含路径引用，没有自动注入全部目录内容；混合项不串归属。

DIR-02 · P0 · 未发送目录草稿

  • 操作：已有聊天A→新聊天，添加目录和正文→回A→回新聊天；正常退出重启，再点新聊天回到未发送草稿。
  • 预期：目录、正文保留，添加阶段侧栏不新增会话；发送后只消费该次快照，后续编辑保留。应用启动先显示旧聊天时，点新聊天仍应找回未发送内容。

DIR-03 · P1 · 路径失效、恢复和移除

  • 操作：在专用临时副本添加目录；将其改名或暂移，重启回草稿；恢复路径后重试；另测路径被同名普通文件替代；移除目录卡、删除聊天。
  • 预期：失效目录可见错误且草稿不能假装就绪发送，路径保留；恢复后可重试；被普通文件替代明确失败，不自动变成文件上传；移除/删聊天不删除本地目录或子文件。目录内容修改后工具读取反映当前内容。

DIR-04 · P1 · 项目和权限边界

  • 操作：给绑定项目的聊天引用项目外目录，观察项目胶囊、模型工作区声明；在ask模式让Agent写目录内文件并拒绝审批；用只读ls/read作对照。
  • 预期：引用不改变项目、cwd、工作区根或AGENTS加载；只读工具可按路径访问，外部目录写入仍遵守原审批规则，引用本身不产生“始终允许此工作区”的新信任根。

IN-09 · P1 · 文件格式组合

  • 操作：分别添加 PNG、JPG、WebP、GIF、PDF、DOCX、XLSX、PPTX、TXT、ZIP、MP4。
  • 预期：允许范围内的原件均可导入；四种常用图片显示方形缩略图，其他类型显示文件卡；附件类型不等于模型已能理解其内容。

IN-10 · P1 · 同名和重复添加

  • 操作：1）同时添加两个目录里的 说明.txt；2）再添加一次其中一个；3）移除最后添加的重复项，发送剩余两项并分别询问正文标记。
  • 预期：各次添加的卡片可独立移除；同名文件的 A17/B28 不串；移除一张不顺带删除另一张，剩余项顺序不变。

二、卡片外观与交互

UI-01 · P0 · 图片尺寸、裁切和详情

  • 操作：1）添加宽图、竖图、方图；2）在输入区观察；3）发送后观察历史中的相同图片。
  • 预期：两处均为 45×45px 正方形，外层圆角 10px；缩略图填满方框而不拉伸；不显示文件名、大小、保存/读取说明。裁切掉边缘是缩略图效果，原图在预览中应完整可看。

UI-02 · P0 · 文件按内容收缩、长名省略

  • 操作：1）同一草稿添加 a.txt 和长名称文件；2）发送后再检查历史；3）悬停长文件名。
  • 预期：文件卡高 45px、外层圆角 10px；短名卡片随内容收缩，长名最大宽度 180px；名称单行省略，悬停可看全名；定位/另存按钮不被挤出卡片。

UI-03 · P0 · 关闭按钮位置与显隐

  • 操作：1）输入区同时放图片、短名文件、长名文件；2）鼠标移到卡片外；3）依次悬停每张卡；4）移出；5）悬停后点击关闭。
  • 预期：关闭按钮统一在卡片内右上角，图标、尺寸、距边位置一致；默认隐藏，悬停该卡才显示，移出后隐藏；显隐不改卡宽、不挤动文字；关闭只移除目标项。已发送的历史附件不出现草稿移除按钮。

UI-04 · P0 · 单卡没有淡白遮罩

  • 操作：1）只添加一个文件，观察最左侧图标和边框；2）改为只添加一张图片；3）再添加多项并横向滚动到两端。
  • 预期：没有常驻的白色/透明渐隐盖住卡片边缘；单卡完整显示；多项超出输入区时正常滚动裁切，没有整页横向撑宽。

UI-05 · P0 · 正常信息保持简洁

  • 操作：观察已就绪的文件卡，并分别悬停文件名、大小和卡片空白区域。
  • 预期：正常只显示文件名与大小；不出现“已保存”“按需读取”“文档工具提取”等内部处理说明，悬停也不补回；文件名完整标题可以保留。

UI-06 · P1 · 文件大小单位

  • 操作：添加字节数已知的文件，例如 0、999、1000、4096、1000000 字节，比较卡片显示。
  • 预期：分别为 0 B、999 B、1.0 KB、4.1 KB、1.0 MB；普通卡片大小不出现 KiB/MiB。此处是十进制显示，准入上限另见 LIMIT 组。

UI-07 · P0 · 图片预览

  • 操作：1）在输入区点图片；2）关闭弹窗；3）发送后再点历史图片；4）在弹窗内观察宽图和竖图，再按 Esc 关闭。
  • 预期：均能打开现有图片预览，显示正确原图、比例正常；缩略图裁掉的内容在原图中可见；关闭后草稿/历史不变。当前验现有预览弹窗，不要求后续灯箱的切图、缩放等功能。

UI-08 · P1 · 键盘与中文输入法

  • 操作：1）鼠标移出卡片，用 Tab/Shift+Tab 聚焦移除按钮；2）用 Enter 或空格移除；3）重新添加附件，正文 Shift+Enter 换行；4）中文输入法组词时按 Enter 选词，之后再 Enter 发送。
  • 预期：键盘聚焦的关闭按钮可见且有焦点反馈；按键只移除目标项；Shift+Enter 不发送；输入法组词时不误发，确认完正文后才发送。

UI-09 · P1 · 窄窗口和多附件

  • 操作：1）窗口缩至约 400px；2）添加至少七张图片和两个文件；3）在输入区横向滚动并关闭中间项；4）发送后查看图片换行。
  • 预期：输入附件自动换行，超过160px高后可用鼠标滚轮纵向滚动，关闭与发送/停止可达； 历史附件换行并保持靠右；没有整页横向滚动、按钮裁切或被撑开的输入框。 数量验收另覆盖100个普通文件：多行、160px视口、滚轮改变scrollTop和发送按钮在窗口内。

UI-10 · P1 · 主题、页面缩放与系统 DPI

  • 操作：在可用深浅主题下重复 UI-01～UI-04、UI-09；分别测试页面 100%/125%/150% 缩放，以及实际系统 DPI 100%/125%/150%。记录实际测到的组合。
  • 预期：图标、边框、文字与关闭按钮可辨；卡片保持比例，不重叠、不失去操作入口。页面缩放通过不能代替系统 DPI 通过；主题入口不可用时记阻塞。

三、发送、消息归属和历史

SEND-01 · P0 · 纯图片发送

  • 操作：1）添加一张可识别图片，不输入正文；2）发送；3）切到另一聊天再切回；4）重启后再次打开。
  • 预期：纯附件可以提交；用户消息保留图片，不出现空白正文气泡，不因无正文而消失；图片始终归属这条用户消息。

SEND-02 · P0 · 纯文件发送

  • 操作：1）只添加 a.txt，正文留空并发送；2）下一轮要求用 read_attachment 读取该附件的标记；3）重启查看历史。
  • 预期：纯文件可发送并保留文件卡；能读到 A17；重开后卡片、文件名、大小与归属正确。

SEND-03 · P0 · 图文与多类型混合布局

  • 操作：1）按“图 A、文件甲、图 B、文件乙”的顺序添加；2）输入“这是混合附件”并发送；3）缩窄窗口再放宽。
  • 预期：附件位于该条用户正文上方，整组靠右；图片行在文件行上方；图片内保持 A→B，文件内保持甲→乙；换行后右缘仍与用户正文气泡对齐。

SEND-04 · P0 · 只添加不创建空聊天

  • 操作：1）从已有会话A记下侧栏数量；2）点击新聊天，添加文件、编辑正文并选择项目；3）切回A，再点新聊天；4）重复点击新聊天、解绑项目；5）最后发送一次。
  • 预期：点击入口、选择/解绑项目、添加/编辑/移除都不新增空会话；返回唯一未发送草稿时文件/正文不丢； 实际发送只创建一个会话；再次点新聊天是新的空草稿。

SEND-05 · P0 · 导入中和失败项不能提交

  • 操作：1）导入一个足够大、能观察到导入过程的文件，立即点击发送或按 Enter；2）另加假 PNG；3）移除失败项并等待其他导入完成后发送。
  • 预期：导入中/失败时不能提交半成品；失败原因可查看；移除错误项后恢复发送。未观察到导入中状态时，该部分记未触发。

SEND-06 · P1 · 同文连续发送不串附件

  • 操作：1）正文“分析这个”，附文件甲并发送；2）完成后用完全相同正文附文件乙再发；3）切会话、重启，再分别核对两条。
  • 预期：两条消息各有自己的附件，甲乙内容不串；不能因正文相同或发送接近而合并、错绑。

SEND-07 · P1 · 停止后保留原始输入

  • 操作：1）图文或文件消息发送后尽快点停止；2）再正常发送另一条；3）重启查看前一条。
  • 预期：已受理的原始正文与附件各保留一份，不显示内部路径/模型输入说明；不会被下一条附件覆盖；没有停止后补出的幽灵卡片。首片前停止与输出后停止分别记录。

SEND-08 · P1 · 提交未受理时保留草稿

  • 条件：可以明确制造“提交 RPC 尚未受理即失败”的测试环境；无法稳定触发则记未触发。
  • 操作：草稿填正文与附件，制造该失败并点发送，恢复连接后重试。
  • 预期：未受理的正文和附件保留，可重新提交；不能假装成功清空。模型在受理后返回 401/网络错误属于已发送回合失败，不能用来验证本条的草稿保留。

四、草稿、切换和重启

DRAFT-01 · P0 · 切设置不丢草稿

  • 操作：1）草稿输入两行文字，添加两项附件；2）打开设置；3）返回聊天；4）再次来回切换。
  • 预期：正文、附件、顺序及可用状态保留；没有因输入组件卸载而重新导入、丢卡或重复卡。

DRAFT-02 · P0 · A/B 聊天隔离

  • 操作：1）A 草稿写“A 草稿”并附文件甲；2）切 B 写“B 草稿”并附文件乙；3）来回切换后只发送 B。
  • 预期：两份草稿互不覆盖；B 发送后只消费 B 的内容；A 的正文和附件仍在。

DRAFT-03 · P1 · 导入中切换聊天

  • 操作：1）在 A 导入较大文件；2）导入完成前切 B 并添加另一文件；3）等待后回 A。
  • 预期：A 的迟到结果只更新 A，不能落到 B；B 的附件不被清空；回 A 能看到原导入的完成或实际错误。

DRAFT-04 · P0 · 导入中移除不复活

  • 操作：1）导入较大文件；2）导入未结束时悬停关闭该项；3）等待数秒，切设置/聊天再回来。
  • 预期：移除项不因迟到成功回包复活；不再阻塞发送，不在下一条消息里出现；其他项不受影响。

DRAFT-05 · P0 · 未发草稿重启恢复

  • 操作：1）输入正文并等两项附件就绪；2）不发送，正常退出应用；3）重启回同一草稿。
  • 预期：正文、附件和预览恢复；可继续移除或发送；不会凭空新增已发送用户消息。

DRAFT-06 · P1 · 中断导入后的恢复

  • 操作：1）只用测试数据，在能观察到导入中时退出应用；2）重启回草稿；3）尝试重试，再重新选择原文件。
  • 预期：未完成项显示需要重新附加/导入失败，不伪装为可发送；重启不能恢复内存 File 时应要求重新选择原文件；重新附加后正常。

DRAFT-07 · P0 · 提交期间的新编辑保留

  • 操作：1）发送正文甲和附件甲；2）提交过程或回复期间立即在输入区写正文乙、加附件乙；3）等待旧发送完成，再切设置返回。
  • 预期：旧提交只消费自己的快照；正文乙和附件乙留在草稿，不被旧成功回包清掉；历史中的甲不被改成乙。

DRAFT-08 · P1 · 交互面板替换输入区

  • 条件：已发送的聊天 A 正在运行，能通过工具审批、ask_user 或计划审批显示交互面板。
  • 操作：运行中先填写下一轮正文并加附件；让交互面板替换输入区，处理面板后查看草稿。
  • 预期：面板出现/消失不会消费下一轮草稿；恢复输入区后正文与附件仍在。未成功触发面板时记未触发。

五、文件副本、导出和删除

FILE-01 · P0 · 原始文件移动或删除

  • 操作：1）导入并发送测试 TXT/图片；2）将源文件移到别处或删除源文件；3）回聊天读取 TXT、打开图片；4）重启再试。
  • 预期：受管副本仍可读、可预览；不会因为原路径失效而丢历史。只处理自己准备的测试原件。

FILE-02 · P0 · 文件另存和取消

  • 操作：1）在历史文件卡点击“另存”；2）保存到另一个测试目录并打开核对；3）再次另存时点取消。
  • 预期：默认文件名为原名，保存内容与原件一致；取消不删原件、不新增空文件、不改卡片；可用系统散列工具进一步比较原件和另存文件。

FILE-03 · P1 · 定位与图片导出

  • 操作：1）点历史文件卡的定位按钮；2）在图片预览中点“定位原件”“另存为”；3）打开导出的图片。
  • 预期：定位的是受管副本所在位置；图片另存保留原图内容、比例和尺寸，不是 45px 缩略图；不是任意错误路径。

FILE-04 · P0 · 共享原件不会误删

  • 操作：1）A、B 分别发送同一个测试文件；2）在另一草稿也附加同一文件再移除；3）删除 A；4）去 B 读取、另存并重启再读。
  • 预期：移除草稿项/删除 A 不影响 B 的有效引用；B 始终可读；没有因内容去重而提前删除仍在使用的原件。

FILE-05 · P1 · 删除带附件的聊天

  • 操作：1）A 有历史附件和未发草稿；2）让 A 另有导入未完成时删除 A；3）切 B、等待后重启。
  • 预期：A 不被迟到导入复活，A 的草稿不出现在新聊天/B；B 正常。磁盘引用释放的完整性另由自动化核对，不以“侧栏消失”推断磁盘已经清干净。

FILE-06 · P1 · 受管对象缺失或被修改（高级）

  • 条件：使用独立测试数据目录，且能确认目标只属于本轮测试；不要修改日常会话的附件目录。
  • 操作：1）通过定位找到受管副本；2）暂时改名使其缺失，重开/预览/读取；3）还原；4）另用一份样本修改其字节后再读取。
  • 预期：缺失或完整性不符有明确失败，卡片不静默消失，不把篡改后的内容当原件成功发送；还原文件并重新打开/加载后再核对，不要求错误卡片自动轮询恢复。

六、本地文档读取

这组先不配置媒体 MCP，便于确认基础文档工具本身可用。正常读取可用文字模型； 按通用触发语明确要求 read_attachment，并展开工具记录核对范围。

DOC-01 · P0 · TXT、JSON、源码和 CSV

  • 操作：分别发送文本、JSON/源码、CSV，问“列出正文标记/字段名/函数名/第二行第三列的值，并说明读的是哪个附件”。
  • 预期：调用文档工具，返回的源内容正确，答案与样本一致；没有只根据文件名猜测；不要求 CSV 自动成为 Excel 工作表模型。

DOC-02 · P1 · 编码与长文本续读

  • 操作：1）读取 UTF-8、带 BOM 的 UTF-16LE；2）读长文本，要求继续到尾标记；3）再读一份无法按支持编码解码的文本。
  • 预期：支持编码的中文正确；长文本能使用 nextCursor 继续，首尾标记都能找到；不把首段截断结果说成全文；不支持编码明确失败，不输出乱码假成功。

DOC-03 · P0 · 中文 PDF 按页读取

  • 操作：发送两页中文文字 PDF，问“请分别读取第 1、2 页，列出每页编号与一句正文”。
  • 预期：无需配置 PDF 原生模型开关；read_attachment 逐页读取、页码和中文正确；第 2 页不能重复第 1 页。高级核对：第 1 页 cursor=0，第 2 页 cursor=1。

DOC-04 · P1 · 扫描 PDF 无分析服务

  • 操作：确保未配置文档视觉分析，发送纯扫描 PDF，要求读取页面上的具体文字。
  • 预期：说明该页未提取到文字、需要相应分析能力；不能编造扫描文字，不能把文件导入成功当 OCR 成功；原件及卡片仍可保留、另存。

DOC-05 · P0 · DOCX 标题、段落和表格

  • 操作：发送 DOCX，问“列出两个标题、第二段原文和表格中指定行列的值”；随后问“能否根据此次提取确认嵌图中的内容？”
  • 预期：标题/段落/表格文字对应正确；输出中表格边界可辨；文字提取不能冒充已分析嵌图、修订、批注或完整页面排版。

DOC-06 · P0 · XLSX 工作表与范围

  • 操作：1）发送 XLSX，要求先列工作表；2）再读取“销售”的 A1:C3；3）读取“库存”的指定范围。
  • 预期：工作表名称和范围正确，单元格地址与值对应；不会混到另一表；只附加文件时不在卡片里展开整张表。

DOC-07 · P1 · XLSX 公式缓存边界

  • 操作：1）读取已有 Excel 计算结果的公式格；2）如有合适样本，再读取没有缓存的公式格；3）询问结果是否刚刚重算。
  • 预期：保留公式与已保存的缓存结果；无缓存明确标“未计算”；不得声称文档工具已重算公式或刷新外链。没有无缓存样本时，该部分记阻塞。

DOC-08 · P1 · PPTX 页面顺序与备注

  • 操作：发送调整过顺序的两页 PPTX，要求按实际顺序列页标题，并读取指定页的演讲者备注。
  • 预期：按演示文稿关联顺序读取，不按内部文件名猜顺序；标题、表格文字和备注对应；不冒充看过图片、SmartArt、动画与版式。

DOC-09 · P1 · 损坏、加密和不支持格式

  • 操作：分别发送损坏/需要密码的 PDF、损坏 DOCX、旧 DOC/XLS、ZIP；逐一请求用文档工具读取正文。
  • 预期：导入层允许保留的原件有卡片、可另存；解析阶段分别给出真实错误或缺少解析能力，不伪造成功空结果；无配置时不静默安装外部转换器。

DOC-10 · P1 · 参数错误与超范围

  • 操作：让模型调用 read_attachment 读取不存在的工作表、PDF 不存在页、非法 XLSX 范围，以及 A1:CV51（5100 格）。
  • 预期：工具明确报错，Host 和聊天不崩；不能自动把错误范围改成另一范围后声称请求已完成；随后读合法范围仍正常。模型未按要求调用则记未触发。

DOC-11 · P1 · 长内容和停止解析

  • 操作：1）读取长文档或返回长结果的服务，要求接续读取；2）在实际解析运行时点停止；3）再发普通消息与小文件读取。
  • 预期：正文结果有明确范围；本地文本用 nextCursor，超长分析可能提供完整结果文件；停止不把取消当成功，后续聊天可用。大文档未触发长结果/运行中停止时分别记未触发。

DOC-12 · P1 · OOXML 命名空间与关系写法兼容

  • 操作：分别读取素材“10 兼容性复现”中的 XLSX、PPTX，并与“03 文档”中内容相同的版本对照。
  • 预期：两份原件正常读取；XLSX两个工作表及销售C2/C3公式缓存42/40正确；PPTX实际两页顺序、表格及备注正确；与常规版本一致，原件字节不变。不以常规版本通过替代原件通过。

七、模型图片能力与降级

MODEL-01 · P0 · 图片模型实际识图

  • 条件：主模型确实支持图片，且设置中的图片输入声明开启；新建聊天；无需图片 MCP。
  • 操作：发送含明显物体/颜色与可辨短编号的图片，问“图片里是什么颜色和形状？编号是什么？”
  • 预期：答案与图片核对；走主模型图片输入，无需额外配置图片分析服务。只回复“看到了”不能判通过。

MODEL-02 · P0 · 文字模型且无图片分析服务

  • 条件：选用文字模型，或显式关闭该模型的图片输入；未配置图片 MCP；新建聊天。
  • 操作：添加图片，观察发送按钮提示并发送，再要求分析图片中具体内容。
  • 预期：可作为文件引用发送，图片仍有卡片与预览；发送提示可为“作为文件发送”；没有可用内容输入时明确说明，不能编造视觉内容。

MODEL-03 · P1 · 图片声明保存与继承

  • 操作：1）打开原本支持图片的模型配置；2）确认选项和“视觉”标签；3）关闭保存，检查设置/菜单标签消失； 4）回同一聊天附一张新图并发送，检查该轮 POST 的 image_url/图片块；5）重新开启再附不同新图，核对图片块恢复。
  • 预期：关闭不被目录默认值重新打开；保存后的下一次提交使用新能力，同聊天也生效； 设置和菜单标签同步；不根据模型名称或旧图历史回答判断。最后恢复本轮前的配置。

MODEL-04 · P1 · 文字主模型委托图片 MCP

  • 条件：文字主模型，已配置可用图片分析 MCP，按 MEDIA-01 新建聊天。
  • 操作：发已知内容图片并明确要求通过 read_attachment 分析；观察主模型、内层 MCP 工具和最终回答。
  • 预期：分析经配置的图片工具执行，返回文字给原主模型继续回答；不自动更换主推理模型；MCP 认证按服务自身配置。

八、文档视觉与视频 MCP（具备服务再测）

MEDIA-01 · P1 · 配置、保存、清除与快照

  • 操作：1）设置 → MCP 服务器 → 附件分析工具；2）选择已安装的本机 stdio 服务，填写工具原名、字符串路径/问题参数名，按需填页码参数、格式与容量；3）保存、重开核对；4）新建聊天调用；5）修改/清除后再新建聊天比较。
  • 预期：配置可保存与清除；新聊天按新绑定工作；已装配聊天不保证热切换，不据此判配置未保存；旧绑定恢复后重新开聊天复测。配置本身不安装服务或上传文件。

MEDIA-02 · P0 · 视频有服务时的完整链路

  • 条件：有效 video 绑定、凭据可用、测试视频符合该服务格式/容量；新建聊天。
  • 操作：只附或图文混合附加短视频，问“分别描述开头和结尾；若分析了声音，复述那句语音，并说明分析覆盖范围”。
  • 预期：read_attachment 委托配置的视频 MCP，服务分析文字回到主模型，卡片与历史保留原件；答案按已知片段核对。不要求产品把视频原生字节发给主模型。

MEDIA-03 · P0 · 视频没有服务

  • 操作：清除视频绑定，新建聊天，附 MP4 后请求分析其中动作。
  • 预期：原件可作为文件保留，卡片可另存/定位；分析时明确缺少可用能力；不能把“已发送附件”当“看懂视频”，不自行抽帧/转写后声称既定视频路线已生效。

MEDIA-04 · P1 · 音轨和时间覆盖不确定

  • 操作：1）使用未声明音轨分析能力的绑定，发送带语音视频；2）查看工具返回的警告与模型回答；3）让服务只报告部分时间段或不报告覆盖范围。
  • 预期：未声明音频能力时保留“音轨未分析”的边界；未报告时间覆盖就不能声称看完整段；仅有画面证据不能编造说话内容。

MEDIA-05 · P1 · 扫描件与页面图表

  • 条件：有效 document 绑定；指定页测试需配置可用的字符串页码参数；新建聊天。
  • 操作：1）发送扫描 PDF 请求识别其已知文字；2）发送带图表文档，明确要求用 read_attachment 的 visual=true、pages="2" 分析第 2 页图表。
  • 预期：扫描页/视觉需求委托文档分析 MCP；路径、问题、页码映射正确；结果与样本核对。没有页码参数时应明确不能保证只分析指定页面，不能假称已限定页码。

MEDIA-06 · P1 · 服务、工具和参数映射不兼容

  • 操作：逐项制造：绑定服务未启用 / 工具原名不存在 / 工具被隐藏 / 路径参数名写错 / 参数类型不是字符串 / 绑定 HTTP 服务 / 工具只收 URL；每改一项新建聊天调用。
  • 预期：各项给出实际缺失或不兼容原因；不得把本机路径伪装成公网 URL，也不得显示为分析成功。逐项记录，测完恢复原配置。

MEDIA-07 · P1 · 媒体服务格式与容量

  • 操作：1）把绑定的支持格式设成不含当前附件后调用；2）恢复格式，设置容量小于附件实际大小再调用；3）改成合法声明并新建聊天重试。
  • 预期：不支持格式、容量超限被明确拒绝，原件仍在；合法配置后才进入服务；Cogent 准入上限与某个厂商服务限制分别判断。

MEDIA-08 · P1 · 审批允许、拒绝、停止

  • 条件：权限用“变更前确认”，计划开关关；配置工具在当前规则下需要审批；每个分支重新触发调用。
  • 操作：1）对嵌套媒体工具允许；2）另一次拒绝；3）另一次在执行中停止，之后发新消息。
  • 预期：允许后实际执行；拒绝不得执行并伪装成功；停止能取消链路、后续聊天可用；嵌套工具不能绕过审批。拒绝/停止后的最终回答不包含捏造的分析结论。

MEDIA-09 · P1 · 服务真实失败与无文本结果

  • 条件：有可控制错误结果的测试 MCP，或能稳定复现对应服务错误；不需要用真实收费请求反复制造故障。
  • 操作：分别测试认证失败、断网、超时、返回 isError、只返回图片/空白文本；每次检查工具记录和最终回答。
  • 预期：错误按失败呈现，嵌套 isError 不转成成功；只返回图片不能当作文字主模型已经获得分析文字；未触发的故障单独记未触发。

九、数量、大小与图片校验

这里必须按字节准备边界样本，不能拿卡片上四舍五入的 MB 数值代替。 1 MiB=1048576 字节；卡片大小仍按十进制 KB/MB 显示。

边界 精确值 主要观察点
普通文件数量 无固定数量上限 21/100个小文件均可发，仍受总容量约束
每条图片数量 20 张 普通文件不占名额；第21图列未添加，合法部分保留

LIMIT-01 · P1 · 普通文件与图片分别计数

  • 操作：1）一次选21个小文件并发送；2）另起草稿选100个小文件；3）另起草稿一次选21张有效小图片和两个普通文件；4）打开未添加明细；5）移除一张图片后补回被拒图片。
  • 预期：普通文件全部可导入/发送，不因超过20被截断；混合批次接收20图和两个文件，只列第21图的文件名及20张上限原因；合法部分可发，移除腾出图片名额后可补回。明细可滚动、可清除，不撑高输入框遮住发送。

LIMIT-02 · P1 · 单文件上限

  • 操作：分别添加 104857600 字节与 104857601 字节的普通 .bin 测试文件。
  • 预期：前者通过导入，后者不加入并在明细显示名称/单文件容量原因；路径源先探测再复制，不写入超额副本。不可解析与准入是两项判断；通过准入不等于最大容量性能已通过。

LIMIT-03 · P1 · 合计上限

  • 操作：1）添加80 MiB、80 MiB、40 MiB三个文件；2）再加1字节；3）查看未添加明细并发送合法部分；4）另起草稿一次选这四个文件。
  • 预期：前三项恰好200 MiB，均可就绪；多出1字节不加入，明细列名称/合计容量原因，前三项仍可发；批量输入同样部分接收。若无解析器，用“作为文件发送”验收，不要求理解正文。旧数据若已超过总量，仍提示且禁发直到移除。

LIMIT-04 · P1 · 图片容量和像素

  • 操作：用真实有效图片分别跨过 20 MiB 和 4000 万像素边界；另用普通小图片作为对照。
  • 预期：超限图片明确失败，不能当正常原生图片发送；小图片正常。仅给 PNG 尾部补零或篡改宽高头不算有效边界图片样本。

LIMIT-05 · P1 · 假图片、损坏图片与重试

  • 操作：1）添加改名为 PNG 的普通文本，或真实损坏 PNG；2）悬停查看失败原因；3）尝试重试；4）移除后添加正常图片。
  • 预期：图像头/类型/解码不合法不会静默省略后假装成功；错误卡仍维持尺寸，重试和关闭不互相遮挡；原件没修好时重试仍失败；替换为有效图片后可正常发。

LIMIT-06 · P1 · 导入队列、移除与跨草稿

  • 操作：一次添加至少5个需等待复制的文件，观察等待/导入状态；移除一项排队文件及一项在途文件；切另一聊天添加文件后返回；另测导入中退出重启。
  • 预期：全应用最多两项在途，其他项等待；排队移除不开始复制，在途移除不被迟到结果复活，剩余任务继续；切聊天结果归原草稿。重启的未完成项明确要求重新选择，不假装就绪。准确并发由自动化核对。

LIMIT-07 · P1 · 模型额度包含历史图片

  • 条件：可控制有效模型的inputLimits及本地SSE测试服务；不靠真实收费API反复制造超额。
  • 操作：声明每请求最多1图，先发送1图成功，再在同聊天加1图；新聊天再发1图。另检查单消息额度和UTF-8/Base64容量阈值。
  • 预期：第二次提示含历史共2图，HTTP请求数不增加；新聊天1图可发；异步原onPayload变换正常且观测保存有效对象。不声明的额度不发明；字节校验是SDK前请求对象，不声称等于所有SDK最终线上字节。

十、进阶稳定性和平台补测

ADV-01 · P1 · 解析超时、并发与取消

  • 条件：能稳定触发长时间解析的测试文档，或受控解析测试环境；普通手测未触发就保留未测。
  • 操作：请求同时读取至少三份复杂文档；等待或在排队/运行中停止，之后读取小文档。
  • 预期：本地解析同时最多两项；超过 30 秒的实际解析有明确超时；排队或运行中取消不写成成功；Host 保持响应，后续读取可用。准确并发与计时以日志/自动化证据核对。

ADV-02 · P1 · 长会话与压缩后的附件

  • 操作：在已有多轮内容的测试聊天发送附件，继续对话至可压缩；完成压缩后切换聊天、重启，再检查早期附件并尝试预览/另存。
  • 预期：保留式历史中的附件仍归属原用户条目，原件可访问；不因压缩条插入而错绑下一条。会话过短无法压缩时记未触发；不强制模型在摘要里逐字记住全文。

ADV-03 · P1 · Linux 与真实文件管理器

  • 操作：在目标 Linux 分别执行 IN-01、02、05、06、07、UI-07、FILE-02；记录文件管理器名称与桌面环境。
  • 预期：原生文件 URI 剪贴板和鼠标拖拽正常，中文/空格路径正确，原生选择与另存对话框可用；Windows 或 DOM 模拟通过不能代替本条。

ADV-04 · P1 · 发行包资源

  • 操作：在实际发行包重复截图粘贴、原图预览、中文 PDF、DOCX/XLSX/PPTX 读取；按目标系统核对最低 Node/glibc 环境。
  • 预期：解析 worker、共享构建文件、PDF 字体/CMap/wasm 等资源可被实际找到；不是仅开发模式可用。没有可运行发行包/目标环境时记阻塞。

ADV-05 · P1 · 外部接口与未来上传接线（自动化为主）

  • 操作：有协议测试环境时验证 HTTP/WS 即使用 admin 凭据也不能调用 attachments.*；运行上传器替身回归验证真实字节、进度、错误和取消。
  • 预期：附件导入/预览不开放为任意远程文件入口；local 分支不调用上传器，server 未注入时明确失败；当前没有服务器上传产品入口，不能把普通模型 API 流量误认为已实现文件上传。
  • 说明：这项无需在 UI 寻找不存在的上传按钮；无协议/替身测试环境就记阻塞，自动化证据不替代用户桌面手测。
