# 技能座手动验收

机制见 [技能座](../模块/技能座.md)，原理见 [技能座笔记](../技术笔记/技能座.md)。
本册保留 GUI、手放文件与真实模型消费场景；步骤是预期，不代表本次已执行。

## 前置与测试数据

由用户启动应用；准备 `<临时工作区>`、一个可靠工具调用模型及该项目的会话。
不改已有个人技能，统一用 `test-` 前缀或确认无重名的 `commit-check`。

| 数据 | 位置/内容 |
| --- | --- |
| 用户定义/状态 | `~/.cogent/skills/<name>/SKILL.md`；`~/.cogent/skills.json` 的 `disabled` 数组 |
| 项目定义/状态 | `<临时工作区>/.cogent/skills/<name>/SKILL.md`；同级 `skills.json` 的 `overrides` 对象 |
| 生态只读来源 | `~/.agents/skills` 与 `<临时工作区>/.agents/skills`；使用独立测试技能，不依赖私人项目 |
| 基准技能 | name=`commit-check`，描述=`提交前的检查清单，涉及 commit 前使用`；正文为“先检查状态，再运行检查，最后报告结果” |
| 项目同名版 | 相同 name，描述=`项目专用检查`，正文末行加“回答以 [PROJECT] 开头” |
| 手动调用版 | `test-manual`，frontmatter 加 `disable-model-invocation: true`；正文“回答以 [MANUAL] 开头” |

`已禁用` 是最终求值；`手动调用` 不进模型清单；`生态目录` 定义只读、仍可启停；
`项目定义` 表定义在项目，`项目覆盖` 表本项目有启停覆盖。选过作用域后固定选择；
未手选时默认跟随活跃会话归属项目。

## GUI 与落盘

本组不需模型。A 组按序运行；空态必须在没有任何有效技能的隔离环境验证。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| SK-01 | 设置→技能→本机/用户；另验空列表 | 两行工具栏、作用域/计数/搜索、刷新/新建；空态有指引，不把已有生态技能误判为空态失败 |
| SK-02/03 | 新建基准技能，查看 SKILL.md | 列表描述正确、默认启用；frontmatter 含转义后的 name/description，正文原样保留 |
| SK-04 | 名称/描述分别留空保存 | 弹窗内必填错误、草稿保留，无新目录 |
| SK-05 | 尝试 `Commit`、`bad name`、`bad_name`、中文、首尾/连续连字符、65字符名字 | 弹窗内说明非法原因，不关闭、不半写；创建规则不外推为上游手放文件的发现规则 |
| SK-06 | 描述输入超过1024字符 | 弹窗内超长错误，未落盘 |
| SK-07/08 | 编辑后保存引号、反引号、中文、emoji、多段正文，再次打开 | name锁定；描述/正文回填完整，保存往返无损 |
| SK-09 | 删除本次新建技能，再刷新 | 行/计数/定义目录消失，启停死名清理 |
| SK-10 | 建第二枚测试技能，分别按名称/描述搜索后清空 | 搜索正确过滤，清空恢复；不改变启停状态 |
| SK-11 | 手建一枚目录型 SKILL.md 与根下裸 `.md` 技能，刷新 | 两种合法形态均被发现；名称与描述按 frontmatter 展示 |

## 作用域与启停

恢复基准用户技能，再建项目同名版；另建用户独有 `test-useronly`。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| SK-20 | 打开作用域菜单，切用户与临时项目 | 级联子菜单、项目路径/覆盖说明正确；手选后不被会话切换覆盖 |
| SK-21/23 | 项目下新建同名版，检查项目目录 | 只显示项目胜出的定义与冲突诊断；仅项目目录新增文件 |
| SK-22 | 项目作用域查看用户独有技能 | 可启停，无编辑/删除；项目定义行仍可编辑/删除 |
| SK-24 | 删除项目同名版 | 用户版本重新胜出，项目定义徽标消失 |
| SK-30 | 用户级禁用 test-useronly | 已禁用徽标，用户 disabled 包含该名 |
| SK-31 | 用户级启用，再在项目级禁用 | 仅该项目覆盖 false，显示项目覆盖/已禁用；用户定义不变 |
| SK-32 | 项目级点重置 | 覆盖键消失，回落用户启停态；若用户禁用则仍禁用 |
| SK-33 | 用户禁用、项目强制启用 | 项目最终启用并显示覆盖；其他项目仍按用户禁用 |
| SK-34 | 删除测试定义，查看同级状态 | 对应禁用/覆盖死名清理，不影响其他技能 |

## 真实模型与同会话刷新

本组使用同一项目会话；确认项目版 commit-check 启用、其他测试技能按需关闭。

| 编号 | 触发操作/输入 | 预期 |
| --- | --- | --- |
| SK-40 | 问“列出当前可用技能及描述” | 出现项目版 commit-check；不要求模型列满无关技能 |
| SK-41 | “按 commit-check 技能办事，先告诉我你要做什么” | 模型先 read 胜出定义正文，再按正文回答；验证真实渐进加载 |
| SK-42 | 设置禁用后，同会话下一轮再问可用技能 | 新请求清单不含该技能；已有对话记忆可能仍提及，必要时在控制台核对清单段 |
| SK-43 | 启用后发 `/skill:commit-check 只列第1步` | 用户气泡保留原指令；模型看到正文与参数、按第1步回应 |
| SK-44 | `/skill:no-such-skill 你好` | 未命中按普通文本透传，不崩溃 |
| SK-45 | 外部编辑器将正文改成4步，不刷新列表，同会话调用 | 下一回合读到新正文，无需新会话 |
| SK-46 | 创建手动调用版，先问清单再 `/skill:test-manual 你好` | 普通清单不含它；手调加载正文并回答带 [MANUAL] |
| SK-47 | 禁用手动版后，新会话发同一 /skill 指令 | 普通文本透传，无正文标记；新会话用于排除历史正文记忆 |

## 坏文件与生态目录

破坏性文件用独立测试配置或先备份、测后恢复；不覆盖个人真实状态。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| SK-50 | 手放缺 description 的测试 SKILL.md，刷新 | 配置诊断显示该文件错误，其他技能仍可用 |
| SK-51 | 手放非法 name 但其他字段完整的文件 | 展示上游名字警告；发现阶段的警告语义与表单创建拒绝分开核对 |
| SK-52/53 | 隔离环境把 skills.json 分别写坏 JSON、错误形状 | 文件级诊断可见，列表不崩；按模块边界回落空状态，恢复原文件后正常 |
| SK-70/71 | 在临时项目 `.agents/skills/test-eco/SKILL.md` 放合法测试技能 | 生态徽标可见，只能启停，无编辑/删除按钮 |
| SK-72/73 | 禁用/启用生态技能后在同会话下一轮提问；再 /skill 调用 | 清单随启停变化，启用时可读取并展开生态正文 |
| SK-74 | 同一作用域 `.cogent/skills` 新建同名定义 | 自有定义胜出、生态徽标消失并有冲突诊断；删除自有版恢复生态版 |

描述截断、20k预算降级与 realpath 去重主要由自动回归承担；需要排查真模型时再
单独构造大量测试技能，不把模型回答不精确直接归因为 formatter 错误。
测后只删除本次创建的定义/状态键，恢复备份；原有 `.agents` 生态内容保持原样。
