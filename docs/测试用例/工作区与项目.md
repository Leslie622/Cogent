# 工作区与项目验收

机制见[工作区与项目](../模块/工作区与项目.md)，视觉配方见[UI布局](../UI布局.md)。

## 侧栏折叠

自动执行 `npm run test:sidebar-animation-browser`，驱动自行启动并关闭独立 Vite 服务、
离屏 Electron 窗口与临时 profile，不连接真实 Host，不读写用户会话及布局偏好。

- 导航几何：240/320px 宽，长短列表，置顶/项目/最近/项目子列表的完整与反向开合；
  逐帧检查行高和图标行内位置，检查常驻 DOM、收起不可聚焦及嵌套展开态保留。
- 静止像素：完整 AppShell，浅/深色、长短列表、0/0.4px 纵向起点；连续绘制期间
  按物理像素裁切并比对“新聊天”、搜索、首页图标。整栏收拢时比对仍完整露出的
  “新聊天”，开合全过程比对首页图标；不把正常裁切或恢复显示时迟到的全收起帧算成抖动。
  整栏连续开合两轮，收集图标尚完整露出时的中间帧。
- DPI 1/1.25/1.5 分别运行；系统减少动画另测即时开合。离屏窗口以 60fps 绘制，
  普通隐藏窗口可能降低 rAF 频率，不能用它的首尾截图冒充连续帧证据。
- 长列表使用 300 条会话：检查屏外子树确实跳过渲染，滚动到底后末行恢复且能命中，
  滚动高度保持；聚焦屏外末行时恢复渲染并滚入视口。像素矩阵的长列表同为 300 条。

性能对照执行 `npm run test:sidebar-animation-browser -- --profile`：125% DPI、24/300 条
会话，对“最近”“项目”和整栏各交替测四次。基线仅在验收页关闭屏外渲染跳过，组件、
数据与时长相同；输出样式计算、布局、主线程时间和最大 rAF 帧间隔的均值，不设跨机器
固定性能门槛，也不把离屏回调间隔当成实际显示器帧率。该模式独立于行为和像素验收。

用户自行启动应用后复核实际显示器效果：

1. 分别折叠/展开整个会话列表、“项目”“最近”和项目子会话，观察“新聊天”左侧图标与
   顶部搜索图标：静止区域不抖动、不忽清忽虚；列表按高度平滑收拢，行内容不被挤扁。
2. 在动画中途反向点击，确认自然续接；分区重开保留项目原展开态，收起内容不能 Tab 聚焦。
3. 在当前 Windows 缩放比例下检查浅/深色、长短列表；短列表不预留滚动槽，长列表保留
   原生滚动条；长列表滚动到底、返回顶部和 Tab 聚焦均能恢复行内容，菜单动作仍可用。
   自动回归不能代表所有显卡、驱动及实际显示器的动效观感。
