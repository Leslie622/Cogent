# MCP 座手动验收

机制见[MCP座](../模块/MCP座.md)，原理及上游源码见[技术笔记](../技术笔记/MCP座.md)。
本册操作是待执行预期，不能由 mock 自动回归推断真实厂商、浏览器或多平台进程已通过。

## 环境与前置

- 使用独立 `COGENT_HOME`、临时工作区和测试密钥，不修改个人现用 MCP 配置。
- 应用由用户启动；准备一个支持可靠工具调用的模型及一个原生支持图片的模型。
- 准备已安装的 filesystem stdio 服务、可控制的 Streamable HTTP / Legacy SSE 服务，
  以及至少一个真实 OAuth MCP。记录系统、Node/Electron 版本、服务版本、端点与协议版本。
- 初次只需 stdio 即可验证设置和工具链；涉及 OAuth/CIMD 的条目需对应真实环境，不能记为跳过即通过。

## 配置、信任与诊断

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| MCP-01 | 新建 stdio 服务，保留缺省暴露档，展开详情 | 状态连接中→已连接，显示工具、schema、资源/提示词与诊断；默认 deferred |
| MCP-02 | 分别导入 Claude/Cursor、VS Code、OpenCode 配置，再表单/JSON往返编辑 | 命令/args/env/cwd/oauth/toolExposure/未知扩展字段保留；不支持的 input 占位符明确提示，不悄悄丢字段 |
| MCP-03 | 配置无效命令、断开的 URL、服务端 stderr，再点击重连/复制诊断 | 显示实际失败；恢复后可重连；尾日志有界且不含测试密钥值 |
| MCP-04 | 两个项目和多会话同时调用同一不依赖目录的用户服务 | 只启动一份进程；依赖项目目录的定义分别隔离；单项目开关不改变其他项目策略 |
| MCP-05 | 项目放 `.mcp.json` / `.cogent/mcp.json` 新定义，打开设置但不信任 | 显示来源/摘要审阅；未信任不启动进程、不发网络探测；原用户服务仍正常 |
| MCP-06 | 信任后调用，再修改文件字节，或同目录绑定另一项目ID | 只有被授权项目可用；文件变化重审，旧摘要不可授权；另一项目不能借用已连实例 |
| MCP-07 | 从另一客户端配置检测入口选择导入 | 探测只列候选路径；选择后才读取正文，不能借此读取任意文件 |
| MCP-08 | 用缺省 `COGENT_HOME` 在用户主目录开会话，用户级已配 stdio 服务，让模型查找并调用其工具；再把该目录登记为项目，在项目页改覆盖档 | 设置页与会话作用域都显示该服务为受信的用户定义并共用一条连接；模型首轮有 `tool_search` 与 MCP 提示段，可搜索并调用；项目页覆盖被明确拒绝，用户级定义不变 |

## 工具、审批与运行期

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| MCP-10 | 默认 deferred 服务让模型查找并调用工具 | 初始不灌全量schema；tool_search发现后能正常调用，结果回灌 |
| MCP-11 | 同一会话切 server/单工具 direct/deferred/hidden，服务端发list_changed | 下一回合工具表更新；禁用/隐藏/移除工具不能被旧排队调用执行 |
| MCP-12 | ask调用带只读提示工具，auto/plan再调；plan调用破坏性工具 | ask仍询问，auto/plan只读放行；破坏性在plan被拦；高风险审批显示服务与工具身份 |
| MCP-13 | 选择本会话允许此工具/此server只读工具，再换会话 | 授权只在原会话命中；不写成其他工具/项目的通配授权 |
| MCP-14 | 删除会话、项目连接闲置超期、重连、关闭应用，检查PID和孙进程 | 引用按约释放；项目连接闲置及应用正常关闭时回收进程树；无误杀其他服务。分别在Windows和目标Linux执行 |

## 环境变量与 OAuth

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| MCP-20 | 在隔离宿主设置测试环境变量，以 `${env:MCP_TEST_TOKEN}` 显式注入服务 env/header；另验默认值和项目路径 | 连接时单遍展开；未声明的宿主敏感键被清洗；缺失变量明确报错；页面无密钥管理入口 |
| MCP-21 | 导入含静态API Key/header/OAuth clientSecret/查询参数URL的测试配置，再编辑保存；另在独立Host执行 `mcp.sync` | 原字段保持原定义，不生成UUID键或替换URL；静态配置保存不依赖main；旧 `${secret:KEY}` 引用明确提示改用环境变量，原文件不自动改写 |
| MCP-22 | 在隔离根准备损坏/跨机密文，或模拟安全存储不可用/basic_text；启动后重新登录；另验加密/写盘失败 | 桌面Host仍完成握手，OAuth空快照且日志/status保留故障，读取不改旧文件；写入绝不回退明文，成功加密提交才自愈，失败保留缓存与文件 |
| MCP-23 | 真实受保护MCP点击登录，浏览器完成PKCE回调 | 凭据安全提交后自动重连，同一会话下一回合可用；URL和凭据私有事件不进renderer/HTTP广播 |
| MCP-24 | 手动粘贴错误state/错误回调地址，再粘贴正确回调；另验取消 | 错误回调不消费登录；正确回调成功；取消关闭监听，不接受旧登录回包 |
| MCP-25 | 使token过期并发调用，再登出/重启 | 刷新串行，不重复消耗旋转token；登出清凭据并停止已授权连接；重启按加密状态恢复 |
| MCP-26 | 显式CIMD未配置公开文档；再使用发行方正式文档与回调注册 | 缺前提明确失败；配置 `COGENT_MCP_OAUTH_METADATA_BASE_URL` 后按发布身份授权，不冒充pi或静默换DCR |
| MCP-27 | 比较公开HTTP、静态Header HTTP/SSE与已完成OAuth授权的服务；再查看只有DCR注册元数据的服务 | 仅已有access/refresh token的OAuth服务显示登出；公开/静态认证及只有注册元数据的服务不显示登出 |
| MCP-28 | 两个项目与用户作用域设置同名服务，切换页面并让各作用域发状态事件 | 用户页仅收无cwd/projectId的事件；项目页仅收当前projectId和cwd一致事件；未有runtime时也不能按同名覆盖 |
