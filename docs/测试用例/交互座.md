## 测前速查

**四枚工具一句话**（机制详见 [../模块/交互座.md](../模块/交互座.md)）：

| 工具 | 作用 | 用户可见面 |
| --- | --- | --- |
| todo_write | 会话任务清单（每次调用**全量替换**） | 内容区右上角浮动 TodoStrip |
| ask_user | 结构化提问（1-4 问 × 每问 2-4 选项） | QuestionPanel 占输入区 |
| enter_plan | 切「计划模式」（只读档，幂等） | 权限菜单触发钮变「计划模式」 |
| submit_plan | 方案送审（仅 plan 档可用） | PlanPanel 占输入区 |

**输入区替换链**（挂起面板与输入框互斥）：待审批 ApprovalPanel >
PlanPanel > QuestionPanel > 输入框。挂起期间**无输入框也无停止钮** ——
出路是在面板上作答/裁决；提问可逐题「忽略」（= 跳过该题）。

**权限三档 + 计划开关**（正交开关 v3）：档位 = 变更前确认(ask) /
自主模式(autonomous) / 完全访问(auto)，权限菜单三选一；**计划模式 =
独立开关**（权限菜单顶部开关项 + 权限钮旁「计划」chip，两处同源同步）。
开关开启 = 写/exec 类一律直接拒（错误结果，**不弹审批面板**，完全访问
档也拦——短路优先于档位放行）；read 类与 todo_write/ask_user/submit_plan
照常（交互工具全 read 档）。开关不碰档位：开启时档位保持不变，关闭后
原档自动恢复。

**已知边界（测前知道，不算 bug）**：
- 挂起面板占输入位是设计定调（审批卡母版），没有「取消挂起」钮；
- 挂起中切换会话再切回：面板还在，但**面板上的半成品作答清空**
  （作答是组件本地态，挂起本身在 store 不丢）；
- 挂起态不持久化：重启/关窗即收口，重开后面板不复活。

**环境准备**（一次）：

1. `npm run dev` 启动（自己开），配一个**工具调用可靠**的模型 ——
   弱模型可能不理会点名工具的指令，屡试不调就换模型；
2. 建测试工作区（如 `C:\Users\41631\Desktop\tool-test-ws`，空目录即可）
   + 在里面建会话；另备一条空会话（跨会话隔离用例要用）；
3. 建议每条用例新开会话，避免上下文串扰；
4. **档位口径**：每条用例首行「档位」标注起测档；「ask（缺省）」= 新
   会话缺省档「变更前确认」—— 若你改过设置页「默认权限」或项目默认
   档，开新会话后瞄一眼权限菜单触发钮确认，不是 ask 就手动切回。
   A/B 组其实不挑档（交互工具全 read 档，plan/autonomous 也免审批
   直行），统一缺省档为结果可比。

**触发语配方**（引导真实模型调特定工具；直接点名最稳）：

- todo：`用 todo_write 建任务清单：调研、实现、测试三项，然后逐项完成并更新状态`
- ask：`动手前先用 ask_user 问我：界面风格选哪种？选项：亮色 / 暗色`
- 多问：`用 ask_user 一次问我两个问题：用哪个数据库？部署到哪个环境？各给 2 个选项`
- 多选：`用 ask_user 问我需要集成哪些服务，选项 GitHub / GitLab / Bitbucket，把 multiSelect 设为 true`
- plan：`这个任务较大：先调 enter_plan 进入计划模式只读调研，然后调 submit_plan 把实现方案给我审批，批准前不要写任何文件`
- 清单清空：`清空任务清单（todo_write 提交空数组）`

## A 组 · todo_write 与任务清单条

### IN-01 首次落笔 → 条出现（免审批）
- 档位：ask（缺省；本组任意档皆可 —— todo_write 是 read 档）。
- 步骤：新会话发 todo 触发语。
- 预期：模型调 todo_write 后，**内容区右上角**浮动出现「任务清单」卡（头部
  计数 n/m）；消息流过程区出现工具卡行，摘要形如
  `todo_write(共 3 项：1 进行中 / 2 待办 / 0 已完成)`；**不弹审批面板**
  （read 档直执行）。

### IN-02 全量替换语义（不是增量追加）
- 档位：ask（缺省）。
- 步骤：清单建好后说「再加一项：发布文档，第一项标完成」。
- 预期：条目整段刷新（新增项出现、第一项变完成态），计数同步 ——
  旧清单不是残留追加；每次 todo_write 工具卡摘要的计数与条一致。

### IN-03 条目样式三态
- 档位：ask（缺省）。
- 步骤：建清单后推进到有完成/进行中/待办三态并存。
- 预期：完成项 = **绿色**实心勾图标 + **划线置灰**；进行中 = 深色进度
  图标；待办 = 灰虚线圈。（priority 字段已砍：无高优先级红点。）

### IN-04 折叠 / 展开
- 档位：ask（缺省）。
- 步骤：点展开卡头部行尾的独立折叠钮收起；hover 折叠胶囊；点胶囊
  任意处。
- 预期：整卡**滑入**角内收成计数胶囊（「任务清单 n/m」、无条目、
  贴住右上角；点击后指针多半停在胶囊上，**600ms 冷却期内不触发**
  展开图标动画 —— 冷却过后或指针移开再回来，hover 才出浅底反馈 +
  **右侧动画滑入展开图标** —— 默认零占位，宽度/透明度过渡）；点击
  胶囊**任意位置**展开（不限图标处）；折叠是 UI 本地态：会话间切换保持，离开聊天视图
  （新聊天/设置）再回来复位 —— 不影响清单数据本身。

### IN-05 跨会话隔离
- 档位：ask（缺省）。
- 步骤：会话 A 建清单后切到空会话 B，再切回 A。
- 预期：B 无任务清单条（B 自己没建过）；A 的条还在且状态一致。

### IN-06 重启持久（StoredSession.todos）
- 档位：ask（缺省）。
- 步骤：清单非空时完全退出应用再启动，打开该会话。
- 预期：任务清单条还在，内容/状态与重启前一致（种子来自
  session.messages 的 todos 字段）。

### IN-07 防失忆（cogent_todos 段消费）
- 档位：ask（缺省）。
- 步骤：清单非空时**新一轮**直接问「我现在的任务清单是什么？」。
- 预期：模型不查任何文件、直接按清单回答（每回合系统提示常驻
  权威状态段；自动化钉的是段文本，这里验真模型消费）。

### IN-08 清空清单 → 条卸载
- 档位：ask（缺省）。
- 步骤：发清单清空触发语。
- 预期：模型调 todo_write 传空数组后，任务清单条**消失**（非空才
  挂载）；工具卡结果「任务清单已清空」。
- 附验（全完成自动催清，2026-11-16 补）：推进清单到全部完成后
  **不发清空指令**、随便发条新消息 —— cogent_todos 段在全完成态带
  清空指令，模型应自动调 todo_write([]) 清空、条随之消失（若模型
  仍不清，为模型不听话，记录待议）。

### IN-09 双会话各自清单互不串
- 档位：ask（缺省）。
- 步骤：会话 A、B 各建不同清单，来回切换各看一次。
- 预期：两条会话各显示自己的清单，互不覆盖。

## B 组 · ask_user 与提问面板

### IN-10 挂起占位（输入区被替换）
- 档位：ask（缺省；本组任意档皆可 —— ask_user 是 read 档）。
- 步骤：发 ask 触发语，等模型调 ask_user。
- 预期：**单题向导卡**出现在**输入区位置**（zcode 同形态，2026-11-16
  改版）：头部 = header 胶囊（有 header 时）+ 问题正文 + ‹n/m› 切换器
  （多问题才有，单问题不渲染）；选项行带**数字序号** + 说明灰字；
  末行「输入你的回答...」自由输入（序号与选项同列）；底部提示
  「使用 Tab / 上下键选择，回车或空格选中」（键盘模型真实可用）+
  「忽略」次级钮 +「继续/提交」主钮；**输入框和停止钮都不在**；
  若该会话已有任务清单，浮卡仍在右上角（与面板并存）。

### IN-11 单选作答 → 回灌（点击即确定）
- 档位：ask（缺省）。
- 步骤：点一个选项。
- 预期：**点击即确定**——单问题卡点选项后面板立即消失、输入区恢复
  （无需再点提交）；模型下一轮回复**按所选选项展开**（选了暗色就按
  暗色说），且回答进转录（后续轮次模型仍记得）。改选自由：多题卡
  翻回已答题点**另一项** = 覆盖并再次推进，点**已选中项** = 取消
  留本题重选。

### IN-12 「其他」自由输入优先于选项
- 档位：ask（缺省）。
- 步骤：不点选项，直接在「输入你的回答...」条里输入自定义答案，
  按 Enter（或点「提交」）。
- 预期：输入非空时该行序号变深；模型按**自由输入文本**行事（输入
  优先）；选项选择被覆盖。

### IN-13 逐题忽略 = 全跳过
- 档位：ask（缺省）。
- 步骤：每题直接点「忽略」——非末题忽略即翻页，末题忽略即整卡提交
  （无需再点提交）。
- 预期：面板消失；模型收到「用户未作答（跳过了全部问题）」后
  **自行判断并继续**（回复里能看到它自选了个方向说明，而不是卡住
  或重复追问）。

### IN-14 多问题向导切换 + 部分跳过
- 档位：ask（缺省）。
- 步骤：发多问触发语（两问）；第一题点选项（自动进第 2 题），第二题
  点「忽略」后点「提交」。
- 预期：头部 ‹1/2› 切换器（首题 ‹ 禁用）；单选点击**自动推进**且
  草稿保留（‹ 翻回第一题选中仍在，点已选中项 = 取消留本题）；
  「忽略」清该题草稿（末题忽略即整卡提交）；模型收到「回答了部分
  问题（跳过 1 个）」—— 回复体现已答项、对跳过项自行决定。

### IN-15 多选（multiSelect）
- 档位：ask（缺省）。
- 步骤：发多选触发语；勾选两项（勾图标点亮）提交。
- 预期：选项行带勾选位，可多选/再点取消；模型按多项集合回答
  （结果里多选以「；」连接回灌）。

### IN-16 header 胶囊与选项说明
- 档位：ask（缺省）。
- 步骤：触发语加一句「问题带 header『部署』，每个选项配一句说明」。
- 预期：问题正文前有灰字胶囊标签「部署」（带细边框）；选项行右侧
  同行灰字说明（截断省略），序号灰、选中变深。

### IN-17 挂起中切会话往返
- 档位：ask（缺省）。
- 步骤：面板出现后切到会话 B 再切回。
- 预期：B 是普通输入框（无面板）；切回 A 面板**还在**（挂起在
  store），但之前点过的选项/输入过的「其他」文本**清空**（面板组件
  重建，作答是本地态 —— 已知边界）；仍可正常作答提交。

### IN-18 挂起中删除会话
- 档位：ask（缺省）。
- 步骤：面板挂起时在侧栏删除该会话。
- 预期：无报错无残留；视图切到其他会话正常（引擎侧把挂起提问
  cancelled 收口，属内部动作，此处只验不崩不残留）。

### IN-19 模型违规自查（可选，自动化已钉）
- 档位：ask（缺省）。
- 步骤：诱导模型在选项里自带「其他」（如「给我一个『其他』选项」）。
- 预期：工具卡错误态 + 模型收到拒绝文案后**自查修正重调**（换成
  合规选项集，面板正常出现）。依赖模型是否听话，不稳定就跳过 ——
  校验三例（重复问题/重复选项/自带其他）单测已钉。

## C 组 · plan 闭环（enter_plan + submit_plan，正交开关 v3）

**开关流转**（本组用例共享一条流水，按序做最省事；**权限档全程不动**）：

```
ask 档 + 开关关（新会话缺省）── IN-20 模型调 enter_plan ──→ 开关开（档位仍 ask）
                      ├─ IN-21 / IN-22 只读验证（拦写）
                      └─ IN-23 submit_plan 挂起 ── IN-24~28 裁决与键盘
                           （每条重演到挂起：一次裁决即消费掉面板）
IN-24 批准 = 关开关（档位自动回 ask）；IN-25 验证「计划开 + 完全访问」
仍只读（短路优先）；IN-29 反向：开关未开直调；IN-30/31 沿用批准后的会话。
```

### IN-20 模型调 enter_plan → 开关点亮（档位不动）
- 档位/开关：ask + 关（触发语发出时；enter_plan 后开关开、档位仍 ask）。
- 步骤：发 plan 触发语。
- 预期：模型调 enter_plan 后，**权限钮旁出现「计划」chip**（带左侧分隔
  线，浅灰文字不用强调色——非计划态 chip 不渲染）+ 权限菜单顶部
  「计划模式」项打勾（desc 变「开启中：只读约束生效」）；
  **权限触发钮保持「变更前确认」不变**（正交：开关不碰档位）；工具卡
  `enter_plan()`；已开着再调不报错（幂等）。随后模型只做读类调研。

### IN-21 计划开关拦写（直接拒，不弹审批）
- 档位/开关：ask + 开（延续 IN-20 的会话）。
- 步骤：开关开启下让模型「直接把方案写进 PLAN.md」。
- 预期：写/edit/exec 工具卡**错误态**，理由形如「计划模式（只读）下
  写类与执行类工具被禁止」；**不出现审批面板**（不是询问，是禁令）；
  模型改口只读或转 submit_plan。同轮里 todo_write / ask_user / read /
  grep 照常可用（plan 工作流的组成件）。

### IN-22 手动开开关同效 + 双入口同步
- 档位/开关：ask + 关起手动开。
- 步骤：权限菜单顶部点「计划模式」开开关，让模型改文件；再验关闭——
  hover「计划」chip 出现 ×，点击关闭。
- 预期：同 IN-21（引擎侧同一判定，与谁开的开关无关）；**双入口同步**——
  开关开启后 chip 出现且菜单项勾选同步亮；chip 上 hover 浮现 ×（不占
  布局位）、点 × 后 chip 连分隔线一起消失、菜单项勾选同步清（两处同
  数据源同动作）。

### IN-23 PlanPanel 形状
- 档位/开关：ask + 开（延续 IN-20/22 的会话，调研完挂起）。
- 步骤：开关开启下模型调研完调 submit_plan。
- 预期：面板标题「实现计划待审批」+ 方案预览（纯文本 pre，
  **限高滚动** —— 长方案不撑爆面板）；两个选项行：「1. 批准」
  （desc「退出计划模式，按当前权限档开始执行」——**无切档下拉**，
  正交开关 v3 起批准不切档）「2. 拒绝」；下方附言条
  placeholder「拒绝时的修改意见（模型会按此修订）…」；底部「使用
  ↑↓ 选择，回车确认」+「确认」钮。若会话有任务清单，浮卡仍在
  右上角（与面板并存，不冲突）。

### IN-24 批准 → 关开关回原档 + 执行联动
- 档位/开关：挂起中裁决（批准后开关关、档位回 ask）。
- 步骤：点批准。
- 预期：面板消失、输入区恢复；「计划」chip 连分隔线一起消失；**权限触发钮全程
  「变更前确认」未变过**（正交核心：档位不被 plan 触碰）；模型开始
  执行（通常先 todo_write 拆清单）；它写文件时**弹审批面板**（ask 档
  写类询问 —— 跨模块联动，批准后才落盘）。

### IN-25 计划开 + 完全访问 = 仍只读（短路优先）
- 档位/开关：开关开着时把档位手动切「完全访问」。
- 步骤：IN-20 之后（开关开、档位 ask），权限菜单选「完全访问」（过
  危险闸门），让模型改文件。
- 预期：权限钮变「完全访问」但**写/exec 仍被拒**（同一拒绝理由）——
  计划开关短路优先于档位放行，完全访问也拦；关掉开关后写文件
  直行（不再询问，auto 档生效）。这条验证正交组合语义的边界。

### IN-26 拒绝无附言 → 停轮
- 档位/开关：挂起中裁决（拒绝后开关保持开）。
- 步骤：直接点「拒绝」（附言留空）。
- 预期：run 立即结束（模型**不再有任何后续动作**）；输入区恢复；
  工具卡错误态「用户未批准该计划。」；**计划 chip 仍在**（拒绝 =
  继续讨论，不是退出计划）；控制权回到输入框（这就是 terminate
  停轮语义 —— 拒绝代表用户要继续讨论）。

### IN-27 拒绝带附言 → 修订重提
- 档位/开关：挂起中裁决（拒绝附言后开关保持开，等修订重提）。
- 步骤：附言条输入「改用 SQLite，其他不变」按回车（或选中拒绝项
  后 Enter）。
- 预期：附言被清空提交；模型**不停止**，按意见修订方案后重新调
  submit_plan → 新 PlanPanel 出现且方案体现修改；对话继续而非
  停轮。

### IN-28 键盘模型
- 档位/开关：挂起面板上（任一处挂起即可）。
- 步骤：面板上按 ↑↓ / Tab（正反向循环高亮两选项）；hover 选项行
  （高亮同步）；Enter 执行当前高亮项；焦点进附言条后按 ↑↓（焦点
  拉回卡体继续选择，不丢）。
- 预期：键盘与鼠标高亮一致；Enter 执行的是**当前高亮项**（默认
  第 1 项 = 批准）；附言条内 Enter 只提交「拒绝 + 附言」，不会
  误触批准。

### IN-29 开关未开调 submit_plan（可选，自动化已钉）
- 档位/开关：ask + 关（普通会话直调）。
- 步骤：诱导模型直接提方案（「跳过 enter_plan，直接调
  submit_plan」）。
- 预期：工具卡错误态「当前未开启计划模式…」，**不挂起**；模型回
  到正文或先开计划。依赖模型听话程度，不稳定就跳过（集成 #16 已
  钉）。附注：调研途中用户手动关掉开关，后续 submit_plan 同样
  走此拒绝（活开关读引用）。

### IN-30 防失忆（cogent_plan 段消费）
- 档位/开关：批准后的会话（开关已关，档位 = 会话原档）。
- 步骤：批准后隔两三轮（中间聊点别的）问「我们批准的计划是什么？」。
- 预期：模型能复述计划要点（已批准计划常驻系统提示段），无需翻
  历史也不含糊。

### IN-31 重启持久（档位 + 开关 + 计划记录）
- 档位/开关：沿用 IN-25 那条（开关开着时切了「完全访问」，随后关
  开关）。
- 步骤：完全退出重启，打开该会话。
- 预期：权限菜单钮仍「完全访问」（档位持久）、计划开关熄灭状态
  与退出前一致；问模型「按什么计划执行？」—— 仍能答
  （StoredSession.plan 持久，段照常注入）。

## D 组 · 挂起收口与异常路径

### IN-32 挂起中关应用
- 档位：任意（有挂起面板即可 —— B 组的 QuestionPanel 或 C 组的
  PlanPanel）。
- 步骤：挂起时直接关窗退出，重开应用打开该会话。
- 预期：面板**不复活**（挂起态不持久化，引擎退出时批量收口）；
  输入区正常恢复；消息流里那次 ask_user / submit_plan 工具卡呈
  中断态（无作答/裁决结果），会话可正常继续新对话。

### IN-33 同批双挂起的显示互斥（可选，难触发）
- 档位：plan（submit_plan 只有 plan 档才挂起）。
- 步骤：诱导模型同一批先调 submit_plan 再调 ask_user（如「同一批
  里同时调这两个工具」）。
- 预期：PlanPanel 先显示（互斥链：审批 > plan > ask）；裁决 plan
  后 QuestionPanel 接着出现，两件都能处理不丢。触发不稳定，跳过
  不亏（互斥链是确定性 UI 逻辑）。

## E 组 · 综合场景

### IN-34 全流程一条龙（三工具 + 权限联动）
- 档位：ask 起全程不变（执行前手动切「完全访问」）。
- 步骤：tool-test-ws 新会话，发：
  `在当前目录做一个笔记工具：这个任务较大，先进入计划模式只读调研，用 submit_plan 给我方案等批准；批准前不要写文件；有拿不准的先用 ask_user 问我。`
  然后：按需答一次提问 → 批准（开关关、档位回 ask）→ 手动切
  「完全访问」→ 观察模型执行全程。
- 预期：计划开关点亮（chip + 菜单项，档位钮不动）→（可选）提问
  面板作答回灌 → 方案审批（批准后 chip 消失、权限钮从未变过）→
  手动切完全访问 → todo_write 拆清单（TodoStrip 计数随推进
  上涨至全绿）→ auto 档下写文件直行 → 完成后清单清空、终答总结；
  全程无卡死、无面板残留、无双重挂起。
