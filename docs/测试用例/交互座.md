## 测前速查

**四枚工具一句话**（机制详见 [../模块/交互座.md](../模块/交互座.md)）：

| 工具 | 作用 | 用户可见面 |
| --- | --- | --- |
| todo_write | 会话任务清单（每次调用**全量替换**） | 输入区上方 TodoStrip 常驻条 |
| ask_user | 结构化提问（1-4 问 × 每问 2-4 选项） | QuestionPanel 占输入区 |
| enter_plan | 切「计划模式」（只读档，幂等） | 权限菜单触发钮变「计划模式」 |
| submit_plan | 方案送审（仅 plan 档可用） | PlanPanel 占输入区 |

**输入区替换链**（挂起面板与输入框互斥）：待审批 ApprovalPanel >
PlanPanel > QuestionPanel > 输入框。挂起期间**无输入框也无停止钮** ——
出路是在面板上作答/裁决；提问可整卡留空提交（= 跳过）。

**权限四档名**（PermissionMenu 触发钮文案）：计划模式(plan) /
变更前确认(ask) / 自主模式(autonomous) / 完全访问(auto)。plan 档 =
写/exec 类一律直接拒（错误结果，**不弹审批面板**）；read 类与
todo_write/ask_user/submit_plan 照常（交互工具全 read 档，任何档位
都不走工具审批）。

**已知边界（测前知道，不算 bug）**：
- 挂起面板占输入位是设计定调（审批卡母版），没有「取消挂起」钮；
- 挂起中切换会话再切回：面板还在，但**面板上的半成品作答清空**
  （作答是组件本地态，挂起本身在 store 不丢）；
- 挂起态不持久化：重启/关窗即收口，重开后面板不复活。

**环境准备**（一次）：

1. `npm run dev` 启动（自己开），配一个**工具调用可靠**的模型 ——
   弱模型可能不理会点名工具的指令，屡试不调就换模型；
2. 建测试工作区（如 `C:\Users\41631\Desktop\tool-test-ws`，空目录即可）
   + 在里面建会话；另备一条空会话（跨会话隔离用例要用）；
3. 建议每条用例新开会话，避免上下文串扰；
4. **档位口径**：每条用例首行「档位」标注起测档；「ask（缺省）」= 新
   会话缺省档「变更前确认」—— 若你改过设置页「默认权限」或项目默认
   档，开新会话后瞄一眼权限菜单触发钮确认，不是 ask 就手动切回。
   A/B 组其实不挑档（交互工具全 read 档，plan/autonomous 也免审批
   直行），统一缺省档为结果可比。

**触发语配方**（引导真实模型调特定工具；直接点名最稳）：

- todo：`用 todo_write 建任务清单：调研、实现、测试三项，然后逐项完成并更新状态`
- 高优先级：`用 todo_write 记录：第一项优先级 high，其余 medium`
- ask：`动手前先用 ask_user 问我：界面风格选哪种？选项：亮色 / 暗色`
- 多问：`用 ask_user 一次问我两个问题：用哪个数据库？部署到哪个环境？各给 2 个选项`
- 多选：`用 ask_user 问我需要集成哪些服务，选项 GitHub / GitLab / Bitbucket，把 multiSelect 设为 true`
- plan：`这个任务较大：先调 enter_plan 进入计划模式只读调研，然后调 submit_plan 把实现方案给我审批，批准前不要写任何文件`
- 清单清空：`清空任务清单（todo_write 提交空数组）`

## A 组 · todo_write 与任务清单条

### IN-01 首次落笔 → 条出现（免审批）
- 档位：ask（缺省；本组任意档皆可 —— todo_write 是 read 档）。
- 步骤：新会话发 todo 触发语。
- 预期：模型调 todo_write 后，**输入区上方**出现「任务清单」条（头部
  计数 n/m）；消息流过程区出现工具卡行，摘要形如
  `todo_write(共 3 项：1 进行中 / 2 待办 / 0 已完成)`；**不弹审批面板**
  （read 档直执行）。

### IN-02 全量替换语义（不是增量追加）
- 档位：ask（缺省）。
- 步骤：清单建好后说「再加一项：发布文档，第一项标完成」。
- 预期：条目整段刷新（新增项出现、第一项变完成态），计数同步 ——
  旧清单不是残留追加；每次 todo_write 工具卡摘要的计数与条一致。

### IN-03 条目样式三态 + 高优先级红点
- 档位：ask（缺省）。
- 步骤：用高优先级触发语建清单；推进到有完成/进行中/待办三态并存。
- 预期：完成项 = 实心勾图标 + **划线置灰**；进行中 = 深色进度图标；
  待办 = 灰虚线圈；high 且未完成的项右缘有红点，**完成后红点消失**。

### IN-04 折叠 / 展开
- 档位：ask（缺省）。
- 步骤：点条头部「任务清单 n/m」。
- 预期：条目区收起/展开，箭头旋转过渡；收起时计数仍可见；
  折叠是 UI 本地态：会话间切换保持，离开聊天视图（新聊天/设置）
  再回来复位 —— 不影响清单数据本身。

### IN-05 跨会话隔离
- 档位：ask（缺省）。
- 步骤：会话 A 建清单后切到空会话 B，再切回 A。
- 预期：B 无任务清单条（B 自己没建过）；A 的条还在且状态一致。

### IN-06 重启持久（StoredSession.todos）
- 档位：ask（缺省）。
- 步骤：清单非空时完全退出应用再启动，打开该会话。
- 预期：任务清单条还在，内容/状态与重启前一致（种子来自
  session.messages 的 todos 字段）。

### IN-07 防失忆（cogent_todos 段消费）
- 档位：ask（缺省）。
- 步骤：清单非空时**新一轮**直接问「我现在的任务清单是什么？」。
- 预期：模型不查任何文件、直接按清单回答（每回合系统提示常驻
  权威状态段；自动化钉的是段文本，这里验真模型消费）。

### IN-08 清空清单 → 条卸载
- 档位：ask（缺省）。
- 步骤：发清单清空触发语。
- 预期：模型调 todo_write 传空数组后，任务清单条**消失**（非空才
  挂载）；工具卡结果「任务清单已清空」。

### IN-09 双会话各自清单互不串
- 档位：ask（缺省）。
- 步骤：会话 A、B 各建不同清单，来回切换各看一次。
- 预期：两条会话各显示自己的清单，互不覆盖。

## B 组 · ask_user 与提问面板

### IN-10 挂起占位（输入区被替换）
- 档位：ask（缺省；本组任意档皆可 —— ask_user 是 read 档）。
- 步骤：发 ask 触发语，等模型调 ask_user。
- 预期：面板标题「需要你的输入」出现在**输入区位置**：问题块（问题
  深色 + 选项行 + 「其他（自由输入）」输入条）+ 底部提示「可留空跳过；
  「其他」输入优先于选项」+ 「提交回答」主钮；**输入框和停止钮
  都不在**；若该会话已有任务清单，清单条仍在面板上方（跨回合层）。

### IN-11 单选作答 → 回灌
- 档位：ask（缺省）。
- 步骤：点一个选项（高亮）→ 再点它（取消）→ 改点另一项 → 提交。
- 预期：面板消失、输入区恢复；模型下一轮回复**按所选选项展开**
  （选了暗色就按暗色说），且回答进转录（后续轮次模型仍记得）。

### IN-12 「其他」自由输入优先于选项
- 档位：ask（缺省）。
- 步骤：点选一个选项后，再在「其他」条里输入自定义答案，提交。
- 预期：模型按**自由输入文本**行事（输入优先）；选项选择被覆盖。

### IN-13 整卡留空 = 全跳过
- 档位：ask（缺省）。
- 步骤：什么都不选不输，直接「提交回答」。
- 预期：面板消失；模型收到「用户未作答（跳过了全部问题）」后
  **自行判断并继续**（回复里能看到它自选了个方向说明，而不是卡住
  或重复追问）。

### IN-14 多问题卡 + 部分跳过
- 档位：ask（缺省）。
- 步骤：发多问触发语（两问）；只答第一问，第二问留空提交。
- 预期：面板里两个问题块竖排，各带独立选项与「其他」条；模型
  收到「回答了部分问题（跳过 1 个）」—— 回复体现已答项、对跳过项
  自行决定。

### IN-15 多选（multiSelect）
- 档位：ask（缺省）。
- 步骤：发多选触发语；勾选两项（勾图标点亮）提交。
- 预期：选项行带勾选位，可多选/再点取消；模型按多项集合回答
  （结果里多选以「；」连接回灌）。

### IN-16 header 短标签与选项说明
- 档位：ask（缺省）。
- 步骤：触发语加一句「问题带 header『部署』，每个选项配一句说明」。
- 预期：问题行前缀灰色「部署：」；选项行右侧同行灰字说明（截断
  省略）。

### IN-17 挂起中切会话往返
- 档位：ask（缺省）。
- 步骤：面板出现后切到会话 B 再切回。
- 预期：B 是普通输入框（无面板）；切回 A 面板**还在**（挂起在
  store），但之前点过的选项/输入过的「其他」文本**清空**（面板组件
  重建，作答是本地态 —— 已知边界）；仍可正常作答提交。

### IN-18 挂起中删除会话
- 档位：ask（缺省）。
- 步骤：面板挂起时在侧栏删除该会话。
- 预期：无报错无残留；视图切到其他会话正常（引擎侧把挂起提问
  cancelled 收口，属内部动作，此处只验不崩不残留）。

### IN-19 模型违规自查（可选，自动化已钉）
- 档位：ask（缺省）。
- 步骤：诱导模型在选项里自带「其他」（如「给我一个『其他』选项」）。
- 预期：工具卡错误态 + 模型收到拒绝文案后**自查修正重调**（换成
  合规选项集，面板正常出现）。依赖模型是否听话，不稳定就跳过 ——
  校验三例（重复问题/重复选项/自带其他）单测已钉。

## C 组 · plan 闭环（enter_plan + submit_plan）

**档位流转**（本组用例共享一条档位流水，按序做最省事）：

```
ask（新会话缺省）── IN-20 模型调 enter_plan ──→ plan
                      ├─ IN-21 / IN-22 只读验证（拦写）
                      └─ IN-23 submit_plan 挂起 ── IN-24~28 裁决与键盘
                           （每条重演到挂起：一次裁决即消费掉面板）
IN-29 反向：非 plan 档（ask 直起）；IN-30/31 沿用批准后的会话
（档位 = 批准时所选，IN-31 用 IN-25 切过「完全访问」的那条）。
```

### IN-20 模型调 enter_plan → 档位自动切
- 档位：ask 起（触发语发出时是缺省 ask；enter_plan 后自动变 plan）。
- 步骤：发 plan 触发语。
- 预期：模型调 enter_plan 后，**权限菜单触发钮自动变「计划模式」**
  （无需手动切）；工具卡 `enter_plan()`；已在此档时再调不报错
  （幂等）。随后模型只做读类调研。

### IN-21 plan 档写拦截（直接拒，不弹审批）
- 档位：plan（延续 IN-20 的会话，或任一 plan 档会话）。
- 步骤：plan 档下让模型「直接把方案写进 PLAN.md」。
- 预期：写/edit/exec 工具卡**错误态**，理由形如「plan（只读）模式下
  写类工具被禁止」；**不出现审批面板**（不是询问，是禁令）；模型
  改口只读或转 submit_plan。同轮里 todo_write / ask_user / read /
  grep 照常可用（plan 工作流的组成件）。

### IN-22 手动切 plan 同效
- 档位：ask 起手动切 plan（权限菜单选「计划模式」）。
- 步骤：权限菜单手动选「计划模式」，让模型改文件。
- 预期：同 IN-21（引擎侧同一判定，与谁切的档无关）。

### IN-23 PlanPanel 形状
- 档位：plan（延续 IN-20/22 的会话，调研完挂起）。
- 步骤：plan 档下模型调研完调 submit_plan。
- 预期：面板标题「实现计划待审批」+ 方案预览（纯文本 pre，
  **限高滚动** —— 长方案不撑爆面板）；两个选项行：「1. 批准，并
  切换为 ▾（缺省显示 变更前确认）」「2. 拒绝」；下方附言条
  placeholder「拒绝时的修改意见（模型会按此修订）…」；底部「使用
  ↑↓ 选择，回车确认」+「确认」钮。若会话有任务清单，条仍在面板
  上方。

### IN-24 批准（缺省 ask）→ 切档 + 执行联动
- 档位：plan 挂起中裁决（批准后落 ask）。
- 步骤：档位下拉保持「变更前确认」，点批准。
- 预期：面板消失、输入区恢复；权限菜单钮变「**变更前确认**」；
  模型开始执行（通常先 todo_write 拆清单）；它写文件时**弹审批
  面板**（ask 档写类询问 —— 跨模块联动，批准后才落盘）。

### IN-25 批准切「完全访问」
- 档位：plan 挂起中裁决（批准后落 auto）。
- 步骤：同 IN-24 但下拉选「完全访问」。
- 预期：菜单钮变「完全访问」；模型执行写文件**不再询问**直行；
  工具结果里模型收到「切换到 完全访问（auto）模式」回执。

### IN-26 拒绝无附言 → 停轮
- 档位：plan 挂起中裁决（拒绝后仍 plan）。
- 步骤：直接点「拒绝」（附言留空）。
- 预期：run 立即结束（模型**不再有任何后续动作**）；输入区恢复；
  工具卡错误态「用户未批准该计划。」；权限档**仍在计划模式**；
  控制权回到输入框（这就是 terminate 停轮语义 —— 拒绝代表用户
  要继续讨论）。

### IN-27 拒绝带附言 → 修订重提
- 档位：plan 挂起中裁决（拒绝附言后仍 plan，等修订重提）。
- 步骤：附言条输入「改用 SQLite，其他不变」按回车（或选中拒绝项
  后 Enter）。
- 预期：附言被清空提交；模型**不停止**，按意见修订方案后重新调
  submit_plan → 新 PlanPanel 出现且方案体现修改；对话继续而非
  停轮。

### IN-28 键盘模型
- 档位：plan 挂起面板上（任一处挂起即可）。
- 步骤：面板上按 ↑↓ / Tab（正反向循环高亮两选项）；hover 选项行
  （高亮同步）；Enter 执行当前高亮项；焦点进附言条后按 ↑↓（焦点
  拉回卡体继续选择，不丢）。
- 预期：键盘与鼠标高亮一致；Enter 执行的是**当前高亮项**（默认
  第 1 项 = 批准）；附言条内 Enter 只提交「拒绝 + 附言」，不会
  误触批准。

### IN-29 非 plan 档调 submit_plan（可选，自动化已钉）
- 档位：ask（**须非 plan** —— 普通会话直调）。
- 步骤：诱导模型直接提方案（「跳过 enter_plan，直接调
  submit_plan」）。
- 预期：工具卡错误态「当前不在 plan 模式…」，**不挂起**；模型回
  到正文或先进 plan。依赖模型听话程度，不稳定就跳过（集成 #16 已
  钉）。附注：plan 调研途中用户手动把档切走，后续 submit_plan 同样
  走此拒绝（活模式读引用）。

### IN-30 防失忆（cogent_plan 段消费）
- 档位：批准后的会话（档位随批准时所切，不挑）。
- 步骤：批准后隔两三轮（中间聊点别的）问「我们批准的计划是什么？」。
- 预期：模型能复述计划要点（已批准计划常驻系统提示段），无需翻
  历史也不含糊。

### IN-31 重启持久（档位 + 计划记录）
- 档位：auto（沿用 IN-25 批准切「完全访问」的那条会话）。
- 步骤：完全退出重启，打开该会话。
- 预期：权限菜单钮仍「完全访问」（档位持久）；问模型「按什么计划
  执行？」—— 仍能答（StoredSession.plan 持久，段照常注入）。

## D 组 · 挂起收口与异常路径

### IN-32 挂起中关应用
- 档位：任意（有挂起面板即可 —— B 组的 QuestionPanel 或 C 组的
  PlanPanel）。
- 步骤：挂起时直接关窗退出，重开应用打开该会话。
- 预期：面板**不复活**（挂起态不持久化，引擎退出时批量收口）；
  输入区正常恢复；消息流里那次 ask_user / submit_plan 工具卡呈
  中断态（无作答/裁决结果），会话可正常继续新对话。

### IN-33 同批双挂起的显示互斥（可选，难触发）
