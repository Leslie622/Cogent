# 钩子座手动验收

机制见 [钩子座](../模块/钩子座.md)。由用户启动应用，配置可用模型，打开运行时控制台。
本册只管审计呈现与GUI接线，不把自动回归结果当成手测记录。

## 审批审计

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| H1 | ask会话让模型写测试文件，面板允许 | 同run出现询问与用户允许裁决，时序正确 |
| H2 | 同类请求拒绝并附言 | 用户拒绝裁决含截断概览，详情保留原因 |
| H3 | 根内写“始终允许”，再写同根 | 第二次只有工作区规则放行裁决，无询问 |
| H4 | 通过可用停止入口中止审批挂起 | 中止裁决、运行收口，不永久挂起 |
| H5 | 计划开关开启时让模型写文件 | 计划拦截裁决，无权限询问面板 |
| H6 | 计划关闭，分别auto/自主档写文件 | 对应档位放行裁决；exec按自主档判定核对 |
| H7 | find/grep/read等只读操作 | 有工具条，无审批域条目 |
| H8 | 打开询问与对应裁决详情 | requestId相同，可对账；不能仅凭时间相邻配对 |
| H12 | 退出重启，打开旧会话控制台 | JSONL审计记录可回看 |
| H13 | 审批挂起期间删除会话 | 挂起收尾、无未决run，控制台可见时有收尾裁决 |

## 注入与边界

- H9：ask↔auto切档后下一轮核对api.request中的`cogent_permission`段。
- H10：技能热刷新沿用 [技能验收](技能座.md#真实模型与同会话刷新)。
- H11：清单/已批准计划注入沿用 [交互验收](交互座.md)。
- 审计尽力记录，失败不改变对话结果；新增裁决分支应有可辨识文案。
