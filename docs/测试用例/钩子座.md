# 钩子座 · 手动测试用例

> 阶段 4d（装配统一 + 审批审计对）。自动化覆盖：inspector.test.ts 单测 3 +
> approval-upgrade.test.ts S8 集成回查；本册管 GUI 手感与控制台呈现。
> 前置：模型可用的自定义 provider；运行时控制台可开（侧栏 → 控制台）。

## 一、审批审计对进控制台（核心新能力）

| # | 操作 | 期望 |
| --- | --- | --- |
| H1 | ask 档会话让模型写文件 → 面板点「允许」 | 控制台时间线该 run 内出现「审批询问 · write」（盾牌图标）与「审批裁决 · 用户允许」（绿盾）两条，先后相邻 |
| H2 | 同上场景点「拒绝」并附言 | 裁决条文案「用户拒绝」，概览含原因（附言截断 120 字内） |
| H3 | 点「允许并始终允许此工作区」→ 同根再写一次 | 第二次**无询问条**、只有「放行（工作区规则）」裁决条 |
| H4 | ask 挂起时点输入框「停止」 | 出现「审批裁决 · 中止」条；run 以失败收尾，无永悬 |
| H5 | 开计划开关（PlanToggle）→ 让模型写文件 | 只有「拦截（计划模式）」裁决条，无询问条，无 approval 面板 |
| H6 | auto/自主档写文件 | 各有「放行（auto 档）」/「放行（自主档）」裁决条 |
| H7 | 只读操作（模型 find/grep/读文件） | **零审批条目**（工具层 tool.* 条照常，审批层无痕 = read 不经审批域） |
| H8 | 任一询问条点开详情 | 「请求标识」块 = appr- 开头 id；对应裁决条详情同 id（可对账） |

## 三、边界确认

- H12：重启应用后开旧会话的控制台 → 审批条目随 JSONL 回看（落盘链路）。
- H13：审批挂起期间删除会话 → 控制台出现「收尾」裁决条（settle 兜底路径），
  引擎不崩、无未决 run。

已知边界：审计为尽力语义（记录失败不影响对话）；裁决词呈现映射在
inspector.ts `VERDICT_LABELS`，新增判定分支需同步补词。
