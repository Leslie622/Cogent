## 准备测试文件

独立 worktree 为 `C:/Users/u/.codex/worktrees/body-file-links/Cogent`，分支 `codex/body-file-links`。
本批修改涉及 Host 与 renderer，测试前请完全退出当前 Cogent，再在上述目录由用户启动 `npm run dev`；
只刷新页面不保证 Host 的定位解析器已更新。不要同时启动桌面原目录的旧实例。

在另一个 PowerShell 进入该 worktree，执行一次下面脚本。它只新建一个随机命名的桌面测试目录，打印路径后把这个目录绑定为测试项目。
不要直接拿自己的业务文件做删除、覆盖和另存测试。

```powershell
$fileLinkTestRoot = Join-Path ([Environment]::GetFolderPath('Desktop')) ('Cogent-文件链接验收-' + [Guid]::NewGuid().ToString('N').Substring(0, 6))
New-Item -ItemType Directory -Path $fileLinkTestRoot | Out-Null
foreach ($part in @('A', 'B', '子目录')) {
    New-Item -ItemType Directory -Path (Join-Path $fileLinkTestRoot $part) | Out-Null
}
$fileLinkUtf8 = [Text.UTF8Encoding]::new($false)
[IO.File]::WriteAllLines((Join-Path $fileLinkTestRoot '测试.txt'), @('第一行标题', 'ABCDEFG', '第三行内容', '第四行内容', '第五行结束'), $fileLinkUtf8)
[IO.File]::WriteAllText((Join-Path $fileLinkTestRoot '中文 空格.txt'), '中文和空格文件名', $fileLinkUtf8)
[IO.File]::WriteAllText((Join-Path $fileLinkTestRoot 'README'), '这是无扩展名文本', $fileLinkUtf8)
[IO.File]::WriteAllText((Join-Path $fileLinkTestRoot '百分号%20#标记.txt'), '字面百分号和井号', $fileLinkUtf8)
[IO.File]::WriteAllText((Join-Path $fileLinkTestRoot 'A/同名.txt'), '我是 A 文件', $fileLinkUtf8)
[IO.File]::WriteAllText((Join-Path $fileLinkTestRoot 'B/同名.txt'), '我是 B 文件', $fileLinkUtf8)
[IO.File]::WriteAllLines((Join-Path $fileLinkTestRoot 'B/测试.txt'), @('B 第一行', 'HIJKLMN'), $fileLinkUtf8)
[IO.File]::WriteAllText((Join-Path $fileLinkTestRoot '预览.md'), "# Markdown 样本`n`n![本地图](./示例.png)`n`n[定位文本](./测试.txt#L2C3)`n`n![外部图](https://example.invalid/blocked.png)", $fileLinkUtf8)
Copy-Item -LiteralPath (Join-Path (Get-Location) 'reference/pi/packages/ai/test/data/red-circle.png') -Destination (Join-Path $fileLinkTestRoot '示例.png')
$fileLinkTestRoot
```

`测试.txt` 第2行固定为 `ABCDEFG`，第3列就是 `C`。行列从1开始，空格和标点也占列；
如果换成 `2. 内容`，第3列是空格，第4列才是“内”，不要据此判断定位差一列。
先做用例1～5，通常即可覆盖这次截图中的问题。测试记录写“通过 / 失败 / 未测”，不以链接变蓝代替点击验收。

## 用例1：显式链接与反引号的基本行为

在新聊天发送以下提示词（这里的反引号也一起复制）：

```text
只使用 read 工具读取项目根目录的“测试.txt”，不要用 powershell/bash 代替。
读取成功后，按下面顺序原样输出这些引用，不要放进代码块，也不要更改链接目标：
[冒号行列](./测试.txt:2:3)
[片段行列](./测试.txt#L2C3)
[带冒号片段](./测试.txt#L2:C3)
[数字片段](./测试.txt#L2:3)
[仅行号](./测试.txt#L2)
[行范围](./测试.txt#L2-L3)
反引号文件名：`测试.txt`
反引号行列：`测试.txt:2:3`
```

操作：等回答结束后逐个点击，观察预览顶部位置提示、正文与选中范围；再关闭面板，用 Tab 聚焦其中一个链接并按 Enter。

| 引用 | 预期 |
| --- | --- |
| 前四个 Markdown 链接、反引号行列 | 都打开根目录的同一个测试.txt，显示“已定位：第 2 行，第 3 列”，对应 C |
| 仅行号 | 第2行第1列，对应 A |
| 行范围 | 选中 ABCDEFG 和第三行内容，不仅移动到第2行 |
| 反引号文件名 | 有文件入口并能预览；没有要求它自动带上某个位置 |
| Tab / Enter | 可聚焦、可打开；悬停或聚焦显示完整路径 |

工具过程应确实有成功的 read；如果模型没按要求读文件、把引用塞进围栏或改写了目标，先区分模型输出与客户端失败。

## 用例2：流式 → 结束 → 刷新一致

同一聊天发送：“再用 read 读取测试.txt，先输出用例1的四个行列链接与反引号行列，然后继续解释文件内容约300字。”

操作：在后半段仍生成时，观察已经闭合的文件链接并尝试点击；生成结束再看一次；最后按 Ctrl+R 刷新并回到该聊天。

预期：流式中的“测试.txt”没有被撑成“测 试 . txt”；已闭合链接可点，未闭合目标不可点。
结束和刷新后，显式链接、反引号链接都仍可用，路径与行列不变。不能出现图1可点、图2退回普通 code 的情况。
生成太快没看清时可用 `npm run test:file-links-electron`，脚本会保持流式响应，检查后再结束，避免手速影响判断。

## 用例4：歧义文件名不任选一个

```text
分别使用 read 读取 A/同名.txt 和 B/同名.txt，然后原样给出三个反引号引用：
`同名.txt`、`A/同名.txt`、`B/同名.txt`。不要创建新文件。
```

预期：裸 `同名.txt` 保持普通 code，因为有两个候选；带目录的两个引用可以点击，分别显示“我是 A 文件”和“我是 B 文件”。
结束、刷新后仍然相同，不能因为缓存把裸名称变成 A 或 B。

## 用例5：没有真实依据的 token 不变成文件

```text
尝试用 read 读取项目根目录的 不存在.txt，失败后不要创建它。
随后原样输出 `不存在.txt`、`npm test`、`未读过.ts`，并在代码围栏里写一行 测试.txt。
最后给出显式链接 [缺失文件](./不存在.txt)。
```

预期：前三个反引号和围栏不生成文件入口。显式“缺失文件”可以点击，但打开后要明确报不存在，不能显示上一份文件。
这是显式目标与自动识别的区别，不要求客户端把所有不存在的 Markdown 链接预先变灰。

## 用例6：中文、空格、无扩展名与百分号

```text
原样输出下面三个 Markdown 链接，不要放进代码围栏：
[中文空格](<./中文 空格.txt>)
[无扩展名](./README)
[字面特殊字符](./百分号%2520%23标记.txt)
```

预期：点击后分别看到“中文和空格文件名”“这是无扩展名文本”“字面百分号和井号”。
最后一项打开的文件名必须是 `百分号%20#标记.txt`，不能把 %20 再解码成空格。
绝对路径补测：让 Agent 把测试.txt 的绝对 Windows 路径和 file URI 各输出一个链接，点击核对与相对链接相同。

## 用例7：无效位置与外链

```text
原样给出：[越界行](./测试.txt:999:1)、[越界列](./测试.txt:2:999)、[零行号](./测试.txt:0)、[网页](https://example.com)。
这只是显示测试，不需要执行或读取这些网页。
```

## 用例8：Markdown 与媒体/文档预览

让 Agent 原样输出 `[Markdown](./预览.md)`、`[图片](./示例.png)`、`[目录](./子目录)`，逐一打开。
Markdown 应显示标题、加载本地图、保留文本定位链接；外部图片标记为未自动加载；源码页签显示原 Markdown。
图片能适配/原图/缩放；目录给出文件管理器操作，不把目录当文本读取。

再把自己的可公开测试样本复制进这个测试目录，按下表逐个让 Agent 返回链接。没有样本的项记“未测”。

| 样本 | 必须观察到 |
| --- | --- |
| PDF，至少2页 | 实际页面、上一/下一页和缩放，不是仅文字提取 |
| DOCX | 段落/标题/表格内容，明确标注内容预览 |
| XLSX，至少2个工作表 | 工作表目录，输入工作表名称和 A1:D20 后得到对应内容 |
| PPTX，至少2页 | 幻灯片页序、上一/下一段可切换且内容不同 |
| WAV/MP3、MP4/WebM | 有原生控件；可支持的编码能播放；不支持时有明确提示和系统打开入口 |

Office 不承诺原生排版；不拿它和 Word/Excel 原窗口的像素版式比较。

## 用例9：桌面动作

通过用例1的“冒号行列”链接打开测试.txt，再打开“文件操作”菜单，依次操作并核对：

1. 复制路径：粘到记事本，应该是本次测试目录的完整路径。
2. 文件管理器定位：选中的是同一份测试.txt；系统打开使用已关联应用。
3. 另存：先取消，确认没有新文件；再另存为 测试-副本.txt，核对内容相同、原件不变。
4. 配置编辑器：选择真实 Code.exe/Cursor.exe，再“编辑器打开”，检查第2行第3列；重启后设置保留。

原生应用启动/另存成功不能只凭按钮没报错判定，必须检查系统窗口或实际保存的文件。

## 用例10：多聊天与重启来源

准备：项目A绑定测试根目录，项目B绑定其中的 B 子目录；两个项目各建一个聊天。
在A、B聊天中分别发送同一段提示词，把读取和引用放在同一轮：

```text
请在本轮使用 read 工具读取当前项目根目录的 测试.txt，不要用 powershell/bash 代替。
读取成功后，仅按下面的原样格式输出，不要做内容摘抄表格，不要放进代码围栏，也不要自创位置写法：
文件名：`测试.txt`
反引号行列：`测试.txt:2:3`
显式链接：[第二行第三列](./测试.txt:2:3)
```

操作：

1. 在A聊天点击“反引号行列”和“第二行第三列”，核对预览完整路径、第二行内容和位置提示。
2. 在B聊天重复相同操作。两个聊天中看起来相同的文件名，应各自打开所属项目的文件。
3. A/B之间反复切换，再点击各自原来那轮的这两个引用；不需要新增追问或重新读取。
4. 完全退出并重启 Cogent，再回到这两个聊天，点击原来那轮的历史引用，核对结果仍相同。

| 聊天 | 预览路径 | 第二行 | 第2行第3列 |
| --- | --- | --- | --- |
| A | 测试根目录下的 测试.txt | ABCDEFG | C |
| B | 测试根目录下 B/测试.txt | HIJKLMN | J |

两个入口都应显示“已定位：第 2 行，第 3 列”。路径正确但没有定位提示，也不算该入口通过。

本例不要求下一轮没有 read 的追问自动继承反引号文件词表。当前自动识别范围是“本轮成功读写过的明确文件”，
所以新一轮只让模型重发 `测试.txt:2:3`、但没有重新读取时，普通 code 属于预期；原来那轮已建立的链接仍应可用。
显式 Markdown 链接不依赖这份自动词表，下一轮仍可按保存的消息来源解析。

模型输出 `HIJKLMN`、`B 第一行` 等内容摘抄时，它们也不是文件引用，不应变成链接。
`测试.txt:1-2`、`测试.txt:1:1-2:7` 不在支持语法中；范围测试使用 `测试.txt#L1-L2`，不要用这些写法判断本例失败。

预期：切换和重启不改变原引用的来源，A的旧链接不跟着当前选中的B走，反引号识别也不借用另一聊天的词表。

## 用例11：改文件、删文件与迟到请求

只在刚建的测试目录操作：先打开测试.txt，用记事本改第二行并保存，再点预览的“重新加载”。
预期显示新内容。把该文件重命名后点旧链接，应报缺失；改回原名后再点应恢复。
在图片/PDF读取时快速切文件、切聊天或关闭面板，旧内容不能在新面板出现，也不能重新弹出已关闭面板。
重启 Host 后旧预览应关闭，重新点击正文能再解析。

## 用例12：布局、键盘与阅读位置

用户暂未执行本例，布局整改后再验；本轮以功能验收为主，不将该项记为人工通过。

在亮/暗主题分别测试宽窗和400px窄窗，重复100%/125%/150%缩放。
宽窗使用右栏，窄窗使用 Dialog；返回宽窗不残留空白遮罩。菜单、关闭按钮、搜索框都可达，无横向裁切。
滚到长回答中间、选中一段文字，再打开旁边文件；正文不应被拉回底部，未受影响的文字选区不应无故丢失。
用 Tab/Enter 打开、Esc 关闭弹窗，检查焦点回到合理位置。断点按应用实际 CSS 宽度计算，不按显示器物理像素判断。

## 用例13：超预算与异常（可后测）

可在测试目录创建一个超过20 MiB的文本，再请求显式链接；应显示容量原因，保留系统打开，不能卡住 Agent。
进一步检查超像素图片、文档解析超时、权限拒绝、软链接换目标、读取中改写，以及连续反复开关的内存回收。
这些不是普通样本自动通过就能推断的结论；Windows 无法方便创建软链接时，留到具备权限或 Linux 环境执行，不记为通过。
