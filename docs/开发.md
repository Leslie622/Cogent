```bash
cat > /tmp/feed.txt <<'EOF'
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"client":"smoke","protocolVersion":1,"credentials":{"anthropic":{"apiKey":"sk-test-fake"}}}}

# 期望（假 key）：run.started 事件 → 各 id 响应 → 约 2~20s 后 run.failed 事件
#（403 转译自 pi 流错误）；真 key 则是 message.delta 流 + run.completed
```

> 踩坑记录（2026-11-06）：用 `printf 'a\nb\nc\n' | node ...` 不带 sleep 冒烟，
> stdin 写完即关闭 → 引擎退出 → 事件看起来"永远不来"（实为进程已死）。
> 冒烟必须保持 stdin 打开等事件。

### 思考链路冒烟（mock 端点，无需真 key）

验证 `message.delta kind:"thinking"` → `run.completed.message.thinking` →
`session.messages` 历史回查的确定性链路（原理见
[技术笔记/thinking-reasoning.md](技术笔记/thinking-reasoning.md) §5）。
pi 的 openai-completions 方言解析 `reasoning_content`（DeepSeek/llama.cpp 风格），
mock 对任何 POST 回一段 SSE：先思考两拍、再正文两拍、stop 收尾。

```js
// /tmp/cogent-smoke/mock-sse.mjs —— node 直接跑，监听 18931
import { createServer } from 'node:http'
createServer((req, res) => {
  req.resume()
  req.on('end', () => {
    res.writeHead(200, { 'content-type': 'text/event-stream' })
    const chunk = (delta, finish = null) =>
      res.write(`data: ${JSON.stringify({ id: 'mock', object: 'chat.completion.chunk',
        created: 0, model: 'mock-reasoner',
        choices: [{ index: 0, delta, finish_reason: finish }] })}\n\n`)
    chunk({ role: 'assistant', reasoning_content: '思考第一段。' })
    chunk({ reasoning_content: '思考第二段。' })
    chunk({ content: '答案第一句。' })
    chunk({ content: '答案第二句。' })
    chunk({}, 'stop')
    res.write('data: [DONE]\n\n')
    res.end()
  })
}).listen(18931)
```

```bash
cat > /tmp/cogent-smoke/feed.txt <<'EOF'
```

### token 用量冒烟（mock 端点，无需真 key）

验证 `turn_end` 用量摘取 → `run.completed.message.usage` 三件套 →
`session.messages` 历史回查的确定性链路（原理见
[技术笔记/token-usage.md](技术笔记/token-usage.md)）。与上面两节的手工 feed 式
不同，这节是**自动化驱动脚本**（spawn 引擎 + stdio JSON-RPC，从 `session.create`
响应取真实 UUID 会话 id —— 受理校验落地后写死 `s-1` 会吃"会话不存在"），
自建临时 `COGENT_HOME` 不碰真实 `~/.cogent`，exit code 即结果（0 = 12 项断言全过）。

mock 关键点：pi 请求自动带 `stream_options.include_usage`，末 chunk 挂 OpenAI
标准 `usage` 对象即可（`prompt_tokens_details.cached_tokens` → cacheRead、
`cache_write_tokens` → cacheWrite、`completion_tokens_details.reasoning_tokens`
→ reasoning，均 pi openai 方言的归一映射）。

```bash

#  usage.input = 100（1000 − 缓存读 800 − 缓存写 100：pi 把缓存从 input 里扣除）
```

### submit 受理校验回归（2026-11-09 修复的防崩守卫）

验证忙会话/不存在会话拿到**错误响应帧**且引擎存活（修复前：异步 reject 变
unhandledRejection 直接崩引擎，全部会话丢失 —— 见
[技术笔记/pi-agent-integration-isolation.md](技术笔记/pi-agent-integration-isolation.md) §3）。
mock 对首个请求慢速流（两拍间隔 1.5s），给"流式进行中再 submit"留窗口。

```js
// /tmp/cogent-smoke/mock-slow.mjs —— node 直接跑，监听 18932
import { createServer } from 'node:http'
let n = 0
createServer((req, res) => {
  req.resume()
  req.on('end', () => {
    res.writeHead(200, { 'content-type': 'text/event-stream' })
    const chunk = (delta, finish = null) =>
      res.write(`data: ${JSON.stringify({ id: 'mock', object: 'chat.completion.chunk',
        created: 0, model: 'mock', choices: [{ index: 0, delta, finish_reason: finish }] })}\n\n`)
    chunk({ role: 'assistant', content: '第一问回复。' })
    if (n++ === 0) { setTimeout(() => { chunk({ content: '（慢拍）' }); chunk({}, 'stop'); res.write('data: [DONE]\n\n'); res.end() }, 1500) }
    else { chunk({}, 'stop'); res.write('data: [DONE]\n\n'); res.end() }
  })
}).listen(18932)
```

## 浏览器里验收 UI（无 preload 环境）

localhost:5173 直开没有 `window.cogent`，App 的引擎接线会在挂载时报错白屏。
调试姿势（playwright/控制台）：

1. 注入桩：`window.cogent = { engineRequest: async () => [], listApiKeys: async () => [],
   getCustomProviders: async () => ({providers:[],overrides:[]}), onEngineEvent: () => () => {},
   onWindowState: () => () => {}, minimizeWindow: async () => {}, toggleMaximizeWindow: async () => {},
   closeWindow: async () => {} }`；
2. 恢复挂载（比 HMR touch 可靠，死树/整页刷新后都适用）：
   `import('/src/main.tsx?t=' + Date.now())` —— 带戳重执行入口，React 在桩存活下重建根。
   HMR touch（往源文件追加空行）在树已崩时经常不触发重挂，勿再依赖。

另：React 根崩溃（如编辑中间态 ReferenceError）后**后续 HMR 不会自愈**，
Electron 窗口里 Ctrl+R 整页刷新即恢复；连续多刀编辑尽量合并成单次整文件写入，
避免把中间态推给 HMR。

## 环境排障

- **引擎 Node 版本要求 ≥ 22.19**（pi 的 engines）。默认用 Electron 自带 Node
  （`process.execPath` + `ELECTRON_RUN_AS_NODE=1`），无需系统安装 node；
  要换运行时用环境变量 `COGENT_NODE_BIN` 指定其他 Node 路径。
- **Electron 二进制下载失败**（国内网络）：
  `cd node_modules/electron && ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node install.js`
- **端口 5173 被占**：vite 自动降级到 5174+，无害；要回收端口先找到残留 node 进程。
- **`npm run build` 报 rolldown `out of memory`**（2026-11-10）：dev 实例
  （electron + 引擎子进程）占着内存时，rolldown worker 分配失败直接 panic。
  关掉 dev 应用再 build 即过；不是代码问题，typecheck/lint 不受影响。
- **改了 agent-service 代码但运行中的应用"没反应"**：引擎是独立 node 子进程
  （`out/main/service.js`），renderer HMR / 主进程热重启都不会替换它 ——
  表现为"设置改了、下拉不更新，重启应用才好"。改引擎侧代码后要重启
  dev/应用让新构建的引擎子进程生效。
