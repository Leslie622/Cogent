## 1. 问题全景:四笔账

1. **窗口**:转录长过 contextWindow,请求被端点直接拒绝(context overflow);
2. **成本**:input 随轮次线性涨,第 50 轮为一个错别字重发 49 轮历史;
3. **注意力**:远期工具输出噪音稀释近期任务焦点(lost in the middle);
4. **输出预算饿死**(本次实测新增,前三账的衍生但独立成账):回复预算 =
   `ctx − 占用 − 安全边际`,占用逼近窗口时预算趋零 —— **推理模型的思考没有
   硬上限,会把小预算全吃光,连工具调用都发不出 → 上下文永远涨不上去 →
   永远到不了压缩线**(死锁)。2026-11-12 用 20K 窗 deepseek-flash 实测:
   占用 67% 时预算 ≈2.4K,思考吃光,`stopReason: length` 空回复,工具未执行。

朴素头部截断不行(模型忘了自己做过什么),压缩的本质 = **用便宜的 LLM 调用
把旧历史蒸馏成结构化检查点,旧区换摘要、近期对话原样保留**。第四账要求:
**触发判定必须感知「剩余输出 room」,不能只看占比**。

## 3. 各家详述(技术要点)

### 3.1 pi(源码级,我们最熟)

- 触发三路:`/compact` 手动;阈值(`_checkCompaction` agent_end 后 +
  `_compactBeforeNextAssistantResponse` 下一响应前,**双检查点**);溢出
  (`_overflowRecoveryAttempted` 单次闸,删失败轮→压缩→重试);
- 判定 `tokens > ctx − reserveTokens(16384)` 固定绝对值:200K 窗 ≈92% 触发
  (设计语义 = 留 16K 给输出+安全边际),**20K 窗 18% 触发是绝对值在小窗的
  失控而非设计意图** —— 且 pi 原版 keepRecent(20000)无窗口夹紧,20K 窗
  压缩判定频繁成立却无可压缩(累计不满保留窗口),「又激进又无效」;
- **参数可配化**(settings-manager.ts):`compaction.enabled / reserveTokens /
  keepRecentTokens` 三参数用户可配,且支持 **modelOverrides 按模型覆盖**
  (解析序:模型覆盖 → 普通设置 → 内建默认)——Cogent D1 的 ROOM_FLOOR
  可配化 + 按模型覆盖有直接上游先例;
- max_tokens 预算(`clampMaxTokensToContext`):`min(maxTokens, ctx − input −
  max(4096, input×15%))`,下夹 1;大窗时 15% 比例边际、小窗时固定 4096;
- length 防御 = failToolCallsFromTruncatedMessage:截断消息里的 toolCall
  **全部 fail 成 toolResult**("arguments may be truncated. Re-issue the
  tool call with complete arguments"),`terminate:false` 回合继续,模型读到
  错误自愈重发 —— **是「防残废调用」不是「续写」**,pi 无 auto-continue;
- 思考钳制两通道:anthropic(`adjustMaxTokensForThinking`,官方参数)/
  openai 方言(`resolveClampedThinkingBudget`,**要求 compat 配
  thinkingTokenBudgetField 才发预算字段**,面向 vLLM/Qwen/DashScope/
  SGLang/llama.cpp 自托管端点,默认关、目录不带)。

### 3.2 DeepSeek-Harness(dsh,源码级:reference/deepseek-harness)

- **能力 seam 架构**:Service Definition / Provider / Consumer 三分,
  compaction 是可插拔能力而非 agent-loop 主干;压缩域拆独立包:
  `compaction-basic`(判定+摘要)/ `compaction-tool-result-pruner`(L1
  裁剪)/ `compaction-image-offload`(图片卸载)/ `command-compact`(手动);
- **触发公式(源码 compaction-basic/src/config.ts + types.ts)**:
  `tokens > min(ctx × thresholdRatio(0.8), ctx − 预留输出 − headroomTokens(64K))`
  —— 占比与绝对余量双参数合成、先到先压;retainRatio(0.16)保留
  `(ctx − 预留输出) × 16%` 原文尾部(**按窗比例**的保留窗口);全部参数
  支持 **modelPolicies 按 provider/model 精确路由覆盖**,另有
  `compactionRetries / maxOverflowRetries` 可配;
- 检查点:pressure 在 `agent/pre-step` 与 `agent/request` 两处;溢出路径
  「低于常规阈值也强制做一次有用的平衡缩减」;另有空闲压缩(手动、低于
  阈值也能做);
- **prune 先行(源码 tool-result-pruner/src/config.ts)**:确定性
  head/middle/tail 裁剪 —— 超过 8192 字符(code point 计量,防切代理对)
  才裁,保头 4096 / 保尾 1024,只替换 middle 为
  `[... tool result middle pruned ...]`,保留 rich-block 顺序;每处替换前
  追加 shadow-price 事件(纯消费者按事件扣减);prune 后重新计量,
  **可无摘要直接推进**;
- **摘要请求 = 主请求真前缀(源码 summarizer.ts 注释原话)**:摘要指令
  **作为最后一条 user 消息**跟在重放对话后,而非独立系统提示词 —— 保留
  会话自己的 system prompt/tools/消息前缀,使辅助调用成为上一次真实请求
  的真前缀,**provider KV cache 复用而非失效**;8 节模板与 Claude Code
  泄露模板同源;落地为 `<compacted-summary>` 标签包裹的替换 user 消息,带
  CHECKPOINT_PREAMBLE(视为既定背景、直接继续、不承认压缩发生);迭代 =
  旧 checkpoint 不照抄、按规则合并为单一摘要;
- **surface 位置语义**:替换 = 追加 user/message 带
  `surfaceOp{op:'replace', startSeq, endSeq}`;转录**只追加不物理删除**,
  shadowedSeqs 是位置跨度(新摘要节点 seq 更高但位置更旧,start 可大于
  end)—— 追加式的存储基础;
- 事务:compaction/start(获锁)/summary/end(释放,end 最后落盘);崩溃 =
  孤儿锁(start 无匹配 end),未匹配 start **阻塞所有压缩入口**;手动失败
  码六种(busy/cancelled/changed/summary/commit/persistence);
- 溢出恢复:`agent/request-error`;**切界保 tool-call/result 配对但不保
  整 turn**(超大 turn 的早期已闭合步骤可单独压缩);
- 独有:**image/offload 图片卸载**(保节点身份、卸内容)。

### 3.3 Claude Code

- auto-compact 占比触发,公开资料 75–95% 且**新版本偏早**(~75%,方向是
  「保护工作记忆」);`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 可配、可整体关闭;
- **microcompact**(0.2.x):空间紧张先只清旧工具调用输出(轻量不打断),
  整段摘要是后备 —— 与 dsh 的 prune 先行同构,先便宜后贵;
- **auto-continue**:响应截断自动续写拼接(changelog 多个 auto-continue
  修复为证)—— 五家里唯一明确的续写机制;
- 手动 `/compact` 可带聚焦指示(只保某主题);8 段结构化摘要模板随版本
  泄露、广为流传。

### 3.4 Codex(OpenAI)

- 阈值可配但**硬钳窗口 90% 封顶、只许调低** —— 「宁早勿死」取向;
- 2026 实验性 Context Management:支持的服务端**在流中**触发压缩
  (mid-stream compaction output item),非 codex 模型走本地;
- 实测两态(2026-11-12 截图):进行中「Compacting context · This can take
  a few minutes」(回合内状态条、可停止)→ 完成「Context automatically
  compacted」标记行(不展开摘要原文)→ **任务无缝继续**(还记得补读哪个
  文件、后续计划);
- 历史教训:曾 ~220K 无感压缩引发社区不满(issue #4106)—— 压缩时机的
  用户感知是产品命题,不只是技术命题。

### 3.5 DeepAgent(LangChain)

- 中间件 opt-in(`summarization`),挂在**图编排层**:压缩即图状态,
  天然可持久化/恢复;步数/触发器可配,摘要替换旧消息;
- 对照启示:Cogent 的线性转录 + persist 原子写在「压缩可恢复」上等价
  (转录即真源),但 dsh 的孤儿锁显式暴露「压缩进行中崩溃」这一中间态,
  是更细的工程颗粒(我们单写者模型天然无此并发面,暂不需要)。

## 4. Cogent 现状与缺口

**已落地**(批次 4,冒烟 8 项全过):submit 前阈值压缩 + session.compact
手动路;6 节 checkpoint 摘要 + 文件表 + 迭代合并;线性转录 compactionSummary
角色 + convertToLlm;保留窗口按窗口夹紧;compacting 并发护栏;落盘重启
复原;UI 折叠条 + 指示器预警线与回落。

**实测死锁复盘**(2026-11-12,20K 窗 deepseek-flash):

```
占用 43% → room ≈7.2K,正常(seed 进账 15.7KB/轮)
占用 67% → room ≈2.4K → 思考吃光 → length 空回复(连 toolCall 都没有)
        → 工具不执行 → 上下文停涨 → 到不了 90% → 压缩永不触发 → 死循环
```

根因链(四个独立因素叠加):① 触发线只看占比(90%),不感知 room;
② max_tokens 公式固定 4096 安全边际(pi 同款);③ 自定义 provider 无
compat 通道,思考预算不下发;④ DeepSeek 端点只支持 reasoning_effort
软控制,无预算硬上限。**任一环补上即可解**,但 ① 是唯一对所有端点可靠的一环。

**缺口清单**:死锁无防御(①)/ 检查点单点,回合中途饿死救不了 / 无 prune
分层(饿死大头恰是工具输出)/ 无溢出恢复 / length 截断直接暴露给用户 /
手动压缩无 UI 入口。

## 5. 方案定稿(决策 D1–D9;D9 为 2026-11-12 GUI 验收后补)

- **D1 触发公式(治死锁,治本)**:
  `shouldCompact = tokens > max(ctx × 0.5, min(ctx × 0.9, ctx − ROOM_FLOOR))`,
  `ROOM_FLOOR = 8192`。128K+ 窗行为不变(90%);20K 窗 → 60% 触发,room 恒
  ≥ 8K − 4096,自由思考也饿不死工具调用。ROOM_FLOOR 不小于
  `4096(边际) + 2048(思考 typical) + 1024(pi 答案保底) + 余量`;
  特小窗(ctx < 2×ROOM_FLOOR = 16K)由 ctx×0.5 给**阈值**兜底防触发线贴地
  (完备化计划评审修正 2026-11-12:原表述「max(ROOM_FLOOR, ctx×0.5)」按字面
  在 8K 窗是 no-op、阈值仍为 0;且绑定边界是 16K 不是 8K——余量线在
  ctx < 2×ROOM_FLOOR 时才低于半窗)。
- **D2 检查点补双点制**:submit 前(现有)+ **工具轮间 pre-step**(每次
  工具批完成、下一请求派发前检查;pi 上游 agent_end 后检查点即此意,
  dsh 的 agent/pre-step 同款)。回合中途也能腾地 —— Codex「压缩不打断
  任务」的时机基础。
- **D3 分层 L1/L2**:压力达标先 **L1 prune**(工具结果确定性裁剪:参数
  直接采纳 dsh 源码默认 —— 超过 8192 字符(code point 计量)才裁,保头
  4096 / 保尾 1024,只替换 middle 为 `[... tool result middle pruned ...]`;
  保 toolCall/toolResult 配对;每处替换记 prune 事件,UI 可呈「已裁剪 N 处
  工具输出」),重新计量;仍超线再 **L2 整段摘要**(现有引擎不动)。
  L1 是纯文本操作、零 LLM 成本、缓存断点最少 —— microcompact/dsh prune
  双重验证过的路线。
- **D4 length 防御三道**:(a) D1/D2 保底(治本,几乎不再发生);(b) 照搬
  pi `failToolCallsFromTruncatedMessage`(截断 toolCall 全 fail + 自愈
  重发,防残废参数执行);(c) 呈现层:真截断时橙色提示条升级为动作
  (「继续生成」/「立即压缩」)。**auto-continue 挂远期池**(Claude Code
  独有;与 prune/room 修好后收益边际化,且续写在 room 真尽时照样失败)。
- **D5 溢出恢复(pi 同款)**:provider 报 context overflow → 删失败轮 →
  L1→L2 → 重试一次,单次闸防循环。D7 当年砍它的前提(「真溢出走
  run.failed 显式暴露」)在死锁复盘后修正:显式暴露没错,但暴露之后
  应该有自动出路。
- **D6 思考预算通道**:ModelDef 增补 compat 字段(`thinkingTokenBudgetField`
  三枚举,照 pi 语义),自托管 vLLM/Qwen 端点吃硬钳制;DeepSeek 类端点
  无法硬钳(仅 effort),依赖 D1 兜底 + UI 在 room 低位时提示降思考档。
- **D7 缓存友好(拆两半)**:**近期** —— 采纳 dsh 的「摘要指令内联」:摘要
  请求不用独立 system prompt,而是保留会话 system/工具声明/消息前缀、把
  摘要指令作为最后一条 user 消息(源码注释实证:成为上一次真实请求的
  **真前缀**,KV cache 复用而非失效)——Cogent 侧改动集中在
  buildSummarizationContext,量小收益直接(完备化 R4 已落地);**远期** ——
  dsh 的追加式 surfaceOp 与 Cogent 线性转录 + pi 重放语义冲突面大(估算
  时效守卫/convertToLlm/落盘复原全要跟着改),等真实账单说话 ——
  **2026-11-12 账单已到,以 D9 保留式变体拉近结清**(见下)。
- **D8 事件与 UI**:compaction.started 已有 → 补「压缩中」状态条呈现
  (Codex 形态:回合内、可停止);折叠条不变;**手动压缩入口**(权限区或
  指示器悬浮卡,session.compact 已通协议);prune 事件 → 折叠条副行。
- **D9 保留式呈现(2026-11-12 GUI 验收修正,决策于完备化完结之后)**:
  销毁式重建(压缩条顶置 + 被摘要区物理删除)实测不可接受 —— 对照用户
  提供的 Codex 截图,主流形态是**旧消息全部保留可滚、压缩标记行原位嵌在
  发生位置**。修法 = 转录**保留式**:压缩只在切点原位插入压缩条
  (insertCompactionMarker,维持 S2 的 splice 原位纪律),影子区(末条
  压缩条之前)不删除、由 convertToLlmMessages 投影裁剪(全转录 system
  原序 + 末条压缩条投影 + 活区非 system;6 处 token 估算调用点全走此单点,
  投影一改判定/估算自动一致)。配套:①「刚压完」守卫换时间戳判定(压缩条
  不在末尾,旧 at(-1) 路径失效,不换守卫则手动连点反复重摘要保留区);
  ② L1 prune 限活区(影子区不进请求,裁它浪费且毁历史原文);③ 渲染层
  completed 手术改插入(不再删除旧消息)、压缩条唯一 id(多次压缩多条
  并存)、**呈现位 = 时间序而非转录切点**(标记行落在压缩发生的位置 ——
  「正在压缩上下文…」状态条消失处,Codex 形态;转录切点是影子区/活区
  语义边界,只服务投影)、run.completed 终态替换保留压缩条/副行、pruned
  独立呈现按 store 注释补齐、groupTurns 压缩条自起无头组;④ IPC 错误
  剥壳(unwrapIpcError,裸 "Error invoking remote method" 前缀不再直出)。
  完整 dsh surfaceOp 追加协议(shadow
  记账/位置跨度)仍在远期 —— 保留式已拿到全部产品收益,多消费者记账
  暂无消费方。

**参数总表**(全部引擎侧常量,可按批次调):

| 参数 | 值 | 来源/依据 |
| --- | --- | --- |
| COMPACTION_THRESHOLD | 0.9 | 占比上限(与 dsh 0.8 / Codex 90% 封顶同量级;pi 靠 reserve 兜) |
| ROOM_FLOOR | 8192 tok | 绝对余量下限,触发线取两者先到;≥ 4096 边际 + 2048 思考 + 1024 答案保底 + 余量;dsh headroom 64K 的桌面版;**可配 + 按模型覆盖(pi modelOverrides 先例)** |
| KEEP_RECENT_TOKENS | min(20000, ctx/2) | 保留窗口(现有;dsh 用 retainRatio 0.16 按窗比例,改比例制留批次内评估) |
| PRUNE_THRESHOLD | 8192 chars | L1 单结果裁剪触发线(dsh 源码默认) |
| PRUNE_HEAD / PRUNE_TAIL | 4096 / 1024 chars | L1 保头保尾(dsh 源码默认),middle 替换为 prune marker |
| OVERFLOW_RETRY | 1 次 | D5 单次闸(dsh maxOverflowRetries 可配) |
