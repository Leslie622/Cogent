## 1. 路线选择(十个维度,每条:选项 → 选择 → 优缺点)

### R1 触发判定 —— dsh 公式 + pi 可配化(两家之长)

选择:`shouldCompact = tokens > max(ctx × 0.5, min(ctx × 0.9, ctx − ROOM_FLOOR(8192)))`,
特小窗(ctx < 2×ROOM_FLOOR = 16K)由 ctx×0.5 给**阈值**兜底防贴地(评审
修正 2026-11-12:兜底对象是阈值而非 ROOM_FLOOR——后者按字面取 max 在 8K 窗
是 no-op,阈值仍为 0 每回合必触发;等价写法 = roomFloor 取 min(ROOM_FLOOR,
ctx/2),两种表述在绑定区 <16K 内同值);参数可配 + 按模型覆盖。

- 依据:dsh 源码同构公式(`min(ctx×0.8, ctx−预留−64K)`,config.ts),
  证明「占比+绝对余量取先到」在生产环境成立;pi settings-manager 证明
  三参数可配 + modelOverrides 三级解析(模型覆盖→普通→默认)的工程形态。
- 优点:大窗行为不变(90%),小窗 60% 即触发,room 恒 ≥4K(触发时
  ctx − threshold ≥ ctx/2 ≥ 4K),从根上拆掉死锁;两参数语义清晰,与 dsh 互为印证。
- 缺点:参数面变宽(阈值/下限/覆盖),设置 UI 与文档要交代;20K 窗触发
  频繁(两三回合一压)是物理规律,靠 R3 的 L1 降成本、UI 提示换大窗模型。

### R2 检查点 —— pi 原生回合内钩子 + 保留 submit 前(双点)

选择:保留现有 submit 前检查;**新增** pi Agent 的
`prepareNextTurnWithContext` 钩子(每个工具轮结束、下一个 assistant 请求
派发前检查)——pi agent-session 的 `_installAgentNextTurnRefresh` 同款手法,
Cogent 的 pi Agent 一等支持,直接照搬。

- 优点:回合内(工具链中途)也能腾地,这是 Codex 实测「压缩不打断任务」
  的时机基础;pi 源码在手,钩子语义、context 返回值契约全清楚,零发明。
- 缺点:回合运行中改转录(`agent.state.messages` 换引用)要守 pi 的
  setter 拷贝语义——好在 `applyPermissionNotice` 运行中改转录已有先例;
  renderer 侧折叠条手术与流式段追加并发,靠 summarizedUntil 锚保证只动
  历史区(见 §5 风险)。

### R3 L1 prune —— dsh 数值 + Cogent 原位改写(否决 shadow 追加)

选择:工具结果超 8192 字符(code point 计量)才裁,保头 4096 / 保尾
1024,middle 替换为 `[... tool result middle pruned ...]`;**原位改写
toolResult 消息**并落盘;每处附 prune 事件。检查点内先 L1 → 重新计量 →
仍超线再 L2 摘要。**范围 = 全转录**(dsh pruneSession 裁整个当前 surface
同款,含保留区内超限结果——只裁被摘要区的话小窗 L1 几乎必然不够,冒烟③
不成立;保留区大结果同样只保头尾是 dsh 生产验证的取舍)。

- 优点:数值直接采纳 dsh 源码默认(经过其生产验证);原位改写与 Cogent
  线性转录零冲突,marker 文本即审计痕迹;零 LLM 成本、缓存断点最少。
- 缺点(即否决 dsh shadow 追加式的理由):追加式要求「转录只追加 +
  位置语义(shadowedSeqs/surfaceOp)」的存储架构,等于给 Cogent 引入
  投影层——估算时效守卫、convertToLlm、落盘复原、UI 手术全部重写,
  是会话层重写而非压缩完备;dsh 需要 shadow 是为多消费者按事件扣减,
  Cogent 单写者没有这个需求。

### R4 摘要请求 —— 指令内联(dsh 式,替换现有独立系统提示词)

选择:摘要请求不再用独立 summarization system prompt,改为
「会话 system 前缀 + 被摘要区原消息(不文本化)+ 指令作为最后一条
user 消息」。dsh 源码注释实证:这使摘要请求成为上一次主请求的
**真前缀,provider KV cache 复用而非失效**。

- 优点:缓存钱直接省(压缩请求的 input 大头是被摘要区,深度缓存命中);
  原消息直传(不再 `<conversation>` 文本化),token 更省且工具调用结构
  保真;dsh 的指令模板规则顺带吸收(不提压缩本身、旧 checkpoint 合并、
  CHECKPOINT_PREAMBLE 前导语替换 pi 的 convertToLlm 前缀措辞)。
- 缺点:摘要请求体积变大(带完整 system/工具声明);`<conversation>`
  防续写的意图靠指令规则补(dsh 模板已含 "Do NOT continue" 类规则);
  前缀缓存命中依赖 provider 支持(DeepSeek/Anthropic/OpenAI 均支持,
  自建网关可能不命中——退化为无损失)。

### R5 溢出恢复 —— pi 式完整搬(删失败轮 → L1/L2 → 重试一次)

选择:provider 报 context overflow(pi-ai `isContextOverflow` 判定)→
删除失败轮转录 → L1→L2 → 原请求重试一次,单次闸防循环。修正批次 4 D7
「不搬」的决策(当时前提「显式暴露即可」在死锁复盘后不成立:暴露之后
应有自动出路)。

- 优点:pi 源码全有(单次闸、删失败轮顺序、重试点);dsh 的
  `agent/request-error` 恢复互证「仅当缩减生成推进才重试」。
- 缺点:错误分类依赖 provider 报文形状(各家 overflow 报文不同,
  pi-ai 的判定函数已聚合多方言,但自定义网关的长尾报文可能漏判——
  漏判退化为止步 + 显式错误,不劣于现状)。

### R6 length 防御 —— pi fail 已原生,auto-continue 自建(唯一无源码参照件)

选择:三层。① room 保够(R1,治本);② pi 原生 `failToolCallsFromTruncatedMessage`
——**核实即可**(Cogent 引擎就是 pi agent-loop,半截 toolCall 被 fail +
模型自愈重发已存在,补冒烟断言固化);③ auto-continue 自建:prompt 收尾
检测末条 `stopReason === 'length'` 且无工具调用 → 注入显式 continue 消息
再跑,上限 3 次;投影层把相邻续写段合并显示;续写仍失败 → 现有橙色
提示条升级为「继续生成 / 立即压缩」动作条。

- continue 注入取「显式 user 消息」而非 pi 的无痕 `finishTurn{continue}`
  (context-only turn):显式消息让模型明确「从截断处接着写」,Claude Code
  同款;无痕续跑模型可能开新话题。
- 优点:三层互补,用户侧几乎不再见截断;③ 是五家中 Claude Code 独有
  能力的补齐,pi/dsh 没有正说明它不属于引擎层,放 Cogent 的 run 编排层
  (session.submit 链)合适。
- 缺点:唯一没有源码对照的大件(自担设计风险);continue 消息进转录
  (保真优先,UI 聚合吸收);连环 length 时最多多花 3 次请求才停
  (上限闸住,且 R1 后罕见)。

### R7 思考预算 —— pi compat 机制透传

选择:`CustomProviderDef` 增加可选 `compat` 字段(schema 照 pi
compat-schema:`thinkingTokenBudgetField` 三枚举 + 相关项)。**落点修正
(2026-11-12 源码核实)**:pi-ai 1.5.0 里 compat 是 **Model 对象的字段**
(types.d.ts 按方言收窄;`CreateProviderOptions` 无此参数位,pi 上游
provider-composer 即 merge 到每个 Model)——Cogent 落点 =
custom-providers.ts 的 `buildModel()` 直接挂字段,未设置时 pi 按 baseUrl
自动探测;ModelDef 可选 `thinkingBudgets` 按档位预算。DeepSeek 类端点
无预算参数,靠 R1 兜底 + UI 侧 room 低位时提示降思考档。

- 优点:pi 机制原样接入,自托管 vLLM/Qwen/DashScope/SGLang/llama.cpp
  端点立刻获得「答案保底 1024」的硬钳制;对无预算端点零影响。
- 缺点:compat 字段是给懂端点的用户的高级面(默认全空),设置 UI 要
  收进「高级」折叠,避免普通用户误配。

### R8 存储 —— 否决追加式(本轮不做,理由不是优先级而是归属)

追加式 surfaceOp 是**会话存储架构**(多消费者、投影、按事件扣减),
不是压缩功能的一部分;其缓存收益的大头已被 R4(摘要请求真前缀)拿走。
若未来做,应立「会话层重构」计划,与压缩完备化解耦。本轮明确不做。

### R9 切界 —— 保持 user 边界(否决 dsh 按步骤切)

dsh 保工具配对不保整 turn 的切法,服务于「单 turn 超大也可压」;Cogent
线性转录的回合原子是批次 4 定稿,超大单回合场景由 R5 溢出恢复兜底
(prune 也是按 toolResult 粒度,已覆盖超大工具输出的主因)。保持现状。

### R10 图片卸载 —— 前置依赖缺失,本轮不做

Cogent 当前**无图片输入路径**(聊天无附件流,ModelDef.input 只是声明
位)。无对象可卸。留接口约定:压缩域事件预留 `image.offload` 形状,
图片输入落地时一并实现。
