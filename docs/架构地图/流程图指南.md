# 流程图设计指南（架构地图）

> 适用范围：`docs/架构地图/` 下全部专题流程图（新建与重构均遵循本指南）。
> 范本对照：`上下文工程与压缩转录`（逻辑版 `flowCompaction` + 源码版 `flowCompactionCode`）。

## 1. 第一原则：让图自己讲故事

1. **图讲全貌，右栏做补充**：读者不点开右侧详情栏，单看画布就应看懂整条业务/机制主干、关键判断条件、核心阈值以及各步由谁执行。不要把核心逻辑藏进右栏大段文字里，只留几个空洞的方框。
2. **逻辑与源码拆成两张真图**：
   - **逻辑版（默认）**：讲「怎么流转、为什么这么裁决、在哪执行」。卡片表面**零函数名、零代码符号、零未解释缩写**。
   - **源码版（`flow*Code` 独立视图）**：讲「真实钩子、函数与数据流调用链」。不是在逻辑版卡片上换一行副标题，而是通过 `flowCodeViewMap` 切换到真正的源码调用图；仅当存在独立源码图时，顶部才显示 `逻辑版 / 源码版` 切换开关。
3. **逻辑版必须标明技术归属**：哪怕不看代码，也要一眼分清关键动作是谁干的（例如 `Cogent Host`、`pi 内核托管`、`pi JSONL`、`pi SDK 投影`、`Host + Worker`），用卡片底部的 `runtimeOwner` 归属标签明示。

## 2. 拓扑与信息展开规则

| 规则 | 正确做法 | 反例（禁止） |
| --- | --- | --- |
| **连续主干** | 严格按事件顺序从左到右推进，收口清晰，避免回折箭头 | 出口套出口、节点互连成蜘蛛网 |
| **真实分流画在图上** | 存在条件分叉（如 `<85% 直通` / `≥85% 轻度瘦身` / `越线深度摘要`）时，直接画出并行路径与合流点 | 把条件分流硬画成一条看似每步必经的单直线 |
| **重环节用容器展开** | 多路入口、多步子阶段、双路出口用 LikeC4 嵌套容器（`system`）展开内部子卡（如 `1. 内容进入上下文`、`4. 深度摘要压缩`、`6. 两路分用`） | 怕画布变宽而把最核心的多步机制压成一张平卡 |
| **卡片直接写关键要点** | 用 `cardPoints`（2–3 条、每条不超一行）把核心规则、数值阈值和边界直接写在卡片里 | 卡片只写标题 + 模糊短语，细节全塞右侧栏 |
| **去黑话与孤立缩写** | 一律用自解释大白话（如「轻度瘦身（不调模型）」「深度摘要压缩」） | 在节点标题或连线上写 `L1`、`L2`、`DI`、`MCS`、`水合` 等内部简称 |
| **不混入正交机制** | 只表达真实因果链，正交机制放回对应视图 | 把“输出长度截断续写”挂在“输入摘要压缩”下游 |

## 3. 布局与连线纪律

1. **跨行容器与横向泳道互斥**：
   - 只要视图包含跨多行的阶段容器，**禁止同时配置 `laneLabels`**（泳道胶囊和横线会遮挡容器标题并拦腰切断容器）。
   - 横向 `laneLabels` 仅用于无跨行容器的平行泳道图（如源码调用图）。
2. **容器边界与备注**：
   - 容器底部 `notes` 保持单行精炼，由 CSS 自动防贴边溢出；
   - 跨容器边界入边由路由器在容器虚线外留白（≥16px），严禁垂直线段紧贴或覆盖虚线边框。
3. **箭头平齐与无交叉**：
   - 大容器单条出边指向右侧节点时应平齐对端中心，避免无谓小折角；
   - 多条同向入边汇入同一节点时，按近端内侧、远端外侧分配端口，避免无谓交叉。
4. **顶部工具栏分组清晰**：模式切换（`逻辑版 / 源码版`）与状态筛选（`全部 / 仅已实现 / 高亮缺口`）之间加竖向分隔线。

## 4. 右侧详情栏规范

1. **统一清爽三页签**（视图概览与节点详情同构，绝不把所有内容堆在一页长滚动）：
   - **`要点 / 职责`**：1 个高亮边界框 + 2–3 条不与画布重复的精炼规则；
   - **`开源对照`**（独立页签，有对照数据时显示）：结构化卡片分三层——顶部仓库标题栏、中性标签「对方做法」块、分隔线 + 浅底标签「Cogent 取舍」块；
   - **`源码`**：核心符号摘要 + 按「实现 / 模块与架构 / 验收 / 目标与计划」分组的可点击复制路径。
2. **开源对照取材铁律**：
   - **只对照本机可实读源码的开源参照仓**（核心为 `deepseek-harness` 与 `zcode`），绝不把未开源产品的外部猜测写成确定事实；
   - 文案说人话，讲清“对方怎么做”与“我们为什么这么取舍”，避免堆砌冷门内部文件名和框架术语。
3. **统一字号阶梯**：
   - 顶栏标题：`text-sm font-semibold`（14px）；
   - 所有可读正文、边界、职责、连线契约、开源对照正文、源码路径：统一 **`text-sm leading-relaxed`（14px）**；
   - 仅小节标题、标签胶囊、核验日期与符号提示用 `text-xs`（12px）；**禁止使用 `11px` 或把大段说明缩成 `text-xs`**。

## 5. 改动与视觉验收清单

每次新增或重构流程图，须同步完成以下两道检查（缺一不可）：

1. **自动守卫全过**：
   - `npm --prefix docs/架构地图 run typecheck`
   - `npm --prefix docs/架构地图 test`（`保真校验.test.ts` + `布局适配.test.ts`）
   - `npm --prefix docs/架构地图 run build`（离线单文件 `dist/index.html < 2 MB`）
   - 根目录 `npm run lint`（文档可达性、链接、字号与 ESLint）
   - 若增删了既有视图的节点或连线数，同步更新 `scripts/check-architecture-browser.mjs`。
2. **真实浏览器截图人工自查（不可只信单测）**：
   - 分别截逻辑版全局图、关键节点/连线放大图、源码版全局图及右侧三页签；
   - 逐项核对：① 无泳道/图例遮挡容器标题；② 无文字贴边或被裁切；③ 无小折角、无多余箭头交叉、无紧贴虚线边框；④ 逻辑版表面无代码函数名与黑话缩写；⑤ 右侧栏字号统一、对照卡片层次分明。
