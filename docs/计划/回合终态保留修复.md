# 回合终态保留修复

> 用户真机反馈：首片前停止后发送“你好”，原提问没有停止头；长文停止后发送“稍等一下”，
> 原回合变成“已工作”。这是上一批验收反例，本批在原授权内修复，不重复请求审批。

## 1. 实证与根因

本次只读实际运行记录确认两次停止均到达pi：首次约393ms、长文约7904ms后，
turn.completed.stopReason=aborted，随后run.failed=Request was aborted；后两条消息正常完成。
当前Host启动与构建时间均为21:49，未以“旧版本”推断归因。main/preload原样转发事件，
没有发现reason丢弃。用户截图不证明引擎没停，证明的是停止标签没有跨回合保留。

`HomeChat.tsx`只给最后一回合会话级lastRunOutcome，其他回合硬传done；追加下一user
立即把旧stopped变done。`TurnGroup.tsx`对空items+done只显示user泡，恰好解释首张图；
有正文则正常done头写“已工作”，解释第二张图。前批只测末回合，遗漏了停止后下一条消息。

## 2. 三仓与设计

沿用并复核同主题实现：pi `reference/pi/packages/coding-agent/src/core/agent-session.ts:209-217,
1139-1146`与`packages/agent/src/agent-loop.ts:250-264`提供真实终态；Harness
`reference/deepseek-harness/packages/core/session/src/types.ts:193-218`把结果存到turn/end；
zcode `reference/zcode/packages/ui/src/v4/conversationTurnRenderUnits.ts:172-202`从turnHeader
读取本回合状态。采后两者“结果属于回合”的分工，不新增引擎队列或替换呈现组件。

```text
owner: Host/pi = 实际run终态；renderer SessionBucket = 用户回合id -> 已知终态
run.completed/failed -> 原终态消息替换 + 同笔记录最后user.id对应结果
下一submit -> 新user与live；旧user的结果不改
手动continue -> 仍属同一user回合，运行中live；新终态覆盖该user的最新结果
HomeChat -> live优先，其余读本回合结果；只有未知历史才默认done
delete/整桶替换 -> 元数据随桶回收，切已有桶会话保留
```

SessionBucket新增按user.id索引的turnOutcomes；所有终态事件统一记录，不按正文匹配，
无输出也能记录。历史协议尚无结果字段，首次水合仍未知，不伪造历史中止事实；本批保证
同一已加载会话里跨后续提交/续写/切会话的终态稳定。无user组继续既有会话级fallback。
本地continue拒绝更新同一回合结果；submit同步拒绝撤回自身user时，不给上一回合乱盖失败。

## 3. 验收

- 真实bindEngineEvents+HomeChat：空输出停止→下一user，旧“已停止”仍在；半截停止→
  下一user→下一run正常完成，旧头不变、正文恰一份。
- 真失败→下一user保留失败；正常完成仍done；相同提问文本以不同user.id分别记录。
- 手动continue同user进入live后最终结果可更新，A/B与删桶/历史水合不串结果。
- 保留已有终态动画与准备期取消回归，定向typecheck/测试后完整四关并读全输出。
- 原位更新消息呈现、会话模块、技术笔记与手测册的“历史恒done”旧描述及代表场景；
  前批54文件484项只证明前批覆盖，不代替本批验收。
