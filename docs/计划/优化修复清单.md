## 仍需设计或实测的优化

| 优先级 | 主题 | 实施前需解决的边界 |
| --- | --- | --- |
| 1 | 窗口、文档与统一授权 | 把主窗口、控制台、可信 demo 和普通网页的顶层导航、frame 与 IPC 能力变成明确合同。审批还需确定真实路径、链接与执行时边界。[架构地图方案](架构地图目标架构.md) |
| 1 | 单写者、业务提交与转录迁移 | 第二个 Host 不覆盖同根数据。编辑、删除、凭据与配置写入需要明确提交和回滚语义。迁移区分完整导入、有缺口的前缀和两份均有独有历史，搜索与历史选择同一权威 |
| 1 | 配置就绪与项目换根 | 现有[配置修复方案](配置归属与启动同步修复.md)已有三仓对照，待审批。项目换根还需定义清晰的回合生效边界，使模型指令、工具、审批和文件共享根版本 |
| 2 | 回合身份、Host 生命周期与积压 | 统一跨入口受理与终态身份，处理历史/实时合并与 MCP 等待。进程代次管理断线、恢复和生产关停；连接另设在途与待发字节预算 |
| 2 | 文件资源交接和容量 | 草稿晋升需在 Host 校验后转移文件上下文所有权。附件废弃暂存、预览准入预算、搜索与观测 I/O 使用真实产品链测量后定策略 |
| 2 | 工作区极窄窗 | 400px 广域探针复现活动标签头被裁切，保留原始截图和几何条件。正式流式性能门槛仍依照[工作区验收余项](多标签工作区实现.md) |
| 3 | 测试并发与发行 | 验证 pi 缓存独立后评估集成并发。最终安装布局产出后，从安装目录量 Host 与各 worker 冷起；Linux 阶段先验证独立 Host |
| 3 | 内核与协议类型 | 待转录、配置和回合合同稳定后，再抽取内核职责、统一公开契约与事件投影 |

保留 Vitest 的源码、jsdom、产物三层，CI 补真实 Electron 最小链路。按缺陷与重复覆盖增删用例；数量不作验收门槛。
跨模块机制按 [AGENTS.md](../../AGENTS.md) 定方案。手测范围、历史失败和当前已验行为由[测试入口](../模块/测试.md#手测入口)索引。
