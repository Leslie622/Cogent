# 聊天正文主题化（路线 B：运行时主题包）

> 聊天正文 Markdown 观感由 Themd 主题包（`.themd.json`）运行时接管。
> 2026-11-16 用户拍板走路线 B（此前路线 A 静态应用为过渡态，其消费表被本方案
> 吸收）；本文档为动工前实现方案，审批通过后实施。

## 目标与动机

现状（路线 A 过渡态）：`globals.css` 末尾「聊天正文主题」段把 Theme-Leslie
的令牌值**静态写死**为 CSS 变量 + 消费表，换主题 = 改代码。且消费表只覆盖了
内容元素，三张实测截图暴露的差距都在包裹 chrome 上：

1. **链接**：Cogent 在 `markdown.tsx` 的 `a` 覆盖里硬编码 chrome-accent +
   中字重，主题令牌（`a.hoverColor` 等）管不到基础态；
2. **表格**：Streamdown 自带 `table-wrapper` 卡片（边框/底色/p-4）+
   `thead` 的 `bg-muted/80` 表头底，主题只动了表格本体；
3. **代码块**：Streamdown 自带 `code-block` 重卡片（border + bg-sidebar +
   p-2 + rounded-xl）与头部栏，主题完全没碰。

目标：令牌契约 + 编译器从 Themd 平移，消费表扩成全集（含上述三处），
`.themd.json` 在设置页导入、持久化、运行时编译注入——**改主题 = 导数据，
永远不改代码**。副产物：Cogent 获得第一个主题化能力（当前 UI 全局仅一套
观感，无暗色切换）。

## 对照结论（动工依据，AGENTS.md 规则 7）

| 实现 | 主题架构 | 出处 |
| --- | --- | --- |
| **Themd**（源系统） | 三层解耦：令牌契约（`'h1.size'` → `--t-h1-size`）→ 编译器（纯函数）→ 语义消费表（`var(--t-*, 回落值)`，回落值集合 = 极简主题）。主题文件只存差异令牌；导入按形状校验，坏字段按无值处理 | `src/lib/theme/tokens.ts`、`compile.ts`、`styles/theme-base.css`、`css-io.ts`；导入防御 `modules/themes/application/theme-controller.ts:69-84` |
| **deepseek-harness** | 样式与渲染同源自控：手写 mdast→React 渲染器 + CSS Module 消费，DOM 结构自己定所以选择器全可控 | `packages/client/ui-primitives/src/markdown/render.tsx:1-14` |
| **zcode** | 主题对象 → 语法样式函数（`createMarkdownSyntaxStyle(theme)`），绑定 TUI 渲染器 | `apps/zcode-cli/packages/tui/src/app-markdown-theme.ts` |
| **pi** | pi-tui 内置 `Markdown` + `MarkdownTheme` 主题对象；HTML 导出走 vendored marked 浏览器端渲染 | `modes/interactive/components/assistant-message.ts:5-8`、`core/export-html/index.ts:148` |

**结论**：Cogent 买 Streamdown 渲染（不重造 dsh 的手写渲染器），要主题自控
——Themd 的「令牌 → CSS 变量 → 消费表」是唯一能把**外部渲染器的 DOM** 与
**主题数据**解耦的架构：变量挂容器、消费表对 DOM 钩子、令牌随包走。
zcode/pi 的主题对象路线绑定各自渲染器，不可移植。

两个关键技术事实（已实测）：

- **cascade 红利**：Streamdown 默认样式是烤进组件的 Tailwind 工具类，经
  `@source`（globals.css:129）生成于 `@layer utilities`；**非 layer 的普通
  CSS 恒胜 layer 内规则**（与优先级无关）——消费表放非 layer 区即可整体
  压制，唯一例外是 Shiki 的内联 `background-color`（见 D2）。
- **稳定 DOM 钩子**：Streamdown 全部块级元素带 `data-streamdown` 属性
  （`table-wrapper` / `table-header` / `code-block` / `code-block-header` /
  `inline-code` / `blockquote` / `horizontal-rule` / `image`…），消费表按
  属性选择器命中，不依赖其 Tailwind 类名。

## 设计

### D1 令牌契约 + 编译器平移（`src/renderer/src/lib/theme/`）

- `tokens.ts`：`TOKEN_VAR` 契约**全量**平移（键 → CSS 变量名），未消费的
  令牌导入后无害存着（后续消费表扩展即生效），裁剪反而制造两仓分叉；
- `compile.ts`：令牌 → `{ [cssVar]: value }` 纯函数平移，含字体 latin+cjk
  拼合逻辑（`Xxx.fontLatin` + `Xxx.fontCjk` → 一条 font-family 栈）；
- `theme-file.ts`：`.themd.json` 形状校验（对齐 Themd `importTheme`
  防御：`name` 必需字符串，`tokens`/`dark` 须为对象，`extraCss` 须为
  string；坏字段按无值处理，不让坏文件污染令牌表）。**这是持久化读取
  边界（约定.md §1.1 第四行），防御合法**。

### D2 消费表全集（globals.css 非 layer 区，扩自路线 A 雏形）

原则：**只写主题能驱动的属性，回落值 = Streamdown 现状观感**；作用域
`.md-body`（markdown.tsx 的 Streamdown 根类，已挂）。令牌组 → DOM 钩子
映射（新增/修订处加 ▲）：

| 令牌组 | 目标（选择器） | 动作 |
| --- | --- | --- |
| root.font/size/leading | `.md-body` | 字体栈/字号/行高（回落 = 现状 text-sm 口径） |
| a.* | `.md-body a` / `:hover` | ▲ 基础态：色/字重回落正文、恒下划线 + `text-underline-offset: 0.2em`（Themd 极简默认）；hover 色 + 过渡（A 已有） |
| del.* | `.md-body del` | 原生 `text-decoration-thickness`（A 已有） |
| inlineCode.* | `[data-streamdown='inline-code']` | 字体/内边距（A 已有） |
| codeBlock.* | `[data-streamdown='code-block']` ▲ 容器卡片归零（bg/border/padding/radius/gap）；`-header` ▲ 语言标签淡化条（45% 透明色、自然高度、与 pre 同底色 + 顶圆角——Themd `.themd-code-lang` 观感）；其内 `pre` ▲ 底色/内边距/下圆角，**底色须 `!important`：Shiki 往 pre 写内联 background-color，CSS 无 !important 打不过内联**（全表唯一一处） |
| quote.* | `[data-streamdown='blockquote']` | 底色/圆角/内边距（A 已有；左边框仍归 Streamdown） |
| table.* / cell.* | `[data-streamdown='table-wrapper']` ▲ 追加 `background: transparent`（A 已除 border/padding）；`table-header` ▲ 中和 `bg-muted/80`；`table`（separate + 圆角）+ 单元格边框 + 末列/首行裁边 + `tbody tr:nth-child(2n)` 斑马纹（A 已有） |
| task.* | `input[type='checkbox']` | accent-color（A 已有） |
| hr.* / img.* | `[data-streamdown='horizontal-rule']` / `'image'` | 高度路线 / 圆角 + 边距 + 居中（A 已有） |

同时：**删除 A 的静态变量块**（`.md-body { --t-*: … }` 写死值）——变量
改由 D3 运行时注入；`markdown.tsx` 的 `a` 覆盖撤出 chrome-accent/字重/
下划线硬编码（**点击行为 preventDefault + window.open 保留**），样式归
消费表——UI布局.md:374 的「文内链接专用色」决策随之退役，进决定.md 防回潮。

### D3 运行时注入（单点挂载）

```
useThemeStore（zustand + persist → localStorage: cogent-themes）
  │  activeThemeId → ThemeFile（含 tokens/dark/extraCss）
  ▼
compile(theme)（D1 纯函数，useMemo）
  │  { '--t-h1-size': … } × 亮色块 + 暗色块
  ▼
ThemeApplier（聊天消息流容器上单点 effect）
  │  亮色块 → 容器 style（CSS 变量沿 DOM 继承，.md-body 规则消费）
  │  暗色块 + extraCss → <style> 元素（.dark 前缀变量块 / @scope (.md-body) 包裹）
  ▼
消费表不变（D2）
```

- 变量挂消息流容器单点（非每个 Markdown 实例重复挂）；CSS 变量继承使
  后代 `.md-body` 全部命中；纪律不变——**消费仅存在于 `.md-body` 规则内**，
  不污染 chrome/侧栏；
- `extraCss`（主题包自带的自定义 CSS）：用 CSS 原生 `@scope (.md-body)`
  包裹后注入 `<style>`（Electron 31 = Chromium 126，@scope 已支持），
  不做选择器改写（Themd css-io 的启发式映射是为「导入第三方 CSS」服务的，
  我们的方向相反——导出端已保证作用于正文）；
- 无异步链路：编译是同步纯函数，无事件顺序问题。

### D4 导入入口 + 持久化 + 切换 UI（设置页 appearance 分区）

- `useThemeStore`：`themes: ThemeFile[]` + `activeThemeId` + 导入/删除/
  激活动作；**全仓首个 zustand persist**——纯渲染端视觉偏好，不进引擎/
  协议/磁盘档案，localStorage 是对的层（跨设备同步是真墙：引擎侧无设置
  同步通道，首发不做）；
- 内置一个不可删除的「默认」主题 = 空令牌（回落值 = Streamdown 观感），
  Theme-Leslie 通过导入流程成为首个用户主题（也是验收用例）；
- 设置页 appearance 分区加「正文主题」区：主题下拉（默认 + 已导入）+
  导入按钮（file input，accept `.themd.json,.json`）+ 删除；导入即校验
  （D1 theme-file.ts），失败 toast 报错不落库。

## 边界 / 首发不做

- **`root.width` 不消费**：真墙是职责归属——正文列宽由布局层（分栏/消息区
  宽度）决定，主题管内容样式不管版面；
- **Shiki token 配色不进消费表**：真墙是层次——代码配色是内联样式 +
  `shikiTheme` prop 的领地（换配色 = 换 Shiki 主题，不是 CSS 主题）；
  消费表只管代码块 chrome（底色/边距/圆角/语言条）；
- **暗色套只编译待命**：`.dark` 变量块随注入生成，但暗色切换本身是独立
  特性（当前 `.dark` 休眠）——真墙是范围，不是技术；
- **不做可视化主题编辑器 / 主题导出**：真墙是产品边界——那是 Themd 的
  产品面，Cogent 是消费端；
- **不做主题跨设备同步**：见 D4，引擎侧无设置同步通道；
- **不迁移路线 A 的静态值为内置主题**：Theme-Leslie 走正规导入流程
  （顺带验证导入链路），避免「内置第二主题」这个无主特殊态。

## 验收

1. 四关全绿：lint / typecheck / build / npm test（新增 compile 单测：
   字体拼合 / 非法值剔除 / dark 分离；导入校验单测：坏 JSON / 缺 name /
   数组形 tokens 拒绝；现有 236 用例不回归）；
2. 行为钉（手测，导入 Theme-Leslie 后对照三张差距截图）：
   - 链接：基础态正文色 + 下划线（offset 0.2em），hover 变 `#3b82f6` +
     220ms 过渡；点击仍走 window.open 系统浏览器；
   - 表格：无卡片壳无表头灰底，2px 单元边框 + 8px 圆角 + 斑马纹，
     横向滚动不回退；

     可用，Shiki 高亮不丢；

   - 重启应用：主题选择与导入列表留存（persist 生效）；
3. 文档同步：模块/消息呈现.md（主题层运行时化）、UI布局.md:374 链接句改写、

   技术笔记/聊天正文主题.md（一模块一笔记：Themd 三层契约出处 +
