### §2 win7 / 国产机事实核查（决策依据；结论 = 锁 Electron 31，放弃 win7 本机）

**win7 死结链（为什么放弃）**：
- pi 三包（agent-core / ai / coding-agent）engines 全部 `node >=22.19.0`；Node 官方最后支持 win7 的是 Node 13，社区补丁最高 [node18-win7](https://github.com/Alex313031/node18-win7)（18.20.2），**无 Node 22 win7 构建** —— 自带打包（D11）救不了"node.exe 二进制本身在 win7 无法启动"
- Electron 22.3.27 虽是最后支持 win7 的 Electron（内置 Electron 自编译的、打了 win7 补丁的 Node 18.12），但其 Chromium 108 缺 color-mix()/oklch()，Tailwind v4 兼容专项成本高
- DeepAgent 有 TS 版（npm `deepagents` = langchain-ai/deepagentsjs，2026-11-13 修正此前"纯 Python"误记）：旧版 0.2.x + @langchain/core 0.3（Node ≥18）理论上可跑 win7（Electron 22 自带 Node 18）——曾使"22.3.27 + 双内核按平台路由"成为备选，用户权衡后仍选 31（新 Chromium + 无 CSS 专项 > 锁死旧版依赖的无承诺 win7 组合）
- win7 兜底通路（远期，零架构改动）：HostApi 面 B（HTTP/WS）+ 纯 web UI（Pi-meme apps/web 模式），任意现代浏览器可作瘦客户端
- 行业对照（2026-11-13 核查，主流 Agent 全线 win7 缺席，锁 31 与行业一致）：zcode = Electron 44 + engines `node >=24`；dsh = engines `node >=24.9`；WorkBuddy（腾讯闭源）= 官方明示「Windows 10 及以上，不支持 7/8/8.1」

**国产 linux 事实链（为什么是 31）**：
- 麒麟 V10 SP1 默认 glibc **2.28**（SP2/SP3 手动升级才有 2.31，不能指望客户机已升）
- Node 18 起 glibc 门槛 2.28 → Electron 19+（内置 Node 18）即 2.28 门槛；**Chromium 128（Electron 32）sysroot 换 Ubuntu 20.04，门槛跳 2.31** —— 麒麟 SP1 默认环境会 `GLIBC_2.31 not found`
- ⇒ 可锁窗口 = Electron 22~31，**锁 31**（窗口内最新）：Chromium 125 ≥111 Tailwind v4 原生；glibc 2.28 麒麟 SP1/UOS/deepin 全达标；官方 linux-x64 + linux-arm64 覆盖海光/兆芯/飞腾/鲲鹏；已 EOL 无安全补丁（信创内网可接受）
- 龙芯 loongarch64：官方 Electron 无此架构，靠龙芯社区移植（版本滞后不连续）——若为硬需求，单独验证龙芯镜像源或该机型走远程模式（HostApi 连 x64/arm64 机）
- 内置 Node 20.15 < 22.19：Host 仍用自带 node22（D11 不变）

## 4. 决策定稿（D1–D14）

- **D1 进程模型**：Electron 31 main 只做壳（窗口/IPC 白名单/凭据 safeStorage/token 签发）；**Host = 独立 Node 22 子进程**（`resources/runtime/node.exe`，版本守卫 ≥22.19，`COGENT_NODE_BIN` 覆盖口保留）。Electron 31 内置 Node 20.15 仍 <22.19，且独立进程白送崩溃隔离与 headless 模式（Electron 不在也能跑，对齐 Pi-meme apps/server）。
- **D2 HostApi 双面**：方法注册表**单一**，两个传输面。面 A stdio JSON-RPC（现 protocol v1 原样延续，协议纪律不变）；面 B HTTP/WS（Hono + ws，默认 loopback 关闭可开，远程模式启用）。不学 zcode 全走 WS —— stdio 对父子进程零端口占用/零防火墙弹窗（国产 linux 上 localhost 监听会触发安全提示），现有 main↔引擎链路零改动。
- **D3 scoped token**：Host 启动生成根 secret → 经 stdio 握手给 main → main 按消费者签发**一次性短 TTL capability 票据**（zcode hostCapability 模式：32B base64url、30s、消费即焚）换取长期会话 token（scope：readonly / session 绑定 / write / admin）。webview 页面只能拿到页面级 scope 票据。
- **D4 KernelRunner 合同**：`CogentKernel` 窄接口（创建/恢复会话、prompt/steer/abort、setModel/setThinkingLevel、compact、事件订阅、审批反向回调、usage 查询），形状 = pi AgentSession 方法面的可序列化子集 + Pi-meme 式 hostRequest 反向桥（approval / ui / context 三类）。**Host 服务层只依赖此合同**。参照 dsh 教训：不做 waterfall 全量合同、不做 replay 确定性承诺 —— 窄到够用，防复杂度黑洞。复杂度账（2026-11-13 质询后沉淀）：这份合同**已隐式存在**于现 `runtime/session.ts`（把 pi Agent 包成协议方法的那段），显式化的增量 ≈ 一个 interface 文件 + "服务层不许直接摸 pi 对象"的纪律；真正的 N 倍复杂度只在写第二个内核时出现（D5 明确不写）。它是纯期权——若最终只跑 pi，直接收益≈0，费用也≈0，砍掉是合理备选但建议保留（DeepAgent 反向校验防合同漏设计）。
- **D5 内核实现策略**：**只维护 PiSdkKernel 一个实现**（in-process `createAgentSession` + `AgentSessionRuntime`，会话走 pi SessionManager、agentDir=`~/.cogent/pi`）。PiRpcKernel（spawn `pi --mode rpc`，官方 RpcClient）作为合同预留位（崩溃隔离/独立版本时启用，零代码先行）。DeepAgent（TS 版 deepagentsjs；当前版依赖 @langchain/core 1.x 要 Node ≥20，将来若做内核需评估版本锁定）仅作合同反向校验（拿它的形态核对接口是否 kernel-agnostic），**不落实现** —— 多内核是"合同可扩展"，不是"多实现并行维护"。
- **D6 host 命运**：进程骨架（stdio 主循环/方法注册表/StorageDriver/项目域/凭据内存表/inspector）**演进为 Host**；手搓内核件（tools/ 8 工具 + truncate/output 三件套 + file-mutation-queue + edit-diff + shell.ts、compaction.ts、session.ts 的 pi 托管与转录持久化）**封存后删除** —— pi 全部内置且经过上游量产验证。技术笔记保留（学习产出不删）。
- **D7 能力总线**：不自研插件运行时。四座全部落到 pi 官方扩展形状：customTools（Host 特有工具）、InlineExtension（钩子：审批/审计/系统提示节/context 注入）、skillsOverride（技能座，Host 管目录；快照式注入 = Pi-meme snapshotSkills 模式——pi 无 snapshotSkills 这个 API，官方钩子名就是 skillsOverride，resource-loader.ts:324）、createMcpExtension（MCP 座，Host 管配置与授权）。dsh 的 seam 三角色纪律作为**逻辑纪律**采纳（每座 = 接口定义/实现/消费三角色齐备才立项），不做物理分包。
- **D8 审批链**：pi 扩展 `tool_call` 事件（async handler 天然挂起）→ 北向 `approval.request` → 裁决经 main 专属通道回填（旧计划（已归档）工具系统与审批.md 的 D3「审批独立成路」语义保留——勿与本文件 D3 混淆）。pi 的 `ToolAnnotations`（readOnly/destructive hint）作为审批分级输入，替代自研 ToolKind 的部分职责（ToolKind 保留为协议兼容投影）。
- **D9 对外 MCP Server**：独立入口进程（参照 Pi-meme apps/mcp）：HostApi 方法 1:1 映射 MCP 工具，Bearer token，**写操作默认关**（env 显式开启）。排后（阶段 5），但 HostApi 方法命名在阶段 2 起就按"可映射"约束（动词_名词、幂等键）。
- **D10 第三方页面嵌入**：`<webview>` + 沙箱属性（contextIsolation/sandbox/webSecurity，禁 node）+ preload 注入票据与 `window.cogent-host`（fetch/WS 小 SDK）。页面**永不直连 preload 的完整 IPC**；一切经 HostApi + token scope。MCP Apps 协议（zcode 模式）列远期互操作位。
- **D11 自带运行时**：构建期下载官方 node22（win-x64/linux-x64/arm64，SHA256 校验，Pi-meme 同款纪律）进 `resources/runtime/`。Electron 31 内置 Node 20.15 满足不了 pi ≥22.19，自带 node22 是唯一通路（现有架构.md 路线②直接转正）。
- **D12 工具沙箱**：初期安全边界 = 权限模式（auto/ask/plan/autonomous）+ 审批矩阵 + D8 链 + bash 只读命令分类（zcode bash-readonly-policy 精简版，正则级起步）。OS 沙箱（AppContainer/bwrap/seatbelt）远期，挂在能力总线"独占 seam"位（dsh 单槽模式）。
- **D13 调试系统**：现有 inspect 域（摘要常推 + 详情按需）+ 运行时控制台窗口 = 调试面 v1，不动架构只扩观测点（HostApi 面 B 打通后调试页可作为普通 webview 页远程使用）。网络抓包（zcode MITM 代理模式）列远期。
- **D14 Electron 45 → 31.x 降级时机**：**阶段 0 立即降**（2026-11-13 用户确认；同日二次定调：锁 31、放弃 win7 本机）。Chromium 125 ≥111，Tailwind v4（color-mix/oklch）原生支持，**CSS 兼容专项取消**。降级验证清单：streamdown/React 19 在 Chromium 125、webview tag、node spawn 链路、麒麟 V10 SP1 实机（glibc 2.28）跑通 linux-x64/arm64 构建。
