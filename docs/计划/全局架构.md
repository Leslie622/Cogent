## 1. 目标

- Electron 桌面壳与 Agent 引擎分离，同一 Host 可供主 UI、内嵌页面和外部客户端使用。
- pi 托管循环、工具、Provider、压缩与转录；Host 负责业务编排和信任边界。
- 能力通过 pi 官方扩展形状装配，不自建插件运行时；内核合同为未来替换留缝。
- 保持独立调试与本地优先存储，不以新增消费者为由复制一套引擎。

## 2. 平台边界与理由

桌面基线是 Electron 40.9.3、Windows 10+、国产 Linux 的 glibc 2.28 环境；
Host 优先使用自带 Node ≥22.19，引擎进程与桌面壳的版本周期分离。

平台约束如下：

- 麒麟 V10 SP1 的目标基线为 glibc 2.28，Electron 固定 40.9.3。
  x64 / arm64 官方发行包的静态 GLIBC 符号需求未超出该基线；核验依据见
  [Node运行时分发](../技术笔记/Node运行时分发.md)。不能从构建宿主的发行版名推断
  运行时 glibc 门槛；系统库、CPU、图形栈和完整应用仍须按目标机验证。
  Chromium 144 满足 Tailwind v4 的原生 CSS 基线。
- 不支持 Windows 7 本机壳：没有满足 pi 要求的官方 Node 22 Win7 构建，
  换成自带 Node 不能解决二进制启动限制；远期瘦客户端属于 Web 消费者范围。
- Linux x64 / arm64 的目标覆盖不等于已完成麒麟实机验收；loongarch64
  没有官方 Electron 构建，若成为硬需求需另验社区移植或远程模式。
- 后续运行时升级保留 glibc 2.28 的目标约束，按具体版本与架构核验，
  不把未经证实的 glibc 2.31 门槛作为排除候选版本的理由。

上述覆盖范围不扩大为所有国产 Linux。运行时分发出处见
[Node运行时分发](../技术笔记/Node运行时分发.md)。

## 3. 目标架构

```text
Electron Shell
  主 UI / 调试 UI ── preload 白名单 ── stdio ──┐
  第三方页面 ── 沙箱 guest SDK ── HTTP/WS ─────┤
                                              ▼
HostApi 北缝：同一方法注册表 + token scope
  │          HTTP chat 门面 / 拨出中继为未立项适配器
  ▼
Host 服务层：会话、项目、凭据桥、权限、观测、能力治理
  能力总线：工具+MCP / 技能 / 钩子 / 子会话（子会话尚未实现）
  │          交互工具经 customTools 装配
  ▼
CogentKernel 南缝：窄合同
  PiSdkKernel：唯一维护实现 → pi AgentSession
  PiRpcKernel / 其他内核：合同预留，不先写实现

外部 MCP 客户端 → 独立 MCP 入口 → 同一 HTTP/WS HostApi
运行时：必带 Node；git/python 由系统提供
```

## 6. 不造轮子与首发边界

直接用 pi：agent loop、steer/followUp、内置工具与截断、JSONL 树、压缩、
Provider/模型目录、usage、skills 渐进加载、AGENTS.md、MCP 客户端与扩展事件。
Cogent 自建：北向协议、业务会话/项目/权限、凭据桥、宿主工具、页面桥、观测与
MCP 方言映射；子会话协调器是后续 Host 职责。

边界必须有真实理由：git/python 不随包是体积与维护成本；OS 沙箱受目标平台
机制碎片化约束；云端市场需服务端；agents 内容物依赖未就绪的子会话座。
不自研插件运行时，不做 Win7 降级内核，不并行维护多内核实现，不承诺 replay。
不能把某个批次的未做项外推成整个方向永久不做。

## 8. 风险与验收纪律

- Electron 固定版本仍须跟踪上游维护与安全更新；平台符号需求符合基线不等于完整兼容验收。
- pi 升级前核对合同、扩展钩子、取消与投影语义；实际解析版本以 lockfile 为准。
- fd/rg 自动下载依赖外网；内网可通过系统安装或预置 pi/bin 解决，分发期预置待排。
- React / Streamdown 在 Chromium 144 的布局、动画，以及麒麟字体/对话框，须由
  对应实机矩阵验证。浏览器预览、jsdom 和四关不能互相冒充。
- 交付按[开发约定](../约定.md#13-交付自检)和对应模块验收执行。
