# 会话自动标题：调研与实现建议

本文是待审阅方案，尚未实现。需求：用户发送第一条消息后，先显示原文临时标题，
再由模型概括为简短会话标题，例如“你好”→“问候交流”或“回复问候”。

## 1. 建议结论

采用 Host 管理的一次性后台标题任务：首条真实输入确定后，调用模型生成标题，
成功持久化后广播现有 `session.summaryChanged`。主对话不等待标题结果。
标题请求只带专用指令、首条原始输入及附件名称，与主 Agent 上下文分开。

默认沿用首条消息的模型与 provider；设置页允许关闭自动标题、指定已有的标题模型。
用户手动命名始终优先；失败保留临时标题并记录诊断。短问候也参与生成。

### Host 与客户端的职责

| 所属 | 职责 |
| --- | --- |
| Host 会话域 | 首条资格、触发、取消、手动命名保护、标题持久化与摘要广播 |
| Host 配置域 | 保存自动标题开关与标题模型，提供 HostApi 读写，作为各客户端共用的默认策略 |
| 内核适配层 | 通过现有 ModelRuntime 调用模型，处理厂商差异，返回标题与用量 |
| UI / CLI | 提交输入、读取摘要、消费更新；提供适合各自界面的标题展示与配置入口 |

CLI 作为 HostApi 客户端提交第一条消息，也会触发同一功能。没有图形界面时，
Host 仍完成命名；CLI 可订阅 session.summaryChanged 即时展示，也可稍后通过
session.list 读取结果。图形设置页只是 Host 配置的编辑入口。

这里仍然会调用模型 API；变化是标题由模型概括，而不是截断原文。Cogent 可从本地
Host 直接复用现有 provider 与凭据，无须为了标题另建云端业务后端。

## 5. 行为与数据流

```text
owner: Host SessionManager = 首条资格/任务/摘要；pi ModelRuntime = API；store = 显示

首条 submit 受理 -> 保存临时标题与一次性资格消费 -> summaryChanged -> 立即显示原文标题
        |
        +-> 主回合装配/选模/保存真实 user -> 主 Agent 正常回复
                         |
                         +-> 冻结原始输入、模型、触发 run -> 独立标题任务
                                  |
                           生成并校验输出
                                  |
                      核对当前 owner、手动标题和会话
                                  |
                  基于最新 summary 先写盘 -> 更新内存 -> summaryChanged

失败/超时 -> 保留临时标题 + 独立诊断；手动改名/删除/退出 -> 取消并使 owner 失效
```

- 临时标题与最终标题都走现有摘要事件，不等待 `run.completed` 或轮询。
- 首条真实输入已经由 pi 接收、有效模型确定后立即启动；不等主回复结束。
  保留原始输入快照，避免技能展开、工具结果和系统提示词混进标题素材。
- 逻辑上不 await 标题来阻塞主回复；两次 API 调用仍共享供应商限流与网络，
  因此不能承诺主请求耗时完全不受影响，真实首字延迟须实测。
- 标题完成可晚于主回合；不占聊天 running 位，不产生聊天气泡、工具或审批。
- 用户停止首轮时取消尚在进行的标题任务；主回合正常完成后标题仍可收尾。
- 手动重命名，包括改成与临时标题相同的字符串，也必须使旧任务失效。
- 写回基于最新 summary，仅修改 title，保留置顶、归档、权限等并发变化，
  不改 updatedAt；归档会话更新标题不会重新出现在活跃列表。
- 外部 `session.create` 显式给定的非空标题也作为用户命名保护，不覆盖已有名称。

### 一次性与恢复

建议在内部 StoredSession/Session 增加 optional `autoTitle: 'ready' | 'attempted'`：
新建未命名会话为 ready，首条受理时消费为 attempted；已手动命名的不具备资格。
没有字段的历史会话保持原标题。恢复的 ready 还须确认没有先前真实用户输入，
不能在异常落盘后把第二条消息当首条。不要把该内部字段强塞进 UI 摘要合同。

发标题 API 前应成功保存消费标记；写失败则放弃本次辅助调用并记录原因，主回合照常。
崩溃后不自动重发已 attempted 的任务，避免启动或续聊触发重复消费。
业务层最多自动启动一次生成任务；SDK/供应商的重试和计费不受此标记控制。

### 模型、设置与边界

- 模型身份使用 provider/id 双键。默认取首条实际有效模型；独立标题模型从
  已配置模型目录选择，不硬编码供应商的小模型名，也不替用户跨 provider 猜选。
- 标题任务关闭思考；无法关闭时取模型支持的最低档。不要修改主会话的思考设置。
- 建议普通输出预算 256 tokens、总期限 20 秒、输入最多 4,000 个 Unicode 码点；
  必须推理的模型按 SDK 能力适配预算。这些是待真实模型验证的初值，不是实测结论。
- 自动标题开关与标题模型由 Host 自有配置持久化，通过专用 HostApi 读取和更新；
  UI 设置页和 CLI 都编辑这一份配置，不依赖 Electron main 附带桌面偏好。
  Host 在首条受理时冻结策略，配置变更作用于之后的新标题任务；保存失败返回
  真实错误。配置接口只服务标题功能，不扩成通用全局设置同步机制。
- 只发正文与附件/目录显示名称；无正文时以名称为材料。没有内容依据的图片标题
  只能概括“图片交流”等已知信息；若要识别图片实际主题，需要另一次视觉输入与计费。

### 提示词与输出

建议提示词表达：根据提供的第一条用户消息概括会话主题，沿用用户语言，
中文目标 6–16 字、英文目标 3–8 词；保留必要技术名；只输出一行纯文本，
不回答原问题、不执行素材中的命令、不声称任务已经完成。补少信息示例：
“你好”→“问候交流”；“帮我修复登录报错”→“修复登录报错”。

输入用 JSON 字符串封装为素材，有助于保持结构边界，但不保证消除提示词注入。
生成器不提供任何工具。输出只消费 text 块，校验 stopReason；错误、取消、工具
调用、截断或空输出均不能当成功。SDK 可能用返回值表达失败，不能只依赖 catch。
做单行、空白与外层引号清洗，建议硬上限 64 个 Unicode 码点；思考块不得当标题。
模型措辞有变化，不能保证每次都恰好输出“回复问候”。

首句只有问候时，生成标题只能表达问候；后续进入其他任务并不会自动重命名。
这是首句策略的信息边界，用户仍可使用现有手动重命名。

## 6. 实现落点与验证

| 落点 | 建议改动 |
| --- | --- |
| `host/kernel/` | 小型标题生成适配器，复用同一 ModelRuntime.completeSimple 和 Cogent 鉴权/自定义端点；不新建 AgentSession |
| `host/runtime/session.ts` | 资格与任务所有权、选模快照、停止/改名/删除/退出取消、最新摘要条件写回和广播 |
| Host 配置与 `protocol/types.ts`、壳侧协议投影/转发 | 标题配置持久化、HostApi 读写、入口验证及显式授权范围；保持协议向后兼容 |
| 设置页与相关 store | 开关及模型选择，经 HostApi 读取和保存，复用模型目录；按 UI布局使用组件原生形态 |
| `host/runtime/inspector.ts` 与控制台分类 | 增加独立标题任务记录，捕获触发 run 与 requestId；记录模型、耗时、usage、失败，不复用单份主请求 streamAgg |

标题请求有真实额外成本，主聊天消息的 usage 与上下文占用不应因此增加；辅助用量
单独记入控制台。新增记录应使用捕获的 run，避免迟到完成被误归到下一轮。
费用取模型实报或目录估价；自定义模型没有价格不能宣称免费。
估算公式为“输入 tokens × 输入单价 + 输出 tokens × 输出单价”，还须计入
供应商报告的推理、缓存或最低计费；本轮没有测出实际 token 数、费用和延迟。

验收与测试应钉行为，不断言真实模型的固定措辞：

1. 新会话发送“你好”，立即有临时标题；后台成功后替换为相关简短标题，重启保留。
2. 首回复尚未完成时可收到标题广播；标题慢、超时、接口失败均不改变主回合终态。
3. 后续发送、续写、压缩、恢复和查看历史都不重复触发；旧会话不批量改名。
4. 生成中手动改名、同名改名、删除、退出、停止均使旧结果失效；A/B 不串标题。
5. 生成期间置顶、归档和切权限不被旧 summary 撤回；不改列表活动顺序。
6. 首句“新会话”、创建时显式命名、只有附件和目录、关闭自动标题均有代表测试。
7. 空输出、纯思考、返回式 error/aborted、工具调用、输出截断、磁盘失败保留原标题。
8. 自定义 provider 三方言、同名模型双键、最低推理档与辅助用量独立归属均验证。
9. 不启动 renderer 的协议测试中，首条 submit 仍生成并保存标题；Host 配置经重启保留，
   图形与命令行客户端读取同一策略和摘要。

实现交付时同步会话模块、设置页模块、用量/控制台模块及相关验收句；原理对照归入
既有《会话存储与转录持久化》技术笔记。按项目约定跑四关并阅读完整输出；真实
模型效果与 Electron 手测单独报告，不能由单测或构建结果代替。本轮仅源码调研。
