# 架构地图目标架构

用户要求先画目标架构，再按架构推进后端；本批只修改架构模型、图的交互与说明，
不实施用户认证、业务授权或新协议接口。研究范围沿用用户确认：本仓库与 LikeC4 官方资料。

## 接线与职责

```text
stdio ── 本机调用身份 ─────────────────→ Cogent 协议 ──┐
                                                       │
HTTP/WS → 身份认证 ─┬─ 原生 /rpc、/ws → Cogent 协议 ────┤
                   └─ 自有协议调用 → 自定义协议适配 ───┤
                                                       ▼
统一权限检查 → HostApi ⇄ Host 服务层 ⇄ KernelRunner ⇄ 模型协议适配 ⇄ 远端模型 API

执行能力（KernelRunner 内）：工具、MCP、技能、钩子、交互工具、子会话（预留），不接入流程线。

KernelRunner 直接子块：PiSdkKernel、其他内核（预留）、执行能力卡片
容器说明：自带 Node 22 · SHA256；权限模式 · 计划 · 审批；OS 沙箱预留
```

请求向执行端传递，响应与事件按反向路径返回；原生协议保留 JSON-RPC 响应与通知，
自定义协议适配层负责旧请求、旧响应、错误和 JSON/SSE 流式格式之间的双向转换。
协议适配后再做统一方法与资源权限判断，避免新增接口绕过授权。
执行能力表示配置、装配与扩展职责；工具和钩子可在运行中参与执行，但总线不是请求转发的必经步骤。
配置治理与注册装配的结构关系保留在模型中，所有用户可见视图均不展示这些连接线。

UI 和远程服务均可作为调用方：可直接使用 Cogent 原生方法，也可保留自己的接口格式。
HTTP 与 WS 是传输选择，不能据此推断 UI 使用哪种业务协议；网络入口接收请求并认证后，
按所用协议进入原生处理或自定义适配。MCP Server 已在入口外完成转换，因此使用原生分支。
自有协议调用方明确包含 UI（远程、内嵌、自定义）和远程服务；点线直接连接其消费的自定义协议适配，实际调用仍经过网络传输和认证。
网络入口仅承载 HTTP、WS 传输，不处理协议映射。部分实现能力分行列出具体完成项与待完成项。

用户系统向认证层提供可验证的用户身份；当前 Host 自签 token 仍可使用。stdio 使用
受信任本机调用身份，不要求网络 token，但目标架构中也进入统一调用权限判断。

## 展示设计

模型提供总览、接入、执行三个视图，复用相同节点和关系；侧边栏只保留架构总览。
总览完整展示 Host 的接入处理、服务、能力、内核和运行基础，不依赖切换细图才能看到核心架构。
Host 保留大框，内部包含接入处理、服务层、KernelRunner 与模型协议适配，执行能力归属 KernelRunner。
整体分为接入与协议、业务分发、内核执行三个阶段，以 HostApi 和 KernelRunner 为衔接点；
HostApi 与服务层相邻，服务层、执行容器和模型适配沿调用主链直接连接；执行能力作为 KernelRunner 内的直接子块，与 PiSdkKernel、其他内核并列，以可点击卡片呈现，详情继续使用能力卡片，不接装配线。
KernelRunner 直接包含 PiSdkKernel、其他内核预留和执行能力卡片，自带 Node 与安全策略作为容器说明呈现。
服务与模型适配的外部调用统一连接 KernelRunner 容器边框，内部内核只表达包含关系。
服务层与执行能力在总览显示摘要卡片，点击进入各自的详细视图，展开职责后可返回总览；所有视图复用同一份模型。
能力详情只显示执行能力父块及六类能力，不放外部服务或内核参照节点；服务层详情去掉执行能力参照，只保留真实调用。
`scripts/layout-architecture.mjs` 通过 LikeC4 `layoutHints` 对齐主链与下方辅助层、提高横向主链权重，
配置与装配连线从可见视图排除，适配消费关系不参与主链层级排序；不可见排版约束不会成为模型关系。
结果通过官方 `save-view-snapshot` 保存到 `.likec4/`，开发、构建与测试前自动重算；
快照不入库。LikeC4 维护模型与一般布局；Runner 三卡紧凑排布及相邻三条主链在布局适配作受限投影，位置、bounds、标签与跨线共同使用最终几何。

Host 服务层包含会话与任务、项目、凭据桥、观测与能力配置；执行能力概括工具、MCP、技能、
钩子和交互工具，子会话明确标为预留。能力代码混合使用 pi 内置工具、官方 MCP 扩展与 Cogent 注入工具及钩子，由 PiSdkKernel 负责当前适配；其他内核仍是预留，不宣称已有独立跨内核能力总线。Host 服务层位于 KernelRunner 外，负责业务与配置治理。
KernelRunner 使用当前合同名 `CogentKernel`，内部包含 pi SDK 实现和未实现的其他内核。
自带运行时展示 Node 22 与 SHA256 校验；安全边界展示权限模式、计划开关和工具审批，OS 沙箱标为预留。

新增区块的实读依据：`src/host/runtime/session.ts:467` 为 `SessionManager implements CogentKernel`，
`:1742` 装配 pi，`:1499` 判定工具审批；`kernel/contract.ts:34` 定义内核接口；
`kernel/pi-session-factory.ts:195` 装配 MCP、`:230` 装配交互工具；
`src/electron/main/host/runtime.ts:44` 决定 Node 路径，`scripts/fetch-runtime.mjs:78` 读取官方校验表。
其他内核、子会话和 OS 沙箱的范围以[全局架构](全局架构.md) D5、D7、D11、D12 为准。
左侧展示桌面壳、按协议分类的网络调用方、外部 Agent；Agent 经标准 MCP 连接独立 MCP 协议适配，再进入网络入口。
接入视图展开 HTTP、WS，调用方与适配层的消费关系在图中直接连线；图中不展示脚本场景。
细图保留为局部阅读入口，不替代总览中的核心节点。
DSL 分别定义 `call`、`configuration`、`assembly` 与 `dependency`，适配器保留关系种类、线型和箭头；
配置与装配关系只记录结构语义，所有可见视图隐藏这两类连接线；可见调用使用实线实心箭头，适配消费关系使用点线开放箭头。
完成度不覆盖语义样式。未实现关系用标签橙点与「未实现关系」可访问名称表达，节点完成度保持独立。
双箭头表示请求及响应/事件使用同一连接的正反方向，紧凑图例只包含调用、适配依赖和未实现状态；视觉配方见 [UI布局](../UI布局.md#架构地图)。
外部系统单独标记为外部依赖。

LikeC4 负责模型与各视图布局，使用从左向右的原生正交布线；React Flow 读取布局结果。
Runner 内三卡以执行能力、PiSdkKernel、其他内核顺序单排，间距 24px，容器内距为左右 24px、顶部 56px、底部 40px，约 636×196；Runner 与服务层中心对齐，主链接左右中点。模型适配和远端模型同排，按新边界后 160px 间距接续，Host 按直接子节点包围盒收紧。其余路径保留原生路由。总览完整呈现 Host 核心，细图辅助局部阅读，保留缩放、平移、聚焦和三栏折叠。
默认保持文字可读，适应按钮显示全图。校验协议分支均经过权限层、返回方向、状态覆盖、
端口贴边、无共享线段、交叉明确跨越、不穿过其他节点、标签避让所有连线及离线浏览器交互。
