# 启动准备期停止修复

> 用户在阅读 [调研结论](启动准备期停止调研.md) 后明确要求“修啊”，本批据此实施所列
> 准备期取消、运行预约与内容保留范围。三仓出处和已安装pi的可控实验住调研文档，本文件
> 在代码前记录最终行为选择与验收；不再把同一修复方向拆成重复确认。

## 1. 目标与范围

submit、手动continue、manual compact准备期间点停止，Host记住意图，不在准备恢复后
继续发起模型工作；下一轮不能抢进尚未收敛的旧链。用户输入、续写前缀和最终结果保持一致。
删除/退出后旧装配结果不能起跑。使用已有pi公开接口和当前Host账本，不增加依赖或调度队列。

## 2. 已定行为

- continue在首await前预约StreamingState并发run.started，校验也是这次已受理工作的
  准备阶段。无效续写随后发唯一run.failed并保留RPC错误响应，避免无预约空窗。
  continue保持原来的长RPC完成时机；取消正常返回，真正错误仍由既有边界反馈。
- 装配完全失败属于真实失败，不因为点过停止就伪装stopped；显示初始化错误，不声称
  用户输入已保存。装配成功且尚未进入pi.prompt的取消，使用公开appendMessage与
  refreshContext保存原始user，再发aborted终态；已由pi交付的输入不可重复保存。
- 不用Promise.race提前释放运行账本。不能协作取消的准备Promise返回后才安全收尾；
  此前界面保持运行锁并显示“正在停止”，不能假装底层工作已经结束。
- continue的终态是最后用户回合的完整显示快照：保存此前assistant分段，与新增分段
  合并后交付，避免空快照或仅新尾段删除截断前缀；压缩条仍由既有替换逻辑保留，不重复装入。

## 3. owner与事件顺序

```text
Host: 本次StreamingState / manual compact操作对象 = 身份 + stopRequested
  同步busy检查 -> 同步预约 -> 异步装配/模型设置/校验
  await返回 -> 核对仍属当前会话/本次owner -> 消费停止或继续准备
abort -> 先置stopRequested -> 已有pi则调用原生取消
pi.prompt preflight -> preflightResult(started)补取消（不throw）
  -> core agent_start -> prepareRequest链式检查signal -> provider遵守signal
manual compact -> compaction_start(manual)按同一owner补abortCompaction
  -> 唯一终态/操作完成 -> 释放本次owner
delete/dispose -> owner失效 -> 迟到pi实例dispose，不prompt/compact

renderer: runRequestId分别关联submit/continue本次调用
  开始 -> 新身份；终态/新run/删桶 -> 旧身份失效
  RPC拒绝 -> 只收自己的在途调用，不覆盖已到终态或下一run
stopRequestId继续只关联abort回包，不代替运行请求身份
```

### Host与pi接入

1. StreamingState保存停止意图、输入是否交付/本次prompt分派情况；每个准备await后
   核对owner。manual compact从Set改为持有本次对象的Map，使取消和finally均按身份处理。
2. 通过preflightResult记录started/handled/queued；started只补pi.abort，不抛异常。
   handled无pi终态时由Host收口；Host不主动请求queued模式，不把queued误作完成。
3. factory链式包裹公开Agent.prepareRequest：调用原hook前后检查signal，保留原返回值
   和异常。已取消的请求可在provider入口前退出；后续异步取消仍依赖provider支持signal，
   不宣称任意时刻、任意provider都零streamFunction入口。
4. 完整续写前缀取当前pi转录投影的最后用户回合assistant分段，不把compaction条再装入。
   新run计费/Inspector仍按新增工作，显示快照带此前正文与其原用量，避免重复累加。
5. 取消早于prompt时保存原始user；prompt已开始分派但handled且无消息交付时，先确认
   本次调用已收敛，再处理输入与终态。外部准备错误走error，不能静默伪造成功取消。

### renderer

runRequestId保存于同一runtime桶；submit/continue的错误回写、delta队列丢弃都要先确认
本次身份。submit回滚按自己乐观user的id定位，不再盲删列表最后一条。已过期的RPC错误
不得重填输入或改新会话；真实当次拒绝继续显示错误并保留既有回填行为。
停止请求在途显示“正在停止”，源与视觉副本共用同一文案，不新增工作状态owner。

## 4. 验收与边界

- 卡住submit装配、setModel、pi input/auth、before_agent_start分别停止；恢复后零新增
  模型HTTP请求、唯一aborted终态；原生已支持的阶段不能回退。
- continue准备期挡第二次submit/continue/compact；取消保留前缀，正常续写与中途停止
  都保留前缀+新增尾部且正文/usage恰一份；无效续写失败后预约释放。
- manual compact装配期及内部await-abort窗口取消，不启动摘要模型；操作与run终态分开。
- 预prompt取消的user在live context、JSONL、重开历史中恰一份；handled不永久running。
- 准备失败/取消竞争、删除/退出期间装配返回、旧准备链不能改新owner；旧submit/continue
  reject不改已停止/已完成结果、不丢下一run的delta或复活已删除桶；A/B隔离。
- 先定向typecheck+相关测试；交付完整lint/typecheck/build/npm test并读全输出，
  集成测试使用新构建产物。同步模块、技术笔记、手测册和引擎图文手册。

底层未提供signal的任意扩展await不能强制杀死；本批保证停止意图不丢、后续工作不越过
可控边界，并保留账本等待收敛，不把后台仍在执行写成已经结束。无user组替换、工具封段
换父容器及历史停止标签持久化仍不属于此运行准备链，维持既有边界。

## 5. 实施记录

已落地上述范围。renderer内部submit返回Promise<boolean>：受理true，过期拒绝false，
真实当次拒绝仍抛错；ChatComposer另以请求/编辑/视图/卸载身份挡住迟到成功，防止旧响应
清掉新草稿或翻回旧会话。未改IPC响应形状。

实现先补实际红灯：

- Host最初7项全部失败，复现准备期停止后仍起跑、continue无预约、compact仍执行、
  迟到pi未回收、handled永久busy、启动未重放取消、续写前缀/usage丢失。扩为16项后转绿。
- renderer新增7项实跑失败，复现旧submit/continue拒绝覆盖终态/新run、删桶被复活和
  盲删列表末项。之后补草稿同文重新编辑/迟到成功/视图切换回归，按自身消息id回滚。
- 真实pi集成追加删除input-preflight场景，两种会话都实际多发1次HTTP。仅过滤Host
  事件不够；现用本次prompt的公开core Agent一次性agent_start监听，首次触发先退订，
  再按owner/stopRequested补取消，finally兜底退订。它不受AgentSession.dispose移除内部
  监听的影响；配合prepareRequest检查，两种删除均零新请求、无新终态、文件不复活。
- 第一次完整四关已通过54文件/483项。最后独立审阅又发现compact准备期被删除后RPC
  拒绝会经renderer patchBucket补造空桶，需补“只回写仍在的桶”的边界及回归后重新验收。

研究/测试夹具问题单独记录，不归因为产品：新集成fixture起初只注册ModelRuntime而未
同步Host目录导致unknown model；length夹具实报2小于max4096，触发pi原生recoverableLength
撤回assistant，曾被初步怀疑成user重复回补，实查后纠正。改为真实输出上限实报后，
自动与手动续写通过。新增fixture的InlineExtension联合窄化、取消包装单测Promise.reject
泛型以及断言lint问题也已修正；不把这些无效样本写成产品原因或首次即绿。

真实pi集成位于node project的 `src/host/kernel/preparation-stop.integration.test.ts`：
通过产品SessionManager/factory、安装版pi与本地OpenAI兼容SSE，公开扩展/装配边界只加
可控等待。10项已验证input/beforeStart/装配取消、handled、续写早停与正常前缀、manual
compact两个窗口及两类删除。它是源码级集成，不冒充构建产物stdio、真实外部模型或
完整Electron视觉验收；原有构建产物集成仍由完整npm test覆盖。

最后压缩回包补修也先新增回归实跑红灯：store41项中1失败/40通过，确有空桶被复活。
