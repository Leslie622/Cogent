# 会话搜索：调研与实施建议

本轮仅调研，本文为待审阅方案，未实现搜索。调研范围经用户确认：Cogent 现状、
pi / deepseek-harness / zcode 同主题源码、公开产品行为、shadcn Command 与本地探针。
入口见[全局架构](全局架构.md)；事实文档在实施后更新，不能把本文当成已交付能力。

## 1. 建议与目标

建议采用 **shadcn Nova Command 浮层 + Host 搜索服务 + 独立 SQLite 派生索引**。
输入关键词，找到聊天标题或用户/助手正文，预览命中上下文，选择后打开聊天并定位原文。
索引采用 trigram 加速较长子串；一、二字查询仍支持，以字面扫描补齐。

首发一起交付：侧栏入口与 Ctrl+K、最近聊天、标题和正文检索、中文短词、
项目筛选、归档查询入口、摘要高亮、同会话多个命中、原消息定位、加载/空态/失败反馈。
这些直接决定能否找到并用上历史内容，不拆成只有弹窗外壳的交付。

参考图借鉴“输入—分组—命中摘要—键盘选择”的结构。当前需求是会话检索，
浮层展示聊天结果；不先铺没有数据的“操作 / 文件 / 文本”页签。
如果以后增加其他搜索对象，再基于真实消费者扩展，不先造通用搜索插件框架。

`messages()` 还会计算上下文明细和系统提示词，因此不应逐会话调用它完成检索。
需要提取可共用的纯读取/正文投影部分，让历史呈现与索引使用同一文本规则。
本轮工作树中的自动标题改动正在进行；搜索只依赖已提交给 Host 的当前标题，
不接管标题生成、不改写其资格和人工命名规则。

## 5. 分词与运行时探针

在项目自带 `resources/runtime/win-x64/bin/node.exe` 上运行临时探针，
未读取真实聊天。结果：Node `22.23.5`、SQLite `3.54.1`、FTS5 可用，
`node:sqlite` 无需额外 npm 原生依赖；运行会产生实验性 API 警告。
[对应 Node 源文档](https://github.com/nodejs/node/blob/v22.23.5/doc/api/sqlite.md)
仍将 API 标为开发中，并说明 `DatabaseSync` 同步执行，故建议放 worker。
此证据仅覆盖 Windows x64 自带运行时，Linux/arm64 须在各自发行包验证。

正确性语料包含 `用户说你好，请检查登录报错；路径 C:\src\session.ts`，
以及带 `%`、`_`、引号、英文大小写和 emoji 的文本。八组路由断言通过：

| 查询 | unicode61 MATCH | trigram MATCH | 字面匹配 / 建议混合路由 |
| --- | --- | --- | --- |
| `你好` / `好` | 未命中 | 未命中 | 命中 |
| `登录报错` | 未命中该连续中文句内子串 | 命中 | 命中 |
| `session.ts` / `100%_literal` | 命中 | 命中 | 命中，标点仍作为字面字符 |
| `hello`（正文为大写） | 命中 | 规范化后命中 | 命中 |
| `OR` | 仅词边界命中 | 少于三字符未命中 | 按字面子串命中，也会命中 `World` 中的 `or` |
| `🚀` | 未命中 | 未命中 | 命中 |

建议索引和查询统一大小写规范化，FTS 使用 `trigram case_sensitive 1`；
三及以上 Unicode 码点的词项先用引号转义后的 MATCH 取候选，再做字面验证。
一、二码点通过 `instr(normalized_text, ?)` 匹配，不设“三字起搜”的产品限制。
多词中有长词时先用长词缩小候选，再验证其余短词。
不要把 JS 的 UTF-16 length 当作 trigram 字符数；原文高亮保留规范化到原文的偏移映射。

这与 [SQLite 官方 trigram 说明](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)一致：
MATCH 不支持少于三个 Unicode 字符的子串；无可用长片段时 LIKE/GLOB 会扫描，
LIKE 的 ESCAPE 子句也会影响索引利用。参数化与字面匹配是两个不同问题。

另做了 50,004 条合成消息的内存库探针，每条正文约两百余字符，每种查询八轮。
第二次运行按相同规范化与 `case_sensitive 1` 配方，采样中位值为：

| 查询 | 全表 instr | trigram |
| --- | --- | --- |
| `登录报错`，11 条命中 | 38.11ms | 0.03ms |
| `你好`，1 条命中 | 38.08ms | 不适用 |
| `好`，1 条命中 | 37.70ms | 不适用 |
| `session.ts`，1 条命中 | 28.27ms | 0.18ms |

探针只测候选计数，排除真实文件 I/O、首次建索引、会话聚合、排序、IPC 与渲染，
八轮也不是严格性能统计。它支持“长词索引有收益、短词扫描须隔离”的方向，
不代表实际产品延迟，更不能作为容量验收已通过。

最小复现方式是在临时内存库分别建立 `fts5(text, tokenize='unicode61')`、
`fts5(text, tokenize='trigram case_sensitive 1')` 与普通文本表，插入上述连续中文句，
比较 `MATCH '"你好"'`、`MATCH '"登录报错"'` 与参数化 `instr(text, ?)>0`。
探针文件仅位于系统临时目录；正式回归随实施补入测试目录。

## 6. 拟议设计

### 6.1 体验与匹配规则

- 侧栏搜索钮和主 UI Ctrl+K 打开同一浮层；标题“搜索聊天”，输入自动聚焦。
  快捷键不注册为系统全局快捷键，不抢文件编辑器自身操作；输入法组合期间不执行选择。
- 空输入列最近聊天；有输入时显示当前查询的结果。状态区分“正在准备历史 / 正在搜索 /
  没有找到 / 搜索失败”，准备不完整时不得显示成完整的零结果。
- 主结果每会话一组：标题、项目或未归类、更新时间、最佳命中摘要；
  正文命中标注用户/助手，提供多个可独立选择的摘要与“更多命中”。
  标题命中但正文没命中时，预览只能标为普通预览，不能画成正文命中。
- 默认搜索全部未归档项目及未归类会话，可切指定项目；提供“包含归档”。
  归档是本项目回收站，默认不混入日常结果。开启后可搜，归档行明确显示
  “恢复并打开”，选择复用 `archive(false)` 并等待成功后导航，不默默恢复。
- 文本为不区分大小写的字面子串；空白分隔的多个词默认 AND，限定在同一标题
  或同一条呈现消息内，避免远隔几十轮的两个词被拼成一个假命中。
  引号支持连续短语；未闭合引号按普通文本处理；`%/_/OR/*` 没有 SQL/FTS 运算语义。
- 排序为标题完整匹配、标题词项命中、正文命中；同档按近期活动、sessionId 稳定排序。
  正文摘要优先连续短语，再按词项覆盖和消息时间取最佳；不同会话的命中不按词频刷屏。
- 选择正文结果打开会话并定位该摘要；在聊天内保留查询与上/下一个命中控件。
  行项、摘要和聊天原文均使用同一匹配区间；高亮为纯文本节点/安全的范围标记，
  不往 Markdown 源文插 HTML，不高亮代码围栏等渲染后不存在的语法符号。
  原始 Markdown 中只有语法的命中仍定位所属段，反馈“匹配原始文本”，不得假造可见选区。

### 6.2 所有权与存储

```text
owner: Host SessionManager = 会话目录与真源；搜索服务 = 查询/更新编排
       单个搜索 worker = 派生索引单写者；renderer = 查询草稿与导航意图

侧栏 / Ctrl+K -> Command -> session.search -> Host目录过滤 -> worker查询
                                                            |
摘要 JSON + pi 当前分支 / 未迁移 v1 -> 共用只读投影 -> 派生 SQLite
                                                            |
结果(摘要+来源锚点+revision) -> 加载/切会话 -> 展开 -> 定位/高亮
```

- 派生库建议 `~/.cogent/search/sessions-v1.sqlite`，服从 `COGENT_HOME`。
  真源仍是摘要与 pi JSONL；搜索不写会话文件、不触发模型/工具装配。
- worker 常驻复用一个连接，独占写派生库；不按按键重建进程、不在 Host 事件循环
  跑 `DatabaseSync`。退出/worker 故障统一收口，诊断只能走 stderr，不污染 RPC stdout。
- 会话元数据表保存标题、项目、归档状态与修订；文档表保存可见正文、来源锚点和投影版本；
  FTS 为文档的派生候选索引。以呈现消息为搜索单元，助手续写合并沿用正文规则，
  不把一整段聊天简单拼成一个失去消息位置的大字符串，也不截掉长聊天后半段。
- 只索引 Host 会话目录明确拥有的文件。项目移除后会话仍可搜，显示“已移除项目”或未归类标签；
  无项目记录不意味着会话已删除。孤儿 JSONL 不重新成为会话。
- 识别库的归属与 schema 版本；不兼容但可识别的派生格式可显式重建。
  损坏库显示诊断和重建入口；损坏源文件报告是哪类读取失败，不当空聊天，也不修改真源修复。
  单会话故障允许其他结果可用，但响应与 UI 标记不完整。

### 6.3 初建、更新与异步顺序

1. Host 就绪后可准备目录，但首次打开搜索才启动建库/对账，按会话分批让出执行权。
   标题结果可先用已准备的元数据；正文准备进度单独呈现，完整性明确。
2. 持久化消息追加后发索引失效通知，合并同会话更新；在完整落盘与元数据绑定后再读。
   pi 公开 `message_end` 先发事件再 append，不能把该事件当成已提交信号。
   利用现有 append 包装取得真实 entryId，用户附件/来源元数据写完后再通知，
   工具循环的已提交助手段也要可更新，不只等整次运行结束。
3. 每次替换一个会话文档集使用事务，修订校验防止慢读取覆盖更新内容。
   文件读取前后核对来源身份/大小/mtime，变化重试；不能用 summary.updatedAt
   单独判断正文是否变化（标题修改也不改变 updatedAt）。同会话只保留一个在途更新与最新失效标记。
4. 搜索开始时对脏会话完成稳定对账；打开与重启校对目录及文件指纹。
   不变的全文不重复解析，外部修复/删除与 v1 导入变化在对账时被识别。
5. 删除会话先在 Host 可见目录中失效，响应前过滤失效 ID，worker 随后移除派生内容；
   迟到更新持有的 owner 已失效便丢弃。标题/项目/归档变化更新元数据与相关查询。
6. renderer 建议约 180ms 防抖；compositionend 后再请求。查询、筛选或关闭递增请求身份，
   只接收当前身份的响应。逻辑丢弃旧响应不等于取消了 Host/worker 工作；后端应合并同消费者
   尚未执行的查询，进行中的同步 SQLite 调用只能在返回后检查取消，不宣称已中断。

整个未封口的逐 token 助手缓冲不属于已保存正文；其完整段在落盘后进入结果。
这是当前真源的提交边界，搜索不会用临时 token 建另一份会话真源。

### 6.4 消息来源锚点与定位

保留现有 UI 消息 id/React key，增添独立可选来源元数据：真实 entryId 与其对应的
正文区间；一条合并助手消息可携多个来源区间。历史加载、终态段与索引共用这一映射。
在 pi 适配层沿现有 append 包装记录来源，再经 Host 窄合同交付，不把 pi 格式暴露给 renderer。
公开 pi 的 `_findPersistedMessageEntryId` 是私有方法，不作为接入点。

搜索结果携来源锚点与修订，renderer 用来源映射找当前桶的消息；不靠标题、时间戳
或摘录文本猜身份。未迁移 v1 用会话内来源序号加旧转录修订，导入后旧结果失效并刷新。
pi 自己的旧版 v1 JSONL 也要采用原始条目序号加文件修订：
`reference/pi/packages/coding-agent/src/core/session-manager.ts:286` 的内存迁移会新生成 ID，
不能把它当跨读取稳定身份。真实装配完成迁移后使旧锚点失效并重新查询。
来源元数据随段合并一起合并；迁移、压缩、自动/手动续写都要保留映射。

导航意图携 sessionId 和独立操作身份，等消息、来源映射、必要的过程展开都就绪再定位。
末次意图获胜，用户切到其他会话后迟到的搜索不得把人拉回来。
终态过程正文使用普通目标节点定位，保持现有不嵌套 `MessageScrollerItem` 的动画边界；
滚动前通过当前 controller 释放跟随。原文来源已变化时刷新结果并说明失效，不能跳错消息。
渲染高亮使用范围映射或 CSS Highlight 等非破坏性方式；具体渲染适配须以代码块、链接、
中文与合并段探针确认，不能通过重挂整个会话或改 Markdown 源完成。

### 6.5 协议与文件落点

建议新增只读 `session.search`，显式支持 query、项目范围、归档范围、
可选 sessionId、limit 与不透明 cursor；同一入口服务全局结果与“更多命中”。
响应含分组结果、摘要与区间、来源锚点、修订、nextCursor、完整性/索引准备状态。
建议默认每页 30 个会话、每会话 2 条摘要；更多命中按会话分页，避免一次搬回长历史。
游标绑定查询/范围/排序/索引世代；变化时返回明确的失效结果，重新查询首屏，避免漏页/重页。
限制作用于结果页和单次工作预算，不把语料只取前 N 条假装全文搜索。

| 落点 | 拟议职责 |
| --- | --- |
| `src/host/runtime/search/` | 搜索编排、来源目录、查询与索引生命周期 |
| pi 适配层与纯正文投影 | 只读提取、来源锚点，历史/索引/终态共用规则 |
| 独立 search worker 构建入口 | SQLite 单连接、事务、候选检索与字面验证 |
| `src/protocol/types.ts`、`src/host/host-main.ts` | 加法式协议、入口校验与方法注册 |
| `src/host/http/server.ts` | 新搜索方法列入 readonly；复用已有鉴权，不另开端口 |
| main 引擎白名单、壳共享类型、renderer `env.d.ts` | 显式接线，保持 renderer 不依赖 pi/protocol |
| `src/renderer/src/features/home/` 的搜索组件与状态 | 浮层、请求身份、结果、导航协调 |
| `src/renderer/src/components/ui/command.tsx` | CLI 安装的 Nova 原语，必要形态改组件本体 |

公开搜索入口沿现有 readonly 会话读取权限，项目筛选属于查询范围，不能冒充新的授权隔离。
本批不新增模型可调用的会话检索工具；若以后暴露给模型，须单独决定工作区可见范围与授权，
不能因 Host 有 GUI 搜索就自动让模型访问全部历史。

## 7. 路线比较、边界与验收

| 路线 | 判断 |
| --- | --- |
| renderer 遍历所有 `session.messages` | 不选：整段历史跨 IPC、内存占用大且污染消息桶；只能覆盖已加载桶的变体还会漏历史 |
| 每按键读全部 JSONL | 不选：重复解析与 I/O；可作临时正确性对照，不能作为最终实现 |
| 纯内存文本缓存 | 可做小语料方案，但冷启动仍全量读取、文本长期驻内存；当前更建议可增量对账的派生库 |
| SQLite 全量字面扫描 | 可验证正确性；中文短词需要这条路径，长词结合 trigram 能显著减少候选 |
| SQLite unicode61 全文 | 不作为默认：本次中文子串反例已复现，不能用英文词匹配结果证明中文可用 |
| SQLite trigram + 字面验证/短词扫描 | 推荐：本地运行时已有能力，兼顾字面语义、中文短词与增量索引 |

本批语料是聊天标题与用户/助手正文，包括正文里的代码和可见附件名称，覆盖压缩前
保留历史。工具返回的文件全文、思考、系统注入和压缩摘要不混进默认正文召回：
它们与用户可见对话不是同一信号，读文件输出尤其会淹没真实谈话；如需检索轨迹，
应显式定义范围与呈现方式，不能把本批范围外推为整个方向不做。

范围之外有实际成本或依赖边界：工作区/附件文件内容搜索需要独立的文件索引、
解析与文件权限生命周期；语义搜索需要额外的 embedding/模型、向量维护及联网/隐私决策；
当前单 Host 全量 readonly 与未来 session scope 的授权能力不同，后者尚未就绪。
这些不应靠加几个空页签伪装成已有能力，也不阻止便宜的项目筛选、归档查询和多摘要进入首发。

验收必须覆盖：

1. 标题、正文分别命中；中文 `你好/好/登录报错`、英文大小写、emoji、路径、
   `%/_/引号/OR/*`、多词 AND 与短语语义明确；没有标题或跨消息拼接出的假命中。
2. 重启后、从未打开的聊天、长会话后半段、压缩前正文、v1 尚未迁移、
   纯附件输入、项目移除、归档范围均可按规则查到；彻底删除和孤儿文件不可见。
3. 冷历史与已有直播缓存均能准确定位；续写合并、相同时间戳/重复文本不串消息；
   过程正文先展开再定位，流式吸底不把人拽回；失败/停止已保存部分可查。
4. 快速输入、输入法 Enter、快速选中 A/B、加载期间切会话/关窗、删除与重命名交错、
   worker 故障、重启/初建取消、游标失效均有确定结果，无迟到导航和旧结果覆盖。
5. 源文件只读验证、旧格式/空文件/中部损坏/末尾写入未封口、派生库损坏、
   无权限/磁盘写失败；错误不伪装成空结果，单会话异常不假称全量完整。
6. 键盘上下/Enter/Esc、焦点恢复、读屏、缩放、窄窗、深浅色；代码块与链接中的
   原文高亮不破坏 Markdown、复制和选区。Windows/Linux/arm64 运行时与 GUI 分别取证。
7. 真磁盘混合语料测冷建库/增量更新、1/2 字高频查询、长词、分页、内存与磁盘增量；
   建议暖索引首屏端到端 p95 ≤200ms 作为待验证目标，首次建库单独报告。
   同时运行聊天，验证 token 消费/停止请求不被检索阻塞；未达目标再据剖析调整短词索引。

实施分三步，但合并成完整功能后验收：①只读正文与来源锚点及回归；②派生索引与协议；
③Command、定位与完整体验。新逻辑随实现写行为单测；交付前按项目约定跑完整四关，
再执行上述真实 GUI/容量矩阵，自动测试与手测证据分别报告。

实施后同步事实归属：`模块/会话与对话.md`、`模块/工作区与项目.md`、
`模块/消息呈现.md`、`UI布局.md`、涉及目录/依赖的`架构.md`与会话手测册；
原理与三仓对照迁入`技术笔记/会话搜索.md`并入索引。迁移完成再删除本计划稿，
不提前在事实文档宣称已经可搜索。
