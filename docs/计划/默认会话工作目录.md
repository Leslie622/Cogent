# 默认会话工作目录调研与建议

> 调研日期：2026-11-22。范围按用户确认：三仓全量，重点Zcode。
> 状态：未实现，按用户决定暂缓；保留调研、建议与验收场景，后续另行安排实施。
> 本文未修改产品代码；当前事实仍见[工作区与项目](../模块/工作区与项目.md)、[多标签工作区](../模块/多标签工作区.md)。

## 1. 结论

建议对齐Zcode普通本地草稿的能力：没有绑定项目的每份新草稿，也能获得一个真实、独立、可持续使用的工作目录。
该目录同时供Agent执行、文件树、文件搜索和路径展示使用；首条消息形成会话后沿用原目录。

这是Host的会话工作目录机制，右侧多标签工作区消费其结果。仅修改文件区标题无法完成这项对齐。
调研建议在文件路线图③之前评估，当前暂缓，后续再确定实施顺序；默认目录本身不提供文件快照或回滚。

建议保留以下边界：

- 新建会话有明确项目/显式cwd时继续使用指定目录，多根项目继续支持多根。
- 未指定目录的新草稿/新会话采用独立受管目录，不使用一个所有聊天共写的默认目录。
- 默认目录及会话关联属于业务数据，跨重启保留；标签、网址、查看状态、展开态继续只在内存中。
- 旧会话保留原始cwd与pi转录定位，不自动搬文件或改变历史相对路径。
- 普通目录分开存放文件；权限模式、外部文件预览和既有读写授权语义继续由原服务负责。

## 2. 先分清四个对象

| 对象 | 含义 | 是否因关闭标签而消失 |
| --- | --- | --- |
| 项目 | 用户命名的目录集合、聊天归属及项目配置 | 否 |
| 会话工作目录 | 本次会话相对路径和新进程默认使用的实际目录 | 否 |
| 多标签工作区 | 右侧的文件/浏览器查看实例与布局 | 打开状态不跨重启保存 |
| 文件预览授权 | 独立文件或目录的读取入口 | 按既有grant/context/lease规则释放 |

未绑定项目可以拥有工作目录；拥有某个外部文件的预览授权，也不意味着该文件所在目录成为会话工作目录。
关闭查看器、删除聊天记录、删除实际文件是三种不同操作，不能相互代办。

## 3. 三仓实读结果

### Zcode：普通本地草稿使用独立目录

1. `packages/ui/src/v4/composer/composerDraftStore.ts:60–102`：客户端先保存稳定draftId，再绑定准备成功的workspacePath。
   重复点击、传输重试和重启可回到同一份待发送草稿。
2. `packages/ui/src/root/useRootWorkspaceActions.ts:377–415`：无项目的本地入口向Host发送draftId/reuseDraft；
   目录准备成功才进入工作面，再启动草稿。准备目录不等于创建真实聊天会话。
3. `packages/services/src/project/index.ts:275–340`：无项目时创建`workspaceDirectory/draft-<UUID>`，返回`projectId:null`；
   没有draftId的自动化等调用另行分配时间戳/UUID目录。已有草稿复用时只检查目录，缺失就报错，不重建空目录冒充原目录。
4. `packages/services/src/node.ts:2336`和`paths.ts:36–47`：默认根为`~/.zcode/workspace`，数据根可配置。
5. `packages/ui/src/WorkspaceFileTree.tsx:171–177`：文件树使用`target.workspacePath`，没有以projectId存在作为显示树的前提。
   `workspace-file-tree/WorkspaceFileTree.tsx:602–605`：标题优先非空工作区名，其次目录末段，最后才是通用名称。
6. `packages/services/src/project-storage/project-repository.ts:615–715`：正式会话创建先记录任务归属与原目录，
   创建命令有稳定回执。`packages/ui/src/v4/pendingCommandRegistry.ts:408–444`在接纳后清除待发送草稿身份，
   这条路径不需要把`draft-<UUID>`目录改名为session ID。

两个不能从截图推导的细节：

- 归入项目不等于切换cwd：`project-repository.ts:480–510`的moveTask要求原cwd已在项目根中，
  或经显式确认把原cwd加入项目；随后修改项目归属，不移动原目录。`project-repository.ts:115–153`继续按记录的root_path解析执行目录。
- Zcode也有共享默认目录入口：`paths.ts:50–53`、`file/fileService.ts:512–535`提供`workspace/default`，
  `packages/ui/src/Root.tsx:1182–1230`用于启动工作面兜底，`hooks/useModelProviders.ts:182–201`也用于本机连通性测试。
  因此“Zcode所有入口都按会话新建目录”不成立；本建议采纳普通本地草稿这一条路径。

删除方面，`session/zcodeTaskService.ts:701–724`区分任务隐藏/归档删除与保留CLI内容，
并另有永久删除接口。本次未证明其所有产品删除路径都会保留或清理默认目录，不能据此给Cogent复制全局自动清理策略。

### deepseek-harness：首次使用的共享默认工作区

- `packages/api/workspace-controller/src/default-directory.ts:35–78`：默认路径为系统Documents下的
  `deepseek-harness/default-workspace`；目录解析由Host负责，支持显式覆盖，查询失败明确返回错误。
- `packages/workspace/workspace/src/index.ts:263–290`：只在工作区注册表及会话历史均为空时初始化，
  串行处理、递归创建、规范化真实路径并登记。已有默认身份直接复用，不创建Session。
- 同文件`:319–331`：删除工作区登记保留目录与会话日志，不把“移除组织项”视为删除用户文件。
- `packages/session/working-directory/src/index.ts:90–205`：每个Session的当前目录由持久化投影拥有；
  设置目录检查文件系统，已有进程保留各自cwd。当前目录消失时只向有效的原始目录恢复，不任意选一个新目录。
- `packages/workspace/workspace/tests/workspace.spec.ts:1400–1435`有并发只初始化一次、复用不改目录内容、失败可重试的行为用例。
  本次仅阅读，未运行这些上游测试。

可借鉴Host单写、幂等准备、目录事实与界面标签分离；共享默认目录会让多份无项目聊天落在同一处，不符合本次更偏向独立会话的目标。

### pi：接受cwd，不替桌面产品分配会话文件目录

- `packages/coding-agent/src/core/sdk.ts:192–205`：cwd优先显式参数，其次SessionManager记录，最后进程启动目录；
  SettingsManager、资源加载器和会话管理器围绕它装配。
- `packages/coding-agent/src/core/session-manager.ts:587–604`：按cwd编码创建的是pi会话日志目录，
  不是给Agent写文档、图片等文件准备的默认工作目录。
- 同文件`:1773–1803`：创建记录cwd，打开已有会话可从会话头读取cwd。

因此可以继续沿用pi公开SDK，由Cogent Host准备并传入目录，无需修改pi内核。

## 4. 主流方案的交叉核对

查阅的是官方当前文档，不将网页介绍当成源码实测：

| 来源 | 明确说明的行为 | 对本次的启示 |
| --- | --- | --- |
| [Claude Code Desktop](https://code.claude.com/docs/en/desktop#start-a-session) | 会话开始前选择环境与项目文件夹；终端使用会话工作目录 | 界面、Agent和终端应围绕同一目录事实 |
| [Claude Code工作树](https://code.claude.com/docs/en/desktop#run-a-session-in-its-own-worktree) | Git项目可显式启用worktree，默认直接在项目文件夹工作 | 独立默认文件夹与Git工作树是两种能力；本次无需引入Git |
| [Cursor工作树](https://cursor.com/docs/configuration/worktrees) | 为Agent任务创建独立Git checkout，具备额外准备与清理机制 | 任务文件分开有收益，但Git准备和回收机制不宜作为普通文件目录的前置依赖 |

这些资料没有证明所有主流产品都采用Zcode式无项目草稿目录。推荐理由来自Cogent的目标和当前缺口，而非“别人都有所以必须照抄”。

## 6. 选型

| 方案 | 收益 | 成本/问题 | 建议 |
| --- | --- | --- | --- |
| 保持homedir回退与空树 | 改动最少 | 生成文件的默认位置与文件树脱节，多份聊天仍共用默认相对路径基点 | 不作为目标方案 |
| 一个全局默认目录 | 目录与树可以接通，改动较少 | 多份聊天的report.md、输出图片等仍可能互相覆盖，文件归属不清 | 不选作普通草稿默认 |
| 每份无项目草稿独立目录 | 生成文件可发现，草稿到会话来源稳定，减少默认相对路径文件冲突 | 涉及Host、首发身份和文件导航，需完整行为验证 | 推荐 |
| 每份任务都创建Git worktree | 项目代码可独立修改 | 依赖Git仓库，涉及分支、依赖与清理，不适用于普通文档会话 | 本次不引入 |

推荐项是一次中等规模的跨层功能，核心复杂度来自身份和兼容，不是mkdir本身；不建议拆成“先改标题、以后再接Agent”。

## 7. 建议合同与生命周期

### Host单写与目录准备

建议在Host会话/项目域增设受管目录服务，复用现有JsonStorageDriver，不引入新数据库。
业务记录持有目录身份、草稿归属、接管后的sessionId、准备状态与原始路径；renderer不拼接实际磁盘路径。

建议目录形态为`<COGENT_HOME或~/.cogent>/workspace/draft-<UUID>`，与本仓已有可备份的数据根一致。
记录与目录内容分开存放；使用Host数据根覆盖值，自动化可继续隔离全部文件。
显示名采用实际目录名，长名省略，悬停及资源管理器入口提供完整路径；名称不充当业务身份。

准备触发点是首次需要该工作目录时：打开草稿文件导航或准备首条发送；不要求应用启动时创建真实Session或打开任何标签。
新草稿入口可提前准备目录，但不由页面挂载承担唯一初始化职责。直接Host API创建的无cwd会话，也走同一个服务。

解析优先级保留现有显式cwd/项目多根语义；没有这些来源时才分配受管默认目录。
prepare可重复调用，同一草稿返回同一目录，多个不同草稿不会复用最近目录。
首次目录/记录提交失败明确报错；成功记录已交付的目录被移走后，报缺失，不静默重建或改回homedir。

### 草稿转会话

```text
owner：Host受管目录服务 = 目录身份与记录；SessionRegistry = 会话；renderer = 呈现

新草稿ID → Host准备目录 → 返回导航根 → 文件树/预览使用
                  └── 首次session.create（带草稿身份）
                        → 同目录接管到sessionId → Agent使用该cwd
                        → 首发接纳 → UI转为正式会话并轮换新草稿ID

收起/关闭标签 → 释放查看资源，保留目录与关联
退出/重启    → 标签为空，按会话重新查询原目录，不恢复标签
```

接管只改变业务归属，不改目录名、不挪文件。
session.create成功但agent.submit失败，重试必须复用同一创建回执，不能把同一草稿再变成第二会话/第二目录。
目录记录与session摘要无法靠一次文件rename共同提交；需要明确准备/接管状态、稳定sessionId与启动对账，
保证中途退出后能沿同一身份完成，而不是让renderer补写一份权威目录。

### 项目选择与既有会话

- 未物化草稿选择项目：后续首发使用项目目录；已有默认目录文件留在原位置，原预览作为外部文件继续可用。
  有文件的默认目录保留其业务关联和资源管理器入口，不因换选项目丢掉访问入口，不自动合并进项目树。
- 正式会话已经开始：后续“归入项目”的组织操作不自动切换cwd或搬文件；当前没有的热切换能力不在本次顺带新增。
- 项目多根和显式cwd继续成立；已存在文件的目录不因项目删除而被当成临时目录回收。

### 保留与清理

关标签、归档、删聊天默认保留实际文件目录；聊天删除时释放资源与解除活跃关联，不附带递归删除生成文件。
没有提交过的空草稿可以在确认空目录、没有业务引用后清理；实现前先定义判据，不能把“未发消息”直接当成“无文件”。
首批提供打开所在目录与明确保留行为。批量查看占用、查找遗留目录和显式清理属于后续管理界面，
不以缺少该界面为由阻塞默认目录贯通；也不在后台按年龄自动删用户文件。

## 8. 旧数据与现有能力

首批对新草稿/新会话启用；旧会话沿用已有piCwd、显式cwd及历史FileContext。
历史上使用homedir的会话不自动迁入空默认目录，避免pi日志定位、旧相对路径和产物来源发生变化。
旧会话仍可独立预览原文件；若展示原目录信息，应明确其身份，不默认遍历整个用户主目录。

如果以后要迁移旧会话，需单独覆盖pi日志锚点、原文件清单、相对依赖和回滚；
不能复制整个homedir，也不能将新目录中的同名文件冒充旧消息的原文件。

保留现有正文文件链接、产物交付副本、文件导航grant/lease、浏览器本地HTML授权与标签仅内存状态。
附件受管原件不搬入会话目录，不能将预览授权或附件引用自动升级为会话根。

## 9. 实施批次与验收建议

建议把A、B作为同一功能的两批交付，全部完成再宣称已对齐；C是可选管理增强。

| 批次 | 内容 | 验收门槛 |
| --- | --- | --- |
| A：Host身份与目录 | 准备/复用、草稿接管、headless入口、cwd/配置/提示词/来源统一、旧会话锚点保留 | 状态与失败回归通过；无renderer仍可正确创建；不修改权限档位语义 |
| B：导航与真实产品 | 树/搜索/标题读取实际导航根、首发与失败重试、重启保留文件但不恢复标签、资源回收 | 同一隔离资料两次真实启动；文件由真实Agent工具链创建并在树中出现；旧历史与①②相关回归 |
| C：目录管理 | 占用查看、遗留目录发现、显式清理/导出入口 | 另立删除合同；不影响A/B目录正确使用 |

核心自动场景：

1. 未发消息打开文件区：只准备目录，不创建假Session；新目录为空时有名称与空态。
2. 同草稿并发prepare/重复发送：同目录、同创建回执；不同草稿各写同名文件互不覆盖。
3. 默认目录下用真实工具创建文件：Agent cwd、工具路径、树、搜索、面包屑和系统打开指向同一文件。
4. prepare成功后首次session.create/agent.submit分别失败或回包丢失：重试不重复分配；落盘失败不发布假成功。
5. 草稿转会话、切聊天、关全部标签再打开、Host重连：目录身份保持；迟到结果不复活旧scope。
6. 正常退出再启动：文件与业务关联保留，标签、最近关闭、阅读状态和展开态为空。
7. 选择项目、项目多根、自有显式cwd、移除项目：使用约定根；已生成默认文件仍可访问，不自动搬家。
8. 已交付目录被移走、变成普通文件、权限拒绝：明确错误，未读成一个新建空目录。
9. 旧会话包含pi日志和历史相对文件链接：消息数量、piCwd、旧来源/交付副本不变。
10. 独立外部文件、附件与原生目录grant：继续能预览，不进入当前默认目录的树与搜索。
