# 文件链接与产物卡片及改动列表

> 状态：待用户审阅；本文不构成实现代码的批准。
> 范围：用户确定的三个功能；调研证据住在[技术笔记](../技术笔记/文件引用与改动追踪.md)，本文负责实施选择、边界与验收。
> 本方案按深度调研编制，覆盖 pi、deepseek-harness、ZCode、im-2.0 功能分支及主流产品公开资料。

## 1. 目标与界面位置

```text
聊天正文
  ① 文件链接：文件名带类型图标，可点击，支持行列定位
正文下方
  ② 产物文件卡片：突出展示需要交给用户的文件
     图标、文件名、类型、说明、打开/预览与更多操作
卡片下方
  ③ 改动列表：本轮全部净改动文件、增删统计、审查入口
```

- 三者共用文件身份、路径解析与打开服务；不另造“预览卡/正式交付卡”两类产品概念。
- **产物不必发生改动**：用户要求交给他一个既有文件，同样可以出卡。
- **改动不必成为产物**：源代码修改、构建脚本、过程文件进入改动列表；不自动全部出卡。
- **产物也保留在全部改动中**：列表回答“改了什么”，卡片回答“交付什么”。同一文件跨区出现是有意行为，不能把产物从列表减掉。
- 不要求使用 Git、不要求模型记得在终答里逐个列出改动文件；重启后仍能看本批记录的产物及冻结 diff。

## 2. 调研结论与选择

以下为固定版本的源码结论，具体文件与行号见技术笔记 §3、§5、§9；不是同模型任务成功率排名。

| 主题 | 参照做法及长处 | 问题/代价 | Cogent 选择与原因 |
| --- | --- | --- | --- |
| 正文文件链接 | ZCode 覆盖 Markdown a，解析路径/行列并接文件查看器 | Windows 转义、URL 清洗顺序、相对路径来源容易失真 | 标准 Markdown 为主，增加消息来源上下文与统一文件打开器；借解析边界，不复制大组件 |
| 行内代码提及 | Harness 用真实 produced/presented 路径及唯一 basename 匹配 | 无已知文件或同名歧义时不能确定目标 | 作为补充；只把已知且唯一的行内引用变成链接，不对所有正文做文件名正则替换 |
| 产物选择 | Harness present、im-2.0 report_outputs 都明确表达交付意图 | 依赖模型申报；不同工具的校验强度不同 | Host 工具 report_outputs + 双槽；不用正文出现次数或扩展名替代交付意图 |
| 成果/过程 | im-2.0 deliverables/byproducts，收尾统一发布 | 强制按 .tmp 路由可能与用户明确交付意图冲突 | 采用语义分类；目录只作候选提示，明确申报的有效文件可以位于临时目录 |
| 产物事实校验 | Harness 解析实际路径、普通文件且存在才登记 | 新增工具往返；源文件以后仍可能被删除 | 先校验再确认；保存交付版本，避免确认时不存在或历史卡依赖唯一源文件 |
| 漏申报 | im-2.0 催报 + 正文/mtime 推断 | basename/时间接近不能证明成果归属 | 已有下一次模型调用时提醒一次；收尾只从唯一、真实候选补漏并标“推断”，不强开额外循环 |
| 工具级 diff | pi edit.details；Codex 从已提交 patch delta 累积净文本差异 | write、shell/MCP 副作用不自动覆盖；文本 diff 不是完整文件目录 | 保留工具过程卡；回合清单另有独立事实源 |
| 本轮文件范围 | Harness Git 首尾树 + 文件 intent 内容捕获 | 无仓库/无 Git 的 shell 覆盖不足；部分对象只留到 Session 释放 | 保留“首尾快照 + 工具目标补漏”方法，使用 Host 持久原始字节快照 |
| Git checkpoint | ZCode/Cline/OpenCode 有私有 index、隐藏 ref 或独立 Git 仓库 | Git 依赖、忽略规则、过滤器/换行转换、对象保留与恢复配置 | 本批不把 Git 对象库作为存储真源；现有 Node 即可运行，避免并行维护两套快照语义 |
| 历史审查/撤销 | ZCode 保存 checkpoint、回退前对比 after hash | 直接写回会覆盖后续用户/其他会话修改 | 冻结 before/after；安全撤销必须校验当前版本；不使用 git reset/clean |

外部公开资料也确认了文件打开、pending edits、回合恢复与版本控制 diff 是不同层：
[VS Code 审查与回退](https://code.visualstudio.com/docs/copilot/chat/review-code-edits)、
[Claude Code checkpoint](https://code.claude.com/docs/en/checkpointing)。
组件核对：[Streamdown 自定义组件](https://streamdown.ai/docs/components)、
[安全管线](https://streamdown.ai/docs/security)、
[AI Elements File Tree](https://ui.shadcn.com/docs/ai-elements/base/file-tree)、
[CodeMirror merge](https://codemirror.net/docs/ref/#merge)。闭源产品未公开的内部机制不作依据。

### 存储路线的明确裁决

推荐 **Host 原始字节内容存储 + 工作区首尾 manifest + 文件工具前后捕获**。
Node crypto/fs、现有 diff 包即可完成；不是重写 Git、Agent 工具或模型循环。

理由：① 非 Git 目录及没有 git 的安装仍可记录 shell 结果；② 快照保留 BOM/CRLF/二进制原字节；
③ 同一内容按 SHA-256 去重，产物、历史 diff 与安全恢复共用；④ 持久化不依赖原仓 GC 或用户分支。
代价是扫描/哈希成本及存储管理，必须按 §7 的预算、部分覆盖和真实性规则实现。
本次临时实验确认 Git text 属性会归一化 CRLF；1,000/10,000 个小文件的单次读取+SHA-256 约为
150–345 ms / 757–1,314 ms，但**不包含遍历、复制、diff 和 UI**，只说明路线可继续验证，不是完整性能验收。
Git 也能通过绕过过滤器等方式保留原字节，不能把该实验外推成 Git 没有此能力；本批选择是避免额外维护
Git 配置、对象保留及无 Git 后备路径，优先复用 Host 现有存储技术。若完整性能验收不达标，再以数据评估索引优化，不能偷换统计语义。

## 4. 文件身份与回合身份

- `fileId` 是 Session 内的不可猜测引用；记录展示路径、真实路径、类型与来源 Host，前端不凭任意路径读内容对象。
  fileId 不是权限本身，入口仍核对 Session 关联与授权范围；不能仅凭知道一个对象 hash 就读取内容。
- Windows 按真实文件系统规则比较，Linux 不整体转小写；归一斜杠不能代替平台路径语义。
- 目录链接允许打开文件管理器；文件链接可带行、列或行范围。符号链接解析后重新核对读取边界，显示保留用户路径。
  别名后来指向其他真实目标时不静默替换 fileId 的身份，显示目标已变并重新解析。
- 主根相对路径只相对本次消息的 cwd；其他根建议输出绝对路径。同名 basename 不跨根盲选。
- 每个真实用户输入分配 `turnId`；每次 submit/手动继续有独立 `executionId`。自动续写、压缩重试不新建用户回合。
- 扩展现有 onUserEntry 回调，对**纯文本和附件消息都**记录实际 user entry id 与 turnId 的 custom 元数据；
  内部续写消息不认作新用户输入。沿用附件“拿到实际 entry id 才绑定”的方式，不按时间或数组位置猜归属。
- `ChatMessage` 增 optional turnId；现有 u-N/a-N 显示 id 与 DOM key 不因本功能整体替换。
  readPiTranscript 读取新 custom 元数据；业务文件记录住 Host，不将大块快照塞进 pi 上下文。
- 手动继续沿用同一用户回合，保存执行区间。保留可继续的 length 回合基线，直到完成或下一个真实用户输入；
  若继续前磁盘与上次 after 不同，标记期间外部变化，净统计口径明确为此回合基线到最新收尾，不冒充独占作者归因。

## 5. ① 聊天中的文件链接

### 目标解析与渲染

首发支持 `[名称](相对/绝对路径)`、带空格尖括号目标、Windows 盘符/UNC、POSIX、`~/`、
`:行`、`:行:列`、`#L行`、`#L行-L行`；位置无效时打开文件并显示未定位，不把行号当文件名。
百分号只解码一次；字面 `#/?` 和数字冒号按明确编码区分。

在 Markdown AST 阶段识别原始目标，将本地目标编码成仅渲染器消费的安全片段链接；
链接组件再解成 FileTarget 并调用 Host。该内部编码不进入模型正文或磁盘转录。
保留 Streamdown 默认 raw/sanitize/harden；不为盘符或 file URL 关闭整个 URL 安全层。
Windows 反斜杠丢失按 ZCode 的原文范围恢复方法处理；在改写前校验相对路径，不允许 URL 归一先吞掉越界段。
`../` 指向 cwd 外部时由 Host 按实际绝对目标核对读取权限，不误配成 cwd 子文件，也不因相对拼接自动取得额外权限。

普通 HTTP(S) 仍走外链打开；片段链接、文件路径与 Web URL 分开路由。点击不得导航走当前 Electron 主窗口。
流式未闭合目标不触发打开；文件 stat 按稳定候选/点击/悬停做批量或缓存查询，不逐 token 发 RPC。

### 行内提及

对反引号 token，只匹配本轮已读/写文件、已登记产物及已记录变化中的完整路径/唯一别名。
未知、同名歧义、命令、代码围栏保持原样；不嵌套 a/button，不把代码里的表达式误认成文件。
提示词要求引用现有文件时优先标准 Markdown 链接，不新增另一套专用 citation 语法。
工具卡中已知文件路径也复用 FileLink；通过工具 callId 关联结构化引用，不反解析已截断的一行摘要。

### 共用打开器与预览

默认在聊天右侧打开只读面板；宽度可拖动，窄窗口使用 Dialog。三个位置打开同一 fileId 时复用当前面板。
支持行列定位、复制路径、资源管理器定位、系统默认程序打开、另存，以及已配置编辑器的固定参数/URI 打开。
编辑器适配必须传参数数组或固定协议编码，不把文件路径拼进可执行 shell 命令。

| 文件类型 | 内置预览 | 其他动作 |
| --- | --- | --- |
| 文本/源码 | CodeMirror 6 只读、行号、搜索和定位；语言高亮按需加载 | 系统/编辑器打开、复制/定位/另存 |
| Markdown | 渲染/源码切换，静态解析无流式动效 | 相同动作；相对引用继续绑定源文件目录 |
| 图片 | 缩放与原图；只读取已授权 fileId | 相同动作 |
| PDF | 复用 PDF.js，按页懒渲染，页码与缩放 | 系统打开/另存；解析失败显示真实原因 |
| DOCX/XLSX/PPTX | 复用受限 worker 的结构文字/工作表/页序预览，明确标“内容预览” | 系统 Office/WPS 打开；不伪装成版式预览 |
| 音视频 | 常见浏览器可解码格式用原生控件，失败仍可外部打开 | 不承诺 Electron 31 没有的编解码器 |
| 其他/过大文件 | 类型、大小与可用动作 | 通用文件卡仍可交付，不按预览扩展名禁止出卡 |

HTML/脚本默认源码预览，不作为应用权限页面执行；Markdown 预览不自动加载任意外部资源。
产物副本中的相对依赖按受限来源解析，缺少依赖时说明，不能把一份 HTML 文件宣称为完整网站部署。

## 6. ② 产物文件卡片

### 申报工具与校验

新增 Host customTool `report_outputs({deliverables:[{path,note?}], byproducts?:[...]})`：
deliverables 是要明显交给用户的文件；byproducts 可选，只登记值得说明的过程文件，不要求枚举每个临时文件。
修改普通源码默认只进改动列表；用户要求交付一个源码/脚本时可以出卡。文件类型不限于 Office。

- 每次是完整替换；允许显式空数组清空本轮卡片，修复 im-2.0 无法撤回全部申报的边界。
- 最多 50 项、说明最多 200 字；批量归一并逐项检查路径、权限和实际普通文件，失败项反馈模型。
  校验失败不发布这次声明，也不抹掉前一份有效清单；明确的空数组不走失败分支。
- 可以交付既有文件或位于工作区之外的实际可读文件；“交付”不等于“本轮新增”。
  不因为 .tmp 目录强制推翻明确的 deliverables 角色，不扩张项目绑定或写权限。
- 接受指向可访问普通文件的符号链接，保存实际目标与显示别名；后续读取与桌面动作复查实际目标。
- 工具类别按只读申报处理，不二次触发写工具审批；源文件写入仍走原有审批链。
- 同步维护 tool-meta 的名称/类别/摘要与工具展示映射，避免新工具落入“未知工具”分支。
- 回执返回确认清单及实际路径，模型/其他客户端可理解；前端不解析回执自然语言获得卡片。

### 收尾、版本与漏报

Host 保存最后一次有效声明。登记时捕获一个可用版本，收尾复查并保存稳定最终版本；
若源文件在收尾前被删除，保留最近已确认副本并明确源文件已不存在，不生成死卡。
内容超过副本预算时仍可交付已确认的源文件卡，标记未保存副本，历史不冒充可恢复。

正常、停止、失败均保留已经确认且实际可用的产物；停止/失败展示所属回合状态，不照搬 im-2.0 的整轮丢弃策略。
ask_user 等待期间可通过正文链接查看当前文件；产物清单在真正 run 收尾后定稿，挂起不伪装成回合完成。

下一次已有模型调用前，如正文已声称产出而尚未申报，注入一次提醒，不强开额外 LLM 轮、不反复催报。
收尾补漏只从明确正文引用和真实文件候选匹配，basename 必须唯一且重新校验；保留 inferred=true，卡片标“推断”。
仅凭 mtime 相近或某扩展名出现不能提升为模型确认产物；模糊候选不强造卡片。

正式卡片固定在终答下方；没有终答正文的停止/失败回合也有固定尾部位置。卡片显示图标、文件名、类型、说明与动作；
有副本时默认预览/另存交付版本，“打开原文件”是明确动作；源文件后来变化不改写已交付版本。
byproducts 的标签用于下面列表的分组/说明，不另造第二类主位产物卡。
只有实际发生变化的 byproduct 才进入改动统计；单纯被申报、但没有变化的过程引用不能伪装成变更。

## 7. ③ 本轮改动列表

### 捕获与覆盖

首次**获准且可能产生文件副作用的工具**执行前准备基线，所有并行工具等待同一准备 Promise；
write/edit、PowerShell/bash 和 MCP 执行类都触发，不静态猜 shell 命令“只读”。无文件活动的纯回答不扫描工作区。
pi 官方 tool_call/tool_result 可等待，包含嵌套调用；只扩展 hook-seat，不替换内置工具。
直接审批已通过后才捕获；嵌套审批与捕获有明确顺序，拒绝不伪造修改。

- 扫描冻结的显式工作区多根；重叠根规范化后去重，嵌套仓库作为边界登记，需要跟踪时显式绑定为根。
- 默认排除 `.git/.hg/.svn/node_modules/.venv/venv/__pycache__/.cache` 及 Cogent 自己的存储目录。
  **不把 .gitignore 等同于无价值文件**，不默认排除 tmp、out、dist；否则会漏掉用户截图里的真实产物。
  排除策略写进 record，可在预览详情看覆盖范围；明确文件工具目标仍可补捕获被排除目录中的业务文件。
- 原始文件流式读入 SHA-256 对象存储；manifest 记录路径、存在性、hash、大小、类型/模式、可用内容引用。
  读前后 stat 变化则重试一次，仍不稳定标未知，不能宣称原子工作区快照。
  不自动跟随目录符号链接扩大全量扫描；链接本体记录目标变化，明确文件目标按授权后的真实路径补捕获。
- 文件工具另捕获首次 before，并在结果回调/最终收尾读实际 after；失败工具也检查已发生写入，不能只信 isError。
  全范围快照已有基线时优先使用它，避免漏掉首次 edit 之前的 shell 修改。
- 没绑定项目时不扫描整个 Home：精确捕获已知文件工具目标；未限定范围的 shell/MCP 副作用标“仅已知文件覆盖”。
  这是无法预知任意全盘写路径与扫描成本的真实边界；绑定项目后获得完整声明范围覆盖。
- 工作区外只通过未声明 shell/MCP 修改的路径无法保证 before；出现候选时保留“未记录修改前版本”，不伪造新增。

### 净变化与统计

收尾冻结 after 后比较首尾 hash/存在性，再用现有 diff 包在 worker 中计算文本 hunks 与行数：

- A→B→C→A 不进入净列表；新建/删除与修改分别处理；同内容且唯一配对的改名保留 oldPath/newPath。
- 只有完整枚举证明的缺席或明确 ENOENT 才是 absent；超时、权限错误、跳过未遍历区域是 unknown，不能据此伪造新增/删除。
- 改名且编辑无法唯一证明时按删除/新增展示，不凭时间接近猜文件身份。
- 纯重命名、文件模式、编码/换行符变化可无文本行数，但仍列文件；BOM/CRLF 原字节可恢复。
- UTF-8 与有 BOM 的 UTF-16 文本按明确编码解析；二进制或错误编码不强行当文本。
- 二进制/过大文件显示类型与大小变化，行数用“—”；diff 超时为未统计，不抄 ZCode 的超时回退零行或将整文件替换冒充精确计数。
- 合计只累加已完成文本统计，注明另有多少项未统计；详情区分完整/部分/仅已知目标覆盖。
- 相同文件在产物区和改动区共享 fileId，但不跨区求差；列表不能遗漏被交付的改动。

多会话/用户/外部进程可同时写工作区，首尾快照观测的是期间净变化，不能证明唯一作者。
保存工具观察来源、并发区间与外部变动迹象；界面称“本轮工作区更改”，有歧义时标来源说明，
不因恰好处于某工具执行时间内就归因给该工具。不会为精确归因阻止其他会话并行工作。

### 审查与安全恢复

列表每行可打开当前文件或审查冻结的 before/after；默认统一 diff，可切双栏。
复用 CodeMirror 6，增加官方 `@codemirror/merge`，设只读并关闭默认 accept/reject 编辑控件；
列表计数以 Host 统计为准，查看器不反写业务数据。

截图中的撤销入口建议一并纳入：单文件/本轮撤销、同等校验的重做；不回退聊天消息。
执行前必须确认当前内容与预期 after/before 匹配。冲突返回具体文件，不覆盖后续修改、不提供默认强制覆盖。
同时核对类型与需恢复的文件模式；恢复只触达已记录路径，专属 IPC 校验窗口来源，不开放给 guest SDK 或普通 Agent 工具。
整轮先预检全部文件；应用中逐项写恢复日志，I/O 中途失败明确报告已恢复/未恢复，不承诺跨文件系统事务原子性。
符号链接/硬链接影响范围不清、缺少副本或版本冲突时禁用该项恢复并说明真实原因；卡片与审查照常可用。

### 初始预算与性能验收

初始建议值：2 路文件 I/O；每个根最多 20,000 个文件；单个内容快照 20 MiB；
产物副本 100 MiB；单个文件哈希上限 100 MiB；单回合新增对象 256 MiB；全库 2 GiB；
基线/收尾扫描各 10 秒；单文件 diff 100 ms。值集中配置，实施时按完整探针结果调优。
这些是资源护栏，不是保证在该容量下已经通过验收。

超限仍保留路径和已知元数据；未知内容/未遍历范围不能报 complete 或零改动。
超过哈希上限的已有文件只能形成待核实项，不能仅凭 mtime 变化计为已确认净修改；不影响可验证的新建/缺席事实。
错误只影响文件记录覆盖，不把原本成功的 Agent 任务改成失败，也不能永久占住运行位。
预算内的大批计数分批发布并固定 record revision；摘要可先显示“统计中”，异步完成后更新，不让 UI 线程跑大 diff。
实现必须测完整遍历/复制/哈希/统计与 UI；目标 1,000 小文件热基线约 1 秒内、10,000 约 5 秒内，超标先实测定位与优化。
不得用 mtime 缓存命中冒充内容 hash 相等。

## 8. 存储、契约与生命周期

Host 单写 `<COGENT_HOME>/files/v1/`：`objects/<sha256>` 原始字节，
`sessions/<sessionId>/turns/<turnId>.json` 已发布记录，`staging/` 基线与恢复日志。
附件与本域不共用引用计数；可以复用底层流式/原子写方法，不把产物伪装成输入附件。

记录最少包含：version/sessionId/turnId/userEntryId/executionIds、冻结 roots、revision/outcome、
已验证产物及版本、变化清单 before/after、统计状态、覆盖范围与错误、撤销状态。
正常收尾只长期保留改动文件两侧与交付副本；可继续的 length 回合保留原基线租约。
归档保留，彻底删除会话释放；只回收本域确定无引用对象，活动扫描/预览/可继续回合持租约。
引用版本不因容量不足被悄悄淘汰；空间不足转明确的有限覆盖，已有历史仍可读。

| 合同（拟增） | 用途与边界 |
| --- | --- |
| `files.resolve`、`files.readCurrent` | 原始链接目标转 fileId、读取当前预览；桌面专用，沿用附件对 HTTP/WS 的隔离方式 |
| `files.listTurns/getTurn` | 读取会话已有文件摘要，重启/断线补偿，不装配 pi |
| `files.diff` / `files.readVersion` | 只按该 Session/turn/fileId 的已记录内容查询；不允许任意对象 hash 或磁盘路径读取 |
| `files.restore` | 桌面专用，用户明确操作，按记录与当前版本校验恢复 |
| `files.referencesUpdated` | 本轮已知文件身份增量，供行内提及匹配 |
| ToolCallRecord 与工具事件 optional fileRefs | 工具卡路径与文件目标精确配对，旧工具/旧历史缺省保持原展示 |
| `files.turnUpdated` | summary 全量替换，按 turnId + 单调 revision 幂等消费 |
| `session.messages` optional `fileTurns` | 历史水合种子；旧引擎/旧会话缺省无记录 |
| ChatMessage optional turnId、run 事件 optional turnId/executionId | 精确锚点，不改既有事件名/字段语义 |
| 壳 `files:action` 白名单 | preview/open/reveal/save/editor；main 执行桌面操作，renderer 不传任意 shell 命令 |

新方法逐一进入 main 的 engine 方法白名单和 HTTP 最低 scope 表；专属桌面动作在 preload 显式暴露，
不放开通用任意 channel。既有协议只加 optional 字段和新方法/事件；旧数据可读，旧 Host 不支持时显示功能不可用，不伪造空结果。

路径解析/当前文件字节与桌面动作暂不开放 HTTP/WS：现有 token 尚无 Session 文件范围约束，
否则新增接口会扩大为任意 Host 文件读取/打开能力。已记录摘要/diff 可以按既有 readonly scope 提供；
未来补齐文件范围授权后再开放当前文件读取，不因此把 Electron 依赖放进 Host。

```text
owner: SessionManager = 运行身份；RunFiles = 文件事实；store = 呈现；main = OS 动作
submit → 建 turn/execution 身份 → 实际 user entry 绑定
获准的首次副作用工具 → await 基线 → 工具/申报 → 过程记录
最终 agent_settled（自动续写已结束）→ 等文件操作收尾 → 冻结 after/保存记录
  → run.completed/failed + 文件摘要 → store 同一回合底部显示；计数异步补齐 revision
stop/error → 同样结算已发生变化；原 outcome 不被文件整理错误替换
重启 → 只读摘要/版本 → 恢复相同卡片与历史 diff
```

现有 translateEvent 是同步函数，不能直接塞入未等待的快照后立即删除 streaming。
抽出单次异步 finalizeRun：在完成冻结或明确记录捕获失败后才释放本次预约；所有成功、失败、早停出口共用，
核对 StreamingState owner 防止迟到结果改新 run。自动续写的终态抑制条件保持；继续链不能提前封存。
崩溃遗留 open manifest 标“整理中断”；只能恢复已落盘版本，不能把重启时磁盘冒充崩溃瞬间 after。
先持久化再发 ready 事件；持久化失败发有限状态并诊断，不声称重启可恢复。

## 9. 前端状态与呈现约束

- chat 桶增加按 turnId 的摘要与 revision；在 groupTurns 结果上关联，不向普通消息流硬塞工具假消息。
  历史水合与实时事件按 revision 合并，迟到的旧查询不能覆盖新摘要。
- 终答 → 产物卡片 → 全部改动列表 → 用量/动作；三者都在“已工作”过程折叠区之外。
- 无产物不挂空卡，无变化且完整覆盖不挂空列表；覆盖失败用简短可展开状态表达，不能伪装成零变化。
- 运行中不重复重建正式卡片；续写保留旧已发布版本，收尾以 revision 替换，不因 store 切会话串数据。
- 链接、卡片和列表复用图标与操作菜单；布局用现有 shadcn Item/Button/DropdownMenu/Collapsible/Resizable/Dialog。
  按 AI Elements File Tree/Tool pattern 组合，调用点不新增皮肤补丁。
- 不改变原消息 DOM key、流式渐显和吸底意图；面板开合/详情计数更新不得把 reading 用户抢回底部。
- 预览请求带代次与 session/file/version，换文件/会话、卸载后丢弃旧结果并取消旧解析；缓存受内容版本和文件服务身份约束。
- 键盘可聚焦和打开，链接 title 可见完整路径；文件名截断不影响复制；多根同名文件显示必要父目录。

## 10. 首发边界：必须有真实理由

| 边界 | 真实原因与处理 |
| --- | --- |
| Office 原生版式编辑/渲染 | 需新排版引擎、字体与跨平台验收；首发提供已有结构内容预览和系统打开，不假装版式一致 |
| 无绑定根的任意 shell/MCP 全盘副作用 | 不预知目标，扫描整个 Home/全盘成本和读取面过大；首发精确文件工具覆盖并明确范围 |
| 进程/用户并行写入的唯一作者归因 | 普通工具钩子与目录快照没有 OS 级写者证据；记录观察来源，不按时间猜作者 |
| 超大内容、扫描不稳定或预算耗尽 | 明确内存/磁盘/延迟上限；仍提供文件卡及当前打开，统计/历史能力按实际可用数据显示 |
| 冲突时自动合并或强制恢复 | 可能覆盖用户后改；首发检测冲突并保留版本供审查，不默认强写 |
| 旧会话回填历史 diff | 修改前字节没有记录，无法可靠重建；旧正文链接可用，新记录从本批开始 |
| 任意网络来源文件上传/云端副本 | 当前无上传账号/服务端；本批交付本机可用文件，不伪造云端能力 |

通用文件类型、非 Git 目录、Git 缺失、目录链接、复制/定位/另存、停止/失败后已有产物与真实变化，均在首发范围内。

## 12. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| Windows 盘符/UNC、Linux、空格中文/百分号、行列范围 | 打开正确文件与位置；不导航走应用；无盘符/转义丢失 |
| A/B 项目同名文件，旧消息后切项目/更新根 | 按原消息来源解析；歧义不自动选一个 |
| 普通 URL/片段/代码围栏/反引号命令 | 各走正确处理，不误变成本地文件按钮 |
| 流式链接未闭合、结构重整、终态 | 不逐 token stat，不破坏渐显/DOM/选区 |
| 用户要求交付既有 PDF、ZIP、脚本或临时目录文件 | 有效申报可出同一种产物卡片，不受预览扩展名白名单阻挡 |
| 申报不存在文件/目录、后续撤回/重报 | 错误反馈明确；无假成功卡；有效旧清单不会被失败调用抹掉 |
| 文件后来被改/删除、应用重启 | 有副本的产物/历史 diff 保持原版本；原文件状态真实 |
| 明确申报/唯一推断/同名歧义 | 确认与推断可区分，歧义不造卡 |
| 编辑同一文件多次、改回原样、新增删除、纯改名 | 首尾净差异及文件数正确；零净变化不累计过程次数 |
| 用户已有 dirty 文件，再新增一行 | 本轮只统计新增变化，不使用 HEAD 冒充基线 |
| Shell/MCP 在已绑定根写文件；目录无 Git/机器无 Git | 声明范围内可发现；工具外变化与来源边界真实 |
| .gitignore 中 tmp 产物、多个根/嵌套根 | 不因忽略规则漏正常产物；同一路径不重复统计 |
| 工具写入后失败/停止；并行同文件与另一个会话编辑 | 已发生变化保留；无错误作者归因、无跨桶污染 |
| 二进制、UTF-16/BOM、CRLF、仅 EOF 换行变化 | 原始版本准确；不编造行数或丢文件条目 |
| 大 diff 超时/扫描预算/磁盘满/快照读时变化 | 状态为未统计或部分覆盖，业务能收尾，不写零冒充成功 |
| 自动续写/压缩/手动继续 | 同一用户回合无重复卡；继续区间可追踪，原基线与外部变化说明正确 |
| 无正文停止、准备期早停、Host 崩溃/恢复 | 不永久 running；已有文件记录有正确归属和完整性状态 |
| 删除会话、预览中切换、迟到 RPC/terminal | 旧结果不复活已删桶/内容，不误释放另一会话版本 |
| 产物同时被改动 | 上方产物卡存在，下方全部改动仍包含它 |
| 当前文件与 after 一致/被用户后改 | 前者可安全恢复；后者报冲突，磁盘内容不被覆盖 |
| 窄窗口、缩放/暗色、键盘、阅读中打开面板 | 无裁切/焦点陷阱，阅读位置不被夺走 |

本轮仅调研和计划：通过文档差异/链接检查不等于上述实现验收。已有 16 项 im-2.0 副本测试与机制探针只证明其限定场景。
