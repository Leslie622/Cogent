## 1. 目标与范围

技能座 = Host 侧管理技能目录（发现 / 列举 / 编辑 / 启停），pi
`skillsOverride` 官方钩子 + `before_agent_start` 段钩子注入（D7 不造
轮子）—— SKILL.md 指令包按「目录清单进系统提示、正文模型自取」的
渐进方式进入 Agent 循环，**回合边界热刷新**。对照 MCP 座（管连接），
技能座管的是**纯文本资源**：无进程、无网络、无新增工具。

首批交付：

1. 目录模型与存储（user 级 + project 级技能目录 + 两级启停状态）；
2. 协议方法（`skills.list` / `skills.save` / `skills.delete` /
   `skills.setEnabled`）+ 装配（快照注入 + 回合边界段刷新）；
3. 清单预算（单条描述截断 + 总预算 + 超限降级）；
4. `/skill:name` 手动展开（Cogent 活展开）；
5. 设置页技能管理卡片 + 手动验收。

**零新增项（全吃 pi 现成）**：

- 渐进加载：pi `formatSkillsForPrompt` 只把 name/description/location
  写进系统提示 `<available_skills>`（skills.ts:358-388），模型用 read
  工具自取正文 —— pi read 无 cwd 圈禁（tools/read.ts:71 仅查可读性），
  工作区外的 `~/.cogent/skills/...` 可读；
- 审批链：技能不是工具，模型按技能行事仍走既有工具审批链（read 档 /
  exec 档照旧），零新增；
- `disable-model-invocation` frontmatter：pi 语义原生（不进清单，仅手动
  `/skill:` 可调，skills.ts:352-359），Cogent formatter 与展开器同规则。

## 3. 设计

### 3.1 数据与文件

```
~/.cogent/skills/<skill-name>/SKILL.md    # user 级技能包（UI 建或用户手放）
<工作区主根>/.cogent/skills/<skill-name>/SKILL.md   # project 级（手放为主）
~/.cogent/skills.json                     # user 级启停 { "disabled": ["name", ...] }
<工作区主根>/.cogent/skills.json          # project 级启停 { "overrides": { "name": false, ... } }
```

- SKILL.md 形状 = pi/Agent Skills 生态标准（YAML frontmatter
  `name`/`description`，正文 Markdown，附带 references/ 等文件由模型按需
  read）；
- 两个目录都**允许定义**（被动文本，无 MCP 式进程信任门）；同名 project
  胜（zcode/dsh 惯例），冲突进诊断；
- 启停求值（每回合随发现一起算）：project overrides 命中即定（false =
  在本项目禁用 user 技能；true = 重新启用 user 已禁），未命中回落 user
  disabled 名单 —— 同名优先级与技能定义一致（近者胜）；
- 两目录/两状态文件不存在 = 空集/无覆盖，不报错。

### 3.2 Host 侧模块

- `src/host/runtime/skill-store.ts`：store（发现 + 合并 + 启停 + 读写）；
  - 发现：pi `loadSkillsFromDir` 每目录一次（校验/ignore/裸 md 全白拿），
    user 先、project 后，同名后者胜 + collision 诊断（镜像 zcode
    nearest-wins；pi 的先得语义不采）；
  - `snapshot(cwd)`：合并结果 − 启停求值 → `{skills, diagnostics}`
    （每回合调用 = 热刷新的数据面；目录 I/O 仅 SKILL.md 层，代价可忽略）；
  - `list(cwd)`：摘要（name/description/scope/enabled/effective/path/
    disable-model-invocation）+ 诊断（readonly 协议用，多带原文信息）；
  - `save({scope, name, description, body})`：写入前镜像 pi 校验
    （name/description 规则），目录名 = name，frontmatter 由 Host 生成
    （防手写错），原子写 SKILL.md；落点守卫：resolve + isPathWithin
    受管目录（防 `../` 逃逸）；
  - `delete({scope, name})`：删技能目录（rmSync recursive + isPathWithin
    守卫），两级状态文件顺带清理；
  - `setEnabled({scope, name, disabled})`：写对应级状态文件（原子写；
    scope=project 写 overrides）。
- `src/host/runtime/skill-prompt.ts`：清单 formatter —— 镜像 pi
  `<available_skills>` XML 形状（skills.ts:365-387），加 zcode 预算模型：
  单条 description >250 chars 截断（带省略号）、全部条目总长 >20k chars
  降级 names-only、仍超再截总长，降级进 diagnostics；
- 协议方法（注册表在 host-main，入口守卫同 MCP 模式）：
  - `skills.list` → 摘要 + 诊断（readonly 档）；
  - `skills.save` / `skills.delete` / `skills.setEnabled` → write 档
    （写用户磁盘文件，与 `mcp.sync` 同级）；
- 装配（`kernel/pi-session-factory.ts`，`PiSessionOptions` 增
  `skills?: {section: () => string | null}`）：
  - `DefaultResourceLoader` 增 `noSkills: true` +
    `skillsOverride: () => ({skills: [], diagnostics: []})` —— pi 静态
    注入面全关（`.pi` 域不扫、扩展动态路径进不来）；
  - 既有 `before_agent_start` 钩子（权限段同款）追加：
    `event.systemPromptOptions.sections = {...sections, skills: opts.skills.section() ?? null}`
    —— 每回合活算，null = 清除该段（空墓碑语义，dsh hot-refresh.md:22
    同效）；pi 的 sections diff 保证树内只留净变更史（Cogent 权限段已
    验证此机制）；
  - SessionManager.buildPiSession 传
    `skills: {section: () => skillPrompt(skillStore.snapshot(主根))}`，
    装配期 stderr 留一次诊断（MCP 座同款；此后诊断随 `skills.list` 回）。
- `/skill:` 活展开（`runtime/session.ts` submit 路径，现
  `pi.prompt(text)` 前）：文本以 `/skill:` 开头 → 活 store 查 name →
  命中则改写为 `<skill name location>\nReferences are relative to
  <baseDir>.\n\n<body>\n</skill>` + 原 args（形状镜像 pi
  agent-session.ts:2325），未命中原样透传（pi 侧也查不到，行为一致）。

### 3.3 UI（设置页）

设置页新增「技能」分区（McpSection 同骨架同视觉）：技能列表
（name + user/project 徽标 + description + 启停开关 + 编辑/删除；user
技能可在本项目视图下显示「项目覆盖中」态）+ 新增/编辑弹窗
（name + description + 正文 textarea）+ 配置诊断组 + 「下一回合生效」
提示（热刷新下无需新会话）。数据经 `engine:request` 通用代理（白名单
`main/ipc/engine.ts` 加四个方法；技能真源在引擎侧文件，无壳侧双写，
与 MCP 同理）。

## 4. 边界（明确不做与归属）

| 项 | 判定 | 理由 |
| --- | --- | --- |
| 运行时修饰字段（`allowed-tools`/`model`/`effort`/`when_to_use`/`context: fork`） | **不做** | pi 无消费点 —— 做了等于在 pi 之上自建第二套技能运行时（按回合改工具白名单/切模型/fork 子会话），zcode 自己也放 P1/P2（skill.md:134-142,271-275）。等真实需求出现再立项，现在做了也没字段可用 |
| 技能市场 / 远程分发 / 插件技能根 / bundled pack | **不做** | 下载即提示词注入面，需要签名/校验/审计/缓存（zcode 明确排除在第一阶段，skill.md:34）；bundled 只是内容不是机制，往目录放文件即可，无需立项 |
| dsh 式 Chokidar 推送监视 | **不采** | 拉模式（每回合重新发现）已覆盖全部场景且无中间态；监视器只在「外部进程改文件要秒级推送」时有增益，桌面单用户场景不成立 |

（原「正文 100KB 硬上限」从边界表移除：pi read 截断护栏已覆盖，非
新增边界。）

## 5. 验收

- 单测（skill-store.test.ts）：发现（两目录 + 裸 md + 坏 frontmatter 诊断）、
  同名 project 胜 + 冲突诊断、启停两级求值（user 禁 / project 覆盖禁 /
  project 重启用）、save/delete 路径守卫（`../` 逃逸拒绝）、save 生成
  frontmatter 往返、状态文件损坏诊断；
- 单测（skill-prompt.test.ts）：形状镜像 pi XML、250 截断、20k 降级
  names-only、空集返回 null；
- 集成（tests/integration/skills.test.ts，mock LLM）：
  1. `skills.save` 建两枚（user + project 同名）→ `skills.list` 断言
    project 胜 + 诊断带冲突；
  2. 首轮请求断言系统提示含 `<available_skills>` 与胜者条目；
  3. mock 让模型调 read 读 SKILL.md → 工具结果含正文（渐进加载闭环）；
  4. **同会话内** `skills.setEnabled` 置 disabled → 下一轮请求系统提示
    无该条目（热刷新断言：sections diff 补丁生效）；
  5. submit `/skill:<name> 列出步骤` → mock 收到的用户消息含
    `<skill name=` 展开块（活展开闭环）；
- 手动（4b-2）：设置页建一枚实用技能（如「提交前检查清单」）→ 会话
  进行中即可被模型按清单行事（下一回合生效）；输入框发
  `/skill:<name> 做某事` → 消息展开为技能块；禁用后下一回合清单消失。
