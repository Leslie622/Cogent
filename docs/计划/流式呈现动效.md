# 流式呈现动效：工作行扫光改造 + 流式正文逐词淡入

两项动效均以 zcode 桌面端为参照（用户拿其截图定调），出处：
扫光 `reference/zcode/packages/ui/src/styles.css:957-1004`（`.animated-gradient-text`）；
逐词淡入 `reference/zcode/packages/ui/src/components/ai-elements/message.tsx:845-1420` +
`reference/zcode/docs/streaming-markdown-reveal.md`（设计文档，含三代被撤实现的历史教训）。

## 目标

1. **工作行扫光改造**：「工作中」标题（`TraceTitle`）现为匀速高光扫（muted 底 +
   foreground 高光带 2.2s 无限循环）。改为 zcode 形态：**文字恒为基色，一条半透明
   淡带周期性扫过**（扫 2s、停 2s 的呼吸节奏），即用户截图中的观感。
2. **流式正文逐词淡入**：流式期间最新输出的尾部若干单元（中日文按字、拉丁文按词）
   处于各自淡入的不同阶段，形成渐隐尾巴（用户截图 "delta" 一词的渐隐）。DOM 文本
   从第一帧起完整，**只有透明度在变** —— zcode 文档的「唯一硬约束」，其三代前身
   都栽在维护第二份随时间变长的 visibleText（高度逐帧增长 → ResizeObserver →
   撞虚拟滚动测高与底部跟随，全部撤回）。

## 对比结论（硬规则 7）

| 维度 | zcode | Cogent 现状 | 取向 |
| --- | --- | --- | --- |
| 扫光形态 | 实色 strong 0/34%，soft(22% 透明) 50%，strong 66/100%；底 300%；扫停 keyframes 4s | muted 底 + foreground 高光带；底 200%；匀速 keyframes 2.2s | **取 zcode 形态与节奏**，色标落 Cogent 令牌（muted-foreground 作 strong） |
| 扫光合成层提示 | will-change + translateZ + backface-visibility | 同款已有 | 保留（两边同款，流式期主线程争用下防跳变） |
| 正文渲染器 | Streamdown 2.5.0 | Streamdown 2.7.1（`rehypePlugins` prop 均在，`streaming` 块级 memo 同构） | 插件方案整体平移 |
| delta 节奏 | 引擎 30ms 合帧后一帧一批 | chat store 每 delta 直接 setState，无合帧 | **不补合帧**：排期算法按 EWMA 自适应任意批大小，批更小排期更平滑 |
| 挂载点 | `MessageResponse` 管多消息，插件按消息 useRef | 流式占位是**单条**消息（id `streaming`），state 生命周期 = Markdown 组件生命周期 | Cogent 更简，收尾 `streaming=false` 切 static 整树重建，span 自动消失 |

## 设计

### 1. 扫光：改 `.shimmer` 本体（globals.css）

不新增类 —— `.shimmer` 是文字扫光的唯一实现位（约定 §6：同类问题修原条目），
所有消费方（`TraceLine data-status=running` 的标题 = 工作中行 + 思考中标题）一并
换成新形态，家族一致。

- 渐变 stops：`var(--color-muted-foreground)` 0%/34% → `color-mix(in srgb,
  var(--color-muted-foreground) 22%, transparent)` 50% → strong 66%/100%；
- `background-size: 300% 100%`（渐变宽 3 倍，留平移空间）；
- `@keyframes shimmer-sweep` 改为 `0%{100% 0} 50%{0% 0} 100%{0% 0}`，4s linear
  infinite —— **扫 2s 停 2s**：停在中间档不是无谓等待，匀速循环观感是"进度条在跑"，
  扫停才是"活着"的呼吸信号（zcode 同款节奏）；
- 基色从 foreground 高光改为 muted-foreground 实色：TraceTitle 所在的 TraceLine
  基色本就是 muted-foreground，扫光停下时文字与静态行同色，淡带扫过时变暗 ——
  语义是"正在工作"而非"高亮"；
- `motion-reduce` 出口（`.shimmer-none`）已有挂点不动。

### 2. 逐词淡入：Streamdown rehype 插件

新文件 `src/renderer/src/components/ui/stream-reveal.ts`（纯逻辑 + 插件工厂）+
`markdown.tsx` 挂载 + globals.css 两段 CSS。

**逻辑层**（全部纯函数，单测主战场）：

- `segmentRevealUnits`：`Intl.Segmenter` word 粒度（模块级缓存，每帧 new 不可接受），
  无 Segmenter 回退正则；含 CJK 的片段再按码点拆单字（ICU 把「拍板」切成一块，
  没有逐字打字感 —— zcode 实测教训）；跳过 `pre`/`svg`/`math` 下的文本（代码块
  高亮异步，逐字与高亮打架），行内 code 整个元素算一个单元（不跳过它，否则
  它一挂载全亮、左边字还在淡入）；
- 进度判定：按 **block** 记 committed（Streamdown streaming 模式每个 block 独立
  跑 rehype，插件只见一个 block，整条消息一个长度会坐标系错位 —— zcode 2026-11
  bugfix）；`revealPredecessorLength` 只认「旧版本」：公共前缀外尾巴 ≤8 字符且
  仅空白标点（短文本对任何前缀都成立，「列表项一」被当「列表项三」旧版的教训）；
- 消息级增量判定：纯追加（`startsWith`）且单帧 ≤600 字符才算 live delta，否则
  整条不动画、**绝不按旧进度裁剪正文**（回填/切会话/中途挂载）；
- `planRevealSchedule` 排期器（zcode 公式原样）：
  `lag = clamp(max(6×e, 1.5×gap), 80, 250)`、`interval = min(40, available/count)`、
  至少铺开 15ms；淡入时长**固定 300ms ease-out 不随速度缩放**（时长一缩每字只剩
  2-3 帧渐变 = 肉眼无动画，zcode 第二个 bugfix 教训）。排期只写
  `transition-delay`，不用 rAF/timer。

**CSS 层**：

```css
:root { --reveal-duration: 300ms; --reveal-ease: ease-out; }
[data-reveal] { transition: opacity var(--reveal-duration) var(--reveal-ease)
                var(--reveal-delay, 0ms); }
@starting-style { [data-reveal="new"] { opacity: 0; } }
[data-reveal-marker]::marker { transition: color … var(--reveal-marker-delay); }
@starting-style { [data-reveal-marker="new"]::marker { color: transparent; } }
```

- **transition + `@starting-style`，不用 keyframes**：单元下一帧就从 `new` 变
  `settled`，keyframes 选择器失配动画即被移除只播一帧；transition 只要属性链
  在就跑完，`@starting-style` 只作用于首次挂载不重播；
- 刻意**不加 will-change**：每单元一个 span，提层反而拖垮长消息；
- 只动 opacity：首帧即占满最终位置，高度恒定，不触发 ResizeObserver（Cogent
  消息流有 content-visibility + 底部跟随，同一堵墙）；列表圆点 `::marker` 不支持
  opacity，过渡 color，延迟用独立变量名（防 li 上的值被内层字继承）；
- `prefers-reduced-motion: reduce` 下 transition 归零 + starting-style 覆盖为实色；
- 每个**非空白单元**都包 span（含 settled）：`hast-util-to-jsx-runtime` 按
  「标签+同级序号」生成 key，只包新单元时新词复用旧词 DOM 节点、动画不播
  （zcode 第三个关键 bugfix）；纯空白保留文本节点。

**挂载与 owner / 事件顺序**（规则 5）：

```
chat store（owner：消息数组）
  │ message.delta → setState（content + delta，每 delta 一次）        [高频]
  ▼
MessageRow（memo：历史项引用稳定 → 仅 id='streaming' 占位重渲染）
  ▼
Markdown（streaming=true；useRef 持 reveal state，插件闭包读写）
  │ render：只读 state（消息级增量判定）
  ▼
Streamdown mode='streaming'（块级 memo → 仅尾部 block 重解析）
  │ transition render：插件跑尾部 block 的 rehype 管线
  │   读 committed（上一帧进度）→ 判新旧 → 新单元包 span[new]+delay → 写 pending
  ▼
Markdown effect（每渲染后）：commit —— pending 转正 committed
  （committed 恒落后一帧：本帧新单元相对上帧 committed 必为新，判定自洽；
   被打断丢弃的 transition 渲染会让少数单元不经淡入直接出现 —— 只影响视觉）
```

插件实例随 Markdown 组件 `useMemo` 创建，**函数名带模块级递增序号**：Streamdown
的 unified processor 缓存按插件函数 `name` 做 key 不看引用，同名实例被共用会读到
第一条消息的已终结 state（zcode 2026-11-06 bugfix：启动后只有第一条消息有动画）。
此缓存规则未写进 streamdown 文档，2.7.1 上是否同构**以渲染测试钉住**（见验收）。

收尾：run 完成占位改名/替换 → `streaming=false` → `mode='static'` 整树重建，
span 全部消失；尾巴（当时的滞后，80~250ms 内）直接出现 —— 消除它需要 UI 等动画
播完再切 static（时间同步状态），不采用。

## 边界

- 引用块左边框、表格边框、分割线、任务列表复选框随元素挂载直接出现，不参与
  排期 —— 逐元素写过渡成本大于收益，zcode 同边界照抄；
- 思考流（Reasoning）不做逐词：它是单行摘要形态，非逐字阅读区，running 态标题
  已由 `.shimmer` 家族承担（本次扫光改造一并换形态）；
- 扫光色标不接聊天正文主题（`.md-body` 消费表）：工作中行在 chrome 区不在
  正文容器内，主题令牌不该越界（主题化计划 D2/D3 的边界本就如此）。

## 验收

1. 单测（`stream-reveal.test.ts`，纯函数）：
   - 切分：拉丁按词 / CJK 按字 / 空白保留 / pre 下跳过 / 行内 code 整体；
   - 进度：严格前缀 / 尾巴 ≤8 纯标点算旧版 / 尾巴含字词不算（「列表项一/三」
     场景）/ 多 block 坐标独立；
   - 排期：滞后自适应（快慢模型两态）/ 250ms 封顶 / 批间接龙 / 同 block 重复
     渲染沿用已排期；
   - 增量判定：纯追加 ≤600 字符 live / 非前缀变化整条不动画且不裁正文。
2. 渲染测试（markdown 层，沿用 tool.render.test 模式）：流式两帧前缀追加 ——
   新单元 span 带 `data-reveal="new"` 与 delay，旧单元 settled 但 span 保留；
   **第二条**流式消息新增单元仍标 new（钉插件名唯一性，防 2.7 缓存规则漂移）。
3. 视觉（用户验收）：快模型流式回复尾部可见渐隐尾巴；工作中行扫光为扫停呼吸
   形态、停下时与静态行同色；reduced-motion 下两者均退化为静态。
4. 交付四关（lint / typecheck / build / npm test）全绿，看完整输出。
