# 配置归属与启动同步修复

待审批实现方案，尚未修改功能代码。问题与既有探针证据见[配置归属审查](配置归属审查.md)。
本批修复全局默认权限、供应商初始化和凭据启动同步；不以开发 CLI 为目标。

## 1. 目标与验收行为

1. Host 自行恢复供应商定义与全局默认权限；不启动 renderer 也得到相同业务配置。
2. session.create 统一执行“显式选择 > 项目默认 > 全局默认 > ask”；客户端只传显式选择。
3. Host 就绪意味着必要配置与凭据交接已完成；启动期间的凭据新增、替换、删除不丢失。
4. 所有保存、迁移及启动失败报告真实结果，旧配置可诊断；现有用户无需重新填写定义。
5. 通过归属规则与行为回归避免复发；模型/思考的上次选择仍是客户端偏好。

## 3. 最终所有权与配置文件

| 内容 | 真源/单写者 | 加载与生效 |
| --- | --- | --- |
| 全局默认权限 | Host；新增 `<root>/session-defaults.json`，v1 | Host 启动恢复；session.create 统一求值 |
| 供应商定义、模型覆盖/禁用 | Host；沿用 `<root>/custom-providers.json`，v1 | Host 启动恢复并注册；保存由同一服务落盘与应用 |
| 模型 API 凭据 | main safeStorage；沿用 credentials.json | 每次启动现读快照；后续变更经有序交接同步到 Host |
| 模型/思考的上次选择、桌面偏好 | 保留现有壳/renderer 所有权 | 客户端选择作为明确提交参数；视觉偏好由客户端消费 |

`session-defaults.json` 形状为 `{ version: 1, defaultPermissionMode: 'ask' | 'auto' }`。
不创建通用配置总线或插件座；两个业务配置服务各有明确职责。

### 旧配置兼容与迁移顺序

- custom-providers.json 文件名、v1 数据形状及内容不变，转交 Host 独占读写。
  main 仅在 spawn 前完成既有 userData → 存储根的文件搬运，之后不再缓存/写定义。
- Host 尚无 session-defaults.json 时，读取旧 settings.json 的 defaultPermissionMode；
  合法值原样迁入，缺字段/缺文件为 ask。新文件存在时它始终优先，旧字段不再参与求值。
- 新文件原子提交后才允许清理旧字段。迁移完成前，main 保存其他壳偏好必须保留旧字段，
  防止启动期的一次浅拷贝写盘抢先把它删除。旧字段保留为只供迁移的兼容数据，不再作为
  UI 的生效来源，也不能经旧 settings:save 路径修改全局默认权限。
- 新配置或待迁移的业务字段/版本/JSON 损坏，保留原文件并给出具体路径与原因；
  不静默重建或覆盖。必要配置未成功恢复则不发布 Host 就绪。
- 迁移提交前失败可再次尝试；提交后崩溃以新文件为准，旧字段是否已经清理不影响结果。

## 4. Host 配置接口与提交语义

| 方法/事件 | 设计 |
| --- | --- |
| 新增 session.defaults.get / set | 返回/保存全局默认权限；set 校验 ask/auto，保存成功后发布 session.defaultsChanged |
| 新增 providers.custom.get | 返回完整定义与覆盖，包括禁用条目；UI 不再从 main 文件缓存读定义 |
| 保留 providers.custom.sync | 继续全量替换，扩为 Host 持久化并应用；保留方法名与 synced 返回字段 |
| 新增 providers.custom.changed | 目录配置变更通知；客户端重读定义和模型列表，不在读取路径回写 |

协议只增方法/事件，已有字段不改名。配置读方法为 readonly；全局默认权限写入为 admin，
stdio 血缘与桌面白名单可调用；providers.custom.sync 保留已有 write 档，不扩大权限。
HTTP/WS 档位表、main 代理白名单与壳侧契约投影同步更新，MCP 工具面维持原约束。

保存过程为“边界校验/构造候选 → 原子写盘 → 无 await 的运行态提交 → 广播/返回”。
供应商构造阶段不得修改活目录；已声明可编辑字段的校验集中复用到磁盘与协议边界。
可预期构造或写盘失败保持旧配置与运行态，不先更新 UI。若外部运行时提交发生不可预期
异常，返回真实应用失败并保留诊断，不伪造成功或声称已经回滚。

保留已有 getCustomProviders/setCustomProviders 壳桥时，将它们改为 HostApi 代理，
不再拥有文件和缓存。renderer engine.load 只读取；移除读取定义后再次保存/同步的副作用。
默认权限行等待 Host 保存结果并显示错误；其他正在修改的显示偏好不在本批重写。

session.create 仅接收客户端显式参数或草稿显式选择；项目匹配和全局默认由 Host 求值。
现有已创建会话不因修改默认而切权限。MCP 出口显式开启计划模式的逻辑维持原语义。

## 5. 凭据交接与请求顺序

```text
owner: main安全存储 = 真源；HostManager = 启动/变更顺序；Host = 生效内存与SDK

Host启动 -> 从安全存储现取快照 -> 私有initialize RPC -> SDK凭据同步完成
    |                                                   |
    +-- starting期间保存/删除：先安全写入，再登记有序操作 --+
                                                        |
                         串行应用所有在途增删 -> 无await交接 -> running/释放请求
                                                        |
running期间保存/删除 -> 同一凭据队列 -> 等待Host确认生效 -> 返回
普通请求 -> 等待启动屏障与此前已登记的凭据操作 -> 发往Host
```

- HostManager 不再持有创建时的永久凭据对象；每次 start 通过注入的读取函数取当前快照。
  系统安全存储依赖仍在 main，HostManager 保持零 Electron import，便于受控时序测试。
- 初始握手使用私有发送入口；正常 request 等待就绪。凭据队列内部也使用私有发送入口，
  避免等待自己的屏障。仅靠 stdin 行顺序不够，Host 的异步 handler 可能交错。
- starting 阶段的 set/remove 在保存后登记操作并等待应用；初始化结束后按接收顺序逐个
  await credentials.set/remove。必须保留删除操作，不能只补一次“合并新增 key”。
- 队列清空与发布 running 间不插入 await；之后的新变更进入同一队列。普通请求等待
  此前已登记变更，避免保存尚在生效时就以旧 key 发下一次请求。
- failed/stopped 时允许安全存储离线保存；结果只表示本地保存，下一次启动现读。
  starting/running 时发生应用失败，向调用方明确报告“已保存，应用到引擎失败”，
  不回滚已成功的安全存储，也不把它描述成落盘失败。
- 退出/启动失败拒绝全部等待者；用本次子进程身份约束迟到结果，旧队列不能发送到
  后一次启动。读取快照失败/握手失败保持原始原因，不无条件后台重试。
- 不增加真实 key 日志；保留系统加密、内存 overlay 与 provider 双键语义。

## 6. 回归与实施批次

| 批次 | 实现与行为测试 |
| --- | --- |
| A 配置真源 | 新 Host defaults 服务、迁移与 provider 文件服务；缺文件/旧字段/坏版本/坏 JSON/原子写失败；只迁一次、重启保留 |
| B 业务与界面接线 | 协议方法/事件/权限表、Host 初始化与会话解析、main 纯代理、UI 只读加载；验证显式 > 项目 > 全局 > ask，旧会话不变 |
| C 凭据交接 | HostManager 就绪与凭据队列、IPC 接线；用 deferred 握手复现新增/替换/删除、同 key 多次操作、启动失败与迟到结果 |
| D 集成与文档 | 无 renderer 的真实构建产物协议回归、迁移竞争窗口、四关与人工验收；整理事实和技术笔记 |

测试放 tests/，不把 tmp 探针作为交付测试。关键验收包括：

1. 仅启动 Host 即加载原有供应商、端点覆盖、禁用与模型能力；models.list 无需 UI 推送。
2. renderer 初载不调用供应商写方法；新配置保存失败不显示新值；成功变更可由其他窗口重读。
3. 旧 settings 中 auto 能迁移；启动期间保存另一个壳字段不抹掉它；新文件优先于残留旧字段。
4. 首次启动和已恢复项目两种路径，session.create 缺省都按 Host 规则执行；MCP 计划约束仍成立。
5. 慢 initialize 期间 set/remove，启动后 Host 生效表与持久存储一致；删除后旧 key 不残留。
6. 多次快速改同一 key，最终是最后操作；普通请求不越过先登记的凭据变更；不只测新增。
7. 启动/应用失败、删除进程与再次启动不会挂起 Promise、污染新进程或虚报回滚。
8. 缺 key/初始化失败仍能显示准确诊断，安全存储的离线保存能力保留。

引擎/协议/store 批次先跑 typecheck 与相关测试；修改测试后跑到通过。
交付执行 lint、typecheck、build、npm test，阅读完整输出。真实 GUI 与系统钥匙串的
验证另报；自动测试不能替代未执行的手测。不运行 npm run dev，不自动提交。
