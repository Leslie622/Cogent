# 页面切换状态保留

> 设计提案，尚未实施。范围是应用侧边栏的一级 AppView 切换。
> 从属于 [全局架构](全局架构.md) 的 renderer 壳层，不改变进程与引擎边界。
> 产品前提：Cogent 是 Agent 客户端，对话是持续工作的工作台。

## 1. 产品契约

首页 → 设置 / 定时任务 / 插件 → 首页，接续同一个工作面。导航本身不能改变
用户正在做的事；「回来了还能重新填」不算保留。

| 状态 | 切走与返回必须达到的效果 |
| --- | --- |
| 布局 | 项目列表宽度、折叠、分区开合、标签页、分屏开合和尺寸保持；别页调整布局不改变首页 |
| 输入 | 草稿、光标、选区、输入框内部滚动、未提交表单保持；不因返回重新预填，也不因导航隐式提交 |
| 阅读 | 仍读同一条消息、相同相对位置；过程卡、工具输出、思考与清单开合保持；返回不强制拉底 |
| 弹层 | 已开的菜单、选择器、弹窗及子层、搜索与表单仍保持原状态；切页不等于关闭、取消或重新打开 |
| 交互 | 后台页面及浮层不遮挡前台、不抢焦点、不截获快捷键、不锁前台滚动；返回接回原交互上下文 |

工作状态保留不等于 Agent 停止运行：后台生成、工具执行、审批等待继续。
原本跟随输出的页面返回时看最新输出；原本读历史的页面保持阅读位置。
请求真实结束、对象被删除等业务变化仍正常反映，不能保留失效操作供再次提交。

被否：切页统一关闭菜单 / tooltip、只保留编辑弹窗草稿。这降低了用户明确要求。
Effect 是否重连是技术选择，不能直接等同于工作状态是否保留。

  列表在 content-sidebar，对话在 content-main，两者都在内容白卡中。
- `src/renderer/src/features/shell/AppShell.tsx:71–82,96–107` 条件替换两个区的
  页面组件。当前导航是 `stores/ui.ts` 的 Zustand AppView，没有 React Router。
  `HomeSidebar.tsx:478–485` 首项展开只限每次挂载一次，重挂载就再次展开。
- `AppShell.tsx:43` 只创建一份 sidebar split；设置页调整宽度 / 折叠也会改变
  首页的布局条件。只保存 HomeSidebar 与 HomeMain 实例仍漏掉这一层。
- `HomeMain.tsx:24–26` Effect 无条件 collapse；`HomeChat.tsx:530` 保存组件级
  草稿；`message-scroller.tsx:59–113` 用 Provider 内 controller 管跟随与测量。
- UI 浮层当前使用默认 body portal。`AppSidebar.tsx:73–81,123–138` 在 click
  才改 view，但 outside-press / focusout 可能更早关闭页面浮层，不能事后补救。
- `ApiKeyField.tsx:25–30,69` 有恢复读值覆盖输入的风险，且在 blur 保存；导航
  失焦须与用户正常离开字段区分，不能把导航当保存动作。
- `App.tsx:60–68` 的引擎订阅、初始加载已在页面之外。继续保留这个归属。

以上缩写文件均位于 `src/renderer/src/` 的对应 feature / component 下。

## 4. 设计建议

采用「已访问的一级工作面保留实例，统一交接前台」。首选 React Activity 承载
隐藏生命周期，并修正恢复语义；先完成 §7 的兼容验证，再铺开各页面。
引入 React Router 不是本问题的必要条件，路由字段只决定谁在前台。

| 手段 | 判断 |
| --- | --- |
| 每次卸载，再外置所有 UI 字段恢复 | 草稿可保存，但 DOM、选区、阅读与多层弹窗容易漏项；不作为一级切换主方案 |
| 所有页面用 opacity / inert 常驻 | 保留几何有优势，但 body portal 与全局 modal 不能由祖先 CSS 暂停；不直接照抄 zcode |
| Activity 保留工作面，针对性处理恢复 | 保留实例与 DOM，并断开后台 UI 副作用及隐藏 portal；作为首选，不能只包一层就宣称完成 |

Activity 隐藏时不保证 UI Effects 连续运行，也不保证几何可测；实现须处理这个
生命周期，产品契约不因此降级。若真实组件验证失败，记录具体失败再调整承载
方式，不凭推断宣布必须改库或必须关闭弹层。

### 状态归属与顺序

```text
App / chat、engine stores
  └─ 引擎事件、每会话消息与运行态、审批请求（始终存活）
AppShell
  ├─ header + app-sidebar（应用导航与窗口控制）
  └─ content 工作面宿主（当前 view、已访问集合）
       ├─ home：独立 sidebar 布局 + HomeSidebar + HomeMain + 所属弹层
       ├─ tasks：独立布局与页面状态
       ├─ plugins：独立布局与页面状态
       └─ settings：独立布局、表单与所属弹层
每个已访问工作面 → 一个稳定身份的 Activity，两个内容区一起切换

owner: AppShell = 导航与前台工作面
owner: 页面 / UI 原语 = 草稿、弹层 open、阅读与布局
owner: App / stores = Agent 事件，不随切页断开

识别 shell 导航意图（含设置齿轮与它的 portal 菜单）
  → 原页浮层忽略该次 outside-press / focusout；导航失焦不提交表单
  → 更新前台 view；旧工作面 hidden，新工作面 visible
  → 旧页 UI Effects 断开，不回退焦点到隐藏页或吞前台事件
  → 新页重连布局 / 观察器，恢复尺寸、阅读与原弹层位置
  → 显示帧内协调焦点与选区（preventScroll），不重新业务初始化
后台 Agent 持续更新 store
  → 返回 following：同一滚动 owner 定位最新底部
  → 返回 reading：同一滚动 owner 保持消息锚点与相对偏移
```

- 首次访问才创建页面；未访问设置不预读凭据等资源。已访问页不因一级导航
  卸载，不使用随导航变化的 key，不为每个会话额外创建一棵常驻页面树。
- 每页独立拥有 sidebar 布局；header 折叠钮操作当前页。已有首页布局记忆有效，
  各页宽度 / 折叠互不覆盖；不把会话表单与草稿扩成磁盘缓存。
- 弹层的 React owner 在所属工作面边界内。若用专属 portal container，从首次
  挂载起保持同一容器，切页不搬 portal，不通过换容器重建弹层。
- 在页面 / portal 内持续记录最后焦点与选区，不能等 hide 才读 activeElement：
  点击导航时焦点可能已经在 rail。阅读锚点仍由现有 scroller 保存和恢复。
- 当前 HomeChat 草稿是单字符串，并非每 session 独立。一级页保留不能被宣称
  已解决 A 会话 → B 会话 → A 的全部状态；两种身份转换须分别验收。本批不得
  返回时重新 select / load 会话来伪造恢复。

## 5. 必须同批处理的恢复与浮层问题

| 位置（src/renderer/src 下） | 必须达到的行为 |
| --- | --- |
| `features/home/HomeMain.tsx:24–26`、`components/ui/resizable.tsx:16–27` | 默认 collapse 只属真实首次初始化；恢复时先还原用户布局，不播放尺寸交接的展开 / 缩回动画 |
| `features/home/HomeSidebar.tsx:470–485` | 保留首项初始化 ref；刷新不覆盖用户全部收起的意图，列表与分区滚动保留 |
| `features/home/HomeChat.tsx:530`、`components/ui/message-scroller.tsx:59–152` | 草稿、following / reading 保留；reading 验证同一消息与偏移，不能只测没有 scrollToEnd；需补锚点时由现有 scroller owner 做 |
| `features/settings/ApiKeyField.tsx:25–30,69` | 数据读取与草稿分开，恢复不能覆盖未提交输入；旧回包不覆盖新输入，导航 blur 不写配置 |
| `features/settings/ModelDialog.tsx:103–117`、`McpServerDialog.tsx:78–84`、`SkillSection.tsx:91–97`（后两者同目录） | 初始化由真实打开动作 / 编辑对象身份驱动；同一表单恢复不重填、不清错误或 JSON 内容 |
| `features/home/TodoStrip.tsx:61–68` | timer 清理与 cooldown 一致；恢复不永久留在 cooldown，也不重置用户清单开合 |
| 审批 / 问题 / 计划卡、ConversationIndex | 后台请求入 store，不抢焦点；同请求的选择与备注保留，旧卡恢复不再次 autofocus；测量使用所属页面节点 |
| 所有浮层原语 | 不更改逻辑 open，不合成关闭 / 重开；嵌套层、菜单搜索 / 滚动与表单接续，不重新预填、保存或重复提交 |

浮层在 `components/ui/` 统一适配，继续复用 shadcn / Base UI，不在业务页散放
补丁。覆盖 Dialog、AlertDialog、DropdownMenu、ContextMenu、Popover、Select、
Tooltip 及嵌套层，分别处理两个问题：

1. 后台浮层退出前台交互：Activity 断开 Effects 有原生优势，但 cleanup 的
   微任务回退焦点、新页 autofocus、恢复时 initialFocus 仍可能竞争。宿主须
   区分真正关闭与暂时隐藏，协调焦点。并非所有 Popup 都公开 initialFocus，
   不能假定统一传该 prop 即可；Select 重注册还可能重定位高亮与滚动。
2. 前台开着 modal 时仍可导航：当前全屏 backdrop 与焦点约束覆盖 rail。页面
   弹层应限制在所属 content 工作面，shell 导航仍可操作；这是模态范围适配，
   Activity 本身不解决。先验证现有公开 API，若必须调整原语，给出最小改动与
   无障碍 / 键盘证据，回写方案再扩大实施，不预先决定 fork 整库。

Base UI 的实际限制见 `dialog/root/useRenderDialogRoot.js:34–35`（AlertDialog
强制 modal）、`menu/popup/MenuPopup.js:160–168`（ContextMenu 焦点管理）、
`select/popup/SelectPopup.js:193–305`、`floating-ui-react/hooks/useListNavigation.js:193–212`
（Select 恢复测量与高亮）。不能承诺改 container 或加 inert 即完成，更不能因
技术缺口改成切页关闭弹层。正常点外部关闭、Escape、取消、保存仍按组件语义。

## 6. 边界与成本

- 本轮是运行期一级导航，不是重启恢复。不新增会话草稿、阅读与弹层磁盘格式；
  现有布局偏好继续维护。
- 仅四个已访问一级工作面，当前无 LRU / 通用路由缓存框架的容量需求。后台仍
  可能低优先级渲染，Activity 不是业务冻结或 Promise 取消。
- 窗口真实缩放、用户改主题 / 字号、后台业务完成可以正常改变呈现；导航本身
  不应制造变化。尺寸变化后的阅读锚点仍由原滚动 owner 处理。
- tasks / plugins 当前占位，本批落实同一宿主契约，不扩建不存在的业务。后续
  webview / 媒体 / 终端须由资源 owner 定义后台行为，不从 React DOM 外推。

## 7. 实施顺序与验收

用户审批方案后才动实现。首步用现有 RRP、消息流和 Base UI 实件验证一条完整
往返，确认承载满足契约，再扩展各页，不能先铺壳再补输入、分屏与浮层保证。

1. 对 home / tasks / plugins / settings 的有向切换和多次往返回归：未访问页
   不读资源，返回不重新初始化业务对象，不额外加载 / 选择会话。
2. 首页全收起项目与分区、列表滚中段；草稿选中文字、输入框内滚动；展开多张
   过程卡、打开标签分屏并拖宽。经任意其他页返回逐项相同；设置中改 sidebar
   宽 / 折叠也不改变首页。恢复首帧不播放错误尺寸过渡。
3. 生成中切走：消息、工具收尾、审批请求正常入 store，后台不抢焦点。分别验
   following 与 reading；后者比较可见消息身份及偏移，含上方异步增高。
4. 分别开模型菜单、项目选择、右键子菜单、编辑弹窗与嵌套确认，保留搜索、
   滚动、选择与未提交文本；实际点击 rail / 设置菜单切页。旧层不遮挡或截键，
   前台可滚动、输入、使用 Escape；返回层级和内容相同，无重复提交。
5. 设置未提交字段、JSON 编辑、搜索与选中往返后保留；导航不保存、恢复读取
   不覆盖草稿；原正常保存 / 取消 / 关闭仍成立。
6. jsdom 验状态身份、回调与清理；真实 Electron 验分屏几何、阅读、焦点 / 选区、
   portal 与恢复首帧。无真实布局证据不宣称整体验收通过。

实现完成同步 UI布局、对应模块事实与技术笔记（含三仓对照），再完整运行
lint / typecheck / build / npm test 并看全量输出。当前仅提案，不引用旧批次
测试结果作为本方案已生效的证据。
