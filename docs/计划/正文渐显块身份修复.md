# 正文渐显块身份修复

> 对应 [对话流畅性诊断与改造](对话流畅性诊断与改造.md) §6.2、§7 已批准的稳定块身份方向。
> 用户于本轮明确要求开始，调研范围选择“聚焦最小修复：仍对照三仓，重点查 Streamdown
> 块身份与重复段落”。本文在实现前记录具体接法，不扩成渲染器替换或代码/表格动效批次。

## 1. 目标

- 同一消息中两个相同文本的段落分别记进度，新段落正常渐显。
- 同一提交包含多个同文块时，各自排期，不能用文本 key 合并。
- 旧块和既有文本组保持节点复用；普通追加只给新单元排期。
- 保留短文本细粒度、大批有限组、首帧完整占位和 CSS opacity 过渡。

## 3. 设计与事件顺序

```text
owner：Markdown 实例 = 消息级增量信号、原生分块观察、共享排期时钟
owner：真实 BlockComponent 实例 = 本块进度、插件实例、已提交文本组边界
owner：CSS = 延迟与淡入；不反向决定消息/运行状态

收到完整正文 → 原生 remend/parser → 原样块列表 + 结构变化标记
  → 真实 Block 实例复用/新增
  → 仅查本块旧文本边界 → 新增组按本块实例身份向消息时钟排期
  → React 提交 → 本块边界转正、消息排期转正
非前缀改写 / 已稳定前缀改变 / 块数减少 → 该次重解析 settled → 提交新边界
```

1. 用稳定 BlockComponent adapter 包装导出的默认 Block，不另建 Markdown parser。
   各 Block 的插件/进度由各自组件实例持有；相同文本不会再选择到另一块的状态。
2. 单消息共享 clock/rate/gap，pendingSchedules 改按块实例身份索引；同一实例同内容的
   重试沿用排期，更新候选只替换本实例，不能跨块用 startsWith 删候选。
3. 稳定的 parseMarkdownIntoBlocksFn 包装只调用并原样返回库的 parser，记录本帧块列表。
   与上次已提交列表比较：块数减少或尾块之前的旧块改变，标记结构重整；该次受影响
   内容 settled，避免脚注/链接定义合块把旧第二段重新算成新增。普通尾块追加/新增段落
   仍按块内进度处理，保留库的解析语义。同块解析文字不再构成可信追加（如脚注定义补全）
   时也 settled；未提交渲染换版时弃掉旧候选，同版重试保留计划。
4. 插件数组/组件类型保持稳定，继续接在原默认 rehype 管线之后。历史静态模式沿用
   Streamdown 原路径；正文内容、链接守卫、代码高亮、表格结构与工作行/scroll owner 保持现有合同。
5. 对已生成的细/粗文本组，追加时沿用提交过的边界；诊断已确认96单元阈值和大批后追加
   会重组旧 span，在同一负责文件修边界记录，不用修改 CSS 时长掩盖 DOM 复用问题。
6. 32组预算口径为单个连续文本片段，加粗等内联标签会拆出多个片段，不能外推整个富文本
   块只含32个动画对象。8ms是正常批次组间目标；跨片段/跨块同批时，间隔服从剩余250ms
   起跳窗口，避免固定地板让多个大段无限接龙。

## 4. 边界

- 不更换 Streamdown 或它的 parser：公开块接口已能解决身份，替换会扩大清洗、Markdown
  与高亮回归面，没有必要成本收益。
- 代码/表格逐行过渡另批：本批只有顶层块身份，未获得流式行身份合同；继续保留当前静态结构。
- 本批保留现有来源信号：能确认的非前缀改写不播，历史 static 不挂插件；新挂载的 running
  消息仍可能从空串判为首次追加。若要区分实时首片与中途快照，需要另补 MessageRow/消息
  生命周期输入合同，不能凭块身份修复宣称已解决所有快照来源。
- 不增加动画 timer/rAF，不让业务终态等待视觉队列；收尾自然完成属于后续小批。

## 5. 验收

- 两个同文段落先后出现、同批出现、第二段继续增长，各有正确 new/settled 与独立排期。
- 旧段落 DOM 身份保留；短批持续追加跨96、大批601字后多次小追加，旧组不重新分组，
  新字符确有新 DOM，不只是把旧 span 文字替换后标成 new。
- 相同前缀的不同段落、列表项、尾随空白/标点与未闭合强调/行内 code 均保持原文与结构。
- 链接定义/脚注合块、setext/表格/列表尾部重整不重播已存在的正文；非前缀改写立即可读。
- 两条消息互不串进度，StrictMode 安全；稳定历史块不因尾块追加重新执行插件。
- 默认清洗及链接行为、代码/表格静态、连续纯文本32组预算与100ms工作行单时钟回归通过。
- 用真实 Streamdown render tests 验属性与 DOM 复用，生产浏览器验实际过渡；最终完整
  lint/typecheck/build/npm test，并同步模块页、技术笔记、手测册和交接记录。
