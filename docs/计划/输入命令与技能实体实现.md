# 输入命令与技能实体实施方案

> 状态：Phase 1 已实现（Lexical 原子实体编辑器、毛玻璃候选浮层、`/` 三类内置命令、`$`/`￥` 技能实体与结构化提交/气泡回显）；Phase 2（自定义 `.cogent/commands/*.md`）待后续排期。
> 关联模块：[技能座](../模块/技能座.md)、[会话与对话](../模块/会话与对话.md)、[上下文压缩](../模块/上下文压缩.md)、[消息呈现](../模块/消息呈现.md)、[图片与文件附件](../模块/图片与文件附件.md)、[UI 布局](../UI布局.md)。

## 1. 背景与目标

当前 Cogent 的技能底座（[技能座](../模块/技能座.md)）和会话控制 RPC（`session.compact`、`session.setPlanMode`、`session.setPermission`、`session.continue` 等）已经就绪，但聊天输入区（[HomeChat.tsx:473-498](../../src/renderer/src/features/home/HomeChat.tsx#L473-L498)）仍是纯文本 `<InputGroupTextarea>`，存在以下缺口：

1. **无 `/` 命令发现与快捷执行**：用户无法在输入框通过 `/` 触发压缩、计划模式、新建会话、重命名等已有能力。
2. **无 `$` / `￥` 技能触发面板**：用户只能盲打 `/skill:<name>`，中文输入法下按 `Shift+4` 打出的全角 `￥` 也无法唤起技能列表。
3. **非实体化表达**：技能与命令若以纯文本留在输入框，既容易误触发（如正文讨论 `$foo` 或 `/compact`），也不易整体删除、校验和在消息气泡中干净回显。

**本方案目标**：
1. 在输入区建立**结构化行内实体编辑器**，将技能与命令渲染为不可拆分的原子实体（带图标与语义色），**不支持纯文本解析触发**（未从面板选中的 `$xxx` / `/xxx` 一律按普通文本发送）。
2. 打通 **`/` 命令面板**与 **`$` / `￥` / `¥` 技能面板**，明确区分「选中即执行」「只能单独发送」「可随正文发送」三类命令行为。
3. 技能实体经结构化字段随 `agent.submit` 提交，后端走活快照展开送入 `pi`，前端用户气泡与历史回放仅展示简洁实体芯片，不泄露展开后的 `SKILL.md` 源码。
4. `@` 面板（插件/会话引用）因 Cogent 尚未具备对应底座，本次**不接线**，仅在触发器解析层保留扩展位。

## 3. Cogent 当前可支持的 `/` 命令清单

基于现有 Host RPC（[host-main.ts:809-876](../../src/host/host-main.ts#L809-L876)）与前端 Store（[chat/types.ts:201-243](../../src/renderer/src/stores/chat/types.ts#L201-L243)、[home.ts:52-61](../../src/renderer/src/stores/home.ts#L52-L61)），不造空壳命令，按执行语义严格分为三类：

### 3.1 选中即执行的本地动作命令（`kind: 'action'`）

选中后立即执行 UI/状态操作，**仅移除当前 `/xxx` 触发词，保留已有正文、技能实体与附件，不自动发送消息**：

| 命令 | 中文/英文搜索关键词 | 适用条件 | 执行动作（复用现有能力） |
| --- | --- | --- | --- |
| `/plan` | `plan`、`计划`、`计划模式` | 始终可用（新聊天草稿 + 已有会话） | 幂等开启 Plan 模式：草稿态调 `useHomeStore.updateNewChat({ planEnabled: true })`，会话态调 `useChatStore.setPlanMode(id, true)`（已开启时保持开启） |
| `/new` | `new`、`clear`、`新聊天`、`新建会话` | 始终可用 | 切换到新聊天草稿（`useHomeStore.startNewChat()`）；不创建空会话 |
| `/mode` | `mode`、`permission`、`权限`、`自动`、`完全访问` | 始终可用 | 展开/直选权限模式（支持 `/mode ask`、`/mode auto`、`/mode autonomous` 或面板中直接呈现对应子项，复用 `setPermission` / `updateNewChat({ permissionMode })`） |
| `/rename` | `rename`、`name`、`重命名` | 仅**已有会话**且非运行中 | 打开当前会话的 `RenameChatDialog`（复用现有重命名弹窗与 `session.rename`） |
| `/settings` | `settings`、`设置`、`偏好` | 始终可用 | 导航打开设置页 |

### 3.2 只能单独发送的会话控制命令（`kind: 'standalone'`）

这类命令走 Host 控制 RPC 而非 `agent.submit` 对话流，**不能与普通正文前缀、技能实体或附件混发**；选中后在输入框首位插入独占命令实体：

| 命令 | 参数支持 | 适用条件 | 独占规则与执行链路 |
| --- | --- | --- | --- |
| `/compact` | 可选压缩说明（`[instructions]`，≤ 2000 字） | 仅**已有会话**、有消息、非运行中、非压缩中 | 只能放在输入开头，后面可跟可选的压缩说明纯文本；**禁止与技能实体或附件同发**（插入时若已有技能/附件，或发送时检测到混用，给出明确内联提示并阻断）。发送后走现有 `session.compact({ sessionId, instructions })`（[host-main.ts:557-569](../../src/host/host-main.ts#L557-L569)） |
| `/continue` | 无参数 | 仅**已有会话**、最近回复 `truncated === true` 且非运行中 | 严格独占（前后不得带文本、技能或附件）；发送后走现有 `session.continue`（`useChatStore.continueGeneration()`） |

> 交互补充：对 `standalone` 命令，用户也可以在面板按 `Enter` 选中插入实体后直接再按 `Enter` 发送（对 `/compact` 方便在实体后补充压缩重点，如 `[ /compact ] 保留架构决策和文件路径`）；若输入区为空且命令无参数（如 `/continue`），选中后直接插入实体或一步执行均可，默认统一为**插入实体、允许确认后发送**，避免误触。

### 3.3 可随正文一起发送的 Prompt 型命令（`kind: 'prompt'`）

选中后插入命令实体，可与补充说明、技能实体、附件一起发送，提交时展开为对应提示词进入 `agent.submit`：

| 命令 | 适用条件 | 行为说明 |
| --- | --- | --- |
| `/init` | 当前会话或新聊天已绑定工作区目录（有 `primaryCwd`） | 内置 Prompt 模板：指示 Agent 检查当前仓库结构与技术栈，创建或更新工作区根目录的 `AGENTS.md`；命令实体后可附加额外要求 |

> **自定义 Markdown 命令（`.cogent/commands/*.md`）**：归入 Phase 2，与技能座对称由 Host 新增 `CommandStore` 发现，沿同一 `kind: 'prompt'` 实体通道接入，不阻塞 Phase 1 交付。

## 4. 核心方案设计

### 4.1 编辑器与实体模型（Lexical 原子节点）

引入成熟编辑器框架 `lexical` + `@lexical/react`（同 `zcode` / `deepseek-harness` 路线），将 [HomeChat.tsx:473](../../src/renderer/src/features/home/HomeChat.tsx#L473) 的 `<InputGroupTextarea>` 替换为受控的 **`ComposerLexicalEditor`**（置于 `src/renderer/src/features/home/composer/`）：

1. **草稿数据结构（升级 [attachments.ts:18](../../src/renderer/src/stores/attachments.ts#L18) 的 `Draft`）**：
   - 在 `Draft` 中新增 `entities: ComposerEntity[]`（与 `text: string` 中的 `\uFFFC` 哨兵按顺序一一对应，保持与 `attachments.saveDraft` 兼容，同时作为 Lexical 序列化/恢复真源）。
   - 实体类型判别联合：
     ```ts
     export type ComposerEntity =
       | { id: string; kind: 'skill'; name: string; scope: 'user' | 'project'; eco?: boolean }
       | { id: string; kind: 'command'; name: 'compact' | 'continue' | 'init'; mode: 'standalone' | 'prompt' }
     ```
   - **防伪造与纯文本隔离**：粘贴纯文本若含 `\uFFFC` 直接剥离；手打 `$foo`、`/compact` 永远只是普通 `TextNode`，不进 `entities`，也不触发任何命令或技能展开。
2. **Lexical 原子节点（`ComposerEntityNode extends DecoratorNode`）**：
   - 使用 Lexical `DecoratorNode`（`isInline() = true`、`isIsolated() = true`）将每个实体渲染为不可拆分的 React 行内芯片：
     - **技能实体**：紫色/强调色图标（`IconWand`）+ 技能名（如 `control-browser`），视觉对标参考图 4；
     - **命令实体**：等宽/强调色胶囊（如 `/compact`、`/init`）。
   - 借助 Lexical 原生能力，自动获得稳健的中文 IME 组合保护、撤销/重做历史、选区/光标越过原子节点、Backspace 整块删除与剪贴板处理。
3. **草稿持久化**：
   - `localStorage` 恢复日志升级为 `version: 2`（向后兼容读取 `version: 1` 旧草稿，缺省 `entities: []`），刷新、切会话或审批面板卸载重挂后实体不丢失。

### 4.2 触发器与候选浮层

1. **触发规则（纯函数模块 `composer/triggers.ts`）**：
   - 仅在光标前处于行首、空白字符或实体哨兵 `\uFFFC` 之后匹配触发符：
     - **`$` / `￥`（U+FFE5）/ `¥`（U+00A5）** → 唤起**技能面板**（仅列出当前作用域已启用的技能，含 `manualOnly` 技能；实时拉取并缓存 `skills.list({ cwd })`，面板打开时静默刷新）。
     - **`/`** → 唤起**命令面板**，分两组展示：
       1. 「命令」分组（§3 列出的可用命令，按当前会话状态动态过滤）；
       2. 「技能」分组（复用同一份已启用技能快照，选中同样插入**技能实体**）。
     - **`@`** → 本次**不注册触发器**，保留接口槽位。
   - **反误触**：查询词含空白时立即收起；按 `Esc` 记录当前触发签名并关闭面板，直到触发词变化前不再反复弹出；输入法组词（`isComposing`）期间不劫持 `Enter` / 上下键。
2. **浮层交互与视觉**：
   - 浮层锚定在输入卡正上方，圆角、阴影与背景色沿用 `bg-popover border shadow-md rounded-xl` 语义令牌。
   - 键盘导航：`↑` / `↓` 环绕选中，`Enter` 或 `Tab` 确认选中，`Esc` 关闭；支持名称、描述、中英文关键词模糊匹配（如 `/压缩` 命中 `/compact`，`/计划` 命中 `/plan`）。
   - 底部常驻轻量提示条：技能面板显示「输入内容以搜索技能」，命令面板显示「输入内容以搜索命令或技能」；每条技能右侧标注来源（`项目` / `用户` / `生态`）+ 单行截断描述。

### 4.3 提交路由与后端结构化技能展开

1. **前端提交分流（`HomeChat.tsx` `send()`）**：
   - **场景 1：存在 `standalone` 命令实体**
     - 校验独占约束：若 `entities` 数量 > 1、存在 `skill` 实体、存在附件/目录，或命令实体不在开头（前面有非空正文）→ 不发送，在输入卡底部 `role="alert"` 展示明确提示（如「`/compact` 需单独发送，请先移除附件或其他技能」）。
     - `/compact`：取实体后的剩余纯文本作为 `instructions`（若超 2000 字提示），调用 `useChatStore.compactNow(instructions)`（需将现有 `compactNow()` 扩展接收可选 `instructions?: string` 并透传给 `session.compact`）。
     - `/continue`：要求无多余文本，调用 `useChatStore.continueGeneration()`。
   - **场景 2：普通消息 / 含 `skill` 或 `prompt` 命令实体**
     - 提取 `skillNames: string[]`（按在输入中出现顺序去重）和剥离实体哨兵后的用户正文（对于 `/init`，附带内置 Prompt 标记或由 Host 展开）。
     - 通过 `agent.submit` 扩展可选字段提交：
       ```ts
       // src/protocol/types.ts — AgentSubmitParams 新增可选项（向后兼容）
       skills?: string[]
       command?: { name: 'init' }
       ```
2. **Host 侧处理与转录/回显隔离（[session.ts:953-956](../../src/host/runtime/session.ts#L953-L956) & [pi-session-factory.ts:146-155](../../src/host/kernel/pi-session-factory.ts#L146-L155)）**：
   - **送给模型的 Prompt**：Host 收到 `skills: string[]` 后，用 `skillStore.snapshotMany(roots)` 按名活查每个技能，依次展开为 `<skill name="..." location="...">...</skill>` 块拼在用户正文前（支持单条消息同时引用多个技能实体；若某技能在提交瞬间已被禁用或删除，显式拒绝本次提交并报错，不静默吞掉）。
   - **用户气泡与历史回显（不泄露展开正文）**：
     - 在 `onUserEntry` 中沿用 `cogent.attachment-input.v1` 同款机制，落一条 `cogent.skill-input.v1`（记录 `{ userEntryId, skills: [{ name }], command?: { name } }`）与用户原始显示文本；
     - `transcript.ts` 投影用户消息时带回 `skills` 元信息并剥离展开的 `<skill>...</skill>` 块，[MessageRow.tsx:110-120](../../src/renderer/src/features/home/MessageRow.tsx#L110-L120) 在用户气泡中把 `skills` 渲染为与输入框一致的实体芯片！
   - **既有 `/skill:` 兼容**：后端 `skillStore.expandSkillCommand` 保留，不影响已有集成测试 `tests/integration/skills.test.ts` 与纯协议调用方。

## 5. 边界与排除项

| 排除项 | 原因与约束 |
| --- | --- |
| `@` 插件与会话引用 | Cogent 当前尚未实现插件座与跨会话引用协议，无真实数据源；保留触发器扩展位，待对应底座落地后接入 |
| `@` 工作区文件引用 | 本次未列入需求范围，且文件搜索与附件/目录引用链路独立；编辑器实体模型已预留 `kind` 扩展点，后续可低成本追加 |
| `pi` CLI 的 24 个 TUI 命令全量搬运 | `/tree`、`/login`、`/hotkeys`、`/theme` 等强绑定终端 TUI 或与 Cogent 壳管理重叠（凭据在 `safeStorage`、会话树未开放）；仅映射 Cogent 已有真实能力的子集 |
| 自定义 `.cogent/commands/*.md` 发现与管理 UI | 涉及新增 `CommandStore`、目录优先级、设置页管理界面与参数替换，拆为 Phase 2 独立交付 |
| 纯文本 `$skill` / `/cmd` 隐藏解析 | 明确禁止：避免正文误触与状态漂移，实体是唯一触发契约 |

### Phase 1（首发闭环）

   - `src/host/runtime/skill-store.ts`：新增 `expandSkillsByName(names, cwds)`（多技能活展开 + 缺失报错）。
   - `src/host/runtime/session.ts` & `src/host/kernel/pi-session-factory.ts` & `src/host/kernel/transcript.ts`：接线结构化技能/内置 `/init` 展开，落 `cogent.skill-input.v1` 并在转录投影剥离展开块、回填展示实体。

   - `src/renderer/src/stores/chat/store.ts` & `types.ts`：`submit` 透传 `skills` / `command`；`compactNow(instructions?: string)` 透传可选压缩指令。
