# 上下文工程与压缩优化实施方案

> 状态：Batch 1（MCP 24K 落盘、L1 压力裁剪、L2 中文黑盒摘要、压缩后资产恢复、手动焦点指令与 UI 入口、5 维上下文归因、规则文件兼容）+ Batch 2（文档归位与架构地图 `flowCompaction` 升级为「上下文工程与压缩转录」）已实现并通过自动验收。
> 关联模块：[上下文压缩](../模块/上下文压缩.md)、[用量与成本](../模块/用量与成本.md)、[钩子座](../模块/钩子座.md)、[会话与对话](../模块/会话与对话.md)、[图片与文件附件](../模块/图片与文件附件.md)、[MCP 座](../模块/MCP座.md)、[架构地图](../模块/架构地图.md)。

## 1. 背景与目标

基于 `reference/` 三仓源码实读与主流产品（Claude Code、Manus、Cursor、OpenAI Codex）公开实践对照，当前 Cogent 在提示词三层治理与 pi 内核托管（决定 26）上已打好基础，但在**上下文工程全链路（防膨胀 → 裁剪 → 压缩 → 恢复 → 观测）**上仍存在 6 类可一步到位补齐的系统性缺口：

1. **执行期 MCP 大输出缺少统一落盘兜底**：pi 内置工具已有 2000 行 / 50KB 截断（终端落盘），`read_attachment` 已有 24K 落盘，但 `mcp__*` 外部工具的大返回体直接全量进入上下文，易单次撑爆窗口或加剧 Context Rot。
2. **缺少 L1 零成本工具结果裁剪（Microcompact / Pruner）**：多轮工具调用积累的陈旧 `read`/`grep`/`bash`/MCP 结果一直原样留存直至触发全量 L2 LLM 摘要，既浪费 token 又提前引入有损摘要。
3. **L2 压缩摘要与中文/黑盒契约割裂**：`compaction.ts` 中的 `COMPACTION_SUMMARY_PREFIX` 仅用于 `estimateContext` 粗估，真实压缩请求完全走 pi 英文默认提示，中文长会话压缩后容易诱发模型复述检查点或短暂漂移回英文。
4. **压缩后工作态恢复薄弱**：用户本会话上传的附件（`id → name` 映射）与目录引用落入影子区后易在摘要中丢失精确 ID，导致压缩后模型无法再调用 `read_attachment` 分页查看附件。
5. **手动压缩与上下文可观测性不足**：`session.compact` 不支持透传焦点指令，UI `ContextIndicator` 缺少手动触发入口；`estimateContext` 仅分 3 段且 `toolDefs` 未计入动态装配的 MCP 工具 schema，无法看清工具输出与技能/MCP 各自占比。
6. **工作区规则发现过窄 & 架构地图存在事实偏差**：规则发现仅查根目录 `AGENTS.md`（未兼容 `AGENTS.override.md` / `CLAUDE.md`）；架构地图 `flowCompaction` 将 `convertToLlmMessages` 误述为真实请求投影、将 `AUTO_CONTINUE` 误挂在 `summarize` 下游，且未呈现上下文工程完整闭环。

**本方案目标（遵循决定 26，不重写 pi 压缩与转录内核，全部走官方扩展点与 Host 承接面）**：
1. 补齐**执行期 MCP 大输出截断落盘** + **压缩前 L1 零成本工具结果裁剪**（不破坏常规轮次 KV-Cache）。
2. 通过 `session_before_compact` 复用 pi 官方 `compact()` 注入**中文/黑盒摘要约束与用户焦点指令**。
3. 实现**压缩后活跃附件与目录引用索引自动恢复**（经 `sections` 稳定段增量维护，不破坏前缀缓存）。
4. 打通**手动压缩焦点指令协议与 `ContextIndicator` 触发入口**、**5 维度上下文归因估算**与**规则文件优先序兼容**。
5. 代码验收通过后，同步升级架构地图 `flowCompaction` 为 **「上下文工程与压缩转录」**，修正事实偏差并清晰体现全部上下文机制。

### 3.2 六项核心机制详细设计

#### ① 执行期 MCP 大输出截断与落盘（`src/host/runtime/tool-spill.ts`）
- **作用域**：在 `pi-session-factory.ts` 的 `session.agent.afterToolCall` 中拦截 `mcp__*` 工具的非错误结果（`!isError`）。
- **阈值与策略**：
  - 单条返回文本总长度 `> 24_000` 字符（与 `read-attachment.ts` 同口径）时触发落盘。
  - 完整原文原子写入 `<hostRoot>/tool-outputs/v1/<uuid>.txt`（目录按需创建，仅限文本块；图片等非文本块原样保留不丢失）。
  - 返回给模型的文本保留**头部 16,000 字符 + 尾部 4,000 字符**（UTF-16 代理对安全切片，不截断 emoji），中间插入省略字符计数，末尾附加内部说明：`完整输出已保存至内部临时文件 <path>（仅用于 read 分页读取，切勿向用户暴露此路径）`。
  - 写入磁盘失败时降级为纯头尾截断 + 诊断日志，不阻断工具返回。

#### ② L1 零成本工具结果裁剪（`pruneStaleToolResults` + pi `appendContextEdit`）
- **为什么不在 `session_before_compact` 中 `cancel`**：实读 `reference/pi/.../agent-session.ts:3274-3293` 证实，`session_before_compact` 触发在 `compaction_start` 之后，返回 `{ cancel: true }` 会向外广播 `compaction_end(aborted: true)` 与 `session_compact_failed`，污染状态机与 UI。
- **正确触发时机**：在 `before_agent_start`（每轮 run 启动前）和 `turn_end`（多轮工具循环中、早于 pi `_compactBeforeNextAssistantResponse` 检查之前）调用 `maybePruneToolResults()`。
- **触发门槛（保护 KV-Cache）**：
  - 计算当前有效压缩阈值 `threshold = contextWindow - adaptCompactionToWindow(settings, contextWindow).reserveTokens`。
  - 仅当当前投影估算 token 达到 **L1 压力线** `l1Trigger = Math.min(Math.floor(threshold * 0.85), threshold - 2_000)` 时才运行裁剪；常规低水位对话**零修改、100% 保持前缀缓存**。
- **裁剪规则**：
  - 仅扫描当前 `piSessionManager.getBranch()` 中**末条 `compaction` 之后**（活动区）的 `toolResult` 条目，跳过已有 `context_edit` 覆盖的条目。
  - 按 `assistant` 轮次从尾部倒数，**保护最近 `5` 轮工具调用**（`KEEP_RECENT_TOOL_ROUNDS = 5`）不被裁剪。
  - 跳过 `isError === true` 的错误结果（保留排障上下文），跳过包含图片/非文本块的结果（或仅裁剪其中超长文本块、保留媒体块）。
  - 仅针对文本长度 `> 8_192` 字符的条目裁剪为：**头部 4,096 字符 + 尾部 1,024 字符**（代理对安全），中间插入 `\n\n[... 已裁剪 ${omitted} 字符以释放上下文；如需原文可重新读取对应文件或重新执行 ...]\n\n`。
  - **最小收益守卫**：统计全部候选条目的预计节省 token（`Math.floor(savedChars / 4)`），若总节省 `< 256` tokens，则**放弃本次裁剪**（避免为极小收益破坏前缀缓存）。
  - **落盘方式**：逐条调用 `piSessionManager.appendContextEdit(entry.id, { content })`（append-only）。
  - **双投影一致性**：pi 的 `buildSessionProjection()` 立即生效并拉低后续请求与阈值判断的 token 数；Cogent 的 `readPiTranscript()` 读取原始 `message` 条目，UI 历史回放仍完整保留原始工具输出。

#### ③ L2 压缩摘要与中文/黑盒契约对齐（`session_before_compact`）
- 在 `createCogentHooks` 新增 `beforeCompact` 回调，挂载 pi 的 `session_before_compact` 钩子。
- 当自动（`threshold` / `overflow`）或手动（`manual`）压缩触发时：
  - 构造合并指令 `buildCompactionInstructions(event.customInstructions)`：
    1. 固定附加 Cogent 摘要约束：默认使用简体中文撰写结构化摘要（代码、路径、标识符、命令与报错原文保持原样）；严守黑盒静默边界（不将 `<system-reminder>`、内部 ID、`~/.cogent/` 内部路径当作用户意图写入）；保留未完成任务、关键决策与精确文件/行号。
    2. 若存在用户传入的 `customInstructions`，以 `用户重点保留要求：...` 附加其后。
  - 通过 `ctx.modelRegistry` / `opts.modelRuntime` 获取当前活动模型的 `apiKey` / `headers`，直接调用 `@earendil-works/pi-coding-agent` 导出的官方 `compact(event.preparation, model, apiKey, headers, mergedInstructions, event.signal)`，返回 `{ compaction: result }`。
  - 异常或模型凭据缺失时返回 `undefined`，安全回落 pi 默认摘要路径，绝不导致压缩退化失败。
- 同时在 `compaction.ts` 中明确注释 `convertToLlmMessages` 仅用于估算口径（真实请求走 pi `buildSessionProjection` + `convertToLlmWithBlockImages`），消除文档与源码的口径歧义。

#### ④ 压缩后活跃工作态恢复（`cogent_session_assets` 动态段）
- **数据源**：从 `piSessionManager.getBranch()` 读取本会话已提交的 `cogent.attachment-input.v1` 自定义条目（包含 `attachments` 与 `directories`）。
- **触发条件**：仅当当前分支存在 `compaction` 条目、且至少有一个附件或目录引用落在最新压缩的**影子区**（即 `firstKeptEntryId` 之前）时生成 `cogent_session_assets` 段；无压缩或全部资产仍在保留区时返回 `null`（零 token 开销）。
- **段位置与缓存友好性**：置于 `DYNAMIC_SECTION_ORDER` 的 `cogent_outputs` 之后、`skills` 之前（`cogent_outputs → cogent_session_assets → skills → cogent_permission → cogent_plan_active → cogent_plan → cogent_todos`），仅在压缩发生或新附件上传后变化一次，由 pi `diffSystemPromptSections` 增量维护。
- **内容格式**：紧凑列出本会话历史附件（`id`、`name`、`mime`、`size`）与目录引用（`name`、`path`），附带与 `reminders.ts` 一致的黑盒边界声明（对外只说文件名，按需用 `read_attachment` 读取，不暴露内部 ID）。

#### ⑤ 手动压缩焦点指令与 UI 入口
- **协议（additive）**：`SessionCompactParams` 新增 `instructions?: string`（[src/protocol/types.ts](../../src/protocol/types.ts)）。
- **Host 边界**：`host-main.ts` 的 `session.compact` 校验 `instructions` 为可选字符串（`trim()` 后若非空且长度 `> 2000` 拒绝 `InvalidParams`）；`session.ts` 的 `compactSession(sessionId, instructions?)` 直通 `pi.compact(instructions)`。
- **UI 交互**：在 `ContextIndicator.tsx` 悬浮卡底部（缓存命中率下方或同区）增加紧凑的「压缩上下文」动作行（复用 `Button variant="outline" size="xs"`），点击调用 `window.cogent.engine.request('session.compact', { sessionId })`；流式生成中或压缩进行中自动禁用并显示状态，错误反馈沿现有 toast/提示链路呈现，不打断输入区视觉简洁度。

#### ⑥ 5 维上下文归因估算 & 规则文件兼容
- **5 维归因估算**：
  - `ContextEstimate`（[src/protocol/types.ts](../../src/protocol/types.ts)）保持既有 4 个必填字段不变，新增可选字段：`skills?: number`、`mcpTools?: number`、`toolResults?: number`。
  - `estimateContext(messages, systemPrompt?, activeTools?)`：
    - 若传入 `activeTools`（来自 `pi.agent.state.tools`），区分内置/宿主工具与 `mcp__*` 工具分别计入 `toolDefs` 与 `mcpTools`（`toolDefs` 仍保持总工具声明口径兼容老 UI，细项按比例拆出）；
    - 从 `systemPrompt` 提取 `<skills>...</skills>` 块单独计入 `skills`；
    - 从非 `system` 消息中拆分 `role === 'toolResult'` 单独计入 `toolResults`。
  - `ContextIndicator.tsx` 检测到细项字段存在时展示：**系统提示词**、**技能清单**（>0 时显示）、**工具声明**（含 MCP 工具标注或拆行）、**对话消息**、**工具输出**（>0 时显示）；老会话无新字段时自动平滑回落原 3 行。
- **规则文件兼容**：`prompts/system.ts` 每个绑定根目录按 `['AGENTS.override.md', 'AGENTS.md', 'CLAUDE.md']` 顺序取首个存在文件，保留 16K 字符上限与 `<workspace_instructions path="...">` 标签。

## 4. 架构地图重构规划（Batch 2，代码验收后同步）

升级 `flowCompaction` 为 **「上下文工程与压缩转录」**（保留 `viewId: 'flowCompaction'` 兼容锚点）：

| 泳道（Lane） | 泳道名称 | 节点链路与状态 |
| --- | --- | --- |
| Lane 0 | 防膨胀、裁剪与占用观测 | `budget`（执行期截断与落盘：pi 50KB/2K行 + 附件/MCP 24K 落盘，`implemented`） → `meter`（5 维占用估算、预警线与缓存命中观测，`implemented`） → `l1Prune`（L1 压力触发工具结果裁剪：`appendContextEdit`，`implemented`） |

## 5. 明确边界与排除项

| 排除项 | 不纳入本批的原因（实际约束） |
| --- | --- |
| 替换或重写 pi 的摘要请求复用主会话 KV-Cache | 决定 26 明确压缩摘要由 pi 内核托管；pi 当前刻意设置 `cacheRetention: "none"` + `<conversation>` 文本化防续写，强行绕开会破坏 split-turn 与文件追踪维护性 |
| 跨会话长期记忆（`MEMORY.md` + LLM Selector + 离线 Dream 巩固） | 涉及独立存储域、用户隐私治理与额外辅助模型费用，属于独立大模块，不在本批上下文压缩治理范围 |
| 子会话上下文防火墙（Subagent Context Isolation） | 依赖路线图中尚未立项的「子会话座」（[全局架构.md](全局架构.md#5-路线与未完成队列)），立项时再单列方案 |
| 压缩后自动从磁盘重读最近 N 个源码文件正文 | 与 pi 原生 `keepRecentTokens = 20000` 保留近期原文存在重复，且易在压缩后瞬间回填大量 token 触发连续压缩；先通过 `<read-files>` 路径 + `cogent_session_assets` 恢复结构化资产索引，成本低且可控 |
| Anthropic `clear_thinking` 协议级参数透传 | 需视上游 `@earendil-works/pi-ai` 是否暴露对应 beta 配置位，不魔改 `node_modules` |
