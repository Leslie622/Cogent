## 对比结论（reference/zcode 实读，2026-11-17）

- **分桶**：zcode `packages/ui/src/store/zcodeSessionStoreTypes.ts:237` 用单一
  `workspaces: Record<string, WorkspaceZCodeUIState>`（一个 tab 一个 workspace 一只桶），
  store 头注释与本项目 chat.ts 同款理由（"切换标签页时…才不会互相串台"）；
  配 `createDefaultWorkspaceState()` 默认工厂（:554）+ 稳定单例默认值（:592，
  防 selector 读未落键桶时快照不稳 —— 与本项目 `EMPTY_MESSAGES` / 约定 1.2-8 同题同解）。
  **反面证据**：zcodeSessionStore.ts 尾部注册内存诊断自认"workspace 桶全仓无删除路径，
  先落日志"——桶只增不减，泄漏仅记账不修。本方案以"删会话删一键"在结构上杜绝此类。
- **拆分**：zcodeSessionStore.ts 主文件 ~70 行，组合 createNavigationSlice /
  createWorkspaceSlice / createTaskSlice 三个切片函数；types（598 行）与 selectors
  （316 行）独立成文件；主文件 re-export 保住旧导入路径。
- **被否方案**：
  - ① 保留 12 map + 泛型 `omitSession` helper —— helper 漏传某个 map 编译器照样
    不报，只有单桶给得了编译期完备性（TS 保证删键即删整桶）；
  - ② zcode 式切片函数组合（`...createXxxSlice(set, get)`）——那是为 900–1000 行级
    独立关切（workspace/task/navigation）服务的；本项目动作面内聚于会话生命周期，
    按文件拆即可，切片组合徒增一层间接。

## 设计

### P1 桶形状（stores/chat/types.ts）

```ts
/** 会话运行标志（run 生命周期的瞬态；桶创建时由工厂给全初值） */
export interface SessionRuntime {
  running: boolean
  stopping: boolean
  compacting: boolean
  truncated: boolean
  lastError: string | null
  /** 最近一次 L1 prune 账目（compaction.completed 配对取后即清） */
  pruned: Array<{ toolCallId: string; originalChars: number; prunedChars: number }> | null
  /** run 内轮终实报（run 终态 / 压缩时清除） */
  contextLive: MessageUsage | null
}

/** 单会话的 renderer 侧全部状态（桶） */
export interface SessionBucket {
  messages: MessageItem[]
  todos: TodoItem[]
  runtime: SessionRuntime
  pendingApprovals: PendingApproval[]
  pendingQuestions: PendingQuestion[]
  pendingPlans: PendingPlan[]
}

interface ChatState {
  sessions: SessionSummary[]          // 不变
  activeSessionId: string | null      // 不变
  /** sessionId → 会话桶：全部 per-session 状态的唯一家 */
  bySession: Record<string, SessionBucket>
  loadError: string | null
  // ...actions 签名不变
}
```

- 工厂 `emptyBucket()`（对应 zcode `createDefaultWorkspaceState`）：事件到达未建桶
  会话时 `state.bySession[id] ?? emptyBucket()` 落键（现各 map 的惰性建键同语义）。
- 清理位从"删 map 键置 undefined"改为桶内字段复位（`lastError: null` 等），
  桶本体只在 `deleteSession` 删除。
- selector 函数 `selectRunning / selectStopping / selectLastError / selectTruncated /
  selectCompacting` **签名与语义不变**，内部改读桶；组件 inline selector 改
  `s.bySession[s.activeSessionId ?? '']?.messages ?? EMPTY_MESSAGES`
  （回退仍是模块级稳定常量，约定 1.2-8）。

### owner + 事件顺序（约定 §4：会话状态改动配图）

```
owner：chat store（stores/chat/）唯一持有会话桶；事件写桶只经 events.ts

App 挂载 ── bindEngineEvents()（events.ts，唯一订阅点；先订阅后 load）
             │ 事件按 sessionId 定位桶：无桶 → emptyBucket() 落键
             ▼
session.list ──────────→ sessions[]（桶不建；选中才建）
selectSession(id) ─────→ 桶不存在 → session.messages 拉历史建桶（todos 种子）
submit(text) ──────────→ 桶.messages 乐观追加 + runtime.running=true
  ├ message.delta ─────→ 桶.messages 流式累积（高频，函数式 set）
  ├ tool.started/completed/progress → 桶.messages 工具卡行
  ├ approval.request ──→ 桶.pendingApprovals（面板唯一数据源）
  ├ run.completed/failed → 桶.messages 整段替换 + runtime 复位 + pending 清
  └ submit catch（IPC 边界）→ running=false + 乐观消息撤回
deleteSession(id) ─────→ delete bySession[id]   ← 单键删除，12 项状态全清
```

## 边界（不做，附真墙）

- **console store 的 runningBySession 不并入**：控制台域自有单 map，无繁殖问题，
  跨域并桶反而制造 store 间耦合。
- **SkillSection（461 行）不拆**：评审未列（低于大文件阈值，无跨域工具引用问题）。
- **事件分支逻辑零改动**：本批只搬文件与换数据形状；任何"顺手优化"事件语义的
  冲动都另行开批。
- **P4/P5 维持评审结论不动**（MCP 数据不上 store——无第二消费方；跨 store 编排
  不收协调层——现状可控）。
