## 1. 目标与已确认问题

实际停止后，回合显示“已停止”，已收到的正文、thinking、过程与 usage 保留；真正失败
显示“出错了”；正常完成显示“已工作”。业务终态立即交接，继续沿用已实现的正文视觉收尾。

本地存在两层信息丢失和一处尾段重复，不能只把 stopping 留成 true：

1. `store.ts:296-308` 先置 stopping；`events.ts:337-351` 在 run.failed 读取后将它清掉，
   同时清 lastError；`HomeChat.tsx:214-221` 因而回落 done。现有 HomeChat 测试直接塞
   `running:false, stopping:true`，没有覆盖真实事件消费。
2. `session.ts:1856-1897` 只用 pi 的 errorMessage 区分终态，漏读
   `agent_settled.aborted`。在最终模型回答已经成功、收口钩子仍在运行时停止，末条
   stopReason 可以仍是 stop、没有 errorMessage；仅给旧错误分支补字段也会漏判。
3. pi 中止也会发 turn_end；Host `session.ts:1691-1723` 已把当前半截正文封进
   segments，但 renderer `events.ts:362-370` 在收到这些 segments 时又追加一次本地
   streaming 占位。同一“半截”会进入两次替换数组。现有 store 测试只给前轮分段，
   错把本地追加当成当前 Host 合同；需要修正夹具并钉住正文恰一份。本项结论来自
   本次源码值链推演，尚未执行真实运行复现或新增回归。

“run”是用户一次提交对应的完整执行周期，里面可以有多轮模型请求和工具调用；单条
assistant 的 stopReason 描述那一轮消息，不能代替整个 run 的最终结果。

## 3. 设计与 owner

```text
owner: pi = 已进入其生命周期的 run 是否实际收到 abort
owner: Host = run 终态转译、分段正文、同会话串行账本
owner: renderer runtime = 本地停止请求窗口 + 最近一次 run 的最终结果
owner: HomeChat = 读取结果显示相位；Markdown 只负责局部视觉收尾

abort 点击 -> stopping=true -> agent.abort（请求受理不是终态）
pi agent_settled
  aborted=true -> run.failed(reason=aborted, messages)
  未中止且有 errorMessage -> run.failed(reason=error, messages)
  其余 -> 原 length 续写判断 / run.completed
terminal -> running=false + stopping=false + lastRunOutcome
  stopped -> 保留已出正文、清本次运行错误 -> “已停止”
  failed  -> 原失败正文规则、记录错误 -> “出错了”
  done    -> 清运行错误、保留最终正文 -> “已工作”
下一次 submit / continue -> 清上次结果和错误 -> live
```

### 3.1 Host 与协议

- `run.failed` 增加可选 `reason: 'aborted' | 'error'`，renderer `env.d.ts` 同步。
  事件名与既有字段不变；没有 reason 的旧事件按 error 处理，不再从 stopping 或文案猜原因。
- `agent_settled.aborted` 优先判中止，包括没有 errorMessage 的收口钩子中止；
  其他失败发 error。无错误文案的中止使用明确的停止说明，不把它伪造成引擎异常。
- 停止仍沿现有 run.failed 通道交付，保持已有消费者能收到终态。Inspector 记录同一
  次收口，不新增第二个终态事件；本批不改其独立展示分类。
- 自动续写在停止终态后必须退出：传递/捕获本次 StreamingState 实例，续写前核对仍
  属于本次 run，不能只因末条还是 length 再起请求，也不能误认下一次 run 的账本。
- agent_settled 的 run.failed 始终带 `messages: segments`，允许空数组；它是 Host 对
  本 run 的完整终态分段快照，包含 aborted/error turn_end 已封存的尾段。renderer 在
  `messages !== undefined` 时直接替换，不再追加本地占位；messages 缺席才沿用旧事件
  的占位封存分支。无需新增去重字段，更不通过正文匹配猜尾段是否已经封存。
- 装配/prompt 前置拒绝的 catch 尚未提供完整分段快照，保留其 messages 缺席语义；
  不能把“未提供快照”伪造成权威空数组。若真实回归发现同一终态存在尚未封存的 Host
  缓冲，则在 Host 本次 StreamingState 内补尾，turn_end 已清空的缓冲不会重复追加。

### 3.2 renderer 与界面

- SessionRuntime 增加 `lastRunOutcome: 'completed' | 'stopped' | 'failed' | null`。
  stopping 仅表示停止命令在途。运行结果与 lastError 分开，手动压缩等操作报错不能
  把上一条成功回复改成失败回合。
- emptyBucket/历史水合从 null 开始；历史协议不含回合结果，null 仍按既有 done 展示，
  不声称重启后能恢复历史停止标签。已有桶切会话继续保留其结果，删除随桶清除。
- run.completed 明确写 completed 并清 stopping/旧运行错误；run.failed 依 reason 写
  stopped 或 failed，两个有无 messages 分支共用判别。停止清错误、失败显示原错误。
- submit 与 continue 开始都清上一结果、stopping、lastError；两者请求被拒绝时按失败
  收口，保留原消息回滚规则。continue 不得残留上次停止/错误状态。
- abort 的 IPC 拒绝在外部边界收口：撤本次停止请求、显示操作错误，实际 run 继续等待
  权威终态。`aborted:false` 只表示无可中止运行，不制造 stopped。回写使用本地请求
  token，终态、新请求、新 run、删除后失效；晚到响应不能覆盖下一次 run。
- HomeChat 在 running 时保持 live，其余从 lastRunOutcome 映射相位。保留末回合消费
  会话级瞬态结果的现有范围，不在本批引入每回合持久化模型。

## 4. 另一个独立问题：启动准备期的停止

本次实读还确认 `session.ts:1126-1132` 在 pi 尚未装配时返回 true，却不取消
`driveRun`；手动 continue 在 `1045-1075` 的首个 await 前也未预约 streaming 账本。
这属于“停止命令丢失/受理预约”，与本批“已到达的终态原因丢失”是两个独立根因。

不能只补 prompt 前判断便声称修完：pi `agent-session.ts:2188-2195` 在 prompt 内还有
异步 preflight，`2598-2610` 的 abort 只在 run active 时记标记。完整修复需要 Host
准备期 stopRequested、agent_start 接力，以及 continue 首 await 前预约；后者还会改变
无效续写请求是否发 started/failed 的受理合同。它作为后续小批单独设计，不被本批验收
覆盖，也不代表取消该方向。实现体量不大，主要新增成本在可控 Promise 的完整起跑测试，
不混进本次结果字段修复后用标签通过冒充命令取消通过。

后续研究已补真实安装版探针，并修正上述草案的适用范围：input/auth与before_agent_start
的原生取消能力不同，还需处理user持久化、continue旧前缀、handled与迟到RPC。
完整证据与候选设计见 [启动准备期停止调研](启动准备期停止调研.md)，本段保留当时范围记录。

## 5. 验收与文档

1. Host 回归：普通完成、真实失败、流中止、成功回答后收口钩子中止；每次唯一终态，
   reason 正确，正文/usage 不丢不重复；length 收口时中止不会自动续写。
2. 真实 bindEngineEvents → store.abort → 终态 → HomeChat，分别覆盖有/无终态 messages、
   未 flush 的 text/thinking 尾片、工具/审批过程；stopping 已清但仍显示“已停止”。
   真实分段夹具必须包含 Host 已封存的中止尾段，另测权威空数组、thinking-only、
   真失败的封存尾段，不能只断言存在正文而漏掉重复。
3. 完成先收口后停止不改 completed；点过停止但收到真实 error 不伪装 stopped；其他
   入口中止即使本窗 stopping=false 也能显示 stopped。旧缺省 reason 事件按 error。
4. abort IPC 拒绝、aborted:false、晚到响应、下一轮 submit/continue、切 A/B 会话和删除；
   操作错误与 run 最终结果分开。会话级串行继续依赖 Host 账本，不宣称新增 runId 协议。
   replaceRunTerminal 在无 user 组的既有替换边界不在本批更改，不能外推该路径已解决。
5. 保留现有正文终态动画测试；本批不改变动画 owner、WorkingLine、scroll pin 或 CSS。
6. 触及 Host/store 后立即跑 typecheck 与相关测试；交付跑完整 lint/typecheck/build/npm test
