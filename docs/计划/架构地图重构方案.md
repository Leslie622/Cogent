# 架构地图重构方案

## 1. 目标与问题

将 `docs/架构地图/` 从“依赖主应用 UI、偏重后端静态展示、靠硬编码投影修补 Graphviz 排版的单页图”，重构为**独立自包含、布局确定不乱跳、兼顾全局下钻与机制流程图、且与代码保持保真同步的 Cogent 项目地图**。

本次重点解决六个问题：

1. **视角冗余与缺失**：现有「接入」「执行」主视图与「总览」高度重叠；而桌面壳内部、数据与存储、以及身份验证/MCP/技能/钩子等具体机制流程缺少独立视图。
2. **左侧栏空置**：占 212px 宽的侧栏目前只有一个「架构总览」按钮，没有承担目录导航职责。
3. **跨目录 UI 强耦合**：直接通过 `@/` 别名复用主应用 `src/renderer/src/components/ui`、`globals.css` 和外观 store，带来 `fs.allow`、`dedupe`、`@types/react` 路径 hack 以及 **~33.4 MB** 的单文件字体包体积。
4. **布局稳定性差**：依赖 Graphviz 全局自动布局，增删节点容易引起全图重排；为此写了 `scripts/layout-architecture.mjs` 与 355 行 `docs/架构地图/src/布局适配.ts` 硬编码节点 ID 投影，维护成本高。
5. **契约与进度可读性不足**：不能点击连线查看边界契约，现状（As-Is）与目标（To-Be）混排难以一键聚焦。
6. **图码保真与同步节奏未立规矩**：缺少源码路径/符号的自动防漂移守卫，也缺少“何时同步、何时不折腾”的明确触发门槛。

---

## 2. 方案对照与关键选型

### 2.1 UI 与依赖边界

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 继续复用主应用 shadcn + `globals.css` | 与主应用组件完全一致 | 跨目录路径 hack、双 React 风险、单文件 ~33.4 MB | 否决 |
| 抽成 Monorepo `@cogent/ui` 共享包 | 依赖关系规范 | 为单一文档站引入 workspaces 与 Electron 打包风险，收益极低 | 否决 |
| **完全自包含的极简 UI 层** | 零跨目录耦合、产物降至 **< 1 MB**、主应用升级互不干扰 | 需维护约 6 个基础轻组件与一份中性色 CSS Token | **采用** |

### 2.2 布局引擎与稳定性

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 继续 LikeC4 + Graphviz + 硬编码节点投影 | 已有实现 | 加减节点会全局抖动，投影代码强耦合具体节点 ID，每次还需生成 `.likec4/*.snap` | 否决 |
| 纯手写绝对像素坐标 `(x, y)` | 绝对稳定 | 增删模块要手工算像素，维护繁琐 | 否决 |
| **LikeC4 管模型语义 + 确定性列/泳道网格布局 + 正交通道路由** | 保留 `.c4` 单一事实源；新增节点只影响所在列/泳道，其余区域纹丝不动；一套算法通吃架构图与流程图；无需 `.likec4/*.snap` 快照 | 需为每个视图声明轻量的列/泳道清单（不含像素坐标） | **采用** |

## 3. 架构与视图体系设计

### 3.1 左侧栏目录结构（砍掉「接入」「执行」，改为两类清晰视图）

左侧栏收拢为两个分组，点击切换视图；同时保留从「架构总览」直接点击模块下钻并返回来路的能力：

1. **架构地图（结构与边界，偏静态拓扑）**
   * **架构总览**：以引擎为主干（外部调用方 → 传输入口 → Host 引擎 → 模型出口），桌面壳保持克制占比，但支持点击下钻；服务层、执行能力同样支持点击下钻。
   * **桌面壳内部**（下钻自 `desktop`）：Renderer UI、多标签工作区、Preload 白名单桥、Electron Main（IPC 分域、HostManager、BrowserRuntime/Webview 策略、safeStorage 凭据）。
   * **Host 服务层**（下钻自 `host.services`）：会话与任务、项目管理、凭据桥、执行观测、能力配置。
   * **执行能力**（下钻自 `host.runtime.capabilities`）：内置工具、MCP 工具、技能、钩子、交互工具、子会话（预留）。
   * **数据与存储**：以 `COGENT_HOME` 为中心呈现单写者归属与落盘边界（pi JSONL 转录、Host 业务 JSON 与 `outputs/v1/` 交付产物、Main 壳偏好与加密凭据、`file-view-grants` / `browser-settings`）。

2. **专题流程（核心机制，独立流程图）**
   * **身份验证与权限**：`stdio` 本机身份 vs `HTTP /rpc` 逐请求认证 vs `WS /ws` 握手认证 → `method-access` scope 检查 → 目标统一资源权限。
   * **消息与审批闭环**：发送 → IPC → `agent.submit` → pi 循环 → 工具审批挂起 `approval.request` → 专属审批 IPC 裁决 → 恢复/拒绝。
   * **MCP 双轨机制**：内部消费外部 MCP 工具（`mcp-config` → `pi-session-factory`）vs 对外 MCP Server（独立进程 `stdio → HTTP/WS → HostApi`）。
   * **技能加载机制**：技能目录发现 → 渐进清单注入 → 按需加载提示段。
   * **钩子与扩展机制**：钩子座生命周期干预、审批审计、以及本地插件分发预留位。

> 注：以上专题流程统一用同一套 LikeC4 模型 + 确定性流程布局渲染；总览模块右栏可直接跳转到相关专题流程，形成双向导航。

### 3.2 交互与阅读体验

* **现状 / 目标模式滤镜**（画布顶部紧凑切换）：
  * `全部`：完整展示现状与规划；
  * `仅已实现`：淡化所有 `planned` 节点与连线，一眼看清当前真实跑通的闭环；
  * `高亮缺口`：突出 `partial` / `planned` 节点与 `#planned` 连线，便于架构评审与排期。
* **点击连线查看契约**：
  * 选中连线时，右栏展示关系语义（调用/依赖/数据流）、实现状态、协议与边界契约（如帧格式、认证时机、事件方向）以及对应源码入口（如 `src/protocol/method-access.ts`）。
* **来源区本地友好**：
  * 保留 GitHub 链接，同时提供**一键复制仓库相对路径**，本地开发直接定位文件。
* **明确排除项**：
  * **全局搜索（`Cmd/Ctrl+K`）**：按用户要求本期不做；待视图和节点数量显著增长后再低成本补加。

## 4. 工程解耦与确定性布局设计

### 4.1 彻底剥离主应用 `src/renderer` 依赖

* **移除跨目录引用**：
  * 清理 [vite.config.ts](../架构地图/vite.config.ts) 中的 `@`、`@shared`、`fs.allow('../../src')` 与 `dedupe`；
  * 清理 [tsconfig.json](../架构地图/tsconfig.json) 中指向 `../../src/**` 与 `../../node_modules/@types/*` 的路径映射；
  * 移除 `页面.css` 对 `../../../src/renderer/src/globals.css` 的导入。
* **极简自包含 UI**：
  * 内置一份轻量的中性色 CSS Token（支持明暗切换，读本地 `localStorage` 与系统偏好），使用系统无衬线 + 等宽字体栈；
  * 自写 Button、Card、Tabs、Badge、Tooltip、Collapsible 轻组件，保留清晰的无障碍焦点与窄屏适配；
  * `vite-plugin-singlefile` 离线产物体积从 **~33.4 MB** 压降至 **~1 MB 以内**，可离线秒开、随时分享。
* **依赖与检查闭环**：
  * 仅保留 `docs/架构地图/` 自身必要依赖；`eslint` 沿用根目录 [eslint.config.mjs](../../eslint.config.mjs) 对源码的检查（或按需补齐局部配置），不引入 Monorepo / workspaces。

### 4.2 确定性列/泳道网格布局（替代 Graphviz 随机重排）

* **模型层（`模型/*.c4`）**：
  * 保持 LikeC4 作为唯一结构真源，可按需拆分为 `模型/架构.c4`（核心结构与下钻）与 `模型/流程.c4`（专题流程图），共用 `specification` 与元素定义。
* **布局声明层（`src/视图布局.ts`）**：
  * 每个视图只声明结构化的拓扑排布（不包含任何像素坐标）：
    * **架构视图**：声明 `columns`（列序）与 `lanes`（泳道行），以及可选的容器 `stages` 标题；
    * **流程视图**：声明步骤列序、分支泳道与回环方向。
* **布局引擎（`src/网格布局.ts`）**：
  * 纯函数、100% 确定性计算：按卡片内容高度与固定列距/行距排布，父容器按子节点包围盒自动收紧；
  * **稳定性保证**：在同一列或同一泳道新增节点时，仅局部顺延该列/泳道，不触发其他列跳位；
  * **正交通道路由**：同行相邻节点直连；跨行/跨列走节点间隙预留的正交轨道，自动避开节点与容器边框、交叉处留白、标签避障；
  * **移除 `.likec4/*.snap` 生成链**：不再依赖 `scripts/layout-architecture.mjs` 跑 Graphviz 快照，`dev` / `build` / `test` 启动更快更稳。

## 5. 图码保真与防漂移机制

为了做到**“既不与代码脱节，又不被过渡性改动频繁拖累”**，将同步拆成两层：

### 5.1 机械底线（自动化校验，CI 兜底）

在 `docs/架构地图/tests/` 中新增**保真校验测试**（随 `npm --prefix docs/架构地图 test` 运行）：

1. **源码路径存在性校验**：遍历所有节点、连线、视图的 `sources[].path`，断言对应文件在仓库根目录真实存在。
2. **关键符号锚点校验**：对显式声明 `symbol`（代码标识符）的源码条目，检查目标文件中仍存在该符号定义或引用（文档条目仅查路径与章节）。
3. **模型与说明双向齐备校验**：`.c4` 中所有可见节点在说明数据中均有登记，无悬空未用说明；所有视图的布局声明中不含已删除的悬空节点 ID。

### 5.2 语义同步门槛（人工/Agent 协作纪律，写入约定）

同步地图只在**稳定边界变更或功能收口**时触发，过渡态不动图：

* **不触发地图同步**：内部实现重构、局部 UI 调整、Bug 修复、实验性或过渡性中间改动。
* **必须同步地图**：
  1. 新增或移除进程、传输通道、核心服务模块、持久化存储域；
  2. 某项 `#planned` 能力正式收口交付（更新节点/连线状态与事实依据）；
  3. 身份验证、消息审批、MCP、技能、钩子/插件等核心机制的主流程发生稳定变更。
* **核验时间戳**：每个视图记录最近核对日期与对应的 `docs/模块/*.md` 事实来源，评审时一眼可知时效性。

## 6. 实施阶段与验收标准

### 分阶段实施

1. **阶段 1：工程解耦与确定性布局底座**
   * 剥离 `src/renderer` 跨目录依赖，落地自包含中性色 UI 与明暗主题；
   * 实现确定性列/泳道网格布局 + 正交通道路由，移除 `scripts/layout-architecture.mjs` 与 `.likec4/` 快照依赖；
   * 迁移现有 3 个核心结构视图（总览、服务层详情、执行能力详情）并跑通几何回归测试。
2. **阶段 2：视图体系扩展与交互升级**
   * 砍掉「接入」「执行」，重构左侧栏为「架构地图 + 专题流程」双分组导航；
   * 补齐「桌面壳内部」「数据与存储」两个结构视图，以及 5 张专题机制流程图；
   * 上线现状/目标滤镜、点击连线看契约、来源一键复制路径。
3. **阶段 3：保真守卫与文档收口**
   * 落地源码路径/符号存在性与模型双向齐备测试；
   * 更新 [架构地图模块](../模块/架构地图.md)、[架构地图 README](../架构地图/README.md)、[技术笔记](../技术笔记/架构地图.md) 与 [约定](../约定.md) 中的同步门槛；
   * 跑通根与子项目全量检查及浏览器验收。

### 验收标准

* **独立性与体积**：`docs/架构地图/` 无任何指向 `../../src/` 或 `../../node_modules/` 的导入与路径映射；`dist/index.html` 离线双击无外部请求、无报错，体积 **< 2 MB**。
* **稳定性**：新增/移除单个节点时，其余无关列与主链坐标不变；几何测试覆盖无节点重叠、无穿节点连线、端口不重叠、交叉留白与标签避让。
* **完整视图与交互**：左侧栏 5 个架构视图 + 5 张专题流程图均可正常切换与下钻返回；`全部 / 仅已实现 / 高亮缺口` 滤镜生效；点击节点和连线均可在右栏查看职责/契约与源码出处并一键复制路径。
* **保真校验**：故意删改一条 `sources[].path` 或代码符号时，`npm --prefix docs/架构地图 test` 立即失败报警。
* **全量门禁**：`npm run lint`、`npm run typecheck`、`npm run build`、`npm test`、`npm --prefix docs/架构地图 test`、`npm --prefix docs/架构地图 run build` 与 `npm --prefix docs/架构地图 run test:browser` 全部通过。
