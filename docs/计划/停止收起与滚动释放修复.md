> 用户验过回合结果保留后，反馈停止详情不收起、底部上滚需要很多次；已确认指针在普通
> 正文/空白处，不以思考或代码内层滚动解释。本批按原流畅性专项修复，两项分别验收。

## 1. 证据与三仓对照

- RunTrace用`open ?? phase==='stopped'`明确把停止设为默认展开；手动false本身不会被
  `??`反转。末条正文在TurnGroup折叠体外常驻，默认收起不会藏掉半截终答。
- 外层wheel释放following，但onScroll仅看距底<=2px就恢复并pin。生产IAB隔离页先用
  真实组件重放“上滚意图→0.5px首帧”，又验证原生trusted wheel deltaY=-0.5584：
  following重新true、位置仍在原底部量化位。这是已复现的竞争路径，尚不代表已覆盖
  用户硬件的每种滚轮动画。
- 本地Provider明确autoScroll=false，已装shadcn0.3.1原语resize只在autoScroll=true且
  following-bottom时追底；不能先把问题归成库又开启了自动跟随。

## 2. 设计与owner

```text
owner: RunTrace = 用户手动开合，所有终态缺省closed；终答仍在外部
owner: MessageScroller controller = 输入意图、following、唯一pin
wheel capture向上 -> 立即reading/撤视觉副本 -> 原生滚轮移动
首帧仍距底<=2px / 旧scroll / RO / 终态折叠 -> 保持reading，不可恢复pin
明确向下阅读并实际到达底部 -> following；发送/回底 -> 显式following
索引/程序定位 -> reading，不能拿落点近底冒充用户回底
```

- RunTrace缺省false，done/stopped/failed一致；保留手动开/关优先，不改半截正文/用量。
- 上滚在capture阶段释放。scroll恢复跟随必须同时满足向底部的真实输入/移动和到底，
  使用同步位置/尺寸基线排除旧事件、布局变化和程序定位；不能只调2px阈值。
- reading时若已在距底<=2px，正wheel/下行键/上滑touch可以直接恢复；此时原生可能
  clamp而不派发scroll，不强造位移。未知方向滚动条按下仍须实际下行，不走快捷。
- 底部向下wheel不应退出following；触摸/滚动键/拖滚动条仍可阅读并主动回底。需要
  中断在途程序平滑滚动时用当前scrollTop的instant停止，不能改变滚轮默认行为或吞输入。
- 不增加另一条pin loop，不破坏单时钟源/副本、节点代次与残差补偿。布局收起与RO必须
  服从同一阅读意图，不能在一帧内反复抢回。

## 3. 验收

1. stopped默认closed，点击展开/收起有效，用户选择不被同组件重渲染覆盖；无详情无箭头。
   真实TurnGroup live→stopped后详情closed、半截终答仍可见，既有压缩条归属断言保留。
2. wheel release后同底scroll、0.5/1px上滚首帧、旧programmatic scroll、RO/terminal同帧
   都不能恢复following；连续小上滚可立即离底，正文追加不抢回。
3. 向下到底、回底/发送、键盘/触摸/滚动条、索引近底、正向wheel在底部、StrictMode和
   节点替换都按真实输入意图验证，不能为了新测试删掉旧生命周期回归。
4. 生产隔离页比修前/修后真实位置与following；同时记录原生输入与可控事件重放的差别，
   不把IAB写成Electron31全硬件/主题/缩放通过。完整四关并读全输出，原位更新事实文档。
