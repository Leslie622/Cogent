## 1. 目标与边界

在每个用户回合（`turnId`）结束时，为用户回答以下两个①②尚未覆盖的问题：

1. **这一轮给工作区留下了哪些净文件变化**（含文件增删改重命名状态与净增删行数，如 `N 个文件已更改 +X -Y`）？
2. **如何审查这轮改动的精确前后差异，并在改坏时安全回退**？

与既有能力的职责边界如下：

| 能力 | 回答的问题 | 真源与生命周期 | 与本方案的关系 |
| --- | --- | --- | --- |
| ① [正文文件链接](../模块/正文文件链接.md) | 正文提到的文件/行列在哪 | `cogent.file-context.v1` / `file-refs.v1` + `FileService` | 共用 `turnId`、`FileContext`、`FileIcon`；不改动①的解析与词表 |
| ② [产物文件卡片](../模块/产物文件卡片.md) | 模型明确交付了哪些成果 | `outputs/v1/sessions/<id>/turns/<turnId>/manifest.json` | 同一文件可同时出现在产物卡与改动列表；撤销源文件不影响已保存交付副本 |
| [多标签工作区](../模块/多标签工作区.md) | 如何在右侧工作区承载视图 | `stores/workspace.ts` + `FilePanel` / `BrowserPane` | 新增 `diff` 标签类型挂载只读差异查看器；工作区容器不拥有快照与回滚逻辑 |
| ③ **本轮改动列表（本文）** | 本轮留下哪些净变化及审查/回退 | `changes/v1/sessions/<id>/turns/<turnId>/manifest.json` + CAS blobs | 独立 Host 服务，按需加载 Diff；不进入 `session.messages` 或普通远程协议 |

## 3. 核心架构与技术设计

### 3.1 总体路线：原始字节首尾快照 + 工具补漏 + 延迟全量基线

为同时满足 **非 Git 目录可用**、**抓到 `powershell`/`bash`/MCP 副作用**、**保留 CRLF/BOM/二进制原始字节** 与 **常规纯编辑回合零全盘扫描成本**，采用**“工作区原始字节首尾快照 + 延迟全量基线”**架构：

```text
owner: SessionManager = 预约与收口时机; WorkspaceChangesService = 快照/净统计/历史审查/恢复; change-diff-worker = 异步文本diff

用户输入 submit → changes.begin(sessionId, turnId, roots) [零磁盘 I/O]
  │
  ├─ 仅 read/grep/find/ask_user 等只读工具
  │    └─ 0 捕获、0 扫描 → finishRun 时 changes.finishEmpty() 立即短路
  │
  ├─ 放行 write/edit（在 approval.decide 放行后、工具执行前 await）
  │    └─ 仅对解析出的单目标路径做写前捕获（<1ms），不触发全工作区扫描
  │
  └─ 首次放行 bash/powershell/mcp__*（无法静态预测写盘目标）
       └─ 触发并 await 一次有界工作区基线扫描（保留此前已由 write/edit 捕获的更早 before）
            ↓
       工具执行完毕（含 isError/部分写入）→ 记录观察点
            ↓
       finishRun（最终成功 / 停止 / 失败）
       ├─ 若曾触发工作区基线：拍工作区终点清单，合并单文件捕获与基线求首尾净差
       ├─ 若仅走单文件捕获：仅对被 write/edit 触及的路径读当前终点，计算净差
       ├─ 立即清理未发生净变化的基线独占 blob，只保留变化文件两侧 blob
       └─ 原子写 changes/.../manifest.json → 广播 changes.updated → 释放 streaming
```

**关键设计收益**：
1. 绝大多数仅调用 `edit`/`write` 改几个文件的回合**完全不扫全工作区**，只读/写几个目标文件即可算出精准净变化。
2. 一旦调用 `bash` / `powershell` / `mcp__*`，立即退火到全工作区基线保护；若此前 `write`/`edit` 已改过文件 A，基线扫描**不会覆盖**文件 A 最早那份 `before`，确保 `A0 → A1(edit) → A2(powershell)` 的起点仍是 `A0`。
3. 没有 Git 依赖，也不改动用户工作区的 `.git`、暂存区或工作树；同时与 `OutputStorage` 一样严格保留原始字节（不经过 Git `autocrlf` / `eol` 过滤器）。

### 3.2 审批与嵌套工具拦截缝

在 `pi-session-factory.ts` 中，直接工具走 `session.agent.beforeToolCall`（`wrapApprovalChain`），嵌套 `ctx.executeTool()` 走 `cogent-hooks` 的 `tool_call` 事件。两条入口均调用 `SessionManager.decideApproval()`：

- **放行后才捕获**：只有当 `decideApproval()` 返回 `{ block: false }` 且 `signal?.aborted !== true` 时，才执行 `await this.changes.beforeTool(sessionId, turnId, streaming, toolName, args, cwd, signal)`。
- **不阻塞只读工具**：只读工具集直接放行并返回，不进入 `beforeTool`。
- **并发工具串行排队基线**：如果模型在同一轮并行发起 3 个 `powershell` 或 `write + powershell` 调用，它们在 `beforeTool` 内部共享同一个 per-turn Promise 队列；首个调用建完所需基线后，其余并发调用直接复用结果，避免抢跑或重复全量扫描。
- **单文件工具结束补采**：在 `tool_execution_end`（或 `afterToolCall`）无论成功或失败（失败前可能已部分落盘），对 `write`/`edit` 的目标路径标记“已观察写后”，确保即使同路径随后被忽略或位于根外，收尾也能准确读到最终态。

### 3.3 工作区基线覆盖范围与排除规则

1. **绑定根边界**：
   - 取回合冻结的 `streaming.workspace.roots`（多根去重并校验 `realpath`）。
   - **无绑定目录（`roots.length === 0`）**：绝不扫描整个 `homedir()`，自动将基线策略置为 `tools-only`（只追踪获准的文件工具目标，状态提示“未绑定工作区目录，仅统计文件工具更改”）。
2. **目录扫描排除规则**：
   - 固定跳过版本库与重型依赖缓存：`.git`、`.svn`、`.hg`、`node_modules`、`.pnpm-store`、`.yarn`、`COGENT_HOME`、`outputs/`、`changes/`。
   - **嵌套仓库边界**：扫描子目录时若发现内含 `.git`，将该子目录记为 `nested-repo` 边界并停止向内遍历（与 Harness `gitlink` 同语义）；若用户需要追踪其内部，须将其显式绑定为项目根。
   - **不默认全盘应用 `.gitignore`**：因为脚本、构建或文档工具生成在 `dist/`、`out/`、`tmp/` 下的真实产出经常在 `.gitignore` 里；保留显式开关或后续配置扩展，首版只排上述目录。
   - **符号链接与 junction**：沿用 `scan-engine.ts` 安全纪律——**不跟随目录符号链接/junction 递归扫描**，防止符号链接循环或逃逸出工作区根；文件符号链接记录其链接目标字符串变化而非偷偷穿透覆写原文件。
3. **覆盖诚实标记（`coverage`）**：
   - `'complete'`：已扫描全部工作区根并覆盖工具补漏；
   - `'tools-only'`：无绑定根，或仅执行了文件工具且完整捕获；
   - `'partial'`：发生扫描超时、文件数超预算、单文件超上限、权限拒绝或读前后文件持续变化，附具体 `warnings: string[]`。**绝不把 `partial` 伪装成“无更改”或 `+0 -0`。**

### 3.4 存储布局、去重、租约与回收

与 `OutputStorage` 一致，存储于 `<hostRoot>/changes/v1/sessions/<sessionId>/`（**按会话分域**而非全局共用一个对象库）：

```text
<hostRoot>/changes/v1/sessions/<sessionId>/
  ├─ blobs/
  │   └─ <sha256[0..2]>/<sha256>     # 本会话内跨回合内容寻址去重（原始字节）
  ├─ stat-cache.json                 # 可选轻量加速：realPath -> { dev,ino,size,mtimeMs,ctimeMs,sha256 }
  └─ turns/
      └─ <turnId>/
          └─ manifest.json           # 回合唯一真源（含基线/终态/entries/coverage/rewinds）
```

**按会话分域的工程依据**：
- `SessionManager.delete()` → `cleanupDeleted()` 时可直接整体 `rm(sessionPath, { recursive: true, force: true })`，无需跨会话引用计数和全局 GC 锁，彻底消除“边删会话边写共享 blob”的竞态。
- 同一个会话内多轮修改同一大项目时，`blobs/` 按 `sha256` 去重，同一份内容只存一份物理字节。
- **未变文件零长期占盘**：
  - 全工作区基线扫描时，对超过单文件副本上限（`20 MiB`）或总增量预算的文件只记 `(size, mtime, sha256_or_oversized)`，不盲目拷贝进 `blobs/`；
  - 收尾比对完成并写出 `manifest.json` 后，立刻执行一次会话内引用计数核对：仅被当前回合基线临时引用、在终点时**未发生任何变化**的 blob（且不被本会话其他历史回合引用）**立即删除**。最终盘上长期留存的只有真正发生净变化的文件两侧 `before`/`after` 字节。
- **租约保护**：工作区正在打开某个 Diff 标签、或 `changes.diff` 正在读取某对 blob 时持有内存 `pinned` 计数，删除或清理避让活跃读取（同 `OutputsService.pinned` 机制）。
- **中断恢复**：Host 启动或历史水合调用 `changes.get(sessionId)` 时，若发现某个 `manifest.json` 停留在 `running` / `finalizing`（例如进程强退），与 `OutputsService.get()` 一样将其推进为 `interrupted`（保留已保存的基线与明确告警“上次运行中断，未冻结终态”，**不拿重启时的当前磁盘冒充当时的回合终点**），并同步清理孤立临时 blob。

### 3.5 净差异计算与 Worker 隔离

1. **Diff 计算与文本判断放到独立 Worker（`change-diff-worker`）**，避免大文件或复杂编辑阻塞 Host 事件循环。
2. **变更类型（`ChangeKind`）全面表达**：
   - `'added'` / `'modified'` / `'deleted'` / `'renamed'` / `'type-changed'`（如文件变符号链接）/ `'mode-changed'`（如可执行位变化，内容不变）/ `'eol-or-encoding'`（去除换行差异或 BOM 后可视行完全一致，但字节发生变化）。
3. **唯一内容匹配改名折叠**：
   - 若同回合内存在非空且 `sha256` 相同的**唯一一次** `deleted` 与**唯一一次** `added`，合并为一条 `renamed`（带 `oldPath` 与 `path`）；出现 1 对多或空文件歧义时保持各自独立条目，不强行猜配对。
4. **行数统计降级诚实**：
   - 二进制（前 8 KiB 含 NUL 字节或非合法 UTF-8/UTF-16）、超出 `maxDiffBytes`（`20 MiB`）、任意一侧缺失内容（`oversized` / `unreadable` / `unknown`）、或 diff 计算超时（`1,000 ms`）：保留文件条目与类型，**`added`/`deleted` 为 `null`**（UI 显示 `—`），绝不写 `0` 误导用户。

### 3.6 手动继续与自动续写语义

- **自动续写（`AUTO_CONTINUE`）**：在同一次 `StreamingState` 内完成，起点基线不变，最终 `agent_settled` → `finishRun` 时结算。
- **手动继续（`continueSession`）**：
  - 传入 `resume = true`。`changes.begin(..., resume = true)` 读取该 `turnId` 既有 `manifest.json` 中的**初始基线**作为 `before`；
  - 本段续写若新改了其他文件，将原基线补充/继承；
  - 若续写前外部修改了原未动文件，通过检查上一个已发布 `revision` 的 `after` 与本次起点状态差异，把“继续前外部变动”记录在诊断提示里，而不把原回合基线覆盖掉；
  - 结算后原子递增 `revision` 并推送 `changes.updated`。

### 3.7 协议与权限设计

在 [src/protocol/domains.ts](../../src/protocol/domains.ts) 与 [src/protocol/method-access.ts](../../src/protocol/method-access.ts) 中新增 `changes` 域（`PROTOCOL_VERSION` 保持向后兼容）：

- **RPC 方法**（均设 `rendererAllowed: true`，**不设 `httpScope`**——同 `files.*` / `outputs.*` 一样拒绝 HTTP/WS 与 guest 访问，且在 `electron/main/ipc/engine.ts` 对 `changes.*` 执行 `requireFileWindow` 校验）：
  - `changes.get`：`{ sessionId, turnId? }` → `TurnChangesSummary[]`（只含摘要列表、统计计数、状态与 `coverage`，**不含文件全文**）。
  - `changes.diff`：`{ sessionId, turnId, revision, changeId }` → `TurnFileDiff`（按需加载单个文件的冻结 `before`/`after` 文本、hunks、行号统计与可用动作能力；超过交互渲染阈值则返回截断/拒绝对话提示）。
  - （P2 预留）`changes.revert`：`{ sessionId, turnId, revision, changeIds?: string[] }` → 冲突预检后回退单文件或整轮。
  - （P2 预留）`changes.redo`：`{ sessionId, turnId, revision, changeIds?: string[] }` → 冲突预检后重做单文件或整轮。
- **增量事件（`ProtocolEvents`）**：
  - `changes.updated`：`TurnChangesSummary`（仅向主窗口广播；WS 不广播，同 `outputs.updated`）。
  - `changes.error`：`{ sessionId, turnId, message }`。

### 3.9 撤销与重做（P2 单独批次，预留契约）

撤销/重做涉及真实写盘与外部并发修改，必须作为独立严格测试批次：
1. **预检与冲突拒绝**：Host 恢复前逐项验证当前磁盘 `exists`、`lstat`（拒绝符号链接/硬链接自动覆盖）、`realpath`、`sha256` 是否与预期版本（撤销比对 `after`、重做比对 `before`）一致；任何一项不匹配立即标 `conflict` 并拒绝覆写用户后续手改代码。
2. **只回退文件，不回退聊天**：聊天消息列表和转录完全保留，撤销后在 `TurnChangesBar` 标记“已撤销（可重做）”。
3. **恢复日志（`rewind-log`）**：整轮撤销先预检全部项，写盘记录目标与顺序再逐项执行；中途因外部并发写入或权限出错停止时，只对仍符合预期版本的已回退项提供局部补偿，并明确报告成功项、冲突项与失败项，不掩盖磁盘真实状态。

## 4. 初始容量预算与性能护栏

集中配置于 `CHANGE_LIMITS`（待真实仓库规模压测后调优，不作虚假性能承诺）：

| 维度 | 初始预算 | 超限降级行为 |
| --- | --- | --- |
| 并发文件捕获 I/O | `2` 路 | 排队等待，支持 `AbortSignal` 取消 |
| 单工作区基线最大文件数 | `20,000` 个 | 停止新增枚举，标记 `coverage: 'partial'` 并附超限提示 |
| 单文件副本/Diff 大小上限 | `20 MiB` | 仅记录元数据与 SHA-256（若 ≤ 哈希上限），不存副本；列表保留条目，统计标 `—` |
| 单文件哈希上限 | `100 MiB` | 大于 100 MiB 不读全文件内容算 hash，标 `oversized` 与未知差异 |
| 单轮新增对象上限 | `256 MiB` | 超额后仅保留路径与元信息，不存副本 |
| 单会话改动存储总上限 | `1 GiB` | 超限提示并停止长期保留旧历史内容副本（或仅保留清单摘要），不悄悄破坏磁盘 |
| 单次扫描（基线/终点）超时 | `10 s` | 中止扫描，标记 `coverage: 'partial'`，已捕获的工具目标仍保留 |
| 单文件文本 Diff 超时 | `1,000 ms` | 降级返回 `timeout` 状态，列表行数标 `—` |
