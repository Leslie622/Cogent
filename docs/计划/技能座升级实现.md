## 1. 背景与目标

Cogent 现有技能座（阶段 4b + 输入命令与技能实体 Phase 1）已跑通四目录发现、回合级热刷新、预算截断与 `$`/`￥`/`/` 原子实体，但在对标主流 Agent 产品（Claude Code、Cursor、Codex CLI、zcode、deepseek-harness）与开放标准（`agentskills.io`）时，存在以下结构性短板：

1. **复用 `read` 工具加载 `SKILL.md` 的架构天花板**：
   - 模型自主激活技能时，在对话流里只是一张普通的「读取 `SKILL.md`」卡片，无专属技能感知与审计统计；
   - `read` 直接读原盘文件，无法在模型自主加载路径上做变量替换（如 `${CLAUDE_SKILL_DIR}`）、`modelInvocable` 拦截、100KB 正文预算截断或附属资源指引；
   - 系统提示清单即便降级到 `names-only` 也必须保留冗长的绝对 `<location>` 路径，严重挤压 20k 预算。
2. **变量替换能力缺失**：社区技能广泛使用 `${CLAUDE_SKILL_DIR}`、`$ARGUMENTS` 等变量，目前无统一可扩展的变量映射表。
3. **无 `bundled` 内置技能层与生态发现缺口**：缺少随安装包分发的内置技能层；未覆盖 `.claude/skills` 生态目录及 monorepo 子目录向 `.git` 根的祖先继承。
4. **Frontmatter 仅支持最小子集且编辑会丢字段**：[skill-store.ts:296](../../src/host/runtime/skill-store.ts#L296) 保存时硬编码只写 `name`/`description`，编辑已有技能会静默抹掉 `disable-model-invocation`、`license`、`when_to_use`、`allowed-tools` 等全部字段；UI 缺少开关与高级配置。
5. **无导入/导出与附属资源管理**：装社区技能（文件夹 / `.zip`）只能手动拷贝目录；设置页无法一键打开技能目录，也看不到同级的 `scripts/`、`references/`、`assets/` 文件。

**升级目标**：彻底淘汰“靠 `read` 工具凑合读 `SKILL.md`”的折中路径，在不破坏 Cogent 核心安全边界（决定 28）与内核边界（决定 27）的前提下，将技能座一次性升级至**主流产品完整水位**。

## 3. 核心设计

### 3.1 专用 `skill` 工具（取代 `read` 读 `SKILL.md`）

新建 `src/host/runtime/skill-tool.ts`，沿现有交互座（[interact-tools.ts](../../src/host/runtime/interact-tools.ts)）模式通过 pi `customTools` 注入并加入 [pi-session-factory.ts:309](../../src/host/kernel/pi-session-factory.ts#L309) 的 `tools` 白名单。

- **工具名与参数**：
  ```ts
  name: 'skill'
  parameters: Type.Object({
    name: Type.String({ description: '可用技能清单中的精确技能名' }),
    args: Type.Optional(Type.String({ description: '传给技能的可选参数文本' }))
  })
  ```
- **执行流程（与显式触发共用 `SkillStore.loadForExecution`）**：
  1. 用当前会话多根工作区 `roots` 实时执行 `snapshotMany(roots)`（无缓存，保持回合内与手动修改文件同步）；
  2. 校验技能存在且已启用；模型调用路径严格校验 `skill.modelInvocable === true`（`disable-model-invocation: true` 的技能抛出明确错误，仅允许用户显式触发）；
  3. 读取 `SKILL.md` 正文，剥离 frontmatter，执行 **100KB（`MAX_SKILL_BYTES = 100_000`）字节上限截断**，超出时尾部追加 `[Skill content truncated]`；
  4. 扫描技能目录附属资源（`scripts/`、`references/`、`assets/` 等，上限 50 项、忽略 `.git`/`node_modules`），生成紧凑相对路径列表，帮助模型准确使用同级脚本与参考文档；
  5. 运行通用变量映射表 `expandTemplateVars`（详见 §3.3）；
  6. 封装统一输出外壳（自主调用与显式触发 100% 同形）：
     ```xml
     <skill_content name="commit-check">
     # Skill: commit-check

     <正文内容（已完成变量替换）>

     Base directory for this skill: /abs/path/to/commit-check
     Relative paths in this skill are relative to this base directory.
     Bundled files:
     - scripts/check.py
     - references/rules.md
     </skill_content>
     ```
- **工具元数据与专属 UI 呈现**：
  - [tool-meta.ts](../../src/host/runtime/tool-meta.ts)：注册 `skill: { kind: 'read', summarize: summarizeSkillArgs }`（返回 `skill(<name>)`，免审批、plan 模式可用）；
  - [tool-display.ts](../../src/renderer/src/components/ui/tool-display.ts)：`KIND_LABELS.skill = '技能'`；
  - [tool.tsx](../../src/renderer/src/components/ui/tool.tsx)：`TOOL_ICON.skill = <BookOpenIcon />`，过程流与折叠轨迹清晰展示「技能 `commit-check`」，展开可查看实际加载的正文与基础目录。
- **观测审计与压缩恢复**：
  - 接入 `InspectStore`，记录 `skill.loaded`（含 `name`、`trigger: 'tool' | 'explicit'`、`origin`、`truncated`）；
  - 在 [compaction.ts:288](../../src/host/runtime/compaction.ts#L288) 的 `buildShadowSessionAssetsSection` 中补充扫描压缩影子区已成功调用的 `skill` 工具与 `cogent.skill-input.v1` 记录，输出「本会话曾激活过的技能列表」，避免长对话压缩后模型失忆；同时提供 `sessionHasLoadedSkill(branch, name)` 工具函数，为未来工作流技能门预留。

### 3.3 通用变量映射表（`src/host/runtime/template-vars.ts`）

新建独立纯函数模块，供技能座、未来插件座及受控配置层复用：

```ts
export interface TemplateVarContext {
  skillDir?: string
  projectDir?: string
  sessionId?: string
  arguments?: string
  positionalArgs?: readonly string[]
  /** 预留给插件座 */
  pluginRoot?: string
  pluginData?: string
  /** 预留给未来自定义非机密变量（如平台基址） */
  extra?: Readonly<Record<string, string>>
  /** 仅允许在 allowSensitive: true 的敏感 sink 中消费（正文恒禁止） */
  secrets?: Readonly<Record<string, string>>
}

export interface ExpandTemplateOptions {
  /** 正文 / Prompt 场景强制为 false；仅未来 MCP env/headers 或受控子进程 sink 允许为 true */
  allowSensitive: boolean
  /** 若正文不含 $ARGUMENTS 且 ctx.arguments 非空，是否自动追加至正文末尾（默认 true） */
  appendUnusedArguments?: boolean
}
```

- **支持的变量与生态兼容别名**：
  - `${COGENT_SKILL_DIR}` / `${CLAUDE_SKILL_DIR}` → `ctx.skillDir`
  - `${COGENT_PROJECT_DIR}` / `${CLAUDE_PROJECT_DIR}` → `ctx.projectDir`
  - `${COGENT_SESSION_ID}` / `${CLAUDE_SESSION_ID}` → `ctx.sessionId`
  - `${COGENT_PLUGIN_ROOT}` / `${CLAUDE_PLUGIN_ROOT}` → `ctx.pluginRoot`（预留）
  - `${COGENT_PLUGIN_DATA}` / `${CLAUDE_PLUGIN_DATA}` → `ctx.pluginData`（预留）
  - `${<extraKey>}` → 命中 `ctx.extra` 显式白名单键时替换
  - `$ARGUMENTS` → `ctx.arguments`；`$ARGUMENTS[N]` 与 `$1`..`$9` → 对应位置参数（按引号/空白切分，对标 Claude Code）
- **替换纪律**：
  1. **单遍扫描**：单次正则替换完成，杜绝路径值内含 `$` 造成二次展开；
  2. **未定义原样保留**：未命中的 `${HOME}`、`${FOO}`、JS 模板字面量 `${id}` 原样保留，绝不破坏 Markdown 代码块；
  3. **Token 安全硬红线（对照 `im-2.0` 与 `zcode`）**：`SKILL.md` 正文渲染硬编码 `allowSensitive: false`，Token/API Key 等机密**严禁替换进正文**（避免发给外部 LLM、落盘 JSONL 转录或进调试日志）。未来若需向联网技能脚本透传用户 Token，沿用 `im-2.0` 的子进程 `env` 临时注入模式（独立于本模板模块的正文路径）。
- **双路径统一**：
  - 用户显式触发（`$`/`/` 实体 `expandSkillsByName`、`/skill:<name> [args]` `expandSkillCommand`）与模型自主调用 `skill` 工具，全部收口到 `SkillStore.loadForExecution(name, ctx)`，统一走变量替换与 `<skill_content>` 外壳。

### 3.4 多源发现、祖先扫描、生态兼容 & `bundled` 内置技能层

升级 [skill-store.ts](../../src/host/runtime/skill-store.ts) 的发现引擎，建立清晰的 **7 级优先级链（高 → 低，近者胜，冲突进诊断）**：

1. **项目原生 `.cogent/skills`**（从绑定根 `cwd` 向上扫描至 `.git` worktree 根，近目录覆盖祖先目录，解决 monorepo 子目录打开丢失仓库根技能的问题）；
2. **项目生态 `.agents/skills`**（同上向上扫描至 `.git`，只读）；
3. **项目生态 `.claude/skills`**（同上向上扫描至 `.git`，只读）；
4. **用户自定义额外目录**（可选 `customSkillDirs`，只读，预留配置位）；
5. **用户原生 `~/.cogent/skills`**（可读写）；
6. **用户生态 `~/.agents/skills`、`~/.claude/skills`**（`.agents` 优先于 `.claude`，只读）；
7. *(未来预留槽位)* **插件技能根**（优先级介于用户与 `bundled` 之间）；
8. **`bundled` 内置技能层**（垫底只读，不可删除，支持用户/项目同名覆盖）。

- **Windows 路径纪律**：symlink / 同文件去重统一使用 `realpathSync.native`（遵守约定 §1.2 第 9 条，规避 Windows 8.3 短名失配）。
- **`bundled` 技能打包与路径解析**：
  - 仓库新增 `resources/skills/` 存放内置技能（首发放入至少 1 枚实用内置技能如 `skill-creator`，教模型按 Cogent/Agent Skills 规范创建和校验技能）；
  - 开发态：`main` 解析 `<repo>/resources/skills`；
  - 打包态：[packaging/build.mjs](../../packaging/build.mjs) 在 `extraResources` 中把 `resources/skills` 打包到 `resources/skills`（若目录存在则同步进 Windows 与 WSL `.deb` 构包链路）；
  - 传递方式：Electron 主进程启动 [HostManager](../../src/electron/main/host/manager.ts) 时注入环境变量 `COGENT_BUNDLED_SKILLS_DIR`；[host-main.ts](../../src/host/host-main.ts) 读取该环境变量传给 `new SkillStore(...)`（纯 headless 缺省时自动探测或静默为空）。
- **与未来 `bundled` 插件的关系**：
  - 单源归属原则：核心常驻、不可卸载的纯技能留在 `bundled-skills`；未来某能力升级为带 MCP Server / UI 面板的可选 `bundled` 插件时，将其技能目录直接迁入插件包（单源迁移）。若过渡期或增强版存在同名，优先级链保证 `插件 > bundled`（启用插件用增强版，关闭自动回退内置版）。

### 3.5 完整 Frontmatter 标准支持 & 无损编辑

扩展 `SkillStore` 的元数据解析与写回逻辑：

- **完整解析字段**：
  - 必填校验：`name`（≤64，`^[a-z0-9-]+$` 无首尾/连续连字符）、`description`（≤1024 非空）；
  - 路由与调用控制：
    - `when_to_use?: string`（补充路由时机）
    - `disable-model-invocation?: boolean`（默认 `false`；映射 `manualOnly`）
    - `user-invocable?: boolean`（默认 `true`；为 `false` 时不出现在输入框 `$`/`/` 面板，仅模型可见）
    - `argument-hint?: string`（输入框参数提示）
  - 权限与运行元信息：
    - `allowed-tools?: string | string[]`（统一归一化为 `string[]`）
    - `context?: string`、`agent?: string`（解析并保留；检测到 `context === 'fork'` 时产出可读提示 `unsupportedRuntime: 'context-fork'`）
    - `license?: string`、`compatibility?: string`、`metadata?: Record<string, unknown>`
- **修复 `skills.save` 丢字段缺陷**：
  - 保存已有技能时，先解析原 `SKILL.md` 的 `frontmatter` 对象（`parseFrontmatter`），保留所有未在本次参数中显式覆盖的字段（如 `license`、`compatibility`、`metadata`、`allowed-tools`、`context`、`agent` 及第三方自定义键），再写回 `name`、`description` 及本次修改的可选字段；
  - 新增 `disable-model-invocation` / `user-invocable` 为默认值时可省略不写冗余键，保持生成文件简洁可读；
  - 序列化采用 `yaml` 包（pi 已传递安装或写严格安全的 YAML frontmatter 序列化器）保证多行字符串、嵌套 `metadata` 往返无损。

### 3.6 与 Cogent 架构/权限边界的明确划分（不造重型权限引擎）

- **`allowed-tools`（静态无损保留 + 详情只读展示，不接运行时审批引擎）**：
  - 调研实证：`agentskills.io` 明确标注其为 **Experimental**；`pi`、`deepseek-harness`、`zcode`（技能运行时）、Cursor、Codex 均未在技能运行时强上该权限引擎；本质上它归属「工具与审批权限层」，不应在技能座里另起炉灶。
  - Cogent 做法：`SkillStore` 完整解析并**无损保留** `allowed-tools`（兼容跨工具文件互拷），设置页详情可只读展示作者声明的预期工具；运行期审批统一继续走 Cogent 现有权限档与工作区规则（决定 28）。
- **`` !`cmd` `` 正文加载期静默执行 Shell（明确安全冲突，不做）**：
  - 与 Cogent 决定 28（所有 shell 必须过审批链、流式可见、可中止、留审计）及工作区信任边界直接冲突（打开陌生项目触发技能即静默执行宿主机命令 = RCE 风险）。模型加载正文后直接调用正常 `bash`/`powershell` 工具执行即可，体验完整且受控。
- **`context: fork` / `agent` 独立子会话执行（前置依赖未就绪，显式留缝）**：
  - 强依赖尚未落地的**子会话座（Subagent）**（[全局架构.md](全局架构.md#5-路线与未完成队列)）。本次无损解析保留并在设置页标明「需子会话支持，当前在主会话执行」，待子会话座落地后无缝接通。

### 3.7 导入导出、目录管理、协议与 UI 全面升级

#### ① 协议增量扩展（[src/protocol/types.ts](../../src/protocol/types.ts) & [method-access.ts](../../src/protocol/method-access.ts)）
保持 `PROTOCOL_VERSION` 不变，全量 additive：
- `SkillOrigin = 'cogent' | 'agents' | 'claude' | 'custom' | 'bundled'`；
- `SkillSummary` 新增可选字段：`origin?`、`userInvocable?`、`whenToUse?`、`argumentHint?`、`allowedTools?`、`unsupportedRuntime?`、`resourceCount?`、`readonly?`（`eco`/`custom`/`bundled` 均为只读不可 UI 编辑删除，`bundled` 单独标「内置」）；
- `SkillReadResult` 新增可选字段：`whenToUse?`、`manualOnly?`、`userInvocable?`、`argumentHint?`、`license?`、`compatibility?`、`allowedTools?`、`unsupportedRuntime?`、`resourceFiles?: string[]`；
- `SkillSaveParams` 新增可选字段：`whenToUse?`、`manualOnly?`、`userInvocable?`、`argumentHint?`、`allowedTools?: string[]`；
- 新增 RPC 方法：
  - `skills.import`（`httpScope: 'write'`, `rendererAllowed: true`）：参数 `{ scope: 'user' | 'project', cwd?: string, sourcePath: string, overwrite?: boolean }`，返回 `{ imported: string[], skipped?: string[] }`。支持导入：
    - 单个技能目录（含 `SKILL.md` 及全部 `scripts/`、`references/`、`assets/`）；
    - 包含多个技能子目录的根目录（批量导入）；
    - `.zip` 压缩包（复用 `package.json` 已有零原生依赖 `fflate`，安全校验：拒绝 `..`/绝对路径穿越、拒绝 symlink 条目、单文件 ≤10MB、总解压 ≤100MB / 1000 文件、校验每个技能的 `name`/`description`，校验全部通过后再原子落盘，失败清理 staging 目录无半装）；
  - `skills.export`（`httpScope: 'readonly'`, `rendererAllowed: true`）：参数 `{ scope: SkillScope, cwd?: string, name: string, destinationPath: string }`，将目标技能整目录用 `fflate` 打包为标准 `.zip`；
  - `skills.revealTarget`（`httpScope: 'readonly'`, `rendererAllowed: true`）：参数 `{ scope: SkillScope, cwd?: string, name: string }`，Host 校验技能存在并返回规范化的真实目录路径，由 Electron main 受信任 IPC 调用 `shell.openPath` 打开系统文件管理器（不接受 renderer 任意路径，同 [ipc/files.ts](../../src/electron/main/ipc/files.ts) 信任边界）。

#### ② Electron 主进程特权 IPC（[src/shared/ipc.ts](../../src/shared/ipc.ts) & `src/electron/main/ipc/skills.ts`）
经 `handleTrusted` + 主窗口顶层 frame 校验注册：
- `skills:pickImportSource`：弹出系统选择器选本地目录或 `.zip` 文件；
- `skills:pickExportDestination`：弹出系统保存框选 `.zip` 输出路径；
- `skills:revealDir`：先经 Host `skills.revealTarget` 核验，再 `shell.openPath(dir)` 打开目录。

#### ③ 设置页 UI 升级（[SkillSection.tsx](../../src/renderer/src/features/settings/SkillSection.tsx)）
- **工具栏与操作**：分组标题右侧提供「刷新」「导入（目录/zip）」「新建」；

  - 附带文件只读清单（展示 `scripts/`、`references/` 等相对路径 + 一键「打开目录」）。
