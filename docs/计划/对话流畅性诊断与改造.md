## 1. 目标与结论

目标：保留丰富的流式渐显、状态扫光和折叠过渡，同时让正文输出、滚动、输入响应稳定。不能以全部关动画冒充达成，也不能用“究极流畅”代替可复现的验收预算。

**不建议整体替换 shadcn。建议局部重构聊天呈现管线，而非继续叠 CSS 补丁。**

| 用户现象 | 本次证据 | 判断边界 |
| --- | --- | --- |
| 大块输出一股脑出现 | 自研 reveal 跳过块代码；相邻展示帧增量超过 600 UTF-16 码元直接 settled；600 汉字首批排期仅 0–79.9ms，淡入持续 300ms，几乎整片重叠 | 属确定策略问题，不是 shadcn 冲突；代码块高亮异步回填是否进一步积批须单独采样 |
| 动画多时卡，状态扫光也不顺 | 表格强压同 DOM 数，禁用 CSS animation/transition 后 P95 从 50ms 降到 16.9ms；原始状态扫光使用 background-position，不能凭 will-change 宣称纯合成 | 支持该样本的动效相关成本；尚未拆清逐字淡入、扫光和其它 transition 的各自占比 |
| 流底图标和字上下微抖 | 后续专项已在真实组件纯文字场景复现：内容增高与滚动量化不匹配，产生0.7px锯齿；固定扫光后图标/标题像素重心分别变化1.22px/0.75px；仅改临时正文行高使高度增量对齐，锯齿消失，恢复原样又出现 | **隔离复现的因果链已定位**（§2.3），不是图标/文字各自布局重排；实际Electron31窗口、用户主题和缩放尚未直接复核，不能宣称已修复 |

“已工作”是终态头，流式时底部实际文案为“工作中”。诊断采样定位后者；用户所指位置与之对应。

## 2. 证据与可复现范围

### 2.1 浏览器测量

临时工具：`tmp/chat-audit-20261117/`（被 gitignore 排除）。`audit.tsx` 直接复用正式 `TurnGroup` / `Markdown` / `MessageScroller`，没有另写聊天 UI；`audit.css` 显式扫描正式组件与 Streamdown，避免临时根目录漏生成样式。执行 `node tmp/chat-audit-20261117/serve.mjs` 构建生产包并启动仅 loopback 的预览，**不启动 Electron、不请求模型、不写真实会话**。

环境：Windows，ZCode IAB Chromium **152.0.7977.130** / Electron 44.7.0，1280×720，DPR≈1。**不是 Cogent Electron 31 / Chromium 125 真机测试**。本次 mock 从 React 状态追加开始，不含 Host / IPC / zustand / 侧栏 / ConversationIndex / 自定义主题。

位置口径：基线最后 4s，代码 y 范围 0px、纯文字 0.75px；强压在 1.5s 后代码 0.45px、表格 0.35px、纯文字 0.75px。**不足一屏时状态行随内容自然下移不算抖动**。这里只量标题，尚未分别追踪图标、文字基线和实际合成帧。

无效样本如实剔除：纯文字基线首测 11.08s 仅16帧/168字，表格基线 11.69s 仅7帧/128字，表格开动效复测 9.45s 仅73帧，均疑似页面节流/暂停；不能用它们证明卡顿或流畅。因此开动效表格只有一次有效压力样本，不能写成稳定重复统计。未执行 20 历史回合、完整 App、真实模型、实际主题与缩放矩阵。

摘要已留 `tmp/chat-audit-20261117/测量摘要.json`。录制 `code-baseline.webm` 保存成功，但本会话模型不支持视频输入，**没有把录制当成已观看的视觉证据**。

### 2.2 纯逻辑与生成物核验

- 以 TypeScript 内存转译真实 `stream-reveal.ts`，构造 HAST 执行插件：600 汉字首批 delay 为 0.0–79.9ms；+601 不动画；总长 10000 再 +8 仍动画。门槛作用于相邻展示帧增量，不是消息总长。
- 同文两段：第一段提交后，真正新加的同文第二段全 settled。进度以文本匹配而非 block 身份判断，确有漏播。
- 内存编译 Tailwind 候选：running 标题扫光选择器特异性 0,3,0；`motion-reduce:shimmer-none` 只有 0,1,0，同层下后者关不掉前者。
- SSR 比较 Streamdown 的 `animated` / `isAnimating`：只开 animated 而 isAnimating=false 无动画 span；二者都开才有。SSR/纯函数不提供浏览器帧率证据。

### 2.3 图标与文案分别微抖：专项复现与消融

用户明确补充“纯文字也抖，图标与文案分别抖”。据此纠正第一轮方法：仅测标题外框、以不到1px判稳定，会漏掉亚像素坐标引发的实际像素变化。第一轮的0.75px不能作为“不抖”证据。

临时 `jitter.html` / `jitter.tsx` 仍直接复用正式组件，初始15段正文保证已滚到底，随后每次加同一段纯文字。分别量整行、图标盒、SVG、标题、文字Range、数字、content和viewport，同时取得固定裁片PNG。正式代码零修改。观测环境仍是IAB Chromium152；工具发现只提供此后端，不能直连用户的Cogent Electron31窗口。

**几何链条已闭环：** 默认正文14px×1.625=22.75px行高（`src/renderer/src/globals.css:550-551`），本样本每段含两行和16px段距，因此每次增高61.5px。原始采样：

```text
contentHeight：1084.85 1146.35 1207.85 1269.35 1330.85 1392.35 1453.85 1515.35
scrollTop：     514.4   576.0   637.6   699.2   760.8   821.6   883.2   944.8
整行/标题 y：  586.45  586.35  586.25  586.15  586.05  586.75  586.65  586.55
图标 y：         +2      +2      +2      +2      +2      +2      +2      +2
数字 y：         +0      +0      +0      +0      +0      +0      +0      +0
```

每帧满足 `lineY = contentHeight - scrollTop + 16`。本环境观测scrollTop量化步长0.8px：高度增加61.5px、滚动通常增加61.6px，视觉位置上移0.1px；一次滚动只增60.8px则下跳0.7px。形成周期锯齿。0.8px与有效缩放1.25相容，但**缩放来源未确认，不能仅凭DPR≈1推断系统或应用缩放设置**。

`TraceLine` 是20px行高flex居中，图标16px，故相对偏移恒2px（`components/ui/trace.tsx:41,55`，前缀 `src/renderer/src/`）；标题/数字的相对布局没有各自变化。滚动owner只做 `viewport.scrollTop = viewport.scrollHeight`（`components/ui/message-scroller.tsx:66-79`）。进一步将scrollTop设为1e9仍被钳在同一值，content.bottom=630.75、viewport.bottom=630不变，**不是再多滚一点就能消掉的残差**。

| 单变量/控制组 | 结果 |
| --- | --- |
| 只暂停标题扫光，正文继续增长 | 几何锯齿仍在；排除扫光运行是该锯齿的必要条件 |
| 暂停扫光，再移除标题transform/will-change/backface提示 | 几何锯齿仍在；分层不是几何残差的来源 |
| 仅正文line-height改24px，扫光/计时/贴底全部保留 | 连续10段每次内容与滚动都增加64px；title/number恒586.3500366、icon恒588.3500366 |
| 恢复原line-height | 同样锯齿立即恢复：586.35→.25→.15→.05→.75→.65→.55→.45 |
| 正文不增长，保留扫光与100ms码表 | 12次数字变化363.09s→364.18s，整行/图标/标题/数字位置恒定；计时更新不是该几何抖动的独立触发源 |

**像素而非只看bbox：** 扫光暂停后，固定150×34裁片的5张PNG中，用 `255 - RGB均值` 加权计算各区域的纵向重心：图标15.4771、15.5565、15.1316、16.2440、16.3545（范围1.2229px）；标题15.6346、15.7386、15.2835、15.8896、16.0319（范围0.7484px）。图标强像素边界有8–22、9–23、9–24的变化，标题强像素边界保持10–22，内部抗锯齿权重变化。**共同的亚像素位移在两类绘制上呈现不同响应，与“分别抖”一致；不能把它误说成图标/标题各自DOM重排。** 未取layer tree/GPU trace，不进一步冒认某个独立合成层bug。

控制截图同样暂停扫光、只将正文换24px：连续追加后3张图标重心15.3722/15.3720/15.3720，标题15.4209完全一致，支持上述差异不是截图过程随机噪声。数字区域因内容变化未用于像素形状比较，仅验证几何坐标。

结论：**本复现已经定位“内容高度与滚动量化不匹配 → 贴底亚像素残差 → 图标/文字不同像素响应”的原因链**，无需正式重构后再猜。24px是可逆诊断干预，不是正式修复；不能以改变正文排版绕过主题、表格、图片和缩放下的任意小数高度。正式修复应在贴底视觉锚定处处理残差，或将live状态槽与可变高度内容的几何解耦，保持阅读/回底语义，并用实际Electron31重复本组恢复实验。

证据留 `tmp/chat-audit-20261117/抖动专项摘要.json`、`暂停扫光像素对照.png`、`整数行高像素对照.png` 与 `pixels.ps1`（只读截图分析）。本轮不再用“≤1px”作为视觉通过标准。

## 3. 当前 owner 与热路径

```text
pi AgentSession message_update
  → Host SessionManager：权威文本/思考缓冲，每 delta notify
  → stdout NDJSON → main 逐行解析/广播 → preload 回调
  → chat store：每 delta 更新会话桶、messages、bySession 外表
       ├ ChatMessages → 全列表 groupTurns → 历史 memo比较 / 当前回合
       │    → Markdown：到这里才做 30ms 展示合帧
       │    → Streamdown：变化块解析 → reveal分词/span → 高亮异步回填
       ├ HomeSidebar：bySession广订阅 → 项目行回调引用变化
       └ ContextIndicator：消息变化 → 历史usage重新聚合

DOM提交 / 高亮回填 / 100ms码表更新
  → 本地 MutationObserver：scrollHeight → scrollTop
  + 本地 ResizeObserver 兜底
  + shadcn：ResizeObserver→rAF测量、scroll后几何测量

跟随状态：本地 atBottom 私有闭包
显式回底动作：shadcn scrollToEnd
二者没有显式恢复通道（关键职责断点）
```

pi 的 `message_update` 是引擎事件，delta 是本次新增片段、partial 是累计消息。引擎正确接收不代表 UI 必须每片段提交 React；**权威数据及时入账、呈现适度合批**可以并存。合批必须尊重工具开始、结束、停止等事件屏障，不能丢尾字或跨会话串流。

## 6. 推荐设计（待审批）

### 6.1 唯一数据与滚动 owner

```text
owner：Host/既有store语义 = 权威消息与运行状态
owner：renderer流式发布器 = 仅会话隔离的待发布text/thinking增量
owner：Markdown块呈现 = 稳定块身份、尾部增量、动效预算
owner：聊天scroll controller = following/reading/定位，唯一写scrollTop者
owner：工作状态slot = 稳定高度/稳定实例，码表仅局部更新

收到delta → 合入(sessionId,run代次,类型)队列 → 统一节拍发布到UI store
工具/收尾/中止/失败/快照屏障 → 先flush该会话 → 再处理结构事件
DOM提交/实际高度变化 → 同一scroll controller依据用户意图同步校正
显式回底/发送 → 同一controller恢复following → 后续继续跟随
动效完成 → 只回收视觉资源，不决定业务run状态
```

不引入另一套协议或第二份持久化消息。合帧放在 renderer 事件入账/呈现边界，Host原始事件流不变；30ms可作为初值，但测试必须覆盖慢后台定时器和最终flush。不能在 Markdown 内外叠两套独立延迟。

### 6.2 动效保留，按内容选粒度与预算

- 普通短文本保留按字/词淡入；**大批文本用有限窗口的短语/行片段渐显**，不把数千个字同时变成动画对象。首轮试验预算为最多128个细粒度活动单元、排期起点落后不超过250ms、总显现不超过550ms；这些是待测参数，不是已验收承诺。
- 代码按新行做短淡入，保留现有高亮缓存；表格按新增行/稳定单元组过渡，列结构先稳定，不把整张表的全部文字逐字排期。必须验证单元格换行、未闭合语法和横向滚动，不能靠 `tr opacity` 的未经验证假设直接落地。
- 使用明确 live append / snapshot / history 信号区分大块实时输出和历史回填，替换仅凭600字符推断来源。大批实时内容不能因“太多”就全部无效；使用低成本粗粒度过渡，不无限拖延内容可读时间。
- 以稳定 block 身份管理进度，修同文段落漏播；只处理变化尾部，稳定块不反复分词/遍历。先利用已装Streamdown的增量能力，不先自研Markdown parser。
- 扫光保留视觉效果，A/B比较现有background-position与有界装饰层transform方案；对滚出视口、折叠、后台会话暂停装饰动效，reduced-motion必须真正静态。通过profile选方案，不只加will-change。
- 完成态不要为清除span立即替换整棵尾轮树；结束后允许已有淡入自然完成、只切交互状态，后续安全时机回收。业务完成不等动画，DOM/语义不保留幽灵running状态。

### 6.3 渲染与滚动约束

- plugins/linkSafety配置常量化，正确传isAnimating并核对内部滚动是否与外层冲突；过程项按稳定item引用memo；侧栏订阅审批摘要，usage按结构/用量版本更新，当前正文不驱动所有区域重算。
- 历史回合与活尾分区且引用稳定，索引只依赖user/结构变化。是否进一步上历史虚拟化由长历史profile决定，数据接口先支持分区，不强加重量级列表库。
- 固定工作状态slot的行高/图标盒/数字宽度；压缩、工具衔接与收尾不因未来消息尚未到达临时翻相位。固定slot不是把状态行永久悬浮到输入框，不改变用户当前阅读语义。
- 统一显式回底与following记账；只对真实尺寸变化pin，不因码表文本每100ms变化就无条件强制布局。live尾部不使用会扰动测高的估高包装；历史保留content-visibility或后续虚拟化能力。具体替换范围以消融结果决定。
