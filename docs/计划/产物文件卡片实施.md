> 状态：用户已批准在codex/body-file-links实施；代码与自动验收已接通，等待用户功能验收。①正文文件链接已通过功能验收；三阶段顺序见[路线图](文件三项功能路线图.md)。
> 本文保留②的施工契约与待验边界；实现事实见[模块](../模块/产物文件卡片.md)，详细操作见[验收册](../测试用例/产物文件卡片.md)。四方取舍见[文件引用笔记](../技术笔记/文件引用与改动追踪.md)§3、§7.2、§10。
> 目标：让用户明确看到“这轮交给我的文件”，能预览、打开和另存；已保存交付版本不受源文件后来改写或删除影响。

## 1. 这次交付什么

```text
聊天正文                         ① 已有：普通文件链接，打开当前文件
  ↓
产物文件卡片                     ② 本次：明确申报、Host确认后的交付文件
  文件图标 / 文件名 / 类型 / 说明 / 预览、系统打开、另存等操作
  ↓
本轮改动列表                     ③ 后续：净变化、增删统计、审查与恢复
```

| 本次包含 | 原因与效果 |
| --- | --- |
| 模型工具 `report_outputs({deliverables})` | 交付意图由模型明确表达，Host核实；正文提到文件、工具写过文件均不自动出卡 |
| 多文件、完整替换、空清单撤回 | 允许纠正交付清单；失败调用不抹掉上一份有效申报 |
| 预算内交付副本与收尾复核 | 默认打开交付版本；保留“打开当前源文件”的独立操作 |
| 成功／停止／失败／重启与手动继续 | 已确认的文件不因任务失败消失，卡片归属不因继续而重复 |
| 各种普通文件 | PDF/Office/图片/音视频/源码/ZIP/无扩展名均能交付；能否内嵌预览不决定能否出卡 |
| 可重复自动测试与用户测试用例 | 特别覆盖空清单、漏报、源文件变化和终态异步，不只检查卡片外观 |

不拍工作区快照，不计算增删行数，不实现diff或恢复，不为③预建扫描器。①的布局整改依用户要求另排；
本次卡片使用现有组件形态，保证可见、可操作和不破坏正文流，不重做整体分栏。

## 3. 工具契约与路径

```json
{"deliverables":[{"path":"out/report.pdf","note":"分析报告"},{"path":"out/data.xlsx","note":"原始数据与汇总"}]}
```

- 只有一组deliverables；每项path必填，note可选。一项代表一个普通文件；文件夹须先由正常工具打包为ZIP，不能递归偷变成多个产物。
- path是字面文件路径，遵循实际工具cwd、Home、盘符/UNC与平台比较规则；不是Markdown URI，不拆`:2:3`定位、不重复解码`%/#`。
  相对路径按当前真实回合的工具来源解析，不按前端所选项目推断。允许根外可访问目标，与①及现有read一致，不扩大写权限。
- 每项检查存在、可读、普通文件；符号链接核实真实目标；有一项非法则整次失败，返回具体路径和原因，保留旧有效清单。
  按真实目标去重，保留首次顺序、最后说明；Windows路径比较不影响Linux大小写语义，不静默截断条目。
- `[]`是成功的明确清空，必须持久化；它与从未申报不同。清空后不催报，不靠正文把卡补回来。
- 成功回执包含规范路径、所属turnId/revision、每项副本状态和警告；UI只消费结构字段，不解析自然语言回执。
  工具元数据归为read类宿主操作，不写源文件、不调用shell，不另弹普通申报审批；read权限语义与当前本机Host相同。

## 4. 回合身份与状态

复用①的真实用户entry↔turnId、工具cwd与piCwd，不改变u-N/a-N、React key、压缩条和附件记录。
新用户输入从未申报开始；自动续写沿用同一owner；手动继续继承原turnId、最后有效声明和已发布副本。
旧会话没有产物记录就不合成历史卡，只有真实申报才建立产物状态。

| 动作 | 必须发生的变化 |
| --- | --- |
| 首次有效申报[A,B] | 原子写入完整声明，建立新revision；工具成功不等于此时立即展示正式卡 |
| 再有效申报[B,C] | 当前声明变为[B,C]，没有A；同文件的说明及版本随本次结果更新 |
| 再有效申报[] | 当前声明为空；终态无产物区，持久记录清空避免重启回填 |
| 再申报有缺失项 | 本次失败，上一份声明和副本继续有效；模型可在正常工具循环中纠正 |
| ask_user挂起 | 仍是运行中，不结算新卡；需要用户提前看文件用①正文链接 |
| 成功／停止／失败 | 统一结算已确认文件；卡片注明回合结果，不把失败中的文件说成完整任务成功 |
| 手动继续 | 同回合保留上次已交付卡并标“更新中”，新结算后替换；不多出第二份回合卡 |
| 进程中断 | 重启恢复最后持久状态；未完成结算显示“上次运行中断，保留最近确认版本”，不自动重读源文件冒充当时交付 |

服务按sessionId/turnId串行提交声明，校验和复制可以有界并行；并行report调用按实际进入服务的序号排队，
不会让先调用但较晚完成的批次覆盖后调用。队列与收尾均校验捕获的owner；删除聊天或退出使旧回写失效。

## 5. 副本、收尾与唯一真源

建议新增`host/runtime/outputs/{tool,service,storage}.ts`，分别管模型工具、状态机、受管字节和原子提交；
不把复制、校验或文件清单逻辑堆进session.ts，也不建立全工作区对象库。

产物域唯一真源是Host受管manifest：`outputs/v1/sessions/<sessionId>/turns/<turnId>/manifest.json`。
文件副本放同一受管域的revision/outputId目录，使用经过basename处理的原文件名，保留二进制字节、BOM和CRLF。
manifest只保存ID、原路径、类型/大小/hash、确认时间、副本状态、revision和回合结果，不在pi正文/会话summary重复保存整份产物表。
模型通过工具回执得知结果；历史UI通过桌面outputs查询读同一真源，不为查询装配pi，也不在HTTP可读的session.messages中夹带产物表。
manifest同时区分活动声明与上次已发布清单，才能在手动继续时保留旧卡；状态为running/finalizing/ready/interrupted，
每次声明或发布提交递增revision。新输出outputId由Host生成，同回合再次申报同一规范目标沿用ID、更新内容版本；不同会话不能共用。

```text
owner: OutputsService = 声明/副本/结算；SessionManager = 活跃运行；renderer = 回合尾部投影
report_outputs → 来源/文件校验 → 同句柄有界复制+hash → revision暂存 → 原子manifest提交 → 回执
真正终态 → 冻结最后有效声明 → 复核源文件并保存最终字节 → 原子发布 → 唯一run.completed/failed
读取/复制失败 → 保留上次确认版并说明；源从未确认/本次申报非法 → 工具失败且不替换清单
重启 → 校验manifest/已保存字节 → 回合尾部恢复；不从正文重造声明
```

1. 复制前后核对同一文件句柄版本、路径真实目标和长度，边读边hash。变化只允许一次有界重试，仍不稳定则本次申报失败。
   目标真实路径变化不静默跟随。字节完成后先落受管revision，再原子替换manifest；提交失败不能先回“申报成功”。
2. 多文件替换是整体提交。暂存失败或取消只清本次受管暂存，旧manifest可继续使用；磁盘损坏显式报错，不按空清单重建。
   崩溃留下的无引用暂存可清理，已提交manifest引用的副本不能因清理丢失。
   拦截/取消/扩展最终判错的工具调用不能成为有效新声明；验证真实pi最终工具结果，并测试异常路径回收暂存、不发布新卡。
3. 正常/停止/失败收尾均复核最后有效声明；申报后又改写源文件时保存收尾版本。源删除、无权限、软链接换目标或持续变化时，
   保留最近确认副本，卡片注明“保留申报时版本／最终版未确认”及原因，不悄悄称为最终文件。
4. 保存交付副本不使用Agent已中止的signal；使用独立有界收尾owner，聊天删除/Host退出能取消。当前run在收尾结束前仍占预约，
   显示“正在保存产物”，不能提前允许下一轮抢入。收尾超时保留已确认版并给警告，不重复发终态。
5. 所有真实收口路径都经过一次finalize：agent_settled、准备失败/早停、handled、continue异常、续写预算耗尽。
   自动续写尚未结束时不提前finalize；没有声明的回合立即经过，不白做磁盘工作。
6. 产物结算异常与模型失败分别记录；不把文件保存失败伪装成Provider错误，不吞掉真正模型错误。若磁盘无法写最终状态，
   当次UI明确给结算错误，重启只恢复上次已持久状态；不承诺断电级事务或物理介质绝对可靠。

初始保护预算：每次最多100项、note最多200字符；复制2路并发，单文件100 MiB、单revision合计256 MiB、
每会话保留副本合计1 GiB，申报/最终复核各30秒总预算。以上是待实测初值，不宣称容量验收已完成。
超过副本预算的合法文件仍可交付，记录`source-only`并醒目标“仅当前原文件，未保存交付副本”；不因格式或预算把卡整个砍掉。
无权限、复制IO失败等真实故障不能冒充预算降级：申报时使本次失败，收尾时保留旧确认版并报原因。

新申报替换/清空后，只清理不再被已发布清单、活动声明及打开预览引用的受管文件；异步清理失败可重试并留诊断。
归档保留、删除会话才释放该会话数据；不删源文件，不在这里实现任意历史revision浏览或回滚。
所有清理路径由服务生成并复核在outputs受管根内，禁止把manifest中的原始sourcePath当删除目标。

## 6. 复用①打开器，而不是再造预览

| 拟增或扩展合同 | 用途 |
| --- | --- |
| `shared/outputs.ts` | OutputItem、TurnOutputs、声明/副本/结算状态及纯类型 |
| `outputs.get` | 按sessionId/turnId读取已持久产物快照；revision单调递增，含明确空声明 |
| `outputs.resolve` | `{sessionId,turnId,revision,outputId,version:'delivery'|'current'}` → 既有FileDescriptor/fileId |
| `outputs.updated` | 完整快照事件；带身份/revision/可见状态，旧事件不覆盖新状态，删桶后迟到事件不复活 |
| 独立`outputs.get`历史水合 | 与正文来源按实际turnId归属，不从位置或当前聊天推断；不扩充session.messages读盘权限 |
| FileDescriptor optional内容来源/原路径/确认时间 | FilePanel区分当前源文件和交付副本，读预算、worker与Blob释放继续复用files.* |

产物ID/revision是持久身份，fileId仍只在本次Host内有效；Host重启后outputs.resolve重新登记。
副本读取核对本会话manifest归属及内容hash，不能受源文件后来删除影响；篡改/丢失明确报错，不自动退回源文件冒充副本。
所有outputs读方法和原生动作沿用主窗口顶层帧校验，HTTP/WS/guest一律拒绝outputs.*，包括以后新增的方法。

卡片点击默认“预览交付副本”；另存也取副本。有副本时，系统打开先导出一个带原文件名的临时工作副本，
避免外部编辑器写坏受管版本；临时文件保留到应用退出后可安全清理，不假装知道外部应用已经关文件。
“打开当前原文件／在原目录定位／编辑当前原文件”独立标明，经Host再核实原路径，不能混作交付副本动作。
source-only卡默认查看当前原文件并明确提示。复制操作注明复制的是原文件路径。

Markdown副本只保证所保存文件的字节。相对依赖先匹配同次交付清单中的副本；未随清单保存的依赖显示“依赖未保存”，
可显式打开当前来源，不自动把当前图片混进历史交付预览。工具提示需要独立保存依赖时一并申报；不递归扫描整个项目。
HTML/脚本仍以源码预览，不获得应用权限执行；ZIP等无内嵌查看器的文件仍有打开/另存。

## 7. 卡片呈现、提醒与正文关系

- TurnGroup的终态尾部只挂一个OutputCards区域，位于终答后、用量行前；无终答的停止/失败回合仍有固定尾部位。
  多文件各有图标/文件名/类型/大小/说明与动作；多于3项可折叠展开，不静默丢项；不依赖是否展开过程区。
- 普通运行或ask_user等待期间不新挂正式交付卡。手动继续时上次已发布卡仍可看，标“更新中”，结算后替换；
  来源与revision属于原用户回合，不能用新段DOM位置或最近消息时间归属，也不改变原消息key和滚动owner。
- report成功项的原路径进入本轮文件词表，复用①的唯一匹配逻辑；原来因read/write已建立的引用不受清空影响。
  来自产物声明本身的词表随有效清单替换/清空，不能把失败候选加进去。正文链接仍打开当前文件，产物卡才默认交付版本。
- 系统工具说明要求需要单独交给用户的文件在终答前申报；普通读参考资料、仅修改源码、纯聊天不要求卡。
  根据成功write/edit等明确文件活动，在本来就要发生的下一次模型请求前最多提醒一次“如需交付文件，请申报”。
  `未申报`才可提醒；有效空清单也算已申报。只用pi公开context/request扩展，不加最后一次强制LLM调用。
- shell/MCP产物也能直接申报，但不靠解析任意命令猜文件来催报。模型漏报时保留①正常能力，不能把正文引用推断成卡；
  验收记录任务中的申报成功率，不能把工具存在视为永不漏报。

准备文档不新建分支、不挪①已验收改动；实现是否继续当前worktree以当时Git状态决定，未经用户要求不提交或合并。

实施落点：O1–O4已接通，使用用户指定的codex/body-file-links；工具明确设model-only，保证公开afterToolCall可等待最终判决。
单批顺序捕获，跨会话限两路；类型由文件名与共用FileService产生，不再在manifest重复维护MIME表。
用户功能验收完成前不进入③；自动验证的适用范围和未测项在验收册，不把工具链测试当真实模型申报率。

## 9. 必须通过的验收

| 场景 | 预期及证据 |
| --- | --- |
| 只写文件/正文提路径，未申报 | 正文链接可用，不出现正式产物卡；明确声明既有ZIP/PDF也能出卡 |
| [A,B]→[B,C]→[]；中间一轮非法 | 全量替换、清空生效；失败保留上一份；终态/刷新/重启一致 |
| 同名文件、多根、根外、空格中文、字面%/#、符号链接 | 工具cwd与真实目标正确；无歧义偷选、重复解码或跨Session借ID |
| 原件已交付后被改写/删除 | 卡片默认仍打开保存字节；显式原文件动作显示当前状态，不能混版本 |
| 先申报A，再正常工具改为B后结束 | 收尾交付B；删除/持续变化则保留A并标最终版未确认；不能静默忽略 |
| 停止/真实失败/无终答/ask_user挂起 | 前三者结算已确认项且状态真实；挂起不结束；唯一终态，无永久busy |
| 自动/手动继续、压缩、准备期早停 | 同turn归属、最后有效清单不丢，继续不重复卡；无产物不启动复制 |
| 两路并行申报、切聊天/删聊天/退出、旧事件迟到 | 顺序和owner正确，不复活状态，不清理其他回合或源文件 |
| 超预算、ENOSPC、不可读、复制中变动、损坏manifest/副本 | source-only仅用于预算；失败/旧版/损坏提示真实；事务不发布半份清单 |
| Markdown+依赖、各种文档/媒体/ZIP/源码 | 复用①功能；缺依赖不混当前内容；外部打开不改坏保存副本 |
| HTTP/WS/guest、伪造revision/ID/路径 | 受信通道与对象归属校验生效；原生动作不接受任意路径或shell命令 |
| 普通任务申报率与条件提醒 | 真实写文件→工具申报→卡片；明确清空不被补卡；无强制收尾LLM请求 |

自动测试须有真实文件和真实pi工具/流式终态链，不只测schema或组件桩；Electron从真实输入发送到卡片、版本预览与重启。
手测册提供固定样本/提示词/步骤/预期，至少覆盖“生成报告”“交付既有文件”“替换清空”“删原件仍可看”“停止与继续”。
交付前跑lint/typecheck/build/npm test并读取完整结果；容量、真实外部应用与目标Linux分别记录，未测不写通过。

## 10. 真实边界与文档落点

| 边界 | 墙与处理 |
| --- | --- |
| 不从正文自动生成交付卡 | 真实引用不能证明交付意图，且会破坏清空；采用显式工具与有限提醒 |
| 不保证所有模型任务永不漏报 | 模型工具选择存在概率性；实测申报率，漏报不伪造成功记录 |
| 大文件可能仅保留源引用 | 持久磁盘/复制时长有预算；卡仍出现但明确没有历史副本 |
| 单文件副本不等于整个网站/依赖归档 | 只保存声明范围；同清单依赖可用，未保存依赖显式标明，避免无界抓取 |
| 不提供旧revision浏览/恢复与变化统计 | 本次任务是交付版本；源码恢复和观察全部变化需要③的基线/冲突合同，不能由产物清单推断 |
| 不扩展远程读盘或在线协作 | 现有token没有会话文件范围授权，outputs保持桌面可信通道 |

实现完成后新增`docs/模块/产物文件卡片.md`和`docs/测试用例/产物文件卡片.md`；同步会话、消息、工具、HTTP模块及UI布局。
原理继续更新现有文件引用技术笔记，不再复制第二套四方调研。方案获批不等于实现通过，②用户验收后才准备③。
