# 模型设置与思考力度升级方案

本文记录已完成实施的模型设置与思考力度升级方案。现状事实见[凭据与模型目录](../模块/凭据与模型目录.md)与[设置页](../模块/设置页.md)。

## 1. 目标

对标主流桌面 AI 客户端（Cursor / Cherry Studio / Chatbox）及 `reference/` 同源参考仓，解决当前「模型配置不完整导致思考参数报错」与「自定义供应商上手成本高」两类问题，一次补齐以下能力闭环：

1. **完整思考档位控制（含 `off` 三态与协议值映射）**：支持禁用 `off`（解决纯思考模型发送 `effort: "none"` 或 `thinking: disabled` 报错），支持按档自定义上游协议字符串（`thinkingLevelMap`），默认不再裸放行 `minimal`。
2. **目录无损回显与模型预设体系**：编辑内置模型无损回显真实 `thinkingLevelMap`；新增/拉取模型按「内置目录 → 主流模型家族预设表」自动填充思考档位、上下文、输出上限与视觉能力，并提供快捷预设模板。
3. **关键兼容参数下放（`compat`）**：在供应商级与模型级补齐 `thinkingFormat`、`supportsReasoningEffort`、`supportsDeveloperRole`、`maxTokensField`、`forceAdaptiveThinking` 等关键兼容字段，解决中转站与自托管端点 400 报错。
4. **端点模型自动发现（`models.discover`）**：支持从 OpenAI 兼容及 Anthropic 兼容端点一键拉取可用模型列表，带搜索、多选、元数据提取与增量合并，保留已调优模型配置。
5. **全内置供应商入口与状态一致性**：左栏保留常用 7 家置顶，开放全部 `pi` 内置供应商检索接入；启动加载与修改配置后同步 clamp 活动思考力度；模型行直观展示思考支持范围。

## 4. 方案设计

### 4.1 协议与存储契约（`src/protocol/` + `business-config.ts`）

保持 additive 兼容，不破坏既有 `custom-providers.json`（v1）：

1. **`ModelDef` 扩展**（[types.ts](../../src/protocol/types.ts#L681-L706)）：
   - 新增 `thinkingLevelMap?: Partial<Record<ThinkingLevelWithOff, string | null>>`：与 `pi-ai` 同构。
     - `off: null` = 禁用关闭思考；`off` 缺省（`undefined`）= 允许关闭且不额外发 effort（沿用方言默认）；`off: "<str>"` = 允许关闭且发送该字符串（如 `"none"`）。
     - 其余 6 档：`string` = 启用并发送该值；`null` = 显式禁用。
   - 保留旧字段 `thinkingLevels?: ThinkingLevel[]` 仅作盘上读兼容，新编辑统一写 `thinkingLevelMap`。
   - 新增模型级 `compat?: ProviderCompatDef`：与供应商级 `compat` 逐字段合并（模型优先）。
2. **`ProviderCompatDef` 扩展**（[types.ts](../../src/protocol/types.ts#L740-L747)）：
   - 补齐 `thinkingFormat?: 'openai' | 'openrouter' | 'deepseek' | 'together' | 'baseten' | 'zai' | 'qwen' | 'qwen-chat-template' | 'chat-template' | 'string-thinking' | 'ant-ling'`、`supportsReasoningEffort?: boolean`、`supportsDeveloperRole?: boolean`、`forceAdaptiveThinking?: boolean`、`supportsTemperature?: boolean`（保留既有 `thinkingTokenBudgetField`、`supportsThinkingTokenBudget`、`maxTokensField`）。
3. **`ModelSummary` 扩展**（[types.ts](../../src/protocol/types.ts#L295-L325)）：
   - 新增可选 `thinkingLevelMap?: Partial<Record<ThinkingLevelWithOff, string | null>>` 与 `compat?: ProviderCompatDef`，由 [session-models.ts](../../src/host/runtime/session-models.ts) 投影下发，供设置页编辑内置模型时无损回显。
4. **新增 RPC `models.discover`**（[method-access.ts](../../src/protocol/method-access.ts) 登记 `{ httpScope: 'write', rendererAllowed: true }`）：
   - 入参：`{ providerId?: string; baseUrl: string; apiFormat: 'openai-completions' | 'openai-responses' | 'anthropic-messages'; apiKey?: string }`。
   - 出参：`{ models: DiscoveredModel[] }`（含 `id`、`name?`、`contextWindow?`、`maxTokens?`、`input?`、`reasoning?`、`thinkingLevelMap?`）。

### 4.2 引擎构建与发现逻辑（`src/host/runtime/`）

1. **`custom-providers.ts` 的 `buildModel`**：
   - `reasoning !== true` 时不写 `thinkingLevelMap`（`getSupportedThinkingLevels` 返回 `['off']`）。
   - `def.thinkingLevelMap !== undefined` 时，按 7 档规范化构造：已声明的字符串键保留原值，显式 `null` 保留 `null`，对于未显式列出的非 `off` 档位（`minimal` ~ `max`）**统一补 `null`**，彻底避免“选了几个档位却意外放开 `minimal`”；`off` 键未出现时保持 `undefined`（允许关闭且不强发字段），显式 `off: null` 时禁止关闭，显式 `off: string` 时透传。
   - 若仅存在旧字段 `def.thinkingLevels` 且无 `def.thinkingLevelMap`，沿用旧转换逻辑保持既有集成回归兼容。
   - `compat` 合并：`mergedCompat = mergeCompat(providerCompat, def.compat)`；`anthropic-messages` 方言按 `pi-ai` 适用字段过滤（`forceAdaptiveThinking` / `supportsTemperature` 等），openai 系透传全部已配置字段。
2. **新建 `model-discovery.ts`**：
   - 仅允许 `http:` / `https:` URL（禁凭据/fragment），复用 Host 凭据表（表单未失焦保存时优先用参数传入 `apiKey`），15 秒超时，`redirect: 'error'` 防 SSRF/跳转泄密。
   - OpenAI 系请求 `<baseUrl>/models`（Bearer），Anthropic 系请求 `<root>/v1/models`（`x-api-key` + `anthropic-version: 2023-06-01`），分页最多 20 页并检查游标去重。
   - 解析标准 `data` 数组及常见网关扩展字段（`context_length` / `max_input_tokens`、`max_output_tokens`、`supported_parameters`、`capabilities`、`thinkingLevelMap`），不做不安全的上游能力猜测。
3. **连通性测试（[model-connectivity.ts](../../src/host/runtime/model-connectivity.ts)）**：
   - 保持 `getSupportedThinkingLevels(model)[0]`；当禁用 `off` 时自然取到最低可用思考档，不再对纯思考模型发 `off`。

### 4.3 预设表与前端设置/聊天联动（`src/shared/` + `src/renderer/`）

1. **主流模型家族预设（新建 `src/shared/model-presets.ts`）**：
   - 收录常见模型家族匹配规则（GPT-5/5.1/5.2/5.3/5.4/o1/o3/o4-mini、Claude 4.5/4.6/4.7、DeepSeek V3/V4/R1、Gemini 2.5/3、Qwen3/QwQ、GLM-4.x/5.x、Grok 3/4），给出推荐 `contextWindow`、`maxTokens`、`input`、`reasoning`、`thinkingLevelMap` 与 `compat` 建议。
   - 提供可点击的「常用思考档位预设」快捷选项（如：通用推理 `off/low/medium/high`、禁关推理 `low/medium/high`、GPT-5.2+ `off/low/medium/high/xhigh`、Claude 4.6+ `off/low/medium/high/max`、DeepSeek V4 `off/low/high/max`），让用户在配置陌生中转模型时有清晰参照。
2. **ModelDialog 升级（[ModelDialog.tsx](../../src/renderer/src/features/settings/ModelDialog.tsx)）**：
   - **7 档全量勾选（含 `Off`）与英文档位名**：开关「思考模式」打开后，思考档位与滑杆统一采用业界通用英文名 `Off / Minimal / Low / Medium / High / XHigh / Max`（标题保留中文「思考力度」），使界面与官方 API 报错及文档 1:1 对齐；新建或刚打开思考模式时按「内置目录 → 模型预设表 → 保守基线 `Off/Low/Medium/High`（不默认勾选 `Minimal`）」预填，不再留空放开 5 档。
   - **高级折叠区**：保留「思考预算」4 档，新增「档位协议值映射」（每个已启用档位可填上游实际字段值，默认同名；`off` 留空 = 不发参数，可填如 `none`）与「模型级兼容参数（`compat`）」。
   - **保存前校验**：开启思考模式时必须至少启用 1 个非 `off` 思考档位，阻止提交无效配置。
3. **详情页与列表增强**：
   - [BuiltinProviderDetail.tsx](../../src/renderer/src/features/settings/BuiltinProviderDetail.tsx)：编辑目录模型时基于 `ModelSummary` 无损构造初值；展示全量 `pi` 内置供应商的展开/搜索入口（保留常用 7 家置顶）。
   - [CustomProviderDetail.tsx](../../src/renderer/src/features/settings/CustomProviderDetail.tsx)：补齐供应商级「高级（端点兼容）」控件；模型列表头新增「获取模型列表」按钮及 `ModelDiscoveryDialog`（搜索、全选/反选、预览元数据、增量合并、自动套用目录与家族预设）。
   - [ProviderModelRow.tsx](../../src/renderer/src/features/settings/ProviderModelRow.tsx)：推理模型行徽标直观显示思考范围摘要（如 `思考 · 4档` / `必思考`）与详细提示。
4. **Store 与滑杆收口（[engine.ts](../../src/renderer/src/stores/engine.ts)）**：
   - `load()` 与 `refreshModels()` 在拿到最新 `models` 后，对照当前活动模型的 `thinkingLevels` 执行 `clamp`，若当前 `thinkingLevel` 不再受支持则就近收窄并持久化。
   - `ThinkingSlider` 当模型只有单一思考档（例如 `gpt-5-pro` 只有 `high`，无 `off`）时，正常展示单档状态，不误标为关闭灰蓝（[ThinkingSlider.tsx](../../src/renderer/src/features/home/ThinkingSlider.tsx#L107-L110) 区分 `off` 与单非 `off` 档的颜色与标签）。

## 5. 边界与排除项

| 排除项 | 排除原因（依赖 / 安全 / 成本约束） |
| --- | --- |
| 自动发对话请求暴力试探模型支持的思考等级 | 每个模型最多需发 7 次对话请求，消耗额度且易触发限流；部分网关静默忽略非法参数，试探结果不可靠 |
| 自定义 OAuth 订阅登录流程 | 涉及各厂商私有 OAuth 协议、回调与令牌刷新状态机，维护与安全边界独立，不在本次模型设置配置面范围 |
| 任意自由 JSON/CEL 表达式映射请求体 | 自由脚本对桌面用户心智负担大且易引入语法错误；`thinkingLevelMap` 逐档字符串映射 + `ProviderCompatDef` 精选字段已覆盖已知兼容场景 |
| 自定义任意 HTTP Headers 编辑器 | 敏感头持久化与防 CRLF/环境变量注入属于独立凭据安全边界，留待后续需要时按 `Pi-meme` 加密模式单列评估 |

## 6. 验收标准

1. **协议与校验**：`npm run typecheck` 通过；`business-config` 与 `custom-providers` 单测覆盖 `thinkingLevelMap`（含 `off: null`、`off: "none"`、未选档补 `null`、旧 `thinkingLevels` 兼容、模型级 `compat` 覆盖供应商级）。
2. **端点发现**：`model-discovery` 单测覆盖 OpenAI/Anthropic 两种列表格式、分页防死循环、超时与错误状态处理、不信任重定向拒绝。
3. **UI 与 Store 回归**：
   - `ModelDialog` 组件测试验证：内置模型编辑无损回显原支持档位；支持禁用 `off`；新建开启思考不默认放开 `minimal`；命中目录/预设自动填充；无非 `off` 档位时阻止保存。
   - `engine` store 测试验证：`load()` 与 `refreshModels()` 后对不兼容 `thinkingLevel` 自动就近 clamp。
   - `ThinkingSlider` 验证：禁用 `off` 的单档/多档模型展示与交互正常。
4. **集成与构建**：既有集成测试（含 `thinking-off.test.ts`、`model-test.test.ts`）与新增集成回归（`off: null` 禁关、自定义映射透传、模型发现）全部通过；最终完成四关验证 `npm run lint && npm run typecheck && npm run build && npm test`。
