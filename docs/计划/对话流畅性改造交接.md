## 1. 用户目标与最新产品裁决

目标始终是：对话区保留渐显、扫光、终态过渡，但要让大块输出连续、动画不拖慢、
流底工作状态稳定、阅读历史不被抢回。

用户已在实际 Cogent 手测确认：

1. 「工作中」文案稳定；Clock 图标随后也稳定；
2. 上翻阅读时新输出不抢回底部；发送新消息回底；主动回底后持续跟随；
3. 回底瞬时完成可接受；
4. **最新反例（尚未修）**：完整工作状态放为滚动根的 normal-flow sibling 后，
   内容不足一屏也被推到屏幕底部；用户明确判定错误。上翻时 sibling 被卸载，
   再回底后工作状态有时不出现。

第 4 点推翻的是“完整状态始终放在滚动内容之外”的方案，**不是**前 3 点的验收。

## 2. 当前正确目标（用户已批准，尚未实现）

采用“流内语义源 + 溢出时固定视觉副本”：

```text
业务状态 / 布局源：流内 WorkingLine，始终作为最后一个消息内容存在

未溢出：          流内行正常紧跟最后消息
已溢出 + following：流内行保留高度与唯一可访问文本；根内视觉副本固定在视口下缘
阅读 / 索引定位：   副本撤销，流内行可见；不写 scrollTop
回到底且仍溢出：    副本恢复
run 终态：          流内行与副本消失；流内 RunTrace 承接「已工作/已停止/出错」
```

### 不可违反的约束

- `following` 只决定**视觉副本**是否画，绝不能决定 WorkingLine 是否存在；
- 副本不写 `scrollTop`，唯一 pin owner 仍是 `message-scroller.tsx`；
- 短内容严格按 `viewport.scrollHeight > viewport.clientHeight` 判未溢出，不贴底；
- 流内源不可 `visibility:hidden` / `aria-hidden`：它是唯一读屏文本与布局占位；
  副本才是 `aria-hidden`、`pointer-events:none`；
- 不把 IAB 结果宣称为 Electron31 真机结论；
- 不再使用 `running && following` 装配完整 normal-flow sibling；
- 不假造 Streamdown 代码/表格逐行身份，不把工作槽改动混入下一步 Markdown 改造。

## 3. Owner 与事件顺序

```text
Host / pi：权威 run、delta、tool、terminal 事件（不改协议）
  → renderer chat store：bySession.messages + runtime.running/stopping/error
  → HomeChat.ChatMessages：活动会话、groupTurns、live/terminal phase
  → TurnGroup：live 流内 WorkingLine（唯一业务/布局/无障碍源）
  → MessageScroller：following + overflow 的边沿状态
  → 根内 portal：仅 overflow && following 时画 aria-hidden 视觉副本

用户上翻 / 触摸 / 滚动键 / 索引定位
  → release following
  → 视觉副本撤销，流内源复显；不滚动、不卸载业务状态

回到底 / 发送
  → following=true → 唯一 pin owner 贴底
  → 若真实溢出，视觉副本出现

run.completed / run.failed（同一笔 Zustand 更新）
  → runtime.running=false + terminal messages
  → 流内源/副本移除 → RunTrace 终态承接
```

`run.started` 在 renderer 有意不设置 `running`；`submit` / `continueGeneration` 已乐观置位。
不要改 Host、协议或 chat store 的业务字段来实现该视觉修复。

### 7.2 portal / overflow / 几何

- portal 目标是同一 `MessageScroller.Root`，不是 `document.body`；root 已 `relative overflow-hidden`；
- 副本 absolute、`pointer-events:none`、`aria-hidden=true`，且不进入 `role=log` Content；
- source 始终在 Content 内，保留高度和可访问文本；副本激活时 source仅视觉透明（不能
  `visibility:hidden`、`display:none`、`aria-hidden`）；
- overflow 使用真实 `viewport.scrollHeight > viewport.clientHeight`；可以维护 Provider 内
  external store，只在布尔边沿通知，不能每个 delta 触发 React 状态更新；不使用库的
  `useMessageScrollerScrollable/Visibility` 快照（受 content-visibility 干扰）；
- clone 不能每个 delta 直接按 source `getBoundingClientRect()` 复制，否则会复制小数滚动
  抖动。以 viewport bottom 为锚：进入 active 时测 source x/height 和
  `content.bottom - source.bottom` inset，再用 root-local imperatively-written位置定位；
  仅 following/overflow边沿、source/root/viewport尺寸变化、主题变化时重新计算；
- overflow 尚未满足、reading、索引定位、源被裁切、terminal、节点卸载时撤副本、源复显；
- viewport/content/root/source 的 DOM 代次变化均要取消旧 observer；2026-11-17 曾真实复现
  `message-scroller.tsx:103 viewport.getBoundingClientRect()` 读 null，当前节点 Context
  修复不可回退成可变 ref 闭包。

### 7.3 计时与可访问性

- 源行是唯一 accessible “工作中”；`Elapsed` 不添加 aria-live，避免100ms播报；
- 副本纯视觉。若 clone 自己再起一个 `Elapsed`，可能与源有数十毫秒漂移；优先抽出
  单一 elapsed 值/共享时钟，或从源同步文本。接手者应明确选择并测试；
- 副本显示时源 opacity 0 仍可能运行扫光和计时；如果 profile显示成本，再专门加
  “视觉副本激活时暂停源动画”的实现，不能借无障碍隐藏偷省；
- 当 run.completed/failed 在一笔 Zustand 更新置 `running=false` 并替换消息时，源与副本
  必须同 render 移除；终态 RunTrace 是唯一可见/可访问承接。

## 8. 自动与手动验收

### 自动回归

- `message-scroller.render.test.tsx`：
  1. `scrollHeight === clientHeight`：源可见、无 clone；
  2. `scrollHeight > clientHeight && following`：源保留空间/可访问，clone存在且 aria-hidden；
  3. wheel/touch/key/scrollbar/index 进入 reading：clone撤销、source复显、scrollTop不变；
  4. 真实到底或 `scrollToEnd`：仍溢出才恢复 clone；
  5. 阈值缩回、source裁切、root/viewport/content/source重挂、StrictMode、卸载：clone和
     ResizeObserver全部清理。
- `home-chat.render.test.tsx`：短内容源在 Content 内；live→done/stopped/failed 没有双工作状态；
  切活动会话无旧 portal。
