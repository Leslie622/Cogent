# 通知与提示音（设置 · 通知分区）

> 状态：待审批。前置调研已完成（见「对比结论」，出处均为 reference/ 实读）。

## 目标

设置页「通知」分区：**何时提醒**（三类事件的触发条件）与**怎么提醒**
（系统 toast / 提示音）正交——两个呈现开关各自独立，可只 toast、只声音、
都开或都关：

1. 轮次完成通知：Select 三档（始终 / 从不 / 仅在未聚焦时），默认**仅在未聚焦时**
2. 权限请求通知：Switch，默认开
3. 等待回答通知：Switch，默认开
4. 系统通知（toast）：Switch，默认**关**（用户定调声音为主，toast 想用再开）
5. 播放提示音：Switch，默认开
6. 系统通知设置：按钮，打开系统通知设置页

声音子系统：三类事件独立声音源（默认合成音 / 用户音频文件），全局音量与
合成基调可调，每类可试听、可恢复默认。toast 走 main 侧 Electron
Notification（zcode 式：silent、点击聚焦窗口）。

## 对比结论（reference 实读）

- **pi / deepseek-harness**：引擎侧零通知设施，只发事件（pi `agent_settled`、
  deepseek `session.query.completed`）。提醒是宿主职责。Cogent 现有事件流
  （`run.completed`/`run.failed`/`approval.request`/`question.asked`，
  挂在 pi `agent_settled` 上）即全部挂点，引擎侧不动。
- **zcode**（`packages/desktop/src/main/desktopNotifications.ts`、
  `packages/ui/src/lib/taskNotificationSound.ts`、`taskNotificationPreferences.ts`）：
  - 通知 `silent: true` + 声音由 renderer 放——系统声音与应用提示音解耦，
    声音开关归应用。本设计采纳其架构（renderer 判定 → main 弹 → 点击聚焦），
    并把「toast / 声音」拆成正交双开关（zcode 是父子绑定：通知关声音也关）。
  - 声音 = 单个打包内 mp3，`HTMLAudioElement` 单例 + 播前 `currentTime = 0`
    重置（复用实例停留在结束态会静默，:33-38）。自定义文件播放照抄此细节。
  - 聚焦判定：main 侧多窗口 `getAllWindows().some(w => !w.isDestroyed() && w.isFocused())`
    （:16-20）。我们是 renderer 直判，用 `document.hasFocus()`（单主窗口够用，
    边界见下）。
  - 三档设置 / 音量音调 / 自定义文件 / 打开系统设置按钮：zcode 均无，自行设计。
    「打开系统设置」抄其麦克风设置 URI 模式（`desktopMicrophoneAccess.ts:17-28`）：
    Win `ms-settings:notifications`、mac `x-apple.systempreferences:` URI、
    **Linux 无统一 URI 不提供**（zcode 同款决定）。
  - zcode 的 3 秒去重防事件重放——我们事件流是引擎 stdout 直转、无重放源，
    approval/question 按 requestId 天然一次，**不引入去重**。

## 设计

### 存储（settings.json，照 closeBehavior 全链路模式）

```ts
turnDoneNotify: 'always' | 'never' | 'unfocused'   // 缺省 'unfocused'
approvalNotify: boolean                            // 缺省 true
questionNotify: boolean                            // 缺省 true
toastEnabled: boolean                              // 缺省 false（声音为主）
soundEnabled: boolean                              // 缺省 true
soundVolume: number                                // 0–1，缺省 0.5
soundPitch: number                                 // 合成基频 Hz 400–1200，缺省 660
turnDoneSoundFile?: string                         // sounds/ 下文件名（三类各自独立）
approvalSoundFile?: string
questionSoundFile?: string
```

main 侧 readAll 归一 + save 校验（数值范围钳制到合法域，越界抛）；engine
store 状态/落盘/回填同 sendShortcut 模式。

### 提醒链路（条件判定 renderer 收口，toast 经 main 展示）

```
chat store events.ts
  ├ run.completed / run.failed → turnDoneNotify 判档（'unfocused' 且
  │                              document.hasFocus() = false 才提醒）
  ├ approval.request           → approvalNotify 开即提醒
  └ question.asked             → questionNotify 开即提醒
        ↓ 提醒分发（单一判定源：renderer；条件不过 = 什么都不发）
   toastEnabled ── IPC notify:toast → main：Electron Notification(silent:true)
   │                                   点击 → 恢复/聚焦主窗口（zcode :77-95）
   soundEnabled ── lib/sound.ts（播放入口收口，学 zcode :19-25）
                    自定义文件？─ 是 → HTMLAudioElement + currentTime=0 重置，
                                    src = cogent-sound://<file>（protocol，见下）
                               └ 否 → AudioContext + oscillator 合成：
                                    完成双音上行 P→P*1.25 / 权限单音 /
                                    问答双音下行，GainNode 乘 soundVolume
```

- toast 与声音**正交**：两个开关各自判定，可只开其一。
- 焦点判定单一源 = renderer `document.hasFocus()`（事件消费在 renderer）；
  toast 的「仅未聚焦」同源，避免 main/renderer 两处判焦不一致。
- 全量会话都提醒（事件不看 sessionId——后台会话更需要）。
- Electron autoplay 默认 `no-user-gesture-required`，无需手势解锁。

### 自定义文件的读取通道（dev 下 file:// 直读被 Chromium 拦）

main 注册特权协议 `cogent-sound://`（`protocol.registerSchemesAsPrivileged` +
`protocol.handle`，Electron 31 支持）映射 `~/.cogent/sounds/`：

- handler 里**只接受纯文件名**（basename 校验拒绝路径穿越），经
  `net.fetch(pathToFileURL(...))` 回流 —— dev（http://localhost）与打包同路。
- 文件选择 IPC `sound:pick-file`：`showOpenDialog` 过滤音频扩展名
  （mp3/wav/ogg/flac/m4a），**拷贝**进 sounds/（源文件删除不丢），同名覆盖；
  返回文件名。恢复默认 IPC `sound:clear-file`：删 sounds/ 文件 + 清字段。

### 系统通知设置按钮

IPC `shell:open-notification-settings`：Win `ms-settings:notifications`、
mac `x-apple.systempreferences:com.apple.Notifications-Settings.extension`；
Linux 平台 renderer 隐藏该行（无统一入口，zcode 麦克风同款决定）。

### UI（NotificationsSection，挂 SettingsMain 注册表）

```
通知组：轮次完成通知（Select）｜权限请求通知（Switch）｜等待回答通知（Switch）
提醒方式组：系统通知 toast（Switch）｜播放提示音（Switch）
           ｜系统通知设置（按钮，Linux 隐藏）
提示音组：音量（滑杆）｜音调（滑杆，自定义文件时该行仍显示——仅合成音生效）
        ｜三类各一行：声音源显示（默认合成 / 文件名）+ 选择文件 + 试听 + 恢复默认
```

## 边界（真实的墙）

- **音调对自定义文件无效**：playbackRate 变调破坏音质，不做；文件声音只受
  音量控制。
- **控制台窗口聚焦的误提醒**：主窗口失焦但控制台窗口聚焦时，主 renderer
  `document.hasFocus()` = false 会提醒 —— 低频场景首版接受，后续可加 main
  焦点查询对齐 zcode 多窗口语义。
- **toast 依赖系统通知服务**：`Notification.isSupported()` 不支持（无桌面
  通知服务的 Linux headless）时静默跳过 toast，声音不受影响。
- **去重不做**：事件流无重放源（stdin 直转、无持久化重播）。
- Linux 无系统设置跳转（隐藏按钮，非报错）。

## 验收

- 三行触发条件正确：三档/开关只在对应条件触发；改设置即时生效
- toast 与声音正交：只开其一时另一路不动作；toast 点击聚焦回主窗口
- 音量/音调调节立即反映在合成音；试听按钮按当前配置播一次
- 自定义文件三类独立生效；选文件-试听-恢复默认闭环；重启后仍在
- Windows 点「系统通知设置」打开系统通知页；Linux 无此行
- typecheck / lint 绿；动到的 `*.test.ts` 跑过；store 回填逻辑钉单测
