## 1. 目标与动机

- 用户诉求：主流产品（zcode 截图实证：插件管理页 + 市场）都有插件；
  Cogent 能力机制已通（四座）但没有"装一个包"的体验；
- 现状差距精确化：**机制层全通、分发层为零** —— 技能要手放目录、MCP 要手写
  mcp.json，没有"包"的概念（一个包 = 技能 + MCP server 的组合分发单位）、
  没有启停管理面、没有版本概念；
- 附带修正一个既有事实：pi 原生扩展发现面（`~/.cogent/pi/extensions/` +
  项目 `.pi/extensions/` 自动发现，§2.2）**已在 Cogent 会话内活着**（factory
  用原生 SettingsManager + DefaultResourceLoader，只关了技能面）—— 本批
  把它写进事实文档明示，不改动其行为（代码扩展属 pi 高阶面，非本批内容物）。

## 3. 设计

### 3.1 插件包格式（manifest 目录约定）

```
<插件根>/
  .cogent-plugin/plugin.json    # manifest（首选路径，见下方三路径回退）
  skills/                       # 内容物①：技能目录（可被 manifest skills 字段改指）
  .mcp.json                     # 内容物②：MCP server 定义（或 manifest mcpServers 字段）
```

manifest 解析**三路径回退**：`.cogent-plugin/` → `.claude-plugin/` →
`.codex-plugin/`（zcode 同款回退链，index.ts:116-118）—— **评审并入项**
（硬规则 9，2026-11-16 业界横向后并入，§2.5）：Claude Code / Codex 生态
的现成插件零转换直接可装（格式同源），其 skills + mcpServers 照常装载，
commands/hooks/agents/ui 走"仅诊断不执行"（§4.4 同款）—— 成本 ≈ 两次
路径判断，收益 = 接入两个现成插件生态。

manifest 首发字段集（zcode 同款薄校验）：`name`（必填，`^[a-z0-9][a-z0-9._-]{0,127}$`）、
`version`（缺省 "0.0.0"，任意字符串）、`description`/`author`/`license`（展示用）、
`skills`（string|string[]，缺省补 `<根>/skills`）、`mcpServers`
（object|string|string[]，缺省补 `<根>/.mcp.json`）。
**预留不解析**（遇到打 warning 不执行，zcode "仅诊断"先例）：`agents`/
`ui`/`extensions`/`commands`/`hooks`/`dependencies`。

### 3.2 存储布局与安装/卸载（zcode 布局的 Cogent 域版）

```
~/.cogent/plugins/
  installed.json            # 安装记录 = authority 文件（tmp+rename 原子写，approvals.json 同款）
                            # 条目：{name, version, installPath, installedAt, source, enabled}
  cache/<name>/<version>/   # 插件本体（多版本保留；installed.json 指向生效版本）
  data/<name>/              # 插件数据目录（env COGENT_PLUGIN_DATA 注入目标）
```

- id = `name`（zcode 是 `name@marketplace` 为跨市场唯一；Cogent 单域无市场
  分层，name 即 id —— 接远程市场时再加 scope，§4.1）；
- **安装**（`plugin.install(source)`，source = 本地目录或 zip 文件路径）：
  解析 manifest（zip 先过解压管线：路径穿越拒绝、解压上限、拒 symlink ——
  zcode zip-source 精简版）→ 复制/解压到 `cache/<name>/.staging-<version>/`
  → 校验 staging 内 manifest 可解析 → rename 为 `<version>/` → 写
  installed.json（enabled 缺省 true，zcode :868-871 同款）。失败 =
  删 staging，installed.json 不动（无半装状态）；
- **卸载**：删记录 + 缓存目录 rename 到 `.tmp-` 前缀后删 + data 一并删
  （首发不留数据，文档明示；zcode keepData 同位功能挂需求）；
- **更新**：同 name 装新 version = 新缓存目录 + 记录指新版，旧版留缓存
  （无远程源，无自动更新判定 —— 更新就是再装一次）。

### 3.3 启停与作用域（两级，zcode 合并语义 + Cogent MCP 座同构）

- **用户级**：installed.json 每插件 `enabled`（缺省 true）；
- **项目级 override**：`<cwd>/.cogent/plugins.json` 的
  `{enabledById: Record<name,boolean>, dirs?: string[]}` —— **只覆盖显式
  写过的 id**（zcode config-merger 按键浅合并同款）；`dirs` = 项目直接
  引用本地插件目录（免安装即用，开发调试位，zcode config.plugins.dirs
  同款 defaultEnabled=true）；
- 作用域管理面两档：用户 / 当前项目（Cogent 单设备，zcode "设备×作用域"
  的设备维退化）。

### 3.4 内容物装载（快照合并缝，零新运行时）

```
owner: 插件域状态 = runtime/plugin-store.ts（新文件：manifest 解析/安装/
       卸载/启停/发现合并 —— installed.json + 项目 plugins.json + dirs 三源）
owner: 技能发现 = skill-store.ts（不变，新增第三类源输入）
owner: MCP 合并 = mcp-config.ts（不变，snapshot 新增插件源叠加）
owner: 会话装配快照 = session.ts 装配线（不变，两座快照各取一次）

装配期（每会话，快照语义与两座现状一致）:
  PluginStore.enabled(cwd) ──► [插件根列表]
      ├─► SkillStore：插件 skills 根追加发现源末位（用户 .cogent >
      │   .agents 两级 > 项目 > 插件垫底，zcode priority 1000+ 同义）；
      │   插件技能限定名 `<plugin>:<skill>`（同名冲突非插件源胜）
      └─► McpConfigStore.snapshot：插件 server 以 `plugin__<plugin>__<server>`
          注册名叠入（env 注入 COGENT_PLUGIN_ROOT/COGENT_PLUGIN_DATA/
          COGENT_PROJECT_DIR + COGENT_PLUGIN_ID 权威覆写）；
          合并序 {...插件, ...用户} —— 用户 mcp.json 同名覆盖插件
运行期: 启停/安装即时写配置；生效 = 下一会话装配（两座现状同款），
        plugin.list 活算即时反映（SkillStore snapshot 无缓存同义）
```

- MCP 注册名用 `plugin__` 下划线连接（非 zcode 的 `:`）—— pi mcpNamespace
  对 `-/_` 归一化查重、Cogent 工具名 `mcp__<server>__<tool>` 链下纯下划线
  无歧义；插件 server 同样可被项目 override（enabled/exposure，键 =
  `plugin__...` 注册名，复用现有 override 机制）；
- 插件 MCP 工具照走 pi 工具管线 → 链式包裹审批照生效（4a 已论证，零新增）。

### 3.5 协议与管理面

- 协议方法（additive，PROTOCOL_VERSION 不动 —— 审批对/inspect kind 前例）：
  `plugin.list`（带 cwd = 合并视图：已装 + dirs 引用 + 组件摘要 + 生效启停 +
  来源；带 marketDir 参数 = 本地市场目录扫描，列出未装插件供选择）、
  `plugin.install(source)`、`plugin.uninstall(name)`、
  `plugin.setEnabled(name, enabled, scope)`；
- 观测：`plugin.installed` / `plugin.uninstalled` / `plugin.enabled` /
  `plugin.disabled` 四 kind 进 inspect 流（inspector 一个 record 调用级成本，
  审计对"放行也留痕"同纪律）；
- UI（设置页新分区"插件"，Cogent 视觉体系）：已安装列表（名称/版本/描述/
  来源/开关，图标 = 名称首字母占位）+ 作用域档（用户/当前项目）+ "添加"
  （Electron 目录/zip 选择器）+ 本地市场目录路径输入 → 未装插件列表 + 安装钮。
  对标 zcode 管理页的信息结构，不做市场三源分段（无云端，§4.1）。

### 3.6 安全与信任模型（明示）

- **本地信任**：用户主动安装本地包 ≡ 手写 mcp.json stdio 命令（任意进程
  执行），不引入新信任边界；zcode 三方插件 hooks 默认放行同款立场
  （index.ts:438-443）；
- **完整性**：无签名服务（zcode 也没有 —— 信任根 = 来源本身）；zip 过
  解压防护管线；manifest 薄校验坏包跳过不炸；
- 技能根不跟 symlink（SkillStore realPath 去重已有）+ 插件 MCP env 不含
  任何 Cogent 凭据（只注入路径与 id）。

## 4. 边界 / 首发不做（逐条真实墙）

1. **云端市场 / 远程 URL 安装** —— 无 registry 服务端；本地 directory/zip
   已覆盖"装一个包"全场景，URL 型只省下载步骤却引入完整网络下载安全面
   （哈希 pin/重定向/下载限），收益 ≪ 成本。接云端时一次开工（届时 id 加
   scope 维度对齐 zcode `name@marketplace`）；
2. **agents 内容物** —— subagent 子会话座未落地（阶段 5 待做项），装载了
   也没有消费者；subagent 座落地后开启该字段；
3. **ui surfaces 内容物** —— webview 面板座（阶段 3）是 Host 内置三面板，
   无第三方面板消费者；有真实需求时参照 Pi-meme 授权模型一次开工；
4. **commands/hooks 内容物** —— Cogent 无 slash 命令体系与进程级 hook
   配置，宿主内干预全走 pi 扩展（决定 27）；manifest 预留字段仅诊断不执行
   （zcode channels/lspServers 同款先例）；
5. **代码扩展（pi extensions）接线** —— pi 原生发现已在会话内活着（§2.2），
   但 DefaultResourceLoader 的 `additionalExtensionPaths` 语义（temporary
   源/peerDependencies 告警面）未验证，且本批无代码插件消费者场景；
   manifest 预留 `extensions` 字段，接线挂后续批（验证成本 > 首发收益）；
6. **插件 secrets / userConfig 敏感选项体系** —— zcode 有 plugin-secrets +
   sensitive sink（mcp.ts:402-463），Cogent 无消费者，不建；
7. **依赖闭包（dependencies）** —— 无市场生态，本地包自包含；预留字段。
