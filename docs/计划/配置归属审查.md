# 配置归属审查：Host 与客户端职责

本文记录源码审查与隔离探针结果，尚未实施迁移。范围：桌面 settings、renderer
持久状态、Host 域配置及启动注入；判断业务默认策略与初始化职责是否完整归位。
用户没有提出开发 CLI 的需求。无界面 Host 是检查架构边界的探针，不能据此新增
CLI 开发任务；下述问题即使只维护桌面客户端也成立。
标题功能本身的方案见[会话自动标题](会话自动标题.md)。
修复设计与待审批范围见[配置归属与启动同步修复](配置归属与启动同步修复.md)。

## 1. 已确认的归属问题

### 全局默认权限只由桌面补参

`src/shared/ipc.ts:165–167` 将 defaultPermissionMode 定义为新会话默认权限；
`src/renderer/src/stores/engine.ts:332–334` 保存到壳 settings.json。
`src/renderer/src/stores/chat/store.ts:167–185` 创建会话时解析：显式参数 >
草稿选择 > 项目默认 > 桌面全局默认，并把结果作为 permissionMode 传给 Host。

Host 的 `src/host/runtime/session.ts:721–737` 只解析显式参数与项目默认，
没有共享全局默认；最终审批在同文件 `1458` 行把缺省当 ask。
因此无项目默认时，桌面设 auto，其他客户端省略 permissionMode 仍是 ask。
项目默认权限已经由 Host 持久化，这个问题只涉及全局链尾。

建议：全局默认权限归 Host；客户端保留显式覆盖能力，Host 统一执行
“显式会话选择 > 项目默认 > 全局默认 > ask”。MCP 出口主动开启计划模式的
策略独立处理，不能因默认值共享而撤掉其现有入口约束。

### 通用供应商与模型覆盖定义依赖 renderer 初始化

非机密定义保存在 main 的 `src/electron/main/custom-providers/store.ts:25–70`。
运行态注册由 Host 的 `src/host/runtime/custom-providers.ts:114–118、147–173`
处理，但构造不读取这份文件。

当前启动链是：

```text
owner: main = 定义文件；renderer = 启动重推；Host = 内存模型目录与请求路由
renderer engine.load -> 读 main 定义 -> custom-providers:set
    -> main 写盘 -> providers.custom.sync -> Host 注册
```

对应 `src/renderer/src/stores/engine.ts:244–282` 和
`src/electron/main/ipc/custom-providers.ts:57–85`。Host 握手只注入凭据，
没有注入供应商定义（`src/electron/main/host/manager.ts:152–157`）。

影响包括自定义 provider、内置 provider 的 baseUrl 覆盖、自建模型、模型禁用
和能力参数覆盖。CLI 连接已完成桌面初始化的同一 Host 可以使用内存配置；
CLI 单独拉起 Host 则不会自动消费磁盘定义。启动早期其他客户端也存在定义
尚未同步的窗口；此窗口是顺序分析结论，未做并发时序实测。

必须修正的是初始化依赖 renderer、引擎就绪与配置加载完成脱节。可由 Host 自行
恢复定义，也可由明确的宿主启动契约完整注入；不以文件放在 main 就判定错误。
具体迁移路线另行设计，保持单写者，并把“加载完成”纳入可用状态。

### 凭据在 Host 启动期间变更会漏同步

这是启动同步缺陷，不是安全存储应搬进 Host 的证据。
`src/electron/main/index.ts:151–159` 在创建 HostManager 时读取凭据快照，
`src/electron/main/host/manager.ts:152–157` 将该快照用于握手。
而 `src/electron/main/ipc/credentials.ts:23–27、36–39` 先保存/删除桌面凭据，
只在状态为 running 时推送 Host；starting 不推送，也没有握手后的补偿。

```text
owner: main CredentialStore = 持久凭据；HostManager = 握手快照；Host = 生效内存表
取启动快照 -> Host starting -> 用户保存/删除凭据（存储已变，未推送）
             -> 握手消费旧快照 -> running（生效值仍旧，无补偿）
```

主窗口与 Host 启动并行（main/index.ts:172–185），App.tsx 无条件挂 AppShell，
凭据 IPC 本身允许 starting 阶段保存。受控探针复现：新增 key 在桌面存储桩中
存在，启动后的 Host 中不存在；删除 key 在存储桩中消失，Host 仍持有旧快照。
进入 running 后执行同样操作，两端恢复一致。

探针执行实际 credentials IPC 源码并连接实际 Host 构建产物；Electron 注册器和
安全存储用桩替代。此证据验证同步分支，未验证系统钥匙串或真实界面点击时序。
修复需覆盖启动交接期间的变更顺序，不能仅把条件改为 running 后继续忽略竞态。

## 2. 默认模型与思考力度：需要拆清两种含义

`src/shared/ipc.ts:161–164` 的 activeModelId/activeProviderId/thinkingLevel
由桌面保存。`src/renderer/src/features/home/HomeChat.tsx:365–415` 读取并随
每次提交下发，`src/renderer/src/stores/engine.ts:311–330` 更新上次选择。

Host 报告的默认模型来自 `src/host/runtime/session.ts:506–507、883–885`，
固定为 anthropic/claude-sonnet-4-5；工厂同样优先指定这个模型与 off
（`src/host/kernel/pi-session-factory.ts:259–268`）。提交未指定思考档时，
`src/host/runtime/session.ts:1047–1051` 不读取桌面偏好。

已确认：独立 Host 不继承桌面的模型/思考选择。不能进一步断言“每次省略参数
都重置默认”：已经装配的会话仍有自己的运行态，恢复还涉及 pi 的会话语义。

客户端记住“上次选了什么”本身合理；若产品要求跨入口共用用户默认值，当前
缺少 Host 默认模型和默认思考配置。这属于待明确的产品语义，尚不能列为已确认
架构缺陷。若需要共享默认，应将其与客户端当前选择分开；当前选择仍是显式
会话/提交覆盖，不应隐式改变全局策略。

## 5. 运行证据与后续范围

运行 `node tmp/config-ownership-audit.mjs`：使用自带 Node、当前 out/main/host.js、
临时 COGENT_HOME 和合成配置，不启动 renderer、不注入真实凭据、不发模型请求。
本轮使用的 Host 构建产物晚于被审查 Host 源文件的修改时间；这只做新鲜度辅助核对。

探针观察到：

- settings.json 写 auto，session.create 的有效权限与持久化摘要仍为 ask。
- settings.json 指向 custom/config-audit 的 audit-model，models.list 仍报告
  anthropic/claude-sonnet-4-5 为默认模型。
- 磁盘存在自定义 provider，启动后目录中没有；显式 providers.custom.sync 后出现。
- 磁盘把 claude-sonnet-4-5 标为禁用，启动后仍列出；显式同步后移除。
- 实际凭据 IPC 在 starting 时完成存储桩变更却不推送；握手后 Host 的新增/删除
  状态落后。running 时的同样变更能正确同步。

这些结果证明当前消费链路，不等于完整 CLI、真实模型请求或迁移方案已验收。
没有修改 src/ 或 tests/，没有运行全量四关；本轮不声称既有测试已验证上述场景。

建议先处理凭据启动同步、供应商定义加载与全局默认权限；模型/思考的共享默认语义需要时再明确。
不新增 CLI、凭据存储或 MCP 启动改造任务。迁移会涉及跨进程配置所有权与旧文件兼容，
应单独设计和审批，不能把本审查稿当成已经批准的实现方案。

| 字段 | 归属判断 |
| --- | --- |
| version | 文件版本元数据 |
