## 一、现状与缺口

| 现有资产 | 实质 | 缺口 |
| --- | --- | --- |
| tmp/cogent-smoke/ 四脚本（tools 14 / compaction 29 / approval-upgrade 17 / ps-utf8 6 断言） | 黑盒集成测试：mock SSE + 真构建产物 `out/main/service.js` + 协议断言，临时 COGENT_HOME 隔离 | 不入库（tmp 被 gitignore，靠 开发.md 配方重建）、无自动化、换机器即失传 |
| 三关（lint / typecheck / build） | 静态质量门 | 无运行时行为验证 |

参照系：三家上游 **全部 Vitest** —— pi（`test/*.test.ts` + `e2e.test.ts`，
`vitest --run`）、deepseek-harness（+ @vitest/coverage-v8）、zcode。选型无悬念。

## 二、决策

**D1 框架 = Vitest（5.x）**。否决 Jest（Vite 生态外，transform 配置负担）、
node:test（无 project 分环境 / 无 RTL 生态 / 报告体验差）。配套：jsdom（web
环境）、@testing-library/react + jest-dom（组件断言）、@vitest/coverage-v8
（覆盖率观察）。

**D2 不做 E2E**（用户定调 2026-11-12）。Playwright Electron 不引入；GUI 黄金
路径维持人工验收，呈现层回归由组件测试兜底。记入远期池，非本计划范围。

**D3 布局：单元/组件与源码同目录 `*.test.ts(x)`（co-located），集成放
`tests/integration/`**。co-located 就近维护（pi coding-agent 同思路）；集成
测试拉构建产物、不属于任何源文件，独立成目录。否决全集中 tests/（单测离
被测代码太远，改代码找不到测试）。

**D4 单配置三 project**（`vitest.config.ts` 内联 projects，Vitest 5 形态）：

| project | 环境 | 范围 | 特殊处理 |
| --- | --- | --- | --- |
| `node` | node | src/agent-service、src/shared 单元 | — |
| `web` | jsdom | src/renderer 单元 + 组件 | setupFiles 挂 jest-dom |
| `integration` | node | tests/integration | `fileParallelism: false`（各文件起 mock SSE + 引擎子进程，端口固定 18940–18942，串行不撞）；testTimeout 放宽（compaction 全流程分钟级） |

**D5 集成跑构建产物**（沿现冒烟口径 —— 测的是打包后真协议路径）：globalSetup
检查 `out/main/service.js`，缺失或比 src 旧则自动 `npm run build`；效果 =
`npm test` 一条命令即全绿，无需记得先 build。

**D6 冒烟迁移 = 断言原样、载体换 Vitest**：四脚本 → 四个 test 文件，98 项
断言一条不丢、场景流编号保留（S1–S16 注释随行）；tmp/cogent-smoke 退役删除，
开发.md 冒烟配方节改指 tests/integration 为真源。临时 COGENT_HOME 隔离
（USERPROFILE/HOME 同步覆写）手法照搬。

**D7 可测性最小改动**：只为测试**导出**已存在的逻辑，不重构生产行为 ——
`unwrapIpcError`、`flattenSegments` / `flatWithApprovals` /
`flatWithCompaction` 加 export；`toChatMessages` 从 session 类私有方法提为
模块级导出函数（已核实不读实例状态，纯函数被类壳困住）。store 行为测试经
window.cogent 可编程 stub + `bindEngineEvents` 驱动**真实接线**，不测复制品。

**D8 覆盖率不设门槛**：装 coverage-v8 供 `npm run coverage` 观察；补测原则 =
「翻过车的 bug 必钉回归测试」，不追数字（学习项目追覆盖率是噪音）。

**D9 CI = GitHub Actions windows-latest 单 job**：npm ci → lint → typecheck
→ build → test（远端 Leslie622/Cogent 已在）。选 Windows：ps-utf8 集成绑
PowerShell 行为，Electron 构建也是本机平台；Electron 二进制与 npm 缓存走
actions/cache。上线后「全绿」从本机口头约定升级为流水事实。

## 三、步骤（一次落地，无批次）

**S1 地基**：devDeps 装机（vitest / coverage-v8 / jsdom / RTL 三件）；
vitest.config.ts + web setup 文件；tsconfig.node.json include 增 `tests/**/*`
与 `vitest.config.ts`（eslint projectService 自动认领）；npm scripts：
`test`（全量）/ `test:watch`（watch，日常只跑 node+web 两 project）/ `coverage`。
eslint 不豁免测试文件 —— 同受 no-floating-promises 等纪律约束。

**S2 单元·引擎层**（node project）：
- `src/agent-service/runtime/compaction.test.ts`：
  - `compactionThreshold`：缺省 90%、override、余量线前移（20000 窗 → 11808
    案例，完备化 S1 验收的公式钉子）；`shouldCompact` 边界；
  - `convertToLlmMessages`：无 bar 原引用直通；有 bar = [system 全局原序] +
    [bar→user 前后缀] + [活区]；影子区与旧 bar 不进请求；
  - `pruneToolResults`：8192 线内不动、超线头 4096 + marker + 尾 1024、
    活区边界（bar 之前不裁）；
  - `findCutPoint` / `prepareCompaction`：keepRecent 落点、D9 时间戳守卫
    （刚压完无新回合 → undefined）；
  - `insertCompactionMarker`：原位 splice 保数组引用（S2 400 bug 回归钉）；
  - `formatFileOperations`、`buildSummarizationInstruction`（含
    \<previous-summary\> 迭代形态）、`summarizationFailure` /
    `summarizationThinkingLevel`。
- `toChatMessages` 提出后单测：bar 时间序落点与延迟 flush（D9 GUI 验收的
  引擎侧回归钉）。

**S3 单元·渲染层**（web project，纯逻辑）：
- `groupTurns`：user 开组、compaction 截断当前组 + 独立成组、后续 headless
  续组 startedAt 继承；
- flat 管道三函数：时间戳合并、approval 右邻配对、tool endedAt 优先；
- `unwrapIpcError`：IPC 前缀剥离（带 / 不带 `Error:` 两形态）。

**S4 组件·TurnGroup**（web project，RTL）：mock MessageRow /
MessageScrollerItem 隔离 markdown 渲染，聚焦 TurnGroup 自身 —— 压缩条独立组
落位、零内容 done 组只渲染用户气泡（双已工作回归）、live 组 WorkingLine、
已工作秒数格式。

**S5 store 行为 + 集成迁移**：
- `chat-store` 测试（web）：window.cogent stub → `bindEngineEvents` 派发伪
  事件序列 —— `compaction.pruned` standalone 行、`compaction.completed`
  时间序落点 + standalone 撤销 + pruned 跟随、`run.completed` keptCompaction
  保留合并（D9 替换区不吞 pruned/bar 回归）、submit 报错消息去前缀；
- 集成四文件迁移：tools / compaction / approval-upgrade / ps-utf8
  （`describe.skipIf(process.platform !== 'win32')`）—— 断言与场景流原样。

**S6 CI + 文档收尾**：`.github/workflows/ci.yml`；`docs/技术笔记/测试体系.md`
（三层取舍 + pi / dsh / zcode 布局对照 + 冒烟→集成正名史 + 为何不做 E2E）；
开发.md 命令表加 test 系列、冒烟节改写真源指向；约定.md §1.3 产出义务增一行
「新逻辑模块须带单测，翻过车的 bug 必钉回归测试」；AGENTS.md 地图行、
技术笔记 README 索引、路线.md 已实现清单回填。

## 五、风险与边界

- vitest 自带 vite 内核，与项目 vite 8 无版本耦合（装机后先跑空测试即验）；
- jsdom 渲染 streamdown 重：组件测试 mock MessageRow 隔离，保持秒级；
- 集成分钟级时长：串行 + timeout 放宽；不进 watch 日常循环（`test:watch`
  只跑 node + web）；
- Windows CI 分钟消耗 2×：学习项目可接受，慢了再拆 ubuntu job 跑非 Windows
  子集（远期）；
- 否决项：E2E（D2）、覆盖率阈值（D8）、UI 快照测试（脆断言，维护成本大于
  收益）、为覆盖率而做的 mock 堆砌（测的是复制品不是代码）。
