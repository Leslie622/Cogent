# 计划模式正交开关

> 交互座 4c-3 的修订：plan 从 PermissionMode 第四档改为独立开关，与权限档正交。
> 2026-11-16 用户拍板采用。状态：**已实施完成**（同日落地，PROTOCOL_VERSION 3，
> 四关全绿；现状见 [../模块/交互座.md](../模块/交互座.md) 与
> [../模块/审批与权限.md](../模块/审批与权限.md)）。原文档存档如下，不再回改。

## 目标与动机

现状把 plan 做成 `PermissionMode` 四档之一（`'auto' | 'ask' | 'plan' | 'autonomous'`，
`src/protocol/types.ts:286`），产生三个补丁味：

1. **原档丢失**：enter_plan 覆盖档位（`session.ts:1428` 直调 setPermission('plan')），
   用户设的档被模型动作改写；
2. **裁决面板被迫带切档下拉**：PlanPanel「批准，并切换为 ▾」——批准的本质是
   退出计划，切档是找回被覆盖档位的补丁；
3. **UI 不联动 bug**：`setPermission`（`session.ts:1175`）只记账+落盘，引擎内
   改档（enter_plan 路径）无北向事件，renderer 权限钮不更新（2026-11-16 手测
   IN-20 实录：模型调了 enter_plan、引擎拦了 powershell，权限钮纹丝不动）。

正交开关：**权限档回答「写东西要不要问」，计划开关回答「现在只读吗」**——
两个正交问题互不覆盖。

## 三仓对照结论（动工依据，AGENTS.md 规则 7）

| 实现 | 形态 | 出处 |
| --- | --- | --- |
| zcode | 正交开关：`planEnabled` bool 独立字段，与 mode 并列；planEnabled 短路一切档位放行 | `reference/zcode/apps/zcode-cli/packages/core/src/permission/plan-mode-policy.ts:7-12`；短路判定 `permission/service.ts:148`；只读拦截 `service.ts:515` |
| deepseek-harness | 正交开关：chip 二态钮（aria「Plan mode on, press to turn off」），`/plan` 直切不经模型；与权限零耦合 | `packages/client/ui-plan/src/client/PlanModeControl.tsx:56`；`apps/web/tests/plan-control-row.e2e.ts:31` |
| pi | 正交开关（扩展示例）：`planModeEnabled` bool，`/plan` toggle；pi 无权限档体系 | `packages/coding-agent/examples/extensions/plan-mode/index.ts:53,130` |
| Claude Code（背景参照） | 互斥四档——根因是 CLI 键盘流 shift+tab 单值循环；Cogent 是 GUI 无此约束 | — |

**transition 语义**（zcode 运行时，`runtime/session-mode-port.ts:11-34`）：
enter/exit 只翻 `planEnabled`，**mode 全程不动**；`getPrePlanMode: () => undefined`
——prePlanMode 只在类型/审批透传层存在（`permission-flow.ts:123` 透传给判定
上下文），运行时不维护。Cogent 全正交后 permissionMode 永不被 plan 触碰，
「回原档」自动发生，**不引入 prePlanMode**——与 zcode 运行时行为一致。

**exit 工具的形态铁律**：zcode `ExitPlanMode(plan)` `needsApproval: true`
（`tool/handlers/plan-mode.ts:60-104,179`）、dsh `exit_plan_mode(plan)`
（`packages/client/ui-plan/src/client/plan.ts:36-46`）、Claude Code ExitPlanMode
——三家的「退出」全是**带 plan 参数 + 强制用户审批的合体工具**（= Cogent 的
submit_plan），没有任何一家提供模型免审自退：enter（收紧为只读）免审合理，
exit（解锁写能力）必须过用户——免审自退 = 模型自己给自己解锁，违背 plan
模式用户守门的初衷。Cogent 保持 submit_plan 单出口，不加免审 exit_plan。

## 设计

### D1 协议（`src/protocol/types.ts`，PROTOCOL_VERSION 2 → 3）

- `PermissionMode` 删 `'plan'` → `'auto' | 'ask' | 'autonomous'`；
- `SessionSummary` 增两 optional 字段（旧盘兼容，缺省 = 关）：

  ```ts
  /** 计划模式开关（正交于权限档）：true = 只读约束生效 + submit_plan 可用 */
  planEnabled?: boolean
  ```

- `PlanRespondParams` 删 `switchMode`（批准不再切档）；
- `session.create` params 增 `planEnabled?: boolean`（new 态暂存位的物化通道，
  与 permissionMode 同款 optional）；
- 新增事件 `session.summaryChanged: { summary: SessionSummary }`（additive）：
  会话摘要任何引擎侧变化（档位/计划开关）即推——顺带修 UI 不联动（现状
  RPC 返回值更新只覆盖用户主动路径，引擎内 enter_plan 路径无通道）。

### D2 引擎（`src/host/runtime/session.ts`）

- `setPermission`：记账+落盘后发 `session.summaryChanged`；plan 开启中用户切档
  照常允许（planEnabled 不动——开关与档位互不干扰，这是正交的全部含义）；
- 新 `setPlanMode(sessionId, enabled)`（手动 toggle 的 RPC 后端）+ 同款事件；
- `decideApproval`（D4 判定矩阵）：**planEnabled 短路优先**——为 true 时
  写/exec 类直接拒（理由文案同现状），read 类照常；档位判定在其后（zcode
  `service.ts:148` 同序）；
- `permissionSectionText` 拆两段：`cogent_permission`（三档文案，plan 分支删）
  + `cogent_plan_active`（开关开启时注入：只读约束 + 调研→submit_plan 工作流；
  关闭即撤段）。两段职责不同，不合并；
- `respondPlan`：批准 → `planEnabled = false` + plan 落账 + 事件；拒绝 → 开关
  保持开（修订重提的语义前提），无附言 terminate 语义不变；
- enter_plan 桥（`buildPiSession`）：改调 setPlanMode(sessionId, true)（内部
  方法直调，事件照发）；
- submit_plan 判定源：`currentMode() !== 'plan'` 改读 `planEnabled !== true`；
- 盘上恢复（`asStoredSession` 收窄层）：v2 盘 `permissionMode === 'plan'` 的
  会话迁移为 `permissionMode = 'ask'`（原档已被覆盖、无从恢复，回缺省）+
  `planEnabled = true`；v2 文档格式不跃迁（summary 内字段级兼容）。

### D3 工具（`src/host/runtime/interact-tools.ts`）

- `enter_plan`：文案改「开启计划模式（只读）：文件写入与命令执行会被拒绝…
  权限档保持不变，退出计划后继续生效」。对照 zcode enter 工具结果文案
  （`plan-mode.ts:261-274` 六步工作流指引）保持 Cogent 现有精简度不堆长；
- **不加免审 exit_plan**（对照结论见上：三家 exit 全是审批合体，Cogent 的
  submit_plan 已是同位物）。模型想放弃计划 = 直接继续对话（只读约束开着
  无害）；用户手动关开关走 UI 计划钮；
- `submit_plan` 批准回执：删切档告知，改「计划已批准。已退出计划模式，当前
  权限档不变——现在开始执行…」（zcode `formatExitPlanModeModelContent`
  同款语义，`plan-mode.ts:276-287`）；拒绝三路语义不变。
- enter_plan / submit_plan 全 read 档（tool-meta 不变，任何档位免审批直行）。

### D4 UI（renderer）

- **计划开关双入口**（2026-11-16 用户定调「都做，状态同步」）——两处消费
  同一数据源（summary.planEnabled，session.summaryChanged 推送）、调同一
  动作（session.setPlanMode），同步是数据流的自然结果而非额外逻辑：
  1. **菜单内开关项**（`PermissionMenu.tsx`）：计划模式项保留但语义改
     toggle（勾选 = 开关开启，不再是四档单选）；**置顶菜单**，其下分割线
     隔开三个权限档——分割线从现状「完全访问上面」（危险组隔离）挪到
     「计划模式下面」（开关与档位两组交互语义的隔离）；完全访问的
     warning 琥珀变体保留（颜色警示与线分家）；
  2. **外置计划 chip**（新组件 `PlanToggle.tsx`，zcode「💡 计划」chip 同位）：
     权限钮右侧同工具行，Button ghost size xs，图标沿用 IconClipboardList；
     开启态 chrome-accent 蓝高亮（与自主模式同族），关闭态灰——具体视觉按
     UI布局.md 配方微调；aria-pressed 表达开关态；开启态 tooltip「只读模式：
     写入与命令被拒绝」；
  - new 态暂存 home store（与权限暂存同链），物化时经 session.create 带上
    （planEnabled 进 session.create params）；
- `PlanPanel.tsx`：删 SWITCH_MODES 下拉与相关状态；批准项 label「批准」，
  desc「退出计划模式，按当前权限档开始执行」；键盘/附言模型不动；
- 联动消费：chat store 监听 `session.summaryChanged`，按 summary.id 替换
  sessions 列表项（与 setPermission 返回值更新同一形状）。

### owner + 事件顺序（会话状态硬规则 5）

```
真源：host 侧 SessionManager 的 session.summary
  （permissionMode: 三档 | planEnabled: bool —— 两字段独立，任何路径不互相覆盖）

模型路径：
  enter_plan → setPlanMode(true) → persist → session.summaryChanged → renderer 钮亮
  （plan 开启中的工具判定）
  decideApproval → planEnabled ? 拦写/exec : 按档判定（read 类两路都放行）
  submit_plan → plan.requested → PlanPanel 挂起
    批准     → planEnabled=false + plan 落账 → summaryChanged → resolve(approved)
               → 模型按原档执行（ask 档写文件 → approval.request，跨模块联动不变）
    拒绝附言 → 开关保持开 → resolve(denied+msg) → 修订重提（新 plan.requested）
    拒绝裸点 → 同上 + terminate（停轮语义不变）

用户路径：
  权限菜单   → session.setPermission → 记账+persist+summaryChanged（planEnabled 不动）
  计划钮     → session.setPlanMode  → 同上（permissionMode 不动）
  run 进行中任一切换 → 下一轮判定/通告段即读新值（活引用语义，现状不变）
```

## 边界 / 首发不做

- **不做计划模式下的档位遮蔽**：plan 开启 + 完全访问 = 只读（短路优先），
  菜单里完全访问仍可选可显示——状态如实呈现，不灰不锁（zcode 同款）；
- 不做 plan 开启的会话列表角标/侧栏标记（摘要字段有了，UI 呈现后续按需）；
- 不做旧盘 plan 档的原档恢复（已被覆盖，无从考据，回 ask 缺省——手测期数据，
  损失可忽略）；
- 不做批准时 `allowedPrompts` 预授权清单（zcode ExitPlanModeInput 有此通道，
  批准时顺带申请命令白名单——独立特性，收益待评估，首发不进）；
- 不做批准计划写工作区文件（zcode `writeApprovedPlanFile` 计划连续性机制；
  Cogent 用 StoredSession.plan + cogent_plan 段已覆盖记忆面）；
- dsh 的「/plan 直切不经模型」斜杠命令通道不在本期（斜杠命令属技能座范畴）。
