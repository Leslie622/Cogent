# 动效与渲染性能收尾

> 对话流畅性剩余清单第 3 项（交接 §22）。调研范围经用户裁决：**zcode 对照 +
> 真机 profile**（2026-11-18）。本文为目标 / 对比结论 / 测量设计 / 边界 / 验收，
> **用户审批通过后才动手**。本批的特殊性：判据是测量证据——先测，热点处理
> 方案由数据决定，本文不预设「要虚拟化」也不预设「不动」。

## 1. 目标

给流畅性专项补性能收口证据，回答四个问题（交接判据原文的场景分解）：

1. **长历史**：几百回合会话下，切会话、滚动、展开折叠的开销是否可感？
   是否需要虚拟化（zcode 的结构性答案）或更便宜的 content-visibility？
2. **活尾更新**：流式输出期间主线程长任务来源（reveal 排期 / 合帧 / 重渲染）；
3. **屏外/后台动效**：运行中工具行滚出视口、窗口最小化时，常开动画
   （扫光 / 三叶 / indeterminate 进度条）是否仍在烧 paint/CPU；
4. **动效属性健康度**：常开动画的动画属性（background-position / left /
   transform / opacity）在真实管线里的每帧成本。

产出 = 数据表 + 逐热点决定（修 / 不修的理由），不是「全部优化一遍」。

## 2. 对比结论（本次实读，zcode + 本仓现状盘点）

| 主题 | zcode 做法 | 出处 | Cogent 现状 |
| --- | --- | --- | --- |
| 长列表结构 | `@tanstack/react-virtual` 虚拟化，虚拟单元 = **一整轮** | `ConversationTimeline.tsx:20,875` | 无虚拟化：TurnGroup 渲染全部回合；历史靠 MessageRow memo 挡**重**解析，初次挂载仍是全量解析 |
| overscan 教训 | 默认 8 轮 overscan 在搜索跳转时同步挂载大量屏外 Markdown → 收到 **2 轮** | `ConversationTimeline.tsx:119-121` | 不适用（无窗口化）；若上虚拟化，此值是现成教训 |
| 未测行估计 | 未知长轮按 72px 会让首屏挂十几轮 → **按一屏保守预算** | `ConversationTimeline.tsx:853-856` | 同上备用 |
| 行高缓存 | turnId 键持久缓存（4000 条 LRU），防 virtualizer 重置时滚动跳动 | `timelineRowHeightCache.ts:1-61` | 无；message-scroller 不测高（RO 贴底路线，见模块页） |
| 屏外动画暂停 | **无通用策略**——屏外不挂载由虚拟化本身解决；个别 JS 动画按需 `pause()`（workflow-face-motion） | 全仓 grep `animation-play-state` | 无虚拟化也无暂停：运行中工具行滚出视口后动画照跑（CSS 动画不因屏外暂停） |
| will-change 纪律 | 按需提层（marquee 仅 hover 提；扫光提 background-position 但注释自认「不保证免于主线程重绘」） | `styles.css:972-973,1483-1487` | 同款思路已随移植带入（`globals.css:291-294` 同注释） |
| 扫光实现 | `gradient-flow` 4s linear infinite，background-position + clip:text | `styles.css:960-1000` | `shimmer-sweep` **同构移植**（逐属性一致）——「对照扫光实现」判据已天然满足 |
| indeterminate 进度 | `left -33%→100%` 1.2s（布局属性动画，细条 absolute） | `styles.css:1007-1021` | `progress-sweep` **同款移植**（含 reduced-motion 行为） |
| 无限动画纪律 | 全部 reduced-motion 退化；数量克制（常开无限动画集中在运行态行） | 全仓模式 | 同（工作行扫光/三叶各一份 + 运行中工具行类别词扫光 N 份 + 运行中 bash 进度条） |

**zcode 的核心答案：动画本身不做屏外暂停，靠虚拟化让屏外内容不存在。**
Cogent 是否走到那一步，由 §3 的测量决定——这是本批与前三批（修已知缺陷）
的本质区别：**先拿证据**。

## 3. 测量设计

### 3.1 场景矩阵

| 场景 | 构造 | 采集 |
| --- | --- | --- |
| S1 长历史静态 | 种子会话 50 / 200 / 500 回合（正文+代码+表格混合，gen 脚本产 JSONL 或 live context 注入） | 切会话首次呈现耗时；DOM 节点数 / JS 堆；滚动 tracing（track 长任务、Layout/Style 计数）；展开折叠体单次耗时 |
| S2 活尾流式 | 真模型长输出（>2000 字 + 代码块 + 表格），复用 §代码与表格过渡 的提示词 | tracing 主线程长任务归因（reveal 排期 / Streamdown 解析 / store 通知）；合成帧率；与 S0 空闲基线的 CPU 差 |
| S3 屏外动效 | 让工具行运行中（长 bash），把该行滚出视口 | tracing 看 raster/paint 是否持续发生；元素 `getAnimations()` 状态与 `IntersectionObserver` 事实核对 |
| S4 后台动效 | 流式中最小化窗口 / 遮挡 30s | CPU 采样（进程级）；恢复后 reveal 排期行为（既有收尾已处理 visibilitychange，核对无积压复活） |

### 3.2 采集方法

- **首选**：沿用 `tmp/chat-audit-20261117/serve.mjs` 先例——生产构建 + 本地
  serve + CDP（Performance.trace / Tracing / HeapProfiler），不启动 Electron，
  我可自主跑全程；Chromium 版本差异（本机浏览器 ≠ Electron31）在结论里标注。
- **Electron31 复核**：仅对「数据接近判据线」或「Electron 特有路径」
  （DIP 缩放、窗口最小化行为）的场景，请用户以
  `npx electron out/main/index.js --remote-debugging-port=9222` 启动一次，
  我连 CDP 复测。**不后台跑 dev**（硬规则）。
- 长会话种子：tmp 下新目录写生成脚本（一次性，不入 src），经既有导入/回放
  路径注入；不能伪造 store 状态冒充真实渲染。

### 3.3 判据与决策规则

- 帧预算：交互（滚动/流式）期间**无 >50ms 主线程长任务**、无连续丢帧；
- 常开动画：S3/S4 中若屏外/后台仍产生持续 paint → 列热点，候选修法
  （content-visibility / 该行动画作用域收窄 / 不修但记录理由）按单点成本选；
- 虚拟化决策：S1 滚动出现 >50ms 长任务且归因屏外 Markdown 挂载/布局 →
  **另立虚拟化实现批**（zcode 四件套为蓝本，本批只出证据不开工）；
  S1 全绿 → 记录收口，不做结构改动；
- 所有数值入表（本文件 §6），逐热点写「修 / 不修 + 理由」；**没有热点也
  是合法结论**，不为了写优化而优化。

## 4. 边界（真实的墙）

- 本批**不实现虚拟化**：若证据指向它，另立批走调研→审批流程（zcode 四件套
  已在 §2 备好出处）；
- serve.mjs 预览的 Chromium 与 Electron31 差异（合成器调度、DIP）只标注、
  不用预览数据下 Electron 特有结论（教训 3 的既有纪律）；
- 动效属性改造（如 progress-sweep 的 left → transform）只在 tracing 证明
  其为热点时做，且 zcode 生产同款实现是「不动」的强参照；

- 测量脚本/种子全部落 `tmp/`（一次性，不进 src、不进测试套件）。

## 6. 测量记录与逐热点决定（2026-11-18）

**环境**：Edge headless（Chromium，`--window-size=1280,900`，视口 700px）+
生产构建预览（`tmp/perf-audit-20261118/`，真实 MessageScroller + TurnGroup +
Markdown 组件树，受控 props 驱动）；原始数据 `tmp/perf-audit-20261118/results/results.json`。
预览 ≠ Electron31（计划 §3.2 纪律），标 * 的结论须真机复核。

**S1 长历史**（回合 = user + 思考 + 2 工具卡 + 混合正文/代码/表格终答；两轮采集，第二轮 JIT 热）：

| 回合 | 挂载 | DOM 节点 | JS 堆 | 挂载最长长任务 | 滚动（24 次 wheel） | 折叠开合 | 静态空转 8s |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 50 | 1.0–1.2s | 1.77 万 | 24–32MB | 0.71–0.85s | 60fps，0 长任务 | 14–34ms | — |
| 200 | 2.0–3.0s | 7.13 万 | 77–78MB | 1.6–2.3s | 60fps，0 长任务 | 17–38ms | — |
| 500 | 4.3–5.5s | 17.8 万 | 122–167MB | 3.1–4.1s | 60fps，0 长任务 | 14–34ms | 净 +2.5% 单核，style/layout 零增量 |

**S3 屏外动效**（30 回合 + 1 个 live 回合：WorkingLine 扫光/三叶 + 运行中 bash 扫光 + 类别词扫光，8s 差分）：

| 组 | ThreadTime 占单核 | style recalc | layout |
| --- | --- | --- | --- |
| 动画开·屏内（贴底） | 14.1% | 0.287s | 0.123s |
| 动画开·屏外（滚到顶） | 8.9% | 0.265s | 0.038s |
| 动画关·屏外（净基线） | 2.9% | 0 | 0.041s |

→ **屏外动画净成本 ≈ 6% 单核/运行回合**：可见性裁剪只省 paint，style recalc
照跑（扫光 background-position 每帧驱动）。多会话并行运行时线性叠加。

**S2 活尾（受控预检，非真模型）**：300ms/批 × 30s（批 = 2 句正文，每 8 批
一个 24 行代码块，比真实 30ms 合帧批重）：ThreadTime 74% 单核（含动画
~14%）；帧 p50=17ms / **p95=133ms** / max=533ms；30s 内 100 个 ≥50ms 长任务
（top 544ms）——批到达存在掉帧尖峰。受控批不等于真实到达节奏，不据此定案。

**S4 后台**：headless 无最小化语义，留 Electron31 真机（含多会话并行运行场景）。

### 逐热点决定

1. **滚动 / 折叠 / 静态常驻：不修。** 500 回合滚动 60fps 零长任务、空转
   style/layout 零增量、折叠 ≤38ms——MessageRow memo + 合成器滚动已覆盖；
   zcode 虚拟化对滚动的收益在 Cogent 不存在对应热点。
2. **虚拟化：不开工，记触发条件。** 唯一收益点 = 首挂/切会话（500 回合
   4.3–5.5s，全量 Markdown 解析单长任务 3–4s）；主流会话（≤100 回合）
   1–1.5s 处可接受边缘，且属等待场景非交互破坏。触发条件（满足其一另立批，
   zcode 四件套出处见 §2）：用户日常会话普遍 ≥200 回合且抱怨切换等待；
   或 S2 真模型揭示屏外长列表在流式期的常驻更新成本。
3. **屏外/后台常开动画：列热点，候选小批修。** 净 6% 单核 × 并行运行会话
   数；zcode 无此问题靠虚拟化卸载，Cogent 无虚拟化 + 多会话场景成立。
   候选修法（成本递增）：`document.hidden` 全局暂停（最便宜，覆盖 S4 主
   场景）→ 元素级 IntersectionObserver + `animation-play-state`（覆盖屏外）。
   待 S4 真机数据后定案（可能两档都要）。
4. **流式批渲染尖峰：记录，待 S2 真模型终验。** 受控批（300ms 大批）p95
   133ms 不能外推到 30ms 合帧的真实链路；真模型复测若 p95 仍 >100ms，
   另立「流式渲染开销」小批（方向：reveal span 量、Streamdown 解析复用）。

### 待办（真机 / 用户在场）

- S2 真模型：长输出 + 代码 + 表格，CDP 采帧与长任务（对照受控预检）；
- S4 后台：最小化/遮挡 + 多会话并行运行，验证 document.hidden 路径与
  屏外动画真机成本（决定 3 的修法定案）；
- 视觉无回归：本批纯测量，无产品代码改动，无回归面。

收口」结案。** 状态如实：§5 验收第 1 条四场景差两项（S2 真模型、S4），
