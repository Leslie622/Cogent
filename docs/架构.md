# 架构 — Cogent

Cogent 是 Electron + pi 的本地优先桌面 Agent 客户端。本文负责进程、目录、
依赖、构建与参照仓；模块机制见 [模块索引](模块/索引.md)，目标架构与待办见
[全局架构](计划/全局架构.md)。代码规则只维护在 [约定](约定.md)。

## 进程与依赖边界

```text
主 UI / 运行时控制台（React，无 Node）
  │ window.cogent 白名单
  ▼ Electron IPC
Electron main（窗口、IPC、凭据、Host 代理）
  │ spawn 自带 Node ≥22.19
  ▼ stdio JSON-RPC
Host（会话、项目、权限、观测、存储）
  │ CogentKernel 窄合同
  ▼ pi AgentSession（循环、工具、压缩、Provider、JSONL 转录）

可信 demo webview ── guest preload 小 SDK ── HTTP/WS + scoped token ──┐
外部 MCP 客户端 ── 独立 MCP 入口 ── HTTP/WS + Bearer token ────┤
                                                           ▼
                                            同一 HostApi 方法注册表

普通浏览器 webview ── main BrowserRuntime（独立 Session，无 Host SDK）
工作区文件入口 ── main fileViews 白名单 ── Host 上下文/lease ── 有界文件读取
```

- 桌面壳固定 Electron 40.9.3（Chromium 144、Node 24.14.1）。Host 是独立 Node
  进程，禁止依赖 Electron 或 renderer；main 优先定位并拉起自带 Node 22，
  使引擎运行时独立于桌面壳的版本周期，并满足 pi 的 Node ≥22.19 要求。
- Host 服务层只经 `kernel/contract.ts` 驱动内核；pi 装配留在 `kernel/`。
  只维护一个 SDK 实现，扩展内核的目标边界见全局架构 D4/D5。
- `protocol/` 是引擎对外契约，零运行时依赖；`shared/` 是壳内 renderer、
  preload、main 的契约，两者分开维护。
- 依赖方向：`renderer → shared ← electron/main → protocol ← host`。
  renderer 只消费壳契约与转发后的事件，不感知 pi。
- 多标签工作区常驻主内容宿主，分栏以对话右内距留位；占满/窄窗只改同一宿主几何，
  不在Dialog和右栏之间重建网页。普通浏览器与可信demo的页面权限分开，见[工作区模块](模块/多标签工作区.md)。
- HostApi 的 stdio 与 HTTP/WS 共用注册表；完整鉴权与事件归属见
  [HTTP通道](模块/HTTP通道.md)，调用门关系见 [入口图](img/HostApi调用入口.html)。
- 窗口关闭分流（`main/window-close.ts`，设置 `closeBehavior` 消费）：quit 放行
  → `window-all-closed` 收口 host；minimize 拦截 close 后 hide + 常驻托盘
  （窗口不销毁、host 继续跑，托盘点击恢复 / 右键退出）；ask 推事件给 renderer
  弹自绘询问弹窗，裁决回 IPC 执行，「不再询问」经 renderer 落盘固化。
  应用单例（`requestSingleInstanceLock`）：第二实例只呼起已有窗口即退；
  托盘常驻（不限 minimize 档），图标取自可执行文件自身。

## 关键数据旅程

```text
owner: main = 桌面桥与凭据文件；Host = 引擎业务与会话文件；pi = 转录树

发送 → preload → main 白名单 → Host agent.submit → pi 循环
     → stdout 事件 → main 广播 → renderer chat 桶 → UI

需审批工具 → Host 挂起 → approval.request → 审批面板
           → 专属 approval:respond IPC → Host 裁决 → 继续 / 拒绝

密钥 → main safeStorage → initialize / credentials.set → Host 内存 overlay
     → pi ModelRuntime；不借用 ~/.pi/auth.json
```

主界面的审批裁决有独立 IPC，不走 renderer 通用请求代理；HTTP/MCP 消费者
经已授权的 HostApi approval.respond 裁决。密钥在引擎协议侧只回布尔位，
设置页则可经壳侧接口按 Provider 取明文；两条信任边界的细节见
[凭据与模型目录](模块/凭据与模型目录.md)。

存储根为 `COGENT_HOME ?? ~/.cogent`。pi JSONL 是转录真源，Host 保存会话域
摘要、项目等业务数据；main 保存壳偏好、加密凭据与自定义 Provider 定义。
交付manifest与字节由Host的`runtime/outputs/`持有，放存储根`outputs/v1/`；与转录、输入附件分域，见[产物文件卡片](模块/产物文件卡片.md)。
工作区标签、布局、阅读偏好与grant引用只在renderer内存保留，应用启动收起且无标签。
文件选择授权与浏览器站点策略分别由main写`file-view-grants.json`、`browser-settings.json`；
Cookie归Chromium独立partition，与运行期标签内容分开。
JSON 文件以同目录临时文件加 rename 原子替换；损坏会话文件逐份旁置，不阻断
其他会话恢复。各文件所有权见 [工作区与项目](模块/工作区与项目.md)，恢复与取消
顺序见 [会话与对话](模块/会话与对话.md)。

## 构建与运行时

`electron.vite.config.ts` 管三目标：main、preload、renderer。
main 有五个入口：`out/main/index.js` 为 Electron main，`host.js` 为 Host，
`mcp.js` 为外部 MCP 客户端入口，`attachment-worker.js` 为文档解析 worker，
`file-view-worker.js` 为有界目录/文件名搜索线程；目录排序不在Host主线程执行。
coding-agent 与 TypeBox 合并进共享 chunks，减少首次安装的逐文件加载；pi-ai、
厂商 SDK、原生依赖和 PDF.js/Office 依赖保持 external。构建保留 coding-agent
模块的原始资源 URL，包元数据、扩展别名和图片 worker 仍定位到安装的 SDK。
renderer文件查看器按需加载Pierre/Shiki WASM、react-pdf、docx-preview、react-xlsx/WASM与pptx-renderer；
文件Markdown懒包另含math/KaTeX和Mermaid，不增加聊天默认插件。`scripts/pdf-assets.ts`为开发和产物提供
同版PDF.js API/worker、`pdfjs/cmaps`、`standard_fonts`、`wasm`，也供PPTX的EMF-PDF转换使用；不代理用户目录。
文件跨进程机制见[正文文件链接](模块/正文文件链接.md)，可视化归属见[文件预览渲染](模块/文件预览渲染.md)。
分发须保留生成的共享 chunks、worker，以及 PDF.js 包的 cmaps/standard_fonts/wasm
和所需原生可选依赖；附件机制与资源边界见[附件模块](模块/图片与文件附件.md)。
`postinstall`强制应用两项文件渲染补丁；`scripts/preview-licenses.ts`把上游许可证与Zcode补丁归因输出到
`out/renderer/licenses/file-preview/`，分发保留该目录及WASM资源。

preload 输出 CJS：主 UI 与控制台使用 `index.cjs`，沙箱 webview 使用
`guest.cjs`；普通浏览器guest不挂此SDK。沙箱 preload 不支持 ESM。renderer 是 React 19、Tailwind v4、
base-nova shadcn/ui 与 Streamdown；控制台只读文本查看器按需加载 CodeMirror 6。
工作区标签排序使用dnd-kit；文件树使用Headless Tree同步投影和TanStack Virtual，异步目录状态仍归本项目owner。
外观取色使用 UIW；Themd 基础样式随本地快照入库，由 PostCSS 维护脚本生成，
构建不依赖外部 Themd 仓库。字体枚举限主窗口顶层应用文档；其他窗口不授予本地字体权限。
文件图标依赖固定版本 `material-icon-theme`，官方关联在 renderer 初始化一次，SVG 经 Vite 输出本地资源；
分发保留 `out/renderer/assets/` 与 `licenses/material-icon-theme/LICENSE`，不依赖网络图标服务。

`npm run fetch:runtime` 下载官方 Node 22，以官方 SHASUMS256.txt 验证 SHA256。
运行时定位顺序为 `COGENT_NODE_BIN` 覆盖、自带二进制、Electron 自带 Node 兜底；
拉起时有版本守卫；Electron 内置 Node 兜底同样经过握手与版本检查。
下载与平台目录见 [Node运行时分发](技术笔记/Node运行时分发.md)。

启动诊断由 main 记录实际 Node 与入口路径，Host 经 stderr 输出 `[startup]` 阶段及
进程启动后的累计毫秒数：模块加载 → 模型运行时 → 存储恢复 → 路由装配 → HTTP
监听（启用时）→ stdio 就绪 → initialize 凭据同步。stdout 只承载协议帧。
main 给完整启动 60 秒预算，超时报出最后收到的阶段；启动失败会结束子进程，并将原始原因
保留在并发请求的拒绝信息中。阶段日志不含凭据或会话内容。
厂商方言预热排在 initialize 响应之后；握手仍保证运行时、存储和传输已可用。
验收：新依赖文件路径首次启动可握手，加载超过 15 秒仍可在预算内完成；
握手成功后计时器清除；超时后状态为 failed、并发请求收到原始失败原因，
Host 延迟退出事件不将 failed 改回 stopped；真实产物的启动日志不污染 JSON-RPC。

引擎供其他宿主复用时，携带 `out/main/host.js`、共享 chunks、附件/文件目录worker、所需 `node_modules` 与
`protocol/` 契约，以 Node ≥22.19 拉起并实现同一 JSON-RPC 即可；不依赖
Electron。权限和凭据仍须由该宿主明确提供。

## reference 源码参照

换机器后按以下方式补拉；只读参照不写入项目 Git 历史。

```bash
git clone --filter=blob:none --sparse https://github.com/earendil-works/pi reference/pi
git -C reference/pi sparse-checkout set packages/agent packages/ai packages/coding-agent
git clone --depth 1 https://github.com/deepseek-ai/deepseek-harness reference/deepseek-harness
git clone --depth 1 https://github.com/zai-org/ZCode reference/zcode
git clone --depth 1 https://gh-proxy.com/https://github.com/xidongdong-153/Pi-meme reference/Pi-meme
```

| 仓库 | 主要用途 |
| --- | --- |
| pi | agent / ai / coding-agent 三包；对照锚点 `74dcca7d4`（短 SHA 至少九位，避开对象前缀碰撞） |
| deepseek-harness | 压缩、工具结果裁剪、能力边界与 browser-use |
| zcode | 桌面布局、server-core、内置浏览器、插件与页面面板 |
| Pi-meme | 独立 Node Host、双通道 HostApi、MCP 出口、自带运行时 |

需要代理时给 Git 命令加 `-c http.proxy=http://127.0.0.1:7897`；pi 的
sparse-checkout 也会拉 blob，必要时先配仓库代理。Pi-meme 的 remote 保持可用
镜像 URL。日常更新用 `git -C reference/<仓库> pull`，文档对照保留实读版本
和文件出处，不将旧调研自动当作当前上游事实。
