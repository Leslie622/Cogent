# 架构 — Cogent

## 1. 项目定位

Cogent 是基于 Electron + [pi](https://github.com/earendil-works/pi) 的桌面 Agent 客户端，
对标主流 Agent 产品（多会话、工具可视化、审批流、设置页），**本地优先存储**。

核心架构决策（已定，不再讨论）：

- **引擎服务化**：pi 封装为独立 Node 进程（`agent-service`），与 Electron 彻底解耦，
  通过 stdio JSON-RPC 通信 —— 任何 Node ≥ 22.19 的宿主都能复用它（含 Electron 22 旧项目）；
- **引擎运行时：默认 Electron 自带 Node**：main 用 `process.execPath` +
  `ELECTRON_RUN_AS_NODE=1` 拉起引擎（Electron 45 内置 Node 24.x，满足 pi ≥ 22.19），
  不依赖用户系统 PATH 里的 node（可能没装 / 版本不受控）。演进路线（已定）：
  ① 现阶段用 Electron 自带 Node，版本随 Electron 发版走，发版前整链路测试兜底；
  ② 要版本独立化时，构建期放官方 node.exe 进 `resources/` 并让它成为默认值。
  `COGENT_NODE_BIN` 始终是覆盖口（开发调试 / 旧宿主复用引擎时指向任意 Node ≥ 22.19）；
- **main 是壳不是业务**：窗口、IPC、引擎代理、凭据；业务（会话/工具/存储）全在引擎进程；
- **本地优先**：存储走 StorageDriver 接口，本地 JSON 先行，将来接云接口只换实现。

## 2. 一图看懂

```
Renderer（纯 UI，无 Node）
  │  window.cogent.*（preload 白名单窄接口）
  ▼ Electron IPC
Main（Electron 主进程 = 壳）
  │  窗口 / IPC 注册 / 凭据(safeStorage) / 引擎代理
  │  spawn Electron 自带 Node（execPath + ELECTRON_RUN_AS_NODE=1；
  │    COGENT_NODE_BIN 可覆盖，版本守卫 >=22.19）
  ▼ stdio JSON-RPC（一行一帧 JSON）
AgentService（独立 Node 进程 = 引擎）
  │  会话管理 / pi Agent / 工具执行 / 审批拦截 / 本地存储
  ▼ 只依赖 pi-* + protocol，零 Electron import
```

消息旅程（2026-11-06 全链路落地）：用户发送 → renderer `window.cogent.engineRequest('agent.submit')`
→ main 校验白名单 → 写入引擎 stdin → 引擎跑 pi 循环，事件流（run.* / message.delta）写 stdout →
main 转发 `webContents.send` → renderer chat store → UI。审批流同路：引擎 `approval.request` →
main → renderer 弹窗 → 用户裁决 → 原路回 `approval.respond`。
偏好旅程（单向）：会话级偏好（选中模型/思考力度）落 ~/.cogent/settings.json（main 写）→ 启动回填 renderer engine store；凭据旅程（单向）：safeStorage 落盘（main）→ 握手注入（initialize.credentials）→ 引擎内存表 →
pi getApiKey 每轮请求解析；key 明文任何情况下不回流 renderer（credentials.list 只回布尔位）。

**为什么引擎不直接进 main**：pi 要求 Node ≥ 22.19 且 ESM-only；Electron 22 内置 Node 18.12
且主进程不支持 ESM —— 进程内集成在旧宿主上物理不可行。服务化同时白送崩溃隔离与进程级 abort。

**依赖方向（唯一，禁止反向）**：
`renderer → shared ← electron/main → protocol ← agent-service`

**构建**：`electron.vite.config.ts` 三目标；main 双入口
（`index`=主进程，`service`=引擎，产物同在 `out/main/`）。
pi 依赖保持 external（provider SDK 懒加载，打进 bundle 会破坏该机制）。

## 4. 集成（供将来参考）

旧 Electron 项目复用引擎 = 复用两个东西：

1. `agent-service/` 构建产物（`out/main/service.js`，纯 ESM，靠 `node_modules` 加载 pi）；
2. `protocol/` 类型与常量（实现同一套 JSON-RPC 即可驱动）。

宿主差异只在"怎么拉起进程"：Cogent 用 main spawn（默认 Electron 自带 Node，
`ELECTRON_RUN_AS_NODE=1`）；旧项目同样 spawn，用系统 Node ≥ 22.19
（引擎内部零 Electron import，宿主版本无关）。
