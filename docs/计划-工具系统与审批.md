## 0. 背景与目标

引擎目前是纯聊天：pi Agent 未注册任何工具，`beforeToolCall` 未接，`tool.*` /
`approval.*` 协议事件在转译层被丢弃。这是 Cogent 与主流 Agent 产品（Claude Code /
Codex / Cursor / ChatGPT 桌面版）的分水岭差距 —— 没有工具循环，steering、上下文
压缩、子代理、MCP 全部无处发力。

本计划落地：

1. **工具系统**：`agent-service/tools/` 注册表 + 第一批工具（read / glob / grep /
   write）+ 工作区边界（路径限制在会话工作区根内）；
2. **审批拦截**：`beforeToolCall` → `approval.request` 挂起 → 宿主裁决 →
   `approval.respond` 放行/拒绝（写类工具先问后做）；
3. **UI 呈现**：工具调用卡（路线空位 #4 后半）+ 审批卡 + abort「已停止」占位
   （空位 #6）。

对比主流的定位：Claude Code 权限三模式 / Codex 沙箱+审批 / ChatGPT「完全访问」
开关，本质都是 **ToolKind × permissionMode 矩阵**，本计划实现同款骨架。

| 引擎 | inspector 的 `toolStarted/toolCompleted` 观测已接（工具一注册控制台即可看）；工作区根（cwds）+ 信任确认 + AGENTS.md 注入已就位 | `tools/` 目录、`createAgent` 装配、事件转译、审批挂起 |
| 壳 | `engine:request` 白名单（刻意不含 approval.respond，架构.md §2 既定意图 = 裁决走宿主专属通道） | `approval:respond` IPC 通道 + preload `respondApproval` |
| renderer | ChatComposer 已有「完全访问」按钮（静态）；AI Elements 有 tool / confirmation 两个现成 pattern | 工具卡、审批卡、chat store 工具项消费 |

关键 pi 形状（转译/挂起的实现依据）：

- `tool_execution_start: { toolCallId, toolName, args }`；
  `tool_execution_end: { toolCallId, toolName, result, isError, durationMs? }`
- `beforeToolCall(context, signal)` 返回 `{ block?: boolean, reason?: string }` ——
  **block 即拒绝**（模型收到 error 工具结果），不 block 即放行；返回 Promise
  挂起 = 等用户裁决，signal 在 abort 时触发（挂起必须监听它，否则中止后卡死）；
- 转录里工具调用 = assistant 消息的 `toolCall` 块（id/name/arguments），
  工具结果 = 独立 `role:'toolResult'` 消息（toolCallId 配对）—— 历史回查按
  toolCallId 配对投影。

## 2. 已定决策（评审通过后不再翻烧饼）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 工具分批：**本计划第一批 = read / glob / grep（只读放行）+ write（审批链路验收）**；edit / bash 第二批；network（fetch/search）第三批 | 只读先行可先落整条「工具循环 + 事件转译 + UI 卡」链路且零风险；write 留在本批是因为审批链路必须有一个真写类工具才能端到端验收（mock 之外） |
| D2 | ~~工作区边界（软）：工具路径一律限工作区根内；无根会话零工具~~ **修订（2026-11-10 用户驳回原案）**：只读工具（read/glob/grep）**不限界** —— 相对路径以基根解析（绑定主根，无绑定 = 用户主目录），绝对路径任意；**任何会话都有只读工具**（无绑定会话以主目录为基 = 桌面应用语境的 "launch cwd"）；写/exec 类才限界（工作区根 ?? 主目录）+ 审批（批次 2） | 用户对照主流：Claude Code 只读默认全盘允许、Cursor/Cline 永远有工作区、Codex 沙箱只管写 ——「无根会话零工具」比所有主流产品都严，不成立。主流共识 = **读几乎不设限、写才设闸**；限界代码（resolveWithinRoots）保留给批次 2 的写类工具 |
| D3 | 审批回传走 **main 专属 IPC 通道**（`approval:respond` → `service.request('approval.respond')`），`engine:request` 白名单继续不含 approval.respond | 架构.md §2 既定意图：「宿主侧裁决不经 renderer 通用代理」——审批是安全边界，通道显式独立，与「工具结果不经 renderer 转发」同理 |
| D4 | 审批判定矩阵 = ToolKind × permissionMode：read 类恒放行；write/exec/network 按 mode —— `ask`（默认）发 approval.request；`auto` 全放行；`plan` 直接 block（附原因）。第一版默认 `ask`；「完全访问」输入卡按钮接 `auto`（会话级）；`plan` 模式先不接 UI | 对齐 Claude Code 三模式 / ChatGPT 完全访问；矩阵在引擎一处判定（beforeToolCall），UI 只是裁决面板 |
| D5 | 挂起语义：beforeToolCall 返回 pending Promise 等待 `approval.respond`；**无超时**（用户不点 = 一直等，输入框变停止钮可 abort）；abort signal 触发 → resolve `{ block: true, reason: '已中止' }`；会话删除/引擎退出同理收尾 | 超时自动拒绝是产品语义不是安全语义（Claude Code 也不超时）；挂起必须有 signal 兜底，否则 abort 后 Promise 永悬 |
| D6 | 流式段化：一个 run = 多段 assistant（text 段与 toolCall 段交错，**按事件序保真**）；协议 `run.completed` 扩 optional `messages?: ChatMessage[]`（分段终态），`message` 保留 = 全段聚合（老宿主兼容）；`ChatMessage` 扩 optional `toolCalls?` | pi 转录本来就是每轮一条 AssistantMessage，投影天然逐条；若像现在把全 run 文本拼一条，工具卡与文本的交错顺序刷新后即丢失 |
| D7 | 工具卡 / 审批卡用 AI Elements **tool / confirmation** pattern（base-luma registry 安装），不自搓 | 约定.md 渲染层硬规则 3；shadcn tool pattern 自带 ToolHeader/ToolContent 折叠骨架 |
| D8 | read 截断策略：单文件读取上限 64KB 字符（截断附提示）；glob 结果上限 200 条；grep 匹配行上限 100 行 | 工具结果进模型上下文，不设上限 = 一次读穿上下文窗口（Claude Code Read 2000 行同款考量） |
| D9 | grep / glob 自研纯 JS 实现，不引 ripgrep 二进制 | 零外部依赖跨平台（rg 分发/授权是独立课题）；性能对小项目够用；真有性能需求时替换实现不动协议 |

## 3. 协议变更（只增不破）

```ts
// 新类型：工具调用投影（流式事件与历史回查共用）
interface ToolCallRecord {
  callId: string
  name: string
  kind: ToolKind
  /** 参数一行摘要（UI 卡标题；引擎生成，如 read("src/index.ts")） */
  summary: string
  status: 'ok' | 'error' | 'blocked'
  /** 结果一行摘要（截断；错误时为原因） */
  resultSummary?: string
}

// ChatMessage 扩 optional（历史回查投影：该 assistant 消息发起的调用）
interface ChatMessage { toolCalls?: ToolCallRecord[] }

// run.completed 扩 optional（分段终态，按事件序；message 保留 = 聚合兼容）
'run.completed': { …, messages?: ChatMessage[] }

// 事件字段只增 optional：tool.started 带 summary（参数摘要，审批卡/工具卡标题共用）
'tool.started': { sessionId; callId; name; kind; summary? }

// 新 method：会话级权限切换（「完全访问」按钮）
'session.setPermission': { params: { sessionId: string; mode: PermissionMode }; result: SessionSummary }
// SessionSummary 扩 optional permissionMode?（持久化）
```

`session.setPermission` 进 `engine:request` 白名单（renderer 可切）；
`approval.respond` **不进**（D3）。env.d.ts 镜像同步。

## 4. 分步实施（每步可运行、三关全绿后再走下一步）

### 第 1 步 — 协议微扩 + 引擎 tools/ 骨架（只读工具）

- `agent-service/tools/`：
  - `index.ts`：注册表 —— `buildTools(roots): AgentTool[]`（roots = 基根
    = 绑定根 ?? 主目录，恒非空 = D2 修订：任何会话都有工具）；每个工具附
    `kind: ToolKind` 元数据（pi 的 AgentTool 没有 kind 字段，Cogent 侧包一层
    `{ tool, kind, summarize(args) }`）；
  - `read.ts` / `glob.ts` / `grep.ts`：pi-schema builders 定义参数 schema；
    路径解析用 `resolveAgainstBase`（相对 → 基根，绝对任意；只读不限界 =
    D2 修订），执行 + 截断（D8 上限）；
- `session.ts` `createAgent`：`initialState.tools = buildTools(toolRoots)`；
  系统提示词恒带工具段（相对路径基根声明）；`resolveWithinRoots` 留给
  批次 2 写类工具；
- 转译：`tool_execution_start/end` → `tool.started`（含 summary）/ `tool.completed`
  （resultSummary 从 result.content 文本提取截断）；
- 冒烟（mock SSE 出 tool_calls chunk）：read 真文件 → 第二轮请求体含工具结果
  → 最终文本；控制台时间线出现 tool.* 条目（inspector 现成，白捡）。

### 第 2 步 — 流式段化 + run.completed.messages

- `StreamingState` 改段累积：text 段缓冲 + `segments: ChatMessage[]`；工具调用
  事件到达 = 当前 text 段封存、push 工具段；turn_end 封段；agent_end 聚合；
- `run.completed` 同时发 `messages`（分段）与 `message`（聚合：text 拼接 +
  toolCalls 合并 —— 老宿主兼容形态）；
- `toChatMessages` 历史回查：assistant 消息带 toolCall 块 → `toolCalls` 投影，
  toolResult 消息按 toolCallId 配对出 status/resultSummary；toolResult 消息
  本身不产出 ChatMessage（避免空消息）；
- 冒烟：带工具调用的会话 → 杀引擎重启 → 历史回查工具卡复原。

### 第 3 步 — UI 工具卡（空位 #4 后半）

- chat store：消息列表元素类型扩为 `ChatMessage | ToolItem`（ToolItem 由
  tool.started/completed 事件维护，id = callId）；run.completed 用 messages
  分段终态整体替换（顺序保真）；
- `components/ui/tool.tsx`：AI Elements tool pattern（base-luma 安装），
  HomeChat 消息流渲染 —— 标题 = `summary`，正文 = resultSummary，错误红字；
- 会话切换/删除时 ToolItem 随消息列表自然清理（同 ChatMessage 生命周期）。

### 第 4 步 — write 工具 + 审批拦截 + 审批卡

- `tools/write.ts`（kind 'write'：整文件写/覆盖，创建目录；路径边界同 D2）；
- `session.ts`：`beforeToolCall` 挂钩 —— 按 D4 矩阵判定：
  - 放行 → `return undefined`；
  - plan / 拒绝 → `{ block: true, reason }`（blocked 状态也发 tool.completed，
    status 'blocked'）；
  - ask → 生成 requestId、发 `approval.request`（summary 复用工具 summarize）、
    Promise 挂起存 pending 表，`approval.respond` 到达 resolve；signal abort →
    resolve block（D5）；
- `index.ts`：`approval.respond` handler（requestId/approved 校验 + 唔配对
  requestId = InvalidParams）；`session.setPermission` handler；
- main：`ipc/approval.ts` —— `approval:respond` 专属通道（D3）+ 白名单；
  preload `respondApproval(requestId, approved)`；`session.setPermission` 进
  engine 白名单；
- renderer：审批卡 = AI Elements confirmation pattern，挂消息流末尾（工具卡
  位置之后）：工具名 + summary + [允许] [拒绝]；点击 → `respondApproval`；
  env.d.ts 补事件/方法镜像；
- 冒烟：write 触发 approval.request → respond(approved) → 文件真写入 →
  respond(false) 路径 → block 结果回模型；abort 挂起中 → block 收尾不卡死。

### 第 5 步 — abort「已停止」占位（空位 #6）+ 完全访问接线

- chat store：`abort()` 前置记 `stoppingBySession`；终态事件（failed/completed）
  到达且该位为真 → 半截流式文本保留 + 尾部「已停止」占位条（不再按错误清空）；
- ChatComposer「完全访问」按钮真接线：toggle 会话 `permissionMode`
  ask ↔ auto（`session.setPermission`），开启态沿用现有橙圈警示样式；
  新会话在物化时带当前选择；
- 设置页「默认权限」开关（静态演示位）后续件统一接全局默认，本步不摊。

## 5. 边界与风险

| 风险 | 对策 |
| --- | --- |
| 挂起 Promise 泄漏（respond 永不到达） | signal abort 兜底（D5）；引擎退出进程即死无泄漏；pending 表随会话删除清理 |
| 审批期间用户又发消息 | pi 约定同会话同时只跑一个 prompt，submit 已挡（串话修复纪律）；审批挂在 run 内部，不构成新 run |
| 模型不支持 function calling（自定义小模型） | tools 传了不调而已，无错误路径；usage 照常 |
| Windows 路径（分隔符/大小写/盘符） | 边界判定统一 `path.resolve` 后前缀比对（小写化比较）；工具描述里声明正斜杠可用 |
| read 大文件打爆上下文 | D8 截断上限；结果带 `[已截断]` 提示模型分段读 |
| mock 冒烟要伪造 tool_calls SSE | 扩展现有 mock 端点配方（openai 格式 tool_calls chunk），入 开发.md |
| 多窗口收到 approval.request | 广播是既有语义；非活动窗口无活动会话自然不渲染（chat store 按 sessionId 归属） |

## 8. 整体验收（Done 的定义）

1. 有项目的会话里问「读一下 package.json」→ 模型调 read → 工具卡出现 →
   回答引用文件内容；控制台时间线可见 tool.*；
2. 让模型写文件 → 审批卡弹出 → 允许 = 文件落盘 + 工具卡 ok；拒绝 = 工具卡
   blocked + 模型改口；
3. 审批挂起中点停止 → 不卡死，工具卡 blocked、流尾部「已停止」；
4. 「完全访问」开启后写文件不再弹审批；
5. 重启应用：工具卡历史回查复原（分段顺序保真）；
6. 无项目的纯聊天会话：工具照常可用（相对路径以主目录为基，绝对路径任意），
   「读一下桌面上的 xxx」直接成功（D2 修订）；
7. 三关全绿；冒烟以 `COGENT_HOME` 临时目录可重复跑。
