## 0. 背景与目标（用户三点反馈）

用户对照主流 Agent 产品（桌面端）提出三块差距：

1. **审批形式**：主流是对话底部的**确认面板**（输入区上方常驻，随裁决消失），
   选项五件套：允许（仅这一次）/ 始终允许 / 完全访问 / 拒绝 / 告诉模型接下来
   怎么做（自由文本）—— 而非现在塞在消息流里的一张卡；
2. **权限菜单**：「完全访问」钮升级为**权限模式下拉菜单**（计划模式 / 变更前
   确认 / 自主模式 / 完全访问；带图标+说明+勾选态，完全访问与前三档分隔线分组）；
3. **侧栏状态 tag**：等待确认的会话，侧栏行右侧显示「等待确认」胶囊 tag
   （浅绿底）。

## 2. 已定决策（评审通过后不再翻烧饼）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 审批呈现 = **对话底部确认面板，待审批时替换输入区**（2026-11-11 用户定调修订：原「输入区上方常驻」形态被推翻 —— run 挂起中本就发不出消息，留着能打字的输入框是误导；HomeChat 条件切换，输入草稿提升父层持防丢），随裁决消失回到输入框，不做弹窗；**卡内布局完全模仿参考图（同日二次定稿）**：竖排全宽选项列表（序号 + 主文案 + 说明灰字；↑↓/Tab 移动选中态、Enter/确认钮执行、点击直接执行）+ 附言无框浅灰输入条 + 底部 ⓘ 快捷键提示与深色确认主钮，替代首版的横排按钮组。裁决完成后**落一条置灰痕迹行进消息流**（复用现有 ApprovalCard 终态形态） | 弹窗打断感强，Claude Code/Codex/图 1 产品全是内嵌面板；pending 态改会话级独立状态（`pendingApprovalBySession`），数据流比塞进消息列表干净 |
| D2 | 选项五件套：**允许（仅这一次）**/ **始终允许此工作区**（D3 规则）/ **完全访问**（respond + setPermission(auto) 两步串）/ **拒绝**/ **告诉模型接下来怎么做…**（= 拒绝 + 附言，附言进工具结果给模型） | 对齐图 1；附言是 steering 的最小雏形（真运行中插话仍是后续空位，不混做） |
| D3 | 「始终允许」第一版 = **工作区级**规则：形状 `{ roots: string[], kind: 'write' }`，项目会话 = 项目全部根、目录会话 = 该根、**无根会话不显示此项**（规则会记成"全放主目录"，过大）；引擎侧新 collection `approvals`（`~/.cogent/approvals.json`，**不进项目目录**）持久化，beforeToolCall 在 ask 判定**前**查规则表（任一根命中即放行）。**判定优先序 = 软边界（工作区外恒拒）> 规则表放行 > mode 矩阵** —— 软边界是天然的顶级 deny，规则只能放行"边界内"的写，与 Claude Code「deny > allow 严格序、跨作用域 deny 终局」铁律同构（2026-11-11 调研，见 §1.5） | 三流派对照后选 Qoder 流派（用户点名形态）：Claude Code 文件写的 don't-ask-again **只到会话结束不落盘**（永久规则只给 Bash 命令族/域名 —— 但存精确命令曾泄漏密钥，Apiiro 实锤 settings.local.json 被误提交）；Qoder「始终允许本项目」= 项目级持久；Codex 无 always 规则、用 trusted_projects（目录信任扩可写根）。三家共识：**文件写的永久放行绑定"位置"不绑定"内容"** —— roots 粒度与 Qoder/Codex 对齐且无参数泄漏面（不存命令/内容，只存目录）；存引擎侧全局文件杜绝 Claude Code 的 repo 内误提交事故面 |
| D4 | 权限菜单 = **三档真选项**（计划模式 / 变更前确认 / 完全访问）+ **「自主模式」第四项置灰占位**（说明"exec / network 工具落地后启用"）—— **用户已拍板（2026-11-11）** | 协议三档零变更；「自主 = 有风险时询问」需要 exec/network 的风险分级才有料，现在实现只能是 ask 同义词 |
| D5 | 触发钮**显当前模式名 + ⌄**（不再恒显「完全访问」）；菜单 = dropdown-menu + 图标/说明/勾选/分隔线（危险分组隔离，照图 2）。**配色定调（2026-11-11 用户修订）**：完全访问的强调 = warning 琥珀（警告）非 destructive 红（错误）；触发钮**无常态背景**（含完全访问态 —— 首版红胶囊常驻底被推翻），仅 hover 出底，箭头随主体同色不单独给灰 | 与主流一致；原「点击应出权限面板属后续件」的空位由本菜单填掉 |
| D6 | plan 模式随菜单**首次真接线**：引擎已有 block 行为，补系统提示词按 mode 附一句（plan：「plan 只读」；auto：「已授予完全访问」）。**提示词时效（评审补，不补即 bug）**：systemPrompt 在 createAgent 固化而模式运行中可切 —— setPermission 时 agent 已建则全量重拼覆写 `agent.state.systemPrompt`（state 可变有先例：submit 改 `agent.state.model`），惰性会话跳过（下次 ensureAgent 按新 mode 建）；否则 auto 切回 ask 会残留「已授予完全访问」的有害提示。**设置页「默认权限」= 开关两态**（开 = 新会话默认 auto / 关 = ask，进 settings.json；plan 不进默认 —— 2026-11-11 用户拍板，保既有 switch 形态） | 菜单里能选就必须真工作；开关两态使接线真一行 |
| D7 | 侧栏 tag：会话行右侧「等待确认」浅绿胶囊（`pendingApprovalBySession` 派生，有 pending 审批即显）；**不做**「生成中」等其他 tag | 用户点名只要等待确认；生成中 tag 牵涉会话列表实时态刷新策略，单独件再说 |

## 1.5 主流实现调研（2026-11-11，D3/风险表的设计依据）

| | 「始终允许」语义 | 规则存储与粒度 | 权限模式集 | 附言拒绝 |
| --- | --- | --- | --- | --- |
| **Claude Code** | 分工具：Bash/WebSearch 域 = **永久落盘**；**文件写（Edit/Write）只到会话结束，刻意不落盘**（永久放行走模式 acceptEdits/bypass，不走规则） | `.claude/settings.local.json`（repo 根）/ settings.json（user/project）；规则 = 工具 specifier（`Bash(npm run test:*)` 前缀、Read/Edit gitignore 路径、`WebFetch(domain:…)`）；**判定序 deny > ask > allow 首配即中、跨作用域 deny 终局**；复合 Bash 每子命令逐一匹配 + wrapper 剥离 | plan / default(Manual) / acceptEdits / auto（风险分类器审，勿打扰版）/ dontAsk / bypassPermissions 六档，企业可禁 | "No, and tell Claude what to do differently (Esc)" —— 图 1 第 5 项的先例 |
| **Qoder**（图 1/2 产品） | 「始终允许本项目」= 项目级持久 | 项目/工作区级（文档未公开存储细节） | 每次询问 / 自动审批（风险检测，= 图 2「自主模式」）/ 完全访问 三档 + 企业策略可禁后两档 | 「告诉模型接下来应该怎么做…」输入框 |
| **Codex** | 无 always 规则；等价物 = **trusted projects**（目录信任，`~/.codex/config.toml`，扩展 workspace-write 可写根）+ VS Code Trusted Workspace 解锁审批策略 | 沙箱（read-only/workspace-write/danger）× approval_policy（on-request/on-failure/never）**两维独立**；`untrusted` 策略因太烦已退役（0.49+） | 沙箱三档 × 策略三档组合 | 无（拒绝即拒） |
| **Cogent（本计划）** | 「始终允许此工作区」= 工作区级持久（Qoder 流派，Claude Code 的文件写永久化缺口用位置粒度弥补） | `~/.cogent/approvals.json`（引擎侧全局，**不进项目目录** —— 无 repo 误提交泄漏面）；粒度 = roots × kind，不存命令/内容 | ask / plan / auto 三档 + 自主模式置灰占位（= Claude Code auto / Qoder 自动审批的分类器语义，待 exec/network 落地） | 拒绝 + 附言（对齐 Claude Code Esc / Qoder 输入框） |

**对风险表的三条直接输入**：① Claude Code 的 settings.local.json 存精确命令（含密钥）被误提交泄漏（[HN](https://news.ycombinator.com/item?id=50407882) / [Apiiro 研究](https://medium.com/skillstuff/claude-codes-don-t-ask-again-feature-had-a-security-cost-developers-didn-t-expect-da30b2af986b)）→ Cogent 只存 roots 且存引擎侧；② deny > allow 严格序 → Cogent 软边界天然是顶级 deny，规则永不放行越界写；③ Codex `untrusted` 退役 → 策略枚举宁少勿烦，Cogent 三档 + 占位足够，自主模式不提前实做。

## 3. 协议变更（只增不破）

```ts
// approval.respond 扩 optional：
'approval.respond': {
  params: {
    requestId: string
    approved: boolean
    /** 拒绝附言（「告诉模型接下来怎么做」）：进工具结果给模型，自我纠正依据 */
    message?: string
    /** 'workspace' = 允许本次 + 落工作区级规则（D3；approved 隐含 true） */
    always?: 'workspace'
  }
}
// 无新 method / 新事件；approvals collection 是引擎内部存储，不入协议
```

## 4. 分步实施（每步可运行、三关全绿后再走下一步）

### 第 1 步 — 引擎：respond 扩参 + 规则表 + plan 提示词

- 引擎侧单文件规则存储 `~/.cogent/approvals.json`（评审勘误：**不走 driver
  collection** —— 那是 `<root>/<collection>/<id>.json` 目录语义；单文件自写
  tmp+rename 原子写，手法同 JsonStorageDriver.put；main 侧的 writeFileAtomic
  不可 import —— agent-service 零 Electron 依赖的边界纪律）+ 启动恢复；

  reason = 附言）；**always 在无绑定根会话上 InvalidParams**（UI 不显示此项
  但协议直达，防主目录全放行落规则 —— 语义校验有「审批请求不存在」先例）；

## 5. 边界与风险

| 风险 | 对策 |
| --- | --- |
| 规则表误授权（工作区全放行后模型乱写） | 规则只记 roots 不记通配；菜单随时可切回 ask；**审计口径（评审校准）**：审批痕迹行是进程内存态（重启即失），跨重启审计靠工具卡 —— 拒绝的写在转录里是 isError toolResult → error 工具卡持久、允许的本就有卡；**规则永不放行越界写**（软边界 = 顶级 deny，优先序见 D3 —— Claude Code deny>allow 铁律同构） |
| 规则文件泄漏面 | 存 `~/.cogent/approvals.json`（引擎侧全局，不进项目目录）+ 只存 roots 不存命令/内容 —— 对照 Claude Code settings.local.json 存精确命令（含密钥）被误提交泄漏的事故（§1.5） |
| 附言超长打爆工具结果 | 截断上限（如 2000 字符，与 D8 截断纪律同源） |
| pending 迁移后旧会话消息流残留 pending 行（升级窗口） | ApprovalItem 已落终态的行保留渲染（痕迹行形状不变），仅 pending 态不再进消息流 |
| 面板与消息流痕迹的时序（裁决瞬间面板消失、痕迹行出现） | 同一 store 事务内完成（set 合并），不闪双份 |
| 多窗口：A 窗裁决、B 窗面板还在 | 裁决经引擎（respond → resolve → run 续走 → 事件流广播），B 窗靠事件收面板 —— 与现状同构 |
| 将来 exec 工具的规则设计（预告，本计划不做） | Claude Code 教训：复合命令须逐子命令匹配 + wrapper 剥离（timeout/nice 剥、npx/docker 不剥）—— exec 批次做规则时直接继承，勿做整串命令前缀匹配 |
| 选项疲劳（面板/模式枚举过多反被弃用） | Codex `untrusted` 因太烦退役的教训：面板五件套封顶、模式三档+占位封顶、「本会话始终允许」中间档不做（完全访问已覆盖会话级需求） |

## 6. 明示不做（防摊大饼）

运行中插话（真 steering —— 附言只随拒绝走）、路径级/工具级细粒度规则与规则
管理 UI（设置页查看/删除规则，后续件）、「本会话始终允许」中间档（调研结论：
完全访问已覆盖会话级需求，多一档徒增选择成本 —— Claude Code 文件写允许即
会话级、Qoder 面板亦无此档）、「生成中」等更多侧栏 tag、
OS 级沙箱、「自主模式」实现（占位待 exec/network）。
