# 计划 — 工作区与会话真实化（.cogent / 项目 / 会话）

> 状态：**已定稿**（2026-11-09 用户评审通过；补充决策 D7：项目类型只做本地，
> 云端/远程置灰禁选是终态——见 §3.5 与 §6）。索引与空位标注已同步。

## 0. 背景与目标

首页侧栏（项目/置顶/最近）仍是 `features/home/data.ts` 静态演示域：演示会话行点击
不选引擎会话（行与内容错位）、真建的引擎会话在侧栏无条目、会话只在引擎内存
（重启全丢）。本计划把 **存储根、项目（= 工作区目录绑定）、会话（= 持久化 + 侧栏
真实化）** 一次规划、分步落地。

## 1. 已定决策（2026-11-09 讨论，不再翻烧饼）

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 第一方存储根 = `~/.cogent/`，**不再用 userData** | 用户（开发者受众）可发现/可备份；规避 dev 态 userData 落在 `%APPDATA%\Electron` 的坑。对齐 `~/.codex` / `~/.zcode` 惯例 |
| D2 | 单一存储根、按域分**单写者**：main 写凭据/壳配置，引擎写会话/项目 | 双写者是事故源；两进程各管各的文件，互不碰 |
| D3 | **项目 = 目录绑定**（`{ id, name, cwds[] }`，多根、首个为主根），会话可归属项目并继承全部目录 | 对齐 Claude Code/Cline；多根收编（2026-11-09 二次决策）：跨仓库任务（前端+后端两仓库一个项目）是主流既定能力（VS Code workspace / `--add-dir`） |
| D4 | 不做 `.cogent/` 内嵌项目目录、不往用户仓库写任何文件 | 主流共识：工作区侧只**读**（AGENTS.md）；项目级设置按 cwd 键控存全局 |
| D5 | 会话文件存 **pi 完整转录**（AgentMessage[]），`ChatMessage` 只是读时投影 | 恢复历史要保真（思考块、将来的 toolCall）；投影丢信息不可逆 |
| D6 | 引擎侧**不做 OS 级沙箱**，工作区边界走软约束（提示词声明 + 将来审批判定） | Windows 沙箱成本高；硬边界归 空位 #2 审批流一起做 |
| D7 | 项目类型**只做本地**，云端/远程置灰禁选（终态非占位），后面再说 | 用户拍板 2026-11-09；引擎无对应能力，先不摊 |

## 2. 存储布局与归属

```
~/.cogent/                      # 根（COGENT_HOME 环境变量可覆盖，冒烟测试指临时目录）
├─ credentials.json             # main 写｜现有格式不变（version 1 + safeStorage 密文）
├─ custom-providers.json        # main 写｜现有格式不变（明文定义）
├─ settings.json                # main 写｜会话级偏好（选中模型/思考力度；2026-11-09 追加）
├─ projects.json                # 引擎写｜{ version, projects: [{ id, name, cwd, createdAt }] }
└─ sessions/
   └─ <sessionId>.json          # 引擎写｜{ version, summary, transcript: AgentMessage[] }
```

- safeStorage 密文按 Windows 用户账户（DPAPI）加密，**与路径无关**，搬家只需重写文件。
- 覆盖口 `COGENT_HOME`：冒烟脚本/测试指临时目录，不污染真数据（同 `COGENT_NODE_BIN` 手法）。

## 3. 协议变更（只增不破，纪律见 约定.md §2）

```ts
// SessionSummary 加 optional 字段（旧宿主忽略新字段即兼容）
interface SessionSummary {
  id: string; title: string; createdAt: number; updatedAt: number
  cwd?: string          // 工作区目录（无项目也可单绑）
  projectId?: string    // 项目归属（继承项目 cwd；两者可并存）
  pinnedAt?: number     // 置顶时间（缺省 = 未置顶；置顶分区按此倒序，新置顶在上）
}

// session.create 参数扩展
'session.create': { params: { title?; permissionMode?; cwd?; projectId? }; result: SessionSummary }

// 新 method（session 置顶 + project 域）
'session.setPinned': { params: { sessionId: string; pinned: boolean }; result: SessionSummary }
'project.list':   { params: {}; result: ProjectSummary[] }
'project.create': { params: { name: string; cwd: string }; result: ProjectSummary }
'project.rename': { params: { projectId: string; name: string }; result: ProjectSummary }
'project.delete': { params: { projectId: string }; result: { deleted: boolean } }
```

main 的 `ipc/engine.ts` 方法**白名单同步加 `project.*`**（代理有白名单，漏加 = 请求到不了引擎）。
目录选择不走引擎协议：main 加 shared 域 channel `workspace:pick-directory`
（`dialog.showOpenDialog` openDirectory），preload 暴露 `pickWorkspace()`。

## 4. 分步实施（每步可运行、三关全绿后再走下一步）

### 第 1 步 — 协议先行 + 引擎存储（路线空位 #3 本体）✅ 已完成（2026-11-09）

- `agent-service/storage/`：`StorageDriver`（文档集合 list/get/put/delete）+
  `JsonStorageDriver`（`<root>/<collection>/<id>.json`，惰性建目录）。「本地优先、
  将来接云只换实现」即此接口（架构.md §1）。
- SessionManager：
  - 启动 `load`：全量摘要进 `session.list`；**pi Agent 惰性重建**——恢复的会话只在
    首次 submit 时实例化并灌转录（`initialState.messages`），不跑不占；
  - 会话 id 改 `crypto.randomUUID()`（现 `s-${nextId++}` 重启归零，与盘上文件**必然撞号**）；
  - 写时机 = 回合边界（create/delete 同步写，agent_end 落转录），不逐 delta 写；
  - 落盘失败不崩引擎、不吞 `run.completed`：catch 记录、转录留在内存，下次回合重写
    （约定.md §1.1 外部失败常态；重演串话修复的教训——异步段必须兜住）。
- `ChatMessage` 投影修正：assistant timestamp 现取 `Date.now()`（session.ts:318），
  改用转录真实 timestamp，否则恢复的历史时间戳漂移。
- 冒烟：create → submit → 杀引擎重启 → `session.list/messages` 复原 → 续聊模型可见
  全部上下文（协议级 mock 端点核对外发请求体，串话修复同款手法）。

### 第 2 步 — 存储根迁移 ~/.cogent（main 侧）✅ 已完成（2026-11-09）

## 5. 边界与风险

| 风险 | 对策 |
| --- | --- |

| 全量转录落盘体积随长会话膨胀 | 先接受（Codex jsonl 同为全量）；裁剪属上下文压缩后续件 |
| dev/打包共用一个 `~/.cogent` | 接受（`~/.codex` 同理）；隔离需求走 `COGENT_HOME` |
| 卸载残留 `~/.cogent` | 接受（用户数据本就不该被卸载器清掉，与 dotfolder 惯例一致） |
| 中途目录被删/移动 | 第 6 步 submit 复查 → `run.failed` 显式报错，不静默 |
