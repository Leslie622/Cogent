# 项目目录交接

项目编辑增删/排序目录，或移除项目时，Host 在空闲边界交接依赖目录的运行资源。
入口：`SessionManager.updateProject/deleteProject`、`kernel/pi-session-factory.ts`、`stores/chat/events.ts` 与 `file-navigator-owner.ts`。

| 身份 | owner 与生效规则 |
| --- | --- |
| 项目绑定 cwds | Host ProjectRegistry，保存成功才发布 project.changed |
| 本次工作 cwd/roots | SessionManager 根快照；显式 session.cwd 在前，再追加去重的项目根；否则取项目首根，无绑定回落主目录 |
| 转录锚点 piCwd | 会话创建时固定并持久化；旧记录缺失时在换根前补存；只决定 JSONL 定位，不决定工具 cwd |
| 文件导航 owner | renderer 按 scope/project/session/根内容认领；换根立即释放所有前后台旧导航，迟到回包只归还旧上下文 |

```text
project.update / delete -> 检查所有归属会话 -> 预约项目交接
 -> 固定旧转录锚点 -> 取消辅助标题 -> 等旧 pi abort/session_shutdown/dispose
 -> 保存项目 -> project.changed -> 文件导航换代/关闭旧上下文
 -> 下一次 submit/compact 从原 JSONL 装配新 cwd、指令、MCP、技能与工具
```

- 准备、回复、自动续写收尾、手动压缩或目录交接中的项目拒绝换根/移除，提示先停止或等待。
  交接期间相关会话 submit/continue/compact、新建会话及项目并发编辑不能进入；其他项目继续使用。
  只改名而根完全相同不重建运行资源，可在运行中执行。
- 清理失败不发布新项目；已释放的实例下次按旧配置重新装配。写盘失败同样保留旧项目。
  多个会话全部等退出后才结束交接，不能因第一个失败就提前解锁；引擎退出时禁止迟到提交。
- 新一轮的系统提示、工具、技能展开、MCP 装配、审批相对路径和消息来源共用根快照。
  pi 会话树沿原文件追加，不迁移、复制或改旧 header；历史来源保留当时 cwd/roots。
  运行数据与转录物理位置分开，历史读取、搜索和删除继续用原锚点。
- 换根后若旧回合有已保存的不同目录来源，手动续写明确要求发送新消息。现有 turnId 文件来源合同
  不能同时表示两个目录版本；保留旧回合来源，不把它重写为新根。自动续写处于同一运行预约，不受空闲换根影响。
- 项目移除不级联删会话；继承会话下轮回落主目录，显式 cwd 保留。项目新根中不存在的目录在提交时明确报错。
- 文件导航按 project.changed 换代，旧搜索/分页/打开结果不能覆盖新树；后台导航也立即取消并关闭 watcher。
  主进程从 Host 会话摘要取显式 cwd，并排在项目根前；sessionId 必须与工作区 scopeId 一致。
  已打开历史文件的独立 lease 沿原来源保留，导航关闭不夺走其他调用方持有的文件。

验收：`tests/integration/project-roots.test.ts` 用真实 Host/pi/工具验证 A→B、多根、显式 cwd、
指令/技能/MCP、相对读写与审批、无 pi 的首次发送、重启、移除、历史和删除。
`session-preparation.test.ts` 覆盖准备/压缩阻塞、扩展退出及写盘失败、交接期间并发；
`file-navigator-owner.test.ts` 与 chat store 回归覆盖后台清理、旧回包和外部更新。
真实产品入口为 `node scripts/check-project-roots-electron.mjs`，结果和未测范围见[架构可靠性验收](../测试用例/架构可靠性.md)。
