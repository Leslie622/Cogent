# 应用启动

主窗口入口为 `src/renderer/src/App.tsx`，启动呈现组件为
`src/renderer/src/components/StartupOverlay.tsx`；视觉配方见[UI布局](../UI布局.md)。

## 初始化交接

`App` 先订阅引擎事件，再并行调用 engine store 与 chat store 的 `load()`。
等待两个 Promise 完整结束，包含自定义模型同步、目录刷新和首次选中会话的历史读取；
engine store 中途发布的 `loaded` 不作为遮罩退出条件。Host 的初始化与就绪发布仍由原链路负责。
外壳在遮罩下正常挂载，退出时不重新挂载页面。独立控制台和内嵌 demo 不经过主窗口 `App`。

```text
App（初始化 owner）
  订阅事件 → engine.load ─┐
           → chat.load ───┴→ 本轮初始化结束 ─┐
StartupOverlay（呈现 owner）                 │
  首次挂载 → 最短展示计时完成 ────────────────┴→ 淡出 → 移除遮罩、恢复交互
```

遮罩至少展示两秒；初始化更慢时继续等待，完成后直接淡出，不追加两秒等待。
遮罩存在期间，页面容器使用 `inert` 与 `aria-hidden`，阻止鼠标、键盘和辅助技术进入尚未揭开的页面；
淡出结束后一起恢复。定时器随组件卸载清理，StrictMode 上轮 effect 的迟到完成不得解除本轮等待。

## 失败与验收

两路 `load()` 在原有边界将失败记录到 `engineError` / `loadError` 后结束。
遮罩按相同展示与淡出规则退出，随后显露真实错误、宿主诊断和原有重试按钮，不把失败卡成永久 spinner。
重试沿用现有数据加载，不重新触发启动遮罩。

验收：快速启动不提前揭开页面；超过两秒的任一路加载仍保持遮罩，完整加载结束才淡出；
淡出完成前页面不可操作，完成后页面身份保持；初始化失败可查看错误并重试；
StrictMode 旧初始化不会提前结束当前等待。自动时序回归见
`tests/renderer/components/startup-overlay.render.test.tsx`，实际透明度与定位须在 Electron 中检查。

原理与同主题源码对照见[应用启动遮罩笔记](../技术笔记/应用启动遮罩.md)。
