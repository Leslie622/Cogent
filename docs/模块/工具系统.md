# 工具系统

自带 `read_attachment` 为附件按需读取入口：只做本地文字提取，不委托 MCP，属于 read 类；
图片、音视频等由模型带着原件路径直接调用工具（多为 MCP），按运行时元数据分级并经过审批链。
原件、资源预算与验收见[附件模块](图片与文件附件.md)。

成功 read/write/edit 的结构化路径由文件引用扩展按实际 cwd 登记，含嵌套调用；
工具卡与正文唯一文件词表共用该事实，不解析摘要或 shell 文本。机制与验收见[正文文件链接](正文文件链接.md)。

`report_outputs` 为 read 类宿主工具，模型直接申报交付清单，完整替换/清空、最终工具确认与持久副本见[产物文件卡片](产物文件卡片.md)。

> 工具执行面 = **pi 内置 8 工具选 7**；
> Cogent 负责策略投影和宿主工具：工具名 allowlist、ToolKind、写类软边界，以及交互/附件工具。
> 落点：`src/host/kernel/pi-session-factory.ts`（装配）、
> `src/host/runtime/{tool-meta,write-boundary}.ts`（策略）、`session.ts`（审批接线）。

## 工具集与命名映射（runtime/tool-meta.ts）

- `COGENT_TOOL_NAMES` = read / **powershell（win）或 bash（其他）** / edit /
  write / grep / find / ls —— 经 createAgentSession 的 `tools` allowlist 显式
  指定（替换 pi 默认的 read/bash/edit/write 四件）；另追加
  `MCP_TOOL_ALLOWLIST`（`mcp__*` + `tool_search` + 资源三件）—— pi 的显式 tools 列表会过滤
  扩展注册的工具，不列名则 direct 档 MCP 工具注册但不声明给模型
  （[MCP座.md](MCP座.md)）；
- v1 旧转录名映射：**glob → find**；bash 在 win 由 powershell 替代（无 Git
  Bash 的 win 机不再依赖系统 bash）。旧转录里的 `glob` toolCall 块由静态
  表的历史条目兜住（kind 同只读）；
- ToolKind 是 Cogent 的产品语义 + 协议兼容投影（`tool.*` 事件与
  ToolCallRecord 都带 kind）：read/grep/find/ls → read，write → write，
  edit → edit，bash/powershell → exec。pi 内置工具不带 annotations
  （决定 28 勘误：上游无此信息），静态表是唯一 kind 源 —— 未装配内核的惰性
  会话历史回查也依赖它（那时无工具实例可查）；
- MCP 工具由 Host 连接池目录提供运行时元数据：已受信服务的只读且非破坏性 annotations
  投影为 read（ask 仍询问），未知/破坏性为 exec；纯静态历史缺元数据时仍用前缀 exec。
  `tool_search` 和资源三件按只读放行，默认 deferred 经搜索激活，见[MCP座](MCP座.md)。

## pi 内置行为要点（Cogent 消费面须知）

| 维度 | pi 内置行为 |
| --- | --- |
| 文件搜索 | find（spawn fd；PATH → `PI_CODING_AGENT_DIR/bin` 自动下载；gitignore 语义经 fd git-aware） |
| 全文搜索 | grep（spawn rg，同上获取链） |
| 读截断 | 50KB / 2000 行，`[Showing lines … Use offset=…]` 续读指引 |
| grep 长行 | 单行 500 字符 `... [truncated]` |
| shell 平台路由 | win 就叫 powershell（工具名即方言；UTF-8 前置 + #8842 退出码尾缀） |
| 输出护栏 | OutputAccumulator（尾保留 + 转存临时文件 + `Full output` 提示） |
| 并发写队列 | withFileMutationQueue（realpath 键 Promise 链，同文件串行） |
| 写边界 | pi 不限路径；根内判定在**审批层**（见 [审批与权限.md](审批与权限.md)） |
| 引擎退出清场 | 无（pi 只管 abort/超时杀；unix 上引擎退出时在跑命令留孤儿是上游语义） |

## 外部二进制依赖（fd / rg，部署事实）

- find/grep 分别 spawn `fd` / `rg`：先查 PATH（fd 兼容 `fdfind`），没有则从
  GitHub releases 下载进 `PI_CODING_AGENT_DIR/bin`（Host 入口 wrapper 把该
  env 归位到 `<COGENT_HOME>/pi`，Host 保持 `~/.cogent` 唯一写者；
  `PI_OFFLINE=1` 关闭下载）；
- **时机陷阱（验收翻车实证）**：pi 的 tools-manager 在**模块加载期**就把
  工具目录冻结成 `getBinDir()` 的返回值 —— env 赋值晚于 pi import 即失效
  （且静态 import 恒先于模块体执行）。所以归位必须住在入口 wrapper 里
  （`src/host/index.ts`：赋值 → 动态 import 真身），回归钉 =
  `tests/integration/pi-bin-domain.test.ts`（无 env spawn + 种 fd）；
- 两者皆不可得时工具返回 error 结果（`fd is not available…`），引擎不崩，
  其余工具（纯 node 实现）不受影响 —— 降级可见，不静默；
- 信创内网 GitHub 资产域不可达 = find/grep 不可用：缓解 = 分发期预置
  fd/rg（zcode 同款 SHA 固定下载思路，列后期批次），风险登记见计划 §9。

- 验收：win 上 shell 工具名为 powershell 且 UTF-8/#8842 语义正确
  （ps-utf8 冒烟对 pi 工具端到端）；read 截断带 offset 续读指引；同批并发写
  同文件内容不交错；越界写在 ask 档弹面板可手许、规则永不覆盖越界，
  auto/autonomous 直行（见 审批与权限.md）；
  abort 后无孤儿进程；fd 不可达时 find 返回 error 结果且引擎存活。

## 协议接口

事件 `tool.started / tool.progress（pi onUpdate 快照，尾 2000 字符）/
tool.completed（含 diff?——pi edit 的 details.diff）`；投影 `ToolCallRecord`
（kind/摘要取静态元数据表，历史名兜只读）。审批拦截不在工具层 ——
判定矩阵在 session 层（见 [审批与权限.md](审批与权限.md)）。
