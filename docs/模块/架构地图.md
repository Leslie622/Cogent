# 架构地图

独立静态文档项目，入口为 `docs/架构地图/`，运行命令见
[项目说明](../架构地图/README.md)。侧边栏只有「架构总览」，模型展示核心目标架构，
图中的能力状态不表示后端已经按目标结构拆分。后端目标与依据见[目标方案](../计划/架构地图目标架构.md)。

## 内容与数据流

```text
owner: 架构.c4 = 组成、关系与视图；模块说明.ts = 职责、能力状态与出处；LikeC4 = 一般布局；布局适配 = Runner 局部投影

架构.c4 → LikeC4 Vite 插件 → 布局模型 → 布局适配 → React Flow 画布
普通模块点击 → selectedId → 画布聚焦 + 模块说明
服务层 / 执行能力点击 → viewId → 该模块详细视图 → 返回总览
```

- 模型有总览、接入、执行三个主视图，以及服务层、执行能力两个详细视图。主视图通过工具条切换；
  服务层在 Host 内显示摘要卡片，执行能力在 KernelRunner 内显示摘要块，带展开图标，点击直接进入对应详情，工具条提供返回总览。
  服务层详情展开会话与任务、项目、凭据桥、观测、能力配置，只保留 API、服务与内核的调用参照，不显示执行能力参照。
  能力详情只展示执行能力父块与工具、MCP、技能、钩子、交互、子会话六类能力，不放外部服务或内核参照节点。
  网络入口在接入视图展开为 HTTP、WebSocket。
- 场景在传输入口左侧独立呈现：桌面壳连接 stdio；网络调用按 Cogent 原生调用、自有协议调用方和 MCP 适配分别接线。
  自有协议调用方包含 UI（远程、内嵌、自定义）与远程服务，说明在右栏呈现；远程不限定是否有 UI。
  调用方卡片以点线直接连接自定义协议适配，标明「协议适配关系」；该线表示消费关系，实际调用仍经过传输和认证。
  接入视图保留 HTTP、WS 的独立接线；网络入口只负责传输，MCP 转换后的调用进入 Cogent 原生分支。
  外部 Agent 通过标准 MCP 接入 MCP Server，转换后才进入网络入口，图中不展示脚本场景。
  目标接线区分身份认证、Cogent 原生协议、自定义协议适配、权限检查与 HostApi 分发；
  两条协议分支汇入同一个权限入口。HTTP 与 WS 分别连接认证，用户身份来源在接入视图展示。
- 传输入口边框表示技术分类；Host 大框包含接入处理、Host 服务层和 KernelRunner。
  KernelRunner 是执行容器，内部保留三张可点击卡片，依次为执行能力、PiSdkKernel、其他内核；服务与模型适配的调用线只连接容器边框，不伸入内部卡片。
  传输入口纵向展开：桌面壳、stdio、原生协议、权限检查与 HostApi 对齐；网络入口与身份认证、自有协议调用方对齐。
  这两条入口线直接水平连接，避免穿过容器标题区折返。Host 按接入与协议、业务分发、内核执行三个阶段横向展开；
  HostApi 与服务层相邻，服务层直连 KernelRunner，后者直连模型适配。执行能力作为 KernelRunner 的直接子块，与 PiSdkKernel、其他内核并列，以可点击卡片呈现，详情继续使用能力卡片，不是请求必经的执行阶段，也不接装配线。
  KernelRunner 对应当前 CogentKernel 接口，
  不是独立进程；其他内核为预留。执行能力混合使用 pi 内置工具、官方 MCP 扩展与 Cogent 注入的工具和钩子，由 PiSdkKernel 完成当前适配；子会话待完成，不宣称已有独立跨内核能力总线。Host 服务层仍在 KernelRunner 外，负责业务与配置治理。
  自带 Node 22 在容器标题旁说明，安全边界在容器底部说明，不各占卡片或接线；Node 承载整个 Host，入口授权与工具审批分别检查。
  模型协议适配处理 Cogent 调用远端，
  与外部调用 Cogent 的入站适配分开。DSL 以 `call`、`configuration`、`assembly`、`dependency` 区分调用、配置、装配与消费关系：
  配置治理与注册装配的结构关系保留在模型中，所有用户可见视图均隐藏 `configuration`、`assembly` 连线，不以无箭头线或虚线替代。
  自有协议调用方到适配层为消费关系，保留开放箭头。
  节点状态集中维护在 `模块说明.ts`，未实现关系在标签旁显示橙点，并提供「未实现关系」可访问名称；完成度不改写关系线型。
  双箭头标请求与响应、事件的两个方向。大区块隐藏状态，样式与常驻紧凑图例见 [UI布局](../UI布局.md#架构地图)。
  身份认证、权限检查、执行能力、模型协议适配的能力明细由 `模块说明.ts` 的 features 提供；节点与右栏共用同一列表，区分已完成与待完成的具体内容。运行基础与安全策略的说明和出处归属 KernelRunner。
- MCP 协议适配明确显示为独立 MCP Server：工具处理函数把标准 MCP 工具调用映射到 Cogent
  方法，HTTP 发送原生帧，WS 接收任务事件，结果与错误包装回 MCP。它区别于 Host 内待实现的
  自定义协议适配。实际机制见[对外MCP](对外MCP.md)，通道边界见[HTTP通道](HTTP通道.md)。
- `src/布局适配.ts` 把 LikeC4 绝对节点坐标转换成父节点相对坐标，保证父节点先输出。
  总览与两个模块详情由 `scripts/layout-architecture.mjs` 调用 LikeC4 `layoutHints` 指定行列与主链权重；
  能力说明块与主链分别排布，适配消费关系不参与总览主链排序；配置与装配关系不进入可见视图的连线。官方 `save-view-snapshot` 保存生成的
  `.likec4/` 布局快照，开发、构建与测试前自动刷新；快照不入库，结构与关系仍只在 DSL 维护。
  DSL 使用 `autoLayout LeftRight … ortho`；LikeC4 提供模型与一般布局，布局适配仅对总览、执行视图的 Runner 内部和相邻三条主链作受限投影。
  三张原有卡片单排，间距 24px，容器内距为左右 24px、顶部 56px、底部 40px，Runner 约 636×196 布局像素。
  Runner 与服务层垂直中心对齐，服务层连接其左中点，右中点连接模型适配；模型适配与远端模型保持同一水平线并按 160px 间距接续。
  Host 按直接子节点包围盒收紧；位置、bounds、连线路径、标签与跨线标记统一使用投影后的几何，其余路径保留原生通道与小圆角。
  标签使用 LikeC4 几何接口根据最终路径共同放置，与所有连线保持至少 6px 间距；
  SVG 遮罩直接使用经过布局校验的尺寸，不在渲染时额外扩宽。
  网络入口由 LikeC4 折叠子元素、聚合关系；总览接线标题在 DSL 视图内覆盖，细图保留原始含义。
  多对多关系出现交叉时，在后绘制连线的交叉点留白，明确跨越；不更改原生路由。
  适配器保留 LikeC4 关系的种类、线型与箭头形状，React Flow 按这些数据呈现；关系语义与完成度分别投影。
- 节点直接使用共享 Card、Button，工具条和面板使用共享 Tooltip、Tabs、Separator，左右栏使用 Collapsible。
  不加载 LikeC4 内置 Mantine 界面；节点控件也不放入 shadow DOM。
- 点击节点会聚焦模块，右栏提供职责、技术边界与可复制的源码路径；点击空白、
  恢复总览按钮或侧栏入口清空选择。右栏折叠时仍保留模块选择，展开后显示对应说明。
- 左右折叠由页面局部状态管理，不持久化。Collapsible 保留内容挂载，关闭侧栏同时设为
  inert，退出键盘与可访问树；右栏内容独立滚动，画布与页面保持原位。
- 画布监听视口尺寸，侧栏收放后重新定位当前视图或选中模块。默认缩放至少 85%，
  从左侧入口开始，横向拖动阅读；适应画布可缩小到全图，恢复总览回到默认阅读视口。
  React Flow 13 的 padding 使用像素：左右 32px、上 120px、下 80px，为上方图例与操作控件留空间。

## 外观与构建

- `src/main.tsx` 只绑定共享 `bindAppearanceDom`，不启动主 App、聊天初始化或 Electron 桥。
  明暗偏好使用现有 appearance store，存储在当前文档来源的 localStorage；与桌面应用
  使用同一明暗和字号投影逻辑，但不跨来源同步偏好；彩色皮肤不作用于文档容器。
- 页面样式导入共享 `globals.css`，只额外定义布局和画布元素；视觉配方与响应式布局见
  [UI布局](../UI布局.md#架构地图)。
- `vite.config.ts` 固定 LikeC4 1.61.0，通过 React 去重避免共享 UI 产生第二份实例；
  TypeScript 的 React 类型也统一解析到根依赖。根依赖与独立项目依赖都须安装。
  开发服务显式允许读取独立项目和仓库 `src/`，共享字体才能通过 Vite 路径检查。
- 生产构建将脚本、样式与字体嵌入 `dist/index.html`，可通过 `file://` 离线使用。
  字体完整嵌入使文件约 35MB；开发服务按需加载源文件，不读取该单文件产物。
- 根 Electron 构建不打包该文档。布局测试在独立项目 `tests/`；浏览器检查入口为
  `scripts/check-architecture-browser.mjs`，不启动 Electron 或遗留服务器。

验收：三栏布局，中栏包含图、紧凑图例与操作控件，左右可独立收放、图随可用空间重新适配，
右栏独立滚动；明暗模式均为中性色，侧栏仅一个总览入口；模块说明、源码、缩放、平移、
复位与键盘触发可用；Host 服务层位于 KernelRunner 外，KernelRunner 内直接包含 pi SDK、其他内核和执行能力卡片，运行时与安全边界以容器说明呈现；
Host 宽度不超过 3000 布局像素；HostApi 到服务层、服务层到 KernelRunner、KernelRunner 到模型适配均直接水平连接；
三主视图切换、两模块点击进入详情、子模块选择与返回总览有效；
模型保留配置治理与能力装配关系，所有可见视图均无这两类连接线；执行能力在 KernelRunner 内独立呈现，详情仅含父块与六类能力；
主调用与适配消费关系完整，常驻图例仅含调用、适配依赖和未实现状态，能力状态、未实现关系橙点与返回方向可见；
接线横向、正交、无共享线段，交叉处明确跨越，端口贴边且不重叠，标签避开节点与所有连线；
默认保持可读字号；1920、1440、1024、390px 页面无溢出，卡片内容无裁切，适应按钮可显示全图；
离线打开无外部资源请求及浏览器错误。自动检查命令见项目说明。
