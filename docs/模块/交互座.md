# 交互座

> 交互工具族（todo_write / ask_user / enter_plan + submit_plan）—— Host
> 特有工具经 pi `customTools` 注入，挂起/回填复用审批模块的骨架
>（pending Map + 北向事件 + respond 方法 + abort/settle 收尾）。
> 落点：`src/host/runtime/interact-tools.ts`（工具定义与纯函数）、
> `runtime/session.ts`（桥：挂起表与状态）、`kernel/pi-session-factory.ts`
>（customTools 透传 + sections 段钩子）、renderer `features/home/`
>（TodoStrip / QuestionPanel / PlanPanel）。

## 数据与生命周期

```
模型调 todo_write ──→ 桥：Session.todos 全量替换 + persist + todos.updated ──→ TodoStrip
                          └→ 新 run 的系统提示 cogent_todos 段（before_agent_start 活算）

模型调 ask_user ──→ 校验（问题/选项唯一、禁自带「其他」）
                    └→ execute 挂起（pendingQuestions）── question.asked ──→ QuestionPanel
                          ↑ signal abort → cancelled 收口 ↘
宿主 question.respond（按问题序作答）──────────────────→ resolve(answers)
                    └→ 答案文本（全答/部分/取消三态）回灌转录 → 下一轮可见

模型调 enter_plan ──→ setPlanMode(true)（幂等；permissionMode 不动 —— 正交开关）
模型调 submit_plan（开关开启时）──→ execute 挂起（pendingPlans）── plan.requested ──→ PlanPanel
  ├─ 批准 → planEnabled=false + StoredSession.plan 落账（档位不动，原档自动恢复）
  │     → 结果含批准回执 + 方案全文；新 run 起 cogent_plan 段常驻（压缩不丢）
  ├─ 拒绝无反馈 → isError + terminate 停轮（控制权交还用户；开关保持开）
  └─ 拒绝带反馈 → isError + 反馈进结果（模型修订重提）
开关未开调 submit_plan → isError 指引文案（不挂起）
```

- 计划是**正交开关**（`summary.planEnabled`），与权限三档两字段独立
  （zcode planEnabled / dsh chip 同构；模块/审批与权限.md）——
  enter_plan 不覆盖档位，批准不切档，UI 双入口（权限菜单顶部 toggle 项 +
  权限钮旁 PlanToggle chip，同数据源同动作）；
- 会话删除/引擎退出：settleInteractions 把挂起提问（cancelled）与方案审批
  （拒绝）批量收口——与 settleApprovals 同点调用；
- 工具 kind='read'（tool-meta 表）：审批链直通（任何档位/开关态）——挂起交互的
  "审批"就是工具自己的面板，与工具执行审批链正交。
- MCP Elicitation 由 `runtime/mcp-elicitation.ts` 单独持有挂起表，按调用会话处理 Form/URL，
  `ElicitationPanel` 经特权 `mcp:elicitationRespond` 回填；非法答案保留输入，resolved 事件精确收口，
  会话取消、超时及 Host 退出清理。它不是自定义 ask_user 工具，协议与验收见[MCP座](MCP座.md)。

## 怎么工作要点

- **customTools 注入**：`createAgentSession({ customTools })` 静态声明 +
  工具名并入 `tools` 白名单（pi 对 customTools 同样过 `_isAllowedTool`
  过滤）；`defineTool` 包装保参数推断（pi 官方姿势）；参数 schema 用
  TypeBox（`import { Type } from 'typebox'`）；
- **段双通道防失忆**（todo 与已批准 plan 同构）：转录里的工具结果（恢复
  回放天然含最后状态）+ 每回合活算的系统提示段（`cogent_todos` /
  `cogent_plan`，null = 撤段）——段是 zcode todo_reminder / plan 文件
  compact 续用的对应物，走 before_agent_start 的 sections diff（净变更史）。
  todo 段在全完成态追加空数组清空指令（仅靠工具描述引导，实测模型
  终答后不清、清单赖着不消——段是每回合常驻的催收尾通道）；
- **批准关开关**：plan.respond(approved) 只翻 planEnabled（session.
  summaryChanged 广播）+ plan 落 StoredSession（不写用户工作区——zcode
  plan 文件落盘是工作区污染，段方案更及时）；档位永不被 plan 触碰，
  「回原档」自动发生（无 prePlanMode 回退字段——zcode 运行时同判）；
  开关只读约束在 decideApproval 里**短路优先于档位放行**（完全访问 +
  计划开 = 只读）；
- **拒绝停轮**：pi 原生 `AgentToolResult.terminate`（"stop after the
  current tool batch"）——拒绝代表用户要继续讨论，模型自我重写计划只会空转。

## 边界

- 无 ask 超时/自动继续（zcode 5 分钟 answers:{} 是后台代理场景；桌面单用户
  前台，挂起时输入框即停止钮）；
- 无选项 HTML preview（安全校验成本 > 收益，label+description 已覆盖）；
- 无 TodoRead（双通道已闭环，那是 zcode SQLite 架构的补丁）；
- 工具跨档恒定（不按档收放目录：请求缓存/行为可预测，dsh 同判）。

验收：三工具经 mock LLM 集成测试一条到底（16 断言：清单/事件/段注入/
挂起/作答回灌/abort 收口/批准关开关与档位不变/未开计划拒绝，
tests/integration/interact.test.ts）；手动验收 = GUI 三面板（见 UI布局.md
与 测试用例/交互座.md）。
