# 钩子座

> Host 干预内核循环的统一装配点：段注入、审批包裹、请求取消检查与厂商观测。
> 原理对比见[钩子座笔记](../技术笔记/钩子座.md)。

## 是什么

各类干预与预留缝使用 pi 的官方形状（不自研插件运行时，全局架构 D7）：

| 干预 | 落点 | 形状 | 为什么是这个形状 |
| --- | --- | --- | --- |
| 系统提示段 | `runtime/hook-seat.ts` 的 `createCogentHooks`（具名 InlineExtension `cogent-hooks`） | `before_agent_start` 扩展事件 → `systemPromptOptions.sections` | pi 官方缝；活算 + diff = 回合边界热刷新 |
| 直接审批 | 同文件 `wrapApprovalChain`（factory 调用点挂装） | 链式包裹 `agent.beforeToolCall` | 保留 core 每次工具调用的 signal，再委托 pi 原链 |
| 嵌套审批 | `createCogentHooks.nestedApproval` | 官方 `tool_call` 事件按 parentToolCallId 筛嵌套项 | ctx.executeTool 绕过公开 Agent 包装；扩展 ctx.signal 提供 agent.signal，同一 ApprovalBridge 保持权限/停止/审计 |
| 请求取消检查 | 同文件 `wrapRequestCancellation`（factory 调用点挂装） | 链式包裹公开 `agent.prepareRequest` | 原 hook 前后检查同一 signal，已取消的准备工作不再进入 provider；保留原返回值与异常 |
| 厂商标量观测 | `runtime/inspector.ts`（AgentOptions 三回调，物理不入座、籍挂本座） | onPayload / onResponse / onProviderStreamEvent | 扩展事件版载荷缺 model 上下文，不等价不迁 |
| 上下文注入 | `createCogentHooks` 的 `context?` 异步可选位 | `context`事件，已有请求前条件产物提醒 | 成功写文件且未申报时最多一次，不额外起模型请求；交付契约见[产物文件卡片](产物文件卡片.md) |

## 怎么工作

装配期（每会话一次，`buildPiSession`）：factory 的 extensionFactories =
`[createMcpExtension?, createCogentHooks({ sections, nestedApproval })]`；直接审批包裹在
`createAgentSession` 之后套上（`session.agent.beforeToolCall =
wrapApprovalChain(原链, approval)`）—— 放行委托原链（挂 `tool_call` 的扩展
不失联），阻止返回 block（reason 进模型可见的工具错误结果）。
嵌套 `ctx.executeTool` 调 pi 私有 `_beforeToolCall`，不经过公开包装；具名扩展仅处理
带 parentToolCallId 的 tool_call，避免直接调用被重复审批。当前 ctx.signal 来自 agent.signal，
不能把分发器省略 signal 形参误读成扩展上下文完全无信号；升级 pi 时重查两条入口。
同一装配期还将 `agent.prepareRequest` 包成 `wrapRequestCancellation(原链)`：先检查
signal，再 await 原 hook，返回后再检查；不替换 pi 原请求准备逻辑。

产物工具另链式包裹公开`afterToolCall`，在pi完整tool_result扩展链之后提交声明；不修改pi循环或嵌套私有方法。

审批审计对：

- `approval.asked`：ask 路径弹面板挂起时记录（requestId / 工具 / 类别 / 摘要 /
  档位快照 / 根外标记）；
- `approval.decided`：**全判定路径**记录（plan 拦截 / auto / autonomous /
  工作区规则 / 用户允许 / 用户拒绝 / 允许并落规则 / abort 中止 / 收尾兜底），
  裁决词 → 呈现文案的映射收在 inspector 的 `VERDICT_LABELS`；
- read 类不经审批域，**两类条目都没有**（工具层已有 tool.started/completed，
  再记 read 放行只剩噪音）；
- 条目进 inspect 流（时间线实时推 + JSONL 落盘回看），运行时控制台
  「工具」层可见，`kinds.ts` 有两条学习注释。

owner：钩子注册表 = hook-seat.ts；审批挂起表 = session.ts（pendingApprovals，
条目含 toolName 供审计对账）；准备期停止意图/操作身份 = session.ts；观测流 = inspector.ts。

```text
Host abort -> 本次 owner.stopRequested -> pi started 交接取消 -> core signal.aborted
prepareRequest 包装 -> 检查 signal -> 原 hook -> 再检查 signal -> provider 请求准备
```

## 边界

- 审批**无超时**（D5 定稿）：用户不点就一直等，停止钮可 abort（signal
  listener 兜底 resolve，与用户裁决先到先得 —— 与 dsh「竞速 + 迟到答案
  构造性丢弃」同构，早于本座已存在）；
- 无第三方钩子生态：不做 matcher / 超时 / 进程级 hook 配置（zcode 有、
  Cogent 无此需求源）；三角色对账是文档级表格，不做 CI 守卫（dsh 有）；
- **pi 原生扩展发现面对 Cogent 会话仍在装载**：factory 用原生 `SettingsManager` + `DefaultResourceLoader` 且
  只关了技能面（noSkills + 空 skillsOverride，pi-session-factory.ts:190-200）
  —— pi 的自动发现（`~/.cogent/pi/extensions/` 与项目 `.pi/extensions/`，
  上游 package-manager.ts addAutoDiscoveredResources）与 settings 包
  （`packages` npm/git 源）对 Cogent 会话活着，现无管理面、无文档外消费者
  （**源码路径推断，未实测验证**）；插件座（D17 暂缓）重启时接管此面；
- 审计是尽力语义：记录失败不炸对话（inspector 既有纪律）；settle 兜底
  路径非抛查找会话，审计不许拦收尾。
- 取消检查不强制结束不合作的 await；检查之后的异步上下文转换/鉴权仍需 provider
  遵守 signal。不能把进入检查前已取消时的零请求，泛化成任意时刻、任意 provider 都零入口。

- 验收：ask 挂起 → 裁决后 inspect 流含 asked+decided 各一条（同 requestId
  可对账）；规则/计划/auto 放行拦截各有 decided 且无 asked；read 零审批条目；
  既有段注入行为与本座引入前等价（skills/interact 集成回归）。
  请求取消保留原 prepareRequest 结果与异常；原 hook 前已停止则不调用原 hook，
  await 期间停止则在其返回后结束，不进入后续 provider 工作。
  `tests/integration/mcp.test.ts` 验证 read_attachment 内层 MCP 的允许/拒绝/停止，不能仅凭 API 注释假定宿主审批已接通。
