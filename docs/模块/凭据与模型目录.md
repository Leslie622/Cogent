# 凭据与模型目录

> API key 的存取链路与模型目录的自定义体系（内置目录 / override / 自定义 provider）。
> 落点：`src/electron/main/credentials/store.ts`、
> `src/host/runtime/{credentials,custom-providers}.ts`、
> `src/renderer/src/features/settings/`（ModelsSection）、
> `src/renderer/src/features/home/{ModelMenu,ThinkingSlider}.tsx`。

## 凭据链路

MCP 仅将 OAuth 状态托管到独立 `mcp-credentials.json`，main 为加密存储唯一写者。
读取故障不阻断启动、旧文件保留；写入仍拒绝安全存储不可用和明文后端。静态 MCP 认证使用
配置或环境变量，无手动密钥管理与自动迁键；私有确认和CIMD前提见[MCP座](MCP座.md)，本页模型provider链路独立。

- main 侧 safeStorage 加密落盘 `~/.cogent/credentials.json`；加密/写盘成功后才替换缓存；每次启动现读并在握手时全量注入。
  启动期间的新增、替换、删除按顺序交接，队列排空才发布 running；普通请求等待此前变更。
  跨 await 核对 Host 代次，离线保存留待下次启动恢复；已保存但同步失败明确返回“已保存，应用到引擎失败”。
- 引擎内存表（runtime/credentials.ts）：key 只进不出；
- 协议：`credentials.set`（写入+进表）/ `list`（批量只回布尔位）/ `get`
  （按 provider 单取**明文**，设置页字段全量回显用——脱敏方案被否，点眼睛
  看明文）/ `remove`（真删，「清除」不是写空串）。

## 自定义 provider（runtime/custom-providers.ts）

- `createProvider` 构建 OpenAI-compatible provider（id `custom/<slug>`）+
  `setProvider` 运行时注入 + 内置 provider baseUrl 覆盖（闭包委托原实例）；
- 三方言：`openai-completions` / `openai-responses` / `anthropic`；baseUrl
  规则：openai 系带 `/v1`、anthropic 根地址；
- 定义由 Host 独占落盘 `~/.cogent/custom-providers.json`（明文，与 key 分离），启动恢复并注册，不依赖 renderer。
- 协议 `providers.custom.sync`（全量替换语义；renderer 写路径唯一化走
  custom-providers:set，防盘上/内存态分叉）。
- get/set 壳桥只代理 Host；候选构造成功后写盘再发布，普通读取不回写。字段校验、默认权限迁移与优先级见[业务配置](业务配置.md)。
  验收：写盘或加密失败不更新缓存；无 renderer 重启后定义和目录完整；启动中凭据变更有序交接。
  自动回归见 `tests/electron/main/credentials/store.test.ts`、`tests/electron/main/host/manager.test.ts` 与 `tests/integration/create-persistence.test.ts`。

## 模型自定义（ModelDef / override / 发现）

- `ModelDef`：id/name/contextWindow/maxTokens/input/reasoning/thinkingLevelMap（兼容旧 thinkingLevels）/thinkingBudgets/compat；
- `models.list` 的 input 下发有效 text/image 声明；覆盖优先于目录，目录外默认 text。
  模型表单继承有效 input 与 `thinkingLevelMap` 回显，关闭图片显式保存 `['text']`，不省略成重新继承。
  模型菜单选项、当前模型子菜单入口与设置模型行按同一有效 input 显示“视觉”标签；关闭后立即移除。
  同名模型在下一提交刷新定义，图片能力、端点等配置不沿用旧会话对象；不为此追加模型切换条目。
  输入框模型菜单用小号“视觉”标签表达图片能力，不显示输入声明说明行；未配置模型时仍可打开，
  原语分组结构见 [UI布局](../UI布局.md)。
  此声明不是端点实测；文档/视频的工具能力见[附件模块](图片与文件附件.md)。
- 内置目录 override：`ProviderOverrideDef.models`（用户新增，与目录并存）+
  `disabledModels`（目录禁用）+ baseUrl 空串 = 只调模型不动端点；左栏置顶常用 7 家，并可展开检索全部 `pi` 内置供应商。
- 同 id 覆盖 = **merge 语义**（目录基底 + 用户显式字段覆盖，cost 永远继承
  目录、全新 id 诚实 0）；目录行可编辑（shadow 目录同名项，可删除还原）；
- 新增或未命中目录时，结合 `src/shared/model-presets.ts` 主流模型家族预设自动填充上下文、输出、视觉、思考档位与兼容提示。
- 模型编辑分为「基础设置 / 思考配置 / 端点兼容」三页签，模型身份与保存栏固定；切换保留草稿。思考配置的「高级设置」统一展开协议映射和预算，默认状态不额外展示摘要。
- 供应商详情在模型列表之后提供「供应商兼容设置」，为全部模型提供默认值；模型内的兼容项只覆盖当前模型，逐项优先级为模型 > 供应商 > 目录或端点默认。
- 端点模型自动发现（`models.discover`）：安全请求 OpenAI `/models` 与 Anthropic `/v1/models`（15 秒超时、禁重定向、分页上限 20 页），支持搜索筛选并增量合入（不覆盖已调优模型）。
- 同名模型跨 provider 歧义：`agent.submit` 带 optional `provider`，引擎
  `getModel(provider, id)` 双键限定；
- **显示一律模型 id**（目录营销名不参与呈现，所见即所传）；
  `ModelSummary.userDefined` 标用户自建；默认（目录原生）模型编辑时 id 只读；
- 上下文窗口滑杆：线性轴 200K/400K/1M 三档吸附（ContextWindowSlider =
  components/StopSlider 通用件的域适配层）。

- 验收：同一模型在聊天菜单、设置页两处显示完全一致（均为 id）；key 输入
  后字段全量回显、清空 = 真删（remove）；同名模型跨 provider 不串（带
  provider 双键）；自定义 provider 三方言各能走通对应端点（baseUrl 规则
  注释与行为一致）；编辑目录原生模型时 id 只读，并无损回显原 `thinkingLevelMap`；
  模型菜单三种输入声明场景展开无上下文异常，并保留模型与思考力度入口；`models.discover`
  能拉取端点列表并增量合并。

## 思考（Reasoning）档位

- `thinkingLevelMap` 与 `pi` 原生 7 档（`Off` / `Minimal` / `Low` / `Medium` / `High` / `XHigh` / `Max`）同构，界面统一展示英文枚举名，支持禁用 `Off`（`off: null`）与按档自定义协议值；未选非 `off` 档统一显式落 `null`（不默认放行 `Minimal`）；开启思考必须保留至少 1 个非 `off` 档位。
- 引擎按 `thinkingLevelMap` 判定真实可用档（`getSupportedThinkingLevels`）；支持供应商级与模型级 `compat`（`thinkingFormat`、`supportsDeveloperRole`、`supportsReasoningEffort`、`maxTokensField`、`thinkingTokenBudgetField`、`forceAdaptiveThinking`、`supportsTemperature`）。
- 滑杆按支持档渲染、切模型及 `load()`/`refreshModels()` 时就近 clamp（先高后低）；
  会话级 thinkingLevel 随 agent.submit 下发。模型行保持简洁「思考」徽标（悬停提示有效支持档位）。

## 模型连通性测试

- 内置与自定义模型行共享测试按钮；供应商或模型禁用时不可测试，请求中显示转圈并阻止重复点击。
- `models.test({ providerId, modelId })` 按双键查 Host 有效目录，复用 pi 的路由、凭据、地址覆盖和方言。
  Host 只接身份，不接前端 key、端点或临时定义；不存在或已禁用的模型明确失败。
- 探测只发固定 system 提示与 `hi`，取最低支持思考档、输出预算 `min(512, 模型上限)`，不重试；
  60 秒取消请求并结束等待，收到正常完成事件才返回耗时。连接成功只代表该文本请求可用，未实测图片或工具能力。
- owner：renderer engine store 等待最近的定义保存与本供应商 Key 保存完成；失败阻止探测旧配置。
  Host 的 `runtime/model-connectivity.ts` 独立调用模型，不创建会话、转录、工具或聊天事件。

```text
字段失焦 → store 保存 Promise → 模型行点击并等待 → models.test
                                              → Host 有效目录 → pi 流式请求
                                              ← 耗时 / 错误 ← 完成 / 失败 / 超时
```

- Toast 在测试中、成功、失败间更新同一条反馈，始终带供应商与模型身份；成功显示耗时，失败显示具体原因。
  HTTP/WS 调用要求 write 档票据，因为测试会消耗模型请求额度。
- 验收：两类供应商均能测试；同名模型不串路由/Key；改地址或 Key 后立即点测试先等待保存；
  401、禁用、无完成事件及超时均不假报成功，失败可重试，聊天列表与当前模型选择不变。

## 聊天页模型菜单（ModelMenu）

- 厂商子列表**钻入式**（DropdownMenuSub：厂商行 → 模型子面板，点模型提交
  并全关）；只展示配了 key 的 provider 的模型；思考力度渐变滑杆同菜单。
- 行图标：「管理模型」= 齿轮+AI（IconSettingsAi，"管理 AI 模型"双语义，
  与侧栏普通齿轮区分，16px 对齐厂商标槽位）；「模型」分组标签 = 立方体
  （IconCube，单个模型单元，14px 随标签 text-xs、色随 muted）
  （2026-11-16，曾试 IconAdjustmentsHorizontal/IconCpu/IconBoxMultiple，
  语义不贴被否）。
- 菜单为**内容型放大形态**（dropdown-menu 原语 `size="lg"`，2026-11-16）：
  面板 rounded-xl + p-1.5，行/标签/分割线随 MenuSizeContext 放大一档
  （py-1.5 / gap-2 / 分割线 my-1.5）；子菜单经 context 继承自动跟随，不用
  逐个显式传。普通动作菜单（权限等）仍是默认紧凑档。
