# 图片与文件附件

> 附件服务、草稿和文档读取的事实入口。原理与三仓对照见
> [技术笔记](../技术笔记/图片与文件附件.md)，操作矩阵见[手测册](../测试用例/图片与文件附件.md)。

## 所有权与数据流

```text
owner: renderer 草稿仓 = 编辑/提交身份；main = OS 入口；Host = 原件/引用；pi = 转录
粘贴 / 拖拽 / 选择 -> 捕获 draftId + 卡片 key -> queued -> 最多2项并发
  路径描述 -> 原子预留容量 -> Host 导入 -> 实际大小复核 -> ready / error
  目录 -> 实时DirectoryRef -> ready；不复制、不上传；发送时复查路径
  超额 -> 未添加明细；合法部分继续；移除排队项不会开始复制
  移除 -> 取消、释放；迟到结果只清理原件，不复活卡片
发送 -> 冻结草稿 -> 按需创建聊天 -> 同步认领附件 -> run.started
  准备/完整性/图片解码 -> pi.prompt(text, {images}) -> 实际 user entry -> custom 元数据
  受理成功 -> 只消费该次快照；新编辑保留；新聊天沿用原 draftId 绑定到 chatId
```

- `src/host/runtime/attachments.ts` 保存 `<COGENT_HOME>/attachments/v1/`：
  `objects/` 为摘要命名原字节，`records/` 为不透明 id/元信息/会话引用，
  `staging/` 为未完成导入，`drafts/` 为草稿 manifest，`analysis/` 为长分析结果。
- 路径输入流式复制；内存 File 按 256 KiB 分片，经壳专用 RPC 写暂存，完成后发布。
  支持取消；文件原件移动/删除不影响副本。受管名不由原始文件名决定。
- 准入：普通文件不设数量上限，图片每消息最多20张，普通文件不占图片名额；
  100 MiB/文件、200 MiB 合计；原生图片 20 MiB/4000 万像素。批量部分接收，
  超额项列出名称与原因，合法部分可继续发送。路径先经 `attachments.describe` 取得
  大小/MIME再复制；File使用已有元信息。renderer全局FIFO与Host路径/分片共享槽均限2项，
  取消/发布完成后才释放槽；实际增长超额的副本释放，不进入就绪状态。
  图片检查实际头信息和声明类型，发送前另用 pi 公开 resizeImage 验证解码。
  这些是准入上限，不表示已测过所有容量/平台的性能。
- 准备和工具读取重新校验大小/SHA256。移除/草稿替换释放未认领引用；删除会话释放
  该会话引用；去重原件到最后一个元数据引用释放才删除。异常退出遗留的无引用记录、
  暂存和分析 artifact 不作自动全盘清扫，避免误删尚未恢复的输入。

## 草稿、消息与桌面入口

- `stores/attachments.ts` 独立于组件；Host manifest 持久化正文与就绪引用，
  localStorage 同步小日志覆盖 IPC 尚未确认的窗口。日志不保存 File/控制器/预览字节。
  中断导入恢复成可见错误；损坏日志明确报错；切聊天/审批卸载不清草稿。
  未发送新聊天由 home store 持唯一身份，点击入口复用；首条受理后原身份绑定已创建聊天。
  删除会话先让绑定草稿的恢复请求失效，再清除草稿。迟到的读取或原件校验不更新草稿或写回旧日志。
- `agent.submit` 接收 `attachmentIds?`、`directories?`、`inputId?`；正文可在有文件/目录引用时为空。
  排队/导入中/失败不能提交，未配置媒体工具可发送未解析引用；导入本身不创建会话。
- adapter 包裹 pi 公开 `sessionManager.appendMessage`：拿到返回的实际 entry id 后
  追加 `cogent.attachment-input.v1` custom entry，保存原始正文/inputId/引用。
  历史按 entry id 配对，压缩后仍保留；不按时间或显示位置猜归属。早停同样落元数据。
- 用户消息在正文上方靠右展示附件：图片方形缩略图与文件卡分行，行内保留发送顺序，
  窄窗口换行；纯附件历史不会被空正文过滤。图片不显示文件详情，导入/错误仍有简短提示。
  文件卡正常只显示名称/大小，大小按十进制 B/KB/MB 展示；不展示保存状态、解析工具或读取路线。
  卡片尺寸与文件名省略规则见 [UI布局](../UI布局.md)。
  图片 Dialog 放大；普通文件定位/另存；原件缺失可见，工具执行状态沿用工具记录。
- preload 使用 Electron 的 `webUtils.getPathForFile`；无路径 File 走分片。
  Windows 原生文件剪贴板走固定 STA PowerShell FileDropList 脚本，Linux 读文件 URI 格式。
  Excel 同时给表格 HTML/文字/位图时优先保留文字；普通文字保持原生粘贴。
- `attachments.*` 只允许桌面 stdio/IPC；HTTP 和 WS 连 admin 也拒绝。
  预览/导出只按受管 id，不暴露任意路径字节读取入口。

目录引用为独立`DirectoryRef {kind:'directory',name,path}`，经`attachments.describe`区分后
跳过复制，目录不计文件/图片容量；同一草稿的相同路径去重。加号菜单、OS目录粘贴/拖拽
走同一草稿链；日志/manifest/真实用户条目保存optional directories，老文件数据保持可读。
目录没有副本保证：移动/删除/变成文件时显示错误，草稿保留路径，恢复目录后可重试。
提交入口按实际绝对路径复查目录并重建名称；模型收到路径数据，按需用ls/find/grep/read读取，
未读取前不声称已读。引用不改变cwd、项目根、AGENTS加载或写类信任；移除/删聊天不删除原目录。

## 按需读取与能力

| 内容 | `read_attachment` 行为 |
| --- | --- |
| 文本/源码 | UTF-8/UTF-16LE 有界读取；nextCursor 续读，错误编码明确失败 |
| PDF | PDF.js 6 legacy 按页提取，使用磁盘 CMap/字体/wasm；不渲染页面；无文字页可委托 document MCP |
| DOCX | 受限 OOXML 读标题、段落、表格；不处理页面排版/修订/批注/嵌图 |
| XLSX | 命名空间感知的内存投影供ExcelJS读取列表/范围/值/公式/缓存；原件不变，无缓存标未计算，不重算或刷新外链 |
| PPTX | 按关系命名空间属性和任意关系ID读实际页序、文字/表格/备注，支持包内相对/绝对目标；不分析图片、SmartArt、动画 |
| 图片 | 有效模型声明含 image 时原生发送；否则按需调用 image MCP |
| 视频 | 按需调用 video MCP，保留主推理模型；不抽帧/转码/转写 |
| 其他/旧 Office | 无内置解析器；可交 document MCP，未配置时保持未解析原件和可读路径 |

本地解析最多同时 2 个 worker、单次 30 秒、V8 old heap 256 MiB；可取消排队和运行。
OOXML 先查展开预算 128 MiB、10000 项、单项 32 MiB，拒绝 DTD/实体；XLSX 单范围
最多 5000 格。输出每次最多 24000 字符，分页或保存完整 artifact 并给 read 路径。
worker 堆限制不是所有原生/ArrayBuffer 内存的硬上限。
XML使用命名空间URI识别关系属性；外部关系、越过包根、编码逃逸与错误部件类型均拒绝。

媒体绑定存 `media.json`，设置 → MCP 服务器中配置 image/video/document：server、工具名、
字符串路径/问题/可选页码映射、格式/容量、视频音轨声明；会话装配时与 MCP 一起快照。
只接受能读取同一 Host 文件系统的 stdio 服务；HTTP/仅 URL/schema 不符/无文本返回明确失败。
嵌套执行用 `ctx.executeTool`；审批双入口见[钩子座](钩子座.md)，取消/拒绝/isError 不转成功。

模型有效 input = 用户覆盖 > pi 目录 > text；`models.list` 下发同一声明，模型表单保存
显式 `['text']` 才能关闭目录 image。PDF/视频是工具路线，不能据此推断供应商模型的原生能力。
同一模型定义在下一次提交前刷新到公开 Agent 状态，图片开关无需重建会话；不追加虚假 model_change。
原生新图在进入pi前校验已声明的单消息额度；`onPayload`先等待原回调完成变换，
再按有效模型 `inputLimits` 检查单消息/整个请求图片数和JSON字节，含历史及工具结果图片。
覆盖OpenAI两种API、Anthropic、Google与Bedrock；有图片额度却无法识别结构时明确失败。
未声明的额度不猜测；超额给出减少图片/新建聊天的原因，不静默删历史。字节是SDK发送前
请求对象的UTF-8 JSON（SDK二进制按Base64计），不是网络抓包或所有SDK后续封装的精确字节。

`prepareForSend(local|server, refs, signal, onProgress)` 是服务器上传注入口；
`AttachmentUploader.upload(metadata, openStream, signal, onProgress)` 返回稳定 locator。
local 不调用上传器，server 未注入明确失败；当前没有账号/云端上传实现。

验收：原件删除后可读取；纯附件/混合发送和重启历史引用不丢；迟到回包不改新草稿，删除会话后不复活草稿；
100个普通文件可添加/发送，20图可混合普通文件，第21图明确拒绝；合法前缀XLSX及通用关系PPTX
原件可读；模型整次请求超额不发HTTP；纯目录发送/草稿重启/历史保留，ls/read按需读子文件且不复制目录；
文档错误可见；MCP审批真实生效；HTTP/WS无壳导入能力。
