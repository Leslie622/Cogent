# 产物文件卡片

正式交付文件由模型 `report_outputs({deliverables:[{path,note?}]})` 明确申报，Host 核实并保存预算内副本。
正文提到文件、read/write/edit 成功均不自动出卡。原理和三仓对照见[文件引用笔记](../技术笔记/文件引用与改动追踪.md#10-cogent-产物卡的实现取舍)，手测见[验收册](../测试用例/产物文件卡片.md)。

## 声明与唯一真源

- 工具由 `outputs/tool.ts` 注入，read 类免普通执行审批，`model-only` 只给模型直接调用。
  直调的公开 afterToolCall 先等待 pi 完整扩展链，再由 Host 确认提交；不让嵌套私有钩绕过此确认。
- 每次完整替换，`[]` 明确清空；任一项不存在、不可读、非普通文件或复制失败则整批失败，旧有效声明不动。
  路径是按真实工具 cwd 解析的字面路径，支持 Home、根外、中文和空格；不解析 Markdown URI 或行列。
  软链接检查真实目标，按平台去重，首次顺序、最后说明；同回合同真实目标的 ID 稳定。
- 真源只有 `outputs/v1/sessions/<sessionId>/turns/<turnId>/manifest.json`；包含活动声明、上次已发布清单、
  revision、确认时间、原路径、字节数、hash、副本状态和回合结果。不在会话 summary 或正文再存一份表。
- `OutputsService` 持有事务队列，工具 execute 暂存，最终成功才原子提交并回执；拦截、取消、扩展判错均不能提交。
  先调用后慢完成的声明不会覆盖后调用；暂存按会话及toolCallId隔离，两个聊天同名调用不串台。
  manifest损坏显式报错，不当空清单重建；受管副本路径必须符合本回合copies/批次/产物ID/原名结构。

```text
owner: SessionManager = 运行预约；OutputsService = 声明/交付字节；chat桶 = 回合投影
report_outputs → 校验/复制暂存 → pi最终工具结果 → 原子manifest → 工具成功回执
真正终态 → finalizing → 复核最后有效声明 → 发布ready → 唯一run终态/释放预约
重启中断 → 最近持久确认版/interrupted；不重新读取源文件冒充历史版本
```

## 版本与收尾

- 同句柄分块复制并计算 SHA256；前后核对版本、长度、真实路径，变化最多重试一次。保留原始二进制、BOM、CRLF。
  受管文件使用独立目录；清理只操作派生的受管路径，不删除源文件。
- 成功、停止、失败、准备期早停和 handled 均经统一收口；自动继续中间不发布，手动继续沿用 turnId。
  收尾使用独立 signal，保存结束前保留运行预约；无声明的新回合不读产物磁盘、不延迟原终态。
- 申报后继续写文件，收尾重新保存最终字节。源删除、权限/链接变化、持续写入或预算不足时保留旧确认副本并说明“最终版未确认”。
  产物结算错误单独 `outputs.error`，不冒充模型失败；当次可显示最近持久确认版，重启只恢复已落盘状态。
- 上限：100项、说明200字符；跨会话最多两路捕获，单文件100 MiB、批次256 MiB、会话引用及预览副本1 GiB；申报/复核各30秒。
  合法文件超副本预算仍可 `source-only`，明确“仅当前原文件”；真实 IO 错误不能冒充预算降级。
  超时通过取消信号实施；系统不支持取消的文件系统调用仍受OS等待时限，网络盘超时行为单列实测。
- 无引用暂存按 manifest 回收，打开的预览/动作登记持有字节租约；关闭/cancel 释放，后续查询回收。
  归档保留；删聊天先封闭并取消历史修复查询，等待事务与清理队列后释放数据，迟到查询不得重建manifest。
  临时导出在退出/下次启动尝试清理，失败留诊断。

## 查询、预览和卡片

- `outputs.get` 查询同一真源，历史加载不装配 pi；`outputs.resolve` 校验 session/turn/revision/outputId。
  fileId 仍是 Host 当次登记 ID；读取副本先核 hash，丢失/篡改不退回源文件。
- 两个 RPC 只对主窗口顶层页面开放，HTTP/WS/guest 整域拒绝，WS 不广播 outputs 事件。
  历史通过独立桌面查询水合，`session.messages` 不夹带受管产物表。
- 卡片为横向文件行，只常显图标、名称、类型和“打开＋下拉”组合钮；不设“交付文件”标题或数量行，正常副本的大小、申报说明和保存状态不占卡面。
  图标复用正文的 Material FileIcon，不铺背景；名称匹配与资源机制见[正文文件链接](正文文件链接.md)。
  仅当前原文件、最终版未确认等异常仍明确提示；文件动作与复制路径失败使用独立 AlertDialog，不插进文件行。
- “打开”默认预览交付副本，另存收进下拉菜单；系统打开先导出带原名的临时副本，外部编辑不能写坏保存字节。
  查看/编辑当前原文件、原目录定位、复制原路径均独立标明；source-only 明确使用当前来源。
- 复用 FileService、右侧 FilePanel、窄窗 Dialog、CodeMirror/文档 worker/PDF/媒体查看器。
  Markdown 依赖只匹配同次发布清单的已保存副本，缺依赖明确提示；HTML/脚本仅源码，ZIP也能另存/系统打开。
- TurnGroup 在终答之后、用量之前挂一个区域；无终答的停止/失败也有位置，首屏3项可展开全部。
  普通运行/ask_user 不新挂卡；继续保留旧卡标“更新中”。状态按真实 turnId/revision 入桶，删桶后迟到事件不复活。
  活动产物原路径合入①正文词表，覆盖/清空随声明变化，原 read/write/edit 词表不受影响。
- 工具说明和系统段要求需要独立交付时申报；成功 write/edit 后，在本来就有的下一请求前最多条件提醒一次。
  已声明（含空清单）不催报，不强制额外模型请求，不用正文推断补卡。

验收：真实 pi 工具与扩展判错、提交失败、终态预约、替换清空、停止/继续/重启及原件删除后的交付字节均有自动回归。
简洁文件行、菜单动作的版本归属、编辑原件失败弹窗与关闭重试有组件回归；预览侧栏的图片手测问题见验收册，未据自动通过改写为手测通过。
真实 Electron 从输入到卡片、依赖、副本另存、临时导出和进程重启有独立脚本；真实外部应用、模型申报率、目标 Linux 与容量上限按验收册分别记录。
