# 消息呈现

> 对话流的功能呈现层：回合分组两态、消息渲染、工具卡与各类轨迹行。
> 落点：`src/renderer/src/features/home/{TurnGroup,MessageRow,HomeChat}.tsx`、
> `src/renderer/src/components/ui/{run-trace,tool,markdown,reasoning}.tsx`。

## 回合分组与两态（TurnGroup）

- **渲染期分组**（store 保持平铺）：`groupTurns` 相邻分组、`splitTurn` 把回合
  切成过程段与终答段（末条有正文 = 终答，其 thinking 剥入过程、usage 剥去，
  durationMs 留给思考行「持续了 Xs」）、`sumUsage` 回合聚合用量；
- **live**：工具、中间正文与活跃占位在同一平级列表按序呈现，空 content 不挂正文
  容器，零工作项连过程容器也不渲染（工作行直接跟用户泡，回合栈高与终态
  头条逐像素一致 —— 立马失败的瞬时翻相不产生高度跳动）；流底只有一份 WorkingLine
  （WorkingSpinner、标题与 100ms 码表）。短内容
  紧跟正文，溢出且 following 时同节点定位视口下缘，reading 恢复普通流；停止请求
  在途改「正在停止」，不可取消的准备 await 返回前保持 live。
- **终态**：过程收进默认关闭的「用时 X 秒」头条，终答常驻，详细档显示聚合用量。折叠体
  keepMounted，内部不套 content-visibility 包装；轨道 minmax(0,0fr↔1fr) 与内层
  padding 同曲线开合。视觉配方见[UI布局](../UI布局.md)，机制见
  [思考流式呈现](../技术笔记/思考流式呈现.md)。
- **封段正文连续性**：
  活跃占位 id 一次分配终身不变（uuid），`placeholder` 布尔表活跃态；工具启动/
  中止封段只翻布尔不改 id。正文段渲染 key = 回合内段序数（live 占位与终态
  权威段一一段对齐，跨封段/跨终态稳定；zcode 对应物是协议 rowId），工具/
  审批等用自身协议 id —— 封段时正文行 key/父容器/位置三不变零重挂（选区、
  渐显状态、代码高亮不丢）；终态与 live 共用同一容器，终答行跨终态保留旧
  DOM 供尾部渐显自然收完。段间**排期接力**（会话级 pacing 种子，ChatMessages
  提供、Markdown 消费）：新段首拍不早于前段末拍的淡入结束 —— 快工具后
  「上段渐显未完、下段已开播」不倒序并存；慢工具（排期尾已过）零影响；
- 「用时」墙钟口径：起点 = user timestamp（压缩条
  截断出的续组继承之），收尾 = 末段 timestamp（请求开口径）**+ 该段
  durationMs**；末条是纯工具段取工具卡 endedAt —— 保证 ≥ 组内模型+工具
  耗时；
- 无过程回合（单段纯文本）恒挂头条（空过程体退化为不可展开单行）；
- 产物区域在终答后、用量前；无终答的停止/失败也有固定落点。普通运行不新挂，手动继续保留已发布卡并标更新中；
  TurnGroup按真实turnId接同桶outputs，不改消息key或过程区开合，机制及验收见[产物文件卡片](产物文件卡片.md)。
- 末回合 running 时为 live，非 live 的用户回合按桶内 turnOutcomes[user.id] 映射
  stopped/failed/done；新 user 不改旧回合结果，零输出停止头也保留。只有未知的初始
  历史默认 done；stopping 仅是指令在途，操作错误不改回合结果。状态 owner 与顺序见
  [会话与对话](会话与对话.md#停止请求与终态结果)；
- 中止不是错误：权威分段保留半截正文 + 「已停止」头条；done/stopped/failed 的详情
  缺省均收起，用户手动开合优先，半截终答在折叠体外常驻。无分段的旧事件才把占位
  翻 placeholder 封存（id 不变）；真失败 = 错误 toast + 「出错了」头条（错误详情
  不进对话流：App 层 `useErrorToast` watch 活动会话 lastError，sonner error toast
  顶部居中、560px 宽、5s 自动消失，右侧 ghost 图标关闭钮（详情引擎控制台留痕）；
  切换会话/非活动会话失败不弹）；
- 压缩条两形（历史保留）：
  - **轮间自动压缩**（run 内 checkpoint/恢复路，bar 之后还有轮次）→ 回合内
    **过程行**：按时间序原位中插在过程流（与工具卡同区），一条用户消息恒
    一个「用时」头与一份总时长（bar 不切开回合）；
  - **回合外压缩**（手动「立即压缩」/idle，bar 后直到下一 user 无工作项）
    → **独立成行**直接可见，不套「用时」头（不属于原回合过程）；直播事件条优先使用落账时记录的 compactionInRun；历史无字段时
    判据 = 向后看有无工作项（轮间
    bar 必然晚于上一轮收尾，时间比较分不出两形）；
  详见 [上下文压缩.md](上下文压缩.md)；
- 验收：真实中止事件消费后 stopping 已清，回合仍显「已停止」且半截正文只保留一份
  （无错误 toast，对话区无错误残留）；详情默认收起，点击可展开/收起且选择不被重渲染覆盖，收起不藏终答；失败回合显
  「出错了」；流式中工具启动封段，已出正文行不重挂（选区不丢、渐显不中断；
  jsdom 同节点回归钉住）；同型工具一运行一完成时无需悬停可区分（运行态类别扫光）；
  失败工具整行不变红、「执行失败」hover 出原因 Tooltip；无过程回合恒挂
  头条（不可展开单行）；切换会话再回来分组与用量行不重算错位；折叠体
  开合动画全程平滑（无卡顿、无高度回落闪烁）。

## 搜索定位

搜索来源锚点和导航顺序见[会话搜索](会话搜索.md#来源锚点导航与异步边界)。
MessageRow 提供正文目标，过程命中让 RunTrace 对本次意图展开一次，不改消息 key，
也不为折叠体内部添加带 content-visibility 的 scroller item。
原文高亮使用 CSS Range，不修改 Markdown/复制/用户选区，关闭时移除。
验收：过程命中先展开并定位，后续 token 不持续拉回视口，已有正文节点不重挂。

## 单条消息（MessageRow）

正文的本地 Markdown 目标、真实且唯一的反引号文件名、工具成功结果的明确路径共用 FileLink；
文件读取、来源身份、预览与桌面动作见[正文文件链接](正文文件链接.md)。链接扩展保留默认安全、脚注及渐显管线。
验收：未闭合链接不能点，完整链接可在流式中点击；文件打开不改变正文段 key 和既有滚动归属。

- 过程项按 item 引用 memo；memo 挡历史消息逐 token 重解析；用户消息灰气泡 + 时间戳/复制，助手平铺；
  附件在正文上方靠右，图片/文件分行，目录引用与文件同行，窄窗口换行；空正文不挂气泡，纯文件/目录历史仍保留。读取/预览/缺失边界见[附件](图片与文件附件.md)。
- UsageLine：`↑ 输入 · ↓ 输出 · 缓存读/写 · $ 成本 · 时长`（零值省略、
  时长由 `lib/format-duration.ts` 的 formatDuration 统一格式化、
  目录估价带 ≈ 前缀），见 [用量与成本.md](用量与成本.md)；简洁档整行不渲染，
  单条消息与回合聚合统计同口径，包含 token、缓存、成本和模型 / 工具耗时。
  `MessageRow` 将单次请求统计标为 `process`，由常规对话设置的
  `showProcessUsage` 控制，默认关闭；`TurnGroup` 的最终汇总使用 `turn`，
  不消费该开关，无过程的单段回答也保留总体统计。直播与历史过程即时响应切换。
- **耗时显示**：不足一分钟显示秒，分钟档显示分秒，小时档显示小时与整分（不显示秒）。
  工作码表与完成头条使用中文单位「时 / 分 / 秒」，数字与单位之间留空格（如「用时 1 分 11.0 秒」），
  思考尾标、模型与工具统计使用 h / m / s。
  工作码表、完成头条、思考尾标、模型与工具统计共同订阅常规设置中的秒位精度，
  默认 2 位，可选整数 / 1 位 / 2 位小数；秒位先舍入再拆分，进位不显示 60s。
  小时档省略不足一分钟的余数，秒位精度不影响它；所有档位只改显示，不改耗时事实。
- 思考（Reasoning 组件）：详细档**默认收起单行**（含流式期间）= 静态脑图标 +
  「正在思考」扫光 + 末行摘要横向滚动（超宽渐隐、增长推到末尾）；展开态
  限高内部滚动 + 底部跟随（贴近底部才吸底），纯文本渲染不走 Markdown；
  手动开合以用户为准；完成态「思考」+「持续了 Xs」（durationMs 保留于
  thinking 伪段）。简洁档只留状态行与耗时，不挂流式摘要、全文或展开入口；
  切回详细可恢复原内容与手动开合状态。

## Markdown 渲染（components/ui/markdown.tsx）

- Streamdown 封装：remend 修复流式未闭合块 +
  块级 memo；plugins/linkSafety 常量化，isAnimating 与 streaming 同步；Shiki 高亮语言懒加载分包；@streamdown/cjk CJK 友好解析；
- **流式正文渐显**（stream-reveal.ts 插件，流式及其视觉收尾使用）：短批单元
  （中日文按字 / 拉丁文按词）逐个包 span 按 300ms ease-out + 排期延迟淡入，
  最新输出尾部呈渐隐尾巴；大批纯追加正文的单个连续文本片段压成最多32组，内联标签
  会拆出多个片段。组内文字首帧完整占位，8ms为正常批次的组间目标；多片段/多块同批
  时压缩间隔，最晚250ms起跳，避免整批 settled 直出或无限排期。
  代码块（pre）与表格**行级 mount-only 淡入**：
  行身份 = 行 span/tr（行索引 key + 增量高亮前缀稳定，jsdom 回归钉住依赖结构），
  globals.css 在 `data-md-streaming` 流式作用域内让新挂载行 @starting-style 淡入
  —— 旧行元素保留永不重播、追加行逐行淡入、首挂整块即整块入场；终态收尾等待同认
  行淡入（纯代码消息不被切断）。单元格/未闭合行内部的文字增长仍直出（行身份 ≠
  字身份）；静态历史不挂插件、无作用域标记零动画。非前缀替换按 settled 处理；来源仍由 streaming
  与正文前缀判断，新挂载的运行中消息可能播放首帧，不能据此区分实时首片与快照。
  每个真实 Streamdown Block 实例独立持有插件、已提交文本和细/粗组边界，消息只共享
  clock/rate/gap；排期按块实例 Symbol 索引，同文段落不会互认进度或合并计划。
  旧组边界随提交保留，普通追加不把已显示的字重新压组；新字符获得新 span。
  原生 parser 包装原样返回分块结果，块数减少、稳定前缀改变或本块解析文字不再是可信
  追加时，本次重解析 settled，避免链接定义/脚注等结构回填重播旧正文。
  ```text
  owner: Markdown（增量信号、原生分块观察、共享排期）
  原生 remend/parser → Block 实例独立进度 → 仅给新增组排期 → CSS opacity
  React 提交 → 本块文本/组边界转正；消息排期转正
  非前缀替换/结构重整 → 本次 settled → 提交新边界
  ```
  DOM 文本首帧即完整、只动 opacity（高度恒定，不撞底部跟随）。**30ms 固定节拍
  合帧**由 renderer 事件入口/store 持有（生命周期见 [会话与对话](会话与对话.md#呈现合批的所有权)），Markdown 不再二次计时：排期器以 30ms 批为前提，
  排期与节点身份原理见
  [流式呈现动效.md](../技术笔记/流式呈现动效.md)。
  验收：短文本尾部可见细粒度渐隐；6480 字符大批正文仅 32 个 reveal span /
  动画对象且全文完整；流式代码/表格结构正确、零 reveal span，追加行淡入、旧行
  不重播（行级淡入与当前 Electron 表现按测试用例册真机验收）；历史消息无 reveal
  span；相同段落先后或同批出现时分别渐显；601字后连续小追加保留32个旧组，新字
  不复用上次新字的 span；短批累计跨96单元不重组旧节点；第二条流式消息与 StrictMode
  后动画照常，链接定义/脚注重整不重播已显示正文。
- **终态视觉收尾**（markdown.tsx）：业务 streaming 与 isAnimating 立即变 false，
  终态头、用量、输入区及 WorkingLine 清理照常；相同正文或末尾追加时，局部视觉 mode
  暂留同一 Block 树，停止新增排期。contents 根包装只提供查询 ref，不新增可视布局。
  getAnimations 只收集本件 data-reveal、代码/表格行的 opacity 与 data-reveal-marker
  的 color CSSTransition，包含延迟阶段；真实 finished/取消后切原生 static，回收 span 并完成全文解析。
  无过渡、页面隐藏或权威非前缀替换直接 static；隐藏事件也立即收口。卸载、新流、换版使旧
  等待失效，cleanup 不 cancel 仍在显示的过渡；扫光等无关动画不参与等待，无固定延时 timer。
  ```text
  owner: store（业务终态），Markdown（视觉树），浏览器（真实过渡）
  terminal → 业务立即完成 → 已有过渡 finished/取消 → static 全文解析
  新流/替换/卸载 → 旧等待失效；不反写运行位
  ```
  验收：常规有 user 回合终态立即出现、工作行立即撤销，尾正文旧 span 自然播完后回收；
  未闭合语法最终与原生 static 一致，无动画/reduced-motion/后台不滞留视觉树。
  工具封段与无 user 首项重挂已由「封段正文连续性」消除；权威快照替换正文段
  id、或快照段数与 live 占位数不齐的边角仍换 DOM（settled 不重播），不外推
  为全部路径逐像素平滑。
- **流式吸底**（message-scroller.tsx）：Provider 内的本地 controller 持有唯一
  following 意图；库 autoScroll 关闭，保留注册、定位与可见性。
  content/viewport 的 ResizeObserver 同步贴底（RO 不是统一在 paint 后交付），
  不监听码表文本 mutation、不另排追赶循环。直接设置 scrollTop，不对内容施加残差平移；
  视口不设 containment，让小数布局沿普通滚动路径绘制。
  上滚在capture阶段立即释放跟随；正文行高不变。重新跟随须有向底部的用户
  输入：仍离底时再按同一位置/尺寸基线上的实际向下移动与到底落点确认；reading时已在
  距底≤2px内，明确正wheel/下行键/上滑touch可同步恢复，因为原生clamp可能不再发scroll。
  未知方向的滚动条按下不走此快捷，仍须实际下行。近底旧scroll不能单独恢复，内容或
  视口尺寸变化会使待确认基线失效；布局/程序定位不冒充用户回底。
  底部向下wheel保持following；阅读手势会以当前位置instant中断本地在途的程序平滑目标，
  原生滚轮仍自行执行，不吞输入。
  ```text
  owner: Provider controller
  上滚capture/触摸/滚动键/索引 → reading → 停止追底
  旧scroll/RO/终态收起 → 保持reading，不因距底≤2px夺回跟随
  用户向下输入 + 实际向底移动 + 同布局到底 → following
  reading且已近底 + 明确下行输入 → following（不强造位移；滚动条按下除外）
  发送/回底 → following → 同步贴底
  内容/窗口尺寸变化 → following 才校正；reading 保留位置
  ```
  验收：底部一次微小上滚即可释放；0.5/1px首帧仍近底、同帧正文追加/终态收起和resize
  均不抢回；用户真正向下到底、发送/显式回底恢复跟随，索引近底定位保持阅读。
  WorkingLine 在 live TurnGroup 末尾通过 MessageScrollerPinnedRow 承载一份 TraceLine；
  短内容、溢出与阅读态共享同一 DOM。仅溢出且following时，外层保留真实行高，内层同一节点
  使用fixed定位，窗口目标top按viewport.bottom减去content与占位尾距、行高计算，width沿用占位。
  同级零尺寸fixed锚点测实际包含块原点，目标top与占位left减去此原点后再写定位；
  inline-size查询容器会改变fixed包含块，不能把窗口坐标直接当作top/left。
  尺寸变化的RO同步定位，不写scrollTop；跟随订阅在上滚capture同栈清定位和占位高度。
  top/left/width/height与前次几何之差均小于1/64 CSS px时保持原定位值，避免边沿相减的
  浮点噪声反复跨过像素舍入边界；真实尺寸或尾距变化仍重新定位。
  内容缩回等高、工作行目标被裁切或无高度时恢复普通流；字体/宽度变化观察真实行尺寸。
  一个100ms时钟更新码表，stopping 时改为「正在停止」，不新增 aria-live；终态同 render
  移除工作行。没有视觉副本、透明源或portal，主题由原DOM继承。
  DOM 生命周期由 Provider 的稳定 callback ref 发布 viewport/content 节点状态；
  pin与PinnedRow的观察者随实际节点代次注册/清理，不从可变ref闭包读取已撤销节点。
  验收：短内容紧跟最后消息；聊天面板有顶部/侧栏偏移时，长内容工作行仍完整可见且走时；
  长内容跟随时图标位置稳定（动效在图标盒内转，不产生盒位移）；上翻保留流内工作行，阅读位置不被抢回；
  全程只有一份工作文案与时钟，终态及切会话无残影。StrictMode 和 root/viewport/content 重挂
  正常，卸载无观察者残留。几何坐标变化不独立判为抖动，像素证据见
  [归因与证据边界](../技术笔记/流式呈现动效.md)，jsdom 不替代真机验收。
- 链接点击改道 `window.open` 走 setWindowOpenHandler 守卫（Electron 裸 `<a>`
  窗口内导航无人拦）；等宽字体 JetBrains Mono 走 `--font-mono`；
- **对话内容主题层**：外观设置导入 Themd 主题包
  （.themd.json，`lib/theme/theme-file.ts` 形状校验，坏字段按无值处理）→
  theme store（zustand persist）→ `compile.ts` 编译为 `--t-*`
  变量 → `ChatTheme.ts` 按明暗选套后单点挂消息流容器 inline style，extraCss
  单独走 `<style>`；`lib/theme/themd-base.css` 从本地 Themd 快照生成，
  `content.css` 适配 Streamdown 结构与暗色缺省色。标准 Markdown 元素按源默认值
  消费，包括标题/段落/强调/列表/任务/引用/提示块/表格/图片；root.width/app.bg 归宿主布局。
  默认 Cogent 主题包显式保留14px正文与代码；导入主题相对 Themd 基础样式做稀疏差异。
  用户字体/代码字号通过独立变量与最先声明的重要层，压过主题附加 CSS；单文字系统
  覆盖保留另一侧，恢复跟随清除覆盖，不改主题原数据。原理与维护命令见[主题笔记](../技术笔记/对话内容主题.md)。
  验收：导入的标题、段落和图片配置生效，空主题排版与源 CSS 一致；切明暗、换主题、
  持久化重读保留用户覆盖，附加 CSS 的 important 不夺取其用途；恢复跟随采用当前主题。
  真实 Electron 检查由 `npm run test:theme-browser` 执行，不能代替 Themd 工场 GUI 验收。

## 正文列与对话索引

- HomeChat 的正文和输入框共用宽度基准，两侧留白与输入框外扩随聊天面板宽度变化，消息滚动条双侧占位保持同轴；尺寸与
  过渡配方见 [UI布局](../UI布局.md)。ConversationIndex 按用户提问生成每轮刻度，
  点击通过 `scrollToMessage` 定位；激活态仍由真实视口几何派生。
- 刻度悬停通过 HoverCard 显示提问与已完成回答摘要；ChatMessages 仅向索引传入
  已完成回合的末段正文，不含进行中、停止/失败、工具、思考或压缩摘要。
  验收：旧已完成回合悬停可见问答摘要；新回合生成时只见问题，完成后摘要出现；点击仍定位提问。
- 索引外壳始终挂载，显隐由聊天面板容器查询控制，收拢宽度不会改变正文列。
  验收：窗口缩放或左右分栏改变聊天宽度时，正文与输入框保持水平对齐；
  输入框宽态左右各超出正文 20px，窄态对称收敛；窄面板正文与输入框均保留双侧留白，用户气泡右侧圆角、
  操作按钮和正文末字完整可见；空间不足时索引宽度过渡到零，收拢后不能通过点击或 Tab 进入，放宽后恢复定位。
- 输入框权限、模型入口按面板宽度切换为紧凑图标呈现，上下文窄态显示圆环，数据与动作不随
  显示方式切换而重建。验收：400px 窗口权限可选档，厂商图标可切模型，圆环可打开用量详情，
  开启计划和超长模型名也不使发送按钮被裁切。

## 工具卡（components/ui/tool.tsx + tool-display.ts）

- 常规设置的输出详细程度由 ToolCard 直接订阅，流式与历史同口径。默认详细；
  简洁档仅留图标、类别词、工具名（MCP 为 server.tool）与执行状态，不挂参数摘要、
  diff 计数/内容、结果输出、运行中尾行、失败原因浮层或展开入口。切回详细仍可查看
  原记录；模型正文与审批交互继续按各自规则呈现。
- 类别词按用途固定为读取、附件、写入、编辑、搜索、目录、终端、待办、提问、计划、
  MCP；bash/powershell 共用「终端」，旧转录 glob 归搜索，未知工具归「工具」。
  summary 经 tool-display 剥壳；MCP 主文案显示 server.tool。运行用类别扫光表达，
  失败和拒绝仍保留独立状态词，不将失败或被拒绝的写入标为「已写入」。
- edit 的结果提供 DiffBlock 与计数；write 当前只有成功摘要，没有旧内容或 diff。工具输出用 CodeBlock；代码正文与直播尾行统一消费外观代码字号（链路见[设置页](设置页.md)）；bash 运行中显示定高两行
  尾部快照，100ms 节流。图标、颜色、扫光与折叠配方见[UI布局](../UI布局.md)。
- 数据形状 `ToolCallRecord`（kind/summary/status/resultSummary/diff），
  流式与历史回查双路径同源。
- 工具行记录调用摘要与结果，不在其下额外挂文件快捷入口；成功工具的 fileRefs
  继续供正文文件识别使用，数据归属见[正文文件链接](正文文件链接.md)。
- 验收：简洁档在工具运行、成功、失败、拒绝与 MCP 行均不展示具体内容，保留
  状态及工具身份；同一工具四态类别不变。已展开工具切换简洁后详情从 DOM 移除，切回详细可重新查看。
  耗时在 60 秒 / 1 小时附近正确进位，修改精度同步更新各位置且不重置码表起点。
  简洁档思考无摘要、全文或展开入口，底部统计整行消失；切回详细恢复原内容。
  详细档默认不显示过程请求统计，开启「显示过程请求详情」后恢复单次请求明细；
  切换不改变最终汇总、头条时长、工具或思考本身的显示规则。

## 审批呈现

- 待审批：ApprovalPanel **替换输入区**（五件套竖排选项列表，见
  [审批与权限.md](审批与权限.md)）；
- 已裁决：原始 approved/denied/cancelled 痕迹继续保留在会话桶；TurnGroup 按
  callId 将其收进对应工具行的图标，允许为盾牌，拒绝/取消沿用各自图标，悬停显示结果。
  不再重复展示同一条命令；无 callId 的旧事件或工具缺失时保留独立「审批」行。
  痕迹不写入 pi 转录，跨重启审计见[审批与权限](审批与权限.md)。
- 验收：运行与终态展开都只显示一份命令；相同摘要的并行工具审批图标按调用 ID
  精确归属；允许图标可与执行失败同时出现，不将授权结果视作执行成功。
