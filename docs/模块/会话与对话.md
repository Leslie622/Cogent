# 会话与对话

> 引擎侧会话生命周期：pi AgentSession 托管、消息
> 收发、流式转译与持久化。落点：`src/host/runtime/session.ts`（托管层）、
> `src/host/kernel/pi-session-factory.ts`（装配）、`src/host/storage/`
> （会话域持久化）、`src/renderer/src/stores/chat/`（消费侧）。

## SessionManager

工作 cwd、每轮根快照与转录物理锚点分离；项目变更的阻塞、重建、历史和续写规则见[项目目录交接](项目目录交接.md)。

```
owner: Host SessionManager = 运行与持久化；renderer chat桶 = 显示状态
用户 submit / continue ──► 同步忙校验、预约本次 StreamingState
        │
        ▼ （惰性装配 / 模型设置 / 输入与鉴权准备；await 后核对 owner）
   pi.prompt() 生命周期 = LLM 循环 + 压缩/溢出恢复/provider 重试全内聚
        │  turn_end：封段成 ChatMessage；message_end：pi 树逐条追加落盘
        ▼
   agent_settled（每轮恰一次）──► 产物复核/发布 ──► run.completed / run.failed(reason, messages)
                                      └──► store 平铺替换 + 保存终态结果
```

- 每会话一个 pi AgentSession，**惰性装配**：启动/恢复只载摘要，首次
  submit/compact 才装配（ensurePiSession 并发去重）；`messages()` 只读路径
  永不装配（readPiTranscript 全量回查 JSONL）；
- `submit` **同步受理校验**：会话不存在 → 错误帧；会话忙（streaming map +
  手动压缩操作 map，账本覆盖准备/恢复/续写链全程）→ InvalidRequest；continue 在首个
  await 前同样预约并发 run.started，末条校验失败发唯一 run.failed 并保留 RPC 错误响应；
- `agent.submit` 可带 attachmentIds/directories/inputId，允许纯文件或目录引用；认领/准备/真实 user entry
  绑定与独立草稿仓见[附件模块](图片与文件附件.md)。新聊天物化后保持原草稿身份，
  后续编辑不会因为受理回包或输入区卸载而丢失。
- 异步段三类失败收口 `run.failed`（装配炸 / prompt 前置拒 / 续写链异常）；
- 终态纪律：进入 pi 生命周期后的 run.completed/run.failed 发射点在 **agent_settled**（pi 在
  prompt 生命周期 finally 里恰发一次，晚于全部内聚恢复）；先读事件的 aborted
  判中止，再读 errorMessage 判失败；成功正文后的收口钩子中止也属于 stopped。
  自动续写只继续自己持有的 StreamingState，终态已释放便退出，不因末条 length 再起跑；
- 所有真实收口经finishRun：已申报回合等待产物结算后才释放预约/发终态，自动继续中间不结算；
  没有声明的新回合保持同步收口。产物异常单独输出，不改写模型结果；细节和验收见[产物文件卡片](产物文件卡片.md)。
- abort：先给本次运行/手动压缩对象记 stopRequested，再调用已有 pi 的原生取消入口并
  受理即回；会话不存在或没有可停止操作时返回 aborted:false。不可取消的准备 await
  返回前保留预约，界面显示「正在停止」；返回后核对 owner，停止意图不会随装配丢失。
  prompt 的 preflightResult(started) 补取消，请求边界检查由
  [钩子座](钩子座.md) 链式 prepareRequest 包装负责；挂起审批经同一 signal 收尾；
- prompt 未启动的早停由 Host 保存原始 user 后发 aborted；handled 没有 pi 终态时由
  Host 收口，不永久 running。装配失败仍报真实 error，不把停止意图当成功取消；
- 手动压缩使用独立操作 owner；装配返回及 compaction_start(manual) 均消费停止意图，
  取消经压缩操作/RPC 收口，不伪造 run 终态。删除/退出使 owner 失效，迟到装配实例
  dispose，后续不再 prompt 或 compact。已进入 pi input 准备的 prompt 另有一次性公开
  core Agent 启动监听：首次 agent_start 先退订，再按失效 owner 补取消，finally 兜底退订；
- 正常退出先等 pi abort 与扩展 session_shutdown，再排空终态/删除/产物并释放服务；超时后 dispose 兜底。
  具体期限与宿主顺序见[应用启动](应用启动.md#host-生命周期)。

## 流式段化（StreamingState）

- 轮内缓冲：text / thinking 分流累积，toolCalls 收集，turn_end **封段**成一条
  ChatMessage（段 id 带 run 级 messageId 前缀防跨 run 撞 key）；
- `run.completed` 发 `messages`（分段终态数组）+ `message`（聚合兼容：text
  拼接 + toolCalls 合并），历史回查 `toChatMessages` 与流式终态同源投影；
- agent_settled 的 `run.failed.messages` 是本次显示替换范围的完整快照，包含中止/失败轮
  已封存的尾段；空数组也是权威结果。renderer 有此字段便直接替换，不再追加本地
  streaming 占位；缺字段才走旧事件的占位封存/删除分支，避免同一半截出现两遍；
- 手动 continue 保存最后 user 回合原 assistant 分段为 baseSegments，与本次新增段合并
  交付完整显示快照；早停保留旧前缀，正常续写/中途停止保留前缀与新尾段，压缩条仍由
  renderer 原替换逻辑保留。原用量随旧段保留，Inspector 的本 run 账只算新增工作；
- timestamp 口径：流式段取 `event.message.timestamp`（pi 的
  assistant timestamp = 请求打开时刻），与历史回查（树里同一消息）完全
  一致，气泡时间与时长起点重启前后不漂移。

## 持久化（双层）

文件来源随真实 user entry 写独立 custom 元数据，纯文本与附件共用 turnId，续写继承原回合；
会话域 piCwd 固定转录目录锚点。来源与工具引用字段不改消息 ID，细节和验收见[正文文件链接](正文文件链接.md#来源与路径)。

- **转录真源 = pi 会话树 JSONL**（`~/.cogent/pi/sessions/<cwd 目录键>/<时间戳>_<id>.jsonl`）：
  pi 在 message_end 逐条追加，崩溃安全；历史回查/保留式呈现都从这读；
- 装配成功、输入尚未交付 pi 的早停，Host 用公开 appendMessage + refreshContext 保存
  原始 user，live context 与 JSONL 同步；已交付输入不重复追加。装配彻底失败不声称输入已落盘；
- **会话域 summary**（`~/.cogent/sessions/<id>.json` v2）：置顶/归档/权限
  模式等 Cogent 私域，变更点整写，原子写（同目录 tmp + rename）；v1 旧文档
  （带 transcript）在 pi 内核首次装配时导入 pi 树后重写 v2；
- `session.create` 保存摘要后才加入会话列表；写入失败通过 RPC 返回，解除故障后可重试。
- 会话 id = UUID，与 pi 会话 id 显式对齐（`SessionManager.create(cwd, dir,
  {id})`）；persist 尽力语义（失败记诊断不炸回合）；
- 恢复：损坏文件改名 `.corrupt` 旁置 + 继续恢复其余（单文件损坏不拒启）；
- 归档 = 软删（`archivedAt`）：`session.list` 默认滤掉，`session.listArchived`
  供归档视图，可恢复或彻底删除。侧栏归档成功弹 sonner「已归档」+「撤销」
  action（5s）：撤销 = `archive(false)` 重拉 `session.list` 回主栏（不走
  `load()` —— 会自动选中首个会话，恢复不带导航副作用）；归档时正开着的
  会话撤销连视图还原（selectSession + openChat）；
- 彻底删除时，已装配会话由 pi 实例提供转录路径，重启后尚未装配的会话沿历史读取的目录锚点和会话 ID 定位原文件。
  转录文件若删除失败，Host 记录诊断并继续清理会话。
  验收：重启后能读到会话原文，即使项目换根，在首次装配 pi 之前删除也移除原 JSONL 和会话摘要；
- 置顶 = `pinnedAt` 时间戳（非布尔）。
- 聊天右键“重命名”打开预填弹窗；`session.rename` 校验非空单行标题并去首尾
  空白，先持久化再更新内存、广播 `session.summaryChanged`。保存失败保留旧标题；
  重命名不改 updatedAt，不装配 pi。`titleManual:true` 防首条消息覆盖手动标题，
  包括用户主动命名为“新会话”。

```text
owner: 弹窗 = 标题草稿；Host = 摘要与持久化；chat store = 列表投影
右键重命名 -> 预填 -> 保存 -> session.rename -> 写摘要 -> 更新内存/广播 -> toast 反馈 + 关窗
                                      写入失败 -> 原标题不变，弹窗显示错误可重试
```

验收：最近/置顶/项目子会话均可右键改名，取消不修改；成功后列表与标题同步、
弹「重命名成功」短语 toast（无详情），重启保留。空白不能提交，失败保留
草稿；终态旧列表回查不覆盖刚改的标题。归档弹带撤销的 toast，撤销后会话回
侧栏；归档时正开着的会话撤销后连对话一起还原。

- 验收：全新会话不发消息则引擎无此会话（新聊天只是视图态）；同会话忙时
  再发得错误帧且引擎存活；杀引擎重启后摘要/转录/置顶/归档状态复原（转录
  经 readPiTranscript 全量回查，影子区/压缩条保留）、续聊上下文完整；损坏
  的会话文件被旁置为 .corrupt 且其余会话正常恢复；阈值/手动/溢出三路压缩
  与 AUTO_CONTINUE 续写链均内聚于单 run（tests/integration/compaction）。

## 会话自动标题

Host 会话域管理一次性后台任务；`kernel/session-title.ts` 复用同一 ModelRuntime 的
`completeSimple` 与现有凭据/端点，不创建 Agent、不提供工具。配置归属和生效顺序见
[设置页](设置页.md#偏好存储分层判定标准谁消费)。

```text
owner: Host = 首条资格/后台任务/摘要；pi = 独立模型调用；chat store = 摘要投影
首条 submit -> ready 消费为 attempted 并保存 -> 广播临时标题 -> 主对话照常准备
    -> 首条真实 user 入树、有效模型确定 -> 独立生成 -> 校验输出
    -> 核对任务 owner 与手动标题 -> 基于最新摘要先写盘 -> 更新内存/广播
停止首轮/手动改名/删除/退出 -> 取消并使 owner 失效；失败/超时 -> 留临时标题与诊断
```

- 默认新会话首条输入截 24 字作临时标题，收到摘要事件立即显示；问候也生成。
  显式创建名称、手动改名（包括“新会话”与同名操作）优先；归档、置顶、权限及
  updatedAt 不被迟到标题撤回。主回合正常结束后标题仍可独立收尾。
- `autoTitle: ready|attempted` 只存内部摘要文档；无字段的历史会话不补发，恢复的
  ready 若已有真实 user 也不补发。消费标记未保存成功不发辅助请求；失败不自动重试。
- 首条受理时冻结开关，标题始终使用首条输入实际模型的快照；仅发原始正文与
  附件/目录名称，最多 4,000 Unicode 码点，不读取附件内容或混入技能展开/主上下文。
- 关闭思考或取最低支持档；普通输出预算 256、无法关闭思考时 2,048，token 型思考预算
  交 pi 适配；总期限 20 秒。只取正常停止的 text，一行清洗、去外层引号，最多 64 码点。
  空白、纯思考、控制字符、工具调用、截断与返回式失败均不写回。用量见[运行时控制台](运行时控制台.md)。

验收：无 renderer 也能生成与保存；标题请求跟随首条实际模型的供应商与端点，旧独立
模型选择不生效；临时/最终标题主动广播；手动操作和 A/B 不串名，
重启与后续输入不重发，磁盘/网络失败不改变主回合终态。自动回归与真实效果手测见
[会话与对话验收](../测试用例/会话与对话.md)。

## renderer 消费（stores/chat/）

- 状态职责：
  `types.ts`（类型与桶形状）/ `flatten.ts`（展平与终态替换纯函数）/
  `selectors.ts`（组件订阅视图 + EMPTY_MESSAGES）/ `store.ts`（状态与动作）/
  `events.ts`（引擎事件唯一订阅点）、`delta-batcher.ts`（增量合批）；
  `index.ts` 为 `@/stores/chat` 公共出口；
- per-session 状态全部住单一 `bySession: Partial<Record<sessionId, SessionBucket>>`
  桶（messages / todos / outputs及错误 / runtime运行位 / 三类挂起面板态），桶由 `emptyBucket()`
  工厂建，`deleteSession` 单键删；
- 桶owner在增量更新时稳定；产物历史查询据owner及revision合并，消息流动不使历史丢失，删桶重建不接受旧回包。
  产物查询独立水合，不阻塞openChat及其草稿身份恢复；标题已出现不能作为输入上下文完成切换的证据。
- 消息流元素是联合 `MessageItem`：ChatMessage / ToolItem / ApprovalItem /
  CompactionItem（终态痕迹与折叠条也在流里，见 消息呈现.md）；
- 「新聊天」是唯一的未发送草稿视图，不建引擎会话；侧栏入口清活动选择并恢复同一 draftId。
  项目、权限与计划选择只改草稿；`submit` 才消费这些暂存位并创建会话。
- 受理返回实际 sessionId，输入区按该 ID 绑定草稿，不回读可能已切换的活动 ID。
  未发送入口转为下一份新身份，原草稿身份留给已创建聊天的后续编辑。
  创建迟到不抢当前视图；已有 A/B 聊天与唯一未发送草稿分别保留正文和附件。
  创建失败经全局 toast 报告，保留未发送草稿的正文和附件。

```text
owner: home store = 主体视图/未发送身份；附件草稿仓 = 正文/附件；chat store = 已创建会话
点击新聊天 -> 清活动选择 -> 恢复唯一未发送草稿（切走/返回/连点均复用）
首条 submit -> 创建会话 -> 受理目标 sessionId -> 原草稿绑定聊天 -> 新入口轮换身份
```

验收：从 A 点击新聊天、填写正文/附件、切回 A 再返回新聊天，草稿保留且列表不增长；
项目选择/解绑不创建列表项，首次发送只创建一项；迟到创建不抢当前聊天。

### 停止请求与终态结果

`runtime.stopping` 只表示本窗停止请求在途；`lastRunOutcome` 为无 user 组提供
最近结果，`turnOutcomes[user.id]` 保存用户回合结果。终态清请求位、新提交清最近
结果，都不改旧 user 记录。`run.failed.reason=aborted`
判停止，error 或缺省判失败，不匹配文案、不以“点过停止”推断引擎结果。

```text
owner: Host = 实际终态；chat桶 = user回合结果；runtime = 请求身份、最近结果与操作错误
abort -> stopping=true + stopRequestId -> IPC
submit/continue -> 新 runRequestId + 清旧结果/停止身份/错误 -> running=true
terminal -> running/stopping=false + 清请求身份 -> 写最近结果与所属user的turnOutcomes
abort 拒绝/无可停止运行 -> 仅收当前请求；错误不伪造 run 终态
```

abort 的晚到响应只能回写同一 stopRequestId；新请求、新 run、终态或删桶使旧请求失效。
submit/continue 的迟到拒绝同样核对自己的 runRequestId 后才可丢 delta 队列、写错误或撤回
乐观消息；submit 按自己的 user id 回滚，不盲删末条。压缩操作迟到拒绝只写仍存在的桶，
不能补造已删除状态。lastError 也承载操作错误（呈现为应用内错误 toast，见
[消息呈现](消息呈现.md)），手动压缩/
停止指令失败不会改上一回合结果。当次运行请求拒绝才收口为 failed；过期请求无权更改
已到终态、下一 run 或已删桶。submit 返回实际目标 ID；过期失败返回 false，调用方不再处理旧输入。

ChatComposer 的发送组合键按设置页「发送快捷键」分流（engine store `sendShortcut`，
落 settings.json；缺省 Enter 发送、其余组合换行，三档判定见 `isSendKey`，IME 组词中
恒不发送）。另以请求、编辑、视图与卸载代次保护草稿：旧成功回包不能清掉后来输入、
切换后会话或新挂载输入区的内容，也不能替旧请求切视图。已有桶切会话保留各user结果，
continue在同一user上更新终态。初始历史水合不含终态原因，未知记录按done展示，重启
不能恢复历史停止标签。无 user 组替换仍
维持既有边界；任意扩展 await 未提供 signal 时不能强制杀死，只能等待后阻止后续工作。

验收：实际停止终态清掉 stopping 后仍显示“已停止”，正文与 usage 恰一份；其他入口中止
也可识别；正常完成、真实失败不被停止意图改写。空输出/半截停止后再发下一条user，
原回合仍显示“已停止”；失败也不会被新提交改成done。下一 run 无旧运行位，A/B不串状态，
旧 abort/submit/continue 响应不改新 run、新草稿或已到终态。自动回归见 `store.test.ts`
与 `home-chat.render.test.tsx`；Host 原因转译与停止后退出续写见 `session-terminal.test.ts`。

### 呈现合批的所有权

`delta-batcher.ts` 只暂存 renderer text/thinking 增量，Host 权威事件与持久化不变。
每会话首片启动 30ms 窗口，后来片段不重置；按原序合入一次 setState，只更新该桶，保留历史项和其它桶引用。
`run.started` 是顺序屏障，也按 Host 的 runId 进入运行态，支持桌面以外的入口发起任务。
本地 submit/continue 仍先设乐观运行位，不能依赖 started 才接受 delta。

```text
owner: store.messageDeltas（session -> 有序片段 / timer）
delta -> 首片起拍 -> 30ms发布 -> 一次store通知
同session非delta -> flush -> 原结构/终态事件（工具封段在flush之后）
select/submit/continue/abort/审批落痕 -> flush -> 原动作
历史快照 -> discard -> 替换 -> 重放水位之后的事件；clear/delete -> discard（旧timer不得复活）
App bind cleanup -> unsubscribe -> flushAll -> timer归零；重挂重新订阅
```

没有独立 clear/snapshot 协议事件；此处指桶清空/整替写入。store 订阅按 messages 引用变化取消仍在队列中的旧批；普通结构事件先 flush 不丢字。
桶存在与 historyLoaded 分开；首次选中仍拉历史。session.messages 带事件水位、运行快照与挂起交互，
加载期间暂存最多 4096 个事件，只重放水位之后的事件，超限重新读取；删除/断连使旧加载 owner 失效。
每次 submit/continue 都有独立 runId，turnId 保留用户回合身份；受理、开始、终态、查询共用身份。
外部开始只认领同 turnId 的输入，不改上一条 user；不匹配本次 runId 的终态丢弃。
验收：先事件后打开、历史迟到/断连、跨入口开始和旧 run 终态均见 `tests/renderer/stores/chat/store.test.ts`。
停止请求先发布已有字，等待终态期间的新尾字继续收，run.failed 再 flush 后消费权威分段；
无分段事件才按停止/失败分别封存或移除未完成占位，详见上文终态分段与结果合同。
验收：跨会话不串字，text/thinking 顺序和全文一致，工具前后分段不合并；终态/快照/删除后无旧队列重放，卸载无遗留 timer。自动回归见 `delta-batcher.test.ts`。

## 搜索与来源

搜索由 Host 独立派生服务提供，范围、索引和协议见[会话搜索](会话搜索.md)。
纯正文投影归 `runtime/message-projection.ts`，只读分支恢复归 `kernel/transcript.ts`；
历史读取不装配 pi，不通过可能迁移落盘的 `open()` 读取旧文件。
消息来源字段与 UI key 分开，直播/历史和续写合并共用来源映射，详见搜索模块。
Cogent v1 在真正导入 pi 前继续随元数据保存 transcript，改名和归档不能提前改写成无转录的 v2。
`kernel/transcript-authority.ts` 统一历史/搜索/迁移选源：空目标或严格前缀返回完整旧历史，完整前缀后的新内容保留；分叉报错并保留两份。
迁移先在临时 JSONL 构造完整内容再原子发布，核对完整后才清旧转录并写 v2；摘要提交前中断仍可重试。
删除先持久化 tombstone 再移出内存、等实例退出并清文件；清理失败返回 cleanupPending/cleanupError，重启按标记重试。
导入历史 user 时只回填转录，当前输入的回合来源和附件元数据等 pi 实例接管后绑定新 user 条目。
验收：旧会话经改名/归档后重启仍可读原文；搜索与消息回查来源一致，读取不改真源。
中断前缀、完整前缀、分叉、压缩条和反复迁移见 `tests/host/kernel/transcript-authority.test.ts`；删除回查见 `tests/integration/session-search.test.ts`。
