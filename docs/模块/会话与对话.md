# 会话与对话

> 引擎侧会话生命周期：pi AgentSession 托管（阶段 1.2a 内核替换后）、消息
> 收发、流式转译与持久化。落点：`src/host/runtime/session.ts`（托管层）、
> `src/host/kernel/pi-session-factory.ts`（装配）、`src/host/storage/`
> （会话域持久化）、`src/renderer/src/stores/chat.ts`（消费侧）。

## SessionManager

```
用户 submit ──► 受理校验（不存在/忙 → 错误帧，run 不启动）
        │
        ▼ （惰性：首用才装配 pi AgentSession，v1 旧转录一次性导入 pi 树）
   pi.prompt() 生命周期 = LLM 循环 + 压缩/溢出恢复/provider 重试全内聚
        │  turn_end：封段成 ChatMessage；message_end：pi 树逐条追加落盘
        ▼
   agent_settled（每轮恰一次）──► run.completed(messages) ──► store 平铺替换
```

- 每会话一个 pi AgentSession，**惰性装配**：启动/恢复只载摘要，首次
  submit/compact 才装配（ensurePiSession 并发去重）；`messages()` 只读路径
  永不装配（readPiTranscript 全量回查 JSONL）；
- `submit` **同步受理校验**：会话不存在 → 错误帧；会话忙（streaming map +
  手动压缩集，单一账本覆盖 pi 恢复/续写链全程）→ InvalidRequest；
- 异步段三类失败收口 `run.failed`（装配炸 / prompt 前置拒 / 续写链异常）；
- 终态纪律：run.completed/run.failed 发射点在 **agent_settled**（pi 在
  prompt 生命周期 finally 里恰发一次，晚于全部内聚恢复）；
- abort：`pi.abort()`（async）受理即回；挂起审批经 abort signal 收尾；
- 引擎退出时 disposeAll（pi dispose 内聚 abort 全部运行）+ 杀 bash detached
  子进程 + settle 全部挂起审批。

## 流式段化（StreamingState）

- 轮内缓冲：text / thinking 分流累积，toolCalls 收集，turn_end **封段**成一条
  ChatMessage（段 id 带 run 级 messageId 前缀防跨 run 撞 key）；
- `run.completed` 发 `messages`（分段终态数组）+ `message`（聚合兼容：text
  拼接 + toolCalls 合并），历史回查 `toChatMessages` 与流式终态同源投影；
- timestamp 口径：流式段取**轮结束墙钟**（Date.now()，UI「已工作」口径）；
  历史回查取 pi 树原生 timestamp（请求开始时刻）—— 两路差一轮流式时长，
  1.4 投影对账项（pi 树是追加式，改写消息会盘内漂移，不能再像手搓时代
  原位覆写）。

## 持久化（双层）

- **转录真源 = pi 会话树 JSONL**（`~/.cogent/pi/sessions/<时间戳>_<id>.jsonl`）：
  pi 在 message_end 逐条追加，崩溃安全；历史回查/保留式呈现都从这读；
- **会话域 summary**（`~/.cogent/sessions/<id>.json` v2）：置顶/归档/权限
  模式等 Cogent 私域，变更点整写，原子写（同目录 tmp + rename）；v1 旧文档
  （带 transcript）在 pi 内核首次装配时导入 pi 树后重写 v2；
- 会话 id = UUID，与 pi 会话 id 显式对齐（`SessionManager.create(cwd, dir,
  {id})`）；persist 尽力语义（失败记诊断不炸回合）；
- 恢复：损坏文件改名 `.corrupt` 旁置 + 继续恢复其余（单文件损坏不拒启）；
- 归档 = 软删（`archivedAt`）：`session.list` 默认滤掉，`session.listArchived`
  供归档视图，可恢复或彻底删除；
- 置顶 = `pinnedAt` 时间戳（非布尔）。

- 验收：全新会话不发消息则引擎无此会话（新聊天只是视图态）；同会话忙时
  再发得错误帧且引擎存活；杀引擎重启后摘要/转录/置顶/归档状态复原（转录
  经 readPiTranscript 全量回查，影子区/压缩条保留）、续聊上下文完整；损坏
  的会话文件被旁置为 .corrupt 且其余会话正常恢复；阈值/手动/溢出三路压缩
  与 AUTO_CONTINUE 续写链均内聚于单 run（tests/integration/compaction）。

## renderer 消费（stores/chat.ts）

- 消息流元素是联合 `MessageItem`：ChatMessage / ToolItem / ApprovalItem /
  CompactionItem（终态痕迹与折叠条也在流里，见 消息呈现.md）；
- 「新聊天」只是 home store 视图态，**不建引擎会话**；`submit` 无活动会话时
  按需 `createSession`（会话只随用户动作物化——空列表/全归档落"新聊天"
  着陆页，不自动建，防幽灵会话）。

## 协议接口

`session.create/list/messages/submit/abort/delete/setPinned/archive/
listArchived/setPermission`（session.create 收 cwd/projectId/permissionMode）；
事件 `message.delta`（kind: text|thinking）、`run.started/completed/failed`。
形状见 `src/protocol/types.ts`，手册见 [../Agent引擎.html](../Agent引擎.html)。
