# 用量与成本

> token 用量的采集链路、消息行统计与上下文窗口指示器。
> 落点：`src/host/runtime/session.ts`（采集）、
> `src/protocol/types.ts`（MessageUsage）、
> `src/renderer/src/features/home/{ContextIndicator,MessageRow}.tsx`。

## 采集链路

- 源头 = pi `turn_end.message.usage`（input/output/cacheRead/cacheWrite/
  reasoning/cost 全套，provider 实报）；
- StreamingState 按 run **多轮累加**（计费口径，向前兼容工具循环）+
  durationMs / model 缓冲；
- 协议 `ChatMessage` 挂 optional `usage / durationMs / model` 三件套
  （MessageUsage 手写投影，协议零依赖）；`run.completed` 与 `toChatMessages`
  历史回查同源 —— 盘上 transcript 本就存 usage，老会话也能显示；
- durationMs = 接口时长口径（pi），非墙钟。

## 消息统计行（UsageLine）

- `↑ 输入 · ↓ 输出 · 缓存读/写 · $ 成本 · 2.42s`（零值省略、tabular-nums、
  11px muted）；↑ 口径 = input 已扣缓存；
- **成本估价带 ≈ 前缀**：pi 目录快照 = 官方高峰价 ÷ 6.8（分时未建模），
  OpenRouter 实报不加 ≈；<$0.0001 显示下限；多轮累加 totalCostFromProvider
  透传取 AND。

## 上下文估算（contextEstimate）

- pi-ai `utils/estimate`（estimateContextTokens 等）—— 与引擎 clampMaxTokens
  的 max_tokens 预算**同源**，明细与预算自洽；
- 协议 MessageUsage.contextEstimate?（additive 搭 usage 便车）；agent_end 算
  一次挂聚合 + 末段两份（事件路径不落盘）；历史回查按需现算挂末条带 usage
  消息（重启后明细不消失）。

- 验收：重启后历史消息的统计行与明细仍在（盘上 usage 现算）；目录估价
  一律带 ≈、OpenRouter 实报不带；多轮工具循环的用量是累加口径；
  ↑ 数值 = input 扣除缓存后。

## 窗口指示器（ContextIndicator）

- 输入卡工具行细横条 + 百分比，75/90 两档变色；悬浮卡 = 总量/进度条/明细
  三段（系统提示词 / 系统工具 / 消息，按占比降序 + 灰黑色阶点）+ 平均缓存
  命中率；总量 = 实报 + 估算缩放对账（3.5 chars/token 中文偏松）；
- 口径 = 末轮 usage（input+cacheRead+cacheWrite+output）对 contextWindow；
  max_tokens 预算 = min(maxTokens, ctx − 占用 − 4096)；
- 90% 处压缩预警线（引擎真值）+ 压缩后回落（见
  [上下文压缩.md](上下文压缩.md)）。
