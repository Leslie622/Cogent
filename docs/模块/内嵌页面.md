# 内嵌页面

> 阶段 3（决定 30）第三方页面消费链：`<webview>` 沙箱 + guest preload 小 SDK +
> 凭证闸。现状 = 3a 最小闭环（demo 页可列会话/发起对话/收事件流）；页面级
> 细档（session 绑定）、真实第三方页面白名单扩展、MCP Apps 互操作见计划。
> 原理与四家对比看 [../技术笔记/内嵌页面接入.md](../技术笔记/内嵌页面接入.md)。

## 是什么 / 在哪

- 硬化策略：`src/electron/main/webview-policy.ts` —— `will-attach-webview`
  钩子推倒重建 renderer 传来的 webPreferences（强制 sandbox/contextIsolation/
  webSecurity、删全部 Node 口子、preload 只认 Cogent 的 guest preload）、
  src 精确匹配随包 demo.html 的规范化真实路径（开发时匹配配置来源和具体文档），同名外部文件不可信；
- 凭证 IPC：`src/electron/main/ipc/guest.ts` —— guest preload 的唯一入口，
  校验已登记的 guest、当前文档、顶层 frame 与可信 owner，再经 HostManager 签发 write 档票据；
- guest preload：`src/electron/preload/guest.ts`（产物 `guest.cjs`，沙箱 CJS
  单文件自包含）—— 暴露 `window.cogentHost = { ready, request, onEvent }`；
- SDK 本体：`src/shared/guest-sdk.ts`（纯逻辑）—— 票据换 token（一次性，
  兑换即焚）→ request 走 `POST /rpc` Bearer、事件走 WS `?token=`；
- demo 页：`src/renderer/public/demo.html`（第三方页面视角，原生 JS，只见
  `window.cogentHost`）；
- 入口：AppSidebar 左下角设置菜单的“内嵌页面”项 → `ipc/embedded.ts` 独立窗口 → hash `#embedded` →
  `features/embedded/EmbeddedDemo.tsx`（webview 容器，宿主开 `webviewTag`）。

## 怎么工作（凭证传递链，owner + 事件顺序）

```
owner: 票据签发 = main（HostManager.issueCapability，stdio 血缘全权）
owner: token = Host HMAC 域；guest 只在 preload 内存持有（不进页面全局）

Electron main                guest preload（沙箱 isolated world）    demo 页
    │ ◀── ipcRenderer.invoke('cogent:guest:credentials') ─┐           │
    │  校验 guest / 文档 / frame / owner                   │ 启动即要  │
    │ ── { ticket(30s·一次性), httpPort } ─────────────────┘           │
    │                        │ POST /auth/exchange → token（即焚）     │
    │                        │ window.cogentHost = {ready,request,onEvent}
    │                        │ ◀── 页面只调这三个函数 ──────────────┤
    │ ◀── request → HTTP 门 Bearer；onEvent → WS 门 ?token=（Host 强制档位）
```

页面永不直连 preload 的完整 IPC（im2.0 `window.native` 泄漏进程级权限的
反面教训）；凭证原语（票据/token）不出 preload 内存。

## 边界

- 特权 IPC 共用 `ipc/trusted.ts`：每次核窗口角色、具体文档、顶层 frame 和文档代次；异步结果和实际写入前再核对。
  主窗口、控制台、容器禁止外来顶层导航/重定向；同 URL 重载也使旧请求失效，事件只发送给当前可信窗口。
  三类窗口均开启 sandbox/contextIsolation，Node integration 关闭；控制台/容器仅有观测与会话读取方法，无凭据或会话写权限。
  验收：`node scripts/check-authorization-electron.mjs` 覆盖真实主窗口、控制台和 demo 正常接线，以及同名文件、iframe、
  外来导航、强制换页后的拒绝；同 URL 重载和异步旧写回由 `tests/electron/main/ipc/trusted.test.ts` 验证。

- scope 定档：3a 所有 guest 统一 `write`（决定 23 的 session 绑定档留后续批次）；
- WS 断线/Host 重启不自动重取凭证（demo 页刷新即重走链路）；
- 页面白名单只有 demo.html；真实第三方页面（含远程 URL）= 后续批次
  （自定义协议 origin 是候选方案，zcode 形状）。

验收：主 UI 左下角设置菜单选择「内嵌页面」打开 demo → demo 页左上角显示
`已连接（scope: write）`、会话下拉可列出/新建会话、发消息收流式回复、
右侧事件流滚动显示引擎事件（`run.started`/`message.delta`/`run.completed`）。
SDK 链路单测 `tests/shared/guest-sdk.test.ts`（6 用例）；Host 侧票据/档位由
`tests/integration/http-auth.test.ts` 钉死；真 webview 渲染 = 手动验收项。
