# 审批与权限

> 写类/执行类工具的人工确认机制：判定矩阵、挂起、规则记忆与 UI。
> 落点：`src/host/runtime/{session.ts,approvals.ts}`、
> `src/electron/main/ipc/approval.ts`、
> `src/renderer/src/features/home/{ApprovalPanel,PermissionMenu,
SwitchModeDropdown}.tsx`。

## 判定矩阵

`session.ts` 的 `decideApproval` 经 factory 链式包裹 `beforeToolCall`。
每次调用读取 summary 的 mode 与 planEnabled 活值；顺序为 read 放行 → 计划
开关短路 → mode 放行 → 根内规则 → 挂起。计划开启时写/exec 全部 block，
即使当前为完全访问也保持只读；read 不进入审批审计域。

| ToolKind | ask（默认） | auto（完全访问） | autonomous（自主模式） |
| --- | --- | --- | --- |
| read | 放行 | 放行 | 放行 |
| write/edit 根内 | 规则命中放行，否则询问 | 放行 | 放行 |
| write/edit 越界 | 询问，不吃规则 | 放行 | 放行 |
| exec | 规则命中放行，否则询问 | 放行 | 规则命中放行，否则询问 |

「始终允许」只记根内信任，不覆盖越界写；越界请求带 `outsideRoots`，面板隐藏
该选项，用户仍可允许本次执行。auto 放行所有写/exec，autonomous 只直接放行
write/edit；其 exec 仍查规则。非 read 判定均记录 `approval.decided`，询问另有
`approval.asked`，归属见[钩子座](钩子座.md)。

验收：ask 写类允许后结果回灌；同根同类规则重启后有效，越界写始终重新询问且
手许可落盘；auto/autonomous 越界写直行，autonomous exec 的已存规则有效；
运行中切 mode 立即改变判定，拒绝附言在模型下轮请求体中可见。

## 工作区规则表（runtime/approvals.ts，ApprovalRegistry）

- `~/.cogent/approvals.json`（不走 driver collection，自写 tmp+rename 原子写）；
- 「始终允许此工作区」= roots×kind 快照，**只存位置不存内容**；判定 = 会话根
  与规则任一根交集；add 幂等；损坏旁置 .corrupt 按空表继续；
- 无绑定根会话发 always → InvalidParams（防主目录全放行的最后一道闸）。

## 挂起语义

- pendingApprovals 表 + 三路收尾（abort signal listener / 会话删除
  settleApprovals / disposeAll）；重复裁决 → InvalidParams；
- 裁决 `approval.respond`：allow / deny + `message` 附言（→ block reason →
  工具 error 结果回灌模型，2000 字符截断）+ `always: 'workspace'`（允许并落
  规则）+ `switchMode: 'auto'|'autonomous'`（「允许，并切换为」：允许本次 +
  切会话模式 + **记为项目默认**；result.summary 回带切换后摘要）；矛盾载荷
  （always/switchMode + approved=false）入口校验拒；
- 走 main 专属通道 `approval:respond` IPC（不经 renderer 通用代理）。

## 项目级默认模式

- `ProjectSummary.defaultPermissionMode`（projects.json 随存随读，值域校验）；
- 新会话解析链（renderer createSession）：显式选择 > 新聊天暂存位 > **项目
  默认**（projectId 直配，否则 cwd 前缀落进 cwds，`projectDefaultMode` 与
  引擎 `projectByIdOrCwd` 同口径）> 设置页全局默认；引擎 `session.create`
  不带 permissionMode 时也按同规则兜底（直驱协议/其他宿主）；
- 无项目归属会话只切当前会话，不落项目默认；切回收紧档（ask）走权限
  菜单显式动作，不藏在审批里。

## 权限通告（before_agent_start sections 通道）

- 模型可见的 mode 告知经 pi **结构化系统提示词节**：factory 的内联扩展
  挂 `before_agent_start`，每轮按活 mode 设 `systemPromptOptions.sections.
  cogent_permission` —— **三档全设正向文案**（ask 只移除段的话，历史里
  被拦截的工具 error 会让模型推断"仍受限"连试都不试；三档全给当下
  状态，切换 = 内容替换）；计划开关另有独立段 `cogent_plan_active`
  （开启时注入只读约束与 plan 工作流，关闭即撤段——两段正交互不替换）；
  pi 对 sections 做「变更才追加 patch、回放按名
  替换」（system-prompt.ts diffSystemPromptSections）—— 运行中切模式
  下一轮即生效、切换不堆积；
- mode 的账本在 `summary.permissionMode`、计划开关在 `summary.planEnabled`
  （审批判定读活值，强制面：计划拦写 / auto 放行 / autonomous 分级）；
  两者任何引擎侧变化（手动切换 / enter_plan / plan.respond 批准 /
  审批切档）经 `session.summaryChanged` 事件广播全量摘要 —— 宿主替换
  列表项即联动；
- 防回潮：勿往 transcript 塞 system 通告（pi 会话树 append-only，塞
  agent.state.messages 不落树、会被投影刷新冲掉）；systemPromptOverride
  拼 段也不行（loader 只在 reload 求值，运行中切不动）。

## renderer 与裁决顺序

```text
owner: Host.pendingApprovals = 挂起裁决；renderer会话桶 = 面板；main = 专属IPC
工具请求 -> 先登记resolver -> approval.request -> 对应会话桶面板替换输入区
用户裁决 -> approval:respond -> Host校验/落规则或切档 -> resolve工具 -> 模型续走
abort/删除/退出 -> 同一挂起表收尾；重复裁决报InvalidParams
```

- ApprovalPanel 替换输入区，草稿由父层保留；允许、始终允许、允许并切换、拒绝
  按同一裁决入口执行。无根或越界不显示始终允许；附言进入拒绝结果。
- 「允许，并切换为」用 SwitchModeDropdown 选择自主模式或完全访问；PlanPanel
  批准只关闭计划开关，无切档下拉。任何入口切 auto 都先过 FullAccessConfirm，
  **闸门就是最终确认**：确认即允许本次并切档，不再要求点击行级确认。
- 下拉开着时移入 portal 不清高亮，开关锁所在行，关闭还焦点到面板；弹层与闸门
  阻止 click 冒泡误执行宿主选项行。无选中时确认钮置灰，Enter 同语义无动作。
- PermissionMenu 的计划开关与权限三档独立；PlanToggle **仅开启时显示灰色 chip**，
  菜单负责开启，chip 可关闭。两入口读 summaryChanged、写 session.setPlanMode。
- `bySession[sid].pendingApprovals` 为数组以接住并行工具；侧栏等待确认常显，已裁决
  痕迹留在消息流，不存在于 pi 转录。布局、颜色及组件配方统一见[UI布局](../UI布局.md)。

验收：审批下拉选完全访问先弹风险闸门，确认后立即带 switchMode 裁决；取消不落档
也不执行原选项。选档后高亮与焦点有效，无高亮时不可确认；计划关闭时 chip 不显示，
开启时显示灰色并与菜单同步。回归见 `approval-panel.render.test.tsx`、
`switch-mode-dropdown.render.test.tsx` 与 `permission-menu.render.test.tsx`。

## 协议接口

`approval.request`（事件，含 `outsideRoots?`）、`approval.respond`（含
`switchMode?` / result `summary?`）、`session.setPermission`、
`session.setPlanMode`（计划开关）、`session.summaryChanged`（事件，摘要
广播）、`session.create` 带 permissionMode / planEnabled（缺省时项目默认
兜底）；`PermissionMode = 'ask'|'auto'|'autonomous'`（计划是正交开关
`planEnabled`，不占档位；stdio 侧有值域守卫防未定义新值；协议版本 v3）。
