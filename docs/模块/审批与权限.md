# 审批与权限

> 写类/执行类工具的人工确认机制：判定矩阵、挂起、规则记忆与 UI。
> 落点：`src/host/runtime/{session.ts,approvals.ts}`、
> `src/electron/main/ipc/approval.ts`、
> `src/renderer/src/features/home/{ApprovalPanel,PermissionMenu,
SwitchModeDropdown}.tsx`。

## 判定矩阵（session.ts decideApproval，挂 factory 链式包裹的 beforeToolCall）

```
工具调用 ──► kind = toolMeta(toolName)?.kind ?? read
        ├─ read ──► 放行（计划开关也不拦 read）
        ├─ planEnabled ──► block（写/exec 全拒 —— 短路优先于档位放行）
        ├─ auto ──► 放行（完全放行，含越界写 —— "完全访问"名副其实）
        ├─ autonomous + write/edit ──► 放行（同上）
        └─ ask（含 autonomous 的 exec）：
              根内写/exec ──► 规则表命中？──是──► 放行
              越界写 ──────────────► 直接弹面板（outsideRoots 标记，不查规则）
              未命中 ──► 发 approval.request 挂起（用户允许即执行，含越界）
```

边界语义（zcode 对齐）：**人是最终裁决者** —— ask 越界写照常弹面板、允许
即执行；「始终允许」规则 = **根内信任记忆**，永不覆盖越界（越界请求带
`outsideRoots` 标记，面板据此隐藏该选项）；auto/autonomous 完全放行
（主流 bypassPermissions / danger-full-access 同款）；计划开关照拦
（**正交于档位**：完全访问 + 计划开 = 只读，zcode service.ts:148 同序短路）。

| ToolKind \ mode | ask（默认） | auto | autonomous |
| --- | --- | --- | --- |
| 只读 | 放行 | 放行 | 放行 |
| 写（根内） | 规则命中放行，否则**挂起询问** | 放行 | 放行 |
| 写（越界） | **挂起询问**（可手许；不吃规则） | 放行 | 放行 |
| exec | 规则命中放行，否则**挂起询问** | 放行 | **逐次询问** |

（计划开关开启时：写/exec 一律 block、只读放行 —— 任何档位之上短路。）

- mode 与 planEnabled 均读会话 summary 活引用，运行中切换即生效；
- 判定序：计划开关短路 → mode 矩阵 →（ask 内）规则表（仅根内）→ 挂起询问；
- 判定全程落观测审计（钩子座 4d）：matrix 每条路径产生 `approval.decided`
  条目（放行也留痕），挂起询问另有 `approval.asked` 成对 —— 详见
  [钩子座.md](钩子座.md)，read 短路不经审批域、零条目。

- 验收：ask 态写类触发面板、允许后工具结果正常回灌；「始终允许」后同根
  同类零审批、杀引擎重启规则仍在；**越界写照常弹面板、手许后真落盘，且
  即使规则在也不吃（越界再现仍弹）**；auto/autonomous 越界写直行；
  运行中切 mode 立即生效且通告段随切随换不堆积；附言拒绝后模型下轮
  请求体可见该附言。

## 工作区规则表（runtime/approvals.ts，ApprovalRegistry）

- `~/.cogent/approvals.json`（不走 driver collection，自写 tmp+rename 原子写）；
- 「始终允许此工作区」= roots×kind 快照，**只存位置不存内容**；判定 = 会话根
  与规则任一根交集；add 幂等；损坏旁置 .corrupt 按空表继续；
- 无绑定根会话发 always → InvalidParams（防主目录全放行的最后一道闸）。

## 挂起语义

- pendingApprovals 表 + 三路收尾（abort signal listener / 会话删除
  settleApprovals / disposeAll）；重复裁决 → InvalidParams；
- 裁决 `approval.respond`：allow / deny + `message` 附言（→ block reason →
  工具 error 结果回灌模型，2000 字符截断）+ `always: 'workspace'`（允许并落
  规则）+ `switchMode: 'auto'|'autonomous'`（「允许，并切换为」：允许本次 +
  切会话模式 + **记为项目默认**；result.summary 回带切换后摘要）；矛盾载荷
  （always/switchMode + approved=false）入口校验拒；
- 走 main 专属通道 `approval:respond` IPC（不经 renderer 通用代理）。

## 项目级默认模式（F6「允许，并切换为」落位）

- `ProjectSummary.defaultPermissionMode`（projects.json 随存随读，值域校验）；
- 新会话解析链（renderer createSession）：显式选择 > 新聊天暂存位 > **项目
  默认**（projectId 直配，否则 cwd 前缀落进 cwds，`projectDefaultMode` 与
  引擎 `projectByIdOrCwd` 同口径）> 设置页全局默认；引擎 `session.create`
  不带 permissionMode 时也按同规则兜底（直驱协议/其他宿主）；
- 无项目归属会话只切当前会话，不落项目默认；切回收紧档（ask）走权限
  菜单显式动作，不藏在审批里。

## 权限通告（before_agent_start sections 通道）

- 模型可见的 mode 告知经 pi **结构化系统提示词节**：factory 的内联扩展
  挂 `before_agent_start`，每轮按活 mode 设 `systemPromptOptions.sections.
  cogent_permission` —— **三档全设正向文案**（ask 只移除段的话，历史里
  被拦截的工具 error 会让模型推断"仍受限"连试都不试；三档全给当下
  状态，切换 = 内容替换）；计划开关另有独立段 `cogent_plan_active`
  （开启时注入只读约束与 plan 工作流，关闭即撤段——两段正交互不替换）；
  pi 对 sections 做「变更才追加 patch、回放按名
  替换」（system-prompt.ts diffSystemPromptSections）—— 运行中切模式
  下一轮即生效、切换不堆积；
- mode 的账本在 `summary.permissionMode`、计划开关在 `summary.planEnabled`
  （审批判定读活值，强制面：计划拦写 / auto 放行 / autonomous 分级）；
  两者任何引擎侧变化（手动切换 / enter_plan / plan.respond 批准 /
  审批切档）经 `session.summaryChanged` 事件广播全量摘要 —— 宿主替换
  列表项即联动（此前只有 RPC 返回值一条路，引擎内改档 UI 无从得知）；
- 防回潮：勿往 transcript 塞 system 通告（pi 会话树 append-only，塞
  agent.state.messages 不落树、会被投影刷新冲掉）；systemPromptOverride
  拼 段也不行（loader 只在 reload 求值，运行中切不动）。

## renderer

- **ApprovalPanel 替换输入区**（输入草稿提升父层持防丢）：竖排选项列表
  （序号 + 主文案 + 说明，↑↓/Tab 移动、Enter/点击执行）—— 允许 / 始终允许
  此工作区（无绑定根或越界请求不显）/ **允许，并切换为 ▾**（zcode 同款：
  行内下拉选 自主模式[默认]/完全访问，同一项目的新会话沿用）/ 拒绝 /
  附言（无框浅灰输入条）；
- **档位下拉 = SwitchModeDropdown 共用组件**（ApprovalPanel 的两档放宽；
  PlanPanel 正交开关 v3 起批准不切档、无下拉）：弹层项与触发器复用
  PermissionMenu 的 `MODES`/`ModeItem`
  （模式图标 + 完全访问 warning 琥珀，视觉单一真源）；**选完全访问先过
  FullAccessConfirm 闸门且闸门即最终确认**（确认启用 = 允许本次并切 auto
  一步到位；与权限菜单同规，任何入口切 auto 都过闸）；**坑：portal 弹层
  的 click 沿 React 树冒泡到宿主选项行 button 会误执行整行**（曾致「点
  完全访问却按旧档 autonomous 允许并切换」的二次 bug）—— Content 与
  闸门外层各包一层 stopPropagation（详见 UI布局.md 档位下拉段）；
  **选项高亮与档位下拉的联动**（2026-11-16 修复：弹层是 portal，鼠标移入
  必触发行 mouseLeave 清高亮 → 确认钮/Enter 曾静默无操作）—— 下拉开着时
  mouseLeave 不清、开/关锁所在行、关时焦点还卡容器；无选中时确认钮置灰
  （Enter 同语义无动作）；
- PermissionMenu（输入区触发钮）：**顶部「计划模式」开关项（勾选 = 开关
  开启，toggle 语义）+ 分割线 + 三档真选项**（线隔的是开关组与档位组两种
  交互语义；完全访问 warning 琥珀保留）；触发钮三色（完全访问 = warning
  琥珀 / 自主 = chrome-accent 蓝 / 变更前确认 = muted 灰，无常态背景）；
- **PlanToggle 外置 chip**（权限钮右侧，正交开关 v3）：常显计划开关状态
  （点亮 = chrome-accent 蓝），与菜单开关项同数据源（summaryChanged 回流）
  同动作（session.setPlanMode），双入口天然同步；
- 会话级挂起表 `pendingApprovalsBySession`（数组形态，pi 并行执行会并发多个
  请求）；侧栏行尾「等待确认」tag 占动作钮簇位置常显；
- 已裁决落终态痕迹行进消息流（用户裁决痕迹，转录无对应物）；
- 验收（renderer）：审批面板档位下拉选「完全访问」先弹危险闸门、确认后
  点确认才带 `switchMode` 走 respond；选档后确认钮不静默（锁行）、高亮
  清空时确认钮置灰（approval-panel.render.test.tsx /
  switch-mode-dropdown.render.test.tsx）。

## 协议接口

`approval.request`（事件，含 `outsideRoots?`）、`approval.respond`（含
`switchMode?` / result `summary?`）、`session.setPermission`、
`session.setPlanMode`（计划开关）、`session.summaryChanged`（事件，摘要
广播）、`session.create` 带 permissionMode / planEnabled（缺省时项目默认
兜底）；`PermissionMode = 'ask'|'auto'|'autonomous'`（计划是正交开关
`planEnabled`，不占档位；stdio 侧有值域守卫防未定义新值；协议版本 v3）。
