# 技能座

> Host 侧管理技能目录（发现 / 列举 / 编辑 / 两级启停），pi `skillsOverride`
> + `before_agent_start` 段钩子注入（D7 不造轮子）—— SKILL.md 指令包按
> 「清单进系统提示、正文模型 read 自取」渐进进入 Agent 循环，**回合边界
> 热刷新**。原理与四家对比看 [../技术笔记/技能座.md](../技术笔记/技能座.md)。

## 是什么 / 在哪

- store：`src/host/runtime/skill-store.ts` —— 四目录发现（.cogent 两级 +
  `.agents` 生态目录两级，pi `loadSkillsFromDir` 白拿校验/ignore/裸 md
  规则）+ 同名 project 胜（同级别 .cogent 胜 .agents）+ 两级启停求值 +
  save/delete/read（落点守卫：名字字符规则排除路径逃逸；生态目录只读，
  写路径只在 .cogent）；
- 清单 formatter：`src/host/runtime/skill-prompt.ts` —— 镜像 pi
  `<available_skills>` XML + zcode 预算（250/条截断、20k 总预算、超限
  降级 names-only、兜底截条目）；
- 协议方法：`skills.list`（摘要+诊断，readonly；带 cwd = 两级合并视图）/
  `skills.read`（正文，编辑回填源）/ `skills.save`·`skills.delete`·
  `skills.setEnabled`（write 档）—— 注册表在 host-main；
- 装配：`kernel/pi-session-factory.ts` —— `noSkills: true` + 空
  `skillsOverride`（pi 静态注入面全关，扩展动态技能路径不可达）+
  `before_agent_start` 钩子每回合活算 skills 段（权限段同机制）；
- `/skill:` 活展开：`runtime/session.ts` submit 路径（`expandSkillCommand`，
  形状镜像 pi agent-session.ts:2325）；
- UI：设置页「技能」分区（`renderer/features/settings/SkillSection.tsx`，
  McpSection 同骨架：级联子菜单作用域（ScopeMenu：本机▸用户 / 项目▸各项目，
  分项目浏览，默认跟随活跃会话归属项目，useProjectScope）+ 技能计数 +
  搜索工具行 + 「已安装 N」组标题行（右侧刷新/新建）+ 图标方块条目行 +
  徽标 + Switch）—— 经 `engine:request` 通用代理（白名单
  `main/ipc/engine.ts`；技能真源在引擎侧文件，无壳侧双写）。
  列表与编辑回填绑定当前作用域及主根。切换后旧读取失效；留在编辑弹窗时保存失败原位提示，离开后提示原作用域的写入失败。

## 数据与生命周期

```
~/.cogent/skills/<name>/SKILL.md        # user 级技能包（UI 建或手放）
<工作区主根>/.cogent/skills/<name>/SKILL.md  # project 级（同名覆盖 user）
~/.cogent/skills.json                   # user 级启停 { disabled: [name] }
<工作区主根>/.cogent/skills.json        # project 级启停 { overrides: {name: bool} }
~/.agents/skills/<name>/SKILL.md        # user 级生态目录（zcode 等工具装，只读发现）
<工作区主根>/.agents/skills/<name>/SKILL.md  # project 级生态目录（同上）
```

```
skills.save / delete / setEnabled（写文件与状态，原子写）
      │
每回合 run 起始：before_agent_start 钩子
      │  skillStore.snapshot(主根)（无缓存，重新发现两目录 + 启停求值）
      │  → formatSkillsSection → sections.skills（空集 = 缺键清段）
      ▼
pi sections diff：内容变更才追加系统补丁（树内只留净变更史）
      │
模型可见 <available_skills>（name/description/location）
      │  ├─ 匹配任务 → read 工具读 SKILL.md 正文（渐进加载，read 档免审批）
      │  └─ 用户输入 /skill:name args → submit 路径活展开为 <skill> 块
```

**热刷新语义**：UI 改动与手动改文件都**下一回合生效**（拉模式，无
Chokidar）；正文每次 read 都是当前文件（dsh 同款「正文不缓存」免费具备）。

## 怎么工作（要点）

- **发现合并**：加目录序 = 同名优先级（项目 .cogent > 项目 .agents >
  用户 .cogent > 用户 .agents，后者胜 + 冲突诊断；zcode nearest-wins，
  pi 的 user 先得是异类不采）。生态目录（`.agents`，zcode 等工具装的）
  **只读**：发现/清单/启停/`/skill:` 全兼容，新建/编辑/删除不动它；
  symlink realPath 去重；
- **启停求值**（近者胜，与定义优先级一致）：project overrides 命中即定
  （true = 重新启用 user 已禁），否则看 user disabled 名单；manualOnly
  （frontmatter disable-model-invocation）技能不进清单但 `/skill:` 可调；
- **写路径**：save 生成 frontmatter（description 走 JSON 字符串 = 合法
  YAML，往返安全）；名字/描述校验镜像 pi validateName/validateDescription，
  非法整单拒绝不半写；delete 只清同级状态；
- **审批零新增**：技能不是工具，模型按技能行事仍走既有工具链（read 档 /
  bash exec 档照旧过 D8）。

## 边界（能力归属）

- 运行时修饰字段（allowed-tools/model/effort/when_to_use）：pi 无消费点，
  做了 = 在 pi 之上自建第二套技能运行时（zcode 也放 P1/P2）；
- 技能市场 / 远程分发 / 插件技能根：下载即提示词注入面，需签名/校验/
  审计（zcode 同样排除在第一阶段）；bundled 只是内容，放文件即可；
- dsh 式 Chokidar 推送监视：明确不采 —— 拉模式（每回合重新发现）已覆盖
  全部场景且无中间态。

验收：`tests/integration/skills.test.ts` —— 同名两级经协议写入后合并视图
project 胜 + 冲突诊断；首轮请求系统提示含 `<available_skills>` 胜者条目；
read 渐进加载正文回灌二轮；**同会话**禁用下一轮请求清单消失（sections diff
补丁 = 热刷新）；inherit 回落 + `/skill:` 活展开进用户消息。
`skill-store.test.ts` / `skill-prompt.test.ts` 单测钉 store 合并/启停求值/
守卫/展开与 formatter 预算模型。
手动验收步骤：设置页建一枚技能 → 会话进行中即可被模型按清单行事；输入框
`/skill:<name> 做某事` → 消息展开为技能块；禁用后下一回合清单消失。
