# 业务配置

Host 负责业务默认值与供应商定义；呈现偏好留客户端，API key 经 main 安全存储交接。
入口：`src/host/runtime/business-config.ts`、`host-main.ts`、`runtime/session.ts` 与 `stores/engine.ts`。

| 内容 | owner / 文件 | 加载者、优先级、生效时机 |
| --- | --- | --- |
| 默认权限 | Host / session-defaults.json v1 | Host 启动恢复；创建时显式参数 > 项目默认 > 全局默认 > ask；不改已创建会话 |
| 供应商、模型覆盖/禁用 | Host / custom-providers.json v1 | 启动注册；编辑先构造候选、原子落盘、提交运行态，再广播 |
| API key | main / credentials.json v1 | safeStorage 提交后有序交接，详见[凭据模块](凭据与模型目录.md) |
| 上次模型/思考与桌面偏好 | 客户端 / settings.json | 上次选择随提交显式传递，视觉配置由客户端消费 |

```text
Host 独占根 -> 恢复配置 -> 注册供应商 -> initialize 凭据快照
main 的启动变更队列 -> 等实际生效 -> running -> 业务请求
UI 修改 -> Host 校验/候选 -> 原子写盘 -> 运行态提交 -> 事件/响应 -> UI 更新
```

`session-defaults.json` 为 `{ version: 1, defaultPermissionMode: 'ask' | 'auto' }`。
新文件缺失才读取旧 settings.json 的同名字段；新文件提交后始终优先。
旧字段保留供迁移，main 保存其他设置不删它，也不再允许经 settings:save 修改它。
旧 custom-providers.json 沿用原形状，main 在 spawn 前完成 userData 搬运，不再持有定义缓存。
坏版本、JSON 或业务字段保留原件并拒绝就绪，写盘失败保留旧配置；已保存但运行态提交异常分别报告。

协议：`session.defaults.get/set`、`providers.custom.get/sync`；事件 `session.defaultsChanged`、`providers.custom.changed`。
HTTP/WS 配置读为 readonly，默认权限写为 admin，供应商写保持原 write 档；壳桥有页面身份和方法白名单。
renderer load 只读配置与模型，不再把读出的定义推回 Host；默认权限行等待保存结果并显示失败。

验收：无 renderer 的真实 Host 启动、旧配置迁移、重启、新文件优先、显式/项目/全局优先级、
候选/写入失败、坏配置不覆盖均有回归；启动期凭据新增/替换/删除及旧代回包见 HostManager 回归。
测试入口为 `tests/host/runtime/business-config.test.ts`、`tests/integration/create-persistence.test.ts`。
三仓对照与取舍见[运行交接与数据可靠性](../技术笔记/运行交接与数据可靠性.md)。
