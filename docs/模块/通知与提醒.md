# 通知与提醒

设置「通知」分区的机制：**触发条件 × 呈现方式正交** —— 三行条件设置决定
「何时提醒」，两个呈现开关（系统 toast / 提示音）各自独立决定「怎么提醒」
（可只 toast、只声音、都开或都关）。引擎侧零设施（pi/deepseek-harness 均只发
事件，调研结论见 Git 历史的计划稿），提醒 100% 是壳层职责。

## 事件挂点与判定（renderer 单一判定源）

```
chat events.ts（引擎事件流）
  ├ run.completed / run.failed(非 aborted) → 'turn-done'（失败换文案；自己中止不提醒）
  ├ approval.request                        → 'approval'
  └ question.asked                          → 'question'
        ↓ lib/notify.ts · notifyEvent(kind)
  shouldNotify（纯函数：三行条件 × document.hasFocus()）—— 不过即静默
        ↓ 过
  toastEnabled → notify:toast IPC → main：Notification(silent) 点击聚焦主窗口
  soundEnabled → playNotifySound：自定义文件（cogent-sound://）或合成音
```

- 全量会话都提醒（事件不看 sessionId —— 后台会话更需要）。
- 焦点判定单一源 = renderer `document.hasFocus()`；toast 的「仅未聚焦」同源，
  避免 main/renderer 两处判焦不一致（zcode 是 main 判，因其设置存 localStorage
  renderer 读不到 main；我们的 settings.json main 可读但事件消费在 renderer）。
- 无事件去重：事件流是引擎 stdout 直转、无重放源，approval/question 按
  requestId 天然一次。

## 提示音（lib/notify.ts）

- **合成音**（缺省）：AudioContext + oscillator，三类音型是基频
  `soundPitch`（400–1200Hz）的相对模式 —— 完成=双音上行、权限=同音两响、
  问答=双音回落；音量 GainNode 乘 `soundVolume`（0–1）。
- **自定义文件**：`~/.cogent/sounds/<kind>-<原名>`（拷贝，源删不丢），
  HTMLAudioElement 走 `cogent-sound://` 协议（main 代理读 —— dev 的
  http://localhost 不能直读 file://）；复用实例播前 `currentTime = 0` 重置。
- 音调只作用合成音；文件不变调（playbackRate 破坏音质）。播放失败静默
  （提醒是增强，不炸主链路）。

## main 侧（electron/main/notifications.ts）

- toast：renderer 判定后 IPC 来弹（silent —— 系统通知不发声，声音归应用）；
  Notification 对象显式持有到 close 防 GC（click listener 随对象回收丢失）；
  `Notification.isSupported()` 不支持则 ok:false 跳过。
- `cogent-sound://`：特权协议（ready 前 `registerSoundScheme` 声明 + ready 后
  `protocol.handle`），handler 只接受纯文件名（basename 校验拒路径穿越）。
- `sound:pick-file` / `sound:clear-file`：文件选择（音频过滤）拷贝 / 删除；
  **设置字段由 renderer 的 setNotifySetting 统一落**（settings:save 单一写路径）。
- `shell:open-notification-settings`：Win `ms-settings:notifications`、mac
  `x-apple.systempreferences:`；Linux 无统一入口不注册，renderer 按 preload
  暴露的 `platform` 隐藏按钮。
- `notify:system-status`：系统通知开关**快照**（OS 无变更事件，监听做不到）——
  Windows 查注册表 `ToastEnabled`（键缺失 = 默认开；查询失败 = 未知 null），
  通知页挂载时查一次，明确查到「已关」时「系统通知」行标题旁亮黄牌
  「系统已关闭 Cogent 通知」；改了系统设置重进页面刷新。

## 设置字段（settings.json，engine store `notify` 域）

`turnDoneNotify`（always/never/**unfocused** 缺省）、`approvalNotify`（开）、
`questionNotify`（开）、`toastEnabled`（**关** —— 用户定调声音为主）、
`soundEnabled`（开）、`soundVolume`（0.5）、`soundPitch`（660）、
三类 `*SoundFile`（缺省无 = 合成音；文件名存 `~/.cogent/sounds/` 下纯名）。
写路径：renderer `setNotifySetting(patch)`（null 文件字段 = 删键恢复默认）。

## 边界

- 控制台窗口聚焦时主窗口 renderer `hasFocus()`=false 会误提醒（低频，后续
  可加 main 多窗口焦点查询对齐 zcode 语义）。
- 音量对文件与合成共用；音调仅合成。

验收：三行条件只在对应条件触发（改设置即时生效）；toast 与声音正交（只开
其一另一路不动作），toast 点击聚焦回主窗口；音量/音调调节立即反映在合成音，
试听按当前配置播一次；自定义文件三类独立、选-试听-恢复默认闭环、重启仍在；
Windows 点「系统通知设置」打开系统通知页，Linux 无此行。判定与音型契约见
`tests/renderer/lib/notify.test.ts`。
