# 悬停滑动与过渡

并列的悬停行（列表、按钮组、标签条、浮层行）原先各自行画悬停底色，逐行进出只会淡入淡出。
`hooks/use-hover-slide.tsx` 的 `useHoverSlide` 在行组容器里放一枚单层胶囊，随指针、焦点或
高亮属性在行间滑行。它只做叠加：行原有的 `hover:` / `focus:bg-*` 类不动，胶囊进入一行时读该行
自己的悬停底色与圆角涂上去，行自身底色在胶囊覆着期间由 `[data-hover-slide][data-pill-over]`
置透明，文字变色、阴影等其余悬停表现留在行上。外观「开启滑动动画」关闭时不渲染胶囊、不挂
监听、容器类名与标记都不留，与未装配一致（行上的 `data-hover-slide` 只是装配标记，无样式依赖）。

## 读色的几处坑

- 悬停样式在指针事件那一刻还没提交。先关掉行的过渡再强制重算，会把文字色等所有悬停变化一起
  瞬间提交，移入方向就没有过渡；不关过渡时 `getComputedStyle` 读到的是过渡起点（透明），
  而且过渡一旦起步，内联改时长对它无效（CSS Transitions 规范如此，Chromium 144 实测亦然）。
  定稿做法：照常让悬停样式按行自己的过渡起步，底色终值从 `background-color` 那条
  `CSSTransition` 的关键帧取（`effect.getKeyframes()` 对运行中的过渡返回 from / to 两帧）。
- 静息底色从被悬停的元素身上读不到：克隆一个隐藏的同级副本来读。副本没有子节点，靠
  `:has([data-active])` 落在整项上的活动底色读不出，所以这类活动项（工作区标签条）不标成行。
  类名驱动的高亮（命令建议面板按 `selectedIndex` 换 `bg-*` 类）克隆副本会连高亮类带走，
  改读同容器里未高亮的另一行。
- 选中态由 `mouseEnter` 落进 state 的行（审批 / 计划 / 提问面板）在 React 提交后才换成
  更深的 `bg-muted`：容器监听行的 `class` 变化，先摘压制属性再读、读完压回，同一步任务内不出帧。
- 悬停不改底色的行（active 钮、已选卡、只变文字色的钮）不接管，当缝隙处理：胶囊留在上一行，
  过宽限期原地淡出。否则滑到 active 钮时它的底色先被掐掉再由胶囊画回来，等于凭空多一次 hover。

## 驱动、落位与归属

- `pointer` 驱动用于列表与按钮组，位置按视口盒子差值加容器自身的scrollLeft/scrollTop算内容坐标，
  否则滚动标签条后胶囊会错开一个滚动距离；`focus` 驱动用于 Base UI 菜单与 Select
  （悬停和方向键都是移焦点），`highlight` 驱动用于 cmdk、Combobox 与命令建议面板（行拿不到焦点，
  看 `data-highlighted` / `data-selected` / `aria-selected`）。后两种按布局量（`offsetParent` 链）
  落位：cmdk 会把高亮行滚进视口、浮层开场有缩放，视口盒子量到的是滚动中 / 缩放中的位置。
- 胶囊动画走 `left / top / width / height` 与背景色，不用 `translate / opacity`：合成层会把其上的
  文字降级成灰度抗锯齿（探针实测头部「文件」二字的次像素彩边消失），主线程动画每次滑动的
  布局加重算不足 10ms。容器 `relative isolate`，胶囊 `z-index: -1` 垫在行内容之下。
- 容器挂 `data-hover-slide-container`，行归最近的容器：输入区工具行的右簇嵌在左簇容器里，
  左簇的胶囊不得把右簇的行当成自己的。回调 ref 记容器，Popover / Select 面板这类晚挂载的浮层也接得上。
- Base UI 菜单在指针离开某行且去向不是另一行时会清空高亮并把焦点移回面板，行 → 分割线 → 行
  成了淡出再淡入。滑动开启时给菜单 Root 传 `resetOnPointerLeave: false`，高亮留在最后一行直到
  下一行接手（同键盘导航）。

## 过渡默认规则与开关

`globals.css` 的 `@layer base` 里一条规则给所有带 `hover:` 类的元素和浮层行补 paint 类属性
（底色、边框色、文字色、outline、阴影、opacity、fill、stroke）的过渡，时长读
`--hover-transition-duration`；放进 base 层是为了让任何显式 `transition-*` / `duration-*` /
`transition-none` 整体覆盖它，侧栏开合、流式呈现、拖拽杀过渡不受影响。已有的 hover 过渡统一
改读同一变量（Tailwind 的 `transition-*` 工具类同时写 property / timing / duration，
`--default-transition-duration` 不动）。外观「开启过渡效果」关闭投影 `0ms`；系统
`prefers-reduced-motion` 用 `!important` 压过用户设置。非 hover 动画（侧栏折叠、滚到底部浮钮、
思考光晕、胶囊自身）保留各自时长。

### 分栏宽度的写法

会话侧栏与工作区的宽度要让裁剪窗、面板、对话留位与应用头部的三个区块逐帧对齐。三区块头部做过三版，
按 Chromium 的实测（Electron 40.9.3 / Chromium 144，离屏探针 + `Performance.getMetrics` +
`contentTracing`，2026-11-28）定下来：

- 变量挂在外壳根节点上继承、过渡写在根节点：继承的变量每帧插值一次，整棵子树的计算样式都跟着变，
  每帧全量重算。1.4 万元素开合一次 `RecalcStyleDuration` 112–135ms，帧间隔 `50/33/33/33`，
  随页面规模增长（用户实测掉帧）。
- 变量改为不继承、每个消费端自己内联持有：过渡逐帧只重算元素自己（合成页 1200 个后代，每帧 1 个）；
  但在元素上**内联写入自定义属性**时，Blink 仍把这个元素的整棵子树标脏重算一遍 —— 每次开合写一次，
  拖拽逐帧写就是逐帧重算（300 行会话侧栏的裁剪窗 28ms/次）。同一元素改写普通 `width` 则零次样式重算。
- 定稿：消费端一律内联写普通属性 —— 裁剪窗与头部左块写 `width`（左块 = 分栏宽 + 52，`min-width` 钳下限），
  面板与头部右块写 `width`，对话留位写 `padding-right`；同一条过渡、同帧起止，线性相关的几处逐帧对齐。
  只有头部中块的让位公式带 `max()`，保留注册为 `<length>`、不继承的变量，且只内联写在它身上（子树 25 个元素）。
  写入统一经 `features/shell/shell-panes.ts`（`data-shell-pane` 标消费端，晚挂的照最近一次宽度补写）。

会话侧栏开合一次的数字（14k 元素，开发版 React）：样式重算 112–135ms → 49–57ms，其中动画期间合计 8ms；
35k 元素时动画期间样式 6.9ms / 布局 10.3ms / 脚本 7.5ms，与 14k 持平；动画帧全程 16.7ms。
规则：要插值的自定义属性不放在祖先上靠继承分发，也不内联写在有大子树的元素上；能写成普通属性线性关系的
就用普通属性 + 同一条过渡。

工作区打开时还有另一条追赶链：Frame观察器逐帧setState，Surface把新宽写给内层，而外框每帧重启
200ms过渡，导致占满时内容右缘横跳。现改为尺寸存ref、观察器安排rAF直写普通属性，容器变化标记
`data-shell-pane-resizing`即时跟随；只有用户开合播放过渡。内层以`data-shell-pane-preserve`收起保宽，
展开时与面板同源更新；拖拽上限操作时现读，文件树只保存影响布局的上限。首页路由的memo不再依赖
会话侧栏开合，Surface也不因外壳重渲染。活动标签显露改为只写标签条scrollLeft，避免scrollIntoView
滚动overflow-hidden的外层头部；标签块允许收窄，防止左块最小宽使占满头部溢出并撑出页面滚动条。

上述坐标与帧间隔检查不能证明内容不抖：Windows CPU栅格化、DPR 1.25下，内容DOM坐标恒定，
同一静止图标仍出现5–6种像素结果，质心横移1个物理像素。Frame随左侧宽度过渡移动，后代的绘制
原点取整发生变化；仅给内层加`transform-gpu`仍有2种结果，仅改到静止父节点仍有SVG重绘差异。
现将面板固定portal到主内容卡（`data-workspace-host`），内层同会话侧栏常驻合成层。宿主就绪才挂载，
所有布局共用这一父树；React owner、宽度测量和快捷键仍在Frame/Surface，关闭焦点经chat ref交还。

`--workspace`像素专项使用与产品相同的Windows `disable-gpu-rasterization`启动参数，按真实paint位图
比较标题、图标、说明和活动标签；覆盖明暗、4/300条、0/0.4px起点及DPR 1/1.25/1.3125/1.5。
每组连续开合两轮，静止区域只能有1种像素结果；首尾也用invalidate产生真实paint，不混比capturePage
截图与paint位图（非标准DPR下实测两条路径像素不同）。不以DOM坐标、类名或rAF间隔代替绘制证据。

## 同主题源码对照

- Base UI 1.9.0 `node_modules/@base-ui/react/menu/root/MenuRoot.js:59` 默认
  `resetOnPointerLeave = true`，实现在 `floating-ui-react/hooks/useListNavigation.js:93,453`。
  它是 `MenuRootInternal` 的内部 prop（公开类型未收），公开 `MenuRoot` 原样透传未知 props，
  `components/ui/menu-slide.tsx` 用展开绕过类型；`permission-menu.render.test` 的 pointerout
  用例是回归断言。Select 未暴露该 prop，高亮在分组留白上会清空（原行为）。
- Tailwind 4.3.4 构建产物实读：`.transition-colors { transition-duration: var(--tw-duration,
  var(--default-transition-duration)) }`，所以默认规则只能在 base 层兜底，不能靠改默认时长变量。
- 这是纯呈现层机制，`reference/` 的 pi 内核没有同主题实现；对照取上述依赖源码与 Electron 40.9.3 /
  Chromium 144 的实际运行证据。
