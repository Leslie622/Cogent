# 文件预览渲染

预览需要原始文件和版式引擎。附件解析器能提取文字，不代表能画纸张、合并单元格或幻灯片。
Cogent的来源授权与交付副本仍由Host负责；可视化库只消费已有租约读取的字节。
当前依赖、交互、寿命和容量的权威描述见[模块页](../模块/文件预览渲染.md)。

## 为什么选WASM与独立懒包

Zcode高亮引擎注释记录了Shiki JS正则翻译占用V8 code range导致OOM的实际故障。
Oniguruma WASM把正则放在线性内存；因此Pierre配置不能只装同名依赖却沿用默认shiki-js。
虚拟行减少DOM数量，原文仍保留完整坐标；搜索和复制从原文取值，不能从当前挂载行拼全文。
Shadow DOM让普通父节点innerText不含源码，产品测试也必须检查真正的shadow行与原生选区。

Office、PDF、Mermaid与数学引擎各自按格式懒加载；安装包体积仍会增长，不能把“懒加载”说成没有体积成本。
react-xlsx支持worker解析，也保留主线程fallback；使用相同依赖不等于能保证所有文件永不阻塞。
PDF.js资源固定本地输出，WASM使用Vite生成URL，不能让file协议页面去请求CDN或worker相对错位路径。
react-pdf和根pdfjs-dist版本锁定，附件中文提取另跑真实CMap回归，不能仅验证UI构建成功。

## 虚拟源码隐藏后的恢复

`@pierre/diffs 1.1.22`的`dist/components/Virtualizer.js:328–344`由IntersectionObserver切换文件可见性。
`VirtualizedFile.js:106–139`在隐藏时重绘占位，显示时只改标志；短文件固定50行渲染范围（:155–162）。
`File.js:291–336`建立占位时删除code/pre却保留renderRange，同文件、同范围的普通render会在:197–203跳过，
因此宿主尺寸和文件lease正常仍可能没有源码行。公开`rerender()`（:68–75）会强制重绘。

Cogent在`visual/code-view.ts`的激活帧先公开恢复可见性，再重绘、核对行高和还原选区/滚动；
这同时覆盖IO恢复回调晚到的顺序，不访问库私有缓存、不更换File实例，也不在每次搜索/选择时强刷。
回归同时使用真实VirtualizedFile负对照和真实React查看器连续隐藏/显示，不以mock渲染器证明修复。

参照Zcode的`components/ui/code-viewer.tsx:680–697,738–788`在自身滚动div中直接使用File，
`previewPaneCodeContent.tsx:81`消费该组件；组件自身不创建Virtualizer，不能直接照搬其生命周期到本地虚拟列表。
此结论仅针对已读组件，不推断Zcode所有祖先容器或其他依赖版本的行为。

## 取消不是统一API

Host/readChunk/fetch可主动取消；docx-preview没有公开Abort/destroy，正确做法是离屏根加代次所有权。
旧解析完成只清自己的DOM与样式；卸载React组件不能被描述成“第三方解析已经停止”。
PPTX真正需要释放的是slide handle、图表和媒体，presentation模型本身没有destroy。
PDF活动Page卸载由react-pdf取消绘制与清理Canvas；Document保留时不重复解码所有页面。

PDF适配宽度不能随自身绘制结果反复变化。若按视口clientWidth算scale，并把scale放进Page的React key，
放大后的纵向滚动条会缩窄视口，重建Page；加载占位移除滚动条，视口再变宽，形成重复加载环。
Cogent使用稳定滚动条占位，同页缩放保留Page，只由react-pdf重建派生层，绘制代次继续隔离迟到完成。
`react-pdf 10.4.1`的`dist/Page.js:100–117`仅在文档/页号变化时取页，`:189–207`自行按scale更换Canvas和文字层；
Zcode的`components/ui/pdf-viewer.tsx:382–395`也直接更新Page的scale，不为倍率另设Page key。
真实Electron回归跨多个视口宽度扫倍率，并观察Page/Canvas身份、加载节点和滚动条变化，避免只凭一次Canvas出现判断稳定。

滚动恢复必须等真实高度，字体和异步图片可能改变布局；隐藏时测得的零尺寸不能覆盖保存位置。
代码选区保留UTF-16原文偏移，程序定位尽量恢复原生Selection；未挂载跨页范围依原文完整复制。
样式与字体属于文档内容，查看器隔离原始版式；菜单和工具条仍使用本项目Nova组件。

## 随依赖带回的修正

Zcode根 `package.json:137–138` 指向两份patchedDependencies：
`patches/@extend-ai__react-xlsx@0.16.0.patch` 补Canvas外链 `onOpenLink`，
`patches/@aiden0z__pptx-renderer@1.2.4.patch` 转义图表tooltip中来自OOXML的动态字段。
只守DOM的a标签会漏掉Canvas里的链接；全局替换window.open会干扰其他标签。
两项改为npm patch-package格式并在postinstall失败时终止安装，版权和改动来源随构建输出。

Office压缩包与作者链接是不可信文件输入，目录预算、禁altChunk和协议校验都写在此边界。
库不支持的格式/坏包显示真实失败，不回退抽文本后宣称保真成功。
`.doc`入口尤其需要区分“按Zcode接线”与“真实OLE文档可读”：依赖README只承诺DOCX。

实际产品截图、失败记录和复现命令归[工作区验收](../测试用例/多标签工作区.md)，不以依赖README代替运行证据。
