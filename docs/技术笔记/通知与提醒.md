# 通知与提醒

提示音属于桌面壳的反馈：引擎报告运行与交互状态，renderer 决定是否提醒，
再分别调用系统通知和媒体播放器。把提醒条件与呈现开关分开，才能支持只响铃、
只弹通知或两者都开；设置页试听直接调用同一播放器，避免预览与真实提醒听起来不同。

## 内置资源与用户覆盖

三个默认音源放在 `src/renderer/src/assets/sounds/`，由 `lib/notify.ts` 通过
Vite 的 `?url` 导入。开发页面取得资源 URL，构建页面取得带内容哈希的本地资源路径，
因此应用不需要先导入素材，也不依赖用户桌面的文件夹。

素材来自 [Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds)
的 `confirmation_001.ogg`，授权为 CC0，允许商用、修改与随包分发，署名非强制。
原始授权收录在[音源授权](../../src/renderer/src/assets/sounds/授权.txt)。
三个版本均为44.1kHz、单声道、16位PCM：

| 资源 | 处理 | 时长 | 用途 |
| --- | --- | --- | --- |
| `turn-done.wav` | 原素材解码为WAV | 约0.29秒 | 轮次完成或失败 |
| `approval.wav` | 通过高质量重采样降低两个半音 | 约0.33秒 | 权限请求 |
| `question.wav` | 通过高质量重采样升高两个半音 | 约0.26秒 | 等待回答 |

自定义音源保存在应用数据目录，由 `cogent-sound://` 读取；只有选择过自定义文件
才向设置写文件名。清除该字段就回到内置资源，因此新配置与恢复默认共享同一条路径。
播放器按 URL 缓存解码 Promise，内置资源与自定义协议都用 fetch 取字节后交给
AudioContext 解码；失败移除缓存，下一次用户操作可重新加载。

## 短音与输出就绪

HTMLMediaElement 的播放 Promise 完成或 ended 事件只能证明媒体管线推进，
不能证明蓝牙耳机已经发声。设备输出的启动延迟可能覆盖只有约0.3秒的整段提示音；
这个设备层解释仍需真实耳机验证，不能只凭浏览器事件认定根因。

Cogent 共用一个 AudioContext，点击的同步栈先调用 resume，加载和解码随后并行。
新建或恢复上下文时将最早声音时刻放到当前输出时钟之后600ms，先输出静音供设备
启动；处于运行态的后续播放不重复等待。三段素材的可听部分没有增加静音或修改。

```text
owner: renderer · lib/notify.ts
点击/事件 → 记录该类请求身份 → resume + 获取/解码音源
         → 等待两者完成 → 检查仍为最新请求 → BufferSource.start(输出就绪时刻)
```

同类连续点击共享加载 Promise，并只兑现最新请求；旧音源晚到不能替换新音源。
每次播放创建 BufferSource，从头播放并停止同类旧节点，结束时断开节点。
试听失败通过 sonner 展示原因；自动提醒只记录诊断，不打断会话或系统通知。

音量与音调的初始值、恢复按钮和播放器基准共用 renderer store 中的
`NOTIFY_SOUND_DEFAULTS`，避免滑杆恢复值与素材原音基准各自漂移。
两个恢复动作通过现有设置写入入口单字段保存，不重置音源与其他通知配置。

`soundPitch` 保留既有400–1200值域；660对应内置素材原速，播放器使用
`soundPitch / 660` 调整播放速率并关闭浏览器保调补偿，让音调控制仍然有效。
此操作也改变时长；自定义文件始终保持原速。音量由每次播放独立的 GainNode 控制。

## 同主题源码对照

- pi `reference/pi/packages/agent/src/types.ts:531`、`:534` 声明
  `agent_end` 与 `turn_end`；`packages/agent/src/agent-loop.ts:262`、`:263`
  在结束路径发布这两类事件。这里提供的是循环生命周期信息，Cogent 在壳层消费
  自己的运行事件后决定如何提示用户。
- zcode `reference/zcode/packages/ui/src/lib/taskNotificationSound.ts:1` 静态导入
  随包MP3，`:11`–`:16` 复用一个 Audio 实例，`:32`–`:41` 暂停、回到起点并处理
  播放拒绝。Cogent 沿用静态资源导入与三类覆盖关系；短提示音的输出时钟与
  复用粒度放在 AudioContext 和解码缓存，每次以新的 BufferSource 播放。

当前设置、事件挂点与验收以[通知与提醒模块](../模块/通知与提醒.md)为准。
