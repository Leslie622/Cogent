# 提示词工程

> 研究主题：系统提示词、工具提示词与消息流注入的三层治理、内部黑盒边界、默认中文回复与思考锚定，以及前缀缓存保护。
> 实施方案见[提示词工程实现](../计划/提示词工程实现.md)，交互式专题流程图见架构地图 `flowPrompts`（[架构地图模块](../模块/架构地图.md)）。

## 1. 问题与根因

随着工具、技能、权限、产物卡片和附件解析不断叠加，提示词分散在十余个运行时文件中，暴露了四类系统性问题：

1. **内部黑盒泄露**：`<cogent_outputs>`、`report_outputs` 描述与 `cogent-output-reminder` 三处重复灌输“申报 / 仅修改源码不必申报 / 副本预算 / Host 收尾复核”，且 `cogent-output-reminder` 经 pi `convertToLlm` 转为裸 `role: "user"` 消息紧贴在 `toolResult` 之后，没有任何“对用户静默”约束，导致模型直接向用户汇报“某文件已申报，某源码不必申报”。
2. **语言割裂与思考漂移**：英文人设 + 中文工作区/工具 + 英文 `<skills>` + 英文 pi 内置工具 + 中文宿主工具 + 英文续写/压缩，且未显式约束思考语言，推理模型在多轮英文工具输出后容易漂移回英文思考。
3. **能力与提示脱节**：前端已实现完整的 Markdown 文件链接（[正文文件链接](../模块/正文文件链接.md)）与本轮改动列表（[本轮改动列表](../模块/本轮改动列表.md)），但系统提示词缺少文件链接格式规范、全局证据先行原则与工具被拒后的行为约束。
4. **缓存、多根与观测盲区**：高频更新的 `cogent_todos` 之前未置于动态段末尾；多根工作区下 `<skills>` 仅扫 `boundRoots[0]`；`SessionInspector` 的 `system.prompt` 仅记录静态基础段，漏掉全部动态段与 `<cwd>`。

## 3. Cogent 三层落点

- **第一层（系统提示词）**：
  - `src/host/runtime/prompts/system.ts`：`buildCoreSystemPrompt`（跨会话恒定的静态前缀）+ `buildSystemPrompt`（追加多根工作区、环境与 `<workspace_instructions>` 包裹的 `AGENTS.md`）；
  - `src/host/runtime/prompts/sections.ts`：`buildDynamicSections` 按稳定度排布 6 个动态段，`renderPromptWithSections` 供未装配 pi 时的惰性上下文估算复用。
- **第二层（工具提示词与回执）**：
  - `src/host/runtime/prompts/tools.ts`：统一维护 `report_outputs`、`read_attachment`、`todo_write`、`ask_user`、`enter_plan`、`submit_plan` 描述与 `formatReportOutputsReceipt` 简洁回执（`turnId`/`revision` 仅保留在 `details`）。
- **第三层（消息流注入）**：
  - `src/host/runtime/prompts/reminders.ts`：`SYSTEM_REMINDER_SOURCES`、`escapeSystemReminderTags`、`wrapSystemReminder`、`outputReminderText`、`formatAttachmentsBlock`、`formatDirectoryReferencesBlock` 与 `AUTO_CONTINUE_MESSAGE`（保留 `[cogent:continue]` 隐藏前缀兼容投影层）。
- **协同与观测**：
  - `src/host/runtime/skill-store.ts`：`snapshotMany` 支持多根工作区技能合并（主根优先、`realpath` 去重）；
  - `src/host/runtime/hook-seat.ts` + `src/host/runtime/inspector.ts`：`before_agent_start` 后经 `onSystemPromptRendered` 调用 `inspector.systemPromptRendered`，在控制台留存含动态段的完整系统提示词。

## 4. 验证边界

- 单元测试 `tests/host/runtime/prompts.test.ts` 覆盖静态核心契约、动态段排序、工具去内部化、`<system-reminder>` 转义、多根技能合并与 Inspector 完整记录；
- 集成测试 `tests/integration/{outputs,interact,skills,approval-upgrade}.test.ts` 验证真实 pi 请求体中的系统段与提醒包裹；
- 真机模型遵循率（GLM / DeepSeek / Claude 的零泄露表现与中文思考一致性）须按真机对照验证，不以单测冒充。
