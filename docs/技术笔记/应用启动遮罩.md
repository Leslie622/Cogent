# 应用启动遮罩

启动遮罩由 `index.html` 在首帧静态绘制（不等待 JS bundle 解析），有两个独立退出条件：数据准备完成，以及极短防闪烁缓冲（250ms，自首帧起算）已到。两者并行计时，退出点取较晚者；这样窗口弹出第一帧就能看到遮罩、快启动不会闪一下，慢启动也不会在加载完成后额外等待。
业务初始化由 `App` 持有，`StartupOverlay` 接管静态遮罩（单元测试无静态壳时渲染同款 React 降级遮罩），只消费 `loading`，不把额外延时放进引擎就绪链路。
当前实现与验收以[应用启动](../模块/应用启动.md)为准，视觉参数以[UI布局](../UI布局.md)为准。

## 为什么等待完整 Promise

engine store 的 `loaded` 会在全部配置汇聚完成前先行置位；
chat store 也需要在列表加载后读取首次选中会话的历史；project store 负责侧栏项目树。因此 `App` 并行等待三路完整的 `load()`，
避免展示时模型目录、项目树或对话内容还在切换。事件订阅仍在数据加载前建立。
组件卸载后作废该轮完成回调，防止 StrictMode 上一轮完成误解锁当前页面。

外壳继续挂载，设置页按视图懒加载，页面自己的初始化可以在遮罩后执行；`inert` 管交互，`aria-hidden` 管可访问树。
只调透明度无法阻止 Tab 进入下层页面，淡出尚未结束也不能提前释放交互。
失败仍消费现有 store 错误出口；遮罩控制显示节奏，不将失败伪装成持续加载。

## 同主题源码对照

- zcode `reference/zcode/packages/desktop/src/renderer/index.html:25` 在 HTML 内联静态启动壳 `#loading`，
  不依赖 JS bundle 在首帧直接绘制；并在 `reference/zcode/packages/desktop/src/renderer/src/main.tsx:271`
  由 `StartupReadyNotifier` 通知壳体退场。Cogent 同样把首帧遮罩内联进 `index.html`，按 `cogent-appearance` 同步匹配明暗主题，并由 `StartupOverlay` 接管淡出与 `inert` 解除。
- zcode `reference/zcode/packages/ui/src/root/RootStartupLoading.tsx:10` 由启动组件承接
  `bg-background` 与完整窗口高度，集中放置标志，并暴露 `role="status"` 和忙碌语义。
  Cogent 同样由启动层承接主题背景，中心使用同款 Spinner 形态与状态语义。
- zcode `reference/zcode/packages/ui/src/root/GlobalDatabaseStartupLoading.tsx:82` 将失败传给
  `busy={!failed}`，并在 `:90` 暴露错误提示。Cogent 保留已有错误横幅与重试按钮作为失败出口，
  待遮罩退出后可操作；数据库迁移控制与日志导出属于 zcode 自身启动域，不由此遮罩引入。

这里对照的是首帧静态呈现、启动交接与失败可见性；250ms 防闪烁缓冲和 300ms 淡出时间来自 Cogent 的交互要求，
不把参考仓库的数据库启动机制推作本项目引擎初始化机制。
