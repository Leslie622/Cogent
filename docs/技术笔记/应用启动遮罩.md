# 应用启动遮罩

启动遮罩有两个独立条件：数据准备完成，以及最短展示时间已到。两者并行计时，
退出点取较晚者；这样快启动不会闪一下，慢启动也不会在加载完成后额外等待。
业务初始化由 `App` 持有，呈现组件只消费 `loading`，不把两秒延时放进引擎就绪链路。
当前实现与验收以[应用启动](../模块/应用启动.md)为准，视觉参数以[UI布局](../UI布局.md)为准。

## 为什么等待完整 Promise

engine store 的 `loaded` 会在自定义 provider 同步和目录刷新之前置为真；
chat store 也需要在列表加载后读取首次选中会话的历史。因此 `App` 等待两个完整的 `load()`，
避免展示时模型目录或对话内容还在切换。事件订阅仍在数据加载前建立。
组件卸载后作废该轮完成回调，防止 StrictMode 上一轮完成误解锁当前页面。

外壳继续挂载，页面自己的初始化可以在遮罩后执行；`inert` 管交互，`aria-hidden` 管可访问树。
只调透明度无法阻止 Tab 进入下层页面，淡出尚未结束也不能提前释放交互。
失败仍消费现有 store 错误出口；遮罩控制显示节奏，不将失败伪装成持续加载。

## 同主题源码对照

- zcode `reference/zcode/packages/desktop/src/renderer/src/main.tsx:171` 在独立的
  `renderDatabaseStartup()` 中向根节点渲染全局启动页，并把重试等操作接回启动控制通道。
- zcode `reference/zcode/packages/ui/src/root/RootStartupLoading.tsx:10` 由启动组件承接
  `bg-background` 与完整窗口高度，集中放置标志，并暴露 `role="status"` 和忙碌语义。
  Cogent 同样由启动层承接主题背景，中心使用已有 shadcn Spinner 的状态语义。
- zcode `reference/zcode/packages/ui/src/root/GlobalDatabaseStartupLoading.tsx:82` 将失败传给
  `busy={!failed}`，并在 `:90` 暴露错误提示。Cogent 保留已有错误横幅与重试按钮作为失败出口，
  待遮罩退出后可操作；数据库迁移控制与日志导出属于 zcode 自身启动域，不由此遮罩引入。

这里对照的是启动呈现与失败可见性；最短展示和淡出时间来自 Cogent 的交互要求，
不把参考仓库的数据库启动机制推作本项目引擎初始化机制。
