# 技术笔记 — 项目/工作区模型与存储根

> 落点：`runtime/project.ts`（ProjectRegistry）、`electron/main/storage-root.ts`
> （~/.cogent 根 + 旧文件迁移）、workspace IPC、`session.ts` 工作区注入
> （存储本体见 [会话存储与转录持久化](会话存储与转录持久化.md)）。

## 1. 问题：Agent 客户端的「项目」是什么

对话产品（ChatGPT）里「项目」是消息分组；编码 Agent 里「项目」是**目录绑定**。
Cogent 选后者：项目 = `{ id, name, cwds }` 薄实体，意义全在被会话引用
（`session.projectId` → 继承多根，首个为主根）。这与 UI 的「项目 → 子聊天」两级结构同构。

## 2. 工作区对模型意味着什么（四通道）

模型无进程无 cwd，工具收到 `read_file("src/index.ts")` 时路径解析是引擎做的。
工作区经四条通道生效：

1. **文字声明**：systemPrompt 写明工作区路径（`buildSystemPrompt`）；
2. **路径锚点**：工具实现闭包捕获 cwd，相对路径 `path.resolve(cwd, p)`
   （pi 工具与 Host 装配使用主根）；
3. **权限边界**：目标在工作区内 = 低摩擦、在外 = 审批（`beforeToolCall` 与工作区规则）；
4. **项目上下文**：启动读 AGENTS.md / git 状态注入。

四通道已分别由提示词、pi 工具、审批和指令加载承担；submit 再复查全部目录存在性。**隔离对话的是 transcript（会话），工作区隔离的是工具作用域**
——所以一个项目可挂多会话（共享目录、不共享对话）。

## 3. 环境块与 AGENTS.md（Claude Code 手法）

- 环境块进 systemPrompt：平台 + cwd + git 分支。分支**直读 `.git/HEAD`**
  （解析 `ref: refs/heads/<branch>`），不 spawn `git` 子进程 —— Windows 免
  依赖、零进程开销；代价是 detached/特殊 worktree 读不到（可接受，失败静默
  省略该行）；
- AGENTS.md 只读加载：存在才拼、限长 16k 字符（巨型指令不吃满上下文）、
  读失败跳过不挡会话（指令文件是增益不是必需品）。全局 `~/.cogent/AGENTS.md`
  的用户级指令层未做（additive 可后补）。

## 4. 存储根：~/.cogent（决策 D1/D2）

- **单一第一方根**：`COGENT_HOME ?? ~/.cogent`，引擎（sessions/projects）与
  main（credentials/custom-providers）各写各的子域，互不碰对方文件（单写者
  纪律）。Electron 侧抽 `storage-root.ts`、引擎侧 index.ts 自算同一路径
  （纯 Node `os.homedir()`，零 Electron）——**路径公式两处各写一遍但没有
  共享模块**：引擎禁 import Electron 代码（目录即边界），复制一行公式是
  边界成本，不是坏味道；
- **旧 userData 迁移**：首启发现旧文件 → 读出 → 写新 → **删旧**（迁移不是
  复制，双份并存 = 用户改旧文件"不生效"的排障噩梦）；
- safeStorage 密文按 Windows 用户账户（DPAPI）加密，与路径无关，搬家只是
  文件位移。

## 5. 项目删除语义：不级联

`project.delete` 只删项目，归属会话保留（projectId 悬挂 → UI 显示为无归属）。
理由：会话是用户资产，项目只是组织结构；级联删是危险动作，真要做应由 UI
显式确认后逐会话删。悬挂引用在单机 GUI 里比数据库领域轻得多 —— 显示层
容错即可。

移除确认留在 renderer：侧栏的“更多”与右键菜单只选择目标，`RemoveProjectDialog`
负责确认、在途禁用与失败重试；`project` store 等 `project.delete` 成功后才更新列表，
弹窗随后发出「项目已移除」通知。取消不触发请求，错误通过既有 IPC 剥壳后留在弹窗。
zcode 侧栏在 `reference/zcode/packages/ui/src/project-sidebar/ProjectSidebarNode.tsx:167–171`
直接删除并刷新；其项目管理在
`reference/zcode/packages/ui/src/project-sidebar/useProjectManagement.ts:192–199` 将结果反馈独立为成功通知。
Cogent 复用现有 AlertDialog 与 sonner，在界面确认和请求完成之间保留明确顺序，
避免误点直接移除，也避免请求未完成就通知成功。

## 6. 与 DeepAgent / 主流 Agent 对比

| 维度 | Cogent | Claude Code | Codex CLI | Cline/Cursor |
| --- | --- | --- | --- | --- |
| 项目/工作区锚点 | 显式绑定（用户选目录，存 projects.json） | 启动 cwd 即工作区，`--add-dir` 加挂 | cwd + 会话文件记 cwd | IDE 打开的文件夹 |
| 工作区→模型 | 四通道（提示词、工具基根、审批、指令） | 每轮环境块注入 cwd/分支/平台 | 环境块 + 沙箱策略注入 | rules 文件 + 上下文索引 |
| 硬边界 | 提示词与审批软边界，无 OS 沙箱 | 权限规则按路径 + 审批 | **OS 级沙箱**（landlock/seatbelt） | IDE 权限弹窗 |
| 项目级指令 | AGENTS.md 只读（限长） | CLAUDE.md 层级（全局/项目） | config.toml + AGENTS.md | .clinerules/.cursorrules |
| 多会话/项目 | 项目挂多会话（projectId 外键） | cwd 哈希归档（目录即分组） | 无项目概念（平会话流 + cwd 标签） | 天然单工作区 |

三点展开：

1. **显式绑定 vs 启动 cwd**：CLI 生下来就在某个目录里，工作区是"起点"；
   桌面 GUI 生在无目录环境，工作区必须是**用户显式选择的一等实体**。
   这个差异决定了 Cogent 需要 projects.json + 目录选择框 + 会话继承链，
   而 Claude Code 一行配置都不用。DeepAgent（作者前项目）没有工作区概念，
   工具吃绝对路径 —— 用户每次都要说全路径，且"在哪个项目里工作"的上下文
   语义完全缺失，这是本次设计的直接动机。
2. **软边界 vs 沙箱**：Codex 的 OS 级沙箱（seatbelt/landlock）是硬保证，
   Windows 上等价物（AppContainer/受限 token）工程成本高且 Electron 集成
   复杂。Cogent 当前采用提示词与审批软边界；它不构成 OS 级隔离，不能从其他产品成功
   推导本项目的安全保证。沙箱依赖平台能力与独立实现，路线见 [全局架构](../计划/全局架构.md)。
3. **AGENTS.md 生态位**：本项目自己根目录的 AGENTS.md 就是活样例 ——
   「给人写、给模型读」的指令文件已是跨工具事实标准（Claude Code/Codex/
   Cursor 均认）。Cogent 只读消费是零成本接入生态；不发明 `.cogent/`
   专用指令格式。

## 6.5 多根与信任

项目保存 `cwds[]`，首个为主根；提示词声明全部根、各根 git 分支和 AGENTS.md，
相对路径默认主根。创建/编辑新增根需要用户确认信任；删除目录后 submit 显式拒绝，
不能让模型在已经不存在的根继续工作。路径扩大与审批根内判断消费同一份根列表。

多根是项目的持久配置，不是一次会话的临时额外权限。原对照中 VS Code workspace
以组合建模，CLI 的 add-dir 是会话层附加；桌面项目要跨多次对话复用，故把组合归项目。
主根摘要放紧凑界面，完整根列表的呈现由模块与 UI 文档维护。

未发送草稿的项目选择只记录暂存 projectId，首次 submit 才物化会话；选择、换绑、解绑不造空脚手架。
草稿生命周期与导航的原因见[会话隔离与受理语义](会话隔离与受理语义.md)，不能通过删建会话换归属而丢掉正文或附件身份。

## 6.6 侧栏开合：呈现状态留在界面

pi 的会话选择器在 `reference/pi/packages/coding-agent/src/modes/interactive/
components/session-selector.ts:273–304` 保存选择、筛选与终端列表状态；这段不提供
桌面折叠动画，界面过渡由 Cogent renderer 自己负责，不增加引擎事件。
zcode 在 `reference/zcode/packages/ui/src/components/ui/collapsible.tsx:20–37`
用 Radix 高度关键帧与直接子层淡入淡出，并显式防止嵌套展开态互相污染。
Cogent 复用已有 Base UI 原语的挂载生命周期，导航变体只过渡 grid 轨道。
轨道内先放普通块级裁剪层，再放自然高度的 flex 列表；若裁剪层同时承担 flex 排列，
收拢会把 32px 行压至 20px，图标也在行内偏移。顶部间距属于内层列表，一起被裁切，
不再单独过渡。起步轨道通过 `@starting-style` 只在恢复显示时设为零，避免尚未收完就
重开时先继续向零收缩。常驻内容保留项目展开态，inert 阻止收起期间的交互，
hidden 在结束后移除布局。系统减少动画时直接切换。

行内图标移动与其他区域的静止图标闪虚是不同证据：完整 AppShell 的 Electron 连续绘制
对照中，项目开合能让“新聊天”和搜索图标出现两种像素状态，修正行高本身不能消除。
AppShell 的保宽、全高侧栏内容以 `transform-gpu` 常驻合成层，外层继续只裁剪宽度；
同一条件对照下静止图标裁片保持一致。该结论支持这个呈现边界，不据此断言 Chromium
内部的具体故障，也不给每个图标单独加层。落点为 `features/shell/AppShell.tsx`、
`components/ui/collapsible.tsx` 与 `features/home/HomeSidebar.tsx`。
与上述 zcode 参照相比，这里验证的是完整侧栏的静止像素，不能从其淡入淡出源码直接
推出 Cogent 的图标稳定性。回归入口与环境边界见[工作区与项目验收](../测试用例/工作区与项目.md)。

开合卡顿还须观察屏外子树的样式计算。固定行高的会话行可交给浏览器保留占位并跳过
屏外渲染，恢复滚动或键盘访问时再计算子树；这样保留菜单、焦点与 React 实例身份，
但不会减少初次创建 DOM 的开销。zcode 的同主题实现
`reference/zcode/packages/ui/src/project-sidebar/grouped/virtualized-group-task-list.tsx:14–19,138–153,208–252`
在超过 80 项时使用 TanStack Virtual，预取 12 行、按 32px 估算，再测量可变行高，
只挂载窗口附近的节点。Cogent 的行高固定，本轮局部优化采用浏览器渲染跳过；两者
分别减少渲染工作和挂载数量，不能把本轮结果当成超大列表的完整虚拟化验收。
性能对照保持 200ms 时长、相同完整 AppShell 和数据，交替启停屏外跳过，各测四次，
记录 Chromium 的样式计算、布局与主线程耗时；帧间隔来自离屏 rAF，不能外推为实际显示器帧率。
Electron 40.9.3 / Chromium 144、125% DPI 的本机四次均值中，300 条“最近”开合的
样式计算为 422.49→117.84ms，主线程为 605.07→246.36ms；同样数据的项目开合
主线程为 406.62→221.53ms，整栏为 525.61→378.04ms。24 条的整栏主线程为
213.83→216.66ms，短列表没有一致的耗时收益；这些是该对照环境的观测，不是跨机器承诺。

分割线的中央胶囊只是装饰，指针捕获、方向键与双击都由父级 separator 承接；
隐藏胶囊时保留父节点及其扩展热区即可，不必另造调宽逻辑。zcode 在
`reference/zcode/packages/ui/src/components/ui/resizable.tsx:85–135` 同样保留 Separator，
将中央 Grip 子节点注释掉。Cogent 的 `SidebarResizeHandle` 用 `withHandle` 控制装饰，
呈现配方归 [UI布局](../UI布局.md)。

滚动条滑块透明并不等于轨道不占位；`scrollbar-gutter: stable` 会在内容未溢出时
继续保留槽宽。会话导航选择按需占位，避免短列表被空轨道挤窄；滑块显隐独立于占位，
通过标准 `scrollbar-width: thin` 与 `scrollbar-color` 使用 Chromium 原生绘制，
保留 Windows 的系统上下箭头且保持滑块可见，不依赖全局滚动标记。
Electron 40.9.3 / Chromium 144 的同页实测中，原生默认轨道为 15px、原生细轨道为 10px，
均自带箭头；现有 13px WebKit 定制没有箭头，仅给按钮设 `display: block` 也不会恢复系统绘制。
参照 zcode 的远程项目列表
`reference/zcode/packages/ui/src/project-sidebar/RemoteProjectList.tsx:143–144`，
列表只用 `overflow-y-auto`；同仓
`reference/zcode/packages/ui/src/app-shell/WorkspaceShellLayout.tsx:2509–2511`
为居中内容列显式保留稳定槽，解决的是居中基准随溢出横跳的另一种需求。
真实 Electron 回归覆盖两档侧栏宽度下的空、短、长及长变短列表，直接量槽宽与滚动位置，
并在鼠标位于列表外、滚动标记因静默而移除后检查原生样式与颜色保持不变。

## 7. 冒烟验证

- 项目域：create/rename/list → 会话挂 projectId → delete（盘上 projects/
  清空、会话保留悬挂）；
- 工作区注入：mock 端点捕获请求体 —— system prompt 含工作区声明、cwd、
  `Git 分支: main`、AGENTS.md 指令全文，四项全 true；
- 已删目录：回合成功后删目录再 submit → 错误帧「工作区目录不存在」，
  引擎存活。
