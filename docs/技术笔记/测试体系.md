## 1. 问题：为什么 tmp 冒烟不够

项目此前零正式测试，验证靠 tmp/ 一次性冒烟脚本 + 三关（lint/typecheck/build）
+ 人工 GUI 验收。三个结构性缺口：

1. **不入库**：tmp/ 被 gitignore，靠仓库外配方手工重建，换机器即失传
   （2026-11-12 就真实丢过一次，靠配方 + 源码推演重建）；
2. **不自动**：要人记得跑，改完引擎没人强制回归；
3. **缺下层**：批次 4 压缩验收翻的车（groupTurns 吞回复、flatWithCompaction
   合并、留痕落点）全是纯函数 bug —— 秒级单测能拦住的层级，却要跑完整
   GUI 验收才发现，定位还慢。

## 3. 分层与取舍（计划 D2–D8）

测试金字塔，**越往下越快越稳、大量写；越往上越像真实用户、少量写**：

| 层 | project | 测什么 | 关键取舍 |
| --- | --- | --- | --- |
| 单元（引擎） | `node` | compaction.ts 纯函数、toChatMessages 投影 | 直读源码不 build；每个翻过车的 bug 一条回归钉 |
| 单元（渲染） | `web`(jsdom) | groupTurns、flat 管道、unwrapIpcError | 同上 |
| 组件 | `web` | TurnGroup 渲染分支（RTL） | mock MessageRow 隔离 markdown；RunTrace/CompactionBar 用真件 —— 文案即验收口径 |
| store 行为 | `web` | bindEngineEvents 伪事件序列 | window.cogent 可编程 stub，测**真实接线**不测复制品 |
| 集成 | `integration` | 原 4 冒烟正名（85 项断言原样） | **跑构建产物** out/main/service.js（测打包后真协议路径）；fileParallelism: false（各自占固定端口 18940–18942）；global-setup 自动补 build |

**否决项及理由**（同计划 §五）：E2E（Playwright Electron —— 慢/脆/难定位，
GUI 黄金路径维持人工验收，远期池）；覆盖率阈值（学习项目按"翻过车的 bug
必钉回归"补，数字是噪音）；UI 快照测试（脆断言）；为覆盖率的 mock 堆砌
（测的是复制品）。

**co-located 布局**（D3）：单元/组件测试与源码同目录 `*.test.ts(x)` ——
改代码的人第一眼看到测试；集成测试拉构建产物、不属于任何源文件，独立
`tests/integration/`。

## 5. 迁移与搭建实录踩坑（值得沉淀的三条）

1. **RTL 自动清理依赖全局 afterEach**：官方 auto-cleanup 挂在全局
   `afterEach` 上，本项目测试一律显式 import（无 vitest globals）→ 组件
   测试 DOM 跨用例串场（首跑三个失败里两个是上一用例的「已工作」残留）。
   修法：setup 文件集中挂一次 `afterEach(cleanup)`。
2. **严格类型下的 JSON 边界**：recommendedTypeChecked 禁 explicit-any，
   引擎 stdout 帧/mock 请求体是动态 JSON —— 收敛到 harness 的
   `EngineEventFrame` / `SmokeResult` 接口，`JSON.parse` 处一次断言收窄，
   测试文件不再各写各的 any。
3. **fixture 时间戳要贴真实时序语义**：写 store 行为测试时把 bar 落点
   预期写反了两次 —— bar 的语义是"插在**压缩时刻已存在**的内容之后"，
   用假时间戳（300ms）配真钟 bar（Date.now()）必然全落尾部。集成语义的
   单测要么 fake timers 钉死时钟，要么 fixture 全用真实量级的时间戳。
   （这也反证了 D9 落点语义：bar 停在压缩打断流的地方，后来的内容排在它后头。）
