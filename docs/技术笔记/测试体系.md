# 测试体系

> 当前目录、命令与验收统一见[模块/测试.md](../模块/测试.md)。
> 本文解释测试层次、源码边界和目录取舍；不维护用例数量快照。

## 1. 问题：自动检查应该守住什么

一次性探针适合研究现象，却可能被忽略目录清理、依赖人工重建，也不会自动进入
CI。正式回归测试应进版本控制，围绕已经发生过的 bug 和新增逻辑验证行为：
消息分组与快照投影适合纯函数测试；会话隔离适合事件序列；协议与进程生命周期
需要真实子进程链路；像素和动画观感需要真窗口验收。

测试代码是检查程序，不是运行实现。删除它不会改变应用当前行为，但会移除后续
修改的自动报警；搬目录只改变查找与导入路径，不应改变测试场景与产品实现。

## 2. 三仓源码对照

本次核对测试目录、源码导入与 Vitest 配置，结论只覆盖这些组织机制。

| 参照 | 本次实读出处 | 可取之处 |
| --- | --- | --- |
| pi | `reference/pi/packages/agent/test/agent.test.ts:11–19`；`packages/agent/vitest.config.ts:17–25`（同仓） | `test/` 与源码分开，测试直接导入 `../src/index.ts`；包别名指向源码，避免必须先构建 |
| deepseek-harness | `reference/deepseek-harness/packages/core/agent/tests/model-selection.spec.ts:1–13`；`vitest.config.ts:18–22、199–247`（同仓） | 包内 `tests/` 直读 `src/`；路径映射优先于包产物，按进程约束拆 project |
| zcode | `reference/zcode/vitest.config.ts:11–25、56–69` | 测试可与源码分离，由 alias 和显式 include 决定执行对象；真实子进程套件串行 |

三者说明目录与执行能力可以分开设计，没有“组件测试必须放在组件旁边”的技术
约束。Cogent 采用仓库级 `tests/` 集中组织，以域目录维持与源码的对应关系；
源码中不再夹测试文件。代价是相对导入更长，因此 renderer 沿用源码别名，Node
域的导入与 mock 都显式指向产品文件。两处指向同一模块，才能真的截住依赖。

## 3. 分层与可信度

| 层次 | 要回答的问题 | 边界 |
| --- | --- | --- |
| 纯函数 | 分组、投影、分词、预算是否正确 | 少量输入和可解释预期，不复制算法算预期 |
| store / hooks | 事件先后与异步晚回是否污染当前状态 | 发真实事件，检查状态；假时间与时间戳统一口径 |
| 组件 | 用户操作、默认开合、DOM 身份是否稳定 | 只 mock 无关外围；被模拟的正文不能证明真实 Markdown 不重挂 |
| 黑盒集成 | 构建后的协议、工具、权限、MCP、技能与交互链能否往返 | 临时数据根与本地假服务；保留真实进程、协议和产品装配 |
| 手动 GUI | 真实像素、滚动、主题、缩放和动画是否正确 | jsdom 不具备浏览器布局与绘制能力，不能外推性能结论 |

同一问题保留不同层次时，每层应有独立的失败边界。纯函数的排期测试与实际
Markdown 管线的节点身份测试分别检查算法和接线，不能仅因主题相同就合并。
覆盖率数字和大范围快照不能替代行为断言；真实 GUI 自动化是否引入另行评估。

## 4. 目录迁移与测试基础设施的约束

- **发现路径与类型路径同步**：Vitest 只收指定目录，TypeScript 工程也要收同一批
  文件；仅移动文件会造成漏测或类型感知 lint 找不到项目。
- **mock 与 import 指向同一源码**：搬目录时一并调整相对模块名、动态 import 与
  `vi.mock`，保持模块实例唯一；`@/` 仍指向 renderer 源码。
- **文件位置推导需核对**：`import.meta.url` 上溯项目根的层数依赖目录深度；
  `tests/electron/main/host/` 与原目录等深，运行时定位测试的上溯口径保持有效。
  `tests/run-tests.mjs` 按工作目录定位 Vitest 和自带 Node，启动器也随测试集中管理。
- **RTL 清理集中设置**：本项目显式 import Vitest API，不启用 globals；
  `tests/setup-web.ts` 统一挂 `afterEach(cleanup)`，避免 DOM 跨用例串场。
- **时间与构建口径**：使用 fake timers 时统一 fixture 时钟；黑盒集成先检查产物
  新鲜度，防止验证的是旧包。源码级测试与产物级测试互补，不互相冒充。

CI 只是执行入口；检查通过的含义仍由每个场景实际走到的产品路径决定。
