# 工具系统与审批（tools & approval）

> 工具执行面 = pi coding-agent 内置 8 选 7；审批 = 引擎协议层的判定矩阵 +
> 挂起 + 工作区规则记忆。代码：`kernel/pi-session-factory.ts`（allowlist +
> beforeToolCall 链式包裹）、`runtime/{tool-meta,write-boundary}.ts`、
> `runtime/session.ts`（decideApproval）、`runtime/approvals.ts`（规则表）、
> `electron/main/ipc/approval.ts`、`renderer/.../ApprovalPanel.tsx`。

## 1. 问题

没有工具循环的 Agent 只是聊天机器人：模型说"我应该先读 package.json"，然后
只能等用户贴内容。工具系统要回答三个问题：

1. **执行**：工具怎么注册、参数怎么校验、结果怎么回灌模型（工具循环）；
2. **风险分级**：读文件和写文件不是一种动作 —— 谁来判定"这个调用需要人点头"；
3. **挂起**：LLM 循环是异步流水线，"等用户点击"意味着循环中途悬停 —— 谁保它
   不死锁、可中止、可恢复。

第 3 问是工程难点：挂起发生在模型两次请求之间，协议层要有事件通知宿主"我在
等你裁决"，宿主裁决要有回流通道，中止/删会话/退出要把悬着的 Promise 收口。

## 2. pi 的做法（源码，pi-agent-core）

pi 核心无内置工具包（连 read 都没有），只给骨架；coding-agent 包提供 8 个
内置工具（read/bash/powershell/edit/write/grep/find/ls）：

- **AgentTool**：`{ name, label, description, parameters, execute }`，参数用
  pi-schema builders（obj/str/opt/int…）声明 + 自动校验（`agent-loop.js`
  prepareToolCall → validateToolArguments，非法参数直接 error 结果，不进 execute）；
- **执行管线**（`agent-loop.js` executeToolCalls）：`tool_execution_start` 事件
  （L352/385/421 三处 —— sequential/parallel/truncated 三路都先发）→
  `prepareToolCall`（L499 内含 beforeToolCall 钩子）→ execute →
  `emitToolExecutionEnd`（L654）。**start 事件在审批钩子之前**：宿主会先看到
  running 卡、随后才是审批请求 —— 不是 bug，是"调用已发生、执行未放行"的
  如实呈现；
- **beforeToolCall**（`types.d.ts` L279）：`(context, signal?) => Promise<
  BeforeToolCallResult | undefined>`；`{ block: true, reason }` = 拒绝（模型收
  error 工具结果，reason 为可见原因），undefined = 放行；**返回 pending
  Promise = 挂起**，signal 在 abort 时触发 —— 挂起方必须监听它，否则中止后
  Promise 永悬、run 永不收尾；block 后 pi 照发 `tool_execution_end(isError)`，
  事件流不需要合成任何帧；
- **工具目录冻结**：find/grep 的二进制获取链在**模块加载期**执行
  `getBinDir()`（读 PI_CODING_AGENT_DIR）—— 之后改 env 无效，且静态 import
  恒先于模块体执行，env 归位必须住在入口 wrapper 的动态 import 之前
  （`src/host/index.ts`；回归钉 pi-bin-domain.test.ts）；
- **转录**：工具调用 = assistant 消息的 toolCall 块，结果 = 独立
  `role:'toolResult'` 消息（toolCallId 配对）—— 恢复历史按 id 配对投影。

Cogent 的工具消费面：`TOOL_METAS` 静态表（runtime/tool-meta.ts —— 历史回查
在内核未装配的惰性会话上也要 kind/摘要，不能依赖活工具实例；pi 内置 8 工具
均未设 ToolAnnotations，风险类别在 pi 侧无信息可查，ToolKind 是纯产品投影）；
工具集经 createAgentSession 的 `tools` allowlist 显式指定（sdk.ts:280-294）。

## 3. 对比

| | 风险分级 | 审批判定 | 挂起实现 | 记忆（"总是允许"） |
|---|---|---|---|---|
| **Cogent** | ToolKind 四类（read/write/exec/network） | 引擎一处矩阵：kind × permissionMode（ask/plan/auto/autonomous）+ 工作区级规则表 | beforeToolCall 返回 pending Promise + pendingApprovals 表 + signal 兜底 | **工作区级持久**（`~/.cogent/approvals.json`，roots×kind 快照）+ 项目级默认模式 |
| **Claude Code** | 工具名 × 参数（Write/Edit/Bash 分立，Bash 按命令前缀） | permission-mode（default/acceptEdits/plan/bypassPermissions）× settings.json 的 allow/deny 规则表 + PreToolUse hook 可改写判定 | SDK 侧 control protocol 挂起（CLI 内联 canApprove 弹窗；headless 模式 canUseTool 回调） | 分工具：Bash/WebSearch 域 = 永久落盘 settings（存精确命令，**曾泄漏密钥** —— Apiiro 实锤 settings.local.json 被误提交）；文件写（Edit/Write）**只到会话结束，刻意不落盘**，永久放行走模式不走规则 |
| **OpenAI Codex CLI** | 沙箱三档（read-only/workspace-write/danger-full-access）与审批策略（untrusted/on-failure/on-request/never）**两维独立** | Rust 引擎 exec 前按 (sandbox, approval_policy, 命令分类) 查表 | TUI 收到审批请求渲染按钮，通道双向（approveRequest/denyRequest） | 无 always 规则；等价物 = trusted projects（`~/.codex/config.toml` 目录信任）；`untrusted` 策略因太烦已退役（0.49+） |
| **DeepAgent**（LangChain deepagents） | 工具粒度：human_in_the_loop=[...] 指定哪些工具要审 | 包装层：待审工具改为先返"待确认"标记内容 | **LangGraph interrupt()**：图执行硬停在节点边界，Command(resume) 恢复 —— 挂起即图状态，天然可持久化/可恢复（Cogent 的挂起是进程内 Promise，引擎重启=丢） | 无内置（resume 时业务自己记） |
| **ChatGPT 桌面 Agent** | 操作分级（浏览/改动/系统） | 会话级"完全访问"开关（关=逐操作确认） | 产品侧（非开源），确认卡挂在消息流 | 会话级记住 |

规则表流派补充（Qoder「始终允许本项目」= 项目级持久，Cogent 同流派）：
三家共识 = **文件写的永久放行绑定"位置"不绑定"内容"** —— Cogent 只存
roots 不存命令/内容，且存引擎侧全局（`~/.cogent`）不进项目目录，杜绝
Claude Code 的 repo 内误提交泄漏面。与 Claude Code「deny > allow 严格序」
铁律同构的落点 = **规则永不放行越界写**（根内判定先于规则查询）。

关键分歧点：

- **判定在哪层**：Claude Code/Codex 在**宿主/引擎贴身层**查表（规则可来自用户
  配置文件），Cogent 放**引擎协议层**（beforeToolCall 一处，UI 只是裁决面板），
  DeepAgent 放**图编排层**。Cogent 的选择理由：矩阵是跨宿主一致的安全语义
  （换壳不改行为），且事件（approval.request）与回流（approval.respond）都已是
  协议帧，任何宿主可驱动；
- **审批 vs 沙箱**：Codex 的沙箱是 OS 级（seatbelt/landlock 白名单文件系统），
  审批只是沙箱之上的 UX；Cogent 当前无 OS 沙箱，审批是工具执行授权边界，不能声称它提供了同样的
  系统级隔离。其他产品的沙箱能力会演进，不以原产品对照永久限定本项目方向；
- **挂起语义**：DeepAgent 的 interrupt 挂在图状态里（可跨进程恢复），Cogent 挂在
  引擎进程内存（引擎重启=挂起丢失，run 已死无所谓恢复）；Claude Code 的
  headless canUseTool 也是进程内。桌面单机语境下进程内挂起够用。

## 4. 取舍记录

- **pi 时序（start 先于审批）与协议的关系**：running 卡先行 + 审批卡随后，
  正好表达"调用已发生、执行未放行"；拒绝后 end(isError) 自然收口，流式段化/
  历史回查/事件流三条投影路径零特判；
- **审批卡是用户痕迹，不随终态替换消失**：模型转录里拒绝只是 error 工具结果，
  用户点过什么无处可查 —— run.completed 替换时保留 approval 行（续在段化终态
  后），终态呈置灰单行；
- **「允许，并切换为 ▾」落项目级默认**（zcode 对齐）：允许本次 + 切会话模式 +
  记为项目默认（同一项目新会话沿用）—— 持久范围收窄到"用户显式批准的项目"，
  忘了关的风险由权限菜单可见性兜住；切回收紧档走权限菜单，不藏在审批里；
- **重复裁决 → InvalidParams 而非静默**：双击/与中止竞态都属此类，显式报错让
  宿主可感知（store 层乐观翻卡 + catch 收声，终局以 run 终态事件为准）；
- **确认面板 vs 弹窗**：弹窗打断感强（模态抢焦点，多审批排队更糟），
  Claude Code/Codex/图 1 产品全是内嵌面板 —— Cogent 落对话底部确认面板，且
  **待审批时替换输入区**（run 挂起中本就发不出消息，留着能打字的框是误导
  —— HomeChat 条件切换 Panel/Composer，输入草稿提升父层持防卸载丢字）；
  卡内布局 = 竖排全宽选项列表 + 序号 + 选中态高亮（终端式选择的 GUI 化：
  ↑↓/Tab 移动选中、Enter/确认钮执行选中项、点击直接执行）。pending 态是
  会话级状态（数组形态 —— pi 并行执行同批工具会并发多个 approval.request），
  裁决完成后落置灰痕迹行进消息流（痕迹是进程内存态，跨重启审计靠工具卡
  error 形态 —— 拒绝的写在转录里是 isError toolResult，持久）；
- **「告诉模型接下来怎么做」= 拒绝 + 附言**：附言拼进 block reason →
  pi 工具 error 结果回灌模型（2000 字符截断），是 steering 的最小雏形 —— 真
  运行中插话（pi 已有 steer()/followUp() 队列）是后续空位，不混做；
- **规则表为什么单文件 + 只存 roots**：规则是全局一小份（预计个位数），单文件
  整读整写最贴切（driver collection 是一实体一文件的目录语义，不匹配）；
  Claude Code 的 settings.local.json 存精确命令（含密钥）被误提交泄漏的教训
  → 只存位置；`untrusted` 策略太烦被 Codex 退役的教训 → 面板选项封顶、
  「本会话始终允许」中间档不做（「允许，并切换为」已覆盖会话级需求）；
- **UI 件事件语义坑（base-nova = Base UI 原语）**：shadcn 组件名相容 Radix
  语法，但 base-nova 变体的菜单项事件跟 Base UI 走 —— Radix 风格 `onSelect`
  会静默落到 DOM 原生 select 事件（菜单项点击永远不进 handler），要用
  `onClick`。从 Radix 文档抄配方时要对每招核对原语实现。

## 6. 部署与加载期事实（运维须知）

- **undici/node 版本**：pi 包根 import 链含 core/settings-manager →
  http-dispatcher → undici 8.x，其模块初始化的 `createZstdDecompress.bind`
  （zlib zstd）在 node <22.15 上是 TypeError —— 引擎与加载 pi 的 vitest 都
  必须跑 node ≥22.19（pi engines 声明）。落地：harness 的引擎 spawn 对齐
  生产三级链（COGENT_NODE_BIN → resources/runtime node → 兜底）；
  `tests/run-tests.mjs` 在系统 node 过老时自动切自带 runtime node 跑
  vitest；
- **fd/rg 获取链**：PATH（fd 兼容 fdfind）→ `<PI_CODING_AGENT_DIR>/bin`
  自动下载（GitHub releases；PI_OFFLINE=1 关闭）→ 皆不可得时 error 降级
  不崩引擎。信创内网资产域不可达 = find/grep 不可用，缓解 = 分发期预置
  （风险与路线见 [全局架构](../计划/全局架构.md)）。
