# 流式呈现动效（扫光 + 逐词淡入）

> 对话流的"活着"信号层：工作行标题扫光 + 流式正文逐词淡入。CSS 形态源自 zcode，
> 块身份另与 pi 的实例复用、Harness 的源码位置 key 对照。计划与决策表见
> [计划/流式呈现动效.md](../计划/流式呈现动效.md)及
> [正文渐显块身份修复](../计划/正文渐显块身份修复.md)。

## 问题

流式输出期间要持续告诉用户"还在工作"：过程间隙（等首轮 delta / 工具执行 /
轮间往返）的工作行是唯一活动信号；正文输出时最新 delta 位置要有"正在长出来"
的观感。硬约束：**动效只能是可丢弃的视觉层** —— 不改正文数据、不碰布局高度、
不与虚拟滚动测高 / 底部跟随打架、reduced-motion 全退化为静态。

## 扫光（渐变文字淡带）

原理四件套（`globals.css` `.shimmer`）：

1. `background-clip: text` + `color: transparent`：文字成为渐变的裁剪蒙版；
2. 渐变嵌一条 22% 透明度的"淡带"（`color-mix(in srgb, 基色 22%, transparent)`），
   其余 stop 全为基色（muted-foreground）；
3. `background-size: 300%` 留平移空间；keyframes 只动 `background-position`
   `100%→0%`（扫 2s）再钉住（停 2s）—— **扫停呼吸**而非匀速循环：匀速观感是
   "进度条在跑"，扫停才是"活着"；停下时文字与静态行同色，淡带扫过变暗，
   语义是"正在工作"而非"高亮"；
4. `will-change` + `translateZ(0)` 提前升层：background-position 逐帧变更走
   主线程重绘，流式期主线程被 delta / 码表打满时动画掉帧、文字在实色与渐变间
   跳变，观感即"工作中行闪动"。

消费方：`TraceLine data-status=running` 的标题（工作中行 + 思考中标题）与工具行
类别词运行形（trace 家族一处定义全体生效）。`.shimmer-none` 是 reduced-motion
出口。

## 逐词淡入（stream-reveal 插件）

原理：rehype 插件把流式普通文本切成单元（中日文按字、拉丁文按词）。短批每个
非空白单元包 `<span data-reveal="new" style="--reveal-delay:Xms">`；超过 96 个
非空白单元时，单个连续文本片段压成最多32组，每组一个span；加粗等内联标签会拆出
多个片段，32不是整个富文本块的动画对象上限。组间目标8ms，跨片段/跨块同批时服从
250ms排期预算压缩间隔。CSS 用
`transition: opacity 300ms ease-out var(--reveal-delay)` + `@starting-style
{ opacity: 0 }` 淡入 —— 短文本保留尾巴，大批避免整片直出或数千个并发过渡。

四条铁律（每条都对应一次真实翻车，出处 zcode）：

1. **DOM 文本首帧即完整，只动 opacity**：zcode 三代前身都维护随时间变长的
   visibleText，高度逐帧增长持续触发 ResizeObserver，撞进虚拟滚动测高与底部
   跟随，全部撤回；
2. **transition + @starting-style，不用 keyframes**：单元下一帧就从 new 变
   settled，keyframes 选择器失配动画即被移除只播一帧；transition 只要属性链
   在就跑完，@starting-style 只作用于首次挂载不重播；
3. **settled 单元也包 span**：`hast-util-to-jsx-runtime` 按"标签 + 同级序号"
   生成 key，只包新单元时下一帧新词复用旧词的 DOM 节点、动画不播；
4. **淡入时长恒 300ms，速度只进排期延迟**：时长随吐字速度缩放会把每字压到
   2-3 帧渐变 = 肉眼无动画；"能不能看出淡入"只取决于单字有几帧处在渐变。

排期器（跨帧浮现时钟）：目标滞后 = `clamp(max(6×单元间隔, 1.5×批间隔), 80,
250ms)` —— 渲染故意落后 token 流约 6 个单元，缓冲把突发铺平；批内间隔
`min(40ms, 可用时间/数量)`，积压时至少铺开 15ms 逐步回落；速度/间隔按 EWMA
自适应（停顿 >300ms 不更新速度，防停顿后突发被按慢节奏排满）。
大批的8ms目标另受剩余窗口除以实际间隔数约束：首拍有count−1个间隔，接在旧队尾后
有count个间隔。多个大段或富文本片段不能靠固定地板把后续文字推到250ms之外。

### 块身份、文本进度与节点边界

身份回答“是哪一个块”，文本比较只回答“本块新增到哪里”。每个真实 Streamdown
Block 实例持有独立进度与唯一插件函数；消息级时钟共享节奏，候选计划按块实例 Symbol
索引。同文新段落不会认领另一段的已提交文本，同批同文段落也不会复用同一排期。

只有保留 span 还不够，细/粗组的边界也必须保留。已提交边界在普通追加时沿用，新单元
才生成新组；601字首批的32组后连续加甲、乙，节点数按32→33→34增长，旧组不重压。
短批累计跨96单元仍保留原节点。否则新字可能复用旧 span，即使标 new，`@starting-style`
也不会在已挂载节点上重新启动。

Streamdown 的公开 BlockComponent 接口提供块序号，runtime 用消息 useId 与序号定 key
（`node_modules/streamdown/dist/index.d.ts:590,716-731`、`dist/chunk-7TTQLYRW.js:40`）。
序号只在当前分块结构中有意义：链接定义、脚注可能使多块合成整文块（同 chunk `:17-20`）。
包装只观察并原样返回默认 parser 的结果；块数减少、旧稳定前缀改变或本块解析文字不再是
可信追加时，该次重解析 settled 后提交新边界，不把旧第二段当新增。解析、清洗与高亮
继续由默认 Block 负责，CSS 仍负责每帧透明度，无新增动画 timer/rAF。

### 业务终态与视觉收尾

业务相位先消费明确结果：Host 从 pi 的 agent_settled.aborted 转出 run.failed.reason，
chat runtime 清 stopping 请求位，桶内turnOutcomes按user.id保留各回合结果，HomeChat据此
显示已停止/出错了/已工作。新提交不把旧停止回合改为done；操作错误条不代替回合结果。
完整状态链及三仓同主题出处见
[pi 接入 §2.3](pi接入与会话管理.md#23-终态原因消息失败与-run-中止分开)。有终态 messages
便直接采用 Host 完整分段，不把本地尾占位再续一次；真实停止不会为等待视觉动画而延迟。

准备期停止可能需要等待未提供 signal 的扩展 await 返回：Host 保留本次运行预约，
streaming 此时仍为 true，WorkingLine 的唯一流内工作行显示「正在停止」。

终态详情缺省收起是用户的明确裁决：done/stopped/failed一致，用户手动选择仍优先。
半截终答由TurnGroup放在折叠体外，收起过程不会隐藏它。此处有意偏离异常历史强开的
参照策略：Harness `reference/deepseek-harness/packages/client/ui-chat/src/client/chat/ChatGroupSeat.tsx:137-160`
对aborted/interrupted/error设alwaysOpen；zcode
`reference/zcode/packages/ui/src/v4/conversationTurnRenderUnits.ts:194-202`也强开异常历史。
pi `reference/pi/packages/coding-agent/src/modes/interactive/interactive-mode.ts:533,4745-4760`
是工具输出缺省收起与全局手动切换，不是同款Web回合折叠合同。
这段等待由实际工作收敛决定，不是为了排空正文动画；权威终态到达才移除工作行。
手动 continue 的终态快照包含旧回答前缀与新尾段，Markdown 仍只消费最终消息，
不承担运行预约、输入保存或迟到 RPC 的判断。

业务完成和视觉资源回收各有 owner。streaming=false 立即下传 isAnimating=false、停止新增
reveal；终态头、输入区和工作行随业务更新。相同正文或末尾追加时，Markdown 只暂留同一
streaming Block 树，让已经创建的 opacity 与 marker color 过渡自然结束，再切原生 static。
contents 根包装提供稳定 DOM ref，维持原布局；getAnimations({subtree:true}) 只筛本件
data-reveal/data-reveal-marker 对应属性的 CSSTransition，不等扫光或任意装饰动画。

Animation.finished 表示真实完成，取消会 reject；Promise.allSettled 统一收口。延迟阶段也
属于该过渡，不能只等已经有可见透明度变化的字。无匹配过渡、页面 hidden、reduced-motion
实际撤销过渡，或权威正文非前缀替换时直接 static；新流、内容换版与卸载撤销旧代回调，
cleanup 不 cancel 还在显示的动画。这里没有按550ms猜测结束的 timer，也不延迟业务运行位。

最终必须真正进入 static：Streamdown `dist/chunk-7TTQLYRW.js:40` 的 streaming 模式仍执行
remend，单独关闭 isAnimating 不会还原未闭合强调、行内 code 与链接的最终字面语义；
static 才走整文 parser。`index.d.ts:687-690` 与同一 runtime 的 onAnimationEnd 只通知
isAnimating 改变，不能当 CSS 已结束。保留树是一次局部视觉收尾，不是永久缓存预览结果。

三仓同主题对照：pi `reference/pi/packages/coding-agent/src/modes/interactive/components/assistant-message.ts:117-133`
复用 Markdown 槽，`interactive-mode.ts:3690-3724`（同 interactive 根）把同一组件更新为结束；
借业务与实例分工，CLI 没有本件 CSS 排空。Harness
`reference/deepseek-harness/packages/client/ui-primitives/src/markdown/MarkdownText.tsx:30-60,201-213`
在结束时清增量 renderer、全文 renderSettled，说明最终语义需要真正结算。zcode
`reference/zcode/docs/streaming-markdown-reveal.md:210-224` 明确接受切 static 后尾巴直出；
`packages/ui/src/v4/conversationTimelineLiveTail.ts:50-81`（同 zcode 根）则保持尾轮父容器身份，
避免 running 改变时整轮重挂。Cogent 的自然收尾按本项目目标实现，不冒充三仓已有同款机制。

常规有 user 回合的尾 answer 位置可沿用已有组件。工具封段与无 user 首项 id 更换的重挂已由
封段连续性机制消除（占位 id 终身不变 + 段序数 key，见[消息呈现](../模块/消息呈现.md)
「封段正文连续性」）；权威快照整段替换正文段 id、或快照段数与 live 占位数不齐的边角仍会
换 DOM（settled 不重播）。局部收尾不能救回已卸载的组件，也不保留权威消息已删除的正文。

## 取舍与 Cogent 适配

- **扫光**：换 zcode 形态（保留原合成层提示，两边同款）；色标不接聊天正文
  主题（工作行在 chrome 区不在 md-body 容器内）。
- **逐词**：三处适配 —— ① renderer 事件入口按会话30ms固定窗口发布，
  Markdown 直接消费，不叠第二套延迟；EWMA 自适应的是 reveal 排期而非 store
  发布频率；② streamdown 2.7.1 的 block
  解析在 render 期 useMemo 同步完成（2.5 走 effect + startTransition），commit
  放本帧渲染后的 effect 即可，无需像 zcode 落后一帧；③ 2.7 的 `rehypePlugins`
  是**覆盖语义**（默认管线 = raw/sanitize/harden），Block adapter 必须继承 Streamdown
  实际传下的插件链再追加本块插件，不能重建或覆盖掉默认清洗与内部处理。
- 保留的 zcode 坑位对策：插件函数名递增序号（processor 缓存按函数名拼 key，
  同名实例被共用会读到第一条消息或另一块的 state）；进度按真实 Block 实例记（streaming
  模式每 block 独立跑 rehype，插件只见一个 block，整条消息一个长度会坐标系错位）；
  pre/svg 跳过（代码块高亮异步，逐字与高亮打架）；行内 code 整体一个
  单元；li::marker 过渡 color（::marker 不支持 opacity）。table 的**逐字/逐格**
  仍跳过：单元格逐字会反复触发表格列宽布局且曾实测产生上千动画对象。
  **行级** mount-only 淡入已交付（[代码与表格过渡](../计划/代码与表格过渡.md)）：
  行身份在自有依赖结构里找到（streamdown CodeBlock 每行一个索引 key 的 span、
  @streamdown/code 按行前缀缓存 grammarState 只重亮尾部），@starting-style 只认
  首次挂载 → 旧行元素保留永不重播、新行淡入，不动 stream-reveal、不给代码排期
  —— zcode「随挂载直出」的接受边界在此点上被超越，证据来自依赖 dist 实读。
- 块级装饰（引用边框 / 表格边框 / 复选框）随挂载直出不排期；收尾机制见上文
  [业务终态与视觉收尾](#业务终态与视觉收尾)，业务不等动画（收尾等待同认行级
  淡入，纯代码消息的尾行不被切断）。
- 来源信号仍是 streaming 与消息正文前缀：静态历史无 reveal，非前缀替换 settled；
  运行中消息重新挂载时，旧来源信息未由当前 Markdown 接口传入，仍可能按首帧追加播放。
  块身份修复不能被外推为已区分所有实时首片、快照和切会话恢复。

## Cogent 落地实测的三个追加教训（真机 CDP 采样定案）

1. **扫光 `.shimmer` 必须 `@utility` 注册**：trace 组件用 Tailwind 变体引用它
   （`data-[status=running]:*:data-[slot=trace-title]:shimmer`），v4 只为认识的
   utility 生成变体规则 —— 普通类名作变体目标**零输出**，首版即栽在这
   （.shimmer 定义完好但从未挂上，运行中 title 的 animationName 恒 none）。
   色标基色用 foreground 而非 muted-foreground（后者再 22% 透明化几乎融进
   背景，扫不动）。
2. **30ms 合帧必须有唯一 owner**：逐片提交下游会放大 store 通知，且排期器
   每批至少铺开15ms容易积压。入口按会话首片起拍，后续不延拍，结构事件同步
   flush，快照替换 discard；Markdown 直接更新时不再享有30ms延迟，这是预期。
   StrictMode cleanup 必须释放队列和timer，重订阅不能继承死timer；组件仍测
   reveal新旧单元和processor独立性，入口另测卸载/重挂，不删断言逃避时序变化。
   本次复用诊断实读出处（不扩大结论）：zcode
   `reference/zcode/apps/zcode-cli/packages/bootstrap/src/zcode-protocol-v4/conversation-topic-publisher.ts:454-489`
   在发布前合批；`reference/zcode/packages/ui/src/v4/conversationProjectionStore.ts:939-1001`
   整帧apply后通知；Harness
   `reference/deepseek-harness/packages/client/ui-conversation/src/client/conversation/assembly.ts:112-168`
   普通流dirty、结构事件立即flush。本项目只借发布/屏障分工，不迁移它们的协议或rAF节拍。
   pi `reference/pi/packages/agent/src/agent-loop.ts:424-477` 的 message_update
   仍是引擎增量语义；UI合批不改变权威账本，pi底层TUI节流未核实。
3. **滚动意图与最终像素分别验证**：Provider controller 独占 following/read 与 scrollTop，

   **为什么不校正小数残差**：getBoundingClientRect 是布局坐标，不能直接代表屏幕像素。

   却逐字节相同；translate 把 DOM y 修平后，图标像素反而变化。视口 containment 也能
   单独触发约1物理像素的跳动。但去掉两者并不充分：只改变视口起点，连续输出仍可跳1px。
