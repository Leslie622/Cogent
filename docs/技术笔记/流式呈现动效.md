# 流式呈现动效

> 学习主题：文字渐显、实例身份、视觉收尾与滚动像素验证。
> 当前机制见 [消息呈现](../模块/消息呈现.md)，手测见 [消息呈现用例](../测试用例/消息呈现.md)。
> 本篇汇集原动效、块身份、收尾、连续性与抖动修复的调研结论；整理未重新执行上游实验。

## 1. 动效必须是可丢弃的视觉层

正文首帧就占满已经收到的文本位置，只推进透明度，不按时钟逐字改 visibleText。
否则高度随动画增长，ResizeObserver、底部跟随和测高互相追赶。zcode 曾撤回多代
visibleText 方案，最终采用完整文本加 opacity（`reference/zcode/docs/streaming-markdown-reveal.md`）。
系统 reduced-motion 取消过渡时，起步 opacity 也要放开，不能留下永久透明的新字。

工作状态用标题扫光与独立图标表达。扫光是 background-clip:text、实色字形中嵌淡带、
300% 渐变底图扫 2s 停 2s；Tailwind 变体消费它，必须以 `@utility` 注册。
普通 CSS 类存在不等于 v4 会为 `data-status:shimmer` 生成变体。基色取 foreground，
淡带过浅会融入背景。`will-change` 的提示不等于已经证明纯合成或低成本。

WorkingSpinner 只拥有图标槽，当前 CSS 为等边三角的 4s/2s 旋转加 3s opacity 呼吸，
伪元素在呼吸相位上错开。本体 opacity 会与子层相乘，不能把层间呼吸当成独立叠色。
等边三角绕质心转 120° 与自身重合，改旋转相位不一定制造可见的三叶错相。
具体形态归 [UI布局](../UI布局.md)，不在此重复候选稿与尺寸清单。

## 2. 文字单元、预算与块身份

普通正文用 rehype 插件按中日文字、拉丁词切单元。短批为每个非空白单元包 span；
超过 96 单元时，一个连续文本片段压为最多 32 组。内联标签会拆片段，32 不是整块
动画对象总上限。排期共享 250ms 窗口，不能让多个片段各自按最小步长把末字推到窗口外。

时长固定 300ms，速度只影响延迟。EWMA 估计批间隔与单元速率，目标滞后为
`clamp(max(6×单元间隔,1.5×批间隔),80,250ms)`；短批间隔最多 40ms，大批目标 8ms，
均服从实际剩余预算。renderer 入口按会话 30ms 合批，Markdown 不叠第二层发布计时。
结构事件先 flush，权威快照替换 discard，避免尾字丢失或迟到 delta 复活。

**文本不是身份。** 同文新段落不能认领旧段落的进度，同批两块也不能共享排期。
每个真实 Streamdown Block 实例持有 Symbol、进度和唯一插件；消息只共享节奏。
已经提交的细/粗组边界也必须保留，新字才挂新 span，否则新增内容会复用旧 DOM，
`@starting-style` 不再触发。settled 单元仍包 span，维持相同标签与同级序号。

Streamdown `index.d.ts:590,716-731` 提供 Block 序号，runtime 用消息 useId 与序号作 key；
`dist/chunk-7TTQLYRW.js:17-20,40` 的脚注/引用可能把多块变成整文块。
序号只在当前分块结构有效。旧稳定前缀改变、块数减少或解析结果不再可信追加时，
本次重解析 settled 后提交新边界，不能把重整后的旧文字当成新词重播。

插件追加到 Block 实际收到的 rehypePlugins 末尾，继承默认 raw/sanitize/harden。
该选项是覆盖语义，自己重建数组可能拆掉清洗链。插件函数名也需唯一，processor
缓存按函数名组合 key，复用同名插件会让别的块读到第一块 state。

## 3. 终态语义与视觉资源回收分工

业务结果立即交给页面；停止、失败、输入恢复、工作行消失不等动画。Host/renderer
运行 owner 的边界见 [pi接入与会话托管](pi接入与会话托管.md)，此处只管仍在显示的 DOM。
相同正文或前缀追加的终态可以暂留原 streaming Block 树，让既有过渡自然结束，再切 static。
权威替换、页面 hidden、无过渡或 reduced-motion 撤销过渡时直接收口。

`getAnimations({subtree:true})` 只筛本件 data-reveal/marker/代码行/表格行的指定属性
CSSTransition。`Animation.finished` 在取消时 reject，用 allSettled 回收；延迟阶段同样是
过渡的一部分。新流、内容换版与卸载使旧代回调失效，cleanup 不去 cancel 仍可见的动画。
不能按固定 550ms 猜结束，也不能等扫光这种永久动画。

最终必须真正进入 static。Streamdown `dist/chunk-7TTQLYRW.js:40` 的 streaming 模式
仍做 remend，单关 isAnimating 不会恢复未闭合强调、行内 code、链接的最终字面语义。
`index.d.ts:687-690` 的 onAnimationEnd 只是 isAnimating 变化通知，不是 CSS 完成事件。

封段连续性还有父层身份：placeholder id 终身不变、段按稳定序数 key，避免工具启动时
因分类或状态变化重挂正文。段间排期以旧段队尾接力，新段首拍不早于旧段淡入结束。
权威快照替换段 id 或段数对不上时仍可换 DOM；局部收尾不能救已卸载组件。

## 4. 代码与表格为什么只按行淡入

逐词插件跳过 pre/svg/table：异步高亮与单元格列宽会放大解析和动画负担。
这不代表代码与表格没有过渡。依赖中有可靠行身份：

- `node_modules/@streamdown/code/dist/index.js` 按行前缀缓存 grammarState，只重亮尾部；
- `node_modules/streamdown/dist/chunk-7TTQLYRW.js` 的 CodeBlock 用索引 key 的行 span，
  不是高亮 HTML 整体替换；追加行时 React 保留旧行，挂新行。

CSS 在 `data-md-streaming` 内对代码行和 tr 做 mount-only opacity 过渡，新行淡入、
旧行不重播；行内新增文字仍直出，不给代码额外逐词排期。依赖 DOM 合同由
`tests/renderer/components/ui/md-line-transition.render.test.tsx` 检查，
不能把这种合同测试等同为重复测试上游功能。收尾等待同时包含这些行过渡。

## 6. 滚动几何与最终像素必须分别验证

用户上滚在 capture 同栈释放跟随；程序 scroll、RO 与终态折叠不能冒充主动回底。
离底恢复跟随需要向下意图、真实移动与同布局到底；近底明确下行输入可同步恢复。
工作行保留一份 DOM 与时钟，不按 following 切换业务节点，也不复制读屏文本。

原抖动实验得到三条不能省略的证伪教训：

1. DOM y 变化 0.7 CSS px 时图标裁片可能相同；translate 把 DOM y 归零后像素反而变化。
   布局坐标不是屏幕像素，不以 rect 归零充当视觉验收。
2. 去掉 viewport containment 与残差 translate 有效，但固定 top=10px 的隔离页覆盖不够；
   只改变视口起点到 48/48.5px 就能复发 1 物理像素二态。副本可掩盖，不证明副本必需。
3. RO 不等于总在 paint 后。rAF 在布局前采到的旧坐标不证明绘制了坏帧；zcode 同样用
   RO 绘制前吸底。规范见 [Resize Observer](https://drafts.csswg.org/resize-observer/#algorithms)。

最终采用单节点定位：短内容/reading 正常流；溢出 following 时原位置保留真实高度，
同一个工作行固定到 viewport.bottom 减尾距与行高，上滚同栈归流。微小浮点尾数跨过
绘制舍入边界也会换像素，top/left/width/height 在 1/64 CSS px 内沿用上一组几何。
`getBoundingClientRect()` 提供窗口坐标，fixed 的 top/left 却属于实际包含块。
聊天根的 `container-type:inline-size` 会令自身成为
fixed 包含块；直接写窗口坐标会重复叠加面板偏移，工作行节点存在却被滚动壳裁掉。
同级零尺寸 fixed 锚点给出该坐标系原点，目标 top/left 减去原点再写入，工作行仍只有
一份 DOM。回归必须让面板有顶部与侧栏偏移，并在实际 Electron 中检查视口边界与命中，
仅断言文案存在或在原点测试不足以发现这类问题。
RO 管尺寸，scrollTop 始终由 controller 管；没有 portal、副本或每帧追赶循环。

zcode 对照：`reference/zcode/packages/ui/src/v4/ConversationTimeline.tsx:1177-1189`
直接写 scrollTop 后回读；`:1327-1376` 的 live tail RO 在实际尺寸改变后同步贴底；
`:1231-1281` 历史列宽变化同步提交测高再贴底；`:2033-2045` 无 viewport containment，
`:2151-2180` 的 live tail 在普通流。测高缓存 Math.round 不代表活动 DOM 高度取整。
本次复读 `:2151-2180`，其普通流 live tail 没有窗口坐标到 fixed 包含块的换算；
Cogent 的零尺寸原点锚点是自身单节点固定定位所需，不能记作移植自该实现。
其默认正文为 14px×1.75=24.5px（`components/ai-elements/message.tsx:2003`、
`lib/uiFontSize.ts:3`），小数行高不是两产品观感差异的充分解释。

原最终隔离页使用真实组件、无实验 CSS 覆盖，在 DPI 1/1.25/1.5、多个视口起点/高度及
22.75/24.5px 行高下录制 12 条件、1132 张连续帧，逐条件的静态时钟图标裁片一致。
用户实际场景复验确认抖动消除；这不是完整主题/硬件矩阵验收，也不能外推到后来更换的
动画图标每帧不变，更不能声称定位了 Chromium 内部某个 bug。原始证据在忽略目录
`tmp/zcode-jitter-research/continuous-repaired-*-results.json`，换机不保证存在。

固定截图不够，代表场景须改变 DPI、视口起点、自然换行节奏并观察连续帧。
稳定 callback ref 发布真实节点，effect 按节点代次绑定与清理 observer/输入事件，
避免 StrictMode、父更新或 viewport 替换后继续读取旧 DOM。

## 7. 正文与输入框的水平基准

正文单侧 padding 可以避开索引，却会偏移正文中心。正文与输入卡应共享列宽，
索引只消费列外留白；滚动条占位也属于布局宽度，单侧稳定槽仍会把正文推偏。
双侧槽占用的空间同样不能当作正文留白：窄面板若只剩 16px 总边距，13px 槽之外
只余 3px；输入卡外扩后更只余 6px 外边距。仅验证中心线和宽度差会漏掉真实裁切。
布局回归必须挂真实消息视口、用户气泡与长正文，量可用视口并检查右缘完整可见。
Cogent 用共享 `.chat-column` 与双侧稳定槽维持同轴，输入卡在共享基准上对称增加宽度，
不另设一套居中算法。外扩和留白均随容器宽度连续变化；工具行的文本/图标切换
也由同一聊天容器裁决，不读窗口宽度，不因打开右侧分屏而沿用宽屏形态。
权限和模型只隐藏触发钮文字、保留原菜单入口，上下文用同一占比的圆环压缩呈现；长模型名省略与
极窄工具组换行分别处理单项过长和总宽不足。窗口级断点叠加自动收起约束，
手动布局仍归原控制器；缩窗引发的 RRP onResize 不能覆盖待恢复快照，否则放宽后
会把自动收起误认成用户有意关闭。布局折叠保留组件身份与输入草稿。
索引外壳宽度归零并裁切内部
固定宽刻度，避免内部 flex 在收拢时压缩刻度。容器查询使用聊天面板而非窗口宽度，
左右分栏改变时自然生效；尺寸与验收的权威描述分别在 UI布局和模块页。

## 8. Cogent 落点与未完成范围

`stream-reveal.ts` 管切分、块进度与排期；`markdown.tsx` 管 adapter、最终 parser 与
视觉资源回收；`globals.css` 管每帧 CSS；`stores/chat/delta-batcher.ts` 管入口合批；
`message-scroller.tsx` 管滚动控制与单节点定位。业务、视觉与滚动不互相代管。
自动回归集中在 `tests/renderer/`，真实像素按手测册复验。

完整 Electron 界面矩阵、真模型流式性能和后台动效仍有未完成项；预览中测得的屏外
动效成本不能扩称真机结果。证据与暂缓边界见
[动效与渲染性能收尾](../计划/动效与渲染性能收尾.md)，任务队列见
[全局架构](../计划/全局架构.md)。
