# 流式呈现动效（扫光 + 逐词淡入）

> 对话流的"活着"信号层：工作行标题扫光 + 流式正文逐词淡入。pi 是 CLI 引擎
> 无 HTML 渲染，本主题的对照对象是 zcode 桌面端（移植源）与 Streamdown 内置
> 动画（被否方案）。计划与决策表见 [计划/流式呈现动效.md](../计划/流式呈现动效.md)。

## 问题

流式输出期间要持续告诉用户"还在工作"：过程间隙（等首轮 delta / 工具执行 /
轮间往返）的工作行是唯一活动信号；正文输出时最新 delta 位置要有"正在长出来"
的观感。硬约束：**动效只能是可丢弃的视觉层** —— 不改正文数据、不碰布局高度、
不与虚拟滚动测高 / 底部跟随打架、reduced-motion 全退化为静态。

## 扫光（渐变文字淡带）

原理四件套（`globals.css` `.shimmer`）：

1. `background-clip: text` + `color: transparent`：文字成为渐变的裁剪蒙版；
2. 渐变嵌一条 22% 透明度的"淡带"（`color-mix(in srgb, 基色 22%, transparent)`），
   其余 stop 全为基色（muted-foreground）；
3. `background-size: 300%` 留平移空间；keyframes 只动 `background-position`
   `100%→0%`（扫 2s）再钉住（停 2s）—— **扫停呼吸**而非匀速循环：匀速观感是
   "进度条在跑"，扫停才是"活着"；停下时文字与静态行同色，淡带扫过变暗，
   语义是"正在工作"而非"高亮"；
4. `will-change` + `translateZ(0)` 提前升层：background-position 逐帧变更走
   主线程重绘，流式期主线程被 delta / 码表打满时动画掉帧、文字在实色与渐变间
   跳变，观感即"工作中行闪动"。

消费方：`TraceLine data-status=running` 的标题（工作中行 + 思考中标题）与工具行
类别词运行形（trace 家族一处定义全体生效）。`.shimmer-none` 是 reduced-motion
出口。

## 逐词淡入（stream-reveal 插件）

原理：rehype 插件把流式 block 的文本切成单元（中日文按字、拉丁文按词），每个
非空白单元包 `<span data-reveal="new" style="--reveal-delay:Xms">`，CSS 用
`transition: opacity 300ms ease-out var(--reveal-delay)` + `@starting-style
{ opacity: 0 }` 淡入 —— 尾部几个单元同时处于不同透明度即成渐隐尾巴。

四条铁律（每条都对应一次真实翻车，出处 zcode）：

1. **DOM 文本首帧即完整，只动 opacity**：zcode 三代前身都维护随时间变长的
   visibleText，高度逐帧增长持续触发 ResizeObserver，撞进虚拟滚动测高与底部
   跟随，全部撤回；
2. **transition + @starting-style，不用 keyframes**：单元下一帧就从 new 变
   settled，keyframes 选择器失配动画即被移除只播一帧；transition 只要属性链
   在就跑完，@starting-style 只作用于首次挂载不重播；
3. **settled 单元也包 span**：`hast-util-to-jsx-runtime` 按"标签 + 同级序号"
   生成 key，只包新单元时下一帧新词复用旧词的 DOM 节点、动画不播；
4. **淡入时长恒 300ms，速度只进排期延迟**：时长随吐字速度缩放会把每字压到
   2-3 帧渐变 = 肉眼无动画；"能不能看出淡入"只取决于单字有几帧处在渐变。

排期器（跨帧浮现时钟）：目标滞后 = `clamp(max(6×单元间隔, 1.5×批间隔), 80,
250ms)` —— 渲染故意落后 token 流约 6 个单元，缓冲把突发铺平；批内间隔
`min(40ms, 可用时间/数量)`，积压时至少铺开 15ms 逐步回落；速度/间隔按 EWMA
自适应（停顿 >300ms 不更新速度，防停顿后突发被按慢节奏排满）。

## 对比

- **zcode 桌面端**（移植源）：扫光 `packages/ui/src/styles.css:957-1004`
  （.animated-gradient-text，4s 扫停，主题变量 strong/soft 四套 + 高速紫变体）；
  逐词 `packages/ui/src/components/ai-elements/message.tsx:845-1345` + 设计文档
  `docs/streaming-markdown-reveal.md`（含三代撤回史与全部 bugfix 教训）。
  另有 motion/react 版 Shimmer（shimmer.tsx，vercel/ai-elements 出身）基本未消费；
- **Streamdown 内置 animated**：会生成 `<span data-sd-animate>` 但动画规则在
  包的 styles.css 里（不引入即无效果）；stagger 40ms **无封顶**（1000 词末尾
  40 秒后才可见）且不能自适应调速 —— zcode 明确否掉，Cogent 同；
- **Cogent 原有 .shimmer**（本次被替换）：muted 底 + foreground 高光带匀速
  2.2s（ChatGPT 思考标题式高光扫）—— 与 zcode"实色 + 淡带扫停"的差别在节奏
  语义，见上。

## 取舍与 Cogent 适配

- **扫光**：换 zcode 形态（保留原合成层提示，两边同款）；色标不接聊天正文
  主题（工作行在 chrome 区不在 md-body 容器内）。
- **逐词**：整体平移，三处适配 —— ① chat store 无 30ms 合帧（每 delta 直接
  setState）→ **markdown.tsx 渲染层补 30ms 固定节拍合帧**（EWMA 只自适应
  呈现节奏、救不了呈现上限：每批至少铺开 15ms → 无合帧时上限 ≈66 字/s，
  快模型恒积压成"散架"，见「落地实测教训」②）；② streamdown 2.7.1 的 block
  解析在 render 期 useMemo 同步完成（2.5 走 effect + startTransition），commit
  放本帧渲染后的 effect 即可，无需像 zcode 落后一帧；③ 2.7 的 `rehypePlugins`
  是**覆盖语义**（默认管线 = raw/sanitize/harden），必须
  `[...Object.values(defaultRehypePlugins), 插件]` 拼接，直接传会丢 sanitize。
- 保留的 zcode 坑位对策：插件函数名递增序号（processor 缓存按函数名拼 key，
  同名实例被共用会读到第一条消息的已终结 state）；进度按 block 记（streaming
  模式每 block 独立跑 rehype，插件只见一个 block，整条消息一个长度会坐标系
  错位）；pre/svg 跳过（代码块高亮异步，逐字与高亮打架）；行内 code 整体一个
  单元；li::marker 过渡 color（::marker 不支持 opacity）。
- 已知代价：收尾切 static 时滞后尾巴（≤250ms）直接出现（消除它需要 UI 等动画
  播完再切换 = 时间同步状态，不采用）；块级装饰（引用边框 / 表格边框 / 复选框）
  随挂载直出不排期。

## Cogent 落地实测的三个追加教训（真机 CDP 采样定案）

1. **扫光 `.shimmer` 必须 `@utility` 注册**：trace 组件用 Tailwind 变体引用它
   （`data-[status=running]:*:data-[slot=trace-title]:shimmer`），v4 只为认识的
   utility 生成变体规则 —— 普通类名作变体目标**零输出**，首版即栽在这
   （.shimmer 定义完好但从未挂上，运行中 title 的 animationName 恒 none）。
   色标基色用 foreground 而非 muted-foreground（后者再 22% 透明化几乎融进
   背景，扫不动）。
2. **必须补 30ms 合帧（markdown.tsx，固定节拍非 debounce）**：chat store 每
   delta 直接 setState（1~2 字/次），排期器每批至少铺开 15ms → 呈现上限
   ≈66 字/s，快模型（100~300 字/s）恒积压 —— delay 中的字 opacity:0 占位
   不显示，夹在已淡入字之间即「散架」观感。zcode 排期参数全部以 30ms 合帧
   为前提。cleanup 清 timer 必须连同置 null：**StrictMode 挂载期跑「挂载→
   cleanup→再挂载」，只 clear 不置 null 的话 ref 挂着死 timer id，再挂载时
   合帧 effect 误判「timer 已在」永不再起 —— displayContent 恒停初值，收尾
   streaming=false 直通全部内容即「不流式、一股脑」（真机 fiber 采样实锤：
   contentLen 持续涨、displayLen 恒 0；回归钉在 stream-reveal.render.test）。
3. **相关：工作中行抖动与逐词无关但同期暴露**（吸底双跟随器打架，见
   模块/消息呈现.md 决定 20）。

测试：`stream-reveal.test.ts`（20 用例，切分 / 进度 / 排期 / 提交）+
`stream-reveal.render.test.tsx`（6 用例，真 Streamdown 管线钉挂载语义、
processor 缓存坑、StrictMode 合帧回归）。
