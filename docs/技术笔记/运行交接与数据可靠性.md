[存储](../模块/工作区与项目.md)、[会话](../模块/会话与对话.md)、[业务配置](../模块/业务配置.md)与[启动](../模块/应用启动.md)。

## 为什么需要不同的身份

窗口仍存在不代表当前页面可信，同 URL 重载也会产生新文档。统一 IPC 包装检查角色、精确文档、
顶层 frame 与导航代次；异步写前和回包前再确认。文件 URL 按真实路径比较，不能用 basename 判断 demo。
控制台能观测不意味着可以读取 key 或修改聊天。sandbox 提供额外隔离，不能替代 sender 校验。

sessionId 标识聊天，turnId 标识用户输入，runId 标识一次执行；续写保留 turnId 但更换 runId。
MCP 先订阅仍可能收到旧运行终态，必须等受理回包后按 runId 认领。
历史加载把“桶已存在”与“已加载”分开：Host 快照含水位和运行态，客户端只补水位之后的事件，
否则旧快照会吞实时工具、重复正文或让运行态回退。断线后重新读快照，不声称提供事件重放服务。

## 保存完整、单写者和迁移是三件事

原子替换只能防半文件，不能防两个进程各拿旧快照互相覆盖。Cogent 没有同根多写需求，
因而按真实根与 owner 取得 OS 管理端点；崩溃由 OS 释放，无心跳抢锁和 PID 重用猜测。
Windows 用命名管道，Linux 用抽象 Unix socket，避免增加原生文件锁分发依赖；Linux 产品准入仍须实机验收。

显式编辑构造新值，写盘成功后发布。凭据加密也在缓存提交之前；配置成功保存而运行时应用失败时，
明确区分两种结果。删除先写标记，文件清理失败保留重试入口。
旧转录迁移把完整内容构造到临时 JSONL 后发布；历史、搜索和迁移共用完整前缀/分叉判定，
不能把“文件已经存在”当作“所有消息已迁完”。分叉留原件并报告，不自动拼接。

## 退出须等待真正的完成点

pi dispose 是同步释放，abort 是等待 idle；退出扩展还须显式发送 session_shutdown。
Host 先拒新工作、取消与解决挂起交互，再等运行和文件提交，最后释放网络/worker。
每段有期限，main 等确认后才结束子进程。强杀无法承诺任意扩展、工具进程全部收尾；测试和手测范围必须分开报告。
配置由 Host 启动装配，凭据由 main 现读快照并串行交接，不能把页面打开当作引擎配置就绪条件。

## 项目工作目录不能等同于转录物理位置

旧实现把 piCwd 同时用于打开 JSONL 和装配工具，项目从 A 换 B 后依然在 A 上创建工具，
指令又被缓存，而新消息 roots 实时读 B，形成混用。本轮把 JSONL 锚点保留在 A，
显式传 cwd=B 给 SDK；user entry 的来源记录消费本轮 cwd/roots，不能读取 sessionManager 的旧 header cwd。
空闲时完整退出旧实例，再装配 B 的 SettingsManager、ResourceLoader、MCP、技能和工具。
准备/运行/压缩与交接预约覆盖整个 await；失败保留旧项目，下轮重新装配旧根。
旧回合已保存不同来源时要求新消息开启回合，避免在同一 turnId 下静默改写文件来源。
文件树按根内容换代，前后台 owner 全部收尾；关闭导航上下文仍允许已打开文件保留独立 lease。

本轮补充实读，版本同上：pi `packages/coding-agent/src/core/sdk.ts:192–200` 显式 cwd 与
sessionManager 可独立传入；`agent-session.ts:518–525、1806` 把 cwd 绑定到实例/扩展上下文，
`session-manager.ts:1148–1150` 的 getCwd 是转录原 cwd，不能拿它标记新工作区的消息。
zcode `packages/services/src/bots/workspaceHelpers.ts:3–21` 把工作区身份与标签分开；
deepseek-harness `packages/session/session-persistence-jsonl/src/generation.ts:70–86` 区分物理来源与发布身份。
这支持分开管理，但不表示三仓均有 Cogent 同样的项目换根 API；不照搬会复制历史的迁移流程。
