# 上下文压缩（context compaction）

> 压缩内核自阶段 1.2a 起整体由 pi AgentSession 接管（全局架构 D6：手搓压缩与
> pi 会话树不兼容 —— 树靠事件追加，原位改写必分叉）。本文写现行事实；
> 手搓时代的实现与决策过程见 [计划/归档/](../计划/归档/)（上下文压缩完备化）
> 与 git 历史；内核替换的手术细节见 [pi内核替换.md](pi内核替换.md)。
> 代码残留面：`host/runtime/compaction.ts`（阈值公式 + 转录整形）；
> 事件面：`compaction.started/completed`（protocol）；UI：`CompactionBar.tsx`。

## 1. 问题

长会话的转录只增不减，三笔账迟早爆：

1. **窗口**：每轮全量重发上下文，转录长过模型 contextWindow 后请求直接被端点
   拒绝（context overflow）；
2. **成本**：input 随轮次线性涨，第 50 轮为一个错别字重发 49 轮的历史；
3. **注意力**：远期的工具输出噪音稀释近期任务焦点（lost in the middle）。

朴素的头部截断不行：模型会忘记自己做过什么、用户要什么。压缩的本质是
**用一次便宜的 LLM 调用把旧历史蒸馏成结构化检查点（checkpoint）**——旧区换
摘要、近期对话原样保留，续聊时模型拿着"摘要 + 近期原文"继续工作。

## 2. pi 的做法（1.5.2，内核现行实现）

- **存储表示**：压缩是会话树上的 `CompactionEntry`（summary + firstKeptEntryId
  + tokensBefore），**不是转录消息**。投影时（session-manager
  `buildContextEntries`）最新压缩条排最前、保留区从 firstKeptEntryId 起、
  被摘要条目隐去；压缩条投成 `compactionSummary` 消息（pi coding-agent 的
  CustomAgentMessages 声明合并），`convertToLlm` 转成 user 摘要消息 ——
  对模型是上下文，对 UI 是标记行；
- **触发三路**（agent-session）：`session.compact` 手动（Cogent 协议直通）；
  threshold（run 后 `_checkCompaction` + 下一响应前双检查点）；overflow
  （删失败轮 → 压缩 → continue 重试一次，`_overflowRecoveryAttempted` 单次闸）；
- **判定**：`tokens > contextWindow − reserveTokens`（缺省 16384 固定绝对值）；
  估算 = 末条有效 usage + 其后消息 chars/4 粗估；
- **切点**：`findProjectedCutPoint` 从尾累计（`estimateTokens` = chars/4，与
  usage 锚定的上下文估算不同源）至 keepRecentTokens（固定 20000）；
  user/assistant 都是切点、user 是 turn start —— 切点落回合中段时走
  split-turn（turn-prefix 二次摘要）。**已知陷阱**：树里的空消息条目
  （model_change / thinking_level_change）会被"空条目回退"把切点挪离 user
  边界 → 误判 split-turn —— Cogent 的 setModel/setThinkingLevel 判等再调
  正是防它（session.ts driveRun）；
- **摘要请求**：被摘要消息**文本化序列化**进 `<conversation>` 标签（防续写）
  + 结构化模板（Goal / Progress / Key Decisions / Next Steps / Critical
  Context）；迭代更新换 UPDATE 提示词 + `<previous-summary>`；文件操作表
  XML 尾缀；半截摘要拒收；整包走重试策略；
- **keep 固定 20000 的行为差异**：小窗（ctx ≤ keep）的常规料区间为空 ——
  触发线早早响、压缩以「无可压缩」收场，直到转录超 keep。手搓版
  `keep=min(20K, ctx/2)` 的小窗自适应是被否的旧案，1.4 经 CompactionSettings
  按模型覆盖对账。

## 3. 对比

| | 触发 | 判定口径 | 摘要形态 | 特殊能力 |

| **pi（现行内核）** | 手动 / 阈值（reserve 16384）/ 溢出恢复 | usage 锚定 + chars/4 粗估 | 结构化 checkpoint + 迭代更新 + 文件表 XML + `<conversation>` 序列化 | 会话树 + split-turn + branch-summarization |

| **DeepAgent** | 中间件 opt-in | 步数/触发器可配 | 摘要替换旧消息 | 压缩即图状态，天然可持久化 |
| **Cogent 承接面** | 手动直通 + 自动（pi 内聚） | pi 真值；UI 预警线用自有 dsh 同构公式（见 §4） | pi 原生 | AUTO_CONTINUE 续写（Cogent 保留件，见 §4） |

## 4. Cogent 的承接面（session.ts / compaction.ts 残留两面）

- **事件转译**：pi `compaction_start/end` → 协议 `compaction.started/completed`
  （reason 增补 overflow 场景）；summarizedUntil = 保留区首条时间戳（经
  firstKeptEntryId 反查 pi 树）；摘要调用自身的账（summaryUsage）取
  compaction result 的 usage；
- **手动 compact**：`pi.compact()` 直通，"Already compacted / Nothing to
  compact" 映射协议错误（映射前原文留 stderr 诊断）；压缩中窗口以
  `compacting` 集同步拒绝 submit/continue；
- **UI 预警线**：`compactionThreshold(contextWindow, override)` —— dsh 同构
  公式 `max(ctx×50%, min(ctx×90%, ctx−8192))` + ModelDef 按模型覆盖，随
  models.list 下发（指示器画线用；pi 引擎真值是 reserve 制，两线的差属
  1.4 对账）；
- **AUTO_CONTINUE（Cogent 保留件）**：纯文本 length 截断（pi 的
  recoverableLength 不接管时 —— 真端点输出贴上限的形态）注入
  `[cogent:continue]` 显式指令续写（≤3 次），事件/历史双投影段合并；
- **转录整形**：`convertToLlmMessages`（compaction.ts）只服务上下文明细
  估算（estimateContext 的输入源）—— 引擎真实请求组装走 pi 自己的投影；
- **呈现口径**：历史回查走 pi JSONL 全量（readPiTranscript，保留式：影子区
  /多代压缩条全在），与上下文口径（影子区不进请求）分离 —— 见
  [pi内核替换.md](pi内核替换.md) §3.2。

## 5. 1.4 对账债

- keep 固定 20000 vs 小窗自适应（CompactionSettings 按模型覆盖）；
- 历史回查折叠条的 tokensAfter / summaryUsage 缺省（pi 树只存 tokensBefore，
  事件侧账完整 —— 投影缺，details 通道是补齐位）；
- L1 工具结果裁剪（prune）与手搓指令内联（真前缀缓存复用）随内核替换退役；
  pi 的等价能力 = 压缩时全量进摘要 —— 若实测成本/缓存劣化明显，经
  session_before_compact 扩展点接回。
