# 上下文压缩（context compaction）

> 对应 [计划/pi借鉴.md](../计划/pi借鉴.md) 批次 4（D7 定稿：自动阈值 90% + 手动
> 双路）。代码：`agent-service/runtime/compaction.ts`（纯函数）+
> `runtime/session.ts`（接线）+ `features/home/CompactionBar.tsx`（折叠条）。
> 上游对照：`reference/pi/packages/coding-agent/src/core/compaction/`。

## 1. 问题

长会话的转录只增不减，三笔账迟早爆：

1. **窗口**：pi 每轮全量重发上下文，转录长过模型 contextWindow 后请求直接
   被端点拒绝（context overflow）；
2. **成本**：input 随轮次线性涨，第 50 轮为一个错别字重发 49 轮的历史；
3. **注意力**：远期的工具输出噪音稀释近期任务焦点（lost in the middle）。

朴素的头部截断不行：模型会忘记自己做过什么、用户要什么。压缩的本质是
**用一次便宜的 LLM 调用把旧历史蒸馏成结构化检查点（checkpoint）**——目标、
约束、进度、关键决策、下一步——旧区换摘要、近期对话原样保留，续聊时模型
拿着"摘要 + 近期原文"继续工作。

## 2. pi 的做法（源码，coding-agent compaction/）

- **存储表示**：压缩是会话树上的 `CompactionEntry`（summary + firstKeptEntryId
  + tokensBefore + details），**不是转录消息**。投影时（session-manager.ts
  `buildContextEntries`）最新的压缩条排最前、保留区从 firstKeptEntryId 起、
  被摘要条目全部隐去；压缩条投成 `compactionSummary` 自定义 AgentMessage
  （messages.ts 声明合并 `CustomAgentMessages`），`convertToLlm` 把它转成
  user 消息（"The conversation history before this point was compacted into
  the following summary: <summary>…"）——**对模型是上下文，对 UI 是标记行**，
  一个角色两种投影；
- **触发三路**（agent-session.ts）：`/compact` 手动；threshold（agent_end 后
  `_checkCompaction` + 下一响应前 `_compactBeforeNextAssistantResponse`
  双检查点）；overflow（provider 报上下文溢出 → 删失败轮 → 压缩 → 重试一次，
  `_omitRecoveryAttempt` + `_overflowRecoveryAttempted` 单次闸）；
- **判定**：`shouldCompact = tokens > contextWindow - reserveTokens`（缺省
  16384 **固定绝对值**）；估算 = 末条有效 usage + 其后消息 chars/4 粗估
  （`estimateContextTokens`），且带**时效守卫**——压缩摘要等前缀消息插入后，
  早于它的 usage 不能再描述当前前缀（pi-ai estimate.ts L80 注释点名该场景）；
- **切点**：`findCutPoint` 从尾往回累计 token 至 keepRecentTokens（缺省 20000），
  合法切点 = user/assistant 消息（**永不切 toolResult**——它必须跟着自己的
  toolCall）；允许切在 assistant 上（回合被劈开），代价是 turn-prefix 二次
  摘要把劈开的前半段单独总结，两段摘要拼接；
- **摘要请求**：`completeSimple` 独立小请求（系统提示词 "Do NOT continue the
  conversation. ONLY output the structured summary"）；主提示词 = `<conversation>`
  标签包序列化文本（防模型当对话续写）+ 结构化模板（Goal / Constraints &
  Preferences / Progress(Done/In Progress/Blocked) / Key Decisions / Next
  Steps / Critical Context）；**迭代更新**：已有旧摘要时换 UPDATE 提示词 +
  `<previous-summary>` 标签（PRESERVE all existing information）；toolResult
  截 2000 字符、thinking 不序列化；文件操作表（read/write/edit 的 path）以
  `<read-files>`/`<modified-files>` XML 尾缀进摘要，details 里另存结构化一份；
  error/length 停因的半截摘要拒收（`getSummarizationFailure`）；整包套
  `retryAssistantCall` 走重试策略；
- **事件**：`compaction_start` / `compaction_end`（reason = manual/threshold/
  overflow，失败带 errorMessage）；压缩后**会话重载**（投影重建，树存储的
  天然动作）。

## 3. 对比

| | 触发 | 判定口径 | 摘要形态 | 摘要请求 | 特殊能力 |
| --- | --- | --- | --- | --- | --- |
| **pi** | 手动 / 阈值（固定 reserve 16384）/ 溢出恢复 | 末轮 usage + trailing 粗估（带时效守卫） | 结构化 checkpoint（6 节）+ 迭代更新 + 文件表 XML | 同会话模型 completeSimple（可带思考档、走重试策略） | 会话树 + 分支摘要（branch-summarization） |
| **Claude Code** | 手动 `/compact`（可带聚焦指示）+ auto-compact（默认开，接近上限触发，公开提示词工程同源） | 官方未公开精确阈值；上下文百分比档 | 8 段结构化摘要（Primary Request / Key Technical Concepts / Files and Code Sections / Errors and fixes / …/ Current Work，提示词随版本泄露广为流传） | 主对话模型 | **microcompact**（0.2.x）：空间紧张时只压缩旧工具结果，不整段摘要 —— 分层压缩思路 |
| **OpenAI Codex CLI** | 自动（接近上限时后台压缩历史） | rust 侧 token 计数 | 历史要点摘要 | 独立请求 | 压缩后继续同一会话，无手动命令（公开资料层面） |
| **DeepAgent**（LangChain deepagents） | 中间件 opt-in（`summarization`） | 步数/触发器可配 | 摘要替换旧消息（prompt 定制） | 图内 summarize 节点 | 挂在图编排层：压缩即图状态，天然可持久化/恢复 |
| **Cogent** | 手动 `session.compact` / submit 前阈值（**90% 百分比**，D7） | pi-ai `estimateContextTokens` 同源（预算同口径 + 时效守卫白捡） | pi 同款 6 节 checkpoint + 迭代更新 + 文件表 XML（照搬） | 会话当前模型 `completeSimple`（带思考档；重试不接，批次 8.4 挂账） | 转录内 `compactionSummary` 消息角色（线性存储，无投影层） |

关键分歧：**压缩记录存在哪**——pi 存会话树的 entry（投影时才变成消息），
Claude Code/Codex 在各自的会话状态里，Cogent **直接作为转录消息存盘**（线性
JSON 转录，无投影层可依赖，消息即真源）；**溢出恢复**——pi 有 compact-and-
retry，Cogent D7 明确不做（provider 溢出走 run.failed 显式暴露，用户手动
压缩或换大窗模型）；**阈值口径**——pi 固定 16384（对 8K 模型=79% 触发、对
200K 模型=92%，小窗反而更早触发），Cogent 百分比对各窗口语义一致。

## 4. 取舍记录（Cogent 线性转录的改造，偷法第 1 则）

- **转录表示 = 自定义消息角色 + convertToLlm 选项**：`declare module
  '@earendil-works/pi-agent-core'` 声明合并加 `compactionSummary` 角色（pi
  官方扩展通道），Agent 构造给 `convertToLlm` 把它转 user 消息——请求组装、
  落盘、历史回查零特殊分支（除投影处一处 role 分支）。**必须给**：缺省的
  convertToLlm 是恒等直通，未知 role 透给 provider 会被拒收；
- **system 消息全保留前置**（vs 上游保留段滤掉、压缩条带一条 systemMessage）：
  我们的 systemPrompt 是转录全部 system 消息的重放拼接（权限通告
  `[cogent:permission]` 在转录里），随摘要丢弃 = 静默丢失权限语义；领头
  system（工作区+工具声明）还是 ensureAgent "已在首位不再补插"的判据；
- **切点只取 user 边界**（vs 上游 user/assistant + split-turn 二次摘要）：
  线性转录里整回合摘要/保留语义更清晰，砍掉 turn-prefix 摘要的复杂度；
  已知边界：单回合超窗口 → 不压缩、provider 显式报错（比静默劈开回合诚实）；
- **文件表靠文本载体**（vs 上游 details 结构化转发）：旧摘要的 XML 尾缀在
  摘要文本里，UPDATE 提示词的 "PRESERVE exact file paths" 规则让文本自身
  完成跨代合并，无需结构化字段；
- **触发单点 = submit 前**（vs 上游 agent_end + pre-prompt 双检查点）：
  正确性等价（下一请求前压缩即正确时机），指示器回落由 completed 事件直接
  驱动，不依赖提前一拍的检查；
- **重建 = `agent.state.messages` 换引用**（vs 上游会话 reload）：pi 的
  setter 自带拷贝，与 applyPermissionNotice 同一手法，无投影层就无需重载；
- **并发护栏 `compacting` 集合**：摘要发生在 prompt 之前——pi 尚未置
  isStreaming，submit 的忙碌检查在这个秒级窗口裸奔，第二个 submit 会双压缩
  +双 prompt；入口先查集（自动/手动/submit 三处），runCompaction 的
  finally 出集；
- **压缩条 timestamp = now 的妙处**：pi-ai 估算的时效守卫按"前缀里晚于
  usage 的消息"判 usage 作废——压缩后保留区的旧 usage 自动失效、估算退回
  纯字符口径，**不需要自己记账**；
- **自动失败不拦提交**（尽力语义）：摘要服务抖一下不该吞掉用户消息；真
  溢出由 provider 报错走 run.failed 显式暴露。手动路相反：无可压缩/失败都
  以协议错误显式反馈（手动动作要明确结果）；
- **不搬清单（批次 4 当时）**：overflow compact-and-retry（D7）、
  retryAssistantCall 包装（批次 8.4 provider 网络层对照后统一）、
  branch-summarization（会话树在远期池）。
  —— 完备化（2026-11-12）**修正其中 overflow 一条**：死锁复盘证明"显式
  暴露"之后应有自动出路，S5 按 pi 同款补齐（见 §4.1）。

## 4.1 完备化增补（2026-11-12，S1–S8 十维路线全落，详录见 计划/上下文压缩完备化.md）

- **触发公式（R1）**：90% 单线 → `max(ctx×50%, min(ctx×0.9, ctx−8192))`
  （dsh 同构：thresholdRatio×headroom 双参数合成 + 特小窗**阈值**兜底——评审
  修正：兜底对象是阈值而非余量，后者按字面 max 在 8K 窗是 no-op；绑定边界
  ctx < 2×8192 = 16K）。参数按模型覆盖：`ModelDef.compaction` → 声明合并挂
  pi `Model` 接口（官方扩展通道，compactionSummary 同款）→ 引擎真值随
  `ModelSummary.compactionThresholdRatio` 下发，指示器预警线跟随（0.9 双处
  镜像废除）。**对比 DeepAgent/Claude Code**：只看占比，无 room 感知；pi 用
  固定绝对值 reserve（小窗失控）——本公式是五家中唯一"占比+绝对余量取先到+
  兜底"的合成式；
- **检查点双点（R2）**：submit 前单点 → + `prepareNextTurnWithContext`
  （pi 1.5.0 原生钩子，`_installAgentNextTurnRefresh` 同款）。关键工程点有
  **两层**（2026-11-12 用户验收实测抓到，回归用例 S14 固化）：① loop 的
  currentContext 是 prompt 起点的**独立数组**（浅拷贝），压缩写回必须
  **原位 splice**（applyCompactionInPlace）而非换引用 —— 换引用后 loop 旧
  引用与 agent.state 各写各的，当轮收尾消息双份落转录；② 钩子返回的
  context.messages 必须是 agent.state.messages 的**浅拷贝**—— 返回同引用
  时，后续轮流式 partial 经 loop 线与 processEvents 状态线对同一数组双
  push。一句话：**原位写回 + 拷贝出请求线**，两条引用线所有权显式分工
  （pi 上游无此问题：它的状态真相在 session 树投影，钩子返回投影数组天然
  分离）；
- **L1 prune（R3）**：dsh tool-result-pruner 数值与算法同款（8192 code
  point 线 / 保头 4096 / 保尾 1024 / 单 marker，头尾按**全局位置**跨块连续
  计量）+ **原位改写**（vs dsh shadow 追加式：那套要"只追加+位置语义"的
  存储架构，是会话层重构而非压缩功能，Cogent 单写者线性转录等价于直接换
  内容）。范围 = **全转录含保留区**（dsh pruneSession 同款；只裁被摘要区的
  话小窗场景 L1 几乎必然不够）。检查点内 **L1 → 重计量 → 仍超线才 L2**，
  L1 单独够时零摘要请求（microcompact/dsh prune 双重验证）；
- **摘要指令内联（R4）**：独立 summarizer system prompt → 会话 system 原对象
  + 被摘要区原消息直传 + 指令作末条 user（dsh 源码注释实证：辅助调用成为
  上一次主请求的**真前缀，provider KV cache 复用而非失效**）。`<conversation>`
  文本化撤下（防续写意图由指令护栏段承担）；投影前导语换 dsh
  CHECKPOINT_PREAMBLE 措辞（"既定背景，直接续"）。**对比 pi**：独立提示词，
  压缩点后缓存全断——这是缓存钱的最大单项改善。**预算守卫（验收修复
  2026-11-12）**：真前缀的代价在 20K 级小窗深占用时暴露 —— 整转录重放把
  pi clampMaxTokensToContext 的输出预算夹到 ≈0,摘要自身必然 length
  （「要压缩先得有空间压缩」的死结）；守卫 = 重放后 available < 2048 即
  降级被摘要区直传（放弃缓存换可生成,退化为无损失）。小窗场景缓存收益本就
  趋零,守卫只在大窗保留;
- **溢出恢复（R5，修正 D7）**：isContextOverflow（pi-ai 模式聚合 30+ 家
  报文）→ 删失败轮 → L1/L2 → `agent.continue()` 重试一次（单次闸）。**单
  run 语义**：可恢复失败在 agent_end 抑制 run.failed、streaming 保活，重试
  的流式增量沿同一对象飞——UI 全程只见一个 run（pi 上游是 run 间隙静默压缩，
  宿主感知不同）；
- **auto-continue（R6③，唯一无源码参照件）**：纯文本 length 截断 → 注入
  `[cogent:continue]` 显式 user 指令续写（≤3 次）→ **段合并双投影**（事件
  路径相邻纯文本段并一 + 历史路径指令泡跳过/无工具 assistant 并回，门 =
  双方无工具卡）。带 toolCall 的 length 走 pi 原生 failToolCallsFromTruncated
  （核实：门控只看 stopReason，参数完整也 fail——冒烟固化）。**对比五家**：
  Claude Code 的 append 式续写独有；pi/dsh 无（放 Cogent run 编排层 =
  settleRun 循环：溢出恢复与续写同环消化）；
- **思考预算通道（R7）**：`ProviderCompatDef.compat` + `ModelDef
  .thinkingBudgets` → buildModel 挂 Model（**评审修正：compat 是 Model 字段
  非 createProvider 参数**，pi 上游 provider-composer 即 merge 到 Model）→
  Agent.thinkingBudgets（构造 + 切模型两处同步）→ pi 方言
  `compat.thinkingTokenBudgetField × thinkingBudgetForLevel` 落请求体（冒烟
  ⑱ 全链实证）。**对比 pi coding-agent**：models.json 胶水；Cogent 设置 UI
  两处「高级」折叠（provider 级字段名 chip + 模型级四档预算）；
- **UI 四件（D8）**：压缩中状态条（started→completed 窗口，Codex 前态）/
  指示器手动压缩入口 / prune 副行（PrunedBar 字符量对账）/ 截断动作条
  （继续生成=预算重满的 session.continue / 立即压缩）。R10 图片卸载：无输入
  路径，协议注释声明 `compaction.offloaded` 形状预留。

## 4.2 保留式呈现（2026-11-12 GUI 验收修正，决策 D9）

S1–S8 完结当天 GUI 手测翻车：压缩后折叠条顶置、被摘要区历史消失 —— 对照
Codex 截图（旧消息全部保留可滚、`Context automatically compacted` 标记行
**原位**嵌在消息中间），销毁式呈现不可接受。**保留式**三件套：

- **转录保留 + 原位插入（引擎）**：`insertCompactionMarker` 在切点 splice
  插入压缩条（替代 rebuildTranscript 物理删除；S2 的原位纪律不变 —— loop
  仍持同一数组引用）；转录形态 = `[system, 影子区…, bar, 活区…]`，多次
  压缩多条 bar 累积、各有其位；
- **投影裁剪（convertToLlmMessages 重写）**：请求 = `[全转录 system 原序]
  + [末条 bar → 摘要 user] + [活区非 system]`。**历史保留 ≠ 上下文保留**
  —— 影子区不进请求，语义已被末条摘要吸收（更早的 bar 连同其影子区一并
  丢弃，previousSummary 在压缩时已合并）。全部 6 处 token 估算调用点都经
  此单点，投影一改、触发判定/溢出恢复/轮间钩子/tokensAfter 自动一致；
  system 全局收集接管了原 rebuild 前置 system 的权限通告语义。**对比**：
  Codex/Claude Code 同为「存储保留、上下文投影」（Claude Code 会话文件
  只追加、投影时换摘要；Codex rollout 全量落盘）；dsh 走 surfaceOp 位置
  跨度 + shadowedSeqs 记账（多消费者架构的完整形态）—— Cogent 单写者
  线性转录用「保留 + 单点投影」拿到同一产品收益，没有记账面；
- **配套守卫**：①「刚压完」判定换**时间戳**（压缩条不在末尾，旧
  `at(-1)` 快速路径失效；bar.timestamp = 压缩时刻，保留区消息恒早于它、
  新回合恒晚于它 —— 不换守卫则手动连点会把保留区反复重摘要）；② L1
  prune 限活区（影子区不进请求，裁它浪费且毁历史原文）；③ 渲染 completed
  手术改插入（不再删除旧消息）、bar 唯一 id、pruned 独立呈现补齐（pruned
  事件即追加副行，completed 到达时按 entries 深比较撤同检查点独立行、随
  bar 配对重插）、groupTurns 压缩条自起无头组（中插 bar 落进「已工作」
  折叠体等于看不见）。
- **呈现位 = 时间序，非切点（第二轮验收修正）**：首版保留式把 bar 插在
  转录切点（影子区/活区语义边界，保留区 20K 之前）—— UI 上标记行跑到
  旧消息堆里，与「正在压缩上下文…」状态条的位置脱节（用户验收：留痕应
  落在状态条消失的地方，Codex 同形态）。修 = **转录切点（语义）与 UI
  呈现位（时间序）解耦**：渲染 completed 手术按时间序定位（末条
  timestamp ≤ bar 时刻的内容之后）；引擎 toChatMessages 历史投影同步
  （压缩条暂存，遇到更晚 timestamp 的消息前归位 —— 转录其余部分本就
  时间序追加）；run.completed 终态替换**保留**压缩条/副行并按时间序并回
  （否则 submit 前压缩的 bar 与 L1 副行落在"最后一条用户消息之后"的替换
  区里、被终态整段替换吞掉 —— 第二轮验收实测「已裁剪」行不显示的根因）。
  分组配套（第三轮验收修正）：groupTurns 里压缩条自成一组并**截断当前组**
  （其后内容自起无头续组）—— 只成组不截断的话，bar 插在触发消息与回复
  之间时，其后落进 bar 组的流式占位/终态回复全被 bar 组渲染分支映射成
  null ＝「压缩后无回复」（引擎正常，纯渲染层吞内容）。

边界：转录磁盘增长不设上限（远期关注）；不做影子区视觉弱化（Codex 旧消息
正常呈现，跟随）。完整 surfaceOp 追加协议仍否决（无多消费者记账需求）。

**摘要成本显式记账（验收后增补）**：摘要是一次独立 LLM 调用，token/成本
不进 run 分段账 —— 回合统计看不见这一笔。落法 = runCompaction 捕获摘要
响应 usage（pi 对未报 usage 端点补零，按 totalTokens>0 判真报）三路下发：
completed 事件 `summaryUsage` + 压缩条消息 `summaryUsage`（随转录持久，
重启后折叠条仍可见）+ 历史投影；折叠条小字「· 摘要 ≈$x」（formatCost
复用，cost>0 才显，目录估价带 ≈）。**对比五家**：均未把摘要成本单独
呈现（Codex 折叠条只有标记文案）—— 成本透明度的超集。
