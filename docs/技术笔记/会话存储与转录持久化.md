# 会话存储与转录持久化

> 学习主题：原始转录、摘要与显示投影的所有权，及恢复时机。
> 当前机制见 [会话与对话](../模块/会话与对话.md)，托管原理见
> [pi接入与会话托管](pi接入与会话托管.md)。

## 1. 两种写频率，对应两种文件

```text
~/.cogent/sessions/<id>.json                          Cogent 会话域摘要
~/.cogent/pi/sessions/--<cwd编码>--/<时间戳>_<id>.jsonl  pi 原始会话树
```

pi 管消息、usage、思考签名、工具配对和压缩树，Cogent 管项目绑定、置顶、归档与权限等
宿主域。显示消息是读时投影，可能丢块边界和内核元信息，不能反过来当转录真源。
使用转录而非显示数组持久化，也让新增显示字段时能从旧数据重新投影，减少数据迁移。

摘要采用 StorageDriver 的文档集合 CRUD，一文档一文件。字段变更时只重写本会话，
不会为一个置顶动作改写全库；文件可单独备份和检查。当前访问模式是整文档读取，
未为用不到的关联查询引入数据库。pi 转录按消息逐条追加，避免长历史整写的写放大。
这是降低故障面，不应夸称进程或机器在任意时刻断电都只会丢最后一行。

手动重命名也是宿主摘要操作，无需装配内核。它先写候选文档，再替换内存摘要并
广播：显式“保存”失败应回到表单重试，不能沿用回合内 persist 的尽力语义来假报
成功。标题与 `titleManual` 一起保存，防止“新会话”这个合法手动名称被自动摘要
覆盖；updatedAt 留作对话活动时间，改名不让列表跳位。

## 自动标题为什么是独立任务

临时标题只需截取首条输入，模型概括则是另一笔 API 消费。把它塞进主 Agent 提示词会
污染回复与上下文，也会让首回复等待辅助任务。Cogent 让 Host 管一次性资格、取消和
摘要提交，pi ModelRuntime 只负责独立请求；图形界面与其他 HostApi 客户端共用结果。

标题调用直接快照首条输入确定的 `pi.model`，沿用该模型的供应商与端点；设置只决定
是否启动任务。pi 的 `ModelRuntime.completeSimple` 接受调用方提供的模型，路由与鉴权
继续由 runtime 处理（`reference/pi/packages/coding-agent/src/core/model-runtime.ts:747–784`）。
Host 在配置读取和保存时只投影 `enabled`，旧模型字段留在客户端合同中兼容旧请求，
不进入运行时策略；这样读取不产生迁移写盘，旧选择也不会成为界面外的隐式覆盖。

```text
受理首句 -> 保存 attempted -> 广播临时标题 -> 主对话准备/真实 user 入树
                                               +-> 主 Agent 回复
                                               +-> 冻结素材/模型/run -> 独立标题调用
    手动改名/停止/删除/退出 -> 使任务身份失效          -> 最新摘要写盘 -> 广播
```

不能用“原标题等于新会话”判断资格：用户可能正好发送这四个字，也可能手动命名成它。
内部 ready/attempted 记录和 titleManual 分别表达自动任务资格与用户意图；无字段的
旧会话不补发，恢复的 ready 还检查真实 user。消费标记未写成功便不发辅助 API，
崩溃后也不重发 attempted；这约束业务层启动，不代表供应商绝不会重试或计费。

结果提交重新读取最新 summary，只替换 title；同名手动重命名也撤销旧 owner。
因此迟到的标题不会撤回并发置顶、归档或权限，也不会改变表示聊天活动的 updatedAt。
观测使用独立请求标识并捕获触发 run，不能复用 Inspector 单份主 SSE 聚合态：
标题若晚于下一轮结束，费用和结果仍属于最初触发轮。取消后供应商不返回的用量未知。

参照仓路径均相对 `reference/`；源码调研与真实供应商效果验证分开。

## 2. 原子替换与坏文件隔离

JSON 摘要先写同目录临时文件，再 rename 覆盖，减少中途失败留下截断目标的风险。
恢复逐文件校验，损坏项改名 `.corrupt` 并记录 stderr，其余会话继续恢复。
报错可见、故障现场保留，与“坏了就静默当新库”有本质区别。

存储驱动负责文件，领域层负责形状。版本变化有显式迁移：旧 v1 文档中的 transcript
在首次装配时导入 pi 树，再写成 v2 摘要。迁移不是两份真源长期同步。
main 与 Host 依进程边界各有原子写实现，共用依赖方向比消除一小段相似代码更重要。

## 3. 为什么恢复先载摘要、内核后装配

```text
owner: Host（会话域）                    owner: pi（转录树）
启动 → 读摘要列表                         只读历史 → JSONL 分支投影
首次 submit/compact/continue → ensurePiSession → AgentSession.open
删除/退出 → owner 失效 → 迟到实例 dispose，禁止起跑
```

装配会触发资源发现、扩展装载和会话树上下文构建，列表中每个历史会话都做一遍会白费。
Host 保留 piBuilding 去重同一会话的并发装配，messages 只读路径不装配内核。
删除或新操作先使旧 owner 失效，异步结果不能因为会话 id 一样就挂回当前运行。

pi 会话文件包含时间戳前缀，按 id 后缀查找；`SessionManager.create(cwd,dir,{id})`
显式对齐 Cogent uuid。新会话会重置索引和路径，见
`reference/pi/packages/coding-agent/src/core/session-manager.ts:1065-1088`。

## 4. 早停输入与续写快照

准备期停止可能早于第一个 user message_end。装配成功、输入尚未交付且准备链已收敛时，
Host 用公开 appendMessage 与 refreshContext 同时更新树、live context 和 JSONL；
已交付输入不再追加，装配失败也不谎称保存成功。
pi 出处：`reference/pi/packages/coding-agent/src/core/session-manager.ts:1168-1193,1222-1232`
与同 core 目录 `agent-session.ts:1505-1507`。

手动 continue 的显示快照取最后 user 回合的旧 assistant 前缀，加本次新增段；
旧正文与 usage 保留，却不重新写回转录、不重复进入本 run 的 Inspector 账本。
没有新增尾段的取消也不能用空显示快照清掉旧回答。读取时 timestamp 直接用源消息，
不能把 Date.now 当缺省，否则每次重启所有历史时间都会漂移。

## 5. 空集合与恢复的反例

活跃列表为空既可能是首装，也可能是用户归档了全部会话。load 中“空则新建”会破坏
后者的合法终态，StrictMode 双挂载又会放大成并发造两个幽灵会话。
因此 load 只恢复；创建与复用归用户导航和发送动作。原理与当前入口差异见
[会话隔离与受理语义](会话隔离与受理语义.md)，不再留另一份相反的新聊天规则。

## 6. 与追加日志、checkpoint 的区别

| 形态 | 真源与目的 | 代价 |
| --- | --- | --- |
| pi 会话树 + Cogent 摘要 | 转录追加、宿主摘要整写；重启恢复与显示投影 | 两类文件按领域分工，读路径需明确选上下文或完整历史 |
| 作者此前 DeepAgent 项目的显示数组存储 | 优先恢复画面 | 后续回放、分析或压缩时才发现原始信息已丢 |
| Claude Code / Codex 的原笔记产品对照 | JSONL 会话或 rollout 便于追加与恢复 | 仅凭文件形态不能推断完整重放、审批恢复或事务保证 |
| LangGraph checkpointer | 持久执行图状态，支持 interrupt、分叉与按步骤恢复 | 是框架级执行状态资产，复杂度和合同都大于单纯保留对话历史 |

pi 的 append-only transcript 不等于把运行中的 Promise、挂起审批和任意扩展栈都持久化。
Host 重启后可以恢复消息，不代表能原位恢复一个未回答的 beforeToolCall Promise。
时间旅行、分叉及崩溃后审批续接都需要各自的公开内核合同，不能从“有 JSONL”免费推导。

存储源代码为 `src/host/storage/{driver,json-driver}.ts`；会话装配与投影在
`src/host/kernel/{pi-session-factory,legacy-import}.ts` 和 `src/host/runtime/session.ts`。
自动协议回归集中在 `tests/integration/`，领域单元测试集中在 `tests/host/`。
