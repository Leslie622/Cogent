# 图片与文件附件：保存、模型输入与工具读取

当前机制见[模块页](../模块/图片与文件附件.md)。附件保存、模型输入和工具处理是三个
责任：导入成功只表示原件可用，不表示模型已读过；MCP 是调用协议，也可封装本地文档提取。

## 为什么保存副本，为什么绑定实际条目

路径只是定位，无法保证明天仍是同一内容。Cogent 用摘要对象 + 不透明引用：同字节可以
去重，不同用户文件仍有独立元数据。草稿与会话引用共同决定释放，原件不因移除另一卡而消失。
原图同时可能进入 pi JSONL，因此图片存在副本和转录两份磁盘成本，不能声称已经消除重复。

用户原始正文与实际模型输入也不同：后者附带受管路径、工具提示与归一化图片。显示层从
custom entry 恢复原始正文；按 user entry id 配对，避免同毫秒、同文重发、早停或压缩串归属。
普通 custom entry 不进入 LLM 上下文。绑定真实成功、input 前早停、纯附件、图片 HTTP 载荷
和追加压缩条后的历史均有真实 pi 测试，未用假内核推断持久化顺序。

## 解析依赖与边界

- PDF 采用 PDF.js 6.5.438 的 Node legacy 入口，CMap/字体/wasm 指向依赖包的绝对目录，
  Windows 路径统一正斜杠并保留末尾 `/`，`useWorkerFetch:false`。中文宋体样本和构建后
  worker 均验证。调研阶段 unpdf/PDF.js 5 组合存在安全公告，因此未用其旧版本作为产品依赖。
- DOCX/PPTX 使用 fflate、fast-xml-parser校验和 `@xmldom/xmldom` 命名空间感知解析读受限OOXML，避免为了文字结构再引入 HTML
  渲染/页面执行面；XLSX 用 ExcelJS 保留公式与可选缓存。ExcelJS 的 uuid 依赖覆盖为 11.1.1，
  并运行真实 XLSX 回归；不把缺缓存公式写成已重算。
- 同时最多两个解析 worker；超时、取消和解压预算保住 Host 响应。V8 堆限额不是完整 OS
  内存沙箱，复杂文档和最大容量仍需压力验证；PDF.js 可选原生 canvas 的分发需平台实测。
- 扫描页/页面图表走 document MCP，视频走 video MCP；没有工具时明示未解析，原件仍可访问。
  服务未声明音频能力时标音轨未分析，未报告时间覆盖则标未知；不用抽几帧冒充看完整段视频。

## 桌面 UI 与在线依据

采用 [shadcn Attachment](https://ui.shadcn.com/docs/components/attachment) 的
[base-nova registry](https://ui.shadcn.com/r/styles/base-nova/attachment.json)，输入卡上方
附件横向排列，保留既有工具行。图片的方形无详情形态和等高、限制最大宽度的文件卡放在原语 image/file 变体内，
短名称卡片按内容收缩，长名称通过最大宽度、不可换行与单行省略约束；移除按钮复用右上角原语，
悬停显现不参与卡片宽度计算，文件预留其空间，避免遮挡文字或引发布局跳动；
输入区自动换行并限高纵向滚动，避免没有横向滚动手势/滚动条时附件不可达；
历史按用户给的参考图采用图片/文件分行、靠右换行，不受输入区限高约束。
对照[Claude Code](https://code.claude.com/docs/en/common-workflows)
和 [VS Code 聊天上下文](https://code.visualstudio.com/docs/copilot/chat/copilot-chat-context)的
粘贴/拖入/选择与回显交互，不据公开 UI 文档猜其内部存储。

[Electron 31 webUtils](https://github.com/electron/electron/blob/v31.7.7/docs/api/web-utils.md)
区分有路径 File 和内存 File；Windows 文件剪贴板另有 STA FileDropList 入口。
实际 Electron 31 验证覆盖内存截图粘贴、DOM 文件拖入、预览、400px 与重启草稿；
另以原生 FileDropList 验证两个中文文件的 Ctrl+V 和路径入口，并验证页面缩放与深色布局。
这些结果不能代替所有文件管理器、Linux 或 OS DPI 的测试。

[Z.AI 视觉 MCP](https://docs.z.ai/devpack/mcp/vision-mcp-server)是本地 MCP 调视觉服务的
路线实例，其视频格式/8 MB/凭据限制属于该服务；Cogent 不把它们硬编码为通用规则。
媒体服务与主模型凭据分离。未来云上传经可注入 uploader 读取同一原件流，当前替身验证
真实字节、进度、错误和取消；local 分支不会暗中进行服务器上传。

## 工作区目录与文件附件是两条入口

本次实读的 zcode 工作区目录路径：`packages/ui/src/lib/workspaceFileDrag.ts:7–15,144–165`
将 file/directory、工作区身份和路径放在拖拽 payload；`v4/ConversationComposer.tsx:853–872`
识别后插入 mention，明确跳过上传队列。`mentions/mentionMarkdown.ts:49–67` 将目录目的地
规范化为结尾带 `/` 的 Markdown 链接；文件树 `WorkspaceFileTreeRowView.tsx:147–157,230–240`
为目录提供相同的拖拽与加入对话动作。

这条已核对的目录分支传递路径引用，不在该层递归复制、打包或展开全部文件内容。
`v4/composer/useComposerAttachments.ts` 的系统 File[] 分支仍走普通附件，不应把两条入口混为一谈。
Cogent将OS目录拖拽/粘贴和目录选择接入同一草稿，Host描述路径后分流成DirectoryRef，
文件仍走受管副本。目录不伪造零字节文件、摘要或上传状态，卡片保存路径并跟随真实用户条目落盘。
实时引用与快照是不同保证：目录变化会反映到后续工具读取，移动/删除会失败，不能当作云上传。

pi `packages/coding-agent/src/cli/file-processor.ts:35–94`的@file入口是文本/图片读取，
目录能力来自`core/tools/ls.ts:79–111`对path的目录校验和有界列举，之后由read等工具读文件。
deepseek-harness `packages/client/ui-conversation/src/client/input/file-intake.ts:17–35`
和`ui-attachment/src/client/drop-events.ts:35–95`单独识别目录成员，支持“目录与文件分别处理”这一入口纪律，
不能由此推断它同样实现Cogent的持久化目录引用。

目录引用不把外部路径升级成项目根，否则会意外改变cwd、AGENTS注入与写类信任；现有只读工具
本来就支持绝对路径，因此无需新建目录解析器。真实stdio/pi回归核对初次请求没有子文件内容，
ls/read后才出现内容标记，历史恢复路径，删除聊天也保留目录；UI复用同一附件卡配方。

| 本次实读来源 | 数量口径与机制 |

| pi `packages/ai/src/providers/model-schema.ts:87–102`、`catalog/providers/{amazon-bedrock,anthropic,google,openai}.ts:31,64–66,35,139` | 有每消息/每请求图片数和请求字节声明，按模型/Provider不同；不能把声明存在当作请求链已统一强制执行 |

pi 目录当前注记包括 Bedrock 每消息20图、Anthropic 每请求100/600图、Google每请求3600图、
OpenAI每请求1500图；这些只是本地参照仓注记，不作为已经在线核实的供应商承诺。
本次检索中，这些字段在 pi 的 schema/目录中出现，未找到通用请求装配层强制执行的消费点。

在线产品依据：[Claude 官方上传说明](https://support.claude.com/en/articles/8241126-upload-files-to-claude)
明确写聊天最多20个文件、单文件500MB；项目文件数量不限但总内容受上下文约束。
“每聊天20个”不能改写成“每消息20个”，项目文件也不能与即时附件轨道混算。
OpenAI帮助中心/API文档本次返回403，Gemini文档连接超时，Anthropic视觉API文档跳到地区不可用页；
这些网页不用于给出当前在线数字，避免把旧经验或 pi 目录注记当新查到的官网事实。

原件准入字节不等于最终请求字节：图片还会缩放/编码，历史图片也可能再次进入请求。

普通文件按需读取，因此用容量与并发约束资源，不套图片数量上限；图片准入和模型请求额度
各自执行，媒体MCP另遵从服务配置。不把“允许附加20个”解释成“任何模型保证理解20张”。
批量采用zcode的部分接收纪律，拒绝明细用浮层展示，避免挤掉发送入口；排队身份属于草稿，
全局最多两项导入，Host路径与分片共享槽防止绕过renderer无限并发。

pi `packages/ai/src/types.ts:176–182`允许异步onPayload及替换载荷；
`api/bedrock-converse-stream.ts:291–308`、`api/google-generative-ai.ts:95–100`和
`api/anthropic-messages.ts:897–905`均等待回调。Cogent先等待原变换，再核对历史图片/字节并记录。
请求对象的JSON/Base64投影是可执行的声明预算，不等于Google/AWS等SDK后续封装的完整线上字节。
超额明确失败而不采用dsh的历史降载，避免无提示丢失先前视觉上下文；未知配额不发明默认厂商值。

## OOXML兼容不能按序列化习惯猜语义

两份合法原件分别采用带前缀SpreadsheetML、通用关系ID及包内绝对路径。XML命名空间由URI
决定，关系ID是任意标识符，不能以`rId`前缀区分数值id和关系id。
zcode `apps/zcode-cli/packages/office-runtime/src/adapters/parse/ooxml.ts:120–158`
按关系查找并解析所属部件目标，是PPTX的对照；其同目录`xlsx.ts:115–131`直接交ExcelJS，
不能作为支持带前缀XLSX的证据。

Cogent通过DOM按命名空间URI保留关系属性，PPTX按关系ID查找和包内路径归一化；XLSX仅在需要时
构造语义等价的内存包，把SpreadsheetML元素投影为默认命名空间供ExcelJS读，保留其他命名空间、
二进制部件与公式缓存。原字节不改；危险目标、外部关系、DTD/实体和展开预算仍拒绝。
回归直接保存两份原始二进制，覆盖页序/备注、公式缓存、关系前缀别名与原件字节不变，
并通过构建后worker读取，避免只测人工拼出的常规XML。
