# 菜单分隔线

CSS 的 1px 是逻辑像素。125% 显示缩放下，`h-px bg-border` 的细条高 1.25 个
物理像素，背景矩形的两条边各自取整；纵向位置不同，就可能分别绘制成 1 行和
2 行同色像素。设置菜单的两个分隔线采用完全相同的样式，仍能出现这种差异。

Cogent 的 `DropdownMenuSeparator` 保留 `h-px` 作为布局占位，改用
`border-t border-border` 绘制。原生边框由 Chromium 按边框宽度统一换算物理像素，
避免将背景矩形的两条边分别取整。边框包含在原有高度内，颜色与 default / lg 的
上下边距保持原配方；不需要按 DPR 注册监听、读取元素位置或缩放伪元素。
这解决的是同一缩放下线宽一致的问题，200% 下仍按 1 CSS px 绘制为 2 个物理像素。

## 通用分隔线

模型表单的两条 `Separator` 也出现相同问题：125% 截图中同色横线分别占2行与1行。
公共 `Separator` 保留水平 `h-px`、垂直 `w-px` 占位，以 `border-t` / `border-l` 绘制；
`ButtonGroupSeparator` 与权限确认面板的自定义颜色改用 border token，避免背景矩形重新参与取整。
这类问题应在分隔线原语修正，调用处不依纵向位置补像素；模型弹窗的对齐与间距另由布局负责。

## 同主题源码对照

- zcode `reference/zcode/packages/ui/src/components/ui/dropdown-menu.tsx:187–198`
  的 `DropdownMenuSeparator` 用 `-mx-1 my-1 h-px bg-border`：以背景色矩形画线，
  同时保留 Radix 的分隔线语义。此处没有分数 DPR 的像素对齐处理。
- Cogent 保留 Base UI 的语义元素与 shadcn 的间距，在公共原语里改变画线方式，
  调用处不加样式补偿。伪元素反向缩放需要额外考虑起点对齐，在此场景无需引入。

## 验证

`node scripts/check-menu-separators-browser.mjs` 使用独立 profile 的 Electron，
在 DPR 1 / 1.25 / 1.5 / 2 下渲染真实 DropdownMenu，等待字体、浮层定位与动画完成。
每个 DPR 覆盖 default / lg、界面字号 11 / 14 / 16、浅深色和三个纵向位置；
逐行读取原生截图的物理像素，要求两条线的像素行数与 RGB 完全一致，并验证预期线宽。
同一入口也验证通用横线、竖线与按钮组的两个方向，在相同字号、主题和分数位置矩阵中比较物理像素。
该检查不以 DOM 高度或类名代替像素结果。`COGENT_MENU_DPR` 可指定单个 DPR，
`COGENT_MENU_SCREENSHOTS` 可指定截图目录；测试进程和临时 Vite 均在结束时关闭。

当前配方见 [UI布局](../UI布局.md)。
