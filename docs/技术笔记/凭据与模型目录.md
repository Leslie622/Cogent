# 凭据与模型目录

> 学习主题：OS 加密、宿主凭据注入、运行时 Provider 注册与模型身份。
> 当前协议和界面行为见 [凭据与模型目录模块](../模块/凭据与模型目录.md)。

## 1. 三类数据分别归谁

API key 是机密；端点地址、模型清单与覆盖定义是非机密配置；pi Model 是请求需要的元数据。
把三者放在同一个前端配置对象里，既扩大密钥可见面，也使“目录里有模型”与“请求能发出”混淆。

Cogent 由 Host 将定义明文落在 `~/.cogent/custom-providers.json`，key 经 main 的 safeStorage
加密落 `credentials.json`。Host 只持内存凭据与运行时注册表，不绑 Electron 加密 API。
引擎协议批量查询只回配置布尔位；壳侧另有按 provider 单取明文供设置页回显的显式 IPC。
“引擎不回传明文”不能外推成“renderer 永远拿不到单个 key”。

## 2. pi 的凭据与目录原语

- `CredentialStore` 提供 read/list/modify/delete，modify 按 provider 串行，保证 OAuth
  读改写的原子性；源码参照 `node_modules/@earendil-works/pi-ai/dist/auth/types.d.ts:57`
  与 `auth/credential-store.js`。持久化由宿主提供，内核不必知道磁盘加密格式。
- `auth/resolve.js:14-24` 依次采用请求覆盖、CredentialStore、provider 的环境来源。
  Cogent 用 `ModelRuntime.setRuntimeApiKey` 内存 overlay 注入，底层空 CredentialStore，
  不读取 `~/.pi`。设置、删除与握手均等待 runtime 更新，避免 UI 成功而请求仍用旧值。
- `createProvider` 把 id、baseUrl、auth、models 和流式方言组装为 Provider。
  `models.js:534-543` 明确内置厂商与 models.json 自定义厂商走同一工厂。
  `MutableModels.setProvider` 按 id upsert（同文件 `:52`），无需改引擎源码。
- Model 是纯数据：id/provider/baseUrl、窗口、输出上限、定价、思考能力分别参与请求、
  预算与展示。目录数据来自 pi 的生成管线，修改可选字段时不能无意丢掉其他元数据。

## 3. 为什么自定义 Provider 必须双注册

```text
非机密定义 → CustomProviderRegistry → 一次 createProvider
                                      ├─ MutableModels：UI 目录与 submit 查找
                                      └─ ModelRuntime：pi streamSimple 请求路由
safeStorage → main → Host 内存凭据 → ModelRuntime runtime key overlay
```

`custom/*` 不是 pi 内置的 provider id，只更新 MutableModels 会出现下拉能选、实际调用却
报 provider 不存在。用同一个 Provider 实例注册两处，可以避免两份映射各自漂移。
删除或禁用时同样卸下两个消费面；内置 provider 的端点覆盖则写进 Model.baseUrl 随请求传入。

内置覆盖保留原 Provider 的流式和 auth 行为，用闭包委托 `original.stream/streamSimple`；
不能对包含方法与内部状态的 Provider 做 JSON 序列化重建。模型对象是纯数据，浅拷贝改
baseUrl 则安全。以上设计在 `src/host/runtime/custom-providers.ts` 文件头与
`sync/buildCustomProvider/buildOverrideProvider` 中集中实现。

## 4. 覆盖、禁用与身份的典型陷阱

| 场景 | 原理与处理 |
| --- | --- |
| 用户编辑目录同 id 模型 | 以原目录条目为基底，显式字段才覆盖；定价、思考映射等未配置维度必须继承 |
| 全新自定义模型 | 没有可验证的计价来源，cost 为 0 表示未知，不伪造价格 |
| 只给新增模型改 baseUrl | 原目录模型仍请求官方端点；覆盖必须对该 Provider 的全部模型生效 |
| 不同 Provider 收录同 id | 选择状态、submit、窗口分母都以 `(providerId, modelId)` 双键定位，单键过滤 key 也消不掉歧义 |
| 用覆盖后的目录判断 userDefined | 用户新增项已混入集合；应以最初的内置目录快照判定，自定义 Provider 条目恒为用户定义 |
| 禁用模型后行消失 | 运行目录允许不注册，但设置页还要保留定义或裸 id 行以便重新启用；行序独立于启用状态 |
| 禁用同名覆盖行后原目录复活 | 覆盖 id 集合必须取未过滤的完整定义，禁用项仍压住原目录孪生条目 |
| renderer 刷新后仍是旧逻辑 | Host 是独立进程；renderer HMR 不更换运行中的 Host，先核对实际构建与进程版本 |
| 同名模型编辑能力后旧会话仍传图 | 只比较 provider/id 会跳过新定义；同名时更新公开 Agent state.model，跨身份才调用 pi.setModel，避免虚假 model_change 条目 |

视觉标签和发送门禁消费同一份有效 input。zcode 的
`reference/zcode/packages/ui/src/lib/modelSelectionGroups.ts:68–75` 读取有效
`properties.inputFormat.supportsImage`，`ModelConfigSelect.tsx:348–359` 在模型旁渲染标签；
`lib/modelVisionBadge.ts:3–20` 另有套餐 GLM-5.3 的纯展示例外，不改变能力事实。
Cogent 没有这条套餐桥接，不复制型号例外，只按有效 input 显示“视觉”。
input表示是否能原生接图，inputLimits表示已声明的数量/请求容量，两者不能互相代替；
后者在发送前按整个有效请求校验，机制与三仓依据见[附件笔记](图片与文件附件.md#数量限制应按入口和模型请求区分)。
pi `reference/pi/packages/coding-agent/src/core/agent-session.ts:2644–2664` 的 setModel
会写转录；同身份的定义刷新直接更新其公开 Agent 状态，与该方法内部实际赋值一致。
真实 pi 回归核对同聊天开启/关闭/再开启的 HTTP 请求和控制台快照，不能拿旧图的历史文字答对当成当前仍传图。

菜单的组件名相同也不能推定原语契约相同：zcode 的
`reference/zcode/packages/ui/src/components/ui/dropdown-menu.tsx:167` 将 Label
映射到 Radix Label；Cogent 的 Label 映射到 Base UI GroupLabel，后者读取父分组
上下文并关联 `aria-labelledby`（`node_modules/@base-ui/react/menu/group-label/MenuGroupLabel.js:29`）。
因此新增模型输入声明时必须遵循本项目的分组结构，不能照搬独立标题的嵌套方式。
回归测试使用真实 Base UI 菜单点击展开，才能覆盖关闭状态下尚未挂载的标签。

显示统一用模型 id，所见即请求所传；pi 的 name 字段仍保留在数据中满足内核契约。
sync 采用全量替换，定义规模小，可同时处理删除、还原内置覆盖和启停，不再建立增量操作日志。

## 5. 方言是 Provider 零件，不是换一个模型名

pi 的懒加载工厂分别构造 OpenAI Completions、OpenAI Responses 与 Anthropic Messages。
Cogent 在 `API_BY_FORMAT` 显式映射三档；网关可能按路由授权，同 key、同模型在一种方言
可用而另一种 403，并不能据此判断模型不存在。

| 方言 | SDK 追加路径 | baseUrl |
| --- | --- | --- |
| openai-completions | `/chat/completions` | 通常包含 `/v1` |
| openai-responses | `/responses` | 通常包含 `/v1` |
| anthropic-messages | `/v1/messages` | 根地址，不重复 `/v1` |

排查先看错误信封是否随方言改变，确认命中路由；再对齐该网关已验证的地址、模型和权限。
错误形状是路由线索，不能单凭“另一个客户端可用”归因于模型名或 Cogent。

## 6. OS 加密的代价与恢复边界

safeStorage 使用系统保护，Windows 的密文与用户/机器环境绑定，整目录迁移并不保证解开。
不能在加密不可用时静默退成明文。另一方面，坏文件也不应阻断窗口与重输入口：
main 显示 credentials:status 的降级错误，内存暂用空表；用户成功重新保存后覆盖恢复。
这是可见的显式恢复，不是把丢 key 伪装成成功。清除使用 remove 真删，空字符串不代表删除。

`src/electron/main/credentials/store.ts` 的 ensureLoaded/status/write/remove 和
`src/electron/main/ipc/credentials.ts` 的 set/remove/get 分别承接这些边界。

## 7. 连通性测试为什么要走真实模型流

模型目录存在、Key 非空或 HTTP 首页能访问，都不能证明指定模型在指定方言下可调用。
探测应使用正式请求链路，并要求完整的流终态；输出只有思考、因预算耗尽而结束，仍可证明连通，
不要求回复文字必须等于某个固定答案。

zcode 的 `reference/zcode/packages/ui/src/settings/model-provider-section/ProviderFormControls.tsx:137`
在模型行发起测试，按供应商/模型身份更新 pending、success、failure 反馈；同文件 `:270` 的图标钮
在测试中转圈并禁用。`InlineEditableProviderCard.tsx:614` 先提交供应商草稿再探测，
服务协议 `reference/zcode/apps/zcode-cli/packages/bootstrap/src/zcode-protocol/workspace-model-runtime.ts:42`
刷新正式注册表。这里可借的是“先让配置生效，再按身份请求”，不需要复制它的工作区应用创建机制。

zcode 的 `reference/zcode/apps/zcode-cli/packages/core/src/runtime/methods/workspace-generate-text.ts:53`
直接调用模型流：固定 system 提示与 `hi`、最低思考档、最多512输出 token、60秒超时，
逐事件检查 error 与 finish。它明确指出1 token预算会被部分上游拒绝，也不能超过模型自身上限。
Cogent 采用相同探测尺度，使用自己的提示身份；独立请求不装配 Agent 工具，也不写聊天记录。

pi 的 `reference/pi/packages/coding-agent/src/core/model-runtime.ts:744` 提供 `streamSimple`，
内部仍经过 `prepareRequest` 解析 Provider 与鉴权，而 `:783` 的 `completeSimple` 只是取流结果。
Cogent 使用前者显式观察 done/error，避免把带 errorMessage 的 AssistantMessage 当正常完成。
外层计时还同时中止请求和结束等待，不能只指望外部实现一定回送取消事件。
renderer store 保存定义与 Key 的 Promise，由测试入口等待；保存失败保留为失败，重新保存后才可继续。
HTTP 与 WS 的调用档位归 write，因为独立测试同样会消耗用户模型额度。

自动验证分三层：Host 流终态/超时单测、renderer 保存交接与按钮反馈、真实构建 Host 配合 loopback SSE
核对供应商双键、内置地址覆盖、鉴权错误及零聊天副作用；真实服务的可用性仍由用户点击时的结果决定。

## 9. Cogent 落点

`src/electron/main/credentials/store.ts` 与 `ipc/credentials.ts` 管密文、单取和状态；
`src/electron/main/host/manager.ts` 管握手注入；`src/host/runtime/credentials.ts`
与 `custom-providers.ts` 管内存桥与注册；设置页 `ModelsSection.tsx`、
`CustomProviderDetail.tsx`、`BuiltinProviderDetail.tsx` 和聊天 `ModelMenu.tsx`
消费同一目录。当前协议与验收由模块页维护。

本轮文档/运行身份、提交/迁移、配置与退出的三仓对照见[运行交接与数据可靠性](运行交接与数据可靠性.md)，当前实现以对应模块为准。
