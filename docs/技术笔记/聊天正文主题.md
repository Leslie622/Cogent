# 聊天正文主题（Themd 主题包运行时化）

> 落点：`src/renderer/src/lib/theme/`（tokens/compile/theme-file）、`stores/theme.ts`、
> `features/home/ChatTheme.ts`、`features/settings/AppearanceSection.tsx`、
> `globals.css`「聊天正文主题」消费表。现状见 [消息呈现](../模块/消息呈现.md)。

## 1. 问题

助手消息正文由 Streamdown 渲染（技术笔记/Markdown渲染.md），样式是**烤进组件的
Tailwind 工具类**——想换观感只能改代码。目标：接住 Themd（作者的 Markdown 笔记本
项目）导出的主题包（`.themd.json`），设置页导入、运行时生效，**换主题 = 导数据，
不改代码**。

难点在「外部渲染器的 DOM」与「主题数据」如何解耦：Streamdown 的 DOM 我们不控制，
但样式必须主题化。

## 2. Themd 的解法（源系统，为什么可移植）

Themd 源仓在作者本机 `C:\Users\41631\Desktop\Themd`（不进本仓 `reference/`，
对照上游令牌/编译实现时以此路径为准）。

Themd 三层契约（`src/lib/theme/`，对照本仓同名平移件）：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 契约 | `tokens.ts` | 179 个令牌键 → CSS 变量名（`'h1.size'` → `--t-h1-size`）的唯一定义 |
| 编译 | `compile.ts` | 纯函数：稀疏令牌集 → 变量表（含 a.underline 策略展开、字体 latin+cjk 拼合与继承链展开） |
| 消费 | theme-base.css | 语义样式表逐项 `var(--t-*, 回落值)`；**回落值集合 = 极简主题**；令牌只存差异 |

关键设计：**主题是一份数据**（稀疏令牌），观感差异全部走 CSS 变量注入，样式表
本身永不改。作用域钉在正文容器类上（`.themd-prose` / Cogent 的 `.md-body`），
不污染应用界面。这套契约零框架依赖（纯 TS + CSS），所以能整体平移。

Themd 的两个可借鉴手法（本仓都用了）：
- `[style*='--t-xxx']` 属性选择器判「令牌是否注入」（Themd del 自绘线在用，
  Cogent 用它做拆壳门控，见 §4）；
- 导入防御形状：坏字段按无值处理（持久化读取边界，约定.md §1.1）。

## 3. 三仓对照（AGENTS.md 规则 7）

| 实现 | 主题架构 | 与本方案的关系 |
| --- | --- | --- |
| **Themd** | 上述三层契约 | 直接平移（179 键两仓逐字一致，改键 = 主题包互不兼容） |
| deepseek-harness | 手写 mdast→React 渲染器 + CSS Module（`packages/client/ui-primitives/src/markdown/render.tsx:1-14`）——DOM 全自控，选择器天然可控 | 不走：为主题化重造渲染器，成本远超收益；他们手写的动机是流式性能与安全策略 |
| pi | pi-tui 的 MarkdownTheme 主题对象；HTML 导出另用 marked（`modes/interactive/components/assistant-message.ts:5-8`、`core/export-html/index.ts:148`） | 属于各自渲染器的消费合同，不能直接作为 Streamdown 的 CSS 主题 |
| zcode | 主题对象 → `createMarkdownSyntaxStyle(theme)`（`apps/zcode-cli/packages/tui/src/app-markdown-theme.ts`），主题喂给渲染函数 | 不走：主题与渲染器绑定（TUI 专属），无法跨端复用；CSS 变量路线才与渲染器解耦 |

结论：Cogent 选择 **CSS 变量 + 消费表**，把第三方渲染器的 DOM 与主题数据解耦——
变量挂容器（继承可达任意后代）、消费表对 DOM 钩子、令牌随包走。

## 4. Cogent 侧的三个技术要点

### 4.1 cascade：非 layer 恒胜 layer

Streamdown 的默认样式经 `@source`（globals.css 头部）生成于 `@layer utilities`；
CSS 层叠规则：**未分层样式恒胜任何 layer 内样式（与优先级无关）**。消费表放
globals.css 末尾的非 layer 区，即可整体压制包默认样式，唯一例外是 Shiki 写在
pre 上的内联 `background-color`——层叠里只有 `!important` 能过内联样式，全表
仅代码块一处；且压制方向是 **transparent**：灰板底色放在滚动容器
（`code-block-body`，即滚动条 13px 占位 gutter 所在层）上，gutter 随容器同色，
pre 透明让底色统一——底色若留在 pre 上，gutter 会透出页面白底。

### 4.2 无令牌组逐像素 = 原生：两类规则分治（决定 19）

首版教训：把 Themd 极简值烤成回落 + 无条件拆壳（代码块三层卡片壳归零），
无令牌的正文代码块变成「语言条/白卡断层」——**回落值 ≠ 原生观感**
因此必须按两类规则分治（「默认」主题 2026-11-18 起带 Theme-Leslie 令牌，
但用户主题包是稀疏差异，任何组都可能缺席，门控两分法长期必要）：

- **平滑属性**（字体/色/内边距/圆角值）：无条件规则 + **原生等值回落**
  （如 inline-code padding 回落 `2px 6px` = 原生 px-1.5 py-0.5）；
- **结构切换**（卡片壳 ↔ 灰板/裸表）：`[style*='--t-code-']` /
  `[style*='--t-table']` 属性选择器**门控**——匹配挂着变量注入的祖先容器
  （ChatTheme 把编译产物挂消息流容器的 style 属性），令牌组注入才整组切换，
  缺席时 CSS 完全不触碰原生结构。

根因记录：CSS 无法表达「自定义属性存在与否」的分支——`var()` 回落只对
属性值有效，而拆壳是结构性增删（多条规则整体启停），不能靠回落表达。
属性选择器匹配 style 属性的序列化文本，是「变量存在性」唯一的纯 CSS 探测
手段。代码块门内 bg 回落 Themd 极简灰（与 Themd「code-bg 恒有默认」语义
对齐）：只设字体的主题（如 Theme-Leslie）也切灰板，不会出现两截色。

### 4.3 注入链路与持久化

```
useThemeStore（zustand persist → localStorage: cogent-themes，全仓首个）
  activeThemeId → ThemeFile（「默认」= 内置 Theme-Leslie 令牌常量，不占存储）
    → compileTokens（纯函数，useMemo）→ 亮色变量挂消息流容器 style
    → dark 套 + extraCss → <style> 元素（.dark 前缀待命 / @scope (.md-body)）
```

单点挂载（消息流唯一容器），CSS 变量沿 DOM 继承覆盖全部 `.md-body` 实例；
extraCss 用 CSS 原生 `@scope` 钉作用域（Electron 31 = Chromium 126 已支持），
不改写选择器——Themd 的正则改写是为「导入第三方 CSS」服务的启发式，
Cogent 方向相反（导出端语义已保证），@scope 更对。merge 时形状校验（坏档
剔除、激活 id 失联回落默认），持久化读取边界。

## 5. 边界

- 代码配色（Shiki token 色）归 `shikiTheme`，不进消费表——内联样式的领地；
- `root.width` 不消费（正文列宽归布局层）；暗色套编译待命（`.dark` 休眠）；
- 主题跨设备同步不做（引擎侧无设置同步通道，localStorage 即正确层）。

## 6. 验收口径

默认态与无主题时代逐像素一致；导入 Theme-Leslie 后引用卡片/表格 2px 边框+
斑马纹/代码灰板/链接 hover 蓝即时生效；切默认全回落；重启留存。
行为钉：`lib/theme/compile.test.ts`、`theme-file.test.ts`。
