# 架构地图：模型与页面分开维护

交互架构文档既需要可信的组成关系，也需要与产品一致的 UI。本篇依据本仓库源码、
LikeC4 官方资料与安装包接口，不包含其他参照仓库的实现结论；调研范围按用户确认收窄。
当前机制与验收归属[架构地图模块](../模块/架构地图.md)。

## 为什么由 LikeC4 管模型

手写 SVG 需要同时维护模块含义和坐标，结构变化会牵动连线。LikeC4 的元素、关系与
视图分开声明，同一份模型可以供多个视图使用；[视图文档](https://likec4.dev/dsl/views/)
与[目录组织](https://likec4.dev/dsl/views/organize/)分别定义两者。本项目的
`docs/架构地图/模型/架构.c4` 是组成与关系的单一来源，坐标由构建插件计算。

这没有消除阅读设计：总览只表达核心结构，细分职责放说明面板。HostApi 是方法集合，
CogentKernel 是进程内 TypeScript 接口，不能因为两者都叫 API 就画成两个服务。
出处是本仓库 `src/host/host-main.ts:798` 方法注册表、
`src/host/kernel/contract.ts:34` 接口，以及
`src/electron/main/host/manager.ts:127` 的 Host 进程启动。

传输与使用场景分列：左侧显示桌面壳、Cogent 原生调用方、自有协议调用方、外部 Agent 与 MCP Server，右侧显示 stdio、网络入口。
总览将 HTTP 与 WS 折叠为网络入口；接入视图中各类网络调用方连接 HTTP 与 WS，
明确两种调用方式，不将每个产品页面都拆成独立模块。
HTTP 用于请求响应，WS 用于双向调用与事件，拆开后能直接看出 MCP 对两种通道的组合使用。
传输入口复用
`src/host/host-main.ts:879` 的 `handleFrame`；MCP 经
`src/host/mcp-server/main.ts:35` 的 stdio 协议面，再由
`src/host/mcp-server/host-client.ts:28` 转为 HTTP 与 WS，不另列为 Host 的传输入口。
MCP 转换显式画在网络入口之前：`tools.ts:129` 的 `cogent_sessions_list` 映射为 `session.list`，
`tools.ts:76` 的 `toolResult` 将返回值与错误包装成 MCP 工具结果。Host 内的通用旧接口适配
是另一项目标能力，不能因为 MCP 已有专用转换就把两者合成同一实现状态。

## 与官方嵌入方式的对照

| 方案 | 本次依据 | 本项目选择 |
| --- | --- | --- |
| 直接嵌入 ReactLikeC4 | [React 文档](https://likec4.dev/tooling/react/)；安装包 `likec4/vite-plugin-modules.d.ts:90` 声明内置组件入口 | 使用方便，但内置界面有 Mantine 与 shadow DOM；壳层换 shadcn 不能统一节点及弹层 |
| 读取布局模型 | 同一文件 `:58` 的 `likec4:single-project`；`useLikeC4Model()` 提供已布局模型 | 读取各视图的 `$layouted`，保留元素、分组、坐标与完整正交路径；这是本项目自定义适配 |
| 自己维护所有图形坐标 | HTML/SVG 可直接表现，但需随结构手工调整 | 不采用；让 LikeC4 计算布局，React Flow 负责显示与视口 |

节点和所有操作控件直接复用 `src/renderer/src/components/ui/`；已实现状态使用有可访问名称的绿色勾，集合区块不标完成度。这样不需要注入一份
shadcn 样式到第三方 shadow DOM，也不必追随其弹层样式。适配器只处理边界数据：
父子坐标、节点渲染数据、既有路径圆角与标签位置。各视图共用元素、关系及能力状态；后续加视图时先扩展模型和导航，
不复制整张页面。固定依赖版本使升级影响集中到适配器与布局检查。

网络入口使用 LikeC4 嵌套元素与视图关系聚合，模型只维护具体 HTTP、WS 连接。
总览通过 `include … with { title '…' }` 覆盖聚合线的标题，细图保留方法调用、事件订阅与认证时机。
这样可以减少总览交叉，也无需复制一套简化关系或在显示层手工合并连线。
协议是调用方的接口约定，不需要为了说明格式再增加一个 Host 模块。图按本次调用所用协议区分
Cogent 原生调用方和自有协议调用方；后者明确包含 UI 与远程服务，远程是部署位置而不是 UI 类型。
调用方卡片直接以 LikeC4 `line dotted` 关系连接自定义协议适配，表达谁消费适配能力；该关系不代表一次跳过认证的请求。
实际调用继续沿传输、认证、协议处理和权限检查流动。适配关系使用圆点线，未实现调用使用长虚线，不再增加专门视图。Cogent 原生协议始终带产品名称。

汇总状态不能替代能力事实。认证、权限和模型适配在 `模块说明.ts` 中分别列出已完成与待完成项，
节点和说明面板共用同一列表，以分行及行尾绿点、橙点表达；不在卡片和面板重复维护状态清单。

### 总览如何收紧 Host

Host 大框内保留服务层、能力总线摘要，以及包含 pi SDK 和其他内核的 KernelRunner 容器。
运行时与安全策略是执行基础，放在容器标题和底部说明，不再各占一张卡片。
服务与能力通过 LikeC4 同一模型的不同视图展开；总览只纳入父元素，详情纳入父元素及子元素，
页面点击摘要切换视图。这样可以详细呈现职责，又不把总览拉成所有子模块的展开图。
KernelRunner 对外作为整体：服务驱动、能力装配和模型请求都连接容器边框，PiSdkKernel 与其他内核仅表达包含关系。
布局提示分别组织接入主链与下方执行区；服务层和能力总线同列分开，避免多条水平线挤在同一高度。
传输入口以两条水平接线确定内部高度：桌面壳直连 stdio，stdio 直连原生协议；网络入口与身份认证及自有协议调用方对齐。
两入口之间的纵向空间由 LikeC4 随对齐约束展开，避免以容器顶部折线补偿节点错位。
子会话、其他内核和 OS 沙箱保留预留状态，不将原图中的目标位当作现有实现。
本仓库 `src/host/runtime/session.ts:467` 实现 CogentKernel，`:1742` 装配 pi；
`kernel/contract.ts:34` 是当前 KernelRunner 职责的真实接口，没有另一个同名类。

仅设置 `autoLayout LeftRight` 无法保证上下行的次序。[LikeC4 官方布局工具](https://likec4.dev/tooling/vscode/)
支持保存布局；安装包 `likec4/dist/chunks/index2.d.mts` 的 `AILayoutHints`、`layoutView` 与
`ChangeView` 则提供行列提示和保存快照接口。本项目的 `scripts/layout-architecture.mjs`
使用这些接口：同列约束控制宽度，较高边权保持主链水平，不可见约束控制上下次序，
并将两个模块详情排成两列；服务与能力供给、消费关系排除出总览主链层级排序，
但保留连线。排版约束不代表额外业务连接。图形坐标和正交路由仍由 LikeC4 生成。
生成的官方快照只是构建中间物，开发、构建和测试前重算，不与结构模型共同手工维护。
布局检查继续验证无穿线、无共享线段、标签避让，并约束总览直接包含全部核心与 Host 宽度。

## 可维护性的实际边界

自动布局不能保证中文字宽与自定义卡片完全一致。卡片保留名称、技术标识与状态，较长解释
放面板；模型测试检查语义、状态、父子坐标与接线几何，真实浏览器再检查内容裁切。
这两个层次分别覆盖语义和渲染，构建成功不能替代后者。

### 为什么不能在显示层再路由一次

LikeC4 1.61.0 支持 `autoLayout LeftRight … ortho`。官方包 `@likec4/core/geometry`
的 `splineToPolyline` 提取 Graphviz 正交路径的真实折点，`placeLabelsAlongRoutes` 根据
所有路径及节点共同放置标签；接口分别见安装包 `dist/chunks/index2.d.mts:147` 与 `:129`。
本项目的 `src/布局适配.ts` 直接消费这些结果。总览业务回接有一个局部例外：Graphviz 允许
HostApi 到服务层的线穿过 KernelRunner 分组的内部空隙，因此该连接根据真实分组边界沿外侧 32px 绕行。
这一最终路径与原生路径一起参与端口、穿线、交叉及标签检查；回归明确禁止它穿过整个执行容器及周围 16px 区域。

被否：只保留首尾端点，再调用 React Flow `getSmoothStepPath`。该方法看不到模型的其他
通道、节点和标签，分支汇入时会重叠，原生标签位置也随之失效。保留原生通道后，只允许
端口贴边、避开卡片圆角，以及拐点小圆角；标签要根据最终路径重新共同放置。
多对多连接保留原生路径，通过局部留白明确跨越点；不能为避免交叉而删掉真实支持的连接。
测试检查每条路径正交、端口分开、不穿过其他节点、不共享线段、每个交叉有跨越标记，以及标签避开所有线。

横向总览还需要独立考虑阅读比例：完整长图适应窗口会把文字缩得过小，默认视口应保持
可读字号，并提供主动适应全图。React Flow 13 的 padding 使用像素，明确预留工具条空间；
浏览器检查默认字号、全图适应和侧栏收放，而不把默认显示全部节点当成可读性保证。

图的目标关系与后端能力不能混为一谈：认证、权限及两种协议分支可以先画清楚，再按
节点说明区分已有能力和待补能力。状态集中维护，不在 DSL 与页面各复制一份；图里可连通
不代表当前后端已经存在对应的统一认证或协议适配接口。

共享 UI 还会遇到 React 实例和类型重复：Vite `dedupe` 管运行时，tsconfig 的路径映射
管类型解析。两者都要统一，不能通过忽略共享组件类型错误来掩盖问题。

离线单文件把中文字体也嵌进去，代价是约 35MB 的产物。它换来与主应用一致的字体、
无网络请求和直接打开；模型、页面源码与锁文件入库，构建产物不入库。
