# 架构地图：模型、确定性布局与页面设计

交互架构文档既要与代码保持一致，也要避免被底层排版引擎和跨工程 UI 耦合拖慢演进。当前架构与验收归属[架构地图模块](../模块/架构地图.md)，重构依据见[架构地图重构方案](../计划/架构地图重构方案.md)。

## 为什么保留 LikeC4 管模型、改用自研网格布局

- **LikeC4 负责语义单一事实源**：`模型/架构.c4` 与 `模型/流程.c4` 共用同一个 `specification` 与元素体系，保持 `call`、`configuration`、`assembly`、`dependency` 关系类型以及 `#planned` 标签语义不丢失。
- **放弃 Graphviz 全局重排与 `.snap` 快照**：Graphviz 在增删节点时容易触发全图重新排秩；过去的 `scripts/layout-architecture.mjs` 与 355 行局部坐标补丁强耦合具体节点 ID。
- **改用声明式 `(col, lane)` + 确定性通道路由**：`src/视图布局.ts` 只声明节点所在逻辑列与泳道；`src/网格布局.ts` 按固定列宽、容器嵌套边界留白、同侧分流端口与正交轨道槽位完成布局与路由，并复用 `@likec4/core/geometry` 的 `placeLabelsAlongRoutes` 自动避让节点与容器边框。同一模型即可同时驱动结构拓扑与专题流程图。

## 为什么剥离主应用 UI 依赖

| 方案 | 优点 | 代价 | 本项目选择 |
| --- | --- | --- | --- |
| 直接嵌入 `ReactLikeC4` | 零自建画布 | 带入 Mantine 与 shadow DOM，交互定制受限 | 不采用 |
| 跨目录复用 `src/renderer` shadcn + `globals.css` | 组件完全同源 | Vite `fs.allow`/`dedupe`、TS `@types/react` 路径 hack、内嵌字体致产物 ~33.4 MB | 已淘汰 |
| **自包含轻 UI + 系统字体栈** | 零跨工程耦合、产物 < 2 MB、主应用升级互不干扰 | 自维护少量中性色原语与内联 SVG 图标 | **采用** |

## 图码保真边界

- **机械底线**：Vitest 的 `保真校验.test.ts` 自动检查所有 `sources[].path` 存在性、代码符号令牌存在性、以及 `.c4` 视图与 `视图布局.ts`/`模块说明.ts` 的 1:1 双向一致性。
- **同步节奏**：不在过渡性实现细节改动时频繁改图；仅在进程/通道/存储边界变更、`#planned` 能力正式收口或核心机制主流程稳定变化时同步。
