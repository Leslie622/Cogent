# 会话搜索：派生索引与消息来源

搜索的难点是“找到后回到正确的原文”。弹窗与候选排序只完成入口；历史、直播、
压缩保留区和续写合并若没有同一来源映射，标题能搜到也可能跳错位置。
当前机制归[模块页](../模块/会话搜索.md)，证据与未测范围归[验收册](../测试用例/会话搜索.md)。

## 为什么选 Command

[shadcn Base Command](https://ui.shadcn.com/docs/components/base/command) 与
[Nova registry](https://ui.shadcn.com/r/styles/base-nova/command.json) 提供输入、分组、
结果项和对话框；当前 Nova 版仍依赖 cmdk。组件通过 CLI 安装，保留已有 Button、
Dialog、InputGroup 的本地定制，没有整体覆盖组件库。

[cmdk 官方说明](https://github.com/pacocoursey/cmdk#readme)确认异步结果、加载态、
循环键盘导航与 `shouldFilter={false}`；Host 已排序，UI 必须关闭二次过滤，
否则正文命中的结果可能因标题不匹配又被藏掉。结果项使用唯一 ID，避免同名聊天冲突。
Nova 源组件的 selected 选择器需按 cmdk 的 `data-selected="true|false"` 精确匹配，
不能仅检查属性存在，否则未选项也会全部染上选中色；可访问名称通过 Command 的 label 提供。

公开产品行为对照：

- [ChatGPT 官方帮助](https://help.openai.com/en/articles/10056348-finding-your-chats-projects-and-files-in-chatgpt)
  描述侧栏/Ctrl+K、标题/消息匹配、旧聊天与归档可搜、删除不再可搜。
  Cogent 搜索浮层按回收站语义排除归档；HostApi 的可选范围参数独立保留，不能把浮层入口范围外推成整个接口的能力边界。
- [Claude 官方帮助](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context)
  描述模型通过 RAG 工具检索旧聊天与项目范围。这是另一个消费者，
  不能据此把 GUI 检索自动升级为模型可读全部历史。

上述资料于 2026-11-21 获取；文档行为不证明闭源后端采用哪一种索引。

## 中文短词与 SQLite

项目自带 Node 22.23.5 的 SQLite 3.54.1 已包含 FTS5，`node:sqlite` 不增加 npm
原生二进制依赖，但仍产生实验性 API 警告。
[对应 Node 文档](https://github.com/nodejs/node/blob/v22.23.5/doc/api/sqlite.md)
说明 DatabaseSync 同步执行，因此数据库与全文读取放入独立搜索 worker。

临时探针对连续中文句 `用户说你好，请检查登录报错` 的结果是：unicode61
不能命中句内的“你好”或“登录报错”；trigram 可命中“登录报错”，但“你好”和“好”
都不匹配。[SQLite 官方说明](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)
明确 MATCH 不支持少于三个 Unicode 字符的子串。故较长词先用 trigram 获取候选，
短词用字符/双字符候选索引，最后由 instr 与同一字面匹配器验证；不通过“三字起搜”掩盖中文检索缺口。

大小写规范化按码点进行，保留原始 UTF-16 区间映射，防止大小写展开和 emoji 使高亮偏移。
FTS 的每个词项都作为引号转义后的数据传入，不把 OR、星号或用户输入当可执行表达式。
查询、摘录与原文高亮共享匹配规则，文本命中单位为呈现消息，不跨几十轮拼接词项。

50,004 条合成消息的早期内存候选计数探针中，长词 trigram 约 0.03–0.18ms，
字面全表扫描约 28–38ms；这是候选计数，不含文件 I/O、分组、IPC 或呈现，
不能声称产品端到端性能。完整磁盘 worker 探针独立记录在验收册。

短词扫描在完整磁盘语料探针中超过目标，因此另建 contentless FTS：把每个规范化
码点和相邻双码点编码成独立 ASCII token，每条文档只存唯一 token，不再存一份正文。
查询先交叉候选，再字面验证；SQLite 内按会话取本页需要的消息，避免高频词把几万条
完整正文搬进 JS 才丢掉。低选择性的高频候选改为逐会话取足结果，避免第一页就给全历史命中排序。schema v1 的已识别派生库仅回填此索引，真源不迁移。

## 搜索必须只读

pi 的 `open()` 在空文件初始化或旧格式迁移时可能改写源文件：
`reference/pi/packages/coding-agent/src/core/session-manager.ts:1037、1093、1132`。
公开 `parseSessionEntries` 与 `inMemory(..., entries)` 入口见同文件 `:355、1822`。
Cogent 用只读文件加载和内存分支恢复，保留压缩前原文，而非模型当前上下文裁剪结果。
损坏行、来源变化或索引错误给出诊断；不能因为解析器会跳过坏行就宣称结果完整。

另一个边界是 Cogent v1 的转录仍在摘要文件里。真正导入 pi 之前，重命名/归档
不能先把它写成没有 transcript 的 v2；这会丢掉唯一真源。元数据保存保留旧转录，
迁移成功才转为 v2，回归覆盖“搜索—改名—归档—重启”。

## 来源身份独立于 UI key

历史 `u-N/a-N` 与直播的 UUID 段 key 并不相同；一个助手显示段又可能合并多个 pi
条目。为搜索直接统一 React key 会打断已有渐显、选区与工具间正文连续性。
因此另加 `sources = [{id,start,end}]`，存真实条目及在显示正文中的区间，合并时一同平移。

pi 先广播公开 message_end 再 append，出处为
`reference/pi/packages/coding-agent/src/core/agent-session.ts:1208、1230`。
来源须在真实 append 与用户附件/上下文元数据提交后取得；不能把公开事件当成已经落盘。
内部续写 user 和纯工具/思考轮没有正文节点，不允许覆盖上一条可见正文的来源。
pi v1 内存迁移会重新生成 ID，见
`reference/pi/packages/coding-agent/src/core/session-manager.ts:286`；此类旧格式使用内容修订
和原始序号锚点，真实迁移后旧结果失效，重新查询。

原文高亮使用 CSS Highlight 的 Range，跨 Markdown 与代码节点绘制，不插入 HTML，
不改用户选区。搜索仅在当前来源消息内定位，不凭时间或重复摘要猜消息。
终态过程先展开再测量，通过已有 scroller 释放吸底；已定位后不会因新的 token 把用户拉回。
