# 界面主题色

> 学习主题：把主题色选择与明暗模式分开保存，让同一套主题色在亮暗环境中保留色相。
> 当前机制和验收见[设置页](../模块/设置页.md)，视觉配方见[UI布局](../UI布局.md)。

## 配色的所有权

主题色拥有头部与两级侧栏的底色，并提供取色器里的六个具名候选色。正文底色
沿用基础明暗 token，Markdown 继续消费内容主题，强调色保存用户独立选色。
从主题色候选点选会复制当下明暗套的点缀色，透明度保留；此后切明暗只更新候选，
不会改写已选的强调色。取色原理见[强调色选择](强调色选择.md)。

```text
owner: appearance store（interfaceSkin、colorMode）
单选卡 → setInterfaceSkin → localStorage + store 订阅
colorMode + matchMedia → 实际明暗
主题色 ID + 实际明暗 → interfaceSkinVariables
  ├─ bindAppearanceDom → 根变量 → 外壳渐变 / 内容侧栏实色
  └─ InterfaceSkinPicker → 卡片局部变量 → 同色缩略图
storage 事件 → rehydrate → 已打开的同源窗口重新投影
```

森林与薄荷分别偏灰绿和青绿；蜜蜂由麦黄过渡到灰蓝；羊皮纸使用暖米色；海盐与
暮紫提供冷色选择。每套显式定义亮暗两套色板，深色降低明度并保留色相，避免将
浅色色值直接套进暗背景。默认薄荷沿用已有浅色色值，旧偏好无需迁移。

缩略图采用真实布局的抽象结构：头部、窄图标栏、内容侧栏和阅读区。单选与方向键
交给 shadcn Nova 的 Base UI RadioGroup；卡片形态属于 `components/ui/radio-group.tsx`
本体，设置分区只提供数据与布局。预览和外壳共用色板，避免两处手写渐变逐渐偏离。

## 参照源码对照

- pi：`reference/pi/packages/coding-agent/src/modes/interactive/theme/theme-controller.ts:103`
  的 `applyFromSettings` 先解析主题选择，再决定是否订阅终端明暗并应用主题；
  `:123` 的 `setThemeName` 则保存选择。Cogent 同样区分持久选择和当下解析结果，
  但实际环境来自浏览器 matchMedia，主题色只覆盖应用外壳。
- deepseek-harness：`reference/deepseek-harness/packages/client/ui-theme/src/client/AppearanceRow.tsx:31`
  定义浅色、深色、跟随系统三档，`:43` 订阅持久偏好，`:52` 按偏好标记选中。
  Cogent 保持这三档含义，再单独增加主题色单选；系统变暗不会把主题色卡换成另一项。
- zcode：`reference/zcode/packages/ui/src/useTheme.ts:13` 将偏好解析成实际明暗，
  `:58` 的 `applyTheme` 同时投影 dark 与具体主题类，`:103` 在系统变更时重新应用。
  Cogent 在已有共享 DOM 投影中按明暗重选配色，所有窗口共用入口，无需逐页面挂 effect。

这些对照只描述上述实读函数，不据此推断参照产品是否拥有其他主题色能力。

## 验证边界

持久化与 DOM 测试覆盖旧档、非法 ID、暗色继续换肤、强调色独立、系统变化与
storage 重读；组件测试覆盖单选、方向键和预览跟随明暗。
`scripts/check-interface-skins-browser.mjs` 使用隔离 profile 的隐藏 Electron，
验证 6 套 × 2 种明暗 × 2 种宽度的实际计算样式，防止深色 CSS 又把主题色截断。
可通过 `COGENT_SKIN_SCREENSHOTS` 指定截图输出目录；测试结束关闭窗口与服务。
