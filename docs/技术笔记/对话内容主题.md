# 对话内容主题（Themd 主题包运行时化）

> 当前机制与验收见[消息呈现](../模块/消息呈现.md)。
> 落点：`lib/theme/`、`features/home/ChatTheme.ts`、`components/ui/markdown.tsx`。

## 1. 主题差异与基础样式是一份合同

Themd 源仓为 `C:\Users\u\Desktop\Themd`。JSON 主题包只保存稀疏差异；空缺项
仍由基础样式赋予语义，不能悄悄替换成接收方 Markdown 库的默认样式。

| Themd 来源 | 职责 |
| --- | --- |
| `src/lib/theme/tokens.ts:12` | 179 个令牌键与 CSS 变量映射 |
| `src/lib/theme/compile.ts:9` | 明暗选套、策略展开、双字体拼栈与继承 |
| `src/styles/theme-base.css:1` | 完整元素消费与默认值，渲染权威 |
| `src/lib/theme/defaults.ts:21` | 131 项静态默认值镜像；字体栈等由 CSS/编译器表达 |
| `src/components/theme/ThemeStudio.tsx:408` | JSON 导出保存的 tokens/dark/extraCss，不展开默认值 |
| `src/lib/theme/portable-css.ts:44,78` | 可移植 CSS 导出附带基础样式全文 |

Themd 的 `defaults-sync.test.ts:40` 机械核对 CSS 回落与镜像。H1–H6 默认字号为
2em/1.5em/1.22em/1.05em/1em/0.9em，字重650、行高1.3、间距1.6em/0.6em，
首个标题无上间距。标题频率属于模型表达，字号属于主题，分别处理。

## 2. 参照与选择

| 参照 | 同主题实现与边界 |
| --- | --- |
| Themd | 基础 CSS + 稀疏令牌，是样式源合同；宿主适配结构差异 |
| deepseek-harness | `reference/deepseek-harness/packages/client/ui-primitives/src/markdown/MarkdownText.module.css:16,351` 区分普通/紧凑模式；自写渲染器不作为 Cogent 默认值来源 |
| zcode | `reference/zcode/packages/ui/src/components/ai-elements/message.tsx:453` 单独定义标题；参考职责分离，不复制字号压过用户主题 |
| pi | `reference/pi/packages/coding-agent/src/modes/interactive/theme/theme.ts:1067` 的终端 MarkdownTheme，不是 Web CSS 合同 |

Cogent 保留 Streamdown 的解析、原生安全清洗、增量高亮和块复用。
主题移植用本地 CSS 基准及适配，不重造渲染器，也不依赖运行机旁边的源仓。

## 3. 本地基准与后续同步

`src/renderer/src/lib/theme/upstream/` 保存五份源文本快照及 manifest.json，记录
来源提交与 LF 归一 SHA-256。`scripts/themd-theme.mjs` 用 PostCSS 生成
`themd-base.css`：转换作用域，去 Themd 编辑器代码工具栏/mermaid 私有包装与
正文列宽，将固定缺省中性色引向宿主明暗变量，其余基础排版保持源语义。
代码字号集中在 pre 消费、code 继承，避免百分比重复缩放。

`content.css` 适配代码滚动层、工具栏、表格外壳和图片包装。标准元素的基础样式
对空主题同样生效，不再以 code/table 变量存在为开关。代码底色落 gutter 所在层，
pre 透明压过 Shiki 内联底色；图片宽度/最大宽度/留白/对齐落包装层，蒙版贴图。
GFM 提示块在默认清洗后按固定枚举转换为可信结构；静态和流式同管线，reveal 继续
追加到真实 Block 的实际插件末尾，见[Markdown渲染](Markdown渲染.md)。

维护命令：

```powershell
npm run theme:check
npm run theme:check -- "C:/Users/u/Desktop/Themd"
node scripts/themd-theme.mjs --update "C:/Users/u/Desktop/Themd"
```

check 只报告变化；显式 update 更新快照及生成件，不覆写本地编译器/适配。
上游新增键仍要同步本地映射及消费；同名令牌默认值变化同样要回归未设置项。
字号门禁先检查快照哈希、令牌映射和生成物逐字一致，生成 CSS 不允许手改；
其他共享消费点精确登记，不放开整片目录。构建与 CI 无须外部 Themd 源仓。
JSON version=1 标文件结构，未锁基础样式版本；升级可能改变旧主题未设置项。

## 4. 用户设置最高与暗色边界

```text
主题 store → 明暗选套 → 主题令牌 + 用户覆盖 → compileTokens → 消息流容器变量
                                  └→ compileUserOverrides → 独立用户变量
主题 extraCss → @scope(.md-body) 样式
用户变量 → 最先声明的 cogent-user 层 + important → 对应用途最终样式
```

同用途优先级：用户显式选择 > 当前主题（含附加 CSS）> 基础默认/宿主缺省适配。
important 的层顺序反转；最先声明 cogent-user，用户字体/代码字号用该层 important
胜过主题无层 important。只在明确选择时产出独立变量，避免主题局部 --t-* 改写绕过
根覆盖。正文覆盖含标题、强调、链接等内容，代码覆盖含高亮子节点，不污染工具栏。
每个元素保留未覆盖的英文/中文槽，不把只改一侧误作整套重置。

跟随主题不产出覆盖；恢复默认清除覆盖，重新读当前主题。换主题、明暗切换、重读
持久值不改用户选择或主题原数据。界面字号与内容隔离，见[统一字号](统一字号.md)。
有 dark 时整面替换，缺键不补亮套；无 dark 沿用 tokens。暗色缺省中性色采用宿主
muted/border，主题显式色优先，不自动反色。Themd 工场编辑写亮套、预览可读暗套
（ThemeStudio.tsx:233,362,399,865），这项上游不一致不在 Cogent 仓修复。

内置 Theme-Leslie 显式设置 root.size=14px、codeBlock.size=14px，保留聊天密度；
导入空主题按 Themd 的16px正文/0.875em代码。用户代码字号仍最高。
root.width/app.bg 归宿主聊天列/画布，不投影到正文；Shiki token 配色不进令牌。
mermaid/math 依赖未安装的渲染插件，本项不新增其语法能力。

## 5. 字体与其他边界

Themd 的 `src/components/SettingsSheet.tsx:56` 用一组英文、中文槽位，
`src/components/settings/FontField.tsx:27` 把本机字体列表与搜索收进弹窗。
Cogent 把同一用途的两个槽位收进同一弹窗，共用搜索和列表。弹窗拥有字体草稿，
预览使用正文同一编译器；保存才整组写入 appearance，关闭不产生持久化副作用。
默认档从当前明暗套读取具体族名回显，保留「默认」语义以继续响应样式变化。
消费侧沿用
Themd `src/lib/theme/compile.ts:119` 的字体栈顺序：英文居前，按缺字回退到
中文和通用族；它是浏览器字形回退，不是按 Unicode 字符区段强制分派。

字体选择也与 CSS 消费端分离。deepseek-harness 同样把字族按用途存储，但其
`reference/deepseek-harness/packages/client/ui-theme/src/client/FontFamilyRow.tsx:35-59`
让用户手填字体栈；Cogent 从 Chromium 本地字体接口枚举族名，主进程只对应用
主窗口的顶层文档授权。用户选定的单个族名按 CSS 字符串编码，这样名字里的逗号
不会被编译器拆成两个字体，引号也不会破坏整条回落栈。

字体令牌不能单独解释像素清晰度，抗锯齿边界见[UI布局](../UI布局.md)。
extraCss 限 .md-body；新增外观设置要同时接入其用途的最终优先层及验收，不能只加
store 字段就声称用户覆盖已生效。主题偏好仍本地持久化，不新增跨设备同步通道。

## 6. 验证证据

纯函数/渲染回归检查原生清洗、提示块、用户单文字系统、代码字号和流式最终收口。
维护脚本测试模拟上游 CSS 改动及新增令牌，验证只报告不覆写。
`tests/renderer/lib/theme/theme.browser.html` 由 `npm run test:theme-browser` 在
隐藏 Electron31/Chromium126 窗口中运行：同页对照 Themd 源 CSS，检查空主题、
导入标题、明暗缺键、重要层冲突、换主题/持久化重读/恢复跟随、流式与窄面板。
临时 Vite、窗口和 profile 随验收收口，不使用 npm run dev。

自动验收覆盖真实 computed style 与布局，不等于人工字体观感评审，也不等于
在 Themd GUI 内完成导出操作或验证其暗面编辑。手动步骤见
[消息呈现手测](../测试用例/消息呈现.md)。
