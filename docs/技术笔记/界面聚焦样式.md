# 界面聚焦样式

shadcn 的视觉配方随组件源码落入项目。常用控件虽然采用同一组 ring 类，
外圈宽度和透明度仍分别写在各个原语里；原生按钮、自写输入与代码编辑器
也不会自动继承这组类。主题变量可以统一颜色，完整的焦点轮廓还需要一个消费入口。

Cogent 用 `globals.css` 的 `:focus-visible` 集中绘制组件轮廓，原生 input 保留
调用处样式，即使带 tabindex 或 contenteditable 也不会被通用焦点选择器重新纳入。
普通 shadcn Input、Textarea 与 InputGroup 保留统一聚焦配方；对话输入卡使用
InputGroup 的 composer 档，只排除该外壳的聚焦描边，内部按钮仍能显示自己的焦点位置。
`--focus-width` 决定实线宽度，负的 outline-offset 把线收进组件边界。outline 不参与布局，
也不清空组件原本的 box-shadow；原语和调用点移除单独的 focus ring。
`--focus-color` 在亮暗两套主题里分别取值，与装饰用途的 `--ring` 分开，
避免调整焦点色时连带改变滑杆边框等常态外观。

常态保留透明实线，聚焦只改变 outline-color，因此进入和离开焦点都能过渡，
线宽与位置保持不动。参与配方的控件默认使用颜色过渡，shadcn 控件沿用自身的
transition-colors/all；只列出特定属性的控件把 outline-color 并入原清单，
避免覆盖位置、缩放或内距的既有动画。reduced-motion 时直接完成切换。

需要焦点轮廓的组合件把提示交给视觉外壳：普通 InputGroup、附件主触发器、代码块、
滑杆隐藏输入和 CodeMirror 的内容节点在外层画线，内部不再叠框。
带图标的原生搜索框保持无新增焦点轮廓，外壳也不因输入聚焦而描边。菜单的导航高亮、
错误字段的红色边框和普通组件阴影继续承担各自语义。

## 同主题源码对照

- zcode `reference/zcode/packages/ui/src/components/ui/input.tsx:7` 用
  `focus-visible:border-input-border-focused`、背景变化与 `focus-visible:ring-0`
  表达聚焦；同仓 `packages/ui/src/styles.css:245`、`:417` 为输入框提供亮暗色槽。
  这说明聚焦反馈可以只依赖组件边界与语义色，不必有向外扩展的 ring。
- zcode `reference/zcode/packages/ui/src/styles.css:133` 的注释记录了系统高亮与
  组件 ring 混用、组合框重复描边的问题；`:139` 的实现全局清除 outline 和阴影。
  Cogent 在同一处集中轮廓所有权，对话输入卡保持常态外观，普通控件保留明确的键盘落点，
  需要外壳轮廓的组合件抑制内部重复描边。

当前视觉参数与维护规则以 [UI布局](../UI布局.md) 为准。
